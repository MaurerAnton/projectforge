Zentrale Entität für die wöchentliche HR-Ressourcenplanung. Mappt auf die Tabelle T_HR_PLANNING, eindeutig eingeschränkt durch Benutzer+Woche. Enthält eine Liste von HRPlanningEntryDO-Kindentitäten und berechnet aggregierte Stundensummen (täglich, nicht zugewiesen, Wochenende).

Entwurf der Entität

Erweitert DefaultBaseDO. Wichtige Beziehungen:

  • user (PFUserDO, ManyToOne): Der Mitarbeiter, dem diese Planungswoche gehört. Wird nur als ID serialisiert über @IdOnlySerializer.
  • week (LocalDate): Erster Tag der Woche (Montag gemäß Locale.GERMAN). Wird in der eindeutigen Einschränkung mit dem Benutzer verwendet.
  • entries (List<HRPlanningEntryDO>, OneToMany): Kindentitäten für jede Projekt-/Statuszuweisung in dieser Woche. Markiert mit @PersistenceBehavior(autoUpdateCollectionEntries=true) für automatisches Kaskadenmanagement.

Berechnete Eigenschaften

Alle @Transient-Eigenschaften berechnen Aggregate aus den Einträgen: totalHours, totalUnassignedHours, totalMondayHours bis totalWeekendHours. Jede überspringt gelöschte Einträge mittels entry.deleted-Prüfung. Die Eigenschaft formattedWeekOfYear delegiert an DateTimeFormatter.

Wichtige Entscheidungen

  • Wochenstart = Montag: Verwendet PFDay.beginOfWeek mit Locale.GERMAN, wodurch Montag der erste Arbeitstag ist.
  • Weiches Löschen für Einträge: deleteEntry() markiert Einträge als gelöscht, anstatt sie zu entfernen, was ein Rückgängigmachen durch erneutes Hinzufügen desselben Status/Projekts ermöglicht.
  • Lazy Loading: Alle Beziehungen verwenden FetchType.LAZY, um N+1-Abfrageprobleme zu vermeiden.
