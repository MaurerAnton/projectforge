#1013: HRPlanningDO.kt

projectforge-business/src/main/kotlin/org/projectforge/business/humanresources/HRPlanningDO.kt JPA-сущность (планирование HR), projectforge-business/src/main/kotlin/org/projectforge/business/humanresources/HRPlanningDO.kt 394 строки · 269 кода · 95 комментариев · 30 пустых
Центральная сущность для еженедельного планирования HR-ресурсов. Отображается на таблицу T_HR_PLANNING, уникальность обеспечивается комбинацией пользователь+неделя. Содержит список дочерних сущностей HRPlanningEntryDO и вычисляет агрегированные итоги по часам (ежедневные, неназначенные, выходные).

Дизайн сущности

Расширяет DefaultBaseDO. Ключевые связи:

  • user (PFUserDO, ManyToOne): Сотрудник, которому принадлежит эта неделя планирования. Сериализуется только как ID через @IdOnlySerializer.
  • week (LocalDate): Первый день недели (понедельник согласно Locale.GERMAN). Используется в ограничении уникальности вместе с пользователем.
  • entries (List, OneToMany): Дочерние сущности для каждого назначения проекта/статуса на этой неделе. Отмечены @PersistenceBehavior(autoUpdateCollectionEntries=true) для автоматического управления каскадами.

Вычисляемые свойства

Все свойства @Transient вычисляют агрегаты из записей: totalHours, totalUnassignedHours, totalMondayHours через totalWeekendHours. Каждое пропускает удалённые записи через проверку entry.deleted. Свойство formattedWeekOfYear делегирует DateTimeFormatter.

Ключевые решения

  • Начало недели = понедельник: Используется PFDay.beginOfWeek с Locale.GERMAN, что делает понедельник первым рабочим днём.
  • Мягкое удаление записей: deleteEntry() помечает записи как удалённые, а не удаляет их, что позволяет отменить действие через повторное добавление того же статуса/проекта.
  • Ленивая загрузка: Все связи используют FetchType.LAZY для избежания проблем с N+1 запросами.
