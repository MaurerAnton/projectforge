Objet d'accès aux données pour la planification hebdomadaire des RH. Étend BaseDao, fournissant des opérations CRUD, l'indexation Hibernate Search, le contrôle d'accès et l'intégration de l'historique pour les entrées de planification hebdomadaire des ressources des employés.

Architecture

Contrôle d'accès

Implémente une vérification fine des droits d'écriture au-delà du contrôle standard USER_RIGHT_ID. Lors de l'insertion/mise à jour, vérifie que l'utilisateur connecté dispose des droits spécifiques au projet pour chaque entrée de planification RH. Les utilisateurs doivent être soit le chef de projet, le responsable commercial, le responsable des ventes, ou un membre du groupe des chefs de projet pour modifier les entrées d'un projet donné. Ceci est appliqué via afterDBWrite qui parcourt toutes les entrées et valide les permissions avant la validation.

Intégration de l'historique

Remplace addOwnHistoryEntries pour fusionner les entrées d'historique des objets enfants HRPlanningEntryDO. Utilise HistoryFormatUtils.setNumberAsPropertyNameForListEntries pour préfixer chaque entrée d'historique avec le nom du projet ou le statut, rendant les différences d'historique lisibles.

Hibernate Search

Définit des champs de recherche supplémentaires (ADDITIONAL_SEARCH_FIELDS) pour la recherche en texte intégral dans le nom du projet, le nom du client et les détails de l'utilisateur des entrées. Enregistre HRPlanningEntryDO comme entité de recherche supplémentaire via additionalHistorySearchDOs.

Performance

Remplace prepareHibernateSearch pour initialiser de manière eager les champs de projet chargés paresseusement (groupe du chef de projet) avant l'indexation Hibernate Search, évitant ainsi les requêtes N+1 lors des mises à jour de l'index de recherche.
