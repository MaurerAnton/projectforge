Spring @Service, предоставляющий интеллектуальное изменение размера и сжатие изображений для адресной книги ProjectForge. Использует многостратегический подход: снижение качества JPEG, бинарный поиск по размерам, сначала JPEG, затем PNG как запасной вариант.

Архитектура

Алгоритм сжатия (shrinkToMaxFileSize)

Сервис реализует двухфазный подход для сжатия изображений до целевого размера файла:

  1. Конвертация формата: Сначала предпринимается попытка конвертации в JPEG (оптимальное сжатие). Используется PNG как запасной вариант, если изображение имеет прозрачность (альфа-канал), которую JPEG не поддерживает. Определение типа изображения осуществляется по магическим байтам.
  2. Стратегия 1 — Снижение качества JPEG: Последовательно тестируются уровни качества 0.85, 0.8, 0.7. Возвращает результат немедленно, если уровень качества достигает оптимального диапазона (95-100% от максимального размера).
  3. Стратегия 2 — Масштабирование бинарным поиском: Если только снижения качества недостаточно, выполняется бинарный поиск по коэффициенту масштаба (0.0-1.0), применяемому к размерам изображения. Минимальный размер стороны установлен на 100px, чтобы предотвратить получение непригодных изображений. Используется лучшее качество JPEG из Стратегии 1.

Ключевые проектные решения

  • Нацеливание на оптимальный диапазон: Стремление к 95-100% от максимального размера, а не просто «ниже лимита», максимизирует качество изображения в заданных ограничениях.
  • Стратегия «сначала JPEG»: JPEG обычно сжимает фотографии в 5-10 раз лучше, чем PNG, поэтому конвертация предпринимается в первую очередь.
  • Определение по магическим байтам: detectImageType() проверяет сырые байты на сигнатуры JPEG (FF D8 FF), GIF (GIF) и PNG (89 50 4E 47), избегая зависимости от расширений файлов.
  • Изменение размера с сохранением пропорций: resizeImagePreserveRatio() вычисляет минимальный масштаб по ширине и высоте, чтобы вписаться в границы, сохраняя соотношение сторон.

Класс данных ImageResult

Содержит bytes: ByteArray и imageType: ImageType. Переопределяет equals/hashCode с контентно-зависимым сравнением, используя contentEquals/contentHashCode.
