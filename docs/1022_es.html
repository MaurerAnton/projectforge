Singleton que implementa penalizaciones de tiempo crecientes para intentos de inicio de sesión fallidos, evitando ataques de fuerza bruta. Rastrea fallos por separado por ID de usuario (basado en cadena) y dirección IP del cliente, con umbrales configurables antes de incrementar la penalización.

Arquitectura

Sistema de penalización de doble mapa

Mantiene dos instancias de LoginProtectionMap: una claveada por cadena de usuario (nombre de usuario o tipoAutenticación:nombre de usuario), otra por dirección IP. En cada inicio de sesión fallido, los mapas correspondientes se incrementan. Se devuelve el desplazamiento de penalización mayor entre usuario e IP.

Separación por tipo de autenticación

Las penalizaciones se separan por tipo de autenticación (DAV, REST_CLIENT o nulo para inicio de sesión normal) usando la convención "tipoAutenticación:userId". Esto evita que los intentos fallidos de inicio de sesión DAV bloqueen el inicio de sesión web del usuario.

Umbrales

  • Umbral de penalización de usuario: 1 intento fallido antes de incrementar (penalización inmediata para ataques dirigidos).
  • Umbral de penalización de IP: 1000 intentos fallidos antes de incrementar (evita penalizar grandes redes NAT).

Acceso Singleton

Se accede mediante el método estático LoginProtection.instance(). El constructor privado configura los dos mapas de protección con diferentes umbrales.
