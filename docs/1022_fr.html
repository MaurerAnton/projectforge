Singleton implémentant des pénalités temporelles croissantes pour les tentatives de connexion échouées, empêchant les attaques par force brute. Suit les échecs séparément par identifiant utilisateur (basé sur une chaîne) et par adresse IP client, avec des seuils configurables avant l'incrémentation des pénalités.

Architecture

Système de pénalité à double carte

Maintient deux instances de LoginProtectionMap : une indexée par chaîne utilisateur (nom d'utilisateur ou typeAuth:nom d'utilisateur), une par adresse IP. À chaque échec de connexion, les cartes correspondantes sont incrémentées. Le décalage de pénalité le plus grand entre l'utilisateur et l'IP est retourné.

Séparation par type d'authentification

Les pénalités sont séparées par type d'authentification (DAV, REST_CLIENT, ou null pour une connexion normale) en utilisant la convention "typeAuthentification:identifiantUtilisateur". Cela empêche les tentatives de connexion DAV échouées de bloquer la connexion web de l'utilisateur.

Seuils

  • Seuil de pénalité utilisateur : 1 tentative échouée avant incrémentation (pénalité immédiate pour les attaques ciblées).
  • Seuil de pénalité IP : 1000 tentatives échouées avant incrémentation (évite de pénaliser les grands réseaux NAT).

Accès Singleton

Accessible via la méthode statique LoginProtection.instance(). Le constructeur privé configure les deux cartes de protection avec des seuils différents.
