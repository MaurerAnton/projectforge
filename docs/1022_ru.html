Синглтон, реализующий эскалацию временных задержек при неудачных попытках входа, предотвращая атаки перебором. Отслеживает неудачи отдельно по идентификатору пользователя (строковый) и IP-адресу клиента, с настраиваемыми порогами перед увеличением задержки.

Архитектура

Система штрафов с двумя картами

Поддерживает два экземпляра LoginProtectionMap: один с ключом по строке пользователя (имя пользователя или authType:имя пользователя), второй — по IP-адресу. При каждой неудачной попытке входа соответствующие карты увеличиваются. Возвращается больший штрафной офсет между пользователем и IP.

Разделение по типу аутентификации

Штрафы разделяются по типу аутентификации (DAV, REST_CLIENT или null для обычного входа) с использованием соглашения "authenticationType:userId". Это предотвращает блокировку веб-входа пользователя из-за неудачных попыток входа через DAV.

Пороговые значения

  • Порог штрафа пользователя: 1 неудачная попытка перед увеличением (немедленный штраф для целевых атак).
  • Порог штрафа по IP: 1000 неудачных попыток перед увеличением (избегает штрафования больших NAT-сетей).

Доступ к синглтону

Доступ через статический метод LoginProtection.instance(). Приватный конструктор настраивает две карты защиты с разными порогами.
