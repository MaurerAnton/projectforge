Singleton interno que resuelve el problema del classpath de scripting de Kotlin en JARs gordos de Spring Boot. Los scripts de Kotlin no pueden acceder directamente a las clases incluidas en un JAR gordo. Este extractor copia los JARs necesarios (projectforge, plugins, merlin, poi) desde el JAR gordo a un directorio temporal y los proporciona como un URLClassLoader para el motor de scripting.

Arquitectura

Detección

Verifica si la ubicación del código fuente comienza con "jar:", lo que indica ejecución desde un JAR gordo. Si no es así (por ejemplo, ejecutándose en el IDE), omite la extracción y utiliza el classpath actual.

Proceso de extracción

  1. Crea el directorio temporal ProjectForge-extracted-jar, eliminando cualquier copia anterior.
  2. Abre el JAR gordo con JarFile.
  3. Itera las entradas; para cada archivo .jar que coincida con los patrones regex configurados (projectforge-business, projectforge-common, poi, poi-ooxml, merlin-core y JARs de plugins), lo extrae al directorio temporal.
  4. Construye la lista classpathFiles y el array classpathUrls para que los use URLClassLoader.

Historial de combate

El historial de git muestra extensas dificultades (commits de4d8d2af, 302470ef9, 7617cf5da, 31545575d) para lograr que el scripting de Kotlin funcione en el JAR gordo. Se probaron múltiples enfoques antes de decidirse por la extracción de JARs.
