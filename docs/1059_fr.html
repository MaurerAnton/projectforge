Singleton interne résolvant le problème de classpath du scripting Kotlin dans les JARs Fat Spring Boot. Les scripts Kotlin ne peuvent pas accéder directement aux classes regroupées dans un JAR Fat. Cet extracteur copie les JARs requis (projectforge, plugins, merlin, poi) depuis le JAR Fat vers un répertoire temporaire et les fournit sous forme de URLClassLoader pour le moteur de script.

Architecture

Détection

Vérifie si l'emplacement de la source du code commence par "jar:", indiquant une exécution depuis un JAR Fat. Si ce n'est pas le cas (par exemple, exécution dans un IDE), l'extraction est ignorée et le classpath actuel est utilisé.

Processus d'extraction

  1. Crée le répertoire temporaire ProjectForge-extracted-jar, en supprimant toute copie précédente.
  2. Ouvre le JAR Fat avec JarFile.
  3. Parcourt les entrées ; pour chaque fichier .jar correspondant aux expressions régulières configurées (projectforge-business, projectforge-common, poi, poi-ooxml, merlin-core et les JARs de plugins), extrait vers le répertoire temporaire.
  4. Construit la liste classpathFiles et le tableau classpathUrls pour utilisation par URLClassLoader.

Historique des combats

L'historique Git montre des luttes approfondies (commits de4d8d2af, 302470ef9, 7617cf5da, 31545575d) pour faire fonctionner le scripting Kotlin dans le JAR Fat. Plusieurs approches ont été essayées avant de se fixer sur l'extraction de JAR.
