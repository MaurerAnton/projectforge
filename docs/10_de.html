Operative Runbooks — kodifiziertes Erfahrungswissen

Der operative Abschnitt ist der wertvollste Teil für neue Entwickler. Er enthält:

  • Schnelle PostgreSQL-Importe (Zeilen 64-74): ALTER SYSTEM SET fsync = off; ALTER SYSTEM SET synchronous_commit = off; — opfert Haltbarkeit für Importgeschwindigkeit. Diese Einstellungen MÜSSEN nach dem Import zurückgesetzt werden.
  • Standard-Entwicklerpasswort (Zeile 84): SHA{BC871652288E56E306CFA093BEFC3FFCD0ED8872} = test123. Überall verwendet — SQL-Beispiele, Docker-Setup, CI-Skripte.
  • Kalenderbereinigung (Zeile 86): update t_calendar set ext_subscription=false — verhindert Massen-API-Aufrufe an externe Kalender bei Verwendung von Produktionsdaten für die Entwicklung.
  • Rancher-Bereinigung (Zeilen 55-62): docker system prune -a --volumes — vollständige Docker-Garbage-Collection. Gefährlich in der Produktion, essenziell in der Entwicklung.

Wichtige Erkenntnisse

  • Hibernate Search ist defekt: Der Abschnitt „Reindexierung“ dokumentiert mehrere Suchindex-Fehler — CronReindexingHourlyJob hat keine Wirkung, History-Einträge fehlen, nur Massen-Reindexierung funktioniert. Dies ist ein erhebliches Produktionsproblem.
  • test123 überall: Der SHA-Hash für das Entwicklerpasswort erscheint in jedem SQL-Beispiel. Wenn Sie es ändern, aktualisieren Sie alle Referenzen.
  • Gemischtes Deutsch/Englisch: Aufgaben auf Deutsch, SQL auf Englisch, technische Begriffe auf Englisch. Normal für das Micromata-Team.
