Операционные инструкции — документирование неявных знаний

Операционный раздел — самая ценная часть для новых разработчиков. Он содержит:

  • Быстрый импорт PostgreSQL (строки 64-74): ALTER SYSTEM SET fsync = off; ALTER SYSTEM SET synchronous_commit = off; — жертвует надёжностью ради скорости импорта. Эти настройки ОБЯЗАТЕЛЬНО нужно вернуть после импорта.
  • Стандартный пароль разработчика (строка 84): SHA{BC871652288E56E306CFA093BEFC3FFCD0ED8872} = test123. Используется везде — в примерах SQL, настройке Docker, CI-скриптах.
  • Очистка календаря (строка 86): update t_calendar set ext_subscription=false — предотвращает массовые API-вызовы к внешним календарям при использовании продакшн-данных для разработки.
  • Очистка Rancher (строки 55-62): docker system prune -a --volumes — полная сборка мусора Docker. Опасно в продакшне, необходимо в разработке.

Ключевые выводы

  • Hibernate Search сломан: Раздел "Reindexierung" документирует множественные сбои поисковых индексов — CronReindexingHourlyJob не работает, записи истории отсутствуют, работает только массовый реиндекс. Это серьёзная проблема для продакшна.
  • test123 повсюду: SHA-хэш пароля разработчика появляется в каждом SQL-примере. Если вы его меняете, обновите все ссылки.
  • Смесь немецкого и английского: Задачи на немецком, SQL на английском, технические термины на английском. Нормально для команды Micromata.
