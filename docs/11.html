File #11: docker/compose/docker-compose.yml

Path: ./docker/compose/docker-compose.yml · Type: Docker Compose · Lines: 48 · Source: GitHub

What it does

This file defines a production-ready Docker stack with three services: the ProjectForge application, a PostgreSQL database, and an nginx reverse proxy. One command — docker compose up -d — launches the entire system.

The app is served from a pre-built Docker image (micromata/projectforge:latest), NOT built from source. The database uses a pinned version (postgres:13.18) for stability.

Service breakdown

projectforge-app (lines 3–21)

imagemicromata/projectforge:latest — pulls from Docker Hub. Built via deployment.adoc step 7.
restart: alwaysAuto-restart on crash or Docker daemon restart. Production-standard.
DOCKER_OPTS="-Ddocker=stack"Java system property — tells ProjectForge it's running in Docker. Used to hide the embedded database option in the setup wizard (line 9 comment). Forces users to configure PostgreSQL.
portsMaps ${APP_PORT}:8080 — default from .env file. The commented line shows a secure variant (localhost-only binding).
volumesCommented out — would mount ~/ProjectForge for persistent application data (uploaded files, config, logs).
depends_onStarts projectforge-db BEFORE the app. Note: depends_on only waits for container start, not database readiness — in production, the app should retry DB connections.

projectforge-db (lines 23–34)

imagepostgres:13.18 — pinned to a specific PostgreSQL minor version. Critical for schema compatibility.
volumes./ProjectForgeDB:/var/lib/postgresql/data — persists DB data on the host. Without this, docker compose down would delete all data.
environmentCredentials from .env file via ${POSTGRES_USER}, ${POSTGRES_PASSWORD}, ${POSTGRES_DB}. Never hardcoded.

nginx (lines 36–48)

imagenginx:latest — floating tag (updates automatically on docker compose pull).
ports80 (HTTP) and 443 (HTTPS) exposed to the world. TLS terminated at nginx, internal traffic is plain HTTP.
volumesThree mounts: nginx.conf (proxy config), certs/ (SSL certificates), keys/ (private keys).

Key takeaways

  • 48 lines, production stack: App + PostgreSQL + nginx — the standard deployment for all but evaluation setups.
  • Docker, not Kubernetes: Single-host deployment — no orchestration, no scaling. Suitable for SME deployments.
  • DB version pinned: postgres:13.18 — flying too close to :latest for DB is dangerous.
  • Credentials from .env: Lines 32–34 — never commit passwords to the compose file.
  • TLS at nginx: Internal traffic (app↔db, nginx↔app) is plain HTTP — TLS terminates at the edge.
