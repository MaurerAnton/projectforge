#113: org.projectforge.plugins.core.AbstractPlugin

Path: plugins/...datatransfer/src/main/resources/META-INF/services/org.projectforge.plugins.core.AbstractPlugin · Lines: 1 · Type: Java ServiceLoader configuration

Plugin registration via Java SPI. This file tells the Java ServiceLoader mechanism that org.projectforge.plugins.datatransfer.DataTransferPlugin is an implementation of org.projectforge.plugins.core.AbstractPlugin. When ProjectForge starts up, PluginsRegistry scans META-INF/services/ across all JARs on the classpath, instantiates each listed class, and registers the plugin in the system.

Single line: org.projectforge.plugins.datatransfer.DataTransferPlugin

How it works

The file name is the fully qualified interface/abstract class name (org.projectforge.plugins.core.AbstractPlugin), and its content is the implementing class name. This is the standard Java SPI (Service Provider Interface) pattern — the same mechanism used by JDBC drivers and SLF4J bindings.

Every ProjectForge plugin has this file at META-INF/services/org.projectforge.plugins.core.AbstractPlugin with its main plugin class. When PluginsRegistry (in projectforge-business) calls ServiceLoader.load(AbstractPlugin.class), all plugin JARs on the classpath are discovered without hardcoded references.

ServiceLoader files across the project

This pattern appears for every plugin — same file name, different content. Also used for other framework extensibility points:

  • META-INF/services/org.projectforge.framework.persistence.api.UserRightId — user right registration
  • META-INF/services/org.projectforge.business.configuration.ConfigurationParam — configuration parameter registration
  • META-INF/services/org.projectforge.business.jobs.JobHandler — scheduled job registration
