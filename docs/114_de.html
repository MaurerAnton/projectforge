E-Mail zur Benachrichtigung über Beobachteraktivitäten – wird an Benutzer gesendet, die einen Datenübertragungsbereich beobachten (haben userWantsToObserve=true). Sie werden über Dateiaktionen anderer Benutzer informiert: Uploads, Umbenennungen, Löschungen und externe Downloads.

Vorlagenvariablen

  • message – dynamische Nachricht (typischerweise: „Die folgenden Aktivitäten wurden in dem von Ihnen beobachteten Datenübertragungsbereich 'Bereichsname' festgestellt.") – Schlüssel plugins.datatransfer.mail.observe.message mit {0}-Ersetzung
  • auditEntries – Liste der letzten Audit-Log-Einträge für den Bereich (gesamte Aktivität, nicht nur Downloads)
  • downloadAuditEntries – gefilterte Liste: nur DOWNLOAD-Ereignisse, die in einem separaten Abschnitt unten angezeigt werden
  • link – direkte URL zum Datenübertragungsbereich
  • pf – Formatierungskontext: getI18nString() für i18n-Bezeichnungen, getString() für Datumsformatierung

Inhaltsstruktur

  1. i18n-Begrüßungsnachricht (message-Variable, vorlokalisiert durch i18n-Ressourcen)
  2. Aktivitätstabelle (alle aktuellen Ereignisse):
    • Spalten: Datum, Dateiname, Beschreibung, Aktion (eventType), Geändert von
    • Iteriert über auditEntries – jeder Eintrag hat timestamp, filenameAsString, descriptionAsString, eventType, byUserAsString
  3. Aktionsbutton: „Link zum Datenübertragungsbereich" – gestaltet als klickbarer Button mit class="button", verlinkt auf ${link}
  4. Tabelle der Download-Ereignisse (gefiltert auf DOWNLOAD):
    • Spalten: Datum, Dateiname, Aktion, Heruntergeladen von
    • Iteriert über downloadAuditEntries
  5. Gemeinsamer E-Mail-Abschluss/Footer über #INCLUDE-Direktiven

Die Trennung von auditEntries und downloadAuditEntries ermöglicht es dem Empfänger, auf einen Blick zu sehen, „wer was heruntergeladen hat", ohne durch Upload-/Umbenennungsrauschen scrollen zu müssen.

Auslöser

Diese Vorlage wird von DataTransferObserverNotificationJob gerendert (einem geplanten Job, der regelmäßig läuft, Audit-Einträge mit notified=false abfragt, sie nach Bereich gruppiert und eine E-Mail pro Beobachter sendet). Nach dem Senden wird das notified-Flag jedes Audit-Eintrags auf true gesetzt, um Duplikate zu vermeiden.
