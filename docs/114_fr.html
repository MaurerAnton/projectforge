#114: dataTransferMail.html

Email de notification d'activité pour observateur — envoyé aux utilisateurs qui surveillent une zone de transfert de données (ayant userWantsToObserve=true). Les informe des actions sur les fichiers effectuées par d'autres utilisateurs : téléversements, renommages, suppressions et téléchargements externes.

Variables du modèle

  • message — message dynamique (typiquement : « Les activités suivantes ont été détectées dans la zone de transfert de données 'NomZone' que vous observez. ») — clé plugins.datatransfer.mail.observe.message avec substitution {0}
  • auditEntries — liste des entrées récentes du journal d'audit pour la zone (activité complète, pas seulement les téléchargements)
  • downloadAuditEntries — liste filtrée : uniquement les événements DOWNLOAD, affichés dans une section séparée ci-dessous
  • link — URL directe vers la zone de transfert de données
  • pf — contexte de formatage : getI18nString() pour les libellés i18n, getString() pour le formatage des dates

Structure du contenu

  1. Message de salutation i18n (variable message, pré-localisée par ressources i18n)
  2. Tableau des activités (tous les événements récents) :
    • Colonnes : Date, Nom du fichier, Description, Action (eventType), Modifié par
    • Itère sur auditEntries — chaque entrée possède timestamp, filenameAsString, descriptionAsString, eventType, byUserAsString
  3. Bouton d'action : « Lien de transfert de données » — stylisé comme un bouton cliquable avec class="button", lien vers ${link}
  4. Tableau des événements de téléchargement (filtré sur DOWNLOAD uniquement) :
    • Colonnes : Date, Nom du fichier, Action, Téléchargé par
    • Itère sur downloadAuditEntries
  5. Fermeture/pied de page d'email partagé via directives #INCLUDE

La séparation entre auditEntries et downloadAuditEntries permet au destinataire de parcourir « qui a téléchargé quoi » sans avoir à défiler à travers le bruit des téléversements/renommages.

Déclencheur

Ce modèle est rendu par DataTransferObserverNotificationJob (une tâche planifiée qui s'exécute périodiquement, interroge les entrées d'audit avec notified=false, les regroupe par zone et envoie un email par observateur). Après l'envoi, le drapeau notified sur chaque entrée d'audit est passé à true pour éviter les doublons.
