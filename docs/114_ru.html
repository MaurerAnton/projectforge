#114: dataTransferMail.html

plugins/org.projectforge.plugins.datatransfer/src/main/resources/mail/dataTransferMail.html Путь: plugins/...datatransfer/src/main/resources/mail/dataTransferMail.html · Строк: 64 · Тип: Шаблон электронного письма Freemarker HTML 64 строки · 58 кода · 4 комментария · 2 пустых

Письмо-уведомление о действиях наблюдателя — отправляется пользователям, которые следят за областью передачи данных (имеют userWantsToObserve=true). Уведомляет их о действиях с файлами других пользователей: загрузках, переименованиях, удалениях и внешних скачиваниях.

Переменные шаблона

  • message — динамическое сообщение (обычно: «В наблюдаемой вами области передачи данных «ИмяОбласти» обнаружены следующие действия») — ключ plugins.datatransfer.mail.observe.message с подстановкой {0}
  • auditEntries — список последних записей аудита для области (все действия, не только скачивания)
  • downloadAuditEntries — отфильтрованный список: только события DOWNLOAD, показаны в отдельном разделе ниже
  • link — прямая ссылка на область передачи данных
  • pf — контекст форматирования: getI18nString() для i18n-меток, getString() для форматирования даты

Структура содержимого

  1. Приветственное сообщение i18n (переменная message, предварительно локализованная через i18n-ресурсы)
  2. Таблица действий (все последние события):
    • Колонки: Дата, Имя файла, Описание, Действие (eventType), Кем изменено
    • Перебор auditEntries — каждая запись содержит timestamp, filenameAsString, descriptionAsString, eventType, byUserAsString
  3. Кнопка действия: «Ссылка на передачу данных» — оформлена как кликабельная кнопка с class="button", ведёт на ${link}
  4. Таблица событий скачивания (отфильтрована только по DOWNLOAD):
    • Колонки: Дата, Имя файла, Действие, Кем скачано
    • Перебор downloadAuditEntries
  5. Общая часть закрытия/подвала письма через директивы #INCLUDE

Разделение auditEntries и downloadAuditEntries позволяет получателю быстро увидеть «кто что скачал», не пролистывая шум от загрузок/переименований.

Триггер

Этот шаблон рендерится задачей DataTransferObserverNotificationJob (плановое задание, запускаемое периодически; запрашивает записи аудита с notified=false, группирует их по области и отправляет одно письмо на каждого наблюдателя). После отправки флаг notified каждой записи аудита устанавливается в true, чтобы избежать дублирования.
