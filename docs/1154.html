1154: VacationCache.kt

Cache, projectforge-business/src/main/kotlin/org/projectforge/business/vacation/VacationCache.kt
In-memory cache of all active (non-deleted) vacation entries, refreshed on DAO change events and supporting period/user-group filtered queries.

Architecture

VacationCache extends AbstractCache and implements BaseDOModifiedListener<VacationDO>. It maintains a thread-safe Map<Long?, VacationDO> and a copy-on-read List<VacationDO> to prevent ConcurrentModificationException.

Refresh Mechanism

refresh() is called by the cache framework (synchronized at the framework level). It runs within an isolated read-only transaction via PfPersistenceService.runIsolatedReadOnly, calls VacationDao.selectAll(checkAccess = false), and filters out deleted entries. After the transaction, the map and list are replaced atomically.

Real-time Updates

afterInsertOrModify(obj, operationType) is registered via VacationDao.register(this) in @PostConstruct. When any vacation entry is inserted or modified, the cache updates its internal map and regenerates the list copy under a synchronized block. This keeps the cache current without full refreshes.

Query: getVacationForPeriodAndUsers

The primary query method filters cached vacations by start/end date overlap, access control (VacationDao.hasSelectAccess), and group/user membership. It resolves employees through EmployeeCache and checks group membership via UserGroupCache. Null safety is enforced for both groupIds and userIds parameters.

Design Rationale

Vacation entries are read-heavy (calendar views, conflict detection, team overviews) but write-infrequent. Caching all entries avoids repeated database round-trips. The listener-based update keeps the cache hot without polling. Using AbstractCache as a base provides automatic expiration and refresh scheduling through the framework's CacheHelper.
