Envía notificaciones por correo electrónico a vacacionistas, gerentes, reemplazos y personal de RR.HH. cuando se crean, modifican o eliminan registros de vacaciones.

Arquitectura

VacationSendMailService es un @Service que integra ConfigurationService (configuración del servidor de correo, dirección de correo de RR.HH.), EmployeeDao (búsquedas de empleados/usuarios) y SendMail (infraestructura de correo). Se invoca exclusivamente desde los hooks de ciclo de vida after* de VacationDao.

Flujo de notificación

  1. checkAndSendMail(obj, operationType, dbObj) — Punto de entrada. Verifica que el servidor de correo esté configurado y construye un contenedor VacationInfo.
  2. Para registros de vacaciones especiales con estado IN_PROGRESS o APPROVED, envía a la dirección de correo de RR.HH. (configurada en administración).
  3. Envía al vacacionista (si no fue él mismo quien realizó el cambio — verificado mediante ThreadLocalUserContext.loggedInUserId).
  4. Envía al gerente (si no es el actor).
  5. Envía al reemplazo principal y a todos los demás reemplazos (deduplicados mediante un conjunto).

Composición del correo

El método prepareMail() crea un objeto Mail con contenido HTML renderizado a partir de la plantilla Groovy mail/vacationMail.html. La plantilla recibe un mapa que contiene:

  • vacationInfo — clase interna VacationInfo con todos los nombres de usuario resueltos, correos electrónicos, fechas formateadas y días laborables
  • vacation — el objeto VacationDO sin procesar
  • mailInfo — asunto, tipo de operación (insertar/actualizar/eliminar/recuperar) y modo (propio/gerente/reemplazo/RR.HH.)

Clase interna VacationInfo

Este contenedor de datos resuelve todas las referencias de empleados (vacacionista, gerente, reemplazo, otrosReemplazos) a objetos PFUserDO y formatea fechas, días laborables, indicadores de medio día y estado especial. El método updateI18n(recipient) vuelve a resolver las cadenas visibles para el usuario según la configuración regional del destinatario, lo que permite la entrega de correos localizados a destinatarios con diferentes configuraciones de idioma.

Generación de URL

El objeto complementario construye de forma perezosa un enlace a la página de edición de vacaciones mediante SendMail.buildUrl() combinado con MenuItemDefId.VACATION.url, generando enlaces profundos como /vacation/edit/123?returnToCaller=account.

Justificación del diseño

El envío de correos está separado del DAO para mantener aisladas las preocupaciones de persistencia. El servicio utiliza VacationInfo como una clase de datos intermedia en lugar de pasar la entidad directamente a las plantillas; esto garantiza que las plantillas nunca accedan a proxies JPA de carga diferida (que fallarían fuera de una transacción). El método updateI18n soporta el requisito multiidioma de una empresa alemana con empleados internacionales. La ruta de notificación a RR.HH. para vacaciones especiales garantiza el monitoreo de cumplimiento incluso cuando empleados y gerentes son la misma persona.
