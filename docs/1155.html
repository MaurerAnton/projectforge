1155: VacationDao.kt

DAO, projectforge-business/src/main/kotlin/org/projectforge/business/vacation/repository/VacationDao.kt
Data access object for vacation entries with role-based access control, status state machine, mail notification triggers, and period-based queries.

Architecture

VacationDao extends BaseDao<VacationDO>, inheriting CRUD operations, search infrastructure, history tracking, and access checking. It is annotated @Service (historically @Repository) and uses constructor-based injection for EmployeeDao, PfCaches, and VacationSendMailService.

Access Control System

The DAO implements four access roles via override methods:

MethodLogic
hasUserSelectAccessAlways true (global read)
hasUserSelectAccess(Object)HR staff, own entry, manager, replacement, OR same-group entries ≤31 days old
hasInsertAccessOwn entry or manager; past-date insertions blocked for non-HR
hasUpdateAccessFull status state machine: HR can do anything; managers can approve/reject non-special entries; employees can only modify IN_PROGRESS entries; past entries locked except for status changes on non-time-period fields
hasDeleteAccessHR staff or own non-approved past entries only
hasHistoryAccessHR staff, own entry, or manager

Status State Machine

getAllowedStatus(user, vacation) returns the list of valid status transitions based on user role (HR, manager, employee), vacation current status, whether the entry is in the past, and whether the entry is a special vacation (requires HR approval). The rules ensure managers can only approve/reject non-special entries, employees cannot approve their own requests, and past entries have restricted modification.

Lifecycle Hooks

  • onInsertOrModify — Ensures special field is never null (defaults to false)
  • onInsert/onUpdate — Delegates to VacationService.validate() for business rule validation (conflict detection, remaining leave days)
  • afterInsert/afterUpdate/afterDelete/afterUndelete — Triggers VacationSendMailService.checkAndSendMail() for e-mail notifications
  • afterLoad — Redacts comment field for users without update access (data privacy)

Query Layer

  • getVacationForPeriod(employeeId, start, end, withSpecial) — JPQL query for vacation entries overlapping a date range for a specific employee
  • getActiveVacationForYear(employee, year, withSpecial) — Year-bound query using January 1 to December 31
  • getOpenLeaveApplicationsForEmployee(employee) — Count of IN_PROGRESS entries where given employee is manager
  • select(filter) — Overridden to support VacationFilter with employee/replacement/manager joins and VacationMode post-filtering

SQL Notes

The DAO uses META_SQL and META_SQL_WITH_SPECIAL companion constants to toggle inclusion of special vacation entries. Sort defaults to employee firstname/lastname ascending and startDate descending. An entity graph (VacationDO.ENTITY_GRAPH_WITH_OTHER_REPLACEMENTIDS) ensures otherReplacements collection is loaded with id-only projections.

Design Rationale

Access control is implemented in the DAO layer rather than service layer to enforce security at the persistence boundary — even direct DAO calls through BaseDao are protected. The status machine is embedded here because status transitions directly affect write access decisions. Mail notifications are triggered in after* hooks (post-commit) to ensure the database state is consistent before sending notifications. The comment redaction in afterLoad implements field-level security for data privacy compliance.
