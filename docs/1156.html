1156: VacationDO.kt

Entity, projectforge-business/src/main/kotlin/org/projectforge/business/vacation/model/VacationDO.kt
JPA entity representing an employee vacation/leave request with employee, manager, replacement, status, and date range fields.

Architecture

VacationDO extends DefaultBaseDO (which provides id, created, lastUpdate, deleted) and maps to table t_employee_vacation. It is annotated with @Indexed for Hibernate Search full-text indexing and carries JPA indexes on employee_id and manager_id.

JSON Serialization

Employee references (employee, replacement, manager) use @JsonSerialize(using = IdOnlySerializer::class) to serialize only the entity ID. The otherReplacements set uses @JsonSerialize(using = IdsOnlySerializer::class) for a list of IDs. This prevents JSON circular references and reduces payload size.

Transient Helpers

  • getVacationmode() — Determines whether the current user is the vacationer (OWN), manager (MANAGER), a replacement (REPLACEMENT), or other. Checks ThreadLocalUserContext.
  • allReplacements — Merges replacement and otherReplacements into a single deduplicated collection.
  • hasOverlap(other) / isInBetween(date) — Date overlap checks used by conflict detection in VacationService.

Named Queries & Entity Graph

FIND_CURRENT_AND_FUTURE named query selects vacations where endDate >= :endDate AND status IN :statusList AND deleted=false. The ENTITY_GRAPH_WITH_OTHER_REPLACEMENTIDS graph loads otherReplacements with only ID attribute nodes to optimize queries that need to check replacement coverage without loading full employee objects.

Design Rationale

All employee relationships use LAZY fetch to avoid N+1 query problems. The status getter has a null-guard defaulting to IN_PROGRESS for safety. The vacationmode field is legacy (marked private, used by Wicket pages). The composite allReplacements getter simplifies callers that need to iterate all substitutes without worrying about the distinction between primary and secondary replacements. The @AUserRightId("EMPLOYEE_VACATION") annotation with checkAccess = false indicates access control is handled at the DAO level rather than through the annotation framework.
