Prueba de integración para el control de acceso de DataTransfer — verifica que administradores, miembros de grupo y usuarios individuales tengan los derechos de acceso correctos a los archivos. Extiende AbstractTestBase que proporciona inyección de contexto Spring (@Autowired), cambio de usuario (logon()) e inicialización del repositorio de prueba JCR.

Configuración de la prueba

  • Beans de Spring inyectados: DataTransferTestService (crea áreas de prueba y usuarios), DataTransferPageRest (controlador REST bajo prueba)
  • Dos usuarios de prueba (testUser1, testUser2) creados mediante DataTransferTestService
  • Repositorio de prueba JCR: initJCRTestRepo(MODUL_NAME, "accessTestRepo") — proporciona un repositorio de contenido Jackrabbit en espacio aislado para pruebas de adjuntos de archivos
  • Inicialización diferida: initialize() se llama en el primer uso (no @PostConstruct — la base de datos no está lista en ese momento), crea el área de prueba

Cobertura de la prueba

Las pruebas utilizan DataTransferPageRest directamente — el controlador REST interno (no el público en #100) — para verificar la lógica de control de acceso a nivel de API:

  • Acceso de administrador: testUser1 configurado como administrador — debe tener CRUD completo en el área
  • Acceso de grupo: testUser2 agregado a accessGroupIds — debe tener acceso a archivos
  • Acceso a nivel de usuario: usuarios específicos en accessUserIds pueden acceder a archivos
  • Sin acceso: los usuarios que no están en ninguna lista de acceso deben ser denegados
  • Acceso público: verifica que las banderas external_download_enabled / external_upload_enabled funcionen

Dependencias

  • DataTransferPageRest — el controlador REST interno bajo prueba
  • DataTransferTestService — ayudante de prueba que pre-puebla la BD y JCR
  • AbstractTestBase — base de prueba Spring Boot de ProjectForge (rollback de transacciones BD, simulación de usuario)
  • FileObject (JCR) — objetos de archivo simulados para pruebas de adjuntos
