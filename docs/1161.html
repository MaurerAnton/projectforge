1161: VacationService.kt

Service, projectforge-business/src/main/kotlin/org/projectforge/business/vacation/service/VacationService.kt
Core business logic for vacation management: statistics calculation, remaining leave carry-over, conflict detection, validation, and average working time analysis.

Architecture

VacationService is the central orchestrator of vacation business logic. It coordinates VacationDao, EmployeeDao, EmployeeService, RemainingLeaveDao, LeaveAccountEntryDao, ConfigurationService, and the ConflictingVacationsCache. All complex calculations (working days, remaining leave, annual leave proration) live here, keeping the DAO focused on persistence and access control.

Vacation Statistics Engine

getVacationStats(employee, year, ...) is the central computation method. It runs in a transaction (to allow RemainingLeaveDao writes) and builds a VacationStats object containing:

  • vacationDaysInYearFromContract — annual leave entitlement from employee contract (prorated for mid-year joins/leaves via getAnnualLeaveDays)
  • vacationDaysInProgressAndApproved — sum of working days for IN_PROGRESS + APPROVED non-special entries
  • remainingLeaveFromPreviousYear — carried vacation days from the prior year (calculated recursively for year-1 if not yet persisted)
  • allocatedDaysInOverlapPeriod — vacation days consumed between Jan 1 and the end of the carry-over period (e.g. March 31)
  • specialVacationDaysApproved/InProgress — separate tracking for special leave
  • leaveAccountEntries — manual adjustments from leave account

Remaining Leave Carry-Over

The overlap period (January 1 to ConfigurationService.getEndOfCarryVacationOfPreviousYear(year), typically March 31) defines when carried vacation from the previous year can be used. After this date, carried days are lost. allocatedDaysInOverlapPeriod subtracts vacation taken in this window from the carried balance.

Annual Leave Proration

getAnnualLeaveDays(employee, year) adjusts the full-year entitlement based on join/leave dates. If the employee joined in the given year, only months from the join month to December count (a month counts if joined by the 14th). If the employee left in the given year, only months from January to the leave month count (counts if left on/after the 15th). The result is rounded with HALF_UP to full days.

Working Days Calculation

The companion object's getVacationDays(startDate, endDate, halfDayBegin, halfDayEnd, periodBegin, periodEnd) computes the number of working days in a vacation period using PFDayUtils.getNumberOfWorkingDays(). Half-day flags subtract 0.5 from the first/last day. If a period boundary trims the vacation range, the corresponding half-day flag is disabled (it no longer applies at the boundary).

Conflict Detection

getVacationOverlaps(vacation) checks whether all substitutes (replacement + otherReplacements) have overlapping vacations during the requested period. It calls checkConflict() which iterates day-by-day through the vacation period: for each day, if every substitute also has a vacation, a conflict is flagged. The result is cached in ConflictingVacationsCache.

Validation

validate(vacation, dbVacation, throwException) delegates to VacationValidator.validate() which checks for business rule violations (insufficient remaining leave, date consistency, etc.). Returns an optional error key.

Average Working Time

getAverageWorkingTimeStats(user, startOfWorkContract, date) computes average working hours per working day over the last 3 months, used for students and employees with flexible hours. It iterates monthly time sheet reports via EmployeeService.getReportOfMonth().

Design Rationale

Statistics calculation is transactional to ensure that the first calculation of remaining leave for a given year is atomically persisted (avoiding race conditions). The recursive call pattern for previous-year stats ensures carry-over is always computed from the source year before being consumed. Working days are computed via PFDayUtils rather than simple date subtraction to account for weekends and holidays. The day-by-day conflict check is O(n*m) but bounded by the vacation period length (typically <30 days) and the number of substitutes (<10), making it acceptable for on-demand computation.
