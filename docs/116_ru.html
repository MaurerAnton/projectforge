Интеграционный тест для DataTransferAuditDao — проверяет управление очередью DAO аудита, отслеживание уведомлений и получение записей. Расширяет AbstractTestBase с Spring-автосвязыванием DAO и recreateDataBase() для изоляции тестов.

Методы тестов (из анализа исходного кода)

  • removeFromQueueTest() — создаёт записи аудита с разными временными метками, проверяет, что internalGetEntriesByAreaId() возвращает все 3, затем тестирует логику получения очереди: записи старше порога должны быть доступны для уведомления, недавние записи должны оставаться в очереди
  • Тесты используют PFDateTime.now().minus(D, ChronoUnit.DAYS/MINUTES) для имитации записей аудита со сдвигом во времени
  • internalGetQueuedEntriesByAreaId() — фильтрованный запрос, возвращающий только записи, ожидающие уведомления
  • Проверяет переход флага notified: в очереди → уведомлено → удалено из очереди

Настройка теста

  • @Autowired DataTransferAuditDao — тестируемый DAO (управляет таблицей t_plugin_datatransfer_audit)
  • @Autowired DataTransferAreaDao — внедрён только для удовлетворения зависимости DataTransferAuditDao.dataTransferAreaDao
  • override fun beforeAll() — вызывает recreateDataBase() для очистки тестовых данных от других тестовых классов
  • init { DataTransferTestService.addPluginEntitiesForTestMode() } — регистрирует сущности плагина в слое персистентности

Система очереди аудита

Очередь аудита — это механизм для уведомлений наблюдателей (см. шаблон письма #112):

  1. Действия с файлами (загрузка/скачивание/удаление) вызывают dataTransferAuditDao.insert() с notified=false
  2. Плановое задание вызывает internalGetQueuedEntriesByAreaId() для поиска неуведомлённых записей
  3. После отправки писем задание помечает записи как notified=true (через removeFromQueue())
  4. Старые записи (>30 дней) периодически очищаются
