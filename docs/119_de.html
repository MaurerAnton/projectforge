Reiner Unit-Test für die Logik der Benachrichtigungsempfänger – überprüft, wer für jeden Ereignistyp benachrichtigt wird. Im Gegensatz zu DataTransferNotificationMailTest (der die gesamte Mail-Pipeline testet), isoliert dieser Test den Algorithmus zur Empfängerauswahl. Erweitert nicht AbstractTestBase – läuft ohne Spring-Kontext, was ihn schnell macht.

Testmethode: registerRecipientsTest()

Verwendet eine Hilfsfunktion testAudit(uploadUserId, byUserId, eventType, observerIds, expected), die:

  1. Mock-PFUserDO-Objekte für den Hochlader, den ausführenden Benutzer und Beobachter erstellt
  2. Ein Audit-Ereignis simuliert, indem die Benachrichtigungslogik direkt aufgerufen wird
  3. Bestätigt, dass nur die erwartete Menge an Beobachter-IDs eine Benachrichtigung erhält

Getestete Benachrichtigungsregeln

  • UPLOAD durch einen anderen Benutzer: Alle Beobachter außer dem Hochlader sollten benachrichtigt werden (der Hochlader weiß bereits, dass er hochgeladen hat)
  • UPLOAD durch sich selbst: Niemand sollte benachrichtigt werden (observerIds = [1,2,3], uploadUserId = 1, byUserId = 1 → erwartet = [2,3])
  • DELETE durch den Beobachter selbst: Der löschende Beobachter sollte keine Benachrichtigung über seine eigene Aktion erhalten
  • DOWNLOAD durch einen externen Benutzer: Alle Beobachter sollten benachrichtigt werden (externer Benutzer ist kein Beobachter)
  • RENAME: Beobachter werden benachrichtigt, der Hochlader wird ausgeschlossen, wenn er derjenige ist, der umbenennt

Die Invariante: Man wird nie über die eigenen Aktionen benachrichtigt – nur die Aktivitäten anderer lösen Benachrichtigungen aus.

Entwurfshinweis

Dies ist ein Unit-Test (keine Datenbank, kein JCR, kein Spring), der nur die Logik der Benachrichtigungsempfänger testet. Die Hilfsfunktion testAudit ruft die Benachrichtigungsmethode direkt mit vorbereiteten Eingaben auf. Der eigentliche DataTransferNotificationJob + die Mail-Darstellung werden in DataTransferNotificationMailTest getestet. Diese Trennung macht den Test der Benachrichtigungslogik schnell (Millisekunden vs. Sekunden für Integrationstests).
