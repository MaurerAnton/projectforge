Prueba unitaria pura para la lógica de destinatarios de notificaciones de observadores — verifica quién recibe notificaciones para cada tipo de evento. A diferencia de DataTransferNotificationMailTest (que prueba el pipeline completo de correo), esta prueba aísla el algoritmo de selección de destinatarios. No extiende AbstractTestBase — se ejecuta sin contexto Spring, lo que la hace rápida.

Método de prueba: registerRecipientsTest()

Utiliza un ayudante testAudit(uploadUserId, byUserId, eventType, observerIds, expected) que:

  1. Crea objetos mock PFUserDO para el subidor, el usuario que realiza la acción y los observadores
  2. Simula un evento de auditoría llamando directamente a la lógica de notificación
  3. Afirma que solo el conjunto esperado de IDs de observadores recibe una notificación

Reglas de notificación probadas

  • SUBIDA por otro usuario: todos los observadores excepto el subidor deben ser notificados (el subidor ya sabe que subió)
  • SUBIDA por uno mismo: nadie debe ser notificado (observerIds = [1,2,3], uploadUserId = 1, byUserId = 1 → esperado = [2,3])
  • ELIMINACIÓN por el propio observador: el observador que elimina no debe recibir una notificación sobre su propia acción
  • DESCARGA por usuario externo: todos los observadores deben ser notificados (el usuario externo no es un observador)
  • RENOMBRAR: los observadores son notificados, el subidor excluido si es quien renombra

El invariante: nunca te notifican sobre tus propias acciones — solo la actividad de otras personas desencadena notificaciones.

Nota de diseño

Esta es una prueba unitaria (sin base de datos, sin JCR, sin Spring) que prueba solo la lógica de destinatarios de notificaciones. El ayudante testAudit llama directamente al método de notificación con entradas preparadas. El DataTransferNotificationJob real + la representación del correo se prueban en DataTransferNotificationMailTest. Esta separación hace que la prueba de lógica de notificaciones sea rápida (milisegundos frente a segundos para pruebas de integración).
