Test unitaire pur pour la logique de sélection des destinataires des notifications — vérifie qui reçoit une notification pour chaque type d'événement. Contrairement à DataTransferNotificationMailTest (qui teste le pipeline complet des e-mails), ce test isole l'algorithme de sélection des destinataires. N'étend pas AbstractTestBase — s'exécute sans contexte Spring, ce qui le rend rapide.

Méthode de test : registerRecipientsTest()

Utilise une fonction d'aide testAudit(uploadUserId, byUserId, eventType, observerIds, expected) qui :

  1. Crée des objets mock PFUserDO pour le téléchargeur, l'utilisateur effectuant l'action et les observateurs
  2. Simule un événement d'audit en appelant directement la logique de notification
  3. Vérifie que seul l'ensemble attendu d'ID d'observateurs reçoit une notification

Règles de notification testées

  • TÉLÉCHARGEMENT par un autre utilisateur : tous les observateurs sauf le téléchargeur doivent être notifiés (le téléchargeur sait déjà qu'il a téléchargé)
  • TÉLÉCHARGEMENT par soi-même : personne ne doit être notifié (observerIds = [1,2,3], uploadUserId = 1, byUserId = 1 → attendu = [2,3])
  • SUPPRESSION par l'observateur lui-même : l'observateur qui supprime ne doit pas recevoir de notification concernant sa propre action
  • TÉLÉCHARGEMENT par un utilisateur externe : tous les observateurs doivent être notifiés (l'utilisateur externe n'est pas un observateur)
  • RENOMMAGE : les observateurs sont notifiés, le téléchargeur est exclu si c'est lui qui renomme

L'invariant : vous n'êtes jamais notifié de vos propres actions — seules les activités des autres déclenchent des notifications.

Note de conception

Ceci est un test unitaire (pas de base de données, pas de JCR, pas de Spring) qui teste uniquement la logique de sélection des destinataires des notifications. La fonction d'aide testAudit appelle directement la méthode de notification avec des entrées préparées. Le DataTransferNotificationJob réel + le rendu des e-mails sont testés dans DataTransferNotificationMailTest. Cette séparation rend le test de la logique de notification rapide (millisecondes contre secondes pour les tests d'intégration).
