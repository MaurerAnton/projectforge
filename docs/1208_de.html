Zentraler Job-Scheduler und Lebenszyklus-Manager für AbstractJob. Behandelt Job-Registrierung, Auswertung der Warteschlangenstrategie, koroutinenbasierte Ausführung, Timeout-Erzwingung, Bereinigung beendeter Jobs sowie Health-Check-Überwachung per E-Mail-Benachrichtigungen. Implementiert ShutdownListener, um laufende Jobs beim Herunterfahren der Anwendung ordnungsgemäß abzubrechen.

Architektur

Klassenübersicht

  • @Service — Spring-verwalteter Singleton
  • ShutdownListener — registriert über ShutdownService in @PostConstruct
  • Verwaltet eine List<AbstractJob> als Job-Registry

Job-Lebenszyklus-Management

MethodeBeschreibung
addJob(job)Registriert den Job, startet eine Koroutine via runBlocking { launch { ... } }, die auf die Freigabe der Warteschlange wartet und dann job.start() aufruft
tidyUp()Wird jede Minute von JobHandlerScheduler aufgerufen; bricht abgelaufene Jobs ab, entfernt alte beendete Jobs
cancelJob(job)Bricht den Job ab, wenn der Benutzer Schreibzugriff hat; ruft job.cancel() auf
shutdown()Bricht alle laufenden Jobs beim Herunterfahren der Anwendung ab und wartet auf deren Beendigung

Auswertung der Warteschlangenstrategie

Die Methode addJob startet eine Koroutine, die:

  1. Bis zu 10.000 Mal iteriert (Paranoia-Zähler, max. 10.000 Sekunden Wartezeit)
  2. Alle vorhandenen Jobs auf Blockierung prüft via other.isBlocking(job)
  3. Bei Blockierung mit REFUSE-Strategie den Job als REFUSED markiert (errorCode: REFUSED_BY_ANOTHER_RUNNING_JOB)
  4. Bei Blockierung mit PER_QUEUE-Strategie den Status auf WAITING setzt und 1000ms verzögert
  5. Wenn keine Blockierungen gefunden werden, den Status auf RUNNING setzt und die Ausführung startet
  6. Wenn die Schleife erschöpft ist, den Job als FAILED markiert (errorCode: TIMEOUT_WHILE_WAITING)

Health-Überwachung

  • checkStatus() — überprüft, ob tidyUp() innerhalb der letzten 5 Minuten aufgerufen wurde
  • reportErrorMail(message) — sendet eine E-Mail an die Support-Adresse via SendMail unter Verwendung der Groovy-Vorlage mail/feedback.txt

Koroutinen-Kontextweitergabe

Beim Starten der Job-Koroutine werden folgende Kontexte weitergegeben:

  • userContext — ThreadLocalUserContext.userContextAsContextElement (bewahrt den angemeldeten Benutzer)
  • localeContext — ThreadLocalUserContext.localeAsContextElement (bewahrt das Gebietsschema für i18n)
  • mdcContext — MDCContext() (bewahrt SLF4J-MDC für die Protokollierung)

Bereinigungskonstanten

  • KEEP_TERMINATED_JOBS_INTERVALL_MS = 1 Stunde (Constants.MILLIS_PER_HOUR)
