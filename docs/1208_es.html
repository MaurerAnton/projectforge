#1208: JobHandler.kt

projectforge-business/src/main/kotlin/org/projectforge/framework/jobs/JobHandler.kt Servicio Spring, projectforge-business/src/main/kotlin/org/projectforge/framework/jobs/JobHandler.kt 290 líneas · 228 código · 40 comentarios · 22 en blanco
Planificador central de trabajos y gestor del ciclo de vida para AbstractJob. Gestiona el registro de trabajos, la evaluación de la estrategia de cola, la ejecución basada en corrutinas, la aplicación de tiempos de espera, la limpieza de trabajos terminados y la monitorización del estado mediante alertas por correo electrónico. Implementa ShutdownListener para cancelar trabajos en ejecución de forma ordenada al apagar la aplicación.

Arquitectura

Resumen de la clase

  • @Service — Singleton gestionado por Spring
  • ShutdownListener — registrado a través de ShutdownService en @PostConstruct
  • Mantiene una List<AbstractJob> como registro de trabajos

Gestión del ciclo de vida del trabajo

MétodoDescripción
addJob(trabajo)Registra el trabajo, lanza una corrutina mediante runBlocking { launch { ... } } que espera a que la cola se despeje y luego llama a trabajo.start()
tidyUp()Se ejecuta cada minuto mediante JobHandlerScheduler; cancela trabajos con tiempo de espera agotado, elimina trabajos terminados antiguos
cancelJob(trabajo)Cancela el trabajo si el usuario tiene acceso de escritura; llama a trabajo.cancel()
shutdown()Cancela y espera a todos los trabajos en ejecución al apagar la aplicación

Evaluación de la estrategia de cola

El método addJob lanza una corrutina que:

    <>Itera hasta 10.000 veces (contador de paranoia, máximo 10.000 segundos de espera)
  1. Comprueba todos los trabajos existentes para ver si bloquean mediante otro.isBlocking(trabajo)
  2. Si está bloqueado con estrategia REFUSE, marca el trabajo como RECHAZADO (código de error: REFUSED_BY_ANOTHER_RUNNING_JOB)
  3. Si está bloqueado con estrategia PER_QUEUE, establece el estado como WAITING y retrasa 1000ms
  4. Si no se encuentran bloqueos, establece el estado como RUNNING e inicia la ejecución
  5. Si el bucle se agota, marca el trabajo como FALLIDO (código de error: TIMEOUT_WHILE_WAITING)

Monitorización del estado

  • checkStatus() — verifica que tidyUp() se haya llamado en los últimos 5 minutos
  • reportErrorMail(mensaje) — envía un correo electrónico a la dirección de soporte mediante SendMail usando la plantilla Groovy mail/feedback.txt

Propagación del contexto de corrutina

Al lanzar la corrutina del trabajo, se propagan los siguientes contextos:

  • userContext — ThreadLocalUserContext.userContextAsContextElement (preserva el usuario conectado)
  • localeContext — ThreadLocalUserContext.localeAsContextElement (preserva la configuración regional para i18n)
  • mdcContext — MDCContext() (preserva el MDC de SLF4J para el registro)

Constantes de limpieza

  • KEEP_TERMINATED_JOBS_INTERVALL_MS = 1 hora (Constants.MILLIS_PER_HOUR)
