#1208 : JobHandler.kt

projectforge-business/src/main/kotlin/org/projectforge/framework/jobs/JobHandler.kt Service Spring, projectforge-business/src/main/kotlin/org/projectforge/framework/jobs/JobHandler.kt 290 lignes · 228 code · 40 commentaires · 22 vides
Ordonnanceur central de tâches et gestionnaire de cycle de vie pour AbstractJob. Gère l'enregistrement des tâches, l'évaluation de la stratégie de file d'attente, l'exécution basée sur les coroutines, l'application des délais d'attente, le nettoyage des tâches terminées et la surveillance de l'état de santé via des alertes par e-mail. Implémente ShutdownListener pour annuler les tâches en cours d'exécution de manière gracieuse lors de l'arrêt de l'application.

Architecture

Aperçu de la classe

  • @Service — Singleton géré par Spring
  • ShutdownListener — enregistré via ShutdownService dans @PostConstruct
  • Maintient une List<AbstractJob> comme registre des tâches

Gestion du cycle de vie des tâches

MéthodeDescription
addJob(job)Enregistre la tâche, lance une coroutine via runBlocking { launch { ... } } qui attend le dégagement de la file d'attente puis appelle job.start()
tidyUp()Appelée chaque minute par JobHandlerScheduler ; annule les tâches en timeout, supprime les anciennes tâches terminées
cancelJob(job)Annule la tâche si l'utilisateur a un accès en écriture ; appelle job.cancel()
shutdown()Annule et attend la fin de toutes les tâches en cours lors de l'arrêt de l'application

Évaluation de la stratégie de file d'attente

La méthode addJob lance une coroutine qui :

  1. Itère jusqu'à 10 000 fois (compteur de sécurité, attente max de 10 000 secondes)
  2. Vérifie toutes les tâches existantes pour un blocage via other.isBlocking(job)
  3. Si bloqué avec la stratégie REFUSE, marque la tâche comme REFUSÉE (errorCode : REFUSED_BY_ANOTHER_RUNNING_JOB)
  4. Si bloqué avec la stratégie PER_QUEUE, définit le statut sur WAITING et attend 1000 ms
  5. Si aucun blocage trouvé, définit le statut sur RUNNING et démarre l'exécution
  6. Si la boucle est épuisée, marque la tâche comme ÉCHOUÉE (errorCode : TIMEOUT_WHILE_WAITING)

Surveillance de l'état de santé

  • checkStatus() — vérifie que tidyUp() a été appelé dans les 5 dernières minutes
  • reportErrorMail(message) — envoie un e-mail à l'adresse de support via SendMail en utilisant le template Groovy mail/feedback.txt

Propagation du contexte de coroutine

Lors du lancement de la coroutine de tâche, les contextes suivants sont propagés :

  • userContext — ThreadLocalUserContext.userContextAsContextElement (préserve l'utilisateur connecté)
  • localeContext — ThreadLocalUserContext.localeAsContextElement (préserve la locale pour l'i18n)
  • mdcContext — MDCContext() (préserve le MDC SLF4J pour la journalisation)

Constantes de nettoyage

  • KEEP_TERMINATED_JOBS_INTERVALL_MS = 1 heure (Constants.MILLIS_PER_HOUR)
