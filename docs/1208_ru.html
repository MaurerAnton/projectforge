#1208: JobHandler.kt

Центральный планировщик заданий и менеджер жизненного цикла для AbstractJob. Обрабатывает регистрацию заданий, оценку стратегии очереди, выполнение на основе корутин, контроль времени ожидания, очистку завершённых заданий и мониторинг работоспособности с оповещениями по электронной почте. Реализует ShutdownListener для корректной отмены выполняющихся заданий при завершении приложения.

Архитектура

Обзор класса

  • @Service — управляемый Spring синглтон
  • ShutdownListener — регистрируется через ShutdownService в @PostConstruct
  • Содержит List<AbstractJob> в качестве реестра заданий

Управление жизненным циклом заданий

МетодОписание
addJob(job)Регистрирует задание, запускает корутину через runBlocking { launch { ... } }, которая ожидает освобождения очереди, затем вызывает job.start()
tidyUp()Вызывается каждую минуту JobHandlerScheduler; отменяет задания с истекшим временем ожидания, удаляет старые завершённые задания
cancelJob(job)Отменяет задание, если у пользователя есть права на запись; вызывает job.cancel()
shutdown()Отменяет и ожидает завершения всех выполняющихся заданий при остановке приложения

Оценка стратегии очереди

Метод addJob запускает корутину, которая:

  1. Выполняет до 10 000 итераций (счётчик паранойи, максимум 10 000 секунд ожидания)
  2. Проверяет все существующие задания на блокировку через other.isBlocking(job)
  3. При блокировке со стратегией REFUSE помечает задание как REFUSED (errorCode: REFUSED_BY_ANOTHER_RUNNING_JOB)
  4. При блокировке со стратегией PER_QUEUE устанавливает статус WAITING и задерживается на 1000 мс
  5. Если блокировок не найдено, устанавливает статус RUNNING и запускает выполнение
  6. Если цикл исчерпан, помечает задание как FAILED (errorCode: TIMEOUT_WHILE_WAITING)

Мониторинг работоспособности

  • checkStatus() — проверяет, что tidyUp() вызывался в течение последних 5 минут
  • reportErrorMail(message) — отправляет электронное письмо на адрес поддержки через SendMail с использованием шаблона Groovy mail/feedback.txt

Распространение контекста корутины

При запуске корутины задания распространяются следующие контексты:

  • userContext — ThreadLocalUserContext.userContextAsContextElement (сохраняет вошедшего пользователя)
  • localeContext — ThreadLocalUserContext.localeAsContextElement (сохраняет локаль для i18n)
  • mdcContext — MDCContext() (сохраняет SLF4J MDC для логирования)

Константы очистки

  • KEEP_TERMINATED_JOBS_INTERVALL_MS = 1 час (Constants.MILLIS_PER_HOUR)
