Prueba de integración para la capa REST pública (externa) de DataTransfer — la prueba más completa de DataTransfer con 227 líneas. Prueba el flujo de acceso anónimo: enlace externo → inicio de sesión → subida/descarga/eliminación → cierre de sesión, utilizando solicitudes HTTP simuladas y archivos JCR.

Componentes bajo prueba

  • DataTransferPublicSession (#101) — gestión de sesiones, protección contra fuerza bruta
  • DataTransferPublicPageRest — devuelve JSON de diseño de página para la interfaz de usuario React anónima
  • DataTransferPublicServicesRest (#100) — endpoints de subida, descarga, eliminación y descarga múltiple
  • LoginProtection — aplicación del desplazamiento temporal por fuerza bruta

Escenarios de prueba (~10 métodos de prueba)

  • Inicio de sesión con credenciales válidas: crea un área con external_download_enabled=true, externalAccessToken, externalPassword, llama a DataTransferPublicSession.login() — verifica que la sesión contenga datos del área
  • Inicio de sesión con contraseña incorrecta: verifica que LoginProtection incremente los intentos fallidos, y después de fallos repetidos se active el desplazamiento temporal
  • Bloqueo por fuerza bruta: después de suficientes fallos, login() devuelve el estado LOGIN_TIME_OFFSET — verificado llamando a login 3+ veces más rápido que la ventana de desplazamiento
  • Buzón personal excluido del acceso público: las áreas isPersonalBox() siempre devuelven LoginResultStatus.FAILED — la comprobación de paranoia en checkDataBaseEntry()
  • Subida: simula MultipartFile (envoltorio de archivo subido de Spring), llama al endpoint REST de subida, verifica que el ID del archivo aparezca en la lista ownedFiles
  • Descarga: sube un archivo como usuario externo, luego lo descarga — verifica que el contenido de InputStreamResource coincida
  • Eliminar archivo propio: verifica que isOwnerOfFile() devuelva verdadero y que la eliminación sea exitosa
  • No se puede eliminar el archivo de otro: el usuario externo2 intenta eliminar la subida del usuario1 — verifica que isOwnerOfFile() devuelva falso
  • Descarga múltiple: sube 3 archivos, descarga todos como ZIP — verifica que ZipInputStream contenga las 3 entradas
  • Fijación de sesión: verifica que después del inicio de sesión, el JSESSIONID cambie (sesión antigua invalidada, nueva sesión creada con datos de área transferidos)

Capa HTTP simulada

Utiliza Mockito para simular HttpServletRequest y HttpSession — crítico porque DataTransferPublicSession almacena datos directamente en atributos de sesión HTTP. La sesión simulada emula getSession(false), getSession(true), getAttribute("transferAreas"), setAttribute() e invalidate() — todo ejercitado en la prueba de fijación de sesión.

También simula MultipartFile para pruebas de subida y HttpServletResponse + ServletOutputStream → ByteArrayOutputStream para capturar contenido de descarga.
