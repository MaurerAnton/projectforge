Test d'intégration pour la couche REST publique (externe) DataTransfer — le test DataTransfer le plus complet avec 227 lignes. Teste le flux d'accès anonyme : lien externe → connexion → téléversement/téléchargement/suppression → déconnexion, en utilisant des requêtes HTTP mockées et des fichiers JCR.

Composants testés

  • DataTransferPublicSession (#101) — gestion de session, protection contre le brute-force
  • DataTransferPublicPageRest — renvoie le JSON de mise en page pour l'interface React anonyme
  • DataTransferPublicServicesRest (#100) — endpoints de téléversement, téléchargement, suppression, téléchargement multiple
  • LoginProtection — application du décalage temporel anti-brute-force

Scénarios de test (~10 méthodes de test)

  • Connexion avec identifiants valides : crée une zone avec external_download_enabled=true, externalAccessToken, externalPassword, appelle DataTransferPublicSession.login() — vérifie que la session contient les données de la zone
  • Connexion avec mot de passe erroné : vérifie que LoginProtection incrémente les tentatives échouées, et qu'après échecs répétés le décalage temporel s'active
  • Blocage par brute-force : après suffisamment d'échecs, login() retourne le statut LOGIN_TIME_OFFSET — vérifié en appelant login 3 fois ou plus plus rapidement que la fenêtre de décalage
  • Boîte personnelle exclue de l'accès public : les zones isPersonalBox() retournent toujours LoginResultStatus.FAILED — le contrôle de paranoïa dans checkDataBaseEntry()
  • Téléversement : mocke MultipartFile (wrapper de fichier téléversé Spring), appelle l'endpoint REST de téléversement, vérifie que l'ID du fichier apparaît dans la liste ownedFiles
  • Téléchargement : téléverse un fichier en tant qu'utilisateur externe, puis le télécharge — vérifie que le contenu de InputStreamResource correspond
  • Suppression de son propre fichier : vérifie que isOwnerOfFile() retourne true, et que la suppression réussit
  • Impossible de supprimer le fichier d'autrui : l'utilisateur externe2 tente de supprimer le téléversement de l'utilisateur1 — vérifie que isOwnerOfFile() retourne false
  • Téléchargement multiple : téléverse 3 fichiers, télécharge tout en ZIP — vérifie que ZipInputStream contient les 3 entrées
  • Fixation de session : vérifie qu'après connexion, le JSESSIONID change (ancienne session invalidée, nouvelle session créée avec les données de zone transférées)

Couche HTTP mockée

Utilise Mockito pour simuler HttpServletRequest et HttpSession — critique car DataTransferPublicSession stocke les données directement dans les attributs de session HTTP. La session mockée simule getSession(false), getSession(true), getAttribute("transferAreas"), setAttribute(), et invalidate() — tous utilisés dans le test de fixation de session.

Mocke également MultipartFile pour les tests de téléversement et HttpServletResponse + ServletOutputStream → ByteArrayOutputStream pour la capture du contenu téléchargé.
