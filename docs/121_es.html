#121: DataTransferTestService.kt

plugins/org.projectforge.plugins.datatransfer/src/test/kotlin/org/projectforge/plugins/datatransfer/DataTransferTestService.kt Ruta: plugins/...datatransfer/src/test/kotlin/.../DataTransferTestService.kt · Líneas: 222 · Tipo: Kotlin @Service — bean auxiliar de prueba 222 líneas · 175 código · 23 comentarios · 24 en blanco

Servicio de fixture de prueba compartido utilizado por cada prueba de integración de DataTransfer (#114, #115, #116, #117, #119). Proporciona métodos reutilizables para crear usuarios de prueba, áreas, entradas de auditoría, archivos simulados e interacciones HTTP simuladas. Registrado como un @Service de Spring para que todas las pruebas obtengan la misma instancia mediante @Autowired.

Métodos clave

  • addPluginEntitiesForTestMode() — método estático de compañía llamado en bloques init {} de todas las clases de prueba. Registra entidades del plugin DataTransfer (DataTransferAreaDO, etc.) con MyJpaWithExtLibrariesScanner — requerido porque el modo de prueba no escanea automáticamente los paquetes del plugin
  • createPersonalBox(user) — asegura que exista un buzón personal para el usuario dado (llama a dataTransferAreaDao.ensurePersonalBox())
  • createArea(adminUser, ...) — método fábrica que crea un DataTransferAreaDO con administradores, observadores, caducidad, token de acceso/contraseña configurables
  • createTestUsers() / createTestUser(name) — crea instancias de PFUserDO para escenarios de prueba
  • createTestGroup() — crea un GroupDO para pruebas de acceso grupal
  • createMockFile() — crea un FileObject con contenido simulado (usa ByteArrayInputStream para los datos del archivo)
  • uploadFiles() — sube uno o más archivos a un área mediante AttachmentsService de JCR
  • createAuditEntry() — inserta un registro de auditoría con tipo de evento, usuario y nombre de archivo especificados
  • createMockHttpSession() — crea Mockito.mock(HttpSession::class.java) con un mapa de atributos configurable para pruebas basadas en sesión
  • unzipAndVerify(ZipInputStream) — extrae un flujo ZIP y verifica el conteo/nombres de archivos (usado en pruebas de descarga múltiple)

Patrón de diseño

Esto sigue el patrón Objeto de Servicio de Prueba — un bean de Spring que encapsula la configuración de datos de prueba, manteniendo las clases de prueba enfocadas en aserciones. Todas las pruebas de DataTransfer autoinyectan este servicio, llaman a sus métodos fábrica para crear su escenario de prueba y luego verifican el comportamiento. La llamada estática addPluginEntitiesForTestMode() en init {} asegura que el registro de entidades ocurra antes de cualquier método @PostConstruct o hooks de ciclo de vida @BeforeEach/beforeAll().

El método @PostConstruct postConstruct() llama a pluginAdminService.initializeAllPluginsForUnitTest() — asegura que todos los plugins (no solo DataTransfer) tengan sus entidades y servicios inicializados antes de que se ejecute cualquier prueba.
