Service de fixture de test partagé utilisé par chaque test d’intégration DataTransfer (#114, #115, #116, #117, #119). Fournit des méthodes réutilisables pour créer des utilisateurs de test, des zones, des entrées d’audit, des fichiers simulés et des interactions HTTP simulées. Enregistré en tant que @Service Spring afin que tous les tests obtiennent la même instance via @Autowired.

Méthodes clés

  • addPluginEntitiesForTestMode() — méthode statique de compagnon appelée dans les blocs init {} de toutes les classes de test. Enregistre les entités du plugin DataTransfer (DataTransferAreaDO, etc.) auprès de MyJpaWithExtLibrariesScanner — nécessaire car le mode test ne scanne pas automatiquement les packages des plugins
  • createPersonalBox(user) — garantit qu’une boîte personnelle existe pour l’utilisateur donné (appelle dataTransferAreaDao.ensurePersonalBox())
  • createArea(adminUser, ...) — méthode d’usine créant un DataTransferAreaDO avec administrateurs, observateurs, expiration, jeton d’accès/mot de passe configurables
  • createTestUsers() / createTestUser(name) — crée des instances PFUserDO pour les scénarios de test
  • createTestGroup() — crée un GroupDO pour les tests d’accès par groupe
  • createMockFile() — crée un FileObject avec un contenu simulé (utilise ByteArrayInputStream pour les données du fichier)
  • uploadFiles() — télécharge un ou plusieurs fichiers vers une zone via le AttachmentsService JCR
  • createAuditEntry() — insère un enregistrement d’audit avec un type d’événement, un utilisateur et un nom de fichier spécifiés
  • createMockHttpSession() — crée Mockito.mock(HttpSession::class.java) avec une carte d’attributs configurable pour les tests basés sur les sessions
  • unzipAndVerify(ZipInputStream) — extrait un flux ZIP et vérifie le nombre/noms des fichiers (utilisé par les tests de téléchargement multiple)

Patron de conception

Ceci suit le patron Objet de service de test — un bean Spring qui encapsule la configuration des données de test, permettant aux classes de test de se concentrer sur les assertions. Tous les tests DataTransfer injectent automatiquement ce service, appellent ses méthodes d’usine pour créer leur scénario de test, puis vérifient le comportement. L’appel statique addPluginEntitiesForTestMode() dans init {} garantit que l’enregistrement des entités a lieu avant toute méthode @PostConstruct ou tout hook de cycle de vie @BeforeEach/beforeAll().

La méthode @PostConstruct postConstruct() appelle pluginAdminService.initializeAllPluginsForUnitTest() — garantit que tous les plugins (pas seulement DataTransfer) ont leurs entités et services initialisés avant l’exécution de tout test.
