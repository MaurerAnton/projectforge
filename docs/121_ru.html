#121: DataTransferTestService.kt

plugins/org.projectforge.plugins.datatransfer/src/test/kotlin/org/projectforge/plugins/datatransfer/DataTransferTestService.kt Путь: plugins/...datatransfer/src/test/kotlin/.../DataTransferTestService.kt · Строк: 222 · Тип: Kotlin @Service — вспомогательный bean для тестов 222 строки · 175 кода · 23 комментария · 24 пустых

Общий сервис тестовых фикстур, используемый каждым интеграционным тестом DataTransfer (#114, #115, #116, #117, #119). Предоставляет переиспользуемые методы для создания тестовых пользователей, областей, записей аудита, имитации файлов и HTTP-взаимодействий. Зарегистрирован как Spring @Service, поэтому все тесты получают один и тот же экземпляр через @Autowired.

Ключевые методы

  • addPluginEntitiesForTestMode() — статический метод компаньона, вызываемый в блоках init {} всех тестовых классов. Регистрирует сущности плагина DataTransfer (DataTransferAreaDO и т.д.) в MyJpaWithExtLibrariesScanner — необходимо, так как тестовый режим не автосканирует пакеты плагинов
  • createPersonalBox(user) — гарантирует существование личного бокса для указанного пользователя (вызывает dataTransferAreaDao.ensurePersonalBox())
  • createArea(adminUser, ...) — фабричный метод, создающий DataTransferAreaDO с настраиваемыми администраторами, наблюдателями, сроком действия, токеном доступа/паролем
  • createTestUsers() / createTestUser(name) — создаёт экземпляры PFUserDO для тестовых сценариев
  • createTestGroup() — создаёт GroupDO для тестов группового доступа
  • createMockFile() — создаёт FileObject с имитацией содержимого (использует ByteArrayInputStream для данных файла)
  • uploadFiles() — загружает один или несколько файлов в область через JCR AttachmentsService
  • createAuditEntry() — вставляет запись аудита с указанным типом события, пользователем, именем файла
  • createMockHttpSession() — создаёт Mockito.mock(HttpSession::class.java) с настраиваемой картой атрибутов для тестов на основе сессии
  • unzipAndVerify(ZipInputStream) — извлекает ZIP-поток и проверяет количество/имена файлов (используется в тестах множественной загрузки)

Шаблон проектирования

Это реализует паттерн Тестовый сервисный объект — Spring-бин, инкапсулирующий настройку тестовых данных, позволяя тестовым классам сосредоточиться на проверках. Все тесты DataTransfer автоматически подключают этот сервис, вызывают его фабричные методы для создания тестового сценария, а затем проверяют поведение. Статический вызов addPluginEntitiesForTestMode() в init {} гарантирует, что регистрация сущностей происходит до любых методов @PostConstruct или хуков жизненного цикла @BeforeEach/beforeAll().

Метод @PostConstruct postConstruct() вызывает pluginAdminService.initializeAllPluginsForUnitTest() — гарантирует, что все плагины (не только DataTransfer) инициализируют свои сущности и сервисы до запуска любого теста.
