#1231: ExtendedBaseDO.kt

projectforge-business/src/main/kotlin/org/projectforge/framework/persistence/api/ExtendedBaseDO.kt Schnittstelle — Persistenz-Basiseinheit, projectforge-business/src/main/kotlin/org/projectforge/framework/persistence/api/ExtendedBaseDO.kt 63 Zeilen · 18 Code · 36 Kommentare · 9 leer
Erweitert BaseDO<I> um Soft-Delete- und Audit-Zeitstempelunterstützung. Fügt deleted (von MarkDeletableRecord), created-Zeitstempel, lastUpdate-Zeitstempel sowie einen recalculate()-Hook für die Berechnung abgeleiteter/transienter Felder vor der Anzeige oder Indizierung hinzu.

Architektur

Schnittstellenhierarchie

Serializable
  └── BaseDO<I : Serializable>
        └── ExtendedBaseDO<I : Serializable>
              (erweitert auch MarkDeletableRecord<I>)

Vertragsfelder & -methoden

MemberTypBeschreibung
deletedBoolean (Überschreibung)Soft-Delete-Flag. Wenn wahr, ist die Entität logisch gelöscht, verbleibt aber in der Datenbank. Von BaseDO überschrieben.
createdDate?Zeitstempel der ursprünglichen Erstellung. Wird automatisch über setCreated() gesetzt.
lastUpdateDate?Zeitstempel der letzten Änderung. Wird von der Persistenzschicht bei jedem Schreibvorgang automatisch aktualisiert. Wird automatisch über setLastUpdate() gesetzt.
recalculate()UnitHook für Berechnungen vor der Anzeige/nach dem Laden. Wird für transiente Felder verwendet, die aus persistenten Feldern berechnet werden (z. B. vollständiger Name aus Vor- und Nachname).
setCreated()UnitHilfsmethode: Setzt created auf die aktuelle Zeit
setLastUpdate()UnitHilfsmethode: Setzt lastUpdate auf die aktuelle Zeit

Verwendungskontext

Die meisten Domänenentitäten in ProjectForge implementieren ExtendedBaseDO anstelle des rohen BaseDO. Die BaseDao-Infrastruktur stützt sich auf diese Felder für:

  • Soft-Delete-Filterung: Das deleted-Flag wird von QueryFilter, MagicFilter und allen Listenseiten überprüft
  • Historieverfolgung: lastUpdate wird von der Hibernate-Envers-Integration und der Historiensuche verwendet
  • Prüfpfade: created und Änderungszeitstempel werden in Bearbeitungsformularen von Entitäten angezeigt
  • Neuberechnung: recalculate() wird von DAOs aufgerufen, bevor Entitäten an die UI-Ebene zurückgegeben werden

Relevante Annotationen

Implementierende Klassen annotieren diese Felder typischerweise mit JPA-Annotationen: @Basic, @Column für die Datenbankzuordnung; @PropertyInfo(i18nKey = "...") für das UI-Eigenschaftssystem.
