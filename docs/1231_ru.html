projectforge-business/src/main/kotlin/org/projectforge/framework/persistence/api/ExtendedBaseDO.kt Интерфейс — Базовая сущность персистентности, projectforge-business/src/main/kotlin/org/projectforge/framework/persistence/api/ExtendedBaseDO.kt 63 строки · 18 кода · 36 комментариев · 9 пустых
Расширяет BaseDO<I> поддержкой мягкого удаления и аудита временных меток. Добавляет deleted (из MarkDeletableRecord), временную метку created, временную метку lastUpdate и хук recalculate() для вычисления производных/транзиентных полей перед отображением или индексацией.

Архитектура

Иерархия интерфейсов

Serializable
  └── BaseDO<I : Serializable>
        └── ExtendedBaseDO<I : Serializable>
              (также расширяет MarkDeletableRecord<I>)

Поля и методы контракта

ЧленТипОписание
deletedBoolean (переопределение)Флаг мягкого удаления. Если true, сущность логически удалена, но сохраняется в базе данных. Переопределено из BaseDO.
createdDate?Временная метка первоначального создания. Устанавливается автоматически через setCreated().
lastUpdateDate?Временная метка последнего изменения. Автоматически обновляется слоем персистентности при каждой записи. Устанавливается автоматически через setLastUpdate().
recalculate()UnitХук для вычислений перед отображением/после загрузки. Используется для транзиентных полей, вычисляемых из постоянных полей (например, полное имя из имени+фамилии).
setCreated()UnitУдобный метод: устанавливает created в текущее время
setLastUpdate()UnitУдобный метод: устанавливает lastUpdate в текущее время

Контекст использования

Большинство доменных сущностей в ProjectForge реализуют ExtendedBaseDO, а не сырой BaseDO. Инфраструктура BaseDao полагается на эти поля для:

  • Фильтрации мягкого удаления: флаг deleted проверяется QueryFilter, MagicFilter и всеми страницами списков
  • Отслеживания истории: lastUpdate используется интеграцией Hibernate Envers и функцией поиска по истории
  • Аудиторских следов: created и временные метки изменений отображаются в формах редактирования сущностей
  • Пересчёта: recalculate() вызывается DAO перед возвратом сущностей на уровень UI

Соответствующие аннотации

Реализующие классы обычно аннотируют эти поля JPA-аннотациями: @Basic, @Column для маппинга базы данных; @PropertyInfo(i18nKey = "...") для системы свойств UI.
