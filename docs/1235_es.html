El modelo de filtro central para las páginas de lista y búsqueda de ProjectForge. Representa criterios de búsqueda definidos por el usuario como una colección de objetos MagicFilterEntry tipados, que admiten búsqueda por campo, búsqueda por rango, búsqueda de texto completo, búsqueda en historial, ordenación, paginación y filtrado de borrado lógico. Extiende AbstractFavorite para la persistencia de preferencias de usuario a través de UserPrefDao.

Arquitectura

Jerarquía de clases

AbstractFavorite (nombre, id)
  └── MagicFilter

Como AbstractFavorite, MagicFilter se puede guardar/cargar como una preferencia de filtro con nombre para cada usuario y cada tipo de entidad. La serialización JSON de Jackson se configura mediante @JsonTypeInfo para la deserialización polimórfica.

Estructura de MagicFilterEntry

Cada entrada tiene: field — el nombre de la propiedad de la entidad (o valor especial para búsqueda en historial), value — un objeto Value con value (exacto), fromValue/toValue (rango), values (lista de selección múltiple), id, label, displayName, synthetic — indica si la entrada es generada automáticamente (no creada por el usuario).

Campos de entrada especiales

  • "deleted" — se trata como el indicador de borrado en lugar de un filtro de campo normal
  • MODIFIED_HISTORY_VALUE / MODIFIED_INTERVAL / MODIFIED_BY_USER — búsqueda en historial de Hibernate Envers
  • "pageSize" — nombre heredado, se renombra automáticamente a paginationPageSize en MagicFilterProcessor

Serialización y persistencia

UserPrefDao almacena instancias de MagicFilter como JSON. El método clone() utiliza el mismo ObjectMapper para la clonación profunda. Después de la deserialización, se debe llamar a init() porque ciertos campos (como los nombres para mostrar de usuario) no se serializan.
