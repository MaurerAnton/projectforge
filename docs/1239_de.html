Die zentrale Datenbankabfragespezifikation für ProjectForge. Sammelt DBPredicate-Objekte, Sortiereigenschaften, Joins, Volltextsuchdirektiven, Historien-Suchparameter und Paginierungssteuerungen. Erkennt automatisch, welche Abfragestrategie verwendet werden soll (JPA Criteria API für indizierte Felder, Hibernate Search Volltext für nicht indizierte, Ergebnislisten-Filterung als Fallback). Dient als Brücke zwischen der Ausgabe von MagicFilterProcessor und der Abfrageausführung von BaseDao/DBFilter.

Architektur

Automatische Erkennung der Abfragestrategie

QueryFilter sammelt Prädikate, ohne die Ausführungsstrategie festzulegen. Die Klassen BaseDao und DBFilter bestimmen zur Abfragezeit, welcher Ansatz verwendet wird: - Criteria API (JPA): Für indizierte/typisierte Prädikate auf persistenten Feldern - Hibernate Search (Volltext): Für DBPredicate.FullSearch unter Verwendung des Lucene-Index - Ergebnislisten-Filterung: Als letztes Mittel für Prädikate, die nicht in SQL/HQL ausgedrückt werden können

Zeitraum-Komfort

setYearAndMonth(dateField, year, month) erstellt ein between-Prädikat für einen bestimmten Jahres-/Monatszeitraum. Wenn month <= 0, wird der gesamte Jahresbereich verwendet.

Legacy-Filter-Kompatibilität

Der Konstruktor akzeptiert einen optionalen BaseSearchFilter für die Abwärtskompatibilität. Er kopiert searchFields, deleted, searchString, modifiedSince, modifiedByUserId und maxRows aus dem Legacy-Filter.

Filter-Finalisierung

createDBFilter(): DBFilter materialisiert den angesammelten Zustand in ein DBFilter-Objekt und fügt das implizite deleted-Prädikat hinzu, falls es nicht bereits vorhanden ist. Dies ist der Punkt, an dem der QueryFilter in seine endgültige ausführbare Form konvertiert wird.
