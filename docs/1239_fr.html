La spécification centrale des requêtes de base de données pour ProjectForge. Accumule les objets DBPredicate, les propriétés de tri, les jointures, les directives de recherche en texte intégral, les paramètres de recherche d'historique et les contrôles de pagination. Détecte automatiquement la stratégie de requête à utiliser (API Criteria JPA pour les champs indexés, recherche en texte intégral Hibernate Search pour les champs non indexés, filtrage de la liste de résultats comme solution de repli). Sert de pont entre la sortie de MagicFilterProcessor et l'exécution des requêtes BaseDao/DBFilter.

Architecture

Détection automatique de la stratégie de requête

QueryFilter accumule les prédicats sans spécifier la stratégie d'exécution. Les classes BaseDao et DBFilter déterminent au moment de la requête quelle approche utiliser : - API Criteria (JPA) : Pour les prédicats indexés/typés sur les champs persistants - Hibernate Search (texte intégral) : Pour DBPredicate.FullSearch utilisant l'index Lucene - Filtrage de la liste de résultats : En dernier recours pour les prédicats qui ne peuvent pas être exprimés en SQL/HQL

Commodité de période temporelle

setYearAndMonth(champDate, annee, mois) construit un prédicat between pour une période année/mois spécifique. Si mois <= 0, la plage de l'année entière est utilisée.

Compatibilité avec les filtres hérités

Le constructeur accepte un BaseSearchFilter optionnel pour la rétrocompatibilité. Il copie searchFields, deleted, searchString, modifiedSince, modifiedByUserId et maxRows du filtre hérité.

Finalisation du filtre

createDBFilter(): DBFilter matérialise l'état accumulé dans un objet DBFilter, en ajoutant le prédicat implicite deleted s'il n'est pas déjà présent. C'est le point où le QueryFilter est converti en sa forme exécutable finale.
