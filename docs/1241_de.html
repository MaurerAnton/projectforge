#1241: CustomResultFilter.kt

Einfache Schnittstelle, die es DAO-Klassen ermöglicht, eine benutzerdefinierte Ergebnislisten-Filterung bereitzustellen. Implementierungen entscheiden pro Element, ob es in die endgültige Ergebnisliste aufgenommen werden soll, mit Zugriff auf bereits geschriebene Elemente für abhängigkeitsbasierte Entscheidungen.

Architektur

Eine generische Schnittstelle mit einer einzelnen Methode, die von BaseDao und der zugehörigen Persistenzinfrastruktur verwendet wird, um eine domänenspezifische Nachabfrage-Filterung zu ermöglichen, bevor eine Ergebnisliste an den Aufrufer zurückgegeben wird. Sie befindet sich im Paket api/impl zusammen mit DBPredicate, DBFilter und anderer Low-Level-Abfrageinfrastruktur.

Vertrag

fun match(list: MutableList<O>, element: O): Boolean
ParameterBeschreibung
listDie Ergebnisliste der bereits geschriebenen (akzeptierten) Elemente. Ermöglicht abhängigkeitsbasierte Filterung – z. B. ein Element ausschließen, wenn bereits ein „besseres“ Element existiert.
elementDas aktuelle Element, das auf Aufnahme geprüft wird.
Rückgabetrue, um das Element einzuschließen, false, um es auszuschließen.

Verwendungskontext

DAO-Klassen können bei Abfragen eine CustomResultFilter-Implementierung bereitstellen. Der Filter wird nach der Datenbankabfrage, aber vor der Rückgabe des Ergebnisses angewendet. Dies ist besonders nützlich für:

  • Adressdeduplizierung – Adressen überspringen, die bereits einen passenden Eintrag im Ergebnis haben
  • Validierung von Geschäftsregeln nach der Abfrage
  • Jedes Szenario, in dem SQL/HQL/Criteria API allein die Filterlogik nicht ausdrücken können
