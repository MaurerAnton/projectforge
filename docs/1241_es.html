Interfaz simple que permite a las clases DAO proporcionar filtrado personalizado de listas de resultados. Las implementaciones deciden por elemento si debe incluirse en la lista de resultados final, con acceso a los elementos ya escritos para decisiones basadas en dependencias.

Arquitectura

Una interfaz genérica de un solo método utilizada por BaseDao y la infraestructura de persistencia relacionada para permitir el filtrado posterior a la consulta específico del dominio antes de que se devuelva una lista de resultados al llamante. Se encuentra en el paquete api/impl junto con DBPredicate, DBFilter y otra infraestructura de consulta de bajo nivel.

Contrato

fun match(list: MutableList<O>, element: O): Boolean
ParámetroDescripción
listLa lista de resultados de elementos ya escritos (aceptados). Permite filtrado basado en dependencias — por ejemplo, filtrar un elemento si ya existe un elemento "mejor".
elementEl elemento actual que se está verificando para su inclusión.
Retornotrue para incluir el elemento, false para excluirlo.

Contexto de uso

Las clases DAO pueden proporcionar una implementación de CustomResultFilter al realizar consultas. El filtro se aplica después de la consulta a la base de datos pero antes de que se devuelva el resultado. Esto es particularmente útil para:

  • Deduplicación de direcciones — omitir direcciones que ya tienen un registro coincidente en el resultado
  • Validación de reglas de negocio posteriores a la consulta
  • Cualquier escenario donde SQL/HQL/Criteria API por sí solos no puedan expresar la lógica del filtro
