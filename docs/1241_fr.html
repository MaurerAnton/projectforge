Interface simple qui permet aux classes DAO de fournir un filtrage personnalisé des listes de résultats. Les implémentations décident par élément s'il doit être inclus dans la liste de résultats finale, avec accès aux éléments déjà écrits pour des décisions basées sur les dépendances.

Architecture

Une interface générique à méthode unique utilisée par BaseDao et l'infrastructure de persistance associée pour permettre un filtrage post-requête spécifique au domaine avant qu'une liste de résultats ne soit renvoyée à l'appelant. Elle se trouve dans le package api/impl aux côtés de DBPredicate, DBFilter et d'autres infrastructures de requêtes de bas niveau.

Contrat

fun match(list: MutableList<O>, element: O): Boolean
ParamètreDescription
listLa liste de résultats des éléments déjà écrits (acceptés). Permet un filtrage basé sur les dépendances — par exemple, exclure un élément si un élément « meilleur » existe déjà.
elementL'élément actuel vérifié pour inclusion.
Retourtrue pour inclure l'élément, false pour l'exclure.

Contexte d'utilisation

Les classes DAO peuvent fournir une implémentation de CustomResultFilter lors des requêtes. Le filtre est appliqué après la requête en base de données mais avant que le résultat ne soit renvoyé. Ceci est particulièrement utile pour :

  • La déduplication d'adresses — ignorer les adresses qui ont déjà un enregistrement correspondant dans le résultat
  • La validation des règles métier post-requête
  • Tout scénario où SQL/HQL/Criteria API seul ne peut pas exprimer la logique de filtrage
