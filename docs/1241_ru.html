Простой интерфейс, позволяющий классам DAO предоставлять собственную фильтрацию списка результатов. Реализации для каждого элемента решают, должен ли он быть включён в итоговый список результатов, с доступом к уже записанным элементам для принятия решений на основе зависимостей.

Архитектура

Обобщённый интерфейс с одним методом, используемый BaseDao и связанной инфраструктурой персистентности, чтобы обеспечить доменную пост-запросную фильтрацию перед возвратом списка результатов вызывающему коду. Он находится в пакете api/impl вместе с DBPredicate, DBFilter и другой низкоуровневой инфраструктурой запросов.

Контракт

fun match(list: MutableList<O>, element: O): Boolean
ПараметрОписание
listСписок результатов уже записанных (принятых) элементов. Позволяет фильтрацию на основе зависимостей — например, исключить элемент, если уже существует «лучший» элемент.
elementТекущий элемент, проверяемый на включение.
Возвратtrue для включения элемента, false для его исключения.

Контекст использования

Классы DAO могут предоставлять реализацию CustomResultFilter при выполнении запроса. Фильтр применяется после запроса к базе данных, но до возврата результата. Это особенно полезно для:

  • Дедупликации адресов — пропуск адресов, которые уже имеют соответствующую запись в результате
  • Пост-запросной проверки бизнес-правил
  • Любых сценариев, где SQL/HQL/Criteria API сами по себе не могут выразить логику фильтрации
