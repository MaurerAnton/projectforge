Le moteur central des opérations de copie et d'historique. Un singleton qui orchestre les gestionnaires au niveau des propriétés pour fusionner les objets source dans les objets de destination et créer des entrées d'historique. Copie d'abord les propriétés persistées, puis les propriétés transitoires (car les propriétés transitoires peuvent dépendre des valeurs persistées). Seules les classes Kotlin sont prises en charge ; les classes Java émettent un avertissement.

Architecture

Chaîne de gestionnaires

Enregistrés dans le bloc init, essayés dans l'ordre :

  1. BigDecimalHandler — comparaison BigDecimal insensible à l'échelle
  2. SqlDateHandler — java.sql.Date
  3. UtilDateHandler — java.util.Date
  4. CollectionHandler — copie profonde de collection avec suivi des ajouts/suppressions/modifications
  5. BaseDOHandler — entités BaseDO (comparaison par ID)
  6. DefaultHandler — solution de repli pour tous les autres types

Processus de copie

  1. Initialiser le proxy Hibernate si nécessaire
  2. Copier l'ID s'il n'est pas dans la liste d'ignorance et si les ID diffèrent
  3. Copier d'abord les propriétés persistées (en utilisant KClassUtils.filterPublicMutableProperties)
  4. Copier ensuite les propriétés non persistées/transitoires
  5. Ignorer les propriétés annotées avec @CandHIgnore, transitoires, statiques ou membres de classe interne
