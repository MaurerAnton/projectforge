1272: AbstractCache.kt

Abstract Cache Base Class, projectforge-business/.../cache/AbstractCache.kt
Thread-safe base class implementing a time-based expiry cache with listener callbacks. Subclasses override refresh() to reload data; callers invoke checkRefresh() to ensure fresh data on each access.

Architecture & Role

AbstractCache provides the framework for all in-memory caches in ProjectForge (e.g., Configuration, UserGroupCache, TaskTree). It uses a double-checked locking pattern with a synchronized block plus an isRefreshInProgress flag to prevent concurrent refreshes.

Expiry Mechanism

  • Default expire time: 60 minutes (configurable via constructor or setter methods in seconds/minutes/hours).
  • Time constants: TICKS_PER_SECOND = 1000, TICKS_PER_MINUTE = 60_000, TICKS_PER_HOUR = 3_600_000, TICKS_PER_DAY = 86_400_000
  • isExpired boolean is set to true on expiry; also markable manually via setExpired().
  • forceReload() = setExpired() + checkRefresh(), used when the underlying data is known to have changed.

Listener System

Uses CopyOnWriteArrayList<CacheListener> to avoid deadlocks during concurrent refresh cycles. Two callbacks:

  • onBeforeCacheRefresh() — invoked before refresh()
  • onAfterCacheRefresh() — invoked after refresh() completes, even on error

Thread Safety

The checkRefresh() method uses synchronized(this) with a re-check pattern. If a refresh is already in progress (isRefreshInProgress == true), the calling thread returns immediately without blocking. This prevents stack-overflow from nested checkRefresh() calls (e.g., cache A depends on cache B, which triggers cache A).
