La página principal del plugin IHK — permite a los aprendices (Auszubildende) seleccionar una semana, ver sus registros de horas y exportarlos como un informe semanal de Excel compatible con IHK. Parte del flujo de trabajo de formación profesional dual (Duale Ausbildung) exigido por la ley alemana.

Arquitectura

Extiende AbstractStandardFormPage (la página base Wicket de ProjectForge) e implementa ISelectCallerPage (para el widget de calendario de selección rápida). La página contiene un componente IHKForm en su cuerpo.

Ciclo de vida:
1. Constructor: crea IHKForm, lo inicializa, añade un enlace LogViewer al menú de contenido
2. select(): maneja los clics de selección rápida del calendario — establece el rango de fechas a la semana de la fecha seleccionada (lunes–domingo)
3. export(): consulta las hojas de tiempo de la semana seleccionada, valida que existan descripciones, delega en IHKExporter para generar el archivo Excel, activa la descarga
4. edit(): navega a TimesheetEditPage para corregir descripciones faltantes

Flujo de validación

El método export() tiene dos compuertas de validación:
1. No se encontraron hojas de tiempo: Si findTimesheets() devuelve vacío, muestra el error "plugins.ihk.noitemsfound"
2. Descripciones faltantes: IHK requiere que cada entrada de la hoja de tiempo tenga una descripción. Si alguna entrada tiene description == null, muestra el error "plugins.ihk.nodescriptionfound" y muestra la lista de entradas infractoras. El usuario puede llamar a export(true) para omitir (bajo su propio riesgo).

Esta validación en dos etapas es un patrón de UX: primero fallar rápido con un error cortés, luego mostrar exactamente qué entradas necesitan corrección, y proporcionar una vía de escape para casos donde la descripción realmente no es necesaria.

Commits clave

45cad02e9 — Creación del plugin: El plugin IHK se añadió como reemplazo del plugin anterior "Ihk-Export". Genera informes Excel directamente desde las hojas de tiempo de ProjectForge para el cumplimiento de la formación profesional alemana.

9522de0eb — Lista de descripciones faltantes: Se añadió el paso de validación que verifica las descripciones vacías en las hojas de tiempo y las muestra al usuario. Antes de esto, las descripciones faltantes producían silenciosamente un informe incompleto.

5d41efc41 — Integración de LogViewer: Cada plugin obtiene una suscripción de registro dedicada a través de IHKPlugin.ensureUserLogSubscription(). El enlace LogViewer en el menú de contenido permite a los usuarios inspeccionar la salida de registro específica del plugin sin salir de la página IHK.

83ced0b86 — Menos manualidad (#141): Se optimizó la experiencia de usuario para reducir los pasos manuales en el flujo de trabajo de generación de informes.
Advertencia — Manejo de zona horaria: El cálculo del rango semanal utiliza ThreadLocalUserContext.getTimeZone() para asegurar que los límites de lunes a domingo se calculen en la zona horaria del usuario. Usar la zona horaria del servidor causaría errores de un día de diferencia para usuarios en diferentes zonas horarias. El commit bf872fc9a (PROJECTFORGE-2524) corrigió específicamente un error de zona horaria en la exportación IHK.
¿Por qué Wicket y no React? El plugin IHK es uno de los plugins más antiguos que todavía usa Apache Wicket para su interfaz de usuario. Los plugins más nuevos usan el stack REST+React. IHKPage permanece en Wicket porque: (a) es un formulario de una sola página sin interactividad compleja, (b) el plugin tiene poco tráfico (solo lo usan aprendices, no todos los empleados), y (c) el esfuerzo de migración frente al beneficio no justificó reescribirlo.
