La page principale du plugin IHK — permet aux apprentis (Auszubildende) de sélectionner une semaine, de visualiser leurs entrées de feuille de temps et de les exporter sous forme de rapport hebdomadaire Excel conforme à l'IHK. Fait partie du flux de travail de la formation professionnelle en alternance (Duale Ausbildung) prescrit par la loi allemande.

Architecture

Étend AbstractStandardFormPage (page de base Wicket de ProjectForge) et implémente ISelectCallerPage (pour le widget de sélection rapide du calendrier). La page contient un composant IHKForm dans son corps.

Cycle de vie :
1. Constructeur : crée IHKForm, l'initialise, ajoute un lien LogViewer au menu de contenu
2. select() : gère les clics de sélection rapide du calendrier — définit la plage de dates sur la semaine de la date cliquée (lundi–dimanche)
3. export() : interroge les feuilles de temps pour la semaine sélectionnée, valide l'existence des descriptions, délègue à IHKExporter la génération du fichier Excel, déclenche le téléchargement
4. edit() : navigue vers TimesheetEditPage pour corriger les descriptions manquantes

Flux de validation

La méthode export() comporte deux étapes de validation :
1. Aucune feuille de temps trouvée : Si findTimesheets() renvoie un résultat vide, affiche l'erreur "plugins.ihk.noitemsfound"
2. Descriptions manquantes : L'IHK exige que chaque entrée de feuille de temps ait une description. Si une entrée a description == null, affiche l'erreur "plugins.ihk.nodescriptionfound" et la liste des entrées concernées. L'utilisateur peut alors appeler export(true) pour passer outre (à ses propres risques).

Cette validation en deux étapes est un modèle UX : d'abord échouer rapidement avec une erreur polie, puis montrer exactement quelles entrées doivent être corrigées, et fournir une échappatoire pour les cas où la description n'est vraiment pas nécessaire.

Validations clés

45cad02e9 — Création du plugin : Le plugin IHK a été ajouté en remplacement de l'ancien plugin "Ihk-Export". Il génère des rapports Excel directement à partir des feuilles de temps de ProjectForge pour la conformité à la formation professionnelle allemande.

9522de0eb — Liste des descriptions manquantes : Ajout de l'étape de validation qui vérifie les descriptions vides dans les feuilles de temps et les affiche à l'utilisateur. Avant cela, les descriptions manquantes produisaient silencieusement un rapport incomplet.

5d41efc41 — Intégration LogViewer : Chaque plugin reçoit un abonnement dédié aux logs via IHKPlugin.ensureUserLogSubscription(). Le lien LogViewer dans le menu de contenu permet aux utilisateurs d'inspecter les logs spécifiques au plugin sans quitter la page IHK.

83ced0b86 — Moins de travail manuel (#141) : Simplification de l'UX pour réduire les étapes manuelles dans le flux de génération de rapports.
Piège — Gestion des fuseaux horaires : Le calcul de la plage de la semaine utilise ThreadLocalUserContext.getTimeZone() pour garantir que les limites lundi–dimanche sont calculées dans le fuseau horaire de l'utilisateur. L'utilisation du fuseau horaire du serveur provoquerait des erreurs de décalage d'un jour pour les utilisateurs dans des fuseaux horaires différents. Le commit bf872fc9a (PROJECTFORGE-2524) a spécifiquement corrigé un bug de fuseau horaire dans l'export IHK.
Pourquoi Wicket et pas React ? Le plugin IHK est l'un des plugins plus anciens qui utilise encore Apache Wicket pour son interface utilisateur. Les plugins plus récents utilisent la pile REST+React. L'IHKPage reste sur Wicket car : (a) c'est un formulaire sur une seule page sans interactivité complexe, (b) le plugin est peu utilisé (uniquement par les apprentis, pas tous les employés), et (c) l'effort de migration par rapport aux bénéfices ne justifiait pas sa réécriture.
