File #13: docker/compose/nginx/nginx.conf

Path: ./docker/compose/nginx/nginx.conf · Type: nginx configuration · Lines: 21 · Source: GitHub

What it does

Two server blocks: the first redirects HTTP→HTTPS, the second terminates TLS and proxies to the app. Together they enforce HTTPS-only access.

Browser │ ├── http://domain.com ──→ server #1 (port 80) │ └→ 301 → https://domain.com │ └── https://domain.com ─→ server #2 (port 443, TLS) └→ proxy_pass → app:8000

Server block #1: HTTP→HTTPS redirect (lines 1–5)

1 server {
2     listen 80;
3     server_name ${DOMAIN};
4     return 301 https://$host$request_uri;
5 }

Line 2: Listens on port 80 (HTTP).

Line 3: ${DOMAIN} — substituted from .env at container start. Defaults to mydomain.com.

Line 4: return 301 https://$host$request_uri — permanent redirect. $host preserves the original domain, $request_uri preserves the path. Request to http://example.com/login → https://example.com/login.

Server block #2: TLS termination + proxy (lines 7–21)

 7 server {
 8     listen 443 ssl;
 9     server_name ${DOMAIN};
10 
11     ssl_certificate /etc/ssl/certs/fullchain.pem;
12     ssl_certificate_key /etc/ssl/private/privkey.pem;
13 
14     location / {
15         proxy_pass http://app:8000;
16         proxy_set_header Host $host;
17         proxy_set_header X-Real-IP $remote_addr;
18         proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
19         proxy_set_header X-Forwarded-Proto $scheme;
20     }
21 }

Lines 11–12: TLS certificate and private key — mounted from host as Docker volumes (compose lines 44–45). Expects Let's Encrypt-standard filenames (fullchain.pem, privkey.pem).

Line 15: proxy_pass http://app:8000 — proxies to the app Docker service on port 8000. app resolves via Docker's internal DNS.

⚠️ Port mismatch? The compose file exposes port 8080 (docker-compose.yml:17), but nginx proxies to port 8000. This either means the app runs on 8000 inside the container (not the default 8080 exposed port), or this configuration has a bug. The DOCKER_OPTS environment variable (line 9 of compose) may reconfigure the internal port.

Lines 16–19: Four proxy headers — essential for the app to know the client's real IP and that the connection is HTTPS:

HeaderValueWhat the app sees
Host$hostOriginal domain (not app:8000)
X-Real-IP$remote_addrClient's real IP (not nginx's Docker IP)
X-Forwarded-ForChain of IPsFull proxy chain (for audit logs)
X-Forwarded-Proto$scheme (https)App knows client used HTTPS (for redirects)

Key takeaways

  • 21 lines, two jobs: HTTP→HTTPS redirect + TLS termination.
  • TLS at the edge: Traffic between nginx and app is plain HTTP (internal Docker network).
  • Domain from .env: ${DOMAIN} — must match the TLS certificate.
  • Port 8000 vs 8080: Possible mismatch with the compose file — the app's internal port needs verification.
