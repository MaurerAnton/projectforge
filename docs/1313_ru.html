Основной фасад для загрузки, слияния, сохранения и удаления записей истории, включая отслеживание изменений на уровне атрибутов. Также обрабатывает разрешение сущностей с проверкой доступа и добавление комментариев пользователя.

Архитектура и роль

HistoryService — это синглтон @Service, который связывает низкоуровневый доступ к данным (HistoryEntryDO/HistoryEntryAttrDO) с конвертерами уровня представления. Он управляет полным жизненным циклом: создание записей истории через адаптеры BaseDao, загрузка с рекурсией встроенных объектов, добавление комментариев пользователя и принудительное удаление.

Ключевые методы

МетодОписание
mergeHistoryEntries(loadContext, entries)Объединяет записи в контекст загрузки, удаляя дубликаты по ID.
findEntryAndEntityById(id, checkAccess?)Загружает запись истории + целевую сущность, проверяя доступ на выборку и обновление. Возвращает EntryInfo с классом сущности, DAO и флагами доступа.

loadHistory(baseDO, baseDao?)Точка входа для загрузки всей истории для заданной сущности. Создаёт новый HistoryLoadContext и вызывает рекурсивный загрузчик.

forceDeletion(historyEntry)Жёстко удаляет запись истории и все её атрибуты (для очистки сущностей в стиле GDPR).

Разрешение встроенных объектов

Приватный метод processAndMergeHistory() сканирует атрибуты записи истории на наличие имён свойств @OneToMany, извлекает ID сущностей из полей value (добавлено) и oldValue (удалено) и рекурсивно загружает историю для этих встроенных сущностей. Он также использует рефлексию на фактически загруженных родительских сущностях для поиска текущих назначенных дочерних элементов, которые могут не отображаться в diff-ах истории.

Внутренний класс: EntryInfo

Тип возвращаемого значения для findEntryAndEntityById(). Содержит сырой HistoryEntryDO, разрешённый класс сущности, её BaseDao, загруженный экземпляр сущности и логические флаги чтения/записи.
