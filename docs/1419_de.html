Zentraler Zwei-Faktor-Authentifizierungsdienst: Validiert OTP-Codes über Authenticator-App (TOTP), SMS oder E-Mail mit Brute-Force-Schutz.

Architektur

My2FAService ist ein @Service, der die mehrkanalige 2FA-Verifizierung orchestriert. Er verbindet UserAuthenticationsService (Token-Speicher), SmsSenderConfig (SMS-Verfügbarkeitsprüfung), My2FABruteForceProtection (Ratenbegrenzung), My2FARequestConfiguration (gruppenbasierte Deaktivierung) und WebAuthnSupport (WebAuthn-Verfügbarkeit).

OTP-Validierungspipeline

  1. validateOTP(code, *expectedToken) — Primärer Einstiegspunkt. Akzeptiert einen 6-stelligen Code und ein oder mehrere erwartete Token (von SMS oder E-Mail).
  2. preCheck(code) — Gibt BLOCKED zurück, wenn der Brute-Force-Schutz aktiv ist, FAILED, wenn der Code zu kurz ist (<4 Zeichen).
  3. Vergleicht den Code mit jedem expectedToken (SMS-/E-Mail-Token). Bei Übereinstimmung: ruft bruteForceProtection.registerOTPSuccess() auf und aktualisiert den Zeitstempel lastSuccessful2FA.
  4. Wenn kein SMS-/E-Mail-Token übereinstimmt, fällt es auf _validateAuthenticatorOTP(code) zurück, das gegen das gespeicherte TOTP-Token über TimeBased2FA.standard.validate() validiert.
  5. Bei Fehlschlag: bruteForceProtection.registerOTPFailure() erhöht den Fehlerzähler.

Brute-Force-Schutz

Erfolgreiche Registrierungen setzen den Zähler zurück. Fehlschläge erhöhen ihn. getBlockedResult() gibt null oder ein BLOCKED-OTPCheckResult mit einer lokalisierten Nachricht zurück. Die Vorprüfung begrenzt die minimale Codelänge (4), um unnötiges Brute-Force-Zählen bei offensichtlich ungültigen Eingaben zu vermeiden.

2FA-Statusprüfungen

  • userConfigured2FA — Wahr, wenn der Benutzer mindestens eine 2FA-Methode konfiguriert hat (Authenticator-App-Token, Mobiltelefon für SMS oder WebAuthn-Anmeldedaten).
  • smsConfigured — Wahr, wenn der SMS-Sender konfiguriert ist oder sich das System im Entwicklungsmodus befindet.
  • checklastSuccessful2FA(timePeriod, unit, user) — Prüft, ob die letzte erfolgreiche 2FA innerhalb eines bestimmten Zeitraums lag (unterstützt MINUTEN, STUNDEN, TAGE).
  • isMail2FADisabledForUser(userContext) — Prüft, ob der Benutzer zu einer Gruppe gehört, die in My2FARequestConfiguration.disableEmail2FAForGroups aufgeführt ist.

Gruppenbasierte 2FA-Deaktivierung

setDisabled(groupNames) parst eine durch Semikolon/Komma/Doppelpunkt getrennte Zeichenfolge von Gruppennamen aus der Konfiguration, löst sie gegen GroupService.allGroups auf und befüllt mail2FADisabledGroupIds. Benutzer in diesen Gruppen überspringen die E-Mail-basierte 2FA. Dies wird bei @PostConstruct aus my2FARequestConfiguration.disableEmail2FAForGroups konfiguriert.

Designbegründung

Die mehrkanalige OTP-Validierung (SMS, E-Mail, Authenticator-App) ist als Fallback-Kette implementiert: Externe Token werden zuerst geprüft, dann TOTP. Dies ermöglicht, dass ein einzelner validateOTP-Aufruf unabhängig von der Zustellungsmethode funktioniert. Der Brute-Force-Schutz wird auf OTP-Ebene (nicht auf Login-Ebene) angewendet, sodass jeder 2FA-Versuch unabhängig ratenbegrenzt wird. Die gruppenbasierte Deaktivierungsfunktion unterstützt organisatorische Richtlinien, bei denen bestimmte Benutzer (z. B. Administratoren mit Hardware-Token) keine E-Mail-2FA benötigen. Der Zeitstempel lastSuccessful2FA ermöglicht das Zwischenspeichern von 2FA auf Sitzungsebene (keine erneute Aufforderung, wenn kürzlich verifiziert).
