plugins/org.projectforge.plugins.licensemanagement/src/main/kotlin/org/projectforge/plugins/licensemanagement/LicenseDO.kt Путь: plugins/...licensemanagement/src/main/kotlin/.../LicenseDO.kt · Строк: 154 · Автор: Kai Reinhard · Тип: Kotlin JPA @Entity — подкласс DefaultBaseDO 154 строки · 95 кода · 37 комментариев · 22 пустых

JPA-сущность для записей лицензий. Отображается на таблицу T_PLUGIN_LM_LICENSE. Расширяет DefaultBaseDO (предоставляет id, created, lastUpdate, deleted). 154 строки, 16 полей данных + 1 вычисляемое свойство.

Текстовые/поисковые поля (15 полей с @FullTextField для индексации Hibernate Search):

  • organization — название компании (VARCHAR 1000)
  • product — название программного продукта (VARCHAR 1000)
  • version — версия ПО (VARCHAR 1000)
  • updateFromVersion — исходная версия для обновления (VARCHAR 1000, столбец update_from_version)
  • licenseHolder — кто владеет лицензией (VARCHAR 10000)
  • key — лицензионный ключ в виде текста (VARCHAR 10000) — позволяет копировать текстовые ключи
  • ownerIds — идентификаторы владельцев через запятую (VARCHAR 4000) — используется LicenseManagementRight для контроля видимости
  • device — связанное устройство/имя хоста (VARCHAR 4000)
  • comment — произвольные текстовые заметки (Constants.LENGTH_TEXT)
  • numberOfLicenses — количество одновременных/рабочих мест (Integer)
  • validSince, validUntil — диапазон дат действия лицензии (LocalDate)
  • status — @Enumerated(STRING) — см. LicenseStatus

Хранилище BLOB-файлов (2 слота для двоичных вложений — примечание: не JCR, используются прямые BLOB-объекты базы данных):

  • file1 / filename1 — первое вложение BLOB + имя файла (например, PDF-сертификат лицензии)
  • file2 / filename2 — второе вложение BLOB + имя файла (например, лицензионное соглашение)

Оба BLOB-поля аннотированы @NoHistory (исключены из отслеживания истории/изменений — двоичные diff-ы были бы бессмысленны) и FetchType.LAZY (загружаются только при явном обращении, а не при каждом запросе). Используется @JdbcTypeCode(SqlTypes.BLOB) для корректной обработки JDBC BLOB.

Вычисляемое свойство: orderString (@Transient) — возвращает "$organization-$product-$version" для сортировки и отображения.

toString(): пользовательская реализация с использованием ReflectionToString, которая исключает file1 и file2 (двоичное содержимое создало бы бессмысленные шестнадцатеричные дампы).
