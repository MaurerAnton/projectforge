File #15: docker/entrypoint.sh

Path: ./docker/entrypoint.sh · Type: Bash shell script · Lines: 98 · Source: GitHub

What it does

This is the Docker ENTRYPOINT — the first process that runs when the container starts. It handles graceful shutdown (SIGTERM trap), two startup modes (normal vs initial setup), and external configuration via environment variables and a sourced shell script.

Container starts │ ├─ Check: java exists? ├─ Source: /ProjectForge/environment.sh (if exists) ├─ Print: JAVA_OPTS, JAVA_ARGS (if set) ├─ Trap: SIGTERM → cleanup() ├─ Default: DOCKER_OPTS="-Ddocker=single" (if not set) │ ├─ Is /ProjectForge/projectforge.properties present? │ ├─ YES → normal start: java -jar ... & (background + wait) │ └─ NO → initial start: java -jar ... (foreground, console wizard) │ └─ wait $CHILD → exit

The shutdown sequence: polite SIGTERM → wait up to 60 seconds (20 × 3s) → SIGKILL. This is the standard Docker pattern: docker stop sends SIGTERM, waits 10s (default), then SIGKILL. The 60s loop here is longer than Docker's default — giving ProjectForge extra time for graceful shutdown (closing DB connections, flushing logs).

Key design decision: On first run (no config file), Java runs in the foreground so the admin can interact with the console setup wizard. On subsequent runs, it runs in the background (with & and wait) so the SIGTERM trap can forward the signal — background processes receive traps differently from foreground ones.

Key takeaways

  • 98 lines, one purpose: Start ProjectForge gracefully in Docker.
  • Two modes: Setup wizard (foreground) vs normal operation (background + signals).
  • 60-second grace period: Spring Boot apps with Hibernate and Flyway need time for orderly shutdown.
  • -Ddocker=single vs -Ddocker=stack: Controls whether the embedded HSQLDB option appears in setup (single=yes, stack=no).
  • Environment sourcing: /ProjectForge/environment.sh is a Docker volume mount — admins can drop JVM tuning variables there without rebuilding the image.
