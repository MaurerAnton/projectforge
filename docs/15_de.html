Was es tut

Jedes Mal, wenn ProjectForge gebaut wird, führt diese Aufgabe fünf Git-Befehle aus und schreibt die Ergebnisse in eine .properties-Datei. Diese Datei wird dann in das JAR verpackt und zur Laufzeit gelesen, um Versionsinformationen anzuzeigen (der "Über"-Dialog, Systemstatus-Endpunkt usw.).

Die erzeugte Ausgabe sieht wie folgt aus:

# Von Gradle generiert gradle.version=8.2-SNAPSHOT gradle.build.date=2026-05-10 gradle.build.timestamp=2026-05-10T12:34:56Z git.branch=fix/vite-eslint-upgrade git.commit.id.abbrev=e67067a git.commit.id.full=e67067aa7f00b3a6b6afc7ffe9af69718e277fc1 git.commit.time=2026-05-10 12:30:00 +0100 git.dirty=true

Das Feld git.dirty=true ist besonders nützlich — es zeigt an, ob der Build aus sauberen Quellen oder mit nicht festgeschriebenen Änderungen erstellt wurde.

Zeile 24 — Dirty-Flag: git status --porcelain gibt einen leeren String für einen sauberen Arbeitsbaum zurück, einen nicht leeren für einen verschmutzten. .isNotBlank() wandelt dies in einen Boolean um, .toString() in "true"/"false". Dies ist das nützlichste Feld für die Fehlersuche: Ein Build mit git.dirty=true bedeutet, dass der ausgeführte Code nicht exakt mit einem Commit übereinstimmt.

Zeilen 25–27: Build-Zeitstempel — zum Zeitpunkt des Builds erfasst, nicht zum Zeitpunkt des Commits. Verwendet OffsetDateTime.now(UTC) für eine konsistente Zeitzone.

Zeilen 46–56: runCommand() — der Shell-Ausführer

46 private fun String.runCommand(workingDir: File): String? {
47     return try {
48         val process = ProcessBuilder(*split(" ").toTypedArray())
49             .directory(workingDir)
50             .redirectErrorStream(true)
51             .start()
52         process.inputStream.bufferedReader().readText().trim()
53             .takeIf { process.waitFor() == 0 }
54     } catch (e: Exception) { null }
55 }

Erweiterungsfunktion auf String — ermöglicht das Aufrufen von Git-Befehlen mit natürlicher Syntax: "git rev-parse HEAD".runCommand(rootDir).

Zeile 48: ProcessBuilder(*split(" ").toTypedArray()) — teilt den Befehlstring durch Leerzeichen in Argumente auf. ProcessBuilder ist die Art und Weise der Java-Standardbibliothek, externe Prozesse zu starten.

Zeile 49: .directory(workingDir) — setzt das Arbeitsverzeichnis für den Git-Befehl. Muss auf das Projektstammverzeichnis zeigen (wo .git/ lebt).

Zeile 50: .redirectErrorStream(true) — leitet stderr in stdout um. Warum? Wenn stderr getrennt und ungelesen wäre, könnte der Prozess hängen bleiben, während er darauf wartet, dass der Puffer geleert wird.

Zeile 53: .takeIf { process.waitFor() == 0 } — gibt die Ausgabe nur zurück, wenn der Prozess mit dem Code 0 (Erfolg) beendet wurde. Wenn Git fehlschlägt (z.B. kein Git-Repository), wird null zurückgegeben → der Aufrufer verwendet ?: "unknown" als Fallback.

Zeile 54: catch (e: Exception) { null } — unterdrückt alle Ausnahmen. Wenn Git nicht installiert ist, stürzt der Build nicht ab — er erhält einfach "unknown"-Werte.

Wo die Ausgabe verwendet wird

Die generierte build.properties wird zur Laufzeit von Spring Boots @PropertySource oder der application.properties-Platzhalterauflösung gelesen. ProjectForge verwendet sie für:

  • Systemstatus-REST-Endpunkt: GET /rs/userStatus gibt { systemData: { version, buildTimestamp } } zurück — das React-Frontend zeigt dies in der Fußzeile an
  • Über-Dialog: Zeigt die Version, das Build-Datum und den Commit-SHA an
  • Versionsprüfung: Die Anwendung vergleicht ihre Version mit der neuesten Version auf GitHub, um Administratoren über Updates zu benachrichtigen

Wichtige Erkenntnisse

  • 57 Zeilen, eine Aufgabe: Git abfragen und eine Eigenschaftendatei schreiben.
  • git.dirty ist Gold wert: Sagt Ihnen sofort, ob der Build nicht festgeschriebene Änderungen enthält.
  • Ausfallsicher: Alle Git-Befehle fallen auf "unknown" zurück — der Build bricht nie ab, weil Git nicht verfügbar ist.
  • Keine Gradle-Aufgabe: Dies ist eine einfache Kotlin-Klasse, die von einem doLast { }-Block in den Build-Skripten der Unterprojekte aufgerufen wird.
  • Ein Build, eine Eigenschaftendatei: Mehrere Unterprojekte können dies aufrufen, jedes mit einem anderen outputFilePath.
