Qué hace

Cada vez que se compila ProjectForge, esta tarea ejecuta cinco comandos git y escribe los resultados en un archivo .properties. Ese archivo luego se empaqueta en el JAR y se lee en tiempo de ejecución para mostrar información de versión (el diálogo "Acerca de", endpoint de estado del sistema, etc.).

La salida generada se ve así:

# Generado por Gradle gradle.version=8.2-SNAPSHOT gradle.build.date=2026-05-10 gradle.build.timestamp=2026-05-10T12:34:56Z git.branch=fix/vite-eslint-upgrade git.commit.id.abbrev=e67067a git.commit.id.full=e67067aa7f00b3a6b6afc7ffe9af69718e277fc1 git.commit.time=2026-05-10 12:30:00 +0100 git.dirty=true

El campo git.dirty=true es especialmente útil — te indica si la compilación se hizo desde fuentes limpias o con cambios sin confirmar.

Línea 24 — indicador de sucio: git status --porcelain devuelve cadena vacía para árbol de trabajo limpio, no vacía para sucio. .isNotBlank() convierte eso a booleano, .toString() a "true"/"false". Este es el campo más útil para depuración: una compilación con git.dirty=true significa que el código en ejecución no coincide exactamente con ningún commit.

Líneas 25–27: Marca de tiempo de compilación — capturada en tiempo de compilación, no en tiempo de commit. Usa OffsetDateTime.now(UTC) para zona horaria consistente.

Líneas 46–56: runCommand() — el ejecutor de shell

46 private fun String.runCommand(workingDir: File): String? {
47     return try {
48         val process = ProcessBuilder(*split(" ").toTypedArray())
49             .directory(workingDir)
50             .redirectErrorStream(true)
51             .start()
52         process.inputStream.bufferedReader().readText().trim()
53             .takeIf { process.waitFor() == 0 }
54     } catch (e: Exception) { null }
55 }

Función de extensión sobre String — permite llamar comandos git con sintaxis natural: "git rev-parse HEAD".runCommand(rootDir).

Línea 48: ProcessBuilder(*split(" ").toTypedArray()) — divide la cadena del comando por espacios en argumentos. ProcessBuilder es la forma estándar de la biblioteca de Java para lanzar procesos externos.

Línea 49: .directory(workingDir) — establece el directorio de trabajo para el comando git. Debe apuntar a la raíz del proyecto (donde vive .git/).

Línea 50: .redirectErrorStream(true) — fusiona stderr en stdout. ¿Por qué? Si stderr estuviera separado y sin leer, el proceso podría colgarse esperando que se consuma el búfer.

Línea 53: .takeIf { process.waitFor() == 0 } — solo devuelve la salida si el proceso terminó con código 0 (éxito). Si git falla (ej. no es un repositorio git), devuelve null → el llamador usa ?: "unknown" como valor de respaldo.

Línea 54: catch (e: Exception) { null } — silencia todas las excepciones. Si git no está instalado, la compilación no falla — solo obtiene valores "unknown".

Dónde se usa la salida

El archivo build.properties generado se lee en tiempo de ejecución mediante @PropertySource de Spring Boot o resolución de placeholders de application.properties. ProjectForge lo usa para:

  • Endpoint REST de estado del sistema: GET /rs/userStatus devuelve { systemData: { version, buildTimestamp } } — el frontend React muestra esto en el pie de página
  • Diálogo Acerca de: Muestra la versión, fecha de compilación y SHA del commit
  • Verificación de versión: La aplicación compara su versión contra el último lanzamiento en GitHub para notificar a los administradores sobre actualizaciones

Conclusiones clave

  • 57 líneas, un trabajo: Interrogar a git y escribir un archivo de propiedades.
  • git.dirty es oro: Te dice al instante si la compilación incluye cambios sin confirmar.
  • A prueba de fallos: Todos los comandos git retroceden a "unknown" — la compilación nunca se rompe porque git no esté disponible.
  • No es una Tarea Gradle: Esta es una clase Kotlin simple, llamada por un bloque doLast { } en los scripts de compilación de los subproyectos.
  • Una compilación, un archivo de propiedades: Varios subproyectos pueden llamar a esto, cada uno con un outputFilePath diferente.
