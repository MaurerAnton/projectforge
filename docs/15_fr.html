Ce qu'il fait

Chaque fois que ProjectForge est construit, cette tâche exécute cinq commandes git et écrit les résultats dans un fichier .properties. Ce fichier est ensuite intégré dans le JAR et lu au moment de l'exécution pour afficher les informations de version (la boîte de dialogue "À propos", le point de terminaison du statut système, etc.).

Le résultat généré ressemble à :

# Généré par Gradle gradle.version=8.2-SNAPSHOT gradle.build.date=2026-05-10 gradle.build.timestamp=2026-05-10T12:34:56Z git.branch=fix/vite-eslint-upgrade git.commit.id.abbrev=e67067a git.commit.id.full=e67067aa7f00b3a6b6afc7ffe9af69718e277fc1 git.commit.time=2026-05-10 12:30:00 +0100 git.dirty=true

Le champ git.dirty=true est particulièrement utile — il vous indique si la construction a été faite à partir de sources propres ou avec des modifications non validées.

Lignes 46–56 : runCommand() — l'exécuteur de shell

46 private fun String.runCommand(workingDir: File): String? {
47     return try {
48         val process = ProcessBuilder(*split(" ").toTypedArray())
49             .directory(workingDir)
50             .redirectErrorStream(true)
51             .start()
52         process.inputStream.bufferedReader().readText().trim()
53             .takeIf { process.waitFor() == 0 }
54     } catch (e: Exception) { null }
55 }

Fonction d'extension sur String — permet d'appeler les commandes git avec une syntaxe naturelle : "git rev-parse HEAD".runCommand(rootDir).

Ligne 48 : ProcessBuilder(*split(" ").toTypedArray()) — divise la chaîne de commande par espaces en arguments. ProcessBuilder est la manière standard de la bibliothèque Java de lancer des processus externes.

Ligne 49 : .directory(workingDir) — définit le répertoire de travail pour la commande git. Doit pointer vers la racine du projet (là où se trouve .git/).

Ligne 50 : .redirectErrorStream(true) — fusionne stderr dans stdout. Pourquoi ? Si stderr était séparé et non lu, le processus pourrait se bloquer en attendant que le tampon soit consommé.

Ligne 53 : .takeIf { process.waitFor() == 0 } — ne renvoie la sortie que si le processus s'est terminé avec le code 0 (succès). Si git échoue (par exemple, pas un dépôt git), renvoie null → l'appelant utilise ?: "inconnu" comme solution de repli.

Ligne 54 : catch (e: Exception) { null } — réduit au silence toutes les exceptions. Si git n'est pas installé, la construction ne plante pas — elle obtient simplement des valeurs "inconnu".

Où la sortie est utilisée

Le fichier build.properties généré est lu au moment de l'exécution par @PropertySource de Spring Boot ou la résolution d'espace réservé application.properties. ProjectForge l'utilise pour :

  • Point de terminaison REST du statut système : GET /rs/userStatus renvoie { systemData: { version, buildTimestamp } } — le frontend React affiche cela dans le pied de page
  • Boîte de dialogue À propos : Affiche la version, la date de construction et le SHA du commit
  • Vérification de version : L'application compare sa version à la dernière version sur GitHub pour informer les administrateurs des mises à jour

Points clés à retenir

  • 57 lignes, un seul travail : Interroger git et écrire un fichier de propriétés.
  • git.dirty est en or : Vous indique instantanément si la construction inclut des modifications non validées.
  • Sécurisé contre les échecs : Toutes les commandes git reviennent à "inconnu" — la construction ne casse jamais parce que git n'est pas disponible.
  • Pas une tâche Gradle : C'est une classe Kotlin simple, appelée par un bloc doLast { } dans les scripts de construction des sous-projets.
  • Une construction, un fichier de propriétés : Plusieurs sous-projets peuvent appeler cela, chacun avec un outputFilePath différent.
