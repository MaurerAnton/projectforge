Что делает

Каждый раз при сборке ProjectForge эта задача выполняет пять команд git и записывает результаты в файл .properties. Затем этот файл упаковывается в JAR и считывается во время выполнения для отображения информации о версии (диалог «О программе», конечная точка статуса системы и т.д.).

Сгенерированный вывод выглядит так:

# Сгенерировано Gradle gradle.version=8.2-SNAPSHOT gradle.build.date=2026-05-10 gradle.build.timestamp=2026-05-10T12:34:56Z git.branch=fix/vite-eslint-upgrade git.commit.id.abbrev=e67067a git.commit.id.full=e67067aa7f00b3a6b6afc7ffe9af69718e277fc1 git.commit.time=2026-05-10 12:30:00 +0100 git.dirty=true

Поле git.dirty=true особенно полезно — оно показывает, была ли сборка выполнена из чистых исходников или с незакоммиченными изменениями.

Строки 16–29: Метод generate() — опрос git

20 val branch = "git rev-parse --abbrev-ref HEAD".runCommand(rootDir) ?: "unknown"
21 val commitIdFull = "git rev-parse HEAD".runCommand(rootDir) ?: "unknown"
22 val commitIdAbbrev = commitIdFull.take(7)

26 val buildDate = now.format(DateTimeFormatter.ISO_OFFSET_DATE)
27 val buildTimeStamp = now.format(DateTimeFormatter.ofPattern("yyyy-MM-dd'T'HH:mm:ss'Z'"))

Пять команд git, выполняемых через runCommand():

21git rev-parse HEADПолный SHA коммитаe67067aa7f00...

Строка 24 — флаг dirty: git status --porcelain возвращает пустую строку для чистой рабочей директории и непустую для грязной. .isNotBlank() преобразует это в логическое значение, .toString() — в "true"/"false". Это самое полезное поле для отладки: сборка с git.dirty=true означает, что запущенный код не соответствует в точности ни одному коммиту.

Строки 25–27: Временная метка сборки — фиксируется во время сборки, а не коммита. Используется OffsetDateTime.now(UTC) для единообразного часового пояса.

Строки 46–56: runCommand() — исполнитель команд оболочки

46 private fun String.runCommand(workingDir: File): String? {
47     return try {
48         val process = ProcessBuilder(*split(" ").toTypedArray())
49             .directory(workingDir)
50             .redirectErrorStream(true)
51             .start()
52         process.inputStream.bufferedReader().readText().trim()
53             .takeIf { process.waitFor() == 0 }
54     } catch (e: Exception) { null }
55 }

Функция-расширение для String — позволяет вызывать команды git с естественным синтаксисом: "git rev-parse HEAD".runCommand(rootDir).

Строка 48: ProcessBuilder(*split(" ").toTypedArray()) — разбивает строку команды по пробелам на аргументы. ProcessBuilder — это стандартный способ Java для запуска внешних процессов.

Строка 49: .directory(workingDir) — устанавливает рабочую директорию для команды git. Должна указывать на корень проекта (где находится .git/).

Строка 50: .redirectErrorStream(true) — объединяет stderr с stdout. Зачем? Если бы stderr был отдельным и не читался, процесс мог бы зависнуть в ожидании освобождения буфера.

Строка 53: .takeIf { process.waitFor() == 0 } — возвращает вывод только если процесс завершился с кодом 0 (успех). Если git завершается ошибкой (например, не git-репозиторий), возвращает null → вызывающий код использует ?: "unknown" как запасной вариант.

Строка 54: catch (e: Exception) { null } — подавляет все исключения. Если git не установлен, сборка не падает — просто получает значения "unknown".

Где используется результат

Сгенерированный build.properties считывается во время выполнения с помощью @PropertySource Spring Boot или подстановки плейсхолдеров application.properties. ProjectForge использует его для:

  • REST-конечная точка статуса системы: GET /rs/userStatus возвращает { systemData: { version, buildTimestamp } } — фронтенд на React отображает это в подвале
  • Диалог «О программе»: Отображает версию, дату сборки и SHA коммита
  • Проверка версии: Приложение сравнивает свою версию с последним релизом на GitHub для уведомления администраторов об обновлениях

Ключевые выводы

  • 57 строк, одна задача: Опрос git и запись файла свойств.
  • git.dirty — золото: Мгновенно показывает, включает ли сборка незакоммиченные изменения.
  • Отказоустойчивость: Все команды git имеют запасной вариант "unknown" — сборка никогда не ломается из-за отсутствия git.
  • Не задача Gradle: Это обычный класс Kotlin, вызываемый из блока doLast { } в скриптах сборки подпроектов.
  • Одна сборка — один файл свойств: Несколько подпроектов могут вызывать этот класс, каждый со своим outputFilePath.
