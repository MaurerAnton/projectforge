File #16: docker/environment.sh

Path: ./docker/environment.sh · Type: Bash shell script · Lines: 10 · Source: GitHub

What it does

A 10-line template for JVM tuning when running ProjectForge in Docker. This file gets volume-mounted into the container at /ProjectForge/environment.sh and is sourced by docker/entrypoint.sh at line 53 before starting Java. All variables are commented out by default — the admin uncomments and sets values per-installation.

Line-by-line

1  #!/bin/bash
2
3  # Set the java options and arguments here for Your docker installation only.
4
5  # Increase ProjectForge's memory settings:
6  #export JAVA_OPTS=-Xms1g -Xmx1g
7  export JAVA_OPTS=
8
9  # Define your optional program arguments here
10  export JAVA_ARGS=

Two exported variables

Both are consumed in entrypoint.sh lines 56–64 and line 74:

VariableLinePurposeExample value
JAVA_OPTS 7 JVM flags: memory, GC, debugging -Xms1g -Xmx1g -XX:+UseG1GC
JAVA_ARGS 10 Spring Boot / application arguments --server.port=9090 --spring.profiles.active=prod

The default values (JAVA_OPTS= and JAVA_ARGS=) are empty strings — the JVM uses its defaults (typically 25% of container memory for heap in Java 10+).

Connection to the Docker stack

This file bridges the gap between build-time (the Docker image, defined in Dockerfile) and run-time (the admin's environment):

  1. The admin copies this template from the repo
  2. Uncomments and sets values for the specific server
  3. Mounts the modified file as a volume: -v ./environment.sh:/ProjectForge/environment.sh
  4. entrypoint.sh sources it on container start
  5. Java launches with the admin's custom flags

Without this file (or if the mount doesn't exist), the -f check in entrypoint.sh line 51 skips sourcing entirely — no error, just JVM defaults.

Key takeaways

  • Only 10 lines: The shortest file documented so far — but critical for production memory tuning.
  • Admin-controlled: Changes don't require rebuilding the Docker image — just restart the container.
  • Optional: If the volume mount is missing, entrypoint.sh ignores it gracefully (no crash).
  • Comments are the documentation: The template itself explains each variable — self-documenting infrastructure-as-code.
