#162: LiquidityForecastCashFlow.java

Lines: 211 · Author: Kai Reinhard · Type: Java Serializable — forecast engine

Core computation engine for liquidity forecasting. The financial math lives here. 211 lines.

Data model: Four BigDecimal[] arrays indexed by day-of-forecast (day 0 = base date, day N = base date + N days): credits (actual payments received), debits (actual payments made), creditsExpected (projected incoming), debitsExpected (projected outgoing). The distinction between actual and expected enables the chart to show projected vs. realized cash flow.

Algorithm: Iterates all LiquidityEntry objects from LiquidityForecast.getEntries(). For each entry:

  • If paid=true: amount goes to credits[] or debits[] at dateOfPayment offset
  • If paid=false: amount goes to creditsExpected[] or debitsExpected[] at expectedDateOfPayment offset
  • CREDIT type → credits array, DEBIT type → debits array
  • Days out of forecast range (before base date or > nextDays) are excluded

Excel export: implements MyExcelExporter — generates a formatted spreadsheet with columns: date, credits (paid), credits expected, debits (paid), debits expected, balance (credits - debits), total balance (cumulative running sum). Uses DateFormats, NumberHelper, and I18n for localized formatting. The export creates one ContentProvider per column for column-oriented Excel generation.

Methods: getCredit(int day), getDebit(int day), getExpectedCredit(day), getExpectedDebit(day) — retrieved by LiquidityChartBuilder to populate JFreeChart TimeSeries; getBalance(day) / getTotalBalance(day) for net position and running total.
