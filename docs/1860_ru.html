#1860: AddressService.kt

projectforge-carddav/src/main/kotlin/org/projectforge/carddav/service/AddressService.kt Kotlin Spring @Service — Фасад сервиса адресной книги CardDAV. Предоставляет контакты ProjectForge (только избранные) через протокол CardDAV для синхронизации с внешними адресными книгами (Apple Контакты, Thunderbird, DAVx⁵ и др.). Расположение: projectforge-carddav/src/main/kotlin/org/projectforge/carddav/service/AddressService.kt 101 строка · 66 кода · 26 комментариев · 9 пустых
Назначение: CardDAV — это расширение адресной книги для WebDAV (RFC 6352). Данный сервис выступает в роли моста между HTTP-эндпоинтами модуля projectforge-carddav и данными адресов бизнес-уровня. Он преобразует доменные объекты адресов ProjectForge в модель Contact CardDAV, обеспечивая политику доступа только избранные.

Архитектура

Сервис следует шаблону фасада только для чтения. Операции создания и обновления закомментированы и возвращают пустые объекты Contact() — реализация CardDAV доступна только для чтения. Метод deleteContact() на самом деле не удаляет адрес; он только удаляет адрес из избранного пользователя (устанавливает isFavoriteCard = false в PersonalAddressDO). Это связано с тем, что:
  • Удаление фактического адреса повлияло бы на других пользователей, которые также добавили его в избранное
  • Клиенты CardDAV ожидают «удаления» контактов из своей личной адресной книги, а не из общего корпоративного справочника
  • Операции записи сложны: синтаксический анализ vCard, разрешение конфликтов и семантика синхронизации потребовали бы значительной дополнительной работы

AddressDAVCache (контекст #844) оборачивает дорогостоящую генерацию vCard (которая включает кодирование фотографий контактов в base64, сопоставление полей и сериализацию формата) в кэш с TTL. Без этого кэша каждая синхронизация клиента CardDAV заново генерировала бы vCard для всех контактов — операция, интенсивно использующая ЦП для адресных книг с сотнями записей и фотографий.

Контекст протокола CardDAV

Клиенты CardDAV (например, Apple Контакты на iOS/macOS, Thunderbird с CardBook, DAVx⁵ на Android) отправляют HTTP-запросы к эндпоинтам /{username}/addressBooks/. Сервис вызывается слоем сервлета/обработчика CardDAV, когда:

1. PROPFIND / address-query REPORT: Клиент выводит список всех контактов → getContactList()
2. GET /addressBooks/{uid}.vcf: Клиент получает один контакт → getContact() (в настоящее время закомментирован)
3. DELETE /addressBooks/{uid}.vcf: Клиент удаляет из адресной книги → deleteContact()
4. PUT: Создание/обновление — не поддерживается

Политика «только избранные» означает, что пользователь должен явно отметить контакты как избранные в веб-интерфейсе ProjectForge, чтобы они появились в его синхронизированной адресной книге. Это служит намеренным ограничением — полный корпоративный справочник обычно слишком велик для личных адресных книг (1000+ записей переполнили бы приложение контактов на телефоне).

Ключевая фиксация: dc92ae34c

Эта фиксация представила AddressDAVCache после обнаружения, что генерация vCard была «очень медленной» — критическое исправление производительности. Генерация vCard включает манипуляции со строками, кодирование изображений в base64 и форматирование дат для каждого контакта. Без кэширования каждый запрос синхронизации CardDAV (который может происходить каждые несколько минут с мобильных устройств) заново генерировал бы все vCard с нуля.

Ключевая фиксация: d0aed59ed — Переименование модуля

Модуль изначально назывался projectforge-caldav (Календарь + Контакты вместе), но был переименован в projectforge-carddav, когда реализации CalDAV (синхронизация календаря) и CardDAV (синхронизация контактов) были разделены на отдельные модули. Это отражает эволюцию от монолитного модуля DAV к отдельным, протокол-специфичным реализациям.

Ключевая фиксация: 27692785d — Удаление Milton

Первоначальная реализация использовала библиотеку Milton Java WebDAV, но она была удалена из-за стоимости лицензии. Реализация протокола DAV была переписана с использованием пользовательского легковесного подхода. Это распространенная проблема в реализациях WebDAV/CardDAV с открытым исходным кодом — доступные библиотеки Java (Milton, Bedework) либо имеют ограничительные лицензии, либо недостаточную поддержку CardDAV.
Засада — удаление Milton: Библиотека Milton предлагала удобные аннотации (@AddressBooks, @AddressBook) для сопоставления эндпоинтов CardDAV. После ее удаления эндпоинты CardDAV пришлось реализовывать вручную, используя необработанную обработку сервлетов или пользовательские аннотации. Это увеличило сложность реализации для соответствия протоколу CardDAV (особенно запросов addressbook-query REPORT и ответов PROPFIND со свойствами addressbook-description).
Обоснование политики «только избранные»: CardDAV в основном используется для синхронизации контактов с мобильными устройствами и настольными почтовыми клиентами. Предоставление доступа ко всему корпоративному справочнику (потенциально тысячи контактов) для каждого устройства было бы непрактичным. Пользователи выборочно добавляют в избранное нужные им контакты, создавая персонализированный поднабор. Метод deleteContact() учитывает многопользовательскую природу адресной книги, удаляя только маркер избранного пользователя, а не основную запись адреса.
