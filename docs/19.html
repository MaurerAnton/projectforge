What it does

A quick-start guide for building, running, and testing ProjectForge in Docker locally. Covers multi-arch builds (arm64/amd64), container lifecycle (run/enter/restart/remove), and an FAQ about port accessibility. Two sections are marked tbd — PostgreSQL integration and compose orchestration are deferred to doc/deployment.adoc or a compose subdirectory.

A two-sentence summary of ProjectForge's feature set: time tracking, team calendar, Gantt charts, financial administration, issue management, WBS — with JIRA as external issue tracker.

Two different build commands — lines 11 and 12 — one for Apple Silicon (arm64) and one for x86-64 (amd64), using docker buildx for cross-platform builds.

Line 17: Memory tuning

17 Edit memory settings etc. in `ProjectForge/environment.sh`.

Refers to the volume-mounted docker/environment.sh at the mount point ~/ProjectForgeDocker/ — not the source file. After the first run, the admin edits the copy on the host filesystem, and changes take effect on next restart.

Lines 19–23: Deletion

20 `docker stop projectforge`
21 `docker rm projectforge`
22 `docker images`
23 `docker rmi `

Standard Docker cleanup: stop → remove container → list images → remove image. The volume at ~/ProjectForgeDocker/ is not deleted — it persists on the host filesystem unless removed separately (docker volume rm).

Deployment is deferred to doc/deployment.adoc. The FAQ entry explains a common Spring Boot + Docker gotcha: the internal application.properties binds to localhost (unreachable from Docker host), so the Dockerfile overrides it to 0.0.0.0 (bound to all interfaces in the container namespace, reachable via port mapping).

Key takeaways

  • 45 lines, partially complete: The local-test workflow is fleshed out; PostgreSQL and compose orchestration are tbd.
  • Multi-arch aware: Separate build commands for arm64 and amd64 — important for M1/M2 Mac developers.
  • Volume at ~/ProjectForgeDocker: The admin's environment.sh edits happen on the host, not inside the container.
  • Port FAQ: server.address=0.0.0.0 override — the single most common Spring Boot Docker issue documented inline.
  • Versioned JAR: Requires the JAR to already exist (projectforge-application-8.0.jar) — no Gradle build step, Docker build assumes pre-built artifacts.
