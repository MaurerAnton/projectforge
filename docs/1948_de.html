Abstrakte Basisklasse für Hintergrund-Jobs in ProjectForge. Unterstützt Warteschlangenstrategien (keine, pro Warteschlange, pro Warteschlange und Benutzer, verweigern), optionales Timeout (Standard 120s), Fortschrittsverfolgung (Gesamt-/Verarbeitet-Anzahl) und Abbruch über Kotlin-Coroutinen. Jobs haben einen Lebenszyklus und exponieren readAccess / writeAccess für Berechtigungsprüfungen. Integriert mit UserGroupCache für die Besitzeranzeige.

Architektur

Klassenhierarchie

  • AbstractJob — abstrakte Klasse, die Comparable<AbstractJob> implementiert
  • Unterklassen müssen suspend fun run() implementieren

Job-Lebenszyklus

Der Lebenszyklus wird von JobHandler verwaltet:

  1. addJob() — Job zum Handler hinzugefügt, Status = WAITING
  2. Warteschlangenprüfung — vergleicht mit laufenden Jobs über isBlocking()
  3. onBeforeStart() — Hook vor der Ausführung
  4. start() — setzt Status auf RUNNING, ruft run() auf
  5. Bei Erfolg: onFinish() → onAfterFinish() → onAfterTermination()
  6. Bei Abbruch: cancel() → onBeforeCancel() → onAfterCancel() → onAfterTermination()
  7. Bei Fehler: markJobAsFailed() → onAfterException() → onAfterTermination()

Berechtigungen

  • readAccess(user) — delegiert standardmäßig an writeAccess(user)
  • writeAccess(user) — abstrakt, muss von Unterklasse implementiert werden
  • isOwner — prüft, ob der aktuell angemeldete Benutzer mit ownerId übereinstimmt

Integrationspunkte

  • JobHandler — verwaltet Jobs, ruft Lebenszyklusmethoden auf
  • JobHandlerScheduler — löst jede Minute tidyUp() aus
  • AccessChecker — injiziert über @Autowired
  • Coroutinen — Job-Handle gespeichert als coroutinesJob
  • I18n — Statusbezeichnungen über I18nEnum.i18nKey
