Classe de base abstraite pour les tâches d'arrière-plan dans ProjectForge. Prend en charge les stratégies de file d'attente (aucune, par file, par file et par utilisateur, refus), un délai d'attente optionnel (120 s par défaut), le suivi de la progression (nombre total/traité) et l'annulation via les coroutines Kotlin. Les tâches ont un cycle de vie et exposent readAccess / writeAccess pour les vérifications de permissions. S'intègre avec UserGroupCache pour l'affichage du propriétaire.

Architecture

Hiérarchie des classes

  • AbstractJob — classe abstraite implémentant Comparable<AbstractJob>
  • Les sous-classes doivent implémenter suspend fun run()

Cycle de vie d'une tâche

Le cycle de vie est géré par JobHandler :

  1. addJob() — tâche ajoutée au gestionnaire, statut = WAITING
  2. Vérification de la file d'attente — comparaison avec les tâches en cours via isBlocking()
  3. onBeforeStart() — crochet avant l'exécution
  4. start() — définit le statut sur RUNNING, appelle run()
  5. En cas de succès : onFinish() → onAfterFinish() → onAfterTermination()
  6. En cas d'annulation : cancel() → onBeforeCancel() → onAfterCancel() → onAfterTermination()
  7. En cas d'échec : markJobAsFailed() → onAfterException() → onAfterTermination()

Permissions

  • readAccess(user) — délègue à writeAccess(user) par défaut
  • writeAccess(user) — abstraite, doit être implémentée par la sous-classe
  • isOwner — vérifie si l'utilisateur connecté correspond à ownerId

Points d'intégration

  • JobHandler — gère les tâches, appelle les méthodes du cycle de vie
  • JobHandlerScheduler — déclenche tidyUp() chaque minute
  • AccessChecker — injecté via @Autowired
  • Coroutines — le handle Job est stocké comme coroutinesJob
  • I18n — étiquettes de statut via I18nEnum.i18nKey
