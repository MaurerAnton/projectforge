Reine Kompositionsarchitektur. Die Startseite hat keinen eigenen Inhalt. Jeder Abschnitt ist ein Jekyll {% include %} – die Seite ist rein eine Zusammensetzung wiederverwendbarer Komponenten. Dies ist der „Lego-Stein“-Ansatz für den Seitenaufbau: Der Index definiert die Reihenfolge und Parameter; jeder Include rendert seinen Abschnitt unabhängig.

Das 5-Abschnitts-Layout – eine vertikale Geschichte

{% include boxes.html columns="3" title="Warum ProjectForge?" ... %}   <!-- Abschnitt 1 -->
{% include image-block.html %}                                        <!-- Abschnitt 2 -->
{% include videos.html columns="2" title="Video-Tutorials" ... %}   <!-- Abschnitt 3 -->
{% include faqs.html category="faq-main" title="FAQs" ... %}          <!-- Abschnitt 4 -->
{% include team.html authors="kai,fin,wolfgang,christian,daniel,roger" %} <!-- 5 -->
AbschnittIncludeVisuellZweck

Jeder Include erhält Parameter: columns steuert das Rasterlayout, title/subtitle setzt Abschnittsüberschriften, category filtert Inhalte. Die Includes kümmern sich um ihr eigenes Rendering – der Index komponiert nur.

Warum width: expand?

Die Startseite verwendet width: expand (Zeile 3) – den speziellen Modus aus page.html (#3925), der rohes {{ content }} ohne Abschnitts-/Container-/Artikel-Wrapper ausgibt. Dies ist notwendig, weil jeder Include (boxes.html, videos.html) seinen EIGENEN Abschnitts-Wrapper mit eigener Hintergrundfarbe und eigenem Innenabstand bereitstellt. Wenn das Seitenlayout einen weiteren Abschnitts-Wrapper hinzufügen würde, gäbe es doppelte Innenabstände und verschachtelte Hintergründe – visuell kaputt.

Der Hero-Bereich wird ebenfalls im Front Matter konfiguriert (Zeilen 4-8): Titel „ProjectForge“, Untertitel über Teamarbeit und Budgets, Hintergrundbild Illustration_DevOps_omg.svg und search: false (keine Suchleiste im Hero).
