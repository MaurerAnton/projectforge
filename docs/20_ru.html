Архитектура только из композиции. Главная страница не имеет собственного контента. Каждый раздел — это Jekyll {% include %} — страница является чистой композицией переиспользуемых компонентов. Это подход «кирпичиков Lego» к построению страниц: индекс определяет порядок и параметры; каждое включение рендерит свой раздел независимо.

Макет из 5 разделов — вертикальная история

{% include boxes.html columns="3" title="Почему ProjectForge?" ... %}   <!-- Раздел 1 -->
{% include image-block.html %}                                        <!-- Раздел 2 -->
{% include videos.html columns="2" title="Видеоуроки" ... %}   <!-- Раздел 3 -->
{% include faqs.html category="faq-main" title="ЧаВо" ... %}          <!-- Раздел 4 -->
{% include team.html authors="kai,fin,wolfgang,christian,daniel,roger" %} <!-- 5 -->

Каждое включение получает параметры: columns управляет сеткой, title/subtitle задаёт заголовки разделов, category фильтрует контент. Включения обрабатывают свой собственный рендеринг — индекс только компонует.

Почему width: expand?

Главная страница использует width: expand (строка 3) — специальный режим из page.html (#3925), который выводит сырой {{ content }} без каких-либо обёрток section/container/article. Это необходимо, потому что каждое включение (boxes.html, videos.html) предоставляет СОБСТВЕННУЮ обёртку раздела со своим цветом фона и отступами. Если бы макет страницы добавил ещё одну обёртку раздела, возникли бы двойные отступы и вложенные фоны — визуально сломанные.

Секция hero также настроена в front matter (строки 4-8): заголовок «ProjectForge», подзаголовок о командной работе и бюджетах, фоновое изображение Illustration_DevOps_omg.svg и search: false (без строки поиска в hero).
