File #24: doc/misc/startProjectForge.sh

Path: ./doc/misc/startProjectForge.sh · Type: Bash shell script · Lines: 25 · Source: GitHub

What it does

A legacy bare-metal startup script — launches ProjectForge as a background process with 4GB heap, auto-detects Java across platforms (Linux/Cygwin), and detaches via nohup. This predates the Docker-based deployment and serves as a reference for non-containerized installations.

Section-by-section

Lines 1–3: JAR path

1  #!/bin/bash
3  PF_JAR=${HOME}/application/projectforge-application-xxx.jar"
Bug: Line 3 has a spurious double-quote at the end — ${HOME}/application/projectforge-application-xxx.jar". This is a syntax error: the opening " is missing. It should be "${HOME}/application/projectforge-application-xxx.jar". The xxx in the filename is a placeholder for the version number.

Lines 19–25: Launch

19 DEBUGOPTS=
21 nohup ${JAVA} -Xms4g -Xmx4g ${DEBUGOPTS} -jar $PF_JAR 2>&1 > /dev/null &

Launches with 4GB heap (-Xms4g -Xmx4g) — both initial and max set to the same value to avoid heap resizing overhead. nohup detaches from the terminal so the process survives logout. 2>&1 > /dev/null redirects both stdout and stderr to /dev/null — all application logging is handled internally (likely SLF4J/Logback) and written to log files, not the console. DEBUGOPTS is empty but can be set for remote debugging (-agentlib:jdwp=transport=dt_socket,server=y,suspend=n,address=5005).

Key takeaways

  • 25 lines, legacy pattern: Pre-dates the Docker-based deployment infrastructure.
  • Hardcoded 4GB heap: No tuning flexibility — contrast with environment.sh (#16) which allows per-installation JVM opts.
  • Missing opening quote: Line 3 has a syntax bug — spurious closing double-quote.
  • No signal handling: nohup + background — cannot gracefully stop via signals (must use kill).
  • Cygwin support: Indicates the project was once tested on Windows — rare for a Java project management tool.
