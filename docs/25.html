File #25: doc/misc/stopProjectForge.sh

Path: ./doc/misc/stopProjectForge.sh · Type: Bash shell script · Lines: 34 · Source: GitHub

What it does

The bare-metal stop companion to startProjectForge.sh. It is the direct ancestor of the cleanup() function in docker/entrypoint.sh — the same shutdown logic (SIGTERM → 60s wait → SIGKILL) was later copied and extended into the Docker entrypoint. Unlike the entrypoint (which is a signal trap), this is a standalone script an admin runs manually.

The lineage of checkStopped()

This is the original source of checkStopped() — a 9-line helper that checks whether the Java process is still alive and reports status. The same function appears verbatim in entrypoint.sh lines 13–22:

stopProjectForge.sh entrypoint.sh checkStopped() → checkStopped() (identical) SIGTERM → wait → SIGKILL → same logic in cleanup() trap

Line-by-line

Lines 1–4: Initialization

1  #!/bin/bash
3  PROCESS_IDENTIFIER="java.*projectforge-application"
4  APP_NAME="ProjectForge"

PROCESS_IDENTIFIER is a pgrep pattern: matches any Java process with projectforge-application in its command line. This is less precise than entrypoint.sh's pgrep -f $JAR_FILE (which matches the full /app/application.jar path) — could match a different ProjectForge instance if multiple are running.

Lines 6–15: checkStopped()

6  checkStopped() {
7    pid=$(pgrep -f $PROCESS_IDENTIFIER)
8    if [[ -z $pid ]]; then
9      echo "${APP_NAME} $1"             ← stopped → report + exit
10     exit 0
11   fi
12   if [[ -n $2 ]]; then
13     echo "${APP_NAME} $2"             ← still running → report status
14   fi
15 }

Dual-mode reporting: one argument means "report on success" (process stopped), two arguments means "report on failure" (process still running). Clever pattern — reuses one function for both the waiting loop and the final kill check.

Lines 17–34: Shutdown sequence

17 checkStopped "process not found (already terminated?)"   ← already dead?
19 echo "Sending shutdown signal to $APP_NAME..."
20 kill $pid                                                  ← SIGTERM
23 for run in {1..20}; do                                     ← 20 × 3s = 60s
24   ...
27 done
29 checkStopped "successfully stopped." "not stopped, sending sigkill now..."
30 kill -9 $pid                                               ← SIGKILL
32 sleep 2
34 checkStopped "killed." "cannot be killed?!"
Line 29 anomaly: In entrypoint.sh, the equivalent line 37 calls checkStopped "successfully stopped." (one argument — exits if stopped). Here, line 29 passes two arguments — meaning the function reports the failure message but doesn't exit, allowing kill -9 to proceed. This is the correct behavior: after waiting 60 seconds without success, it should force-kill. In entrypoint.sh, this was refactored to exit on success via one argument, and the force-kill is unconditional at line 41 — both approaches work, just slightly different control flow.

Key takeaways

  • 34 lines, 1 purpose: Gracefully stop a ProjectForge process — the bare-metal ancestor of Docker's graceful shutdown.
  • Identical shutdown sequence: SIGTERM → 60s → SIGKILL — the same logic later embedded in entrypoint.sh.
  • Manual operation: Unlike the Docker trap which fires automatically, this script is run by an admin.
  • Less precise PID detection: pgrep matches java.*projectforge-application — could collide with multiple instances.
  • Doubles as status checker: Running it on an already-stopped process prints "process not found" and exits — safe for idempotent operations.
