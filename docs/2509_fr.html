Pas UIkit. Ce fichier se trouve dans site/_sass/theme/ — un répertoire SÉPARÉ de _sass/uikit/theme/. Il est importé APRÈS les 63 fichiers de thème UIkit, ce qui lui confère une spécificité maximale pour remplacer toute valeur par défaut d'UIkit par l'identité de marque de ProjectForge.

Ce qui est présent ici et qu'UIkit ne fournit pas

Contrairement aux 63 fichiers de thème UIkit (qui définissent principalement des variables et laissent les hooks en commentaire), ce fichier contient des règles CSS réelles — 110 lignes de surcharges explicites organisées par zone visuelle :

1. Couleur des liens de marque — la règle la plus impactante

p a, li a, table td a {
  color: #BF4040;    // Rouge ProjectForge — PAS le bleu par défaut d'UIkit
}

Chaque lien dans les paragraphes, les éléments de liste et les cellules de tableau reçoit #BF4040 — un rouge atténué. C'est LA couleur de marque ProjectForge pour les liens. La couleur de lien par défaut d'UIkit est son bleu primaire ($global-primary-background ≈ #1e87f0). Cette seule règle rend le site ProjectForge visuellement distinct de tout autre site UIkit. La spécificité via les sélecteurs d'élément+contexte (p a, pas seulement a) garantit qu'elle n'affecte que les liens de contenu, pas les liens de navigation ou les boutons.

2. Barre de navigation en gras + positionnement du menu déroulant

.uk-navbar-nav > li > a {
  font-weight: 700;            // Éléments de navigation en gras — plus forts que la valeur par défaut d'UIkit
}
.uk-navbar-dropdown {
  padding: 10px 20px;          // Remplace le padding de 25px du thème
  top: 60px !important;        // Position FORCÉE — remplace la position calculée par JS
}

font-weight: 700 — rend les éléments de navigation plus gras que le poids normal d'UIkit. Combiné avec la transformation MAJUSCULE du thème, cela crée un style de navigation très affirmé.

top: 60px !important — le !important est notable. Le composant Drop d'UIkit calcule la position du menu déroulant via JavaScript et la définit en ligne. Le !important remplace le style en ligne pour forcer un espacement cohérent de 60px. Sans cela, les menus déroulants pourraient apparaître trop proches ou trop éloignés de la navigation selon la fenêtre d'affichage. C'est un motif de « lutte contre JavaScript avec CSS ».

3. Style des tableaux — lisibilité de la documentation

table {
  width: auto;                // Les tableaux ne s'étirent pas sur toute la largeur
  th { background: #f2f2f2; } // En-tête gris clair — plus clair que le thème atténué
  th:first-child, td:first-child { padding-left: 10px; }
}

width: auto — empêche les tableaux de s'étirer à 100% de leur conteneur. Sur les pages de documentation avec un contenu étroit (tableaux comparatifs, listes de paramètres), les tableaux pleine largeur gaspillent de l'espace. La largeur automatique permet aux tableaux d'être aussi larges que leur contenu.

4. Blocs de code — corrections du rendu AsciiDoc

pre {
  color: #b90505;              // Texte de code rouge foncé
  font-size: .775rem;          // Plus petit que le texte du corps
  &.highlight {
    padding: 15px; background: #f4f4f4;  // Fond du code surligné
  }
}
.listingblock {
  pre code table { margin: 0; }          // Liste de code AsciiDoc — supprimer les marges
  table.linenotable td { margin: 0; padding: 0; }  // Tableau des numéros de ligne — compact
}

Couleur de code #b90505 — rouge foncé pour le texte du code. Un choix inhabituel (la plupart des sites utilisent du gris foncé/noir). Cela lie visuellement le code à la palette rouge de la marque.

Règles .listingblock — corrigent les blocs de code rendus par AsciiDoc. AsciiDoc génère des structures imbriquées table > pre > code avec des marges par défaut qui créent un espace blanc excessif. Ces règles réduisent ces marges. Le sélecteur table.linenotable cible spécifiquement les blocs de code numérotés d'AsciiDoc.

5. Accordéon FAQ — style interactif personnalisé

#pf-faq .uk-section {
  padding-top: 0; padding-bottom: 20px;
  .uk-accordion li a.uk-accordion-title {
    border-bottom: 1px solid #ebecee !important;  // Bordure subtile entre les éléments FAQ
    font-weight: 600; padding: 10px; font-size: 16px;  // Zone cliquable plus grande
  }
  > :nth-child(n+2) { margin-top: 10px; }  // Espace entre les éléments
}

Style spécifique à la FAQ limité à #pf-faq. Chaque titre d'accordéon reçoit un séparateur de bordure léger, un poids gras et un padding généreux pour la convivialité tactile. Le !important sur la bordure remplace la valeur par défaut de l'accordéon UIkit.

Chaîne d'importation — où cela s'insère

L'ordre de compilation CSS qui permet à ces surcharges de fonctionner :

  1. variables.scss (#4091) — variables UIkit de base
  2. variables-theme.scss (#4092) — surcharges de thème ProjectForge
  3. 63 fichiers de thème via _import.scss (#4052) — thème des composants UIkit
  4. 60+ fichiers de composants principaux — CSS fonctionnel UIkit
  5. projectforge.scss (ce fichier) — surcharges de MARQUE ProjectForge (DERNIER)

Parce que ce fichier est chargé en dernier, ses règles ont une spécificité plus élevée que tout style UIkit chargé avant lui. C'est la « couche de surcharge de marque » — tout ce qui précède est le framework, ce fichier est l'identité.
