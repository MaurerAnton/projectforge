doc/misc/startProjectForge.sh

Ruta: site/uploads/startProjectForge.sh · Líneas: 22 · Shebang: #!/bin/bash

Propósito: Script de inicio para producción: detecta la instalación de Java en múltiples plataformas (Cygwin/Linux/macOS), asigna 4 GB de heap, lanza ProjectForge como un demonio en segundo plano con nohup y toda la salida redirigida a /dev/null.

Error de sintaxis en la línea 3: Falta la comilla doble de apertura — PF_JAR=${HOME}/application/...". La línea correcta debería ser PF_JAR="${HOME}/application/projectforge-application-xxx.jar". El script tal como está fallará al analizarse.

Detección de Java en tres niveles

if [ "${OSTYPE}" == 'cygwin' ]; then
  JAVA=`cygpath "${JAVA_HOME}"`/jre/bin/java     # Windows vía Cygwin
else
  if [[ -n "$JAVA_HOME" ]] && [[ -x "$JAVA_HOME/bin/java" ]]; then
    JAVA="$JAVA_HOME/bin/java"                      # Linux/macOS con JAVA_HOME
  else
    JAVA=/usr/bin/java                              # Fallback: Java del sistema
  fi
fi

Nivel 1 — Cygwin: Convierte la ruta de Windows (C:\Program Files\Java\jdk17) al estilo Unix (/cygdrive/c/Program Files/Java/jdk17) usando cygpath.

Nivel 2 — JAVA_HOME: Verifica que $JAVA_HOME/bin/java exista Y sea ejecutable (-x). Ambas condiciones deben cumplirse.

Nivel 3 — Valor por defecto del sistema: /usr/bin/java — funciona en la mayoría de las distribuciones Linux, pero puede ser una versión antigua o un stub que redirige a alternatives.

El comando de lanzamiento — línea 22

nohup ${JAVA} -Xms4g -Xmx4g ${DEBUGOPTS} -jar $PF_JAR 2>&1 > /dev/null &
ComponenteEfecto
nohupIgnora SIGHUP — el proceso sobrevive al cierre de sesión del terminal
-Xms4g -Xmx4gHeap de 4 GB, mínimo=máximo. Evita pausas del GC por redimensionamiento del heap. Apropiado para producción, excesivo para desarrollo.
${DEBUGOPTS}Vacío por defecto (línea 20). Cambiar a -agentlib:jdwp=transport=dt_socket,server=y,suspend=n,address=5005 para depuración remota.
2>&1 > /dev/nullRedirige stderr→stdout, luego stdout→/dev/null. Toda la salida de consola se descarta. ProjectForge registra en ~/ProjectForge/logs/ProjectForge.log vía Logback — no se ve afectado.
&Segundo plano — el script regresa inmediatamente, no espera al inicio.

Conclusiones clave

  • Corregir el error de sintaxis: La línea 3 no tiene comilla de apertura. El script no se ejecutará.
  • Marcador xxx: projectforge-application-xxx.jar — reemplazar xxx con la versión real antes de usar.
  • Sin verificación de inicio: El script no comprueba que ProjectForge realmente haya arrancado. Siempre revisar ~/ProjectForge/logs/ProjectForge.log después de ejecutar.
  • No para Docker: Los usuarios de Docker deben usar docker start/stop projectforge en su lugar.
