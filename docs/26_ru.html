doc/misc/startProjectForge.sh

Назначение: Скрипт запуска в продакшене — определяет установку Java на разных платформах (Cygwin/Linux/macOS), выделяет 4 ГБ кучи, запускает ProjectForge как фоновый демон nohup с перенаправлением всего вывода в /dev/null.

Синтаксическая ошибка в строке 3: Отсутствует открывающая двойная кавычка — PF_JAR=${HOME}/application/...". Правильная строка должна быть PF_JAR="${HOME}/application/projectforge-application-xxx.jar". В текущем виде скрипт не сможет выполниться.

Трёхуровневое определение Java

if [ "${OSTYPE}" == 'cygwin' ]; then
  JAVA=`cygpath "${JAVA_HOME}"`/jre/bin/java     # Windows через Cygwin
else
  if [[ -n "$JAVA_HOME" ]] && [[ -x "$JAVA_HOME/bin/java" ]]; then
    JAVA="$JAVA_HOME/bin/java"                      # Linux/macOS с JAVA_HOME
  else
    JAVA=/usr/bin/java                              # Запасной вариант: системная Java
  fi
fi

Уровень 1 — Cygwin: Преобразует путь Windows (C:\Program Files\Java\jdk17) в стиль Unix (/cygdrive/c/Program Files/Java/jdk17) с помощью cygpath.

Уровень 2 — JAVA_HOME: Проверяет, что $JAVA_HOME/bin/java существует И является исполняемым (-x). Должны выполняться оба условия.

Уровень 3 — Системная Java по умолчанию: /usr/bin/java — работает на большинстве дистрибутивов Linux, но может быть старой версией или заглушкой, перенаправляющей на alternatives.

Команда запуска — строка 22

nohup ${JAVA} -Xms4g -Xmx4g ${DEBUGOPTS} -jar $PF_JAR 2>&1 > /dev/null &
КомпонентЭффект
nohupИгнорирует SIGHUP — процесс продолжает работу после выхода из терминала
-Xms4g -Xmx4g4 ГБ кучи, минимум=максимум. Избегает пауз GC из-за изменения размера кучи. Подходит для продакшена, избыточно для разработки.
${DEBUGOPTS}По умолчанию пусто (строка 20). Измените на -agentlib:jdwp=transport=dt_socket,server=y,suspend=n,address=5005 для удалённой отладки.
2>&1 > /dev/nullПеренаправляет stderr→stdout, затем stdout→/dev/null. Весь консольный вывод отбрасывается. ProjectForge пишет логи в ~/ProjectForge/logs/ProjectForge.log через Logback — это не затрагивается.
&Фоновый режим — скрипт завершается сразу, не дожидаясь запуска.

Ключевые выводы

  • Исправьте синтаксическую ошибку: В строке 3 отсутствует открывающая кавычка. Скрипт не выполнится.
  • Заполнитель xxx: projectforge-application-xxx.jar — замените xxx на актуальную версию перед использованием.
  • Нет проверки запуска: Скрипт не проверяет, что ProjectForge действительно запустился. Всегда проверяйте ~/ProjectForge/logs/ProjectForge.log после выполнения.
  • Не для Docker: Пользователям Docker следует использовать docker start/stop projectforge.
