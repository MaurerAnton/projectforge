Zweck: DIE Zugriffsrechte-Verwaltungsseite – die zentrale Benutzeroberfläche zum Konfigurieren, wer (Gruppe) was (Zugriffstyp) auf welche Aufgabe (Strukturelement) tun darf. Generische Typarchitektur – der 3-Typen-Vertrag

public class AccessListPage extends AbstractListPage<
    AccessListForm,          // F – das Wicket-Formular mit Filter-/Suchfeldern
    AccessDao,               // D – das Datenzugriffsobjekt für CRUD
    GroupTaskAccessDO        // E – die Entität / das Domänenobjekt, das aufgelistet wird
> implements IListPageColumnsCreator<GroupTaskAccessDO>

Die Wicket-Architektur von ProjectForge verwendet für jede Listenseite ein 3-Typen-generisches Muster. Dies ist der RAD-Ansatz (Rapid Application Development) aus dem Entwicklungsleitfaden (#site/_docs/development.adoc): "Leiten Sie UI-Klassen von den Basisklassen ab." Durch die Erweiterung von AbstractListPage mit diesen drei Typen erbt die Seite:

  • Filter-/Such-UI – von AccessListForm (der F-Typ). Das Formular bietet Filterfelder (Aufgabenauswahl, Gruppenauswahl, Benutzerauswahl, Suchtext).
  • CRUD-Operationen – von AccessDao (der D-Typ). Das DAO kümmert sich um Datenbankabfragen mit automatischer Zugriffsrechtefilterung – Benutzer sehen nur Einträge, die sie anzuzeigen berechtigt sind.
  • Datenbindung – von GroupTaskAccessDO (der E-Typ). Die Entität stellt Spaltendaten, Sortierung und Zeilenidentifikation bereit.

Die Annotation @ListPage(editPage = AccessEditPage.class) in Zeile 53 verknüpft diese Listenseite mit ihrem Bearbeitungs-Pendant. Wenn ein Benutzer auf eine Zeile klickt, navigiert Wicket mit der Entitäts-ID zu AccessEditPage. Dies ist eine eigene Annotation von ProjectForge – nicht Standard-Wicket.

Die 4-Spalten-DataTable – jede Spalte ist ein Mini-Renderer

// SPALTE 1: Aufgabe – hierarchischer Baum-Pfad
new PropertyColumn("task.title") {
  @Override public void populateItem(...) {
    TaskDO task = access.getTask();
    WicketTaskFormatter.appendFormattedTask(cycle, buf, task, true, false);
    item.add(new ListSelectActionPanel(..., AccessEditPage.class, access.getId(), ...));
    addRowClick(item);  // Ganze Zeile klickbar zur Bearbeitungsseite
  }
}

// SPALTE 2: Gruppe – einfacher Text
new PropertyColumn("group.name")

// SPALTE 3: Rekursiv – Häkchen-Symbol oder leer
new PropertyColumn("recursive") {
  @Override public void populateItem(...) {
    if (access.getRecursive()) item.add(new IconPanel(..., IconType.ACCEPT));
    else item.add(createInvisibleDummyComponent(...));  // DOM-Struktur erhalten
  }
}

// SPALTE 4: Zugriffseinträge – EINGEBETTETE UNTERTABELLE
new PropertyColumn("accessEntries") {
  @Override public void populateItem(...) {
    AccessTablePanel accessTablePanel = new AccessTablePanel(..., accessEntries);
    if (rowIndex == 0) accessTablePanel.setDrawHeader(true);  // Kopfzeile in erster Zeile
    item.add(accessTablePanel);
  }
}

Spalte 1 – Aufgabenbaum (Zeilen 83-105): Die komplexeste Spalte. WicketTaskFormatter.appendFormattedTask() rendert den vollständigen hierarchischen Pfad der Aufgabe (z. B. "ACME Inc. → Web-Portal → Sprint 3") als einzelne formatierte Zeichenkette. Das ListSelectActionPanel umschließt dies mit einem klickbaren Link zu AccessEditPage. addRowClick(item) macht die GESAMTE Zeile klickbar, nicht nur den Aufgabennamen.

Spalte 3 – Rekursives Flag (Zeilen 110-125): Zeigt ein grünes Häkchen (IconType.ACCEPT), wenn der Zugriff rekursiv ist (gilt für alle Unteraufgaben). Andernfalls wird eine unsichtbare Dummy-Komponente angezeigt – nicht nur leer. Dies ist ein Wicket-Muster: Das Entfernen einer Komponente aus der Hierarchie unterbricht die Indexzuordnung des Wiederholers. Der Dummy bewahrt die Komponentenbaumstruktur, während nichts Sichtbares gerendert wird.

Spalte 4 – Eingebettetes AccessTablePanel (Zeilen 126-143): Jede Zeile enthält eine VERSCHACHTELTE Untertabelle, die einzelne Zugriffseinträge (Lesen, Schreiben, Löschen usw.) für diese Gruppen-/Aufgabenkombination anzeigt. Die Kopfzeile wird nur in der ERSTEN Zeile gezeichnet (rowIndex == 0), um sich wiederholende Spaltenüberschriften in jeder Zeile zu vermeiden. Dies ist ein Liste-in-Liste-Muster – die äußere Liste zeigt Gruppen-/Aufgabenpaare, die jeweils eine innere Liste von Zugriffstypen enthalten.

Admin-Assistent – Massenzugriffseinrichtung (Zeilen 160-174)

@Override protected void init() {
  if (getAccessChecker().isLoggedInUserMemberOfAdminGroup()) {
    ContentMenuEntryPanel menuEntry = new ContentMenuEntryPanel(..., new Link() {
      public void onClick() {
        TaskWizardPage wizardPage = new TaskWizardPage(params);
        wizardPage.setReturnToPage(AccessListPage.this);
        setResponsePage(wizardPage);
      }
    }, getString("wizard"));
    addContentMenuEntry(menuEntry);
  }
}

Der Assistenten-Button erscheint im Kontextmenü der Seite NUR für Admin-Benutzer. Er navigiert zu TaskWizardPage – einem mehrschrittigen Assistenten, der massenhaft Zugriffseinträge für eine Aufgabenhierarchie erstellt. Dies ist die im Benutzerhandbuch dokumentierte "Schnellstart"-Funktion: Anstatt Dutzende von Zugriffseinträgen manuell pro Aufgabe zu erstellen, generiert der Assistent sie automatisch mit Vorlagen (z. B. die Vorlage "Mitarbeiter" gibt Lesezugriff auf alle Unteraufgaben). Das setReturnToPage(AccessListPage.this) stellt sicher, dass der Assistent nach Abschluss hierher zurückkehrt.

Auswählen/Abwählen – nach Aufgabe, Gruppe oder Benutzer filtern (Zeilen 179-217)

public void select(String property, Object selectedValue) {
  if ("taskId".equals(property)) {
    form.getSearchFilter().setTaskId((Long) selectedValue); refresh();
  } else if ("groupId".equals(property)) {
    form.getSearchFilter().setGroupId((Long) selectedValue); refresh();
  } else if ("userId".equals(property)) {
    form.getSearchFilter().setUserId((Long) selectedValue); refresh();
  } else {
    super.select(property, selectedValue);
  }
}

Die Methoden select/unselect implementieren ein Callback-Muster für die Auswahl-Popups von ProjectForge. Wenn der Benutzer in der Filterleiste auf "Aufgabe auswählen" klickt, öffnet sich ein Auswahldialog. Wenn der Benutzer eine Aufgabe auswählt, ruft der Dialog select("taskId", taskId) auf dieser Seite auf. Die Methode setzt den Filter und ruft refresh() auf, um die Tabelle neu zu laden. unselect löscht den Filter. Der Zweig groupId enthält form.groupSelectPanel.getTextField().modelChanged() – benachrichtigt Wicket, dass das Modell des Textfelds extern geändert wurde, was ein erneutes Rendern auslöst.

Wichtige Erkenntnisse

  • 3-Typen-generisch: Jede Listenseite folgt dem <F, D, E>-Muster. Dies zu verstehen, erschließt die gesamte Wicket-UI-Architektur.
  • Dummy-Komponenten: Das createInvisibleDummyComponent in Zeile 121 ist ein kritisches Wicket-Muster – geben Sie niemals null zurück oder überspringen Sie Komponenten in einem Wiederholer.
  • Eingebettete Untertabellen: Spalte 4 rendert ein vollständiges AccessTablePanel innerhalb einer Tabellenzelle. Dies ist ein leistungsstarkes, aber aufwändiges Muster – jede Zeile erstellt einen neuen Wicket-Komponentenbaum.
  • Assistenten-Rückkehr: setReturnToPage(this) erstellt eine Navigations-Breadcrumb zurück zur Listenseite.
  • Nur-Admin-Funktionen: Der Assistenten-Button ist durch isLoggedInUserMemberOfAdminGroup() geschützt. Nicht-Admin-Benutzer sehen ihn nie – die Sicherheit wird auf UI-Ebene durchgesetzt (zusätzlich zu serverseitigen Zugriffsprüfungen im DAO).
