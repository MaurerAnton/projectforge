Arquitectura de tipo genérico — el contrato de 3 tipos

public class AccessListPage extends AbstractListPage<
    AccessListForm,          // F — el formulario Wicket con campos de filtro/búsqueda
    AccessDao,               // D — el Objeto de Acceso a Datos para CRUD
    GroupTaskAccessDO        // E — la entidad/objeto de dominio que se lista
> implements IListPageColumnsCreator<GroupTaskAccessDO>

La arquitectura Wicket de ProjectForge utiliza un patrón genérico de 3 tipos para cada página de lista. Este es el enfoque RAD (Desarrollo Rápido de Aplicaciones) de la guía de desarrollo (#site/_docs/development.adoc): "Derive clases de interfaz de usuario a partir de las clases base." Al extender AbstractListPage con estos tres tipos, la página hereda:

  • Interfaz de filtro/búsqueda — de AccessListForm (el tipo F). El formulario proporciona campos de filtro (selector de tarea, selector de grupo, selector de usuario, texto de búsqueda).
  • Operaciones CRUD — de AccessDao (el tipo D). El DAO maneja consultas a la base de datos con filtrado automático de derechos de acceso — los usuarios solo ven las entradas que están autorizados a ver.
  • Enlace de datos — de GroupTaskAccessDO (el tipo E). La entidad proporciona datos de columna, ordenamiento e identificación de fila.

La anotación @ListPage(editPage = AccessEditPage.class) en la línea 53 enlaza esta página de lista con su contraparte de edición. Cuando un usuario hace clic en una fila, Wicket navega a AccessEditPage con el ID de la entidad. Esta es una anotación propia de ProjectForge — no es Wicket estándar.

Columna 1 — Árbol de tareas (líneas 83-105): La columna más compleja. WicketTaskFormatter.appendFormattedTask() renderiza la ruta jerárquica completa de la tarea (ej., "ACME Inc. → Portal Web → Sprint 3") como una sola cadena formateada. El ListSelectActionPanel envuelve esto en un enlace cliqueable a AccessEditPage. addRowClick(item) hace que TODA la fila sea cliqueable, no solo el nombre de la tarea.

Columna 3 — Bandera recursiva (líneas 110-125): Muestra una marca de verificación verde (IconType.ACCEPT) si el acceso es recursivo (se aplica a todas las tareas hijas). De lo contrario, muestra un componente dummy invisible — no solo vacío. Este es un patrón de Wicket: eliminar un componente de la jerarquía rompe el mapeo de índices del repetidor. El dummy preserva la estructura del árbol de componentes mientras renderiza nada visible.

Columna 4 — AccessTablePanel embebido (líneas 126-143): Cada fila contiene una subtabla ANIDADA que muestra entradas de acceso individuales (lectura, escritura, eliminación, etc.) para esa combinación de grupo/tarea. El encabezado se dibuja solo en la PRIMERA fila (rowIndex == 0) para evitar repetir encabezados de columna en cada fila. Este es un patrón de lista-dentro-de-lista — la lista externa muestra pares grupo/tarea, cada uno contiene una lista interna de tipos de acceso.

Asistente de administración — configuración masiva de accesos (líneas 160-174)

@Override protected void init() {
  if (getAccessChecker().isLoggedInUserMemberOfAdminGroup()) {

      public void onClick() {
        TaskWizardPage wizardPage = new TaskWizardPage(params);

    }, getString("wizard"));
    addContentMenuEntry(menuEntry);

El botón de asistente aparece en el menú contextual de la página SOLO para usuarios administradores. Navega a TaskWizardPage — un asistente de varios pasos que crea entradas de acceso de forma masiva para una jerarquía de tareas. Esta es la función "Inicio Rápido" documentada en la guía de usuario: en lugar de crear manualmente docenas de entradas de acceso por tarea, el asistente las genera automáticamente con plantillas (ej., la plantilla "empleado" da acceso de lectura a todas las tareas hijas). El setReturnToPage(AccessListPage.this) asegura que el asistente regrese aquí después de completarse.

Seleccionar/deseleccionar — filtrar por tarea, grupo o usuario (líneas 179-217)

public void select(String property, Object selectedValue) {
  if ("taskId".equals(property)) {
    form.getSearchFilter().setTaskId((Long) selectedValue); refresh();
  } else if ("groupId".equals(property)) {
    form.getSearchFilter().setGroupId((Long) selectedValue); refresh();
  } else if ("userId".equals(property)) {
    form.getSearchFilter().setUserId((Long) selectedValue); refresh();
  } else {
    super.select(property, selectedValue);
  }
}

Los métodos select/unselect implementan un patrón de callback para los popups de selector de ProjectForge. Cuando el usuario hace clic en "Seleccionar tarea" en la barra de filtros, se abre un selector emergente. Cuando el usuario elige una tarea, el popup llama a select("taskId", taskId) en esta página. El método establece el filtro y llama a refresh() para recargar la tabla. unselect limpia el filtro. La rama groupId tiene form.groupSelectPanel.getTextField().modelChanged() — notifica a Wicket que el modelo del campo de texto fue cambiado externamente, provocando un re-renderizado.

Conclusiones clave

  • Genérico de 3 tipos: Cada página de lista sigue el patrón <F, D, E>. Entender esto desbloquea toda la arquitectura de la interfaz de usuario de Wicket.
  • Componentes dummy: El createInvisibleDummyComponent de la línea 121 es un patrón crítico de Wicket — nunca devuelva null ni omita componentes en un repetidor.
  • Subtablas embebidas: La columna 4 renderiza un AccessTablePanel completo dentro de una celda de tabla. Este es un patrón potente pero costoso — cada fila crea un nuevo árbol de componentes de Wicket.
  • Retorno de asistente: setReturnToPage(this) crea una miga de pan de navegación de vuelta a la página de lista.
  • Funciones solo para administradores: El botón de asistente está controlado por isLoggedInUserMemberOfAdminGroup(). Los usuarios no administradores nunca lo ven — la seguridad se aplica a nivel de interfaz de usuario (además de las comprobaciones de acceso del lado del servidor en el DAO).
