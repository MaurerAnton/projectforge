Objectif : LA page de gestion des droits d'accès — l'interface centrale pour configurer qui (groupe) peut faire quoi (type d'accès) sur quelle tâche (élément de structure). Bouton assistant réservé aux administrateurs pour la configuration en masse des accès.

Architecture générique à trois types — le contrat des 3 types

public class AccessListPage extends AbstractListPage<
    AccessListForm,          // F — le formulaire Wicket avec les champs de filtre/recherche
    AccessDao,               // D — l'objet d'accès aux données pour le CRUD
    GroupTaskAccessDO        // E — l'entité/objet métier listé
> implements IListPageColumnsCreator<GroupTaskAccessDO>

L'architecture Wicket de ProjectForge utilise un modèle générique à 3 types pour chaque page de liste. C'est l'approche RAD (développement rapide d'applications) du guide de développement (#site/_docs/development.adoc) : « Dérivez les classes UI des classes de base. » En étendant AbstractListPage avec ces trois types, la page hérite :

  • Interface de filtre/recherche — depuis AccessListForm (le type F). Le formulaire fournit les champs de filtre (sélecteur de tâche, sélecteur de groupe, sélecteur d'utilisateur, texte de recherche).
  • Opérations CRUD — depuis AccessDao (le type D). Le DAO gère les requêtes en base de données avec un filtrage automatique des droits d'accès — les utilisateurs ne voient que les entrées qu'ils sont autorisés à consulter.
  • Liaison de données — depuis GroupTaskAccessDO (le type E). L'entité fournit les données des colonnes, le tri et l'identification des lignes.

L'annotation @ListPage(editPage = AccessEditPage.class) à la ligne 53 relie cette page de liste à sa contrepartie d'édition. Lorsqu'un utilisateur clique sur une ligne, Wicket navigue vers AccessEditPage avec l'ID de l'entité. Il s'agit d'une annotation propre à ProjectForge — pas du Wicket standard.

Le DataTable à 4 colonnes — chaque colonne est un mini-renderer

// COLONNE 1 : Tâche — chemin arborescent hiérarchique
new PropertyColumn("task.title") {
  @Override public void populateItem(...) {
    TaskDO task = access.getTask();
    WicketTaskFormatter.appendFormattedTask(cycle, buf, task, true, false);
    item.add(new ListSelectActionPanel(..., AccessEditPage.class, access.getId(), ...));
    addRowClick(item);  // Toute la ligne est cliquable vers la page d'édition
  }
}

// COLONNE 2 : Groupe — texte simple
new PropertyColumn("group.name")

// COLONNE 3 : Récursif — icône de coche ou vide
new PropertyColumn("recursive") {
  @Override public void populateItem(...) {
    if (access.getRecursive()) item.add(new IconPanel(..., IconType.ACCEPT));
    else item.add(createInvisibleDummyComponent(...));  // Préserver la structure DOM
  }
}

// COLONNE 4 : Entrées d'accès — SOUS-TABLEAU INTÉGRÉ
new PropertyColumn("accessEntries") {
  @Override public void populateItem(...) {
    AccessTablePanel accessTablePanel = new AccessTablePanel(..., accessEntries);
    if (rowIndex == 0) accessTablePanel.setDrawHeader(true);  // En-tête sur la première ligne
    item.add(accessTablePanel);
  }
}

Colonne 1 — Arborescence des tâches (lignes 83-105) : La colonne la plus complexe. WicketTaskFormatter.appendFormattedTask() affiche le chemin hiérarchique complet de la tâche (ex. « ACME Inc. → Portail Web → Sprint 3 ») sous forme d'une chaîne formatée unique. Le ListSelectActionPanel encapsule cela dans un lien cliquable vers AccessEditPage. addRowClick(item) rend la LIGNE ENTIÈRE cliquable, pas seulement le nom de la tâche.

Colonne 3 — Indicateur récursif (lignes 110-125) : Affiche une coche verte (IconType.ACCEPT) si l'accès est récursif (s'applique à toutes les tâches enfants). Sinon, affiche un composant factice invisible — pas simplement vide. C'est un modèle Wicket : supprimer un composant de la hiérarchie casse le mappage d'index du répéteur. Le composant factice préserve la structure de l'arbre de composants tout en n'affichant rien de visible.

Colonne 4 — AccessTablePanel intégré (lignes 126-143) : Chaque ligne contient un sous-tableau IMBRIQUÉ affichant les entrées d'accès individuelles (lecture, écriture, suppression, etc.) pour cette combinaison groupe/tâche. L'en-tête n'est dessiné que sur la PREMIÈRE ligne (rowIndex == 0) pour éviter de répéter les en-têtes de colonnes sur chaque ligne. C'est un modèle liste-dans-liste — la liste externe montre les paires groupe/tâche, chacune contenant une liste interne de types d'accès.

Assistant administrateur — configuration en masse des accès (lignes 160-174)

@Override protected void init() {
  if (getAccessChecker().isLoggedInUserMemberOfAdminGroup()) {
    ContentMenuEntryPanel menuEntry = new ContentMenuEntryPanel(..., new Link() {
      public void onClick() {
        TaskWizardPage wizardPage = new TaskWizardPage(params);
        wizardPage.setReturnToPage(AccessListPage.this);
        setResponsePage(wizardPage);
      }
    }, getString("wizard"));
    addContentMenuEntry(menuEntry);
  }
}

Le bouton de l'assistant apparaît dans le menu contextuel de la page UNIQUEMENT pour les utilisateurs administrateurs. Il navigue vers TaskWizardPage — un assistant en plusieurs étapes qui crée en masse des entrées d'accès pour une hiérarchie de tâches. C'est la fonctionnalité « Démarrage rapide » documentée dans le guide utilisateur : au lieu de créer manuellement des dizaines d'entrées d'accès par tâche, l'assistant les génère automatiquement avec des modèles (ex. : le modèle « employé » donne un accès en lecture à toutes les tâches enfants). Le setReturnToPage(AccessListPage.this) garantit que l'assistant revient ici après la fin.

Sélection/Désélection — filtre par tâche, groupe ou utilisateur (lignes 179-217)

public void select(String property, Object selectedValue) {
  if ("taskId".equals(property)) {
    form.getSearchFilter().setTaskId((Long) selectedValue); refresh();
  } else if ("groupId".equals(property)) {
    form.getSearchFilter().setGroupId((Long) selectedValue); refresh();
  } else if ("userId".equals(property)) {
    form.getSearchFilter().setUserId((Long) selectedValue); refresh();
  } else {
    super.select(property, selectedValue);
  }
}

Les méthodes select/unselect implémentent un modèle de rappel pour les sélecteurs contextuels de ProjectForge. Lorsque l'utilisateur clique sur « Sélectionner une tâche » dans la barre de filtre, un sélecteur contextuel s'ouvre. Lorsque l'utilisateur choisit une tâche, le sélecteur appelle select("taskId", taskId) sur cette page. La méthode définit le filtre et appelle refresh() pour recharger le tableau. unselect efface le filtre. La branche groupId contient form.groupSelectPanel.getTextField().modelChanged() — notifie à Wicket que le modèle du champ de texte a été modifié de manière externe, déclenchant un réaffichage.

Points clés à retenir

  • Générique à 3 types : Chaque page de liste suit le modèle <F, D, E>. Comprendre cela déverrouille toute l'architecture UI Wicket.
  • Composants factices : Le createInvisibleDummyComponent de la ligne 121 est un modèle Wicket critique — ne jamais retourner null ni sauter de composants dans un répéteur.
  • Sous-tableaux intégrés : La colonne 4 affiche un AccessTablePanel complet à l'intérieur d'une cellule de tableau. C'est un modèle puissant mais coûteux — chaque ligne crée un nouvel arbre de composants Wicket.
  • Retour de l'assistant : setReturnToPage(this) crée un fil d'Ariane de navigation vers la page de liste.
  • Fonctionnalités réservées aux administrateurs : Le bouton de l'assistant est protégé par isLoggedInUserMemberOfAdminGroup(). Les utilisateurs non administrateurs ne le voient jamais — la sécurité est appliquée au niveau de l'interface utilisateur (en plus des vérifications d'accès côté serveur dans le DAO).
