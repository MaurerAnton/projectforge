Назначение: Главная страница управления правами доступа — центральный интерфейс для настройки того, кто (группа) может что делать (тип доступа) над какой задачей (структурный элемент). Отображает записи GroupTaskAccess в Wicket DataTable с 4 пользовательскими колонками: иерархическое дерево задач, имя группы, типы доступа (подтаблица) и рекурсивный флаг (галочка). Кнопка мастера только для администраторов для массовой настройки доступа.

Архитектура обобщённых типов — контракт из 3 типов

public class AccessListPage extends AbstractListPage<
    AccessListForm,          // F — форма Wicket с полями фильтра/поиска
    AccessDao,               // D — объект доступа к данным для CRUD
    GroupTaskAccessDO        // E — сущность/доменный объект, который отображается
> implements IListPageColumnsCreator<GroupTaskAccessDO>

Архитектура Wicket в ProjectForge использует шаблон с 3 обобщёнными типами для каждой страницы списка. Это подход быстрой разработки (RAD) из руководства разработчика (#site/_docs/development.adoc): "Создавайте классы UI на основе базовых классов." Расширяя AbstractListPage этими тремя типами, страница наследует:

  • Интерфейс фильтра/поиска — от AccessListForm (тип F). Форма предоставляет поля фильтра (выбор задачи, выбор группы, выбор пользователя, текст поиска).
  • CRUD-операции — от AccessDao (тип D). DAO обрабатывает запросы к базе данных с автоматической фильтрацией прав доступа — пользователи видят только те записи, которые им разрешено просматривать.
  • Привязка данных — от GroupTaskAccessDO (тип E). Сущность предоставляет данные колонок, сортировку и идентификацию строк.

Аннотация @ListPage(editPage = AccessEditPage.class) в строке 53 связывает эту страницу списка с её редактором. Когда пользователь кликает по строке, Wicket переходит на AccessEditPage с идентификатором сущности. Это собственная аннотация ProjectForge — не стандартная аннотация Wicket.

DataTable из 4 колонок — каждая колонка как мини-рендерер

// КОЛОНКА 1: Задача — иерархический путь дерева
new PropertyColumn("task.title") {
  @Override public void populateItem(...) {
    TaskDO task = access.getTask();
    WicketTaskFormatter.appendFormattedTask(cycle, buf, task, true, false);
    item.add(new ListSelectActionPanel(..., AccessEditPage.class, access.getId(), ...));
    addRowClick(item);  // Вся строка кликабельна для перехода к редактированию
  }
}

// КОЛОНКА 2: Группа — простой текст
new PropertyColumn("group.name")

// КОЛОНКА 3: Рекурсивность — иконка галочки или пусто
new PropertyColumn("recursive") {
  @Override public void populateItem(...) {
    if (access.getRecursive()) item.add(new IconPanel(..., IconType.ACCEPT));
    else item.add(createInvisibleDummyComponent(...));  // Сохраняем структуру DOM
  }
}

// КОЛОНКА 4: Записи доступа — ВСТРОЕННАЯ ПОДТАБЛИЦА
new PropertyColumn("accessEntries") {
  @Override public void populateItem(...) {
    AccessTablePanel accessTablePanel = new AccessTablePanel(..., accessEntries);
    if (rowIndex == 0) accessTablePanel.setDrawHeader(true);  // Заголовок только в первой строке
    item.add(accessTablePanel);
  }
}

Колонка 1 — Дерево задач (строки 83-105): Самая сложная колонка. WicketTaskFormatter.appendFormattedTask() отображает полный иерархический путь задачи (например, "ООО "Ромашка" → Веб-портал → Спринт 3") в виде одной форматированной строки. ListSelectActionPanel оборачивает это в кликабельную ссылку на AccessEditPage. addRowClick(item) делает кликабельной ВСЮ строку, а не только имя задачи.

Колонка 3 — Рекурсивный флаг (строки 110-125): Показывает зелёную галочку (IconType.ACCEPT), если доступ рекурсивный (применяется ко всем дочерним задачам). В противном случае показывает невидимый фиктивный компонент — не просто пустоту. Это паттерн Wicket: удаление компонента из иерархии нарушает индексное отображение повторителя. Фиктивный компонент сохраняет структуру дерева компонентов, не отображая ничего видимого.

Колонка 4 — Встроенный AccessTablePanel (строки 126-143): Каждая строка содержит ВЛОЖЕННУЮ подтаблицу, показывающую отдельные записи доступа (чтение, запись, удаление и т.д.) для данной комбинации группы/задачи. Заголовок отображается только в ПЕРВОЙ строке (rowIndex == 0), чтобы избежать повторения заголовков колонок в каждой строке. Это паттерн "список-в-списке" — внешний список показывает пары группа/задача, каждая из которых содержит внутренний список типов доступа.

Мастер для администратора — массовая настройка доступа (строки 160-174)

@Override protected void init() {
  if (getAccessChecker().isLoggedInUserMemberOfAdminGroup()) {
    ContentMenuEntryPanel menuEntry = new ContentMenuEntryPanel(..., new Link() {
      public void onClick() {
        TaskWizardPage wizardPage = new TaskWizardPage(params);
        wizardPage.setReturnToPage(AccessListPage.this);
        setResponsePage(wizardPage);
      }
    }, getString("wizard"));
    addContentMenuEntry(menuEntry);
  }
}

Кнопка мастера появляется в контекстном меню страницы ТОЛЬКО для пользователей-администраторов. Она ведёт на TaskWizardPage — многошаговый мастер, который массово создаёт записи доступа для иерархии задач. Это функция "Быстрый старт", описанная в руководстве пользователя: вместо ручного создания десятков записей доступа для каждой задачи, мастер генерирует их автоматически с помощью шаблонов (например, шаблон "сотрудник" даёт доступ на чтение ко всем дочерним задачам). setReturnToPage(AccessListPage.this) гарантирует, что мастер вернётся на эту страницу после завершения.

Выбор/отмена выбора — фильтрация по задаче, группе или пользователю (строки 179-217)

public void select(String property, Object selectedValue) {
  if ("taskId".equals(property)) {
    form.getSearchFilter().setTaskId((Long) selectedValue); refresh();
  } else if ("groupId".equals(property)) {
    form.getSearchFilter().setGroupId((Long) selectedValue); refresh();
  } else if ("userId".equals(property)) {
    form.getSearchFilter().setUserId((Long) selectedValue); refresh();
  } else {
    super.select(property, selectedValue);
  }
}

Методы select/unselect реализуют паттерн обратного вызова для всплывающих окон выбора в ProjectForge. Когда пользователь нажимает "Выбрать задачу" в панели фильтра, открывается окно выбора. Когда пользователь выбирает задачу, всплывающее окно вызывает select("taskId", taskId) на этой странице. Метод устанавливает фильтр и вызывает refresh() для перезагрузки таблицы. unselect очищает фильтр. Ветка groupId содержит form.groupSelectPanel.getTextField().modelChanged() — уведомляет Wicket о том, что модель текстового поля была изменена извне, что вызывает перерисовку.

Ключевые выводы

  • 3 обобщённых типа: Каждая страница списка следует шаблону <F, D, E>. Понимание этого открывает всю архитектуру Wicket UI.
  • Фиктивные компоненты: createInvisibleDummyComponent в строке 121 — критически важный паттерн Wicket: никогда не возвращайте null и не пропускайте компоненты в повторителе.
  • Встроенные подтаблицы: Колонка 4 отображает целый AccessTablePanel внутри ячейки таблицы. Это мощный, но дорогой паттерн — каждая строка создаёт новое дерево компонентов Wicket.
  • Возврат из мастера: setReturnToPage(this) создаёт навигационную "хлебную крошку" обратно на страницу списка.
  • Функции только для администраторов: Кнопка мастера защищена проверкой isLoggedInUserMemberOfAdminGroup(). Пользователи, не являющиеся администраторами, никогда её не видят — безопасность обеспечивается на уровне UI (в дополнение к проверкам доступа на стороне сервера в DAO).
