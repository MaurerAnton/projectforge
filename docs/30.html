File #30: .github/workflows/github-pages.yml

Path: ./.github/workflows/github-pages.yml · Type: GitHub Actions workflow · Lines: 35 · Source: GitHub

What it does

Deploys the Jekyll-based website (site/ directory) to GitHub Pages on every push to develop that touches site/** files. Uses the helaili/jekyll-action third-party action to build the Jekyll site and push the output to the gh-pages branch.

Push to develop (site/** changes) → checkout code → cache Ruby gems (vendor/bundle) → jekyll-action@v2: build site/ → deploy to gh-pages branch → projectforge.org updated

Section-by-section

Lines 1–8: Trigger

1  name: GitHub Pages publication
3  on:
4    push:
5      branches: [ develop ]
6      paths:
7        - 'site/**'
8        - '.github/workflows/**'

Only fires on pushes to develop, and only when files in site/ or workflow files change. This avoids unnecessary builds — code-only changes (Java/Kotlin) don't trigger a site rebuild.

Lines 10–22: Cache

17 - uses: actions/cache@v3
18   with:
19     path: vendor/bundle
20     key: ${{ runner.os }}-gems-${{ hashFiles('**/Gemfile') }}

Caches Ruby gems in vendor/bundle keyed by the Gemfile hash — when the Gemfile doesn't change, gems are restored from cache, speeding up builds.

Lines 24–35: Jekyll build and deploy

25 - uses: helaili/jekyll-action@v2
26   with:
27     token: ${{ secrets.GITHUB_TOKEN }}
28     jekyll_src: 'site'
31 - uses: helaili/jekyll-action@v2
32   with:
33     token: ${{ secrets.GITHUB_TOKEN }}
34     target_branch: 'gh-pages'
35     jekyll_src: 'site'

The helaili/jekyll-action builds the Jekyll site from site/ and pushes output to the gh-pages branch. The GITHUB_TOKEN secret is auto-provided by GitHub Actions — no manual token configuration needed.

Key takeaways

  • 35 lines, CI for projectforge.org: Builds the Jekyll marketing site from site/ and deploys to GitHub Pages.
  • Path-filtered trigger: Only fires on site/** changes — no wasted builds on code commits.
  • Third-party action: Uses helaili/jekyll-action@v2 — not the official GitHub Pages action.
  • Ruby gem caching: Standard CI optimization — gem installation is slow without caching.
