El clasificador de excepciones de 6 vías — líneas 88-116

public static String getExceptionMessage(AbstractSecuredBasePage securedPage,
                                         ProjectForgeException exception, boolean doLog) {
  if (exception instanceof UserException) {           // Categoría 1: errores orientados al usuario
    return securedPage.translateParams(ex.getI18nKey(), ex.getMsgParams(), ex.getParams());
  } else if (exception instanceof InternalErrorException) { // Categoría 2: errores internos
    return securedPage.translateParams(ex.getI18nKey(), ex.getMsgParams(), ex.getParams());
  } else if (exception instanceof AccessException) {  // Categoría 3: acceso denegado
    return securedPage.translateParams(ex.getI18nKey(), ex.getMessageArgs(), ex.getParams());
  }
  throw new UnsupportedOperationException("...¡agregue aquí ProjectForgeException desconocida!", exception);
}

El UnsupportedOperationException en la línea 115 es un fallo deliberado: Si una subclase desconocida de ProjectForgeException llega a este punto, el desarrollador olvidó agregar un manejador. El comentario "Para el desarrollador: ¡Agregue aquí ProjectForgeException desconocida!" es un diseño autodocumentado — el fallo obliga al desarrollador a manejar explícitamente nuevos tipos de excepción, en lugar de pasar silenciosamente con un mensaje de error genérico.

Filtrado de StackTrace: ONLY4NAMESPACE = "org.projectforge" (línea 65) limita los stack traces solo a paquetes de ProjectForge. Esto mantiene los registros limpios — sin docenas de marcos de Spring/Hibernate/Tomcat saturando los informes de error. ExceptionHelper.getFilteredStackTrace(ex, ONLY4NAMESPACE) elimina todo lo que esté fuera de org.projectforge.

El constructor — 4 rutas de excepción, 81 líneas de enrutamiento de errores (líneas 118-199)

public ErrorPage(final Throwable throwable) {
  // Predeterminado: mostrar error genérico con formulario de comentarios
  errorMessage = getString("errorpage.unknownError");
  showFeedback = true;
  
  if (throwable != null) {
    rootCause = ExceptionHelper.getRootCause(throwable);
    
    // RUTA A: ProjectForgeException — mensaje traducido
    if (rootCause instanceof ProjectForgeException) {
      errorMessage = getExceptionMessage(this, (ProjectForgeException) rootCause, true);
    
    // RUTA B: ServletException — registrar + mensaje "contacte al equipo de desarrollo"
    } else if (throwable instanceof ServletException) {
      messageNumber = String.valueOf(System.currentTimeMillis());
      log.error("Mensaje #" + messageNumber + ": " + throwable.getMessage(), throwable);
      errorMessage = getLocalizedMessage(UserException.I18N_KEY_PLEASE_CONTACT_DEVELOPER_TEAM, messageNumber);
    
    // RUTA C: PageExpiredException — tiempo de sesión agotado (sin formulario de comentarios)
    } else if (throwable instanceof PageExpiredException) {
      showFeedback = false;  // No pedir comentarios al usuario por tiempo de espera
      errorMessage = getString("message.wicket.pageExpired");
    
    // RUTA D: Todo lo demás — genérico "contacte al equipo de desarrollo"
    } else {
      messageNumber = String.valueOf(System.currentTimeMillis());
      log.error("Mensaje #" + messageNumber + ": " + throwable.getMessage(), throwable);
      errorMessage = getLocalizedMessage(UserException.I18N_KEY_PLEASE_CONTACT_DEVELOPER_TEAM, messageNumber);
    }
  }
}

RUTA A — Excepciones de ProjectForge (líneas 130-131): La ruta feliz para errores conocidos. La causa raíz se desempaqueta mediante ExceptionHelper.getRootCause() (elimina envoltorios de ServletException/Spring), y el mensaje se traduce mediante i18n. El usuario ve un mensaje útil en su idioma.

RUTA B — ServletException (líneas 132-138): Errores a nivel de contenedor (fallos en la cadena de filtros de Tomcat, errores de análisis de solicitudes). Obtiene un messageNumber — System.currentTimeMillis() como cadena. Este es el ID de error único mostrado al usuario como "Por favor contacte al equipo de desarrollo con el mensaje #1712345678901". El número es una marca de tiempo, para que el soporte pueda correlacionarlo con los registros del servidor.

RUTA C — PageExpiredException (líneas 139-143): La sesión de Wicket del usuario expiró. showFeedback = false — sin formulario de comentarios, porque el usuario no encontró un error, solo esperó demasiado. El título se establece en "Mensaje" (línea 143) en lugar del "Error" predeterminado.

RUTA D — Todo lo demás (líneas 144-148): Excepciones desconocidas (NullPointerException, excepciones de Hibernate, etc.). Mismo tratamiento que ServletException — número de mensaje + "contacte al equipo de desarrollo".

Informe de errores proactivo — correo electrónico al equipo de soporte (líneas 201-223)

private void sendProactiveMessageToSupportTeam() {
  if (configService.getPfSupportMailAddress() != null && configService.isSendMailConfigured()) {
    SendFeedbackData errorData = new SendFeedbackData();
    errorData.setSender(sendMail.getMailFromStandardEmailSender());
    errorData.setReceiver(configService.getPfSupportMailAddress());
    errorData.setSubject("Error ocurrido: #" + messageNumber + " en " + domainService.getDomain());
    errorData.setDescription(
      "Error ocurrido en: " + dateString + "(" + timeZone + ")" +
      " con número: #" + messageNumber +
      " del usuario: " + sender +
      " Traza de pila de la excepción: \n" + rootCauseStackTrace);
    sendFeedback.send(errorData);
  }
}

Este es el sistema de monitoreo proactivo. Cuando ocurre un error crítico Y el correo de soporte está configurado, el sistema envía automáticamente un correo electrónico que contiene:

  • El número de mensaje único (marca de tiempo)
  • El dominio donde ocurrió el error
  • La fecha/hora con zona horaria
  • El usuario que encontró el error
  • La traza de pila completa de la causa raíz

Esto es esencialmente un sistema de monitoreo de errores incorporado sin necesidad de Sentry, Datadog o ELK. Para implementaciones autoalojadas, esta es la forma principal en que los administradores se enteran de errores en producción. El correo va a configService.getPfSupportMailAddress() — configurado en projectforge.properties.

Tres categorías de excepciones se suprimen deliberadamente — no se envía correo, no hay notificación proactiva:

ExcepciónPor qué se suprime
null throwableErrorPage llamado sin una excepción — desde CallAllPagesTest (comentario línea 188-189). El conjunto de pruebas navega a ErrorPage directamente para verificar que se renderiza.
ComponentNotFoundExceptionCiclo de vida normal de Wicket. Cuando un usuario navega a través de AddressListPage, los componentes de imagen son eliminados por el framework — Wicket lanza esto al intentar encontrar un componente que ya fue limpiado. No es un error.
ConnectExceptionEl navegador del usuario se desconectó. Ocurre cuando el usuario hace clic para salir durante una solicitud de larga duración — para cuando la respuesta está lista, el navegador ya no está. No es un error.

Bloque estático GlobalExceptionRegistry (líneas 67-70): Pre-registra StalePageException y ComponentNotFoundException con descripciones legibles para humanos ("Página Wicket ya no disponible"). La verificación sendMailToDevelopers() en la línea 196 consulta este registro — solo las excepciones NO registradas como "conocidas/esperadas" activan correos proactivos.

Anulaciones de Wicket — identidad de página

@Override public boolean isVersioned() { return false; }    // Nunca almacenar versiones de página
@Override public boolean isErrorPage() { return true; }     // Decirle a Wicket que ESTA es una página de error

isVersioned() = false (línea 257): Wicket normalmente versiona las páginas — almacena copias antiguas para que el botón de retroceso del navegador funcione. Para páginas de error, el versionado está deshabilitado porque: (1) las páginas de error son transitorias — no deberías navegar hacia atrás a un error, (2) el versionado almacena el objeto de excepción en la sesión, lo que podría filtrar memoria o contener datos sensibles, (3) las páginas de error siempre deben mostrar contenido fresco al volver a visitar.

isErrorPage() = true (línea 265): Le dice a la cadena de manejo de excepciones de Wicket que ESTA página es la página de error — evita la recursión infinita si la propia página de error lanza una excepción (Wicket mostraría entonces su propia página de error de respaldo).

Dónde encaja Pac-Man

El huevo de Pascua de Pac-Man (#3780) está enlazado DESDE esta página de error. La plantilla HTML (ErrorPage.html, 24 líneas) muestra la estructura: un div alert-danger para el mensaje de error, un FeedbackPanel para informes de usuario, y un formulario con botones de acción. El botón "Jugar Pac-Man" se renderizaría como uno de los botones de acción del formulario — convirtiendo un error 500 en una invitación al juego. Este es el momento donde la frustración se convierte en diversión.
