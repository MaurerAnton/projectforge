Chemin : projectforge-wicket/src/main/java/org/projectforge/web/wicket/ErrorPage.java · Lignes : 268 · Étend : AbstractSecuredPage · Auteur : Kai Reinhard

Objectif : LA page d'erreur globale — intercepte TOUTE exception non gérée dans l'application web Wicket. Classe les exceptions en 6 catégories, journalise avec des numéros de message uniques (System.currentTimeMillis()), affiche des messages traduits et conviviaux, propose éventuellement un formulaire de retour pour que les utilisateurs soumettent des rapports d'erreur, et envoie de manière proactive un e-mail à l'équipe de support pour les erreurs critiques. C'est ici que l'œuf de Pâques Pac-Man est lié.

Le classifieur d'exceptions en 6 catégories — lignes 88-116

public static String getExceptionMessage(AbstractSecuredBasePage securedPage,
                                         ProjectForgeException exception, boolean doLog) {
  if (exception instanceof UserException) {           // Catégorie 1 : erreurs utilisateur
    return securedPage.translateParams(ex.getI18nKey(), ex.getMsgParams(), ex.getParams());
  } else if (exception instanceof InternalErrorException) { // Catégorie 2 : erreurs internes
    return securedPage.translateParams(ex.getI18nKey(), ex.getMsgParams(), ex.getParams());
  } else if (exception instanceof AccessException) {  // Catégorie 3 : accès refusé
    return securedPage.translateParams(ex.getI18nKey(), ex.getMessageArgs(), ex.getParams());
  }
  throw new UnsupportedOperationException("...ajoutez ici une ProjectForgeException inconnue !", exception);
}

Trois types d'exceptions spécifiques à ProjectForge, chacun traité avec une traduction i18n. La différence clé entre eux :

L'UnsupportedOperationException à la ligne 115 est un crash délibéré : Si une sous-classe inconnue de ProjectForgeException atteint ce point, le développeur a oublié d'ajouter un gestionnaire. Le commentaire "Pour le développeur : veuillez ajouter ici une ProjectForgeException inconnue !" est une conception auto-documentée — le crash force le développeur à gérer explicitement les nouveaux types d'exceptions, plutôt que de passer silencieusement avec un message d'erreur générique.

Filtrage de la pile d'appels : ONLY4NAMESPACE = "org.projectforge" (ligne 65) limite les traces de pile aux packages ProjectForge uniquement. Cela maintient les journaux propres — pas de dizaines de trames Spring/Hibernate/Tomcat encombrant les rapports d'erreur. ExceptionHelper.getFilteredStackTrace(ex, ONLY4NAMESPACE) supprime tout ce qui est en dehors de org.projectforge.

Le constructeur — 4 chemins d'exception, 81 lignes de routage d'erreur (lignes 118-199)

public ErrorPage(final Throwable throwable) {
  // Par défaut : afficher une erreur générique avec formulaire de retour
  errorMessage = getString("errorpage.unknownError");
  showFeedback = true;
  
  if (throwable != null) {
    rootCause = ExceptionHelper.getRootCause(throwable);
    
    // CHEMIN A : ProjectForgeException — message traduit
    if (rootCause instanceof ProjectForgeException) {
      errorMessage = getExceptionMessage(this, (ProjectForgeException) rootCause, true);
    
    // CHEMIN B : ServletException — journalisation + message "contactez l'équipe de développement"
    } else if (throwable instanceof ServletException) {
      messageNumber = String.valueOf(System.currentTimeMillis());
      log.error("Message #" + messageNumber + " : " + throwable.getMessage(), throwable);
      errorMessage = getLocalizedMessage(UserException.I18N_KEY_PLEASE_CONTACT_DEVELOPER_TEAM, messageNumber);
    
    // CHEMIN C : PageExpiredException — expiration de session (pas de formulaire de retour)
    } else if (throwable instanceof PageExpiredException) {
      showFeedback = false;  // Ne pas demander de retour à l'utilisateur en cas d'expiration
      errorMessage = getString("message.wicket.pageExpired");
    
    // CHEMIN D : Tout le reste — "contactez l'équipe de développement" générique
    } else {
      messageNumber = String.valueOf(System.currentTimeMillis());
      log.error("Message #" + messageNumber + " : " + throwable.getMessage(), throwable);
      errorMessage = getLocalizedMessage(UserException.I18N_KEY_PLEASE_CONTACT_DEVELOPER_TEAM, messageNumber);
    }
  }
}

CHEMIN A — Exceptions ProjectForge (lignes 130-131) : Le chemin heureux pour les erreurs connues. La cause racine est extraite via ExceptionHelper.getRootCause() (supprime les wrappers ServletException/Spring), et le message est traduit via i18n. L'utilisateur voit un message utile dans sa langue.

CHEMIN B — ServletException (lignes 132-138) : Erreurs au niveau du conteneur (échecs de la chaîne de filtres Tomcat, erreurs d'analyse des requêtes). Obtient un messageNumber — System.currentTimeMillis() sous forme de chaîne. C'est l'ID d'erreur unique affiché à l'utilisateur comme "Veuillez contacter l'équipe de développement avec le message #1712345678901". Le numéro est un horodatage, afin que le support puisse le corréler avec les journaux du serveur.

CHEMIN C — PageExpiredException (lignes 139-143) : La session Wicket de l'utilisateur a expiré. showFeedback = false — pas de formulaire de retour, car l'utilisateur n'a pas rencontré de bogue, il a simplement attendu trop longtemps. Le titre est défini sur "Message" (ligne 143) au lieu du "Erreur" par défaut.

CHEMIN D — Tout le reste (lignes 144-148) : Exceptions inconnues (NullPointerException, exceptions Hibernate, etc.). Même traitement que ServletException — numéro de message + "contactez l'équipe de développement".

Signalement proactif des erreurs — envoyer un e-mail à l'équipe de support (lignes 201-223)

private void sendProactiveMessageToSupportTeam() {
  if (configService.getPfSupportMailAddress() != null && configService.isSendMailConfigured()) {
    SendFeedbackData errorData = new SendFeedbackData();
    errorData.setSender(sendMail.getMailFromStandardEmailSender());
    errorData.setReceiver(configService.getPfSupportMailAddress());
    errorData.setSubject("Erreur survenue : #" + messageNumber + " sur " + domainService.getDomain());
    errorData.setDescription(
      "Erreur survenue à : " + dateString + "(" + timeZone + ")" +
      " avec le numéro : #" + messageNumber +
      " de l'utilisateur : " + sender +
      " Trace de la pile d'exception : \n" + rootCauseStackTrace);
    sendFeedback.send(errorData);
  }
}

C'est le système de surveillance proactive. Lorsqu'une erreur critique se produit ET que l'e-mail de support est configuré, le système envoie automatiquement un e-mail contenant :

  • Le numéro de message unique (horodatage)
  • Le domaine où l'erreur s'est produite
  • La date/heure avec le fuseau horaire
  • L'utilisateur qui a rencontré l'erreur
  • La trace de pile complète de la cause racine

Il s'agit essentiellement d'un système de surveillance des erreurs intégré, sans avoir besoin de Sentry, Datadog ou ELK. Pour les déploiements auto-hébergés, c'est le principal moyen pour les administrateurs de prendre connaissance des erreurs de production. L'e-mail est envoyé à configService.getPfSupportMailAddress() — configuré dans projectforge.properties.

Trois catégories d'exceptions sont délibérément supprimées — aucun e-mail n'est envoyé, aucune notification proactive :

ExceptionPourquoi supprimée
null throwableErrorPage appelée sans exception — depuis CallAllPagesTest (commentaire lignes 188-189). La suite de tests navigue directement vers ErrorPage pour vérifier son rendu.
ComponentNotFoundExceptionCycle de vie normal de Wicket. Lorsqu'un utilisateur navigue dans AddressListPage, les composants image sont supprimés par le framework — Wicket lance ceci en essayant de trouver un composant déjà nettoyé. Ce n'est pas un bogue.
ConnectExceptionLe navigateur de l'utilisateur s'est déconnecté. Se produit lorsque l'utilisateur clique ailleurs pendant une requête de longue durée — au moment où la réponse est prête, le navigateur est parti. Ce n'est pas un bogue.

Bloc statique GlobalExceptionRegistry (lignes 67-70) : Pré-enregistre StalePageException et ComponentNotFoundException avec des descriptions lisibles par l'humain ("Page Wicket plus disponible"). La vérification sendMailToDevelopers() à la ligne 196 consulte ce registre — seules les exceptions NON enregistrées comme "connues/attendues" déclenchent des e-mails proactifs.

Redéfinitions Wicket — identité de la page

@Override public boolean isVersioned() { return false; }    // Ne jamais stocker les versions de page
@Override public boolean isErrorPage() { return true; }     // Dire à Wicket que CECI est une page d'erreur

isVersioned() = false (ligne 257) : Normalement, Wicket versionne les pages — stocke des copies anciennes pour que le bouton de retour du navigateur fonctionne. Pour les pages d'erreur, le versionnage est désactivé car : (1) les pages d'erreur sont transitoires — vous ne devriez pas revenir en arrière vers une erreur, (2) le versionnage stocke l'objet exception dans la session, ce qui pourrait fuir la mémoire ou contenir des données sensibles, (3) les pages d'erreur doivent toujours afficher un contenu frais lors d'une revisite.

isErrorPage() = true (ligne 265) : Indique à la chaîne de gestion des exceptions de Wicket que CETTE page est la page d'erreur — empêche la récursion infinie si la page d'erreur elle-même lève une exception (Wicket afficherait alors sa propre page d'erreur de secours).

Où Pac-Man s'intègre

L'œuf de Pâques Pac-Man (#3780) est lié DEPUIS cette page d'erreur. Le modèle HTML (ErrorPage.html, 24 lignes) montre la structure : un div alert-danger pour le message d'erreur, un FeedbackPanel pour les rapports utilisateur, et un formulaire avec des boutons d'action. Le bouton "Jouer à Pac-Man" serait rendu comme l'un des boutons d'action du formulaire — transformant une erreur 500 en invitation à jouer. C'est le moment où la frustration devient amusante.
