What it does

The Gradle version catalog — a central single source of truth for all dependency versions across 20+ Gradle modules. Declares 80+ version aliases and 120+ library coordinates in TOML format. Version constraints are resolved here, then aliases are referenced in build.gradle.kts files across the project — when a version changes, it changes in one place only.

Version pinning notes from comments

The file contains several critical version constraints documented in comments — these are dependency hell warnings for future maintainers:

LibraryConstraintReason
webauthn4jMust stay at 0.28.20.29+ requires Jackson 2.20+, 0.31+ pulls Jackson 3.x — conflicts with the project's Jackson 2.18.x
Apache GroovyMust stay ≤ 4.0.244.0.25+ depends on Jackson 2.19+ which conflicts with project's 2.18.x
RhinoMust stay at 1.7.151.8+ removed tools.shell.Global used by LessCompiler in the webapp
These are technical debt markers. Jackson 2.18.x vs 2.19+ is a known pain point — upgrading Jackson would enable Groovy 4.0.25+ and webauthn4j 0.29+, but would cascade through the entire dependency tree.

How it's consumed

The catalog is declared in buildSrc/settings.gradle.kts (#3) and shared across all modules. Individual build.gradle.kts files reference libraries by alias:

implementation(libs.org.apache.wicket.spring)   ← Gradle generates typesafe accessors

The root build.gradle.kts (#1) uses strictly() and force() to lock versions and prevent transitive downgrades — complementing the catalog's declarations.

Key takeaways

  • 218 lines, 80+ versions, 120+ libraries: The largest single file documented so far — the entire dependency manifest for a 20-module project.
  • 3 critical version pins: webauthn4j, Groovy, Rhino — all frozen due to transitive Jackson or API-breaking issues.
  • 15+ domain libraries: PDF generation (iText + FOP), CalDAV (ical4j), MS Project (MPXJ), WebAuthn, vCard, QR codes — reflects the breadth of a project management tool.
  • Dual database support: HSQLDB + PostgreSQL — Flyway has separate drivers for each.
  • Wicket-centric UI: The web layer is built on Apache Wicket 10.8 (not React/Angular/Vue) — the webapp module adds React as a modernization layer on top.
