Parte del código base original de ProjectForge desde 2016. Sobrevivió a la reescritura 7.x, a la migración CRA→Vite y a la transición Wicket→React.

¿Por qué hay un juego en un software de gestión de proyectos? Este es un huevo de pascua para desarrolladores — cuando la aplicación web Wicket encuentra una excepción no controlada (error 500), en lugar de un aburrido stack trace, la página de error ofrece jugar al Pac-Man. Convierte la frustración en diversión. El juego también es accesible directamente en /wa/pacman para descansos rápidos durante el desarrollo.

Arquitectura del juego — 11 estados, 4 fantasmas, 30 FPS

var NONE = 4, UP = 3, LEFT = 2, DOWN = 1, RIGHT = 11,
    WAITING = 5, PAUSE = 6, PLAYING = 7,
    COUNTDOWN = 8, EATEN_PAUSE = 9, DYING = 10;
Pacman.FPS = 30;

11 estados del juego: El juego rastrea el estado mediante constantes numéricas — no un enum (JS es anterior al uso generalizado de enums). Transiciones de estado: WAITING → COUNTDOWN → PLAYING → (DYING | EATEN_PAUSE) → PLAYING. El estado EATEN_PAUSE es la breve pausa cuando Pac-Man se come un fantasma — un detalle clásico de arcade.

Sistema de IA de fantasmas: Cada fantasma (Pacman.Ghost) rastrea: posición, dirección, comestible (vulnerable después de la píldora de poder), comido (regresando a la base) y pendiente (temporizador de aparición). La velocidad de movimiento varía según el estado — los fantasmas vulnerables se mueven a velocidad 1 (lenta), los fantasmas ocultos a 4 (rápido para regresar a la base), los normales a 2.

Bucle de juego a 30 FPS: El juego se ejecuta a 30 fotogramas por segundo mediante setInterval. La detección de colisiones utiliza ajuste a la cuadrícula — los fantasmas se ajustan a celdas de 10px para evitar saltar sobre las paredes. La función addBounded() maneja casos extremos donde la velocidad de un fantasma podría sobrepasar el límite de una pared.

La capa de renderizado — Canvas + sprites de audio

El juego se renderiza en un elemento <canvas> de HTML5. El laberinto, las bolitas, Pac-Man y los fantasmas se dibujan todos mediante programación. El audio utiliza más de 20 archivos .ogg y .mp3 en scripts/pacman/audio/ — sirena (persecución de fantasmas), masticación (comer bolitas), muerte (muerte de Pac-Man), comer fantasma (consumo de fantasma), vidas extra (1-up). Se proporcionan ambos formatos para compatibilidad con navegadores (OGG para Firefox, MP3 para Chrome/Safari).

Errores conocidos (de comentarios en la fuente, líneas 4-9): El audio en bucle no funciona correctamente, las frutas y niveles están incompletos, el estado de fantasma comido está roto (el fantasma debería regresar a la base pero no lo hace), y los mecanismos de personalidad adecuados de los fantasmas (Blinky persigue, Pinky embosca, Inky es aleatorio, Clyde deambula) no están completamente implementados.
