El puente JPA→HTML — por qué esta prueba es importante

PropertyModel<String> model = new PropertyModel<>(new PFUserDO(), "username");
assertInteger(255, MaxLengthTextField.getMaxLength(model));      // Desde @Column(length=255)
assertInteger(255, MaxLengthTextField.getMaxLength(model, 300)); // Anulación ignorada (gana BD)
assertInteger(100, MaxLengthTextField.getMaxLength(model, 100)); // Anulación manual gana (100 < 255)

model = new PropertyModel<>(new BaseSearchFilter(), "searchString");
assertNull(MaxLengthTextField.getMaxLength(model));              // Sin @Column = sin maxlength
assertInteger(100, MaxLengthTextField.getMaxLength(model, 100)); // Anulación manual

assertNull(MaxLengthTextField.getMaxLength(Model.of("test")));   // Modelo simple = sin maxlength

El algoritmo bajo prueba: getMaxLength(propertyModel, manualMaxLength) sigue esta lógica:

  1. Extrae el nombre de la propiedad del PropertyModel de Wicket (ej., "username")
  2. Encuentra la clase de entidad JPA y el campo correspondiente
  3. Lee la anotación @Column(length = N)
  4. Si se proporciona un maxLength manual Y es menor que la longitud de la columna BD, usa el valor manual (la validación HTML debe ser más estricta que la BD)
  5. Si no existe anotación @Column, retorna null (sin atributo maxlength en el input HTML)

Esto previene un error común: los usuarios escriben 300 caracteres en un campo de formulario, envían y la base de datos trunca a 255. Con maxlength HTML establecido desde la anotación JPA, el navegador evita la entrada demasiado larga antes del envío.

Helper assertInteger: Aserción personalizada que verifica tanto no nulo COMO igualdad. Evita la trampa común de que assertEquals(255, valor) pase cuando valor es null (el autounboxing lanzaría NPE).
