Das Build-Abhängigkeitsmanifest. Die Ausführung von bundle install liest diese Datei und installiert die genauen Gem-Versionen in Gemfile.lock. Die Ausführung von bundle exec jekyll serve startet den Entwicklungsserver mit diesen gesperrten Versionen. Das Ökosystem: Ruby → Bundler → Jekyll → Liquid → HTML.

Die 8 Gems, die die Website betreiben

gem "jekyll", "4.4.1"                          # Generator für statische Seiten
group :jekyll_plugins do
  gem "jekyll-feed", "~> 0.17.0"              # RSS/Atom-Feed-Generierung
  gem 'jekyll-paginate', '~> 1.1'             # Seitenaufteilung für Blog-Listen
  gem 'jekyll-seo-tag', '~> 2.8.0'            # SEO-Meta-Tags (og:, twitter:)
  gem 'jekyll-gist', '~> 1.5.0'               # GitHub-Gists in Seiten einbetten
  gem 'jekyll-avatar', '~> 0.8.0'             # GitHub-Avatar-Bilder
  gem 'jekyll-asciidoc', '~> 3.0.1'           # AsciiDoc → HTML-Konvertierung ⭐
  gem 'jekyll-numbered-headings', '~> 0.1.1'  # Automatisch nummerierte Abschnittsüberschriften
  gem 'kramdown-parser-gfm', '~> 1.1.0'       # GitHub-Flavored-Markdown-Parser
end
gem "webrick", "~> 1.9.0"                     # Ruby-HTTP-Server für die Entwicklung

jekyll-asciidoc ist das kritische Plugin: Ohne es würden alle 63 .adoc-Dokumentationsdateien (installation.adoc, userguide.adoc usw.) nicht gerendert werden. Dieses Gem verbindet Jekylls Liquid-Templating mit AsciiDocs Auszeichnungssprache – es ist der Grund, warum die ProjectForge-Dokumente sowohl {% include %} (Liquid) als auch == Abschnitt == (AsciiDoc) in derselben Datei verwenden können.

Gemfile.lock-Begleiter: Die Datei Gemfile.lock (ebenfalls in site/) zeichnet die GENAUEN installierten Versionen auf, einschließlich transitiver Abhängigkeiten. Dies gewährleistet reproduzierbare Builds auf verschiedenen Maschinen. Es ist das Ruby-Äquivalent von package-lock.json.

Strategie zur Versionseinfrierung

OperatorBeispielBedeutung
Exakt"4.4.1"jekyll 4.4.1 genau – keine andere Version
Pessimistisch"~> 0.17.0">= 0.17.0 UND < 0.18.0 – Patch-Updates erlaubt, Minor eingefroren
Pessimistisch"~> 3.0.1">= 3.0.1 UND < 3.1.0 – für jekyll-asciidoc

Jekyll selbst ist auf die GENAUE Version 4.4.1 festgelegt – größere Jekyll-Upgrades brechen oft Themes und Plugins. Plugins verwenden pessimistische Versionierung (~>), um Sicherheitspatches zu ermöglichen, ohne das Risiko von Breaking Changes einzugehen.

Auskommentierte Alternativen: Die Zeilen 15-19 zeigen den standardmäßigen Jekyll-Boilerplate-Code für GitHub Pages – kommentieren Sie das github-pages-Gem aus, wenn Sie direkt auf GitHub Pages hosten. Die ProjectForge-Website verwendet ein benutzerdefiniertes Jekyll-Setup (nicht das integrierte Jekyll von GitHub Pages), daher bleiben diese auskommentiert.
