Манифест зависимостей сборки. Запуск bundle install считывает этот файл и устанавливает точные версии гемов в Gemfile.lock. Запуск bundle exec jekyll serve запускает сервер разработки, используя эти зафиксированные версии. Экосистема: Ruby → Bundler → Jekyll → Liquid → HTML.

8 гемов, которые обеспечивают работу сайта

gem "jekyll", "4.4.1"                          # Генератор статических сайтов
group :jekyll_plugins do
  gem "jekyll-feed", "~> 0.17.0"              # Генерация RSS/Atom ленты
  gem 'jekyll-paginate', '~> 1.1'             # Разбивка страниц для списков блога
  gem 'jekyll-seo-tag', '~> 2.8.0'            # SEO мета-теги (og:, twitter:)
  gem 'jekyll-gist', '~> 1.5.0'               # Встраивание GitHub Gist в страницы
  gem 'jekyll-avatar', '~> 0.8.0'             # Изображения аватаров GitHub
  gem 'jekyll-asciidoc', '~> 3.0.1'           # Конвертация AsciiDoc → HTML ⭐
  gem 'jekyll-numbered-headings', '~> 0.1.1'  # Автоматическая нумерация заголовков разделов
  gem 'kramdown-parser-gfm', '~> 1.1.0'       # Парсер Markdown в стиле GitHub
end
gem "webrick", "~> 1.9.0"                     # HTTP-сервер Ruby для разработки

jekyll-asciidoc — критически важный плагин: Без него все 63 файла документации .adoc (installation.adoc, userguide.adoc и т.д.) не будут отображаться. Этот гем соединяет шаблонизатор Liquid от Jekyll с разметкой AsciiDoc — именно благодаря ему в документах ProjectForge можно использовать одновременно {% include %} (Liquid) и == Раздел == (AsciiDoc) в одном файле.

Компаньон Gemfile.lock: Файл Gemfile.lock (также в site/) записывает ТОЧНЫЕ установленные версии, включая транзитивные зависимости. Это обеспечивает воспроизводимую сборку на разных машинах. Это аналог package-lock.json в Ruby.

Стратегия фиксации версий

ОператорПримерЗначение
Точный"4.4.1"jekyll 4.4.1 точно — никакая другая версия
Пессимистичный"~> 0.17.0">= 0.17.0 И < 0.18.0 — разрешены только патч-обновления, минорная версия заморожена
Пессимистичный"~> 3.0.1">= 3.0.1 И < 3.1.0 — для jekyll-asciidoc

Сам Jekyll зафиксирован на ТОЧНОЙ версии 4.4.1 — крупные обновления Jekyll часто ломают темы и плагины. Плагины используют пессимистичное версионирование (~>), чтобы разрешить исправления безопасности без риска критических изменений.

Закомментированные альтернативы: Строки 15-19 показывают стандартный шаблон Jekyll для GitHub Pages — раскомментируйте гем github-pages, если размещаетесь непосредственно на GitHub Pages. Сайт ProjectForge использует собственную настройку Jekyll (не встроенный Jekyll GitHub Pages), поэтому эти строки оставлены закомментированными.
