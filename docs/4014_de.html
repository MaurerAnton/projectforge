#4014: hero.html

site/_includes/hero.html

Pfad: site/_includes/hero.html · Zeilen: 56 · Typ: Jekyll Liquid Include

Zweck: Rendert das Hero-Banner oben auf wichtigen Seiten — vollflächiges Hintergrundbild mit Überlagerung, Seitentitel, Untertitel, optionalem Hero-Bild und optionaler SimpleJekyllSearch-Leiste. Verwendet von der Startseite, der Suchseite und jeder Seite mit hero: Front Matter.

Enthält eine eigene Navigationsleiste. Anders als Seiten ohne Hero (die die Navigationsleiste von default.html erhalten), bindet das Hero-Template navbar.html in Zeile 14 ein. Deshalb enthält default.html die Bedingung: „Wenn Hero, dann Navigationsleiste überspringen.“ Die Navigationsleiste wird INNERHALB der Hero-Überlagerung gerendert, was ihr einen transparenten Hintergrund verleiht, der mit dem Hero-Bild verschmilzt.

Hintergrundbildsystem — zwei Quellen

{% if page.header.image %}
  {% assign image = page.header.image %}     // Aus dem Front Matter der Seite
{% endif %}
// Fallback: verwendet page.hero.image, wenn header.image nicht gesetzt ist

<header style="background-image: url({{ image }});">  // Inline-CSS
  <div style="background: {{ page.header.overlay }};">  // Farbüberlagerung

Das Hero hat ZWEI mögliche Hintergrundbildquellen:

QuelleFront-Matter-SchlüsselVerwendet von
Header-Bildpage.header.imageBlogbeiträge, Changelog-Einträge — headerspezifischer Hintergrund
Hero-Bildpage.hero.imageDokumentationsseiten — die Hero-Bereichsillustration (z. B. search.png)

URLs werden über {% if image contains 'http' %} aufgelöst — externe Bilder verwenden absolute URLs, internen Bildern wird {{ site.uploads | absolute_url }} vorangestellt. Die Überlagerung wird als halbtransparente Farbe über dem Bild angewendet, um die Lesbarkeit des Textes zu gewährleisten.

Scrollspy-Animation — Eingangseffekt

data-uk-scrollspy="cls: uk-animation-slide-bottom-medium; repeat: true"

Der Hero-Inhalt (Titel, Untertitel) gleitet von unten nach oben, wenn der Benutzer zu ihm scrollt. repeat: true bedeutet, dass die Animation jedes Mal wiederholt wird, wenn das Element in den Viewport gelangt — nicht nur einmal. Dies ist eine subtile UX-Verbesserung: Auf langen Seiten wird die Animation beim Zurückkehren zum Hero erneut ausgelöst.

uk-animation-slide-bottom-medium ist eine UIkit-Animationsklasse — Elemente starten 50px unter ihrer endgültigen Position und gleiten mit einem mittellangen Übergang nach oben. Dies wird durch animation.scss (#4028) gestaltet.

Suchleiste — SimpleJekyllSearch (wie in der Navigationsleiste)

Die Hero-Suchleiste ist identisch mit der Navigationsleisten-Suche (#3905) — dieselbe Bibliothek (SimpleJekyllSearch), dieselbe Datenquelle (search.json), dieselbe benutzerdefinierte Funktion searchResults(). Der einzige Unterschied: Die Hero-Suche verwendet id="search-hero" anstelle von id="search-navbar" und wird nur gerendert, wenn page.hero.search wahr ist.

Auf der Startseite: search: false — keine Suchleiste im Hero. Das Wertversprechen ist stärker, ohne dass ein Suchfeld um Aufmerksamkeit konkurriert.

Auf der Suchseite (#4093): search: true — die Suchleiste IST der Zweck des Heros. Der Hero bietet den visuellen Kontext für das Sucherlebnis.
