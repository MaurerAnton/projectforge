Inclut sa propre barre de navigation. Contrairement aux pages sans hero (qui reçoivent la barre de navigation depuis default.html), le template hero inclut navbar.html à la ligne 14. C'est pourquoi default.html a la condition : « si hero, ignorer la barre de navigation. » La barre de navigation s'affiche À L'INTÉRIEUR de la superposition du hero, lui donnant un fond transparent qui se fond avec l'image du hero.

Système d'image de fond — deux sources

{% if page.header.image %}
  {% assign image = page.header.image %}     // Depuis le front matter de la page
{% endif %}
// Repli : utilise page.hero.image si header.image n'est pas défini

<header style="background-image: url({{ image }});">  // CSS en ligne
  <div style="background: {{ page.header.overlay }};">  // Superposition de couleur

Le hero a DEUX sources possibles d'image de fond :

SourceClé du front matterUtilisée par
Image d'en-têtepage.header.imageArticles de blog, entrées de journal — fond spécifique à l'en-tête
Image heropage.hero.imagePages de documentation — illustration de la section hero (ex. : search.png)

Les URL sont résolues via {% if image contains 'http' %} — les images externes utilisent des URL absolues, les images internes reçoivent {{ site.uploads | absolute_url }} en préfixe. La superposition est appliquée comme une couleur semi-transparente sur l'image pour la lisibilité du texte.

Animation Scrollspy — effet d'entrée

data-uk-scrollspy="cls: uk-animation-slide-bottom-medium; repeat: true"

Le contenu du hero (titre, sous-titre) glisse vers le haut depuis le bas lorsque l'utilisateur fait défiler jusqu'à lui. repeat: true signifie que l'animation se rejoue chaque fois que l'élément entre dans la zone d'affichage — pas seulement une fois. C'est une subtilité UX : sur les longues pages, revenir au hero déclenche à nouveau l'animation.

uk-animation-slide-bottom-medium est une classe d'animation UIkit — les éléments commencent 50 pixels en dessous de leur position finale et glissent vers le haut avec une transition de durée moyenne. Ceci est thématisé par animation.scss (#4028).

Barre de recherche — SimpleJekyllSearch (identique à la barre de navigation)

La barre de recherche du hero est identique à celle de la barre de navigation (#3905) — même bibliothèque (SimpleJekyllSearch), même source de données (search.json), même fonction personnalisée searchResults(). La seule différence : la recherche du hero utilise id="search-hero" au lieu de id="search-navbar", et elle n'est affichée que lorsque page.hero.search est vrai.

Sur la page d'accueil : search: false — pas de barre de recherche dans le hero. La proposition de valeur est plus forte sans champ de recherche en compétition pour l'attention.

Sur la page de recherche (#4093) : search: true — la barre de recherche EST l'objectif du hero. Le hero fournit le contexte visuel pour l'expérience de recherche.
