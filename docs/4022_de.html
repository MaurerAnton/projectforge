Datengetriebene Navigation. Die Navigationsleiste enthält keine hartcodierten Links. ALLE Navigationselemente stammen aus site.data.navigation_header – einer YAML-Datei (_data/navigation_header.yml). Die Vorlage iteriert über die Arrays .left und .right und rendert dynamisch Links, Dropdowns und Schaltflächen. Die Navigation zu ändern bedeutet eine YAML-Bearbeitung, keine HTML-Bearbeitung.

Architektur – 5 horizontale Zonen

<div data-uk-navbar>                    <!-- UIkit-Flex-Container -->
  <div class="uk-navbar-left">           <!-- ZONE 1: Logo + Desktop-Navigationslinks -->
    <a class="uk-logo uk-visible@m">    <!-- Logo (nur Desktop) -->
    <a class="uk-navbar-toggle uk-hidden@m"> <!-- Hamburger (nur mobil) -->
    <ul class="uk-navbar-nav uk-visible@m"> <!-- LINKE Navigationselemente aus YAML -->
  </div>
  <div class="uk-navbar-center uk-hidden@m"> <!-- ZONE 2: Logo (mobil zentriert) -->
  </div>
  <div class="uk-navbar-right">         <!-- ZONE 3: Suche + RECHTE Navigationselemente -->
    <!-- SimpleJekyllSearch-Umschalter -->
    <ul class="uk-navbar-nav uk-visible@m"> <!-- RECHTE Navigationselemente aus YAML -->
    <a class="uk-navbar-toggle uk-hidden@m"> <!-- Mobiler Seiten-Navigations-Umschalter -->
  </div>
</div>

Die Navigationsleiste hat 5 logische Zonen, die über UIkits Flex-Navbar-Komponente angeordnet sind. Die Zonen 1 und 3 sind die Hauptinhaltsbereiche (Desktop), Zone 2 ist ein nur für Mobilgeräte zentriertes Logo, und die Zonen 4-5 sind implizit (das Such-Dropdown und der mobile Offcanvas-Umschalter).

Das Muster uk-visible@m / uk-hidden@m zieht sich durch – Desktop-Elemente sind auf Mobilgeräten versteckt, mobile Elemente auf dem Desktop. Der Breakpoint @m beträgt 960px (aus $breakpoint-medium in variables.scss #4091).

Die Liquid-Template-Engine – datengetriebene Navigation

{% for link in site.data.navigation_header.left %}    <!-- YAML-Daten durchlaufen -->
  {% if link.url contains 'http' %}                    <!-- Erkennung externer Links -->
    {% assign domain = '' %}                           <!-- Kein relative_url für http-Links -->
  {% else %}
    {% assign domain = '' | relative_url %}             <!-- Basis-URL für interne Links voranstellen -->
  {% endif %}
  {% if link.url == page.url %}                        <!-- Erkennung aktiver Seite -->
    {% assign current = ' class="uk-active"' %}        <!-- Aktuelle Seite hervorheben -->
  {% endif %}
  {% if link.button %}                                 <!-- Als Schaltfläche gestaltetes Navigationselement -->
    <li><a class="uk-button uk-button-{{ link.button }}"> <!-- Dynamischer Schaltflächenstil -->
  {% elsif link.url %}
    <li{{ current }}><a href="{{ domain }}{{ link.url }}"> <!-- Standard-Navigationslink -->
  {% else %}
    <!-- Dropdown: Link ohne URL → Abschnittsüberschrift -->
    <div class="uk-navbar-dropdown">
      {% for child in link.dropdown %}                 <!-- Verschachtelte Schleife für Unterelemente -->
        {% if child.url %}
          <li><a href="...">{{ child.title }}</a></li>
        {% else %}
          <li class="uk-nav-header">{{ child.title }}</li> <!-- Abschnittsüberschrift -->
        {% endif %}
      {% endfor %}
    </div>
  {% endif %}
{% endfor %}

Die Rendering-Logik der Navigation hat drei Zweige pro Link-Element:

ZweigBedingungRendert
Schaltflächelink.button ist gesetztEin als Schaltfläche gestaltetes Navigationselement (.uk-button-{{ link.button }}). Der Schaltflächenstil (primary/secondary/danger) stammt aus YAML.
Standard-Linklink.url existiert, keine SchaltflächeEin regulärer <a>-Link. Erhält die Klasse .uk-active, wenn link.url == page.url.
DropdownWeder URL noch SchaltflächeEin Dropdown-Menü mit einer verschachtelten {% for %}-Schleife. Unterelemente mit URLs werden zu Links; Unterelemente ohne werden zu .uk-nav-header-Abschnittsüberschriften.

Erkennung externer Links: {% if link.url contains 'http' %} – wenn die URL http enthält, wird domain auf einen leeren String gesetzt (die URL ist absolut). Andernfalls stellt der Filter relative_url die Basis-URL der Website voran. Dies behandelt sowohl interne Dokumentlinks als auch externe Links (GitHub, SourceForge) problemlos.

Erkennung aktiver Seite: {% if link.url == page.url %} – exakter String-Vergleich zwischen der URL des Links und der URL der aktuellen Seite. Bei Übereinstimmung wird die Klasse .uk-active hinzugefügt, die UIkit mit dem Erscheinungsbild des aktiven Navigationselements gestaltet. Dies ist einfach, aber fragil – es funktioniert nicht, wenn eine URL einen abschließenden Schrägstrich hat und die andere nicht.

Suche – SimpleJekyllSearch, NICHT Tipue

<script>
SimpleJekyllSearch({
  searchInput: document.getElementById('search-navbar'),
  resultsContainer: document.getElementById('search-navbar-results'),
  noResultsText: '...',
  searchResultTemplate: '<li><a href="{url}">{title}</a></li>',
  json: "{{ '/search.json' | relative_url }}"
});
searchResults("search-navbar");
</script>

Auf der Website existieren zwei verschiedene Suchimplementierungen nebeneinander:

SucheBibliothekWoDatenquelle
Navigationsleisten-SucheSimpleJekyllSearchNavigationsleisten-Umschalter (Desktop)search.json (#4094)
SeitensucheTipue Search/search/ (#4093)search.json (#4094)

Beide verwenden DIESELBE Datenquelle (search.json), aber unterschiedliche JavaScript-Bibliotheken. SimpleJekyllSearch ist einfacher – es nimmt eine JSON-Datei, ein Eingabeelement und einen Ergebniscontainer entgegen und führt eine clientseitige Filterung durch. Es wird in der Navigationsleiste verwendet, weil es leichter ist als Tipue und gut für eine kompakte Dropdown-Ergebnisliste funktioniert.

Der Aufruf searchResults("search-navbar") in Zeile 86 ist eine benutzerdefinierte Funktion (nicht von SimpleJekyllSearch) – wahrscheinlich anderswo definiert, um das Umschaltverhalten zu handhaben (Ein-/Ausblenden von Ergebnissen bei Eingabefokus).

Mobil – duales Offcanvas-System

Die Navigationsleiste hat ZWEI separate mobile Menüs:

UmschalterZielSichtbarer Text
Linker Hamburger#offcanvas-docs"Dokumentation" (aus site.data.translation[site.lang].mobile_nav_docs)
Rechter Hamburger#offcanvas"Seite" (aus site.data.translation[site.lang].mobile_nav_site)

Dieses Dual-Menü-Muster trennt die Dokumentationsnavigation von der Seitennavigation auf Mobilgeräten – eine durchdachte UX-Entscheidung. Die Übersetzungsschlüssel (mobile_nav_docs, mobile_nav_site) ermöglichen mehrsprachige Unterstützung. Wenn Übersetzungen fehlen (Zeilen 9-10, 143-144), erscheint der Hamburger ohne Text – nur das Symbol.

Die Offcanvas-Panels selbst sind in separaten Include-Dateien definiert (offcanvas.html, offcanvas-docs.html), nicht in dieser Vorlage.

Sticky-Verhalten – der Animationsvertrag

data-uk-sticky="animation: uk-animation-slide-top;
  sel-target: .uk-navbar-container;
  cls-active: uk-navbar-sticky;
  cls-inactive: uk-navbar-transparent;
  top: 200"

UIkits Sticky-Komponente wird über ein Datenattribut mit semikolongetrennten Parametern konfiguriert:

  • animation: uk-animation-slide-top – wenn die Navigationsleiste klebrig wird (Benutzer scrollt über 200px), gleitet sie mit einer sanften Animation von oben herein.
  • sel-target: .uk-navbar-container – das Sticky-Verhalten gilt für den inneren .uk-navbar-container, nicht für den äußeren Wrapper <div>. Dadurch bleibt der Wrapper im Fluss, während der Container fixiert wird.
  • cls-active: uk-navbar-sticky – wenn fixiert, wird diese Klasse hinzugefügt (thematisiert von sticky.scss #4076, um einen Schatten hinzuzufügen).
  • cls-inactive: uk-navbar-transparent – wenn nicht fixiert (oben), ist die Navigationsleiste transparent. Dies erzeugt einen "Beim Scrollen enthüllen"-Effekt.
  • top: 200 – die Navigationsleiste wird klebrig, nachdem der Benutzer 200px gescrollt hat. Diese Verzögerung verhindert, dass der Sticky-Übergang auf kurzen Seiten zu aggressiv ist.
