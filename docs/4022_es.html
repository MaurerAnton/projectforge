La barra de navegación tiene 5 zonas lógicas dispuestas a través del componente de barra de navegación flexible de UIkit. Las zonas 1 y 3 son las áreas de contenido principales (escritorio), la zona 2 es un logotipo centrado solo para móvil, y las zonas 4-5 son implícitas (el menú desplegable de búsqueda y la alternancia fuera del lienzo móvil).

El patrón uk-visible@m / uk-hidden@m aparece en todas partes — los elementos de escritorio están ocultos en móvil, los elementos móviles están ocultos en escritorio. El punto de interrupción @m es 960px (de $breakpoint-medium en variables.scss #4091).

El motor de plantillas Liquid — navegación basada en datos

{% for link in site.data.navigation_header.left %}    <!-- Iterar datos YAML -->
  {% if link.url contains 'http' %}                    <!-- Detección de enlace externo -->
    {% assign domain = '' %}                           <!-- Sin relative_url para enlaces http -->
  {% else %}
    {% assign domain = '' | relative_url %}             <!-- Anteponer URL base para internos -->
  {% endif %}
  {% if link.url == page.url %}                        <!-- Detección de página activa -->
    {% assign current = ' class="uk-active"' %}        <!-- Resaltar página actual -->
  {% endif %}
  {% if link.button %}                                 <!-- Elemento de navegación con estilo de botón -->
    <li><a class="uk-button uk-button-{{ link.button }}"> <!-- Estilo de botón dinámico -->
  {% elsif link.url %}
    <li{{ current }}><a href="{{ domain }}{{ link.url }}"> <!-- Enlace de navegación estándar -->
  {% else %}
    <!-- Menú desplegable: enlace sin URL → encabezado de sección -->
    <div class="uk-navbar-dropdown">
      {% for child in link.dropdown %}                 <!-- Bucle anidado para hijos -->
        {% if child.url %}
          <li><a href="...">{{ child.title }}</a></li>
        {% else %}
          <li class="uk-nav-header">{{ child.title }}</li> <!-- Encabezado de sección -->
        {% endif %}
      {% endfor %}
    </div>
  {% endif %}
{% endfor %}

La lógica de renderizado de navegación tiene tres ramas por elemento de enlace:

RamaCondiciónRenderiza
Botónlink.button está establecidoUn elemento de navegación con estilo de botón (.uk-button-{{ link.button }}). El estilo del botón (primario/secundario/peligro) proviene de YAML.
Enlace estándarlink.url existe, sin botónUn enlace <a> regular. Obtiene la clase .uk-active si link.url == page.url.
Menú desplegableNi url ni botónUn menú desplegable con bucle {% for %} anidado. Los hijos con URL se convierten en enlaces; los hijos sin URL se convierten en encabezados de sección .uk-nav-header.

Detección de enlace externo: {% if link.url contains 'http' %} — si la URL contiene http, domain se establece en cadena vacía (la URL es absoluta). De lo contrario, el filtro relative_url antepone la URL base del sitio. Esto maneja elegantemente tanto enlaces internos de documentos como enlaces externos (GitHub, SourceForge).

Detección de página activa: {% if link.url == page.url %} — comparación exacta de cadenas entre la URL del enlace y la URL de la página actual. Si coinciden, se agrega la clase .uk-active, que UIkit estiliza con la apariencia del elemento de navegación activo. Esto es simple pero frágil — no coincidirá si una URL tiene una barra inclinada final y la otra no.

Búsqueda — SimpleJekyllSearch, NO Tipue

<script>
SimpleJekyllSearch({
  searchInput: document.getElementById('search-navbar'),
  resultsContainer: document.getElementById('search-navbar-results'),
  noResultsText: '...',
  searchResultTemplate: '<li><a href="{url}">{title}</a></li>',
  json: "{{ '/search.json' | relative_url }}"
});
searchResults("search-navbar");
</script>

Dos implementaciones de búsqueda diferentes coexisten en el sitio:

BúsquedaBibliotecaDóndeFuente de datos
Búsqueda en barra de navegaciónSimpleJekyllSearchAlternancia de barra de navegación (escritorio)search.json (#4094)
Búsqueda de páginaTipue Search/search/ (#4093)search.json (#4094)

Ambas usan la MISMA fuente de datos (search.json) pero diferentes bibliotecas JavaScript. SimpleJekyllSearch es más simple — toma un archivo JSON, un elemento de entrada y un contenedor de resultados, y realiza filtrado del lado del cliente. Se usa en la barra de navegación porque es más ligero que Tipue y funciona bien para una lista compacta de resultados desplegables.

La llamada searchResults("search-navbar") en la línea 86 es una función personalizada (no de SimpleJekyllSearch) — probablemente definida en otro lugar para manejar el comportamiento de alternancia (mostrar/ocultar resultados al enfocar la entrada).

Móvil — sistema dual fuera del lienzo

La barra de navegación tiene DOS menús móviles separados:

AlternanciaDestinoTexto visible
Hamburguesa izquierda#offcanvas-docs"Documentación" (de site.data.translation[site.lang].mobile_nav_docs)
Hamburguesa derecha#offcanvas"Sitio" (de site.data.translation[site.lang].mobile_nav_site)

Este patrón de menú dual separa la navegación de documentación de la navegación del sitio en móvil — una decisión de UX reflexiva. Las claves de traducción (mobile_nav_docs, mobile_nav_site) permiten soporte multilingüe. Si las traducciones están ausentes (líneas 9-10, 143-144), la hamburguesa aparece sin texto — solo el icono.

Los paneles fuera del lienzo en sí mismos se definen en archivos de inclusión separados (offcanvas.html, offcanvas-docs.html), no en esta plantilla.

Comportamiento fijo — el contrato de animación

data-uk-sticky="animation: uk-animation-slide-top;
  sel-target: .uk-navbar-container;
  cls-active: uk-navbar-sticky;
  cls-inactive: uk-navbar-transparent;
  top: 200"

El componente Sticky de UIkit se configura a través de un atributo de datos con parámetros separados por punto y coma:

  • animation: uk-animation-slide-top — cuando la barra de navegación se vuelve fija (el usuario se desplaza más allá de 200px), se desliza hacia abajo desde la parte superior con una animación suave.
  • sel-target: .uk-navbar-container — el comportamiento fijo se aplica al .uk-navbar-container interno, no al <div> envolvente externo. Esto mantiene el envolvente en el flujo mientras el contenedor se vuelve fijo.
  • cls-active: uk-navbar-sticky — cuando está fijo, se agrega esta clase (temada por sticky.scss #4076 para agregar una sombra).
  • cls-inactive: uk-navbar-transparent — cuando no está fijo (en la parte superior), la barra de navegación es transparente. Esto crea un efecto de "revelar al desplazar".
  • top: 200 — la barra de navegación se vuelve fija después de que el usuario se desplaza 200px. Este retraso evita que la transición fija sea demasiado agresiva en páginas cortas.
