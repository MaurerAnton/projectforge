Navigation pilotée par les données. La barre de navigation ne code en dur aucun lien. TOUS les éléments de navigation proviennent de site.data.navigation_header — un fichier YAML (_data/navigation_header.yml). Le modèle itère sur les tableaux .left et .right, générant dynamiquement des liens, des menus déroulants et des boutons. Modifier la navigation est une édition YAML, pas une édition HTML.

Architecture — 5 zones horizontales

<div data-uk-navbar>                    <!-- Conteneur flexible UIkit -->
  <div class="uk-navbar-left">           <!-- ZONE 1 : Logo + liens de navigation bureau -->
    <a class="uk-logo uk-visible@m">    <!-- Logo (bureau uniquement) -->
    <a class="uk-navbar-toggle uk-hidden@m"> <!-- Hamburger (mobile uniquement) -->
    <ul class="uk-navbar-nav uk-visible@m"> <!-- Éléments de navigation GAUCHE depuis YAML -->
  </div>
  <div class="uk-navbar-center uk-hidden@m"> <!-- ZONE 2 : Logo (centre mobile) -->
  </div>
  <div class="uk-navbar-right">         <!-- ZONE 3 : Recherche + éléments de navigation DROITE -->
    <!-- Bascule SimpleJekyllSearch -->
    <ul class="uk-navbar-nav uk-visible@m"> <!-- Éléments de navigation DROITE depuis YAML -->
    <a class="uk-navbar-toggle uk-hidden@m"> <!-- Bascule de navigation du site mobile -->
  </div>
</div>

La barre de navigation comporte 5 zones logiques disposées via le composant de barre flexible d'UIkit. Les zones 1 et 3 sont les zones de contenu principales (bureau), la zone 2 est un logo centré mobile uniquement, et les zones 4-5 sont implicites (le menu déroulant de recherche et la bascule hors-champ mobile).

Le motif uk-visible@m / uk-hidden@m apparaît partout — les éléments bureau sont cachés sur mobile, les éléments mobiles sont cachés sur bureau. Le point de rupture @m est 960px (depuis $breakpoint-medium dans variables.scss #4091).

Le moteur de template Liquid — navigation pilotée par les données

{% for link in site.data.navigation_header.left %}    <!-- Itérer sur les données YAML -->
  {% if link.url contains 'http' %}                    <!-- Détection de lien externe -->
    {% assign domain = '' %}                           <!-- Pas de relative_url pour les liens http -->
  {% else %}
    {% assign domain = '' | relative_url %}             <!-- Préfixer l'URL de base pour les internes -->
  {% endif %}
  {% if link.url == page.url %}                        <!-- Détection de page active -->
    {% assign current = ' class="uk-active"' %}        <!-- Mettre en surbrillance la page courante -->
  {% endif %}
  {% if link.button %}                                 <!-- Élément de navigation stylisé en bouton -->
    <li><a class="uk-button uk-button-{{ link.button }}"> <!-- Style de bouton dynamique -->
  {% elsif link.url %}
    <li{{ current }}><a href="{{ domain }}{{ link.url }}"> <!-- Lien de navigation standard -->
  {% else %}
    <!-- Menu déroulant : lien sans URL → en-tête de section -->
    <div class="uk-navbar-dropdown">
      {% for child in link.dropdown %}                 <!-- Boucle imbriquée pour les enfants -->
        {% if child.url %}
          <li><a href="...">{{ child.title }}</a></li>
        {% else %}
          <li class="uk-nav-header">{{ child.title }}</li> <!-- En-tête de section -->
        {% endif %}
      {% endfor %}
    </div>
  {% endif %}
{% endfor %}

La logique de rendu de la navigation comporte trois branches par élément de lien :

BrancheConditionGénère
Boutonlink.button est définiUn élément de navigation stylisé en bouton (.uk-button-{{ link.button }}). Le style du bouton (primaire/secondaire/danger) provient du YAML.
Lien standardlink.url existe, pas de boutonUn lien <a> régulier. Reçoit la classe .uk-active si link.url == page.url.
Menu déroulantNi url ni boutonUn menu déroulant avec une boucle {% for %} imbriquée. Les enfants avec URL deviennent des liens ; les enfants sans deviennent des en-têtes de section .uk-nav-header.

Détection de lien externe : {% if link.url contains 'http' %} — si l'URL contient http, domain est défini sur une chaîne vide (l'URL est absolue). Sinon, le filtre relative_url préfixe l'URL de base du site. Cela gère élégamment à la fois les liens internes de documentation et les liens externes (GitHub, SourceForge).

Détection de page active : {% if link.url == page.url %} — comparaison exacte de chaîne entre l'URL du lien et l'URL de la page courante. Si elles correspondent, la classe .uk-active est ajoutée, qu'UIkit stylise avec l'apparence d'élément de navigation actif. C'est simple mais fragile — cela ne fonctionnera pas si une URL a une barre oblique finale et l'autre non.

Recherche — SimpleJekyllSearch, PAS Tipue

<script>
SimpleJekyllSearch({
  searchInput: document.getElementById('search-navbar'),
  resultsContainer: document.getElementById('search-navbar-results'),
  noResultsText: '...',
  searchResultTemplate: '<li><a href="{url}">{title}</a></li>',
  json: "{{ '/search.json' | relative_url }}"
});
searchResults("search-navbar");
</script>

Deux implémentations de recherche différentes coexistent sur le site :

RechercheBibliothèqueOùSource de données
Recherche barre de navigationSimpleJekyllSearchBascule barre de navigation (bureau)search.json (#4094)
Recherche pageTipue Search/search/ (#4093)search.json (#4094)

Les deux utilisent la MÊME source de données (search.json) mais des bibliothèques JavaScript différentes. SimpleJekyllSearch est plus simple — il prend un fichier JSON, un élément d'entrée et un conteneur de résultats, et effectue un filtrage côté client. Il est utilisé dans la barre de navigation car il est plus léger que Tipue et fonctionne bien pour une liste compacte de résultats déroulants.

L'appel searchResults("search-navbar") à la ligne 86 est une fonction personnalisée (pas de SimpleJekyllSearch) — probablement définie ailleurs pour gérer le comportement de bascule (afficher/masquer les résultats lors du focus de l'entrée).

Mobile — système double hors-champ

La barre de navigation a DEUX menus mobiles séparés :

BasculeCibleTexte visible
Hamburger gauche#offcanvas-docs"Documentation" (depuis site.data.translation[site.lang].mobile_nav_docs)
Hamburger droit#offcanvas"Site" (depuis site.data.translation[site.lang].mobile_nav_site)

Ce motif à double menu sépare la navigation de la documentation de la navigation du site sur mobile — une décision UX réfléchie. Les clés de traduction (mobile_nav_docs, mobile_nav_site) permettent la prise en charge multilingue. Si les traductions sont absentes (lignes 9-10, 143-144), le hamburger apparaît sans texte — juste l'icône.

Les panneaux hors-champ eux-mêmes sont définis dans des fichiers d'inclusion séparés (offcanvas.html, offcanvas-docs.html), pas dans ce modèle.

Comportement collant — le contrat d'animation

data-uk-sticky="animation: uk-animation-slide-top;
  sel-target: .uk-navbar-container;
  cls-active: uk-navbar-sticky;
  cls-inactive: uk-navbar-transparent;
  top: 200"

Le composant Sticky d'UIkit est configuré via un attribut de données avec des paramètres séparés par des points-virgules :

  • animation: uk-animation-slide-top — lorsque la barre de navigation devient collante (l'utilisateur dépasse 200px), elle glisse vers le bas depuis le haut avec une animation fluide.
  • sel-target: .uk-navbar-container — le comportement collant s'applique au conteneur interne .uk-navbar-container, pas à la div externe <div>. Cela maintient l'élément englobant dans le flux tandis que le conteneur devient fixe.
  • cls-active: uk-navbar-sticky — lorsqu'il est collé, cette classe est ajoutée (thématisée par sticky.scss #4076 pour ajouter une ombre).
  • cls-inactive: uk-navbar-transparent — lorsqu'il n'est pas collé (en haut), la barre de navigation est transparente. Cela crée un effet de "révélation au défilement".
  • top: 200 — la barre de navigation devient collante après que l'utilisateur a défilé de 200px. Ce délai empêche la transition collante d'être trop agressive sur les pages courtes.
