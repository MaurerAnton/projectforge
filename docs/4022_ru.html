#4022: navbar.html

site/_includes/navbar.html

Путь: site/_includes/navbar.html · Строк: 151 · Тип: Шаблон включения Jekyll Liquid

Назначение: ОСНОВНАЯ панель навигации — самый сложный шаблон Liquid на сайте. Отображает: липкий заголовок, двойную левую/правую навигацию из YAML-данных, вложенные выпадающие списки, мобильный переключатель offcanvas, интеграцию SimpleJekyllSearch, обработку логотипа, определение активной ссылки. Каждая страница на projectforge.org включает этот шаблон через макет по умолчанию.

Навигация на основе данных. Панель навигации не содержит жестко заданных ссылок. ВСЕ пункты навигации берутся из site.data.navigation_header — YAML-файла (_data/navigation_header.yml). Шаблон перебирает массивы .left и .right, динамически отображая ссылки, выпадающие списки и кнопки. Изменение навигации — это правка YAML, а не HTML.

Архитектура — 5 горизонтальных зон

<div data-uk-navbar>                    <!-- UIkit flex-контейнер -->
  <div class="uk-navbar-left">           <!-- ЗОНА 1: Логотип + ссылки десктопной навигации -->
    <a class="uk-logo uk-visible@m">    <!-- Логотип (только десктоп) -->
    <a class="uk-navbar-toggle uk-hidden@m"> <!-- Гамбургер (только мобильные) -->
    <ul class="uk-navbar-nav uk-visible@m"> <!-- Левые пункты навигации из YAML -->
  </div>
  <div class="uk-navbar-center uk-hidden@m"> <!-- ЗОНА 2: Логотип (центр на мобильных) -->
  </div>
  <div class="uk-navbar-right">         <!-- ЗОНА 3: Поиск + Правые пункты навигации -->
    <!-- Переключатель SimpleJekyllSearch -->
    <ul class="uk-navbar-nav uk-visible@m"> <!-- Правые пункты навигации из YAML -->
    <a class="uk-navbar-toggle uk-hidden@m"> <!-- Переключатель мобильной навигации сайта -->
  </div>
</div>

Панель навигации имеет 5 логических зон, организованных с помощью flex-компонента панели навигации UIkit. Зоны 1 и 3 — основные области содержимого (десктоп), зона 2 — логотип по центру только для мобильных, а зоны 4-5 являются неявными (выпадающий поиск и переключатель мобильного offcanvas).

Шаблон uk-visible@m / uk-hidden@m используется повсеместно — элементы для десктопа скрыты на мобильных, элементы для мобильных скрыты на десктопе. Точка останова @m равна 960px (из $breakpoint-medium в variables.scss #4091).

Шаблонизатор Liquid — навигация на основе данных

{% for link in site.data.navigation_header.left %}    <!-- Перебор YAML-данных -->
  {% if link.url contains 'http' %}                    <!-- Определение внешней ссылки -->
    {% assign domain = '' %}                           <!-- Без relative_url для http-ссылок -->
  {% else %}
    {% assign domain = '' | relative_url %}             <!-- Добавление базового URL для внутренних -->
  {% endif %}
  {% if link.url == page.url %}                        <!-- Определение активной страницы -->
    {% assign current = ' class="uk-active"' %}        <!-- Подсветка текущей страницы -->
  {% endif %}
  {% if link.button %}                                 <!-- Пункт навигации в стиле кнопки -->
    <li><a class="uk-button uk-button-{{ link.button }}"> <!-- Динамический стиль кнопки -->
  {% elsif link.url %}
    <li{{ current }}><a href="{{ domain }}{{ link.url }}"> <!-- Стандартная ссылка навигации -->
  {% else %}
    <!-- Выпадающий список: ссылка без URL → заголовок раздела -->
    <div class="uk-navbar-dropdown">
      {% for child in link.dropdown %}                 <!-- Вложенный цикл для дочерних элементов -->
        {% if child.url %}
          <li><a href="...">{{ child.title }}</a></li>
        {% else %}
          <li class="uk-nav-header">{{ child.title }}</li> <!-- Заголовок раздела -->
        {% endif %}
      {% endfor %}
    </div>
  {% endif %}
{% endfor %}

Логика отображения навигации имеет три ветви для каждого элемента ссылки:

ВетвьУсловиеОтображает
КнопкаУстановлено link.buttonПункт навигации в стиле кнопки (.uk-button-{{ link.button }}). Стиль кнопки (primary/secondary/danger) берется из YAML.
Стандартная ссылкаСуществует link.url, нет кнопкиОбычная ссылка <a>. Получает класс .uk-active, если link.url == page.url.
Выпадающий списокНет ни url, ни кнопкиВыпадающее меню с вложенным циклом {% for %}. Дочерние элементы с URL становятся ссылками; дочерние элементы без URL становятся заголовками разделов .uk-nav-header.

Определение внешних ссылок: {% if link.url contains 'http' %} — если URL содержит http, domain устанавливается в пустую строку (URL абсолютный). В противном случае фильтр relative_url добавляет базовый URL сайта. Это корректно обрабатывает как внутренние ссылки на документы, так и внешние ссылки (GitHub, SourceForge).

Определение активной страницы: {% if link.url == page.url %} — точное сравнение строк между URL ссылки и URL текущей страницы. Если они совпадают, добавляется класс .uk-active, который UIkit стилизует как активный элемент навигации. Это просто, но хрупко — не сработает, если один URL имеет завершающий слеш, а другой нет.

Поиск — SimpleJekyllSearch, НЕ Tipue

<script>
SimpleJekyllSearch({
  searchInput: document.getElementById('search-navbar'),
  resultsContainer: document.getElementById('search-navbar-results'),
  noResultsText: '...',
  searchResultTemplate: '<li><a href="{url}">{title}</a></li>',
  json: "{{ '/search.json' | relative_url }}"
});
searchResults("search-navbar");
</script>

На сайте сосуществуют две разные реализации поиска:

ПоискБиблиотекаГдеИсточник данных
Поиск в панели навигацииSimpleJekyllSearchПереключатель панели навигации (десктоп)search.json (#4094)
Поиск на страницеTipue Search/search/ (#4093)search.json (#4094)

Оба используют ОДИН И ТОТ ЖЕ источник данных (search.json), но разные JavaScript-библиотеки. SimpleJekyllSearch проще — он принимает JSON-файл, элемент ввода и контейнер результатов и выполняет фильтрацию на стороне клиента. Он используется в панели навигации, потому что легче Tipue и хорошо работает для компактного выпадающего списка результатов.

Вызов searchResults("search-navbar") в строке 86 — это пользовательская функция (не из SimpleJekyllSearch), вероятно, определенная в другом месте для обработки поведения переключателя (показать/скрыть результаты при фокусе ввода).

Мобильные устройства — двойная система offcanvas

Панель навигации имеет ДВА отдельных мобильных меню:

ПереключательЦельВидимый текст
Левый гамбургер#offcanvas-docs"Документация" (из site.data.translation[site.lang].mobile_nav_docs)
Правый гамбургер#offcanvas"Сайт" (из site.data.translation[site.lang].mobile_nav_site)

Этот шаблон с двумя меню разделяет навигацию по документации и навигацию по сайту на мобильных устройствах — продуманное UX-решение. Ключи перевода (mobile_nav_docs, mobile_nav_site) обеспечивают поддержку нескольких языков. Если переводы отсутствуют (строки 9-10, 143-144), гамбургер отображается без текста — только иконка.

Сами панели offcanvas определены в отдельных файлах включения (offcanvas.html, offcanvas-docs.html), а не в этом шаблоне.

Липкое поведение — контракт анимации

data-uk-sticky="animation: uk-animation-slide-top;
  sel-target: .uk-navbar-container;
  cls-active: uk-navbar-sticky;
  cls-inactive: uk-navbar-transparent;
  top: 200"

Компонент Sticky от UIkit настраивается через строку атрибута данных с параметрами, разделенными точкой с запятой:

  • animation: uk-animation-slide-top — когда панель навигации становится липкой (пользователь прокручивает более 200px), она плавно выезжает сверху.
  • sel-target: .uk-navbar-container — липкое поведение применяется к внутреннему .uk-navbar-container, а не к внешнему обертке <div>. Это сохраняет обертку в потоке, пока контейнер становится фиксированным.
  • cls-active: uk-navbar-sticky — когда зафиксировано, добавляется этот класс (стилизуется sticky.scss #4076 для добавления тени).
  • cls-inactive: uk-navbar-transparent — когда не зафиксировано (вверху), панель навигации прозрачна. Это создает эффект "появления при прокрутке".
  • top: 200 — панель навигации становится липкой после того, как пользователь прокрутит 200px. Эта задержка предотвращает слишком агрессивный переход липкости на коротких страницах.
