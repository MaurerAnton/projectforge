Wurzel des Layout-Vererbungsbaums. Alle anderen Layouts (page.html, doc.html, post.html, changelog.html) deklarieren layout: default in ihrem Front Matter, was bedeutet, dass ihre Ausgabe in {{ content }} in Zeile 14 dieser Datei eingefügt wird. Dies ist das untere Ende der Vererbungskette – es gibt das eigentliche HTML-Dokument aus.

Der vollständige Seitenlebenszyklus – 12 Includes in Reihenfolge

1. {% include head.html %}               // <meta>, <title>, CSS, JS (im <head>)
2. {% include hero.html %} ODER navbar    // Bedingt: Hero-Bereich oder einfache Navbar
3. {{ content }}                          // Seitenspezifischer Inhalt (vom untergeordneten Layout)
4. {% include offcanvas-docs.html %}      // Mobiles Dokumentationsmenü-Panel
5. {% include offcanvas.html %}           // Mobiles Seitenmenü-Panel
6. {% include footer.html %}              // Bedingt: nur wenn NICHT Doc-Layout
7. {% include hook-pre-closing-body-doc.html %}  // Bedingt: nur für Doc-Layout
8. {% include hook-pre-closing-body.html %}      // Immer: globale Skripte vor </body>

Die Reihenfolge ist wichtig – Offcanvas-Panels müssen nach dem Inhalt kommen (sie sind position:fixed-Overlays), der Footer wird für Dokumentationsseiten bedingt unterdrückt, und Hook-Includes werden direkt vor </body> eingefügt, um die Leistung zu optimieren (Skripte am Ende des Body).

Das Hook-System – Erweiterbarkeit ohne Layout-Bearbeitung

Die drei hook-*.html-Includes sind Jekylls Version von WordPress-Hooks – Injektionspunkte, an denen Plugins oder Seitentypen Skripte/Styles hinzufügen können, ohne die Layout-Vorlage zu ändern:

HookInjektionspunktVerwendet von
hook-head.htmlInnerhalb von <head> (via head.html)Seitenspezifisches CSS, Meta-Tags
hook-post-content-doc.htmlNach Inhalt, nur DokumentationsseitenDokumentspezifische Skripte nach dem Inhalt
hook-pre-closing-body.htmlVor </body>, immerGlobales JS: Analysen, Suchinitialisierung, UIkit-Initialisierung
hook-pre-closing-body-doc.htmlVor </body>, nur DokumentationsseitenDokumentspezifisches JS: TOC-Scroll-Spy, Vorher-/Zurück-Tastaturnavigation

Dies ist dasselbe Architekturmuster wie UIkits Hook/Mixin-System in SCSS (#4061) – leere Erweiterungspunkte, die untergeordnete Layouts implementieren können, ohne das übergeordnete Element zu ändern.
