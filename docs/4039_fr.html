Racine de l'arbre d'héritage des layouts. Tous les autres layouts (page.html, doc.html, post.html, changelog.html) déclarent layout: default dans leur front matter, ce qui signifie que leur sortie est injectée dans {{ content }} à la ligne 14 de ce fichier. C'est le bas de la chaîne d'héritage — il produit le document HTML réel.

Le cycle de vie complet de la page — 12 inclusions dans l'ordre

1. {% include head.html %}               // <meta>, <title>, CSS, JS (dans <head>)
2. {% include hero.html %} OU navbar      // Conditionnel : section hero ou barre de navigation simple
3. {{ content }}                          // Contenu spécifique à la page (depuis le layout enfant)
4. {% include offcanvas-docs.html %}      // Panneau de menu de documentation mobile
5. {% include offcanvas.html %}           // Panneau de menu du site mobile
6. {% include footer.html %}              // Conditionnel : uniquement si PAS le layout doc
7. {% include hook-pre-closing-body-doc.html %}  // Conditionnel : uniquement pour le layout doc
8. {% include hook-pre-closing-body.html %}      // Toujours : scripts globaux avant </body>

L'ordre est important — les panneaux offcanvas doivent être après le contenu (ce sont des superpositions position:fixed), le pied de page est conditionnellement supprimé pour les pages de documentation, et les inclusions de hooks sont injectées juste avant </body> pour la performance (scripts à la fin du body).

Le système de hooks — extensibilité sans modifier les layouts

Les trois inclusions hook-*.html sont la version Jekyll des hooks WordPress — des points d'injection où les plugins ou types de pages peuvent ajouter des scripts/styles sans modifier le template du layout :

HookPoint d'injectionUtilisé par
hook-head.htmlÀ l'intérieur de <head> (via head.html)CSS spécifique à la page, balises meta
hook-post-content-doc.htmlAprès le contenu, pages doc uniquementScripts post-contenu spécifiques à la doc
hook-pre-closing-body.htmlAvant </body>, toujoursJS global : analytics, initialisation de la recherche, initialisation UIkit
hook-pre-closing-body-doc.htmlAvant </body>, pages doc uniquementJS spécifique à la doc : espion de défilement TOC, navigation clavier précédent/suivant

C'est le même modèle architectural que le système de hook/mixin d'UIkit en SCSS (#4061) — des points d'extension vides que les layouts enfants peuvent implémenter sans modifier le parent.
