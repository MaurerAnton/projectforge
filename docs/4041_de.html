#4041: page.html

site/_layouts/page.html

Pfad: site/_layouts/page.html · Zeilen: 23 · Typ: Jekyll-Layout (Liquid-Template)

Zweck: Das Standard-Seitenlayout – wird von ca. 60 % aller Seiten der Website verwendet. Umschließt den Inhalt mit einem UIkit-Abschnitt + Container, rendert einen Artikel mit h1-Titel und unterstützt Breitenvarianten (small, large, expand). Erbt vom default-Layout, das die vollständige HTML-Hülle (head, navbar, footer) bereitstellt.

Layout-Vererbungskette: page.html → default.html → gibt vollständiges HTML aus. Der Frontmatter-Eintrag layout: default (Zeile 2) bedeutet, dass dieses Layout seine Ausgabe INNERHALB des Standard-Layouts umschließt. Das Standard-Layout stellt <html>, <head>, Navbar-Einbindung, Footer-Einbindung und Script-Einbindungen bereit.

Das Breitensystem – drei Rendering-Modi

{% if page.width == 'expand' %}       <!-- Volle Breite, kein Container -->
  {{ content }}                        <!-- Rohinhalt, kein Wrapper -->
{% else %}
  <div class="uk-section">             <!-- Standard-UIkit-Abschnittswrapper -->
    <div class="uk-container{% if page.width %} uk-container-{{page.width}}{% endif %}">
      <article class="uk-article">
        <h1 class="uk-article-title">{{ page.title | escape }}</h1>
        <div class="article-content link-primary">
          {{ content }}
        </div>
      </article>
    </div>
  </div>
{% endif %}

Seiten legen ihre Breite über den Frontmatter fest:

FrontmatterContainer-KlasseTypische max. BreiteVerwendet für
(keine).uk-container1200pxStandard-Dokumentationsseiten
width: small.uk-container-small900pxSuchseite (#4093), rechtliche Seiten, schmaler Inhalt
width: large.uk-container-large1600pxBreite Tabellen, Vergleichsseiten
width: expandKein Container100% ViewportVollflächige Layouts, Landingpages

Der expand-Modus ist speziell – er umgeht den gesamten Abschnitts-/Artikel-Wrapper und gibt direkt {{ content }} aus. Dies wird für Seiten verwendet, die volle Kontrolle über die Viewport-Breite benötigen (benutzerdefinierte Hero-Bereiche, Landingpages).

Semantische HTML-Entscheidungen

<article> (Zeile 11): Die Verwendung des HTML5-<article>-Elements zeigt an, dass jede Seite als in sich geschlossene Einheit betrachtet wird – gut für SEO und Barrierefreiheit. Die Klasse .uk-article wird durch article.scss (#4029) für die Typografie gestaltet.

link-primary (Zeile 15): Diese benutzerdefinierte Klasse auf dem Inhaltswrapper bewirkt, dass alle darin enthaltenen Links die Primärfarbe verwenden. Im ProjectForge-Brand-SCSS (projectforge.scss #3945) wird diese auf #BF4040 (ProjectForge-Rot) überschrieben. Ohne diese Klasse würden Links innerhalb von Artikelinhalten das standardmäßige UIkit-Blau verwenden.

{{ page.title | escape }} (Zeile 13): Der Liquid-Filter | escape verhindert XSS – falls ein Seitentitel HTML/JS enthält, wird dieser maskiert statt gerendert. Defense-in-depth für Inhalte aus Markdown/AsciiDoc-Frontmatter.

Wichtige Erkenntnisse

  • 60 % der Seiten verwenden dies: Jede Dokumentationsseite, rechtliche Seite, Suchseite und Inhaltsseite erbt von page.html. Änderungen hier betreffen die Mehrheit der Website.
  • Expand-Modus ist roh: Kein Abschnitt, kein Container, kein Artikel-Wrapper – nur {{ content }}. Mit Vorsicht zu verwenden; die Seite muss ihr eigenes Layout bereitstellen.
  • link-primary ist der Markenauslöser: Die Klasse, die die rote Linkfarbe von ProjectForge (#BF4040) aktiviert. Ohne sie bleiben Links im standardmäßigen UIkit-Blau.
  • Erbt von default: Dieses Layout hat 23 Zeilen, da der Großteil der HTML-Struktur (head, navbar, footer) in default.html lebt. Das Layoutsystem ist eine Kompositionskette.
