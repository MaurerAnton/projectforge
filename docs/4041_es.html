Propósito: El diseño de página estándar — utilizado por ~60% de todas las páginas del sitio. Cadena de herencia del diseño: page.html → default.html → genera HTML completo. El front matter layout: default (línea 2) significa que este diseño envuelve su salida DENTRO del diseño predeterminado. El diseño predeterminado proporciona <html>, <head>, include de barra de navegación, include de pie de página e includes de scripts.

El sistema de ancho — tres modos de renderizado

{% if page.width == 'expand' %}       <!-- Ancho completo, sin contenedor -->
  {{ content }}                        <!-- Contenido sin procesar, sin envoltorio -->
{% else %}
  <div class="uk-section">             <!-- Envoltorio de sección UIkit estándar -->
    <div class="uk-container{% if page.width %} uk-container-{{page.width}}{% endif %}">
      <article class="uk-article">
        <h1 class="uk-article-title">{{ page.title | escape }}</h1>
        <div class="article-content link-primary">
          {{ content }}
        </div>
      </article>
    </div>
  </div>
{% endif %}

Las páginas establecen su ancho mediante front matter:

Front matterClase del contenedorAncho máximo típicoUsado para
(ninguno).uk-container1200pxPáginas de documentación estándar
width: small.uk-container-small900pxPágina de búsqueda (#4093), páginas legales, contenido estrecho
width: large.uk-container-large1600pxTablas anchas, páginas de comparación
width: expandSin contenedor en absoluto100% del viewportDiseños de ancho completo, páginas de aterrizaje

El modo expand es especial — omite todo el envoltorio de sección/artículo y genera directamente {{ content }} sin procesar. Se usa para páginas que necesitan control de ancho completo del viewport (secciones de héroe personalizadas, páginas de aterrizaje).

Elecciones de HTML semántico

<article> (línea 11): El uso del elemento HTML5 <article> indica que cada página se considera una composición independiente — bueno para SEO y accesibilidad. La clase .uk-article recibe estilo de article.scss (#4029) para tipografía.

link-primary (línea 15): Esta clase personalizada en el envoltorio de contenido hace que todos los enlaces internos usen el color primario. En el SCSS de la marca ProjectForge (projectforge.scss #3945), esto se sobrescribe a #BF4040 (rojo de ProjectForge). Sin esta clase, los enlaces dentro del contenido del artículo usarían el azul predeterminado de UIkit.

{{ page.title | escape }} (línea 13): El filtro Liquid | escape previene XSS — si un título de página contiene HTML/JS, se escapa en lugar de renderizarse. Defensa en profundidad para contenido proveniente de front matter de Markdown/AsciiDoc.

Conclusiones clave

  • El 60% de las páginas usan esto: Cada página de documentación, página legal, página de búsqueda y página de contenido hereda de page.html. Los cambios aquí afectan a la mayoría del sitio.
  • El modo expand es sin procesar: Sin sección, sin contenedor, sin envoltorio de artículo — solo {{ content }}. Usar con precaución; la página debe proporcionar su propio diseño.
  • link-primary es el activador de la marca: La clase que activa el color de enlace rojo de ProjectForge (#BF4040). Sin ella, los enlaces mantienen el azul predeterminado de UIkit.
  • Hereda de default: Este diseño tiene 23 líneas porque la mayor parte de la estructura HTML (head, barra de navegación, pie de página) reside en default.html. El sistema de diseño es una cadena de composición.
