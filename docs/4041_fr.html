Chaîne d'héritage des mises en page : page.html → default.html → produit le HTML complet. Les métadonnées layout: default (ligne 2) signifient que cette mise en page insère son résultat À L'INTÉRIEUR de la mise en page par défaut. La mise en page par défaut fournit <html>, <head>, l'inclusion de la barre de navigation, l'inclusion du pied de page et les inclusions de scripts.

Le système de largeur — trois modes de rendu

{% if page.width == 'expand' %}       <!-- Pleine largeur, sans conteneur -->
  {{ content }}                        <!-- Contenu brut, sans wrapper -->
{% else %}
  <div class="uk-section">             <!-- Wrapper de section UIkit standard -->
    <div class="uk-container{% if page.width %} uk-container-{{page.width}}{% endif %}">
      <article class="uk-article">
        <h1 class="uk-article-title">{{ page.title | escape }}</h1>
        <div class="article-content link-primary">
          {{ content }}
        </div>
      </article>
    </div>
  </div>
{% endif %}

Les pages définissent leur largeur via les métadonnées :

MétadonnéesClasse du conteneurLargeur max typiqueUtilisé pour
(aucune).uk-container1200pxPages de documentation standard
width: small.uk-container-small900pxPage de recherche (#4093), pages légales, contenu étroit
width: large.uk-container-large1600pxTableaux larges, pages de comparaison
width: expandAucun conteneur100% de la fenêtreMises en page pleine largeur, pages d'accueil

Le mode expand est spécial — il contourne l'intégralité du wrapper section/article et affiche directement le {{ content }} brut. Ceci est utilisé pour les pages qui nécessitent un contrôle total de la largeur de la fenêtre (sections hero personnalisées, pages d'accueil).

Choix HTML sémantiques

<article> (ligne 11) : L'utilisation de l'élément HTML5 <article> indique que chaque page est considérée comme une composition autonome — bon pour le SEO et l'accessibilité. La classe .uk-article est thématisée par article.scss (#4029) pour la typographie.

link-primary (ligne 15) : Cette classe personnalisée sur le wrapper de contenu fait que tous les liens à l'intérieur utilisent la couleur primaire. Dans le SCSS de la marque ProjectForge (projectforge.scss #3945), elle est remplacée par #BF4040 (rouge ProjectForge). Sans cette classe, les liens dans le contenu de l'article utiliseraient le bleu par défaut d'UIkit.

{{ page.title | escape }} (ligne 13) : Le filtre Liquid | escape empêche les XSS — si un titre de page contient du HTML/JS, il est échappé plutôt que rendu. Défense en profondeur pour le contenu provenant des métadonnées Markdown/AsciiDoc.

Points clés à retenir

  • 60 % des pages utilisent ceci : Chaque page de documentation, page légale, page de recherche et page de contenu hérite de page.html. Les modifications ici affectent la majorité du site.
  • Le mode Expand est brut : Pas de section, pas de conteneur, pas de wrapper d'article — juste {{ content }}. À utiliser avec prudence ; la page doit fournir sa propre mise en page.
  • link-primary est le déclencheur de marque : La classe qui active la couleur de lien rouge de ProjectForge (#BF4040). Sans elle, les liens restent bleus par défaut dans UIkit.
  • Hérite de default : Cette mise en page fait 23 lignes car la majeure partie de la structure HTML (head, barre de navigation, pied de page) se trouve dans default.html. Le système de mise en page est une chaîne de composition.
