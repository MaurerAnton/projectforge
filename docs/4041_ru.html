#4041: page.html

site/_layouts/page.html

Путь: site/_layouts/page.html · Строк: 23 · Тип: Макет Jekyll (шаблон Liquid)

Назначение: Стандартный макет страницы — используется примерно на 60% всех страниц сайта. Оборачивает содержимое в секцию UIkit + контейнер, отображает статью с заголовком h1 и поддерживает варианты ширины (small, large, expand). Наследуется от макета default, который предоставляет полную HTML-оболочку (head, панель навигации, подвал).

Цепочка наследования макетов: page.html → default.html → выводит полный HTML. Фронт-материя layout: default (строка 2) означает, что этот макет оборачивает свой вывод ВНУТРИ макета по умолчанию. Макет по умолчанию предоставляет <html>, <head>, включает панель навигации, подвал и скрипты.

Система ширины — три режима отображения

{% if page.width == 'expand' %}       <!-- На всю ширину, без контейнера -->
  {{ content }}                        <!-- Сырой контент, без обёртки -->
{% else %}
  <div class="uk-section">             <!-- Стандартная обёртка секции UIkit -->
    <div class="uk-container{% if page.width %} uk-container-{{page.width}}{% endif %}">
      <article class="uk-article">
        <h1 class="uk-article-title">{{ page.title | escape }}</h1>
        <div class="article-content link-primary">
          {{ content }}
        </div>
      </article>
    </div>
  </div>
{% endif %}

Страницы задают свою ширину через фронт-материю:

Фронт-материяКласс контейнераТипичная макс. ширинаИспользуется для
(нет).uk-container1200pxСтандартные страницы документации
width: small.uk-container-small900pxСтраница поиска (#4093), юридические страницы, узкий контент
width: large.uk-container-large1600pxШирокие таблицы, страницы сравнения
width: expandБез контейнера100% окна просмотраМакеты на всю ширину, посадочные страницы

Режим expand особенный — он обходит всю обёртку секции/статьи и выводит сырой {{ content }} напрямую. Используется для страниц, которым нужен полный контроль ширины окна просмотра (пользовательские секции-герои, посадочные страницы).

Семантический выбор HTML

<article> (строка 11): Использование элемента HTML5 <article> указывает, что каждая страница считается самостоятельным композиционным элементом — хорошо для SEO и доступности. Класс .uk-article оформляется через article.scss (#4029) для типографики.

link-primary (строка 15): Этот пользовательский класс на обёртке контента делает все ссылки внутри использующими основной цвет. В фирменном SCSS ProjectForge (projectforge.scss #3945) он переопределяется на #BF4040 (красный ProjectForge). Без этого класса ссылки внутри контента статьи использовали бы синий цвет UIkit по умолчанию.

{{ page.title | escape }} (строка 13): Фильтр Liquid | escape предотвращает XSS — если заголовок страницы каким-то образом содержит HTML/JS, он экранируется, а не отображается. Защита в глубину для контента, поступающего из фронт-материи Markdown/AsciiDoc.

Ключевые выводы

  • 60% страниц используют это: Каждая страница документации, юридическая страница, страница поиска и контентная страница наследуются от page.html. Изменения здесь затрагивают большинство сайта.
  • Режим expand — сырой: Ни секции, ни контейнера, ни обёртки статьи — только {{ content }}. Используйте с осторожностью; страница должна предоставлять собственный макет.
  • link-primary — триггер бренда: Класс, который активирует красный цвет ссылок ProjectForge (#BF4040). Без него ссылки остаются синими по умолчанию UIkit.
  • Наследуется от default: Этот макет состоит из 23 строк, потому что большая часть структуры HTML (head, панель навигации, подвал) находится в default.html. Система макетов — это цепочка композиции.
