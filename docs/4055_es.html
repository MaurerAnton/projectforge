Se importa DESPUÉS de los 63 archivos de tema de UIkit, lo que le otorga la máxima especificidad para sobrescribir cualquier valor predeterminado de UIkit con la identidad de marca de ProjectForge.

Qué hay aquí que UIkit no proporciona

A diferencia de los 63 archivos de tema de UIkit (que principalmente definen variables y dejan los hooks comentados), este archivo contiene reglas CSS reales — 110 líneas de sobrescrituras explícitas organizadas por área visual:

1. Color de enlace de marca — la regla de mayor impacto

p a, li a, table td a {
  color: #BF4040;    // Rojo ProjectForge — NO el azul predeterminado de UIkit
}

Cada enlace en párrafos, elementos de lista y celdas de tabla obtiene #BF4040 — un rojo apagado. Este es EL color de marca de ProjectForge para enlaces. El color de enlace predeterminado de UIkit es su azul primario ($global-primary-background ≈ #1e87f0). Esta única regla es lo que hace que el sitio de ProjectForge sea visualmente distinto de cualquier otro sitio UIkit. La especificidad mediante selectores de elemento+contexto (p a, no solo a) asegura que solo afecte a los enlaces de contenido, no a los enlaces de navegación o botones.

2. Barra de navegación en negrita + posicionamiento del menú desplegable

.uk-navbar-nav > li > a {
  font-weight: 700;            // Elementos de navegación en negrita — más fuerte que el predeterminado de UIkit
}
.uk-navbar-dropdown {
  padding: 10px 20px;          // Sobrescribe el padding de 25px del tema
  top: 60px !important;        // Posición FORZADA — sobrescribe la posición calculada por JS
}

font-weight: 700 — hace que los elementos de navegación sean más negritos que el peso normal de UIkit. Combinado con la transformación a MAYÚSCULAS del tema, esto crea un estilo de navegación muy asertivo.

top: 60px !important — el !important es notable. El componente Drop de UIkit calcula la posición del menú desplegable mediante JavaScript y la establece en línea. El !important sobrescribe el estilo en línea para forzar un espacio consistente de 60px. Sin esto, los menús desplegables podrían aparecer demasiado cerca o lejos de la navegación dependiendo de la ventana gráfica. Este es un patrón de "luchar contra JavaScript con CSS".

3. Estilo de tabla — legibilidad de documentos

table {
  width: auto;                // Las tablas no se estiran a todo el ancho
  th { background: #f2f2f2; } // Encabezado gris claro — más claro que el atenuado del tema
  th:first-child, td:first-child { padding-left: 10px; }
}

width: auto — evita que las tablas se estiren al 100% de su contenedor. En páginas de documentación con contenido estrecho (tablas comparativas, listas de parámetros), las tablas de ancho completo desperdician espacio. El ancho automático permite que las tablas tengan solo el ancho de su contenido.

4. Bloques de código — correcciones de renderizado AsciiDoc

pre {
  color: #b90505;              // Texto de código rojo oscuro
  font-size: .775rem;          // Más pequeño que el texto del cuerpo
  &.highlight {
    padding: 15px; background: #f4f4f4;  // Fondo de código resaltado
  }
}
.listingblock {
  pre code table { margin: 0; }          // Listado de código AsciiDoc — eliminar márgenes
  table.linenotable td { margin: 0; padding: 0; }  // Tabla de números de línea — compacta
}

Color de código #b90505 — rojo oscuro para el texto del código. Una elección inusual (la mayoría de los sitios usan gris oscuro/negro). Esto vincula visualmente el código con la paleta roja de la marca.

Reglas .listingblock — estas corrigen los bloques de código renderizados por AsciiDoc. AsciiDoc genera estructuras anidadas table > pre > code con márgenes predeterminados que crean un espacio en blanco excesivo. Estas reglas colapsan esos márgenes. El selector table.linenotable se dirige específicamente a los bloques de código con números de línea de AsciiDoc.

5. Acordeón de preguntas frecuentes — estilo interactivo personalizado

#pf-faq .uk-section {
  padding-top: 0; padding-bottom: 20px;
  .uk-accordion li a.uk-accordion-title {
    border-bottom: 1px solid #ebecee !important;  // Borde sutil entre elementos de preguntas frecuentes
    font-weight: 600; padding: 10px; font-size: 16px;  // Área de clic más grande
  }
  > :nth-child(n+2) { margin-top: 10px; }  // Espacio entre elementos
}

Estilo específico para preguntas frecuentes bajo el ámbito de #pf-faq. Cada título de acordeón obtiene un separador de borde claro, peso negrita y un padding generoso para la facilidad táctil. El !important en el borde sobrescribe el valor predeterminado del acordeón de UIkit.
