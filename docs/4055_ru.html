Не UIkit. Этот файл находится в site/_sass/theme/ — отдельном каталоге от _sass/uikit/theme/. Он импортируется ПОСЛЕ всех 63 файлов темы UIkit, что даёт ему максимальную специфичность для переопределения любых стандартных настроек UIkit в соответствии с фирменным стилем ProjectForge.

Что здесь есть, чего нет в UIkit

В отличие от 63 файлов темы UIkit (которые в основном определяют переменные и оставляют хуки закомментированными), этот файл содержит фактические CSS-правила — 110 строк явных переопределений, сгруппированных по визуальным областям:

1. Цвет ссылок бренда — самое влиятельное правило

p a, li a, table td a {
  color: #BF4040;    // Красный ProjectForge — НЕ стандартный синий UIkit
}

Каждая ссылка в абзацах, элементах списков и ячейках таблиц получает цвет #BF4040 — приглушённый красный. Это ГЛАВНЫЙ фирменный цвет ProjectForge для ссылок. Стандартный цвет ссылок UIkit — его основной синий ($global-primary-background ≈ #1e87f0). Это единственное правило делает сайт ProjectForge визуально отличным от любого другого сайта на UIkit. Специфичность через селекторы элемент+контекст (p a, а не просто a) гарантирует, что оно применяется только к контентным ссылкам, а не к навигации или кнопкам.

2. Жирная панель навигации + позиционирование выпадающего меню

.uk-navbar-nav > li > a {
  font-weight: 700;            // Жирные пункты меню — сильнее стандартного UIkit
}
.uk-navbar-dropdown {
  padding: 10px 20px;          // Переопределяет отступ темы в 25px
  top: 60px !important;        // ПРИНУДИТЕЛЬНАЯ позиция — переопределяет позицию, рассчитанную JS
}

font-weight: 700 — делает пункты меню жирнее, чем стандартная насыщенность UIkit. В сочетании с преобразованием в ВЕРХНИЙ РЕГИСТР темы создаёт очень уверенный стиль навигации.

top: 60px !important — использование !important примечательно. Компонент Drop в UIkit рассчитывает позицию выпадающего меню через JavaScript и устанавливает её инлайн. !important переопределяет инлайн-стиль, принудительно устанавливая постоянный отступ в 60px. Без этого выпадающие меню могут отображаться слишком близко или далеко от панели навигации в зависимости от области просмотра. Это пример подхода «борьба с JavaScript с помощью CSS».

3. Стилизация таблиц — читаемость документации

table {
  width: auto;                // Таблицы не растягиваются на всю ширину
  th { background: #f2f2f2; } // Светло-серый заголовок — чётче, чем приглушённый тон темы
  th:first-child, td:first-child { padding-left: 10px; }
}

width: auto — предотвращает растягивание таблиц на 100% ширины контейнера. На страницах документации с узким содержимым (сравнительные таблицы, списки параметров) полноразмерные таблицы занимают лишнее место. Автоширина позволяет таблицам быть только такой ширины, как их содержимое.

4. Блоки кода — исправления рендеринга AsciiDoc

pre {
  color: #b90505;              // Тёмно-красный текст кода
  font-size: .775rem;          // Меньше, чем основной текст
  &.highlight {
    padding: 15px; background: #f4f4f4;  // Фон выделенного кода
  }
}
.listingblock {
  pre code table { margin: 0; }          // Блоки кода AsciiDoc — убрать отступы
  table.linenotable td { margin: 0; padding: 0; }  // Таблица номеров строк — компактно
}

Цвет кода #b90505 — тёмно-красный для текста кода. Необычный выбор (большинство сайтов используют тёмно-серый/чёрный). Это визуально связывает код с красной палитрой бренда.

Правила .listingblock — исправляют отображение блоков кода, сгенерированных AsciiDoc. AsciiDoc создаёт вложенные структуры table > pre > code со стандартными отступами, которые создают излишние пробелы. Эти правила схлопывают эти отступы. Селектор table.linenotable нацелен конкретно на блоки кода с нумерацией строк AsciiDoc.

5. Аккордеон FAQ — пользовательское интерактивное оформление

#pf-faq .uk-section {
  padding-top: 0; padding-bottom: 20px;
  .uk-accordion li a.uk-accordion-title {
    border-bottom: 1px solid #ebecee !important;  // Тонкая граница между элементами FAQ
    font-weight: 600; padding: 10px; font-size: 16px;  // Увеличенная область клика
  }
  > :nth-child(n+2) { margin-top: 10px; }  // Промежуток между элементами
}

Стилизация, специфичная для FAQ, ограниченная контекстом #pf-faq. Каждый заголовок аккордеона получает светлую разделительную границу, жирное начертание и щедрые отступы для удобства сенсорного управления. !important для границы переопределяет стандартные настройки аккордеона UIkit.
