Kern, nicht Theme. Diese Datei enthält tatsächliche CSS-Regeln (nicht nur Hooks oder Variablen). Sie definiert das strukturelle CSS für die Cover-Komponente. Das Theme-Pendant in site/_sass/uikit/theme/ würde visuelle Gestaltung hinzufügen — aber es gibt KEIN theme/cover.scss auf der ProjectForge-Seite. Das Cover verwendet UIkit-Standardeinstellungen für sein Erscheinungsbild.

Die Zentrierungstechnik — ein CSS-Klassiker

.uk-cover {
  max-width: none;                           // 1. Responsive Breitenbegrenzung entfernen
  position: absolute;                        // 2. Aus dem Dokumentenfluss nehmen
  left: 50%; top: 50%;                       // 3. Obere linke Ecke in der Mitte positionieren
  transform: translate(-50%, -50%);          // 4. Um die Hälfte der Breite/Höhe zurückverschieben
}

.uk-cover-container {
  overflow: hidden;                          // Inhalt beschneiden, der den Container überragt
  position: relative;                        // Positionierungskontext für .uk-cover herstellen
}

iframe.uk-cover { pointer-events: none; }    // Klicks gehen zum Elternelement durch

Zeile für Zeile des Zentrierungstricks:

  1. max-width: none: Entfernt jegliche responsive Breitenbeschränkung. Das Cover-Element muss sich frei ausdehnen können, um den Container abzudecken, selbst wenn es die Viewport-Breite überschreitet.
  2. position: absolute: Nimmt das Element aus dem normalen Dokumentenfluss. Dies ist erforderlich, damit left/top funktionieren, und es benötigt den Eltern-Container mit position: relative (Zeile 47).
  3. left: 50%; top: 50%: Positioniert die OBERE LINKE Ecke des Elements in der Mitte des Containers. An diesem Punkt ist das Element versetzt — seine obere linke Ecke ist zentriert, nicht das Element selbst.
  4. transform: translate(-50%, -50%): Verschiebt das Element um die Hälfte seiner eigenen Breite und Höhe ZURÜCK. Das Ergebnis: Die MITTE des Elements befindet sich jetzt in der Mitte des Containers. Dies funktioniert, weil Prozentwerte in translate() sich auf die eigenen Abmessungen des Elements beziehen, nicht auf die des Elternteils.

Dies ist wohl das berühmteste CSS-Zentrierungsmuster. Wird auf der ProjectForge-Seite für Hero-Hintergrundbilder verwendet — die Kopfzeilen der Dokumentationsseiten mit Hintergrundfotos.

Wie Hero-Bereiche dies verwenden

Auf der ProjectForge-Seite werden Helden der Dokumentationsseiten wie folgt dargestellt:

<div class="uk-cover-container">
  <img src="search.png" data-uk-cover>    <!-- Dies wird zu .uk-cover -->
  <div class="uk-position-relative">        <!-- Inhalt liegt oben auf -->
    <h1>Suche</h1>
  </div>
</div>

UIkits JavaScript fügt die Klasse .uk-cover hinzu und berechnet die Abmessungen dynamisch. Das CSS aus dieser Datei sorgt für die Positionierung. Das overflow: hidden am Container stellt sicher, dass das Cover-Bild nicht überläuft, wenn es größer als der Container ist.

Wichtige Erkenntnisse

  • Kern, nicht Theme: Dies ist reines Layout-CSS. Keine Farben, keine Schatten — nur Positionierungsmathematik.
  • iframe-pointer-events-Hack (Zeile 33): pointer-events: none auf Iframes verhindert, dass das Iframe Klicks abfängt. Unverzichtbar für eingebettete YouTube/Vimeo-Videos, die als Hintergründe verwendet werden — Benutzer müssen mit Inhalten OBEN AUF dem Video interagieren können.
  • Kein Theme-Pendant: Anders als die meisten UIkit-Komponenten, die sowohl Kern- als auch Theme-Dateien haben, hat Cover kein theme/cover.scss. Die gesamte visuelle Gestaltung stammt vom Inhalt selbst (dem Bild) und den umgebenden Kachel-/Abschnittskomponenten.
  • JavaScript-Abhängigkeit: Das Attribut data-uk-cover löst UIkits JS aus, um den Container zu messen und entsprechende Abmessungen festzulegen. Das CSS allein sorgt nicht für die Abdeckung — es benötigt das JS für die dynamische Größenanpassung.
