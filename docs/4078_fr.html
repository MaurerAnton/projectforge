Cœur, pas un thème. Ce fichier contient des règles CSS réelles (pas seulement des hooks ou des variables). Il définit le CSS structurel pour le composant Cover. La contrepartie thématique dans site/_sass/uikit/theme/ ajouterait le style visuel — mais il n’y a PAS de theme/cover.scss dans le site ProjectForge. Le cover utilise les valeurs par défaut d’UIkit pour son apparence.

La technique de centrage — un classique CSS

.uk-cover {
  max-width: none;                           // 1. Supprime la limite de largeur responsive
  position: absolute;                        // 2. Sort du flux du document
  left: 50%; top: 50%;                       // 3. Positionne le coin supérieur gauche au centre
  transform: translate(-50%, -50%);          // 4. Décale en arrière de la moitié de la largeur/hauteur
}

.uk-cover-container {
  overflow: hidden;                          // Coupe le contenu qui dépasse du conteneur
  position: relative;                        // Établit un contexte de positionnement pour .uk-cover
}

iframe.uk-cover { pointer-events: none; }    // Les clics traversent vers le parent

Ligne par ligne de l’astuce de centrage :

  1. max-width: none : Supprime toute contrainte de largeur responsive. L’élément cover doit être libre de s’étendre pour couvrir le conteneur, même s’il dépasse la largeur de la fenêtre.
  2. position: absolute : Sort l’élément du flux normal du document. Nécessaire pour que left/top fonctionne, et nécessite que le conteneur parent ait position: relative (ligne 47).
  3. left: 50%; top: 50% : Positionne le coin SUPÉRIEUR GAUCHE de l’élément au centre du conteneur. À ce stade, l’élément est décalé — son coin supérieur gauche est centré, pas l’élément lui-même.
  4. transform: translate(-50%, -50%) : Décale l’élément VERS L’ARRIÈRE de la moitié de sa propre largeur et hauteur. Résultat : le CENTRE de l’élément est maintenant au centre du conteneur. Cela fonctionne car les valeurs en pourcentage dans translate() se réfèrent aux dimensions propres de l’élément, pas à celles du parent.

C’est sans doute le motif de centrage CSS le plus célèbre. Utilisé sur le site ProjectForge pour les images d’arrière-plan hero — les en-têtes de page de documentation avec photos d’arrière-plan.

Comment les sections hero utilisent cela

Sur le site ProjectForge, les héros des pages de documentation sont rendus ainsi :

<div class="uk-cover-container">
  <img src="search.png" data-uk-cover>    <!-- Devient .uk-cover -->
  <div class="uk-position-relative">        <!-- Le contenu se place par-dessus -->
    <h1>Recherche</h1>
  </div>
</div>

Le JavaScript d’UIkit ajoute la classe .uk-cover et calcule les dimensions dynamiquement. Le CSS de ce fichier fournit le positionnement. Le overflow: hidden sur le conteneur garantit que l’image de couverture ne déborde pas si elle est plus grande que le conteneur.

Points clés à retenir

  • Cœur, pas un thème : C’est du CSS de mise en page pur. Pas de couleurs, pas d’ombres — juste des calculs de positionnement.
  • Astuce pointer-events pour iframe (ligne 33) : pointer-events: none sur les iframes empêche l’iframe de capturer les clics. Essentiel pour les vidéos YouTube/Vimeo intégrées utilisées comme arrière-plans — les utilisateurs doivent pouvoir interagir avec le contenu AU-DESSUS de la vidéo.
  • Pas de contrepartie thème : Contrairement à la plupart des composants UIkit qui ont à la fois des fichiers cœur et thème, Cover n’a pas de theme/cover.scss. Tout son style visuel provient du contenu lui-même (l’image) et des composants de tuile/section qui l’encapsulent.
  • Dépendance JavaScript : L’attribut data-uk-cover déclenche le JS d’UIkit pour mesurer le conteneur et définir les dimensions appropriées. Le CSS seul ne suffit pas à le faire couvrir — il a besoin du JS pour le dimensionnement dynamique.
