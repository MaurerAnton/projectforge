Ядро, не тема. Этот файл содержит фактические CSS-правила (не только хуки или переменные). Он определяет структурный CSS для компонента Cover. Тематический аналог в site/_sass/uikit/theme/ добавлял бы визуальное оформление — но в ProjectForge НЕТ theme/cover.scss. Компонент cover использует стандартные настройки UIkit для своего внешнего вида.

Техника центрирования — классика CSS

.uk-cover {
  max-width: none;                           // 1. Убираем ограничение адаптивной ширины
  position: absolute;                        // 2. Извлекаем из потока документа
  left: 50%; top: 50%;                       // 3. Позиционируем верхний левый угол по центру
  transform: translate(-50%, -50%);          // 4. Сдвигаем обратно на половину ширины/высоты
}

.uk-cover-container {
  overflow: hidden;                          // Обрезаем контент, выходящий за пределы контейнера
  position: relative;                        // Устанавливаем контекст позиционирования для .uk-cover
}

iframe.uk-cover { pointer-events: none; }    // Клики проходят сквозь к родителю

Построчное объяснение трюка с центрированием:

  1. max-width: none: Убирает любые ограничения адаптивной ширины. Элемент cover должен иметь возможность свободно расширяться, чтобы покрыть контейнер, даже если он превышает ширину окна просмотра.
  2. position: absolute: Извлекает элемент из нормального потока документа. Это необходимо для работы left/top, и требуется, чтобы родительский контейнер имел position: relative (строка 47).
  3. left: 50%; top: 50%: Позиционирует ВЕРХНИЙ ЛЕВЫЙ угол элемента по центру контейнера. На этом этапе элемент смещён — его верхний левый угол находится в центре, а не сам элемент.
  4. transform: translate(-50%, -50%): Сдвигает элемент ОБРАТНО на половину его собственной ширины и высоты. Результат: ЦЕНТР элемента теперь находится в центре контейнера. Это работает, потому что процентные значения в translate() относятся к собственным размерам элемента, а не родителя.

Это, пожалуй, самый известный CSS-паттерн центрирования. Используется на сайте ProjectForge для фоновых изображений hero — заголовков страниц документации с фоновыми фотографиями.

Как hero-секции используют это

На сайте ProjectForge hero страниц документации отображаются так:

<div class="uk-cover-container">
  <img src="search.png" data-uk-cover>    <!-- Это становится .uk-cover -->
  <div class="uk-position-relative">        <!-- Контент располагается сверху -->
    <h1>Поиск</h1>
  </div>
</div>

JavaScript UIkit добавляет класс .uk-cover и динамически вычисляет размеры. CSS из этого файла обеспечивает позиционирование. overflow: hidden на контейнере гарантирует, что фоновое изображение не вылезет за пределы, если оно больше контейнера.

Ключевые выводы

  • Ядро, не тема: Это чистый CSS для раскладки. Никаких цветов, никаких теней — только математика позиционирования.
  • Хак с pointer-events для iframe (строка 33): pointer-events: none на iframe предотвращает перехват кликов iframe. Необходимо для встроенных видео YouTube/Vimeo, используемых в качестве фона — пользователи должны иметь возможность взаимодействовать с контентом ПОВЕРХ видео.
  • Нет тематического аналога: В отличие от большинства компонентов UIkit, которые имеют как основные, так и тематические файлы, Cover не имеет theme/cover.scss. Всё его визуальное оформление исходит от самого контента (изображения) и компонентов плиток/секций, которые его оборачивают.
  • Зависимость от JavaScript: Атрибут data-uk-cover запускает JS UIkit для измерения контейнера и установки соответствующих размеров. Один CSS не заставит элемент покрывать контейнер — для динамического изменения размеров требуется JS.
