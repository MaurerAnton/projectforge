Core vs Theme — the architectural split

UIkit has a two-file entry point architecture:

FileWhat it importsWhen to use
uikit.scss (this file)Only core component SCSS — no theme extensionsWhen you want UIkit's layout system (grid, flex, positioning) but will write your own visual styling
uikit-theme.scss (#4090)Core components + all 63 theme files + variable overridesWhen you want the full themed UIkit experience with brand colors and visual polish

The ProjectForge site uses uikit-theme.scss (#4090) as its entry point — the site needs the full themed appearance. This core-only file exists as a reference and for potential minimal-CSS use cases where only layout functionality is needed.

What's included: Grid system, flex utilities, width/height utilities, visibility responsive classes, position utilities, margin/padding utilities, and the basic component structures (without colors/shadows/fonts). Essentially: "where elements go" without "how elements look."

Key takeaways

  • Not the active entry point: ProjectForge.org uses uikit-theme.scss (#4090). This file provides only structural CSS — no colors, no shadows, no branded appearance.
  • Upgrade safety: This file is typically from the UIkit npm package. When upgrading UIkit, update this from upstream — it should have no ProjectForge-specific modifications.
  • Core/theme separation: Understanding this split is essential for any UIkit customization. Modify theme files, never core files.
