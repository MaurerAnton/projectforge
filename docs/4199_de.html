Die vollständige CSS-Kompilierungskette

Wenn Jekyll die Site erstellt, durchläuft die CSS-Kompilierung genau 5 Dateien, bevor die endgültige Ausgabe erzeugt wird:

SchrittDateiFunktion
1assets/css/main.scssJekyll-Einstiegspunkt – hat leere Front-Matter (---\n---), die Jekyll anweist, diese Datei zu verarbeiten. Enthält: @import "uikit/uikit-theme.scss";
2uikit-theme.scss (diese Datei)Importiert Variablen → Theme-Überschreibungen → alle 63 Komponenten-Theme-Dateien → alle Kernkomponenten-Dateien
3variables.scss (#4091) + variables-theme.scss (#4092)Definiert und überschreibt Design-Tokens
463 theme/*.scss-DateienVisuelles Styling für jede Komponente (Farben, Schatten, Schriftarten) – geladen über _import.scss (#4052)
560+ components/*.scss-DateienFunktionales CSS (Layout, Grid, Positionierung) – geladen über mehrere _import.*.scss-Dateien

Diese Datei enthält fast keine eigenen CSS-Regeln – sie ist ein Sammler/Manifest. Ihre @import-Reihenfolge ist sorgfältig sequenziert: zuerst Variablen (damit Komponenten darauf verweisen können), dann Theme-Überschreibungen (selektive Änderung der Kernstandards), dann alle Komponentenstile.

Wichtige Erkenntnisse

  • Der einzelne Importpunkt: Alles, was das Site-CSS benötigt, fließt durch diese Datei. Entfernen Sie einen Import hier, und die Stile dieser Komponente verschwinden.
  • @import-Abkündigung: SCSS @import ist in Dart Sass 2.0+ veraltet. Eine zukünftige Migration zu @use/@forward erfordert eine Umstrukturierung dieser Datei.
  • Übergeordnete Abhängigkeit: assets/css/main.scss muss Jekyll-Front-Matter haben (auch leer), damit Jekyll sie verarbeitet. Ohne diese behandelt Jekyll sie als statische Ressource und kompiliert SCSS nicht.
