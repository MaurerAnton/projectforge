La cadena completa de compilación CSS

Cuando Jekyll construye el sitio, la compilación CSS fluye a través de exactamente 5 archivos antes de producir la salida final:

PasoArchivoQué hace
1assets/css/main.scssPunto de entrada de Jekyll — tiene front matter vacío (---\n---) que le indica a Jekyll que procese este archivo. Contiene: @import "uikit/uikit-theme.scss";
2uikit-theme.scss (este archivo)Importa variables → anulaciones de tema → los 63 archivos de tema de componentes → todos los archivos de componentes principales
3variables.scss (#4091) + variables-theme.scss (#4092)Define y anula los tokens de diseño
463 archivos theme/*.scssEstilo visual para cada componente (colores, sombras, fuentes) — cargado a través de _import.scss (#4052)
560+ archivos components/*.scssCSS funcional (diseño, cuadrícula, posicionamiento) — cargado a través de múltiples archivos _import.*.scss

Este archivo contiene casi ninguna regla CSS propia — es un agregador/manifiesto. Su orden de @import está cuidadosamente secuenciado: primero las variables (para que los componentes puedan referenciarlas), segundo las anulaciones de tema (modificando selectivamente los valores predeterminados del núcleo), luego todos los estilos de componentes.

Conclusiones clave

  • El punto de importación único: Todo lo que necesita el CSS del sitio fluye a través de este archivo. Elimina una importación aquí, y los estilos de ese componente desaparecen.
  • Obsolescencia de @import: @import de SCSS está obsoleto en Dart Sass 2.0+. La migración futura a @use/@forward requerirá reestructurar este archivo.
  • Dependencia principal: assets/css/main.scss debe tener front matter de Jekyll (incluso vacío) para que Jekyll lo procese. Sin él, Jekyll lo trata como un activo estático y no compila SCSS.
