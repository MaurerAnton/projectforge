La chaîne de compilation CSS complète

Lorsque Jekyll construit le site, la compilation CSS traverse exactement 5 fichiers avant de produire la sortie finale :

ÉtapeFichierCe qu’il fait
1assets/css/main.scssPoint d’entrée Jekyll — possède un front matter vide (---\n---) qui indique à Jekyll de traiter ce fichier. Contient : @import "uikit/uikit-theme.scss";
2uikit-theme.scss (ce fichier)Importe les variables → les surcharges de thème → les 63 fichiers de thème de composants → tous les fichiers de composants principaux
3variables.scss (#4091) + variables-theme.scss (#4092)Définit et surcharge les jetons de conception
463 fichiers theme/*.scssStyle visuel pour chaque composant (couleurs, ombres, polices) — chargé via _import.scss (#4052)
560+ fichiers components/*.scssCSS fonctionnel (disposition, grille, positionnement) — chargé via plusieurs fichiers _import.*.scss

Ce fichier ne contient presque aucune règle CSS propre — c’est un agrégateur/manifeste. Son ordre @import est soigneusement séquencé : d’abord les variables (afin que les composants puissent les référencer), ensuite les surcharges de thème (modifiant sélectivement les valeurs par défaut du noyau), puis tous les styles de composants.

Points clés à retenir

  • Le point d’import unique : Tout ce dont le CSS du site a besoin passe par ce fichier. Supprimez une importation ici, et les styles de ce composant disparaissent.
  • Obsolescence de @import : @import SCSS est obsolète dans Dart Sass 2.0+. Une future migration vers @use/@forward nécessitera une restructuration de ce fichier.
  • Dépendance parent : assets/css/main.scss doit avoir un front matter Jekyll (même vide) pour que Jekyll le traite. Sans cela, Jekyll le traite comme un actif statique et ne compile pas le SCSS.
