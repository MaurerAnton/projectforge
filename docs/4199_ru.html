Полная цепочка компиляции CSS

Когда Jekyll собирает сайт, компиляция CSS проходит ровно через 5 файлов перед созданием финального вывода:

ШагФайлЧто делает
1assets/css/main.scssТочка входа Jekyll — содержит пустой front matter (---\n---), который указывает Jekyll обработать этот файл. Содержит: @import "uikit/uikit-theme.scss";
2uikit-theme.scss (этот файл)Импортирует переменные → переопределения темы → все 63 файла тем компонентов → все основные файлы компонентов
3variables.scss (#4091) + variables-theme.scss (#4092)Определяет и переопределяет токены дизайна
463 файла theme/*.scssВизуальный стиль для каждого компонента (цвета, тени, шрифты) — загружаются через _import.scss (#4052)
560+ файлов components/*.scssФункциональный CSS (раскладка, сетка, позиционирование) — загружаются через несколько файлов _import.*.scss

Этот файл почти не содержит собственных CSS-правил — это агрегатор/манифест. Порядок @import тщательно выверен: сначала переменные (чтобы компоненты могли на них ссылаться), затем переопределения темы (выборочно изменяющие базовые настройки), и наконец все стили компонентов.

Ключевые выводы

  • Единая точка импорта: Всё, что нужно CSS сайта, проходит через этот файл. Удалите импорт здесь — и стили этого компонента исчезнут.
  • Устаревание @import: SCSS @import объявлен устаревшим в Dart Sass 2.0+. Будущая миграция на @use/@forward потребует реструктуризации этого файла.
  • Родительская зависимость: assets/css/main.scss должен иметь front matter Jekyll (даже пустой), чтобы Jekyll его обработал. Без него Jekyll воспринимает файл как статический ресурс и не компилирует SCSS.
