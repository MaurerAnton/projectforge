Drei Technologien in einer Datei

Diese Seite vereint auf einzigartige Weise drei Ebenen:

  1. Jekyll-Frontmatter (Zeilen 1-10): YAML-Konfiguration – layout: page verwendet _layouts/page.html, width: small schmälert den Inhalt, tipue_search_active: true löst die Einbindung von Tipue-CSS/JS-Assets aus, hero konfiguriert das Banner mit dem Titel „Suche“ und dem Hintergrundbild search.png, permalink: /search/ legt die URL fest.
  2. AsciiDoc ++++ Durchlass-Block (Zeilen 14-31): Inhalt zwischen ++++-Markierungen wird ohne AsciiDoc-Verarbeitung direkt an die HTML-Ausgabe weitergegeben. Dies ermöglicht das Einbetten von rohem HTML und JavaScript in ein AsciiDoc-Dokument – notwendig, da AsciiDoc keine interaktiven Suchwidgets ausdrücken kann.
  3. JavaScript-Initialisierung (Zeilen 26-29): jQuery $(document).ready() bindet Tipue Search an #tipue_search_input mit .tipuesearch() – die einzelne Zeile, die die clientseitige Suche aktiviert.
<form class="uk-search uk-search-default uk-width-1-1">
  <span class="uk-search-icon-flip" data-uk-search-icon></span>
  <input id="tipue_search_input" pattern=".{3,}" required>
  <div id="tipue_search_content"></div>
</form>

<script>
$(document).ready(function() {
  $('#tipue_search_input').tipuesearch();
});
</script>

UIkit-Styling: Klassen uk-search, uk-search-default, uk-width-1-1, uk-search-icon-flip aus dem UIkit-Framework. Thematisiert durch das search.scss-Theme (#4071) – transparenter Hintergrund, sichtbarer Rand, gestrichelte Fokus-Variante.

pattern=".{3,}": HTML5-Client-seitige Validierung – erfordert mindestens 3 Zeichen vor dem Absenden des Formulars. Tipue Search erzwingt dies auch serverseitig.

Datenquelle: Der Suchindex stammt aus search.json (#4094) – wird einmal abgerufen, wenn der Benutzer zum ersten Mal tippt, und dann clientseitig gefiltert.
