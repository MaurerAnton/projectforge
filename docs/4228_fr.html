Trois technologies dans un seul fichier

Cette page combine de manière unique trois couches :

  1. En-tête Jekyll (lignes 1-10) : Configuration YAML — layout: page utilise _layouts/page.html, width: small réduit le contenu, tipue_search_active: true déclenche l’inclusion des ressources CSS/JS Tipue, hero configure la bannière avec le titre « Recherche » et l’image de fond search.png, permalink: /search/ définit l’URL.
  2. Bloc de passage AsciiDoc ++++ (lignes 14-31) : Le contenu entre les marqueurs ++++ est transmis directement à la sortie HTML sans traitement AsciiDoc. Cela permet d’intégrer du HTML brut et du JavaScript dans un document AsciiDoc — nécessaire car AsciiDoc ne peut pas exprimer de widgets de recherche interactifs.
  3. Initialisation JavaScript (lignes 26-29) : jQuery $(document).ready() lie Tipue Search à #tipue_search_input avec .tipuesearch() — la seule ligne qui active la recherche côté client.
<form class="uk-search uk-search-default uk-width-1-1">
  <span class="uk-search-icon-flip" data-uk-search-icon></span>
  <input id="tipue_search_input" pattern=".{3,}" required>
  <div id="tipue_search_content"></div>
</form>

<script>
$(document).ready(function() {
  $('#tipue_search_input').tipuesearch();
});
</script>

Style UIkit : Classes uk-search, uk-search-default, uk-width-1-1, uk-search-icon-flip du framework UIkit. Thème via search.scss (#4071) — fond transparent, bordure visible, variante pointillée au focus.

pattern=".{3,}" : Validation côté client HTML5 — nécessite au moins 3 caractères avant la soumission du formulaire. Tipue Search applique également cette règle côté serveur.

Source de données : L’index de recherche provient de search.json (#4094) — récupéré une fois lorsque l’utilisateur commence à taper, puis filtré côté client.
