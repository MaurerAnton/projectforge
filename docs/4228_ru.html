Три технологии в одном файле

Эта страница уникальным образом объединяет три уровня:

  1. Jekyll front matter (строки 1-10): YAML-конфигурация — layout: page использует _layouts/page.html, width: small сужает контент, tipue_search_active: true включает подключение CSS/JS-ресурсов Tipue, hero настраивает баннер с заголовком "Поиск" и фоновым изображением search.png, permalink: /search/ задаёт URL.
  2. AsciiDoc-блок пропуска ++++ (строки 14-31): Содержимое между маркерами ++++ передаётся напрямую в HTML-вывод без обработки AsciiDoc. Это позволяет встраивать сырой HTML и JavaScript в документ AsciiDoc — необходимо, поскольку AsciiDoc не может выразить интерактивные виджеты поиска.
  3. Инициализация JavaScript (строки 26-29): jQuery $(document).ready() привязывает Tipue Search к #tipue_search_input с помощью .tipuesearch() — единственная строка, активирующая поиск на стороне клиента.
<form class="uk-search uk-search-default uk-width-1-1">
  <span class="uk-search-icon-flip" data-uk-search-icon></span>
  <input id="tipue_search_input" pattern=".{3,}" required>
  <div id="tipue_search_content"></div>
</form>

<script>
$(document).ready(function() {
  $('#tipue_search_input').tipuesearch();
});
</script>

Стилизация UIkit: Классы uk-search, uk-search-default, uk-width-1-1, uk-search-icon-flip из фреймворка UIkit. Тема оформлена через search.scss (#4071) — прозрачный фон, видимая граница, пунктирный вариант при фокусе.

pattern=".{3,}": Валидация на стороне клиента HTML5 — требуется минимум 3 символа перед отправкой формы. Tipue Search также применяет это ограничение на серверной стороне.

Источник данных: Поисковый индекс берётся из search.json (#4094) — загружается один раз, когда пользователь начинает ввод, затем фильтруется на стороне клиента.
