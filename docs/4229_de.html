Wie die statische Suche funktioniert – Die Jekyll+TipueSearch-Architektur

Diese Datei ist KEINE statische JSON-Datei – es ist ein Jekyll-Template, das zur Build-Zeit verarbeitet wird. Der Ablauf:

  1. Build-Zeit: Jekyll verarbeitet {% for doc in site.docs %} – iteriert über jedes Dokument in der _docs/-Sammlung (installation.adoc, userguide.adoc, development.adoc usw.) – und erzeugt eine statische search.json-Datei im Ausgabeverzeichnis.
  2. Laufzeit: Wenn ein Benutzer im Suchfeld auf /search/ (#4093) tippt, ruft das Tipue-Search-jQuery-Plugin /search.json ab, filtert Einträge clientseitig und zeigt Ergebnisse an – kein Server, keine Datenbank, keine API.

Dies ist eine statische Seitensuche – der gesamte durchsuchbare Korpus ist eine einzige vorberechnete JSON-Datei. Schnell, günstig, aber nicht skalierbar über ein paar hundert Seiten hinaus.

---
layout: null         # Kritisch: Ohne dies würde JSON in HTML eingebettet
---
[
  {% for doc in site.docs %}
    {
      "title": "{{ doc.title | escape }}",
      "category": "{{ doc.category }}",
      "tags": "{{ doc.tags | join: ', ' }}",
      "url": "{{ site.baseurl }}{{ doc.url }}",
      "date": "{{ doc.date }}"
    } {% unless forloop.last %},{% endunless %}
  {% endfor %}
]

layout: null: Ohne dies umschließt Jekyll das JSON mit dem HTML-Template der Seite (Kopfzeile, Navigation, Fußzeile) – was ungültiges JSON erzeugt. Das null-Layout gibt rohen Inhalt aus.

{% unless forloop.last %},{% endunless %}: Fügt Kommas zwischen Array-Elementen ein, aber NICHT nach dem letzten Element. Ein abschließendes Komma würde ungültiges JSON erzeugen. Liquid hat keinen eingebauten „generiere gültiges JSON“-Filter – diese manuelle Komma-Steuerung ist notwendig.

Einschränkungen: Nur die site.docs-Sammlung wird indiziert – Blogbeiträge, FAQs und Änderungsprotokolle sind NICHT durchsuchbar. Nur Titel-/Tag-Übereinstimmung – keine Volltextsuche im Dokumentinhalt. Alle Metadaten werden beim ersten Suchvorgang in den Browser geladen – nicht skalierbar auf tausende Seiten.
