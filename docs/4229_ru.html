Как работает статический поиск — архитектура Jekyll+TipueSearch

Этот файл НЕ является статическим JSON-файлом — это шаблон Jekyll, обрабатываемый во время сборки. Рабочий процесс:

  1. Время сборки: Jekyll обрабатывает {% for doc in site.docs %} — перебирает каждый документ в коллекции _docs/ (installation.adoc, userguide.adoc, development.adoc и т.д.) — и генерирует статический файл search.json в выходной директории.
  2. Время выполнения: Когда пользователь вводит текст в поле поиска на /search/ (#4093), jQuery-плагин Tipue Search загружает /search.json, фильтрует записи на стороне клиента и отображает результаты — без сервера, базы данных или API.

Это статический поиск по сайту — весь корпус для поиска представляет собой один предварительно вычисленный JSON-файл. Быстро, дёшево, но не масштабируется за пределы нескольких сотен страниц.

---
layout: null         # Критически важно: без этого JSON был бы обёрнут в HTML
---
[
  {% for doc in site.docs %}
    {
      "title": "{{ doc.title | escape }}",
      "category": "{{ doc.category }}",
      "tags": "{{ doc.tags | join: ', ' }}",
      "url": "{{ site.baseurl }}{{ doc.url }}",
      "date": "{{ doc.date }}"
    } {% unless forloop.last %},{% endunless %}
  {% endfor %}
]

layout: null: Без этого Jekyll оборачивает JSON в HTML-шаблон сайта (шапка, навигация, подвал) — создавая невалидный JSON. Макет null выводит сырой контент.

{% unless forloop.last %},{% endunless %}: Добавляет запятые между элементами массива, но НЕ после последнего элемента. Завершающая запятая привела бы к невалидному JSON. В Liquid нет встроенного фильтра «сгенерировать валидный JSON» — необходимо ручное управление запятыми.

Ограничения: Индексируется только коллекция site.docs — записи блога, FAQ и журналы изменений НЕ доступны для поиска. Только сопоставление по заголовку/тегам — без полнотекстового поиска по содержимому документов. Все метаданные загружаются в браузер при первом поиске — не масштабируется на тысячи страниц.
