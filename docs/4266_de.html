#4266: startProjectForge.sh

site/uploads/startProjectForge.sh

Pfad: site/uploads/startProjectForge.sh · Zeilen: 22 · Shebang: #!/bin/bash

Zweck: Produktions-Startskript – erkennt Java-Installation plattformübergreifend (Cygwin/Linux/macOS), weist 4 GB Heap zu, startet ProjectForge als nohup-Hintergrunddienst mit kompletter Ausgabeumleitung nach /dev/null.

Syntaxfehler in Zeile 3: Fehlendes öffnendes Anführungszeichen — PF_JAR=${HOME}/application/...". Die korrekte Zeile sollte PF_JAR="${HOME}/application/projectforge-application-xxx.jar" lauten. Das Skript wird so nicht analysiert werden können.

Dreistufige Java-Erkennung

if [ "${OSTYPE}" == 'cygwin' ]; then
  JAVA=`cygpath "${JAVA_HOME}"`/jre/bin/java     # Windows via Cygwin
else
  if [[ -n "$JAVA_HOME" ]] && [[ -x "$JAVA_HOME/bin/java" ]]; then
    JAVA="$JAVA_HOME/bin/java"                      # Linux/macOS mit JAVA_HOME
  else
    JAVA=/usr/bin/java                              # Fallback: System-Java
  fi
fi

Stufe 1 – Cygwin: Wandelt Windows-Pfad (C:\Program Files\Java\jdk17) in Unix-Stil (/cygdrive/c/Program Files/Java/jdk17) mittels cygpath um.

Stufe 2 – JAVA_HOME: Prüft, ob $JAVA_HOME/bin/java existiert UND ausführbar ist (-x). Beide Bedingungen müssen erfüllt sein.

Stufe 3 – Systemstandard: /usr/bin/java – funktioniert auf den meisten Linux-Distributionen, könnte aber eine ältere Version oder ein Platzhalter sein, der zu alternatives weiterleitet.

Der Startbefehl – Zeile 22

nohup ${JAVA} -Xms4g -Xmx4g ${DEBUGOPTS} -jar $PF_JAR 2>&1 > /dev/null &
KomponenteWirkung
nohupIgnoriert SIGHUP – Prozess überlebt Terminal-Abmeldung
-Xms4g -Xmx4g4 GB Heap, min=max. Vermeidet GC-Pausen durch Heap-Größenänderung. Angemessen für Produktion, überdimensioniert für Entwicklung.
${DEBUGOPTS}Standardmäßig leer (Zeile 20). Ändern zu -agentlib:jdwp=transport=dt_socket,server=y,suspend=n,address=5005 für Remote-Debugging.
2>&1 > /dev/nullLeitet stderr→stdout um, dann stdout→/dev/null. Sämtliche Konsolenausgabe verworfen. ProjectForge protokolliert in ~/ProjectForge/logs/ProjectForge.log via Logback – nicht betroffen.
&Hintergrund – Skript kehrt sofort zurück, wartet nicht auf den Start.

Wichtige Erkenntnisse

  • Syntaxfehler beheben: Zeile 3 fehlt ein öffnendes Anführungszeichen. Das Skript wird nicht ausgeführt.
  • xxx-Platzhalter: projectforge-application-xxx.jar – xxx vor Verwendung durch die tatsächliche Version ersetzen.
  • Keine Startprüfung: Skript überprüft nicht, ob ProjectForge tatsächlich gestartet wurde. Nach dem Ausführen immer ~/ProjectForge/logs/ProjectForge.log prüfen.
  • Nicht für Docker: Docker-Benutzer sollten stattdessen docker start/stop projectforge verwenden.
