Erreur de syntaxe à la ligne 3 : Guillemet ouvrant manquant — PF_JAR=${HOME}/application/...". La ligne correcte devrait être PF_JAR="${HOME}/application/projectforge-application-xxx.jar". Le script tel quel échouera à l'analyse.

Détection Java à trois niveaux

if [ "${OSTYPE}" == 'cygwin' ]; then
  JAVA=`cygpath "${JAVA_HOME}"`/jre/bin/java     # Windows via Cygwin
else
  if [[ -n "$JAVA_HOME" ]] && [[ -x "$JAVA_HOME/bin/java" ]]; then
    JAVA="$JAVA_HOME/bin/java"                      # Linux/macOS avec JAVA_HOME
  else
    JAVA=/usr/bin/java                              # Repli : Java système
  fi
fi

Niveau 1 — Cygwin : Convertit le chemin Windows (C:\Program Files\Java\jdk17) au style Unix (/cygdrive/c/Program Files/Java/jdk17) en utilisant cygpath.

Niveau 2 — JAVA_HOME : Vérifie que $JAVA_HOME/bin/java existe ET est exécutable (-x). Les deux conditions doivent être remplies.

Niveau 3 — Par défaut système : /usr/bin/java — fonctionne sur la plupart des distributions Linux mais peut être une version plus ancienne ou un stub qui redirige vers alternatives.

La commande de lancement — ligne 22

nohup ${JAVA} -Xms4g -Xmx4g ${DEBUGOPTS} -jar $PF_JAR 2>&1 > /dev/null &
ComposantEffet
nohupIgnore SIGHUP — le processus survit à la déconnexion du terminal
-Xms4g -Xmx4gHeap de 4 Go, min=max. Évite les pauses GC dues au redimensionnement du heap. Approprié pour la production, excessif pour le développement.
${DEBUGOPTS}Vide par défaut (ligne 20). Remplacez par -agentlib:jdwp=transport=dt_socket,server=y,suspend=n,address=5005 pour le débogage à distance.
2>&1 > /dev/nullRedirige stderr→stdout, puis stdout→/dev/null. TOUTE la sortie console est supprimée. ProjectForge journalise dans ~/ProjectForge/logs/ProjectForge.log via Logback — non affecté.
&Arrière-plan — le script retourne immédiatement, n'attend pas le démarrage.

Points clés à retenir

  • Corrigez l'erreur de syntaxe : La ligne 3 manque d'un guillemet ouvrant. Le script ne s'exécutera pas.
  • Espace réservé xxx : projectforge-application-xxx.jar — remplacez xxx par la version réelle avant utilisation.
  • Aucune vérification de démarrage : Le script ne vérifie pas que ProjectForge a réellement démarré. Vérifiez toujours ~/ProjectForge/logs/ProjectForge.log après l'exécution.
  • Pas pour Docker : Les utilisateurs de Docker doivent utiliser docker start/stop projectforge à la place.
