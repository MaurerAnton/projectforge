Двухфазный протокол остановки

Скрипт идентифицирует Java-процесс ProjectForge через pgrep -f "java.*projectforge-application" (поиск по шаблону в командной строке JVM), затем выполняет:

  1. Фаза 1 — Штатная (60 секунд): kill $pid отправляет SIGTERM (сигнал 15). JVM перехватывает его и запускает колбэки жизненного цикла Spring @PreDestroy — Hibernate сбрасывает кеши, пулы соединений закрываются, задачи Quartz останавливаются, Tomcat выключается. Скрипт делает 20 циклов × 3 секунды, проверяя, завершился ли процесс.
  2. Фаза 2 — Принудительная: Если процесс всё ещё жив через 60 с, kill -9 $pid отправляет SIGKILL (сигнал 9) — не перехватывается, мгновенное завершение. Без очистки: соединения с БД остаются брошенными, индексы Lucene могут быть повреждены, буферы логов теряются. Скрипт ждёт 2 секунды и проверяет снова.

Этот двухфазный подход предотвращает самую частую проблему продакшена: утечки соединений с БД от убитых Java-процессов. Окно в 60 секунд щедрое — большинство Spring Boot приложений выключаются за 5–15 секунд.

Анализ скрипта — ключевые строки

checkStopped() {
  pid=$(pgrep -f $PROCESS_IDENTIFIER)      # Повторная проверка существования процесса
  if [[ -z $pid ]]; then                     # Если PID не найден
    echo "${APP_NAME} $1"                    # Вывод сообщения об успехе
    exit 0                                   # Немедленный выход
  fi
  if [[ -n $2 ]]; then                       # Если передан второй аргумент (режим предупреждения)
    echo "${APP_NAME} $2"                    # Вывод предупреждения, но продолжение
  fi
}

Двухрежимная функция: checkStopped служит двум целям в зависимости от количества аргументов — с 1 аргументом это «проверка успеха» (выход, если остановлен), с 2 аргументами это «отчёт о статусе» (вывод и продолжение).

Ошибка области видимости переменной: $pid устанавливается внутри функции (строка 7), но используется снаружи в строке 20 — это работает, потому что pid не объявлен как local, и поэтому просачивается в область видимости вызывающего кода. Хрупко — если между проверками появится второй подходящий процесс, будет убит только первый PID.

Ключевые выводы

  • Всегда предпочитайте этот скрипт kill -9: Штатное завершение сохраняет целостность базы данных и предотвращает утечки соединений.
  • Спрятан в uploads/: Находится в site/uploads/ — вложениях файлов сайта Jekyll — необычное место для эксплуатационных инструментов.
  • Нет PID-файла: Идентифицирует процесс по шаблону командной строки, а не по PID-файлу. Более устойчив при перезапусках, но не срабатывает, если совпадают два экземпляра ProjectForge.
  • Требуется pgrep: Часть пакета procps-ng — недоступен в минимальных Docker-образах.
