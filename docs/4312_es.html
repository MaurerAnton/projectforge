Artefacto histórico. Esta herramienta fue escrita durante la migración de ProjectForge 6.x (monolito en projectforge-webapp/src/main/java) a 7.x (multimódulo: projectforge-business/, projectforge-wicket/, projectforge-rest/, plugins/*/). Verificó que todas las clases se movieran correctamente a sus nuevos hogares de módulo. Las rutas hardcodeadas hacen referencia a la máquina de un desarrollador (/Users/blumenstein/), lo que la hace no portable.

Cómo funciona — el algoritmo de comparación

La herramienta construye dos mapas HashMap<String, String> (nombre de archivo → ruta de paquete) recorriendo recursivamente los árboles fuente de Java:

  1. Escaneo de estructura antigua: Recorre projectforge-webapp/src/main/java (el monolito previo a la migración), extrae cada archivo .java, almacena className → packagePath
  2. Escaneo de estructura nueva: Recorre TRES árboles separados: projectforge-business/src/main/java, projectforge-wicket/src/main/java y 9 directorios de plugins bajo plugins/<nombre>/src/main/java. Todos los resultados van a un único mapa newStructure.
  3. Comparación: Para cada clase antigua, verifica si existe en el mapa nuevo con (a) el mismo paquete → éxito, (b) un paquete diferente → informa el cambio en formato clave=valor, (c) no encontrada → informa como faltante. Luego verifica clases nuevas no presentes en las antiguas → informa como adiciones.

Limitación crítica: Usar el nombre de archivo (sin paquete) como clave del mapa significa que dos clases con el mismo nombre en diferentes paquetes colisionan. Gana la última escaneada. En la práctica, ProjectForge evita nombres de clase duplicados entre paquetes, pero esto es un defecto de diseño.

write() (líneas 98-112): Recorredor recursivo de árbol de archivos. Omite .DS_Store (metadatos de macOS), se sumerge en directorios y para archivos .java extrae el nombre de clase (eliminando la extensión .java) y el paquete (convirtiendo la ruta del sistema de archivos /org/projectforge/business/address/ → org.projectforge.business.address). Usa parent.list() sin verificación nula — NPE si el directorio no existe.

writePropertiesFile() (líneas 74-96): Nombre engañoso — imprime en stdout, no escribe un archivo. El formato de salida es paqueteAntiguo=paqueteNuevo (como formato .properties), destinado a scripts de refactorización automatizados. Los mensajes de consola están en alemán ("Klasse in new structure not found") — herramienta interna para el equipo de habla alemana.

Conclusiones clave

  • No ejecutar: Las rutas absolutas hardcodeadas hacen que esta herramienta no sea portable. Se conserva como referencia histórica.
  • Solo Java: Solo escanea archivos .java (línea 13). Los archivos Kotlin .kt se ignoran — una brecha significativa para la base de código moderna.
  • Salida en alemán: Mensajes de consola en alemán — refleja la cultura de desarrollo interna de Micromata.
