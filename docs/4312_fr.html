Artefact historique. Cet outil a été écrit lors de la migration de ProjectForge 6.x (monolithe dans projectforge-webapp/src/main/java) vers 7.x (multi-module : projectforge-business/, projectforge-wicket/, projectforge-rest/, plugins/*/). Il vérifiait que toutes les classes avaient été correctement déplacées vers leurs nouveaux modules. Les chemins codés en dur référencent la machine d'un développeur (/Users/blumenstein/), ce qui le rend non portable.

Fonctionnement — l'algorithme de comparaison

L'outil construit deux tables HashMap<String, String> (nom de fichier → chemin du package) en parcourant récursivement les arborescences source Java :

  1. Analyse de l'ancienne structure : Parcourt projectforge-webapp/src/main/java (le monolithe pré-migration), extrait chaque fichier .java, stocke className → packagePath
  2. Analyse de la nouvelle structure : Parcourt TROIS arborescences distinctes : projectforge-business/src/main/java, projectforge-wicket/src/main/java, et 9 répertoires de plugins sous plugins/<nom>/src/main/java. Tous les résultats sont stockés dans une seule table newStructure.
  3. Comparaison : Pour chaque ancienne classe, vérifie si elle existe dans la nouvelle table avec (a) le même package → succès, (b) un package différent → signale le changement au format clé=valeur, (c) non trouvée → signalée comme manquante. Ensuite, vérifie les nouvelles classes absentes de l'ancienne structure → signalées comme ajouts.

Limitation critique : L'utilisation du nom de fichier (sans le package) comme clé de la table signifie que deux classes de même nom dans des packages différents entrent en collision. La dernière analysée l'emporte. En pratique, ProjectForge évite les noms de classe en double entre packages, mais c'est une faille de conception.

write() (lignes 98-112) : Parcours récursif d'arborescence de fichiers. Ignore .DS_Store (métadonnées macOS), plonge dans les répertoires, et pour les fichiers .java extrait le nom de la classe (en supprimant l'extension .java) et le package (en convertissant le chemin du système de fichiers /org/projectforge/business/address/ → org.projectforge.business.address). Utilise parent.list() sans vérification null — NPE si le répertoire n'existe pas.

writePropertiesFile() (lignes 74-96) : Nom trompeur — imprime sur la sortie standard, n'écrit pas de fichier. Le format de sortie est ancienPackage=nouveauPackage (comme le format .properties), destiné aux scripts de refactoring automatisés. Les messages console sont en allemand ("Klasse in new structure not found") — outil interne pour une équipe germanophone.

Points clés à retenir

  • Ne pas exécuter : Les chemins absolus codés en dur rendent cet outil non portable. Il est conservé à titre de référence historique.
  • Java uniquement : Analyse uniquement les fichiers .java (ligne 13). Les fichiers Kotlin .kt sont ignorés — une lacune importante pour la base de code moderne.
  • Sortie en allemand : Messages console en allemand — reflète la culture de développement interne de Micromata.
  • 9 plugins listés : Skillmatrix, Banking, CRM, LicenseManagement, LiquidityPlanning, Marketing, Memo, Poll, TODO. Vérifiez cette liste par rapport au répertoire actuel plugins/.
