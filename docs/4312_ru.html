Исторический артефакт. Этот инструмент был написан во время миграции с ProjectForge 6.x (монолит в projectforge-webapp/src/main/java) на 7.x (многомодульная структура: projectforge-business/, projectforge-wicket/, projectforge-rest/, plugins/*/). Он проверял, что все классы были корректно перемещены в свои новые модульные дома. Жёстко прописанные пути ссылаются на машину разработчика (/Users/blumenstein/), что делает его непереносимым.

Как это работает — алгоритм сравнения

Инструмент строит две карты HashMap<String, String> (имя файла → путь пакета) путём рекурсивного обхода деревьев исходных Java-файлов:

  1. Сканирование старой структуры: Обходит projectforge-webapp/src/main/java (монолит до миграции), извлекает каждый .java файл, сохраняет className → packagePath
  2. Сканирование новой структуры: Обходит ТРИ отдельных дерева: projectforge-business/src/main/java, projectforge-wicket/src/main/java и 9 директорий плагинов в plugins/<имя>/src/main/java. Все результаты попадают в единую карту newStructure.
  3. Сравнение: Для каждого старого класса проверяется, существует ли он в новой карте: (а) с тем же пакетом → успех, (б) с другим пакетом → сообщается об изменении в формате ключ=значение, (в) не найден → сообщается как потерянный. Затем проверяются новые классы, отсутствующие в старой структуре → сообщается как добавленные.

Критическое ограничение: Использование имени файла (без пакета) в качестве ключа карты означает, что два одноимённых класса в разных пакетах конфликтуют. Побеждает последний просканированный. На практике ProjectForge избегает дублирования имён классов в разных пакетах, но это является недостатком проектирования.

9 плагинов, которые были извлечены из монолита в независимые подмодули Gradle. Этот список может быть устаревшим — плагины могли быть добавлены/удалены после рефакторинга.

write() (строки 98-112): Рекурсивный обход дерева файлов. Пропускает .DS_Store (метаданные macOS), заходит в директории и для .java файлов извлекает имя класса (удаляя расширение .java) и пакет (преобразуя путь файловой системы /org/projectforge/business/address/ → org.projectforge.business.address). Использует parent.list() без проверки на null — NPE, если директория не существует.

writePropertiesFile() (строки 74-96): Вводящее в заблуждение название — выводит в stdout, а не записывает файл. Формат вывода: oldPackage=NewPackage (как формат .properties), предназначен для автоматизированных скриптов рефакторинга. Сообщения в консоли на немецком ("Klasse in new structure not found") — внутренний инструмент для немецкоязычной команды.

Ключевые выводы

  • Не запускать: Жёстко прописанные абсолютные пути делают этот инструмент непереносимым. Он сохранён для исторической справки.
  • Только Java: Сканирует только .java файлы (строка 13). Файлы Kotlin .kt игнорируются — существенный пробел для современной кодовой базы.
  • Вывод на немецком: Сообщения в консоли на немецком языке — отражает внутреннюю культуру разработки Micromata.
