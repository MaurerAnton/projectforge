Les 11 lignes qui contrôlent tout

@Configuration
@ComponentScan({ "org.projectforge", "de.micromata.mgc.jpa.spring" })
public class SchemaExpContext { }

Bien qu'il ne comporte que 11 lignes, ce fichier est sans doute le plus critique de l'outil SchemaExp. Son @ComponentScan détermine quels beans Spring sont découverts et disponibles :

PaquetageCe qu'il apporte
org.projectforgeTous les composants ProjectForge — SchemaExpService (#4104), XmlDump, ConfigurationDao, PfEmgrFactory, tous les DAO, tous les DO, toutes les pages Wicket, tous les contrôleurs REST. Des milliers de beans.
de.micromata.mgc.jpa.springFramework Genome JPA — JpaXmlDumpService, JpaSchemaService, gestion des transactions, configuration EntityManagerFactory. La dépendance critique pour le dump/restauration XML.

Problème de portée : Le scan "org.projectforge" est excessivement large — il découvre toutes les pages Wicket, les contrôleurs REST, les planificateurs Quartz, les services email et les filtres de sécurité. La plupart ne sont jamais utilisés par l'outil SchemaExp mais sont instanciés quand même. Cela explique pourquoi l'outil nécessite une connexion à la base de données même pour les opérations d'exportation (les DAO ont besoin d'une base de données pour l'initialisation). Un scan plus restreint réduirait le temps de démarrage et les dépendances.
