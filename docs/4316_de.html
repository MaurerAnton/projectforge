Unterschiede zur Hauptanwendung

Im Gegensatz zur Hauptanwendung ProjectForge, die Spring Boot verwendet (SpringApplication.run(ProjectForgeApplication.class, args)), startet dieses Tool manuell einen einfachen Spring-Kontext:

ApplicationContext context = new AnnotationConfigApplicationContext(SchemaExpContext.class);
TenantRegistryMap.getInstance().setApplicationContext(context);
DatabaseSupport.setInstance(new DatabaseSupport(HibernateUtils.getDialect()));

Drei manuelle Bootstrap-Schritte ersetzen das, was Spring Boot automatisch erledigt: Kontexterstellung, Registrierung der Mandantenverwaltung und Einrichtung des Hibernate-Dialekts. Dies verleiht dem Tool einen minimalen Fußabdruck – kein eingebetteter Tomcat, kein Spring Security, kein Quartz-Scheduler.

CLI-Argument-Parsing

Das Tool akzeptiert Optionen, gefolgt von einem einzelnen Dateiargument. Unterstützte Flags:

FlagWirkung
-expExportvorgang → SchemaExpService.doExport()
-impImportvorgang → SchemaExpService.doImport()
-cleardbAlle Tabellen vor dem Import löschen (oder eigenständiges Löschen)
-insertnewRestoreMode.InsertNew – vorhandene Datensätze überspringen
-overwriteRestoreMode.OverWrite – vorhandene Datensätze aktualisieren
-insertallRestoreMode.InsertAll – alles einfügen (Standard)

Der Optionsparser (parseOption(), Zeilen 40-65) verwendet StringUtils.equalsIgnoreCase() für eine Groß-/Kleinschreibung-unabhängige Prüfung. Positionsoptionen – Flags müssen vor dem Dateiargument kommen. Die while (parseOption(args, pos++))-Schleife (Zeile 78) iteriert, bis sie auf eine Nicht-Option trifft, dann rückt --pos zurück, um auf das erste Nicht-Option-Argument (den Dateinamen) zu zeigen.

Bekannte Probleme

  • Tippfehler: initApplicatinContext (Zeile 122) – das 'o' in "Application" fehlt. Der Tippfehler existiert sowohl im Methodennamen als auch an der Aufrufstelle (Zeile 73).
  • Toter Code: Der catch (IllegalArgumentException)-Block in Zeile 82 wird nie ausgeführt – parseOption() wirft diese Ausnahme nie.
  • restoreMode == null (Zeilen 95-98) prüft auf null, aber restoreMode wird mit RestoreMode.InsertAll initialisiert (Zeile 36) und nie auf null gesetzt. Diese Prüfung kann nie zuschlagen.
  • Keine Exit-Codes: Das Programm beendet sich immer mit Code 0, selbst bei Ausnahmen. Skripting in CI erfordert stdout/stderr-Parsing.
  • Breiter Komponenten-Scan: @ComponentScan({"org.projectforge", ...}) (in SchemaExpContext) bringt Tausende von Beans mit – weit mehr als nötig. Der Kontextstart kann langsam sein.
