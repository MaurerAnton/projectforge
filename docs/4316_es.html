Cómo difiere de la aplicación principal

A diferencia de la aplicación principal de ProjectForge que utiliza Spring Boot (SpringApplication.run(ProjectForgeApplication.class, args)), esta herramienta inicia manualmente un contexto Spring simple:

ApplicationContext context = new AnnotationConfigApplicationContext(SchemaExpContext.class);
TenantRegistryMap.getInstance().setApplicationContext(context);
DatabaseSupport.setInstance(new DatabaseSupport(HibernateUtils.getDialect()));

Tres pasos de arranque manual reemplazan lo que Spring Boot hace automáticamente: creación del contexto, registro del registro de inquilinos y configuración del dialecto Hibernate. Esto le da a la herramienta una huella mínima — sin Tomcat embebido, sin Spring Security, sin programador Quartz.

Análisis de argumentos CLI

La herramienta acepta opciones seguidas de un único argumento de archivo. Banderas soportadas:

BanderaEfecto
-expOperación de exportación → SchemaExpService.doExport()
-impOperación de importación → SchemaExpService.doImport()
-cleardbEliminar todas las tablas antes de importar (o limpieza independiente)
-insertnewRestoreMode.InsertNew — omitir registros existentes
-overwriteRestoreMode.OverWrite — actualizar registros existentes
-insertallRestoreMode.InsertAll — insertar todo (predeterminado)

El analizador de opciones (parseOption(), líneas 40-65) utiliza StringUtils.equalsIgnoreCase() para coincidencia sin distinción de mayúsculas/minúsculas. Opciones posicionales — las banderas deben ir antes del argumento de archivo. El bucle while (parseOption(args, pos++)) (línea 78) itera hasta que encuentra una no-opción, luego --pos retrocede para apuntar al primer argumento no-opción (el nombre del archivo).

Problemas conocidos

  • Error tipográfico: initApplicatinContext (línea 122) — falta la 'o' en "Application". El error tipográfico existe tanto en el nombre del método como en su sitio de llamada (línea 73).
  • Código muerto: El bloque catch (IllegalArgumentException) en la línea 82 nunca se ejecuta — parseOption() nunca lanza esta excepción.
  • Verificación muerta: Las líneas 95-98 verifican restoreMode == null pero restoreMode se inicializa a RestoreMode.InsertAll (línea 36) y nunca se establece a null. Esta verificación nunca puede activarse.
  • Sin códigos de salida: El programa siempre sale con código 0, incluso en excepciones. El scripting en CI requiere análisis de stdout/stderr.
  • Escaneo de componentes amplio: @ComponentScan({"org.projectforge", ...}) (en SchemaExpContext) trae miles de beans — mucho más de lo necesario. El inicio del contexto puede ser lento.
