Чем отличается от основного приложения

В отличие от основного приложения ProjectForge, которое использует Spring Boot (SpringApplication.run(ProjectForgeApplication.class, args)), этот инструмент вручную загружает простой контекст Spring:

ApplicationContext context = new AnnotationConfigApplicationContext(SchemaExpContext.class);
TenantRegistryMap.getInstance().setApplicationContext(context);
DatabaseSupport.setInstance(new DatabaseSupport(HibernateUtils.getDialect()));

Три ручных шага загрузки заменяют то, что Spring Boot делает автоматически: создание контекста, регистрация реестра арендаторов и настройка диалекта Hibernate. Это обеспечивает минимальную нагрузку инструмента — никакого встроенного Tomcat, Spring Security или планировщика Quartz.

Разбор аргументов CLI

Инструмент принимает опции, за которыми следует один аргумент — имя файла. Поддерживаемые флаги:

ФлагДействие
-expОперация экспорта → SchemaExpService.doExport()
-impОперация импорта → SchemaExpService.doImport()
-cleardbУдалить все таблицы перед импортом (или автономная очистка)
-insertnewRestoreMode.InsertNew — пропускать существующие записи
-overwriteRestoreMode.OverWrite — обновлять существующие записи
-insertallRestoreMode.InsertAll — вставлять всё (по умолчанию)

Парсер опций (parseOption(), строки 40-65) использует StringUtils.equalsIgnoreCase() для регистронезависимого сравнения. Позиционные опции — флаги должны располагаться перед аргументом файла. Цикл while (parseOption(args, pos++)) (строка 78) выполняется до тех пор, пока не встретит не-опцию, затем --pos возвращается назад, чтобы указать на первый не-опционный аргумент (имя файла).

Известные проблемы

  • Опечатка: initApplicatinContext (строка 122) — пропущена буква 'o' в "Application". Опечатка присутствует как в имени метода, так и в месте его вызова (строка 73).
  • Мёртвый код: Блок catch (IllegalArgumentException) в строке 82 никогда не выполняется — parseOption() никогда не выбрасывает это исключение.
  • Мёртвая проверка: Строки 95-98 проверяют restoreMode == null, но restoreMode инициализируется значением RestoreMode.InsertAll (строка 36) и никогда не устанавливается в null. Эта проверка никогда не сработает.
  • Отсутствие кодов возврата: Программа всегда завершается с кодом 0, даже при исключениях. Для автоматизации в CI требуется парсинг stdout/stderr.
  • Широкое сканирование компонентов: @ComponentScan({"org.projectforge", ...}) (в SchemaExpContext) подключает тысячи бинов — гораздо больше, чем необходимо. Запуск контекста может быть медленным.
