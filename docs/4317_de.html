Architektur: Dual-Engine-Importsystem

Das bemerkenswerteste architektonische Merkmal der Klasse ist ihr Dual-Engine-Importsystem, gesteuert durch useJpaXmlDumpService = true (Zeile 47):

EngineFlagBibliothekFunktionen
Genome JPAtrue (Standard)de.micromata.genome.db.jpa.xmldumpJPA-bewusstes Parsen, Auflösung von Entitätstypen, Beziehungshandhabung, RestoreMode-Unterstützung (InsertNew/OverWrite/InsertAll), Primärschlüsselzuweisung über Sequenzgeneratoren
Legacy XStreamfalseThoughtWorks XStream via XmlDumpRohe XStream-Serialisierung, manuelle Verifizierung via verifyDump(), Integritätsprüfungen nach dem Import via ConfigurationDao

Die Genome-Engine wird bevorzugt, da sie JPA-Entitätsmetadaten versteht — sie behandelt korrekt @OneToMany-Kaskaden, @Inheritance-Strategien und Fremdschlüsselbeziehungen während des Imports. Die Legacy-Engine wird aus Gründen der Abwärtskompatibilität beibehalten.

Wichtige Methoden

clearDb() (Zeilen 49-52): Ruft emfac.getJpaSchemaService().clearDatabase() auf — löscht alle Tabellen in umgekehrter Abhängigkeitsreihenfolge. Dies ist eine destruktive Operation ohne Rückgängigmachung. Wird sowohl eigenständig (-cleardb-Flag) als auch als Voraussetzung für Importe (-cleardb -imp) verwendet.

doImport(boolean clearDb, String clientFileName, RestoreMode modus) (Zeilen 54-87): Die Hauptimport-Pipeline: (1) optional die Datenbank bereinigen, (2) Dateiexistenz validieren, (3) Dateiformat erkennen (.xml vs. .xml.gz) und ggf. dekomprimieren, (4) an die ausgewählte Engine delegieren, (5) Bereinigung im finally-Block durchführen. Der RestoreMode-Enum steuert die Konfliktlösung: InsertNew überspringt vorhandene Datensätze, OverWrite aktualisiert sie, InsertAll fügt alles ein (schlägt bei Duplikaten fehl).

doExport(String fileName) (Zeilen 89-94): Delegiert an jpaXmlDumpService.dumpToXml(emfac, file). Anders als beim Import verwendet der Export immer die Genome-Bibliothek — es gibt keinen Legacy-XStream-Exportpfad. Fragt alle Entitätstypen aus JPA-Metadaten ab, lädt alle Datensätze (vollständige Tabellenscans) und serialisiert sie mit JPA-bewusstem Marshalling nach XML.

Anmerkungen zur Codequalität

  • Unbenutztes Feld: TransactionTemplate txTemplate (Zeile 32) wird injiziert, aber nie verwendet — toter Code.
  • Veraltete API: IOUtils.closeQuietly() (Zeile 84) ist in Apache Commons IO 2.7+ veraltet. Sollte try-with-resources verwenden.
  • Tippfehler in der Elternklasse: SchemaExpMain.initApplicatinContext() (fehlendes 'o' in "Application") wird von allen Tests aufgerufen.
  • Hartcodiertes Flag: useJpaXmlDumpService = true sollte idealerweise eine Spring-@Value-Eigenschaft für die Laufzeitkonfiguration sein.
  • Keine Exportkomprimierung: Der Exportpfad gzippt die Ausgabe nicht. Für Produktions-Dumps nach dem Export manuell gzippen.
