Architecture : Système d'import à double moteur

La caractéristique architecturale la plus notable de cette classe est son système d'import à double moteur, contrôlé par useJpaXmlDumpService = true (ligne 47) :

MoteurDrapeauBibliothèqueFonctionnalités
Genome JPAtrue (par défaut)de.micromata.genome.db.jpa.xmldumpAnalyse compatible JPA, résolution des types d'entités, gestion des relations, prise en charge de RestoreMode (InsertNew/OverWrite/InsertAll), allocation de clés primaires via générateurs de séquences
XStream héritéfalseThoughtWorks XStream via XmlDumpSérialisation XStream brute, vérification manuelle via verifyDump(), contrôles d'intégrité post-import via ConfigurationDao

Le moteur Genome est préféré car il comprend les métadonnées des entités JPA — il gère correctement les cascades @OneToMany, les stratégies @Inheritance et les relations de clés étrangères lors de l'import. Le moteur hérité est conservé pour la rétrocompatibilité.

Méthodes clés

clearDb() (lignes 49-52) : Appelle emfac.getJpaSchemaService().clearDatabase() — supprime toutes les tables dans l'ordre inverse des dépendances. C'est une opération destructive sans annulation. Utilisé à la fois de manière autonome (drapeau -cleardb) et comme prérequis pour les imports (-cleardb -imp).

doImport(boolean clearDb, String clientFileName, RestoreMode modus) (lignes 54-87) : Le pipeline d'import principal : (1) nettoyage optionnel de la base de données, (2) validation de l'existence du fichier, (3) détection du format de fichier (.xml vs .xml.gz) et décompression si nécessaire, (4) délégation au moteur sélectionné, (5) gestion du nettoyage dans le bloc finally. L'énumération RestoreMode contrôle la résolution des conflits : InsertNew ignore les enregistrements existants, OverWrite les met à jour, InsertAll insère tout (échoue en cas de doublons).

doExport(String fileName) (lignes 89-94) : Délègue à jpaXmlDumpService.dumpToXml(emfac, file). Contrairement à l'import, l'export utilise toujours la bibliothèque Genome — il n'y a pas de chemin d'export XStream hérité. Interroge tous les types d'entités à partir des métadonnées JPA, charge tous les enregistrements (analyses complètes de table) et sérialise en XML avec un marshalling compatible JPA.

Notes sur la qualité du code

  • Champ inutilisé : TransactionTemplate txTemplate (ligne 32) est injecté mais jamais utilisé — code mort.
  • API obsolète : IOUtils.closeQuietly() (ligne 84) est obsolète dans Apache Commons IO 2.7+. Devrait utiliser try-with-resources.
  • Faute de frappe dans la classe parente : SchemaExpMain.initApplicatinContext() ('o' manquant dans "Application") est appelé par tous les tests.
  • Drapeau codé en dur : useJpaXmlDumpService = true devrait idéalement être une propriété Spring @Value pour une configuration à l'exécution.
  • Pas de compression d'export : Le chemin d'export ne compresse pas la sortie en gzip. Pour les dumps de production, gzipper manuellement après l'export.
