Архитектура: Система импорта с двумя движками

Наиболее примечательная архитектурная особенность класса — это система импорта с двумя движками, управляемая флагом useJpaXmlDumpService = true (строка 47):

ДвижокФлагБиблиотекаВозможности
Genome JPAtrue (по умолчанию)de.micromata.genome.db.jpa.xmldumpРазбор с учётом JPA, разрешение типов сущностей, обработка связей, поддержка RestoreMode (InsertNew/OverWrite/InsertAll), выделение первичных ключей через генераторы последовательностей
Устаревший XStreamfalseThoughtWorks XStream через XmlDumpСырая сериализация XStream, ручная верификация через verifyDump(), проверки целостности после импорта через ConfigurationDao

Движок Genome предпочтительнее, так как он понимает метаданные сущностей JPA — он корректно обрабатывает каскады @OneToMany, стратегии @Inheritance и связи по внешним ключам во время импорта. Устаревший движок сохранён для обратной совместимости.

Ключевые методы

clearDb() (строки 49-52): Вызывает emfac.getJpaSchemaService().clearDatabase() — удаляет все таблицы в обратном порядке зависимостей. Это разрушительная операция без возможности отмены. Используется как отдельно (флаг -cleardb), так и в качестве предварительного условия для импорта (-cleardb -imp).

doImport(boolean clearDb, String clientFileName, RestoreMode modus) (строки 54-87): Основной конвейер импорта: (1) опционально очищает базу данных, (2) проверяет существование файла, (3) определяет формат файла (.xml или .xml.gz) и при необходимости распаковывает, (4) делегирует выбранному движку, (5) выполняет очистку в блоке finally. Перечисление RestoreMode управляет разрешением конфликтов: InsertNew пропускает существующие записи, OverWrite обновляет их, InsertAll вставляет всё (завершается ошибкой при дубликатах).

doExport(String fileName) (строки 89-94): Делегирует jpaXmlDumpService.dumpToXml(emfac, file). В отличие от импорта, экспорт всегда использует библиотеку Genome — устаревшего пути экспорта через XStream нет. Запрашивает все типы сущностей из метаданных JPA, загружает все записи (полное сканирование таблиц) и сериализует в XML с маршаллингом, учитывающим JPA.

Заметки о качестве кода

  • Неиспользуемое поле: TransactionTemplate txTemplate (строка 32) внедряется, но никогда не используется — мёртвый код.
  • Устаревший API: IOUtils.closeQuietly() (строка 84) помечен как устаревший в Apache Commons IO 2.7+. Следует использовать try-with-resources.
  • Опечатка в родительском классе: SchemaExpMain.initApplicatinContext() (пропущена буква 'o' в "Application") вызывается всеми тестами.
  • Жёстко заданный флаг: useJpaXmlDumpService = true в идеале должен быть свойством Spring @Value для конфигурации во время выполнения.
  • Отсутствие сжатия при экспорте: Путь экспорта не сжимает вывод в gzip. Для рабочих дампов следует вручную выполнять gzip после экспорта.
