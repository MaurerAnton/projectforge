ZERSTÖRERISCH: Verwendet -cleardb — löscht ALLE Tabellen vor dem Import. Nur gegen postgres2 ausführen, niemals gegen postgres.

Was es tut

Das Import-Gegenstück zu ToXmlTest. Erzwingt die postgres2-Datenquelle (eine separate, wegwerfbare PostgreSQL-Instanz) und ruft dann SchemaExpMain mit drei Flags auf: -imp (Import), -cleardb (alle Tabellen zuerst löschen) und -insertall (alle Entitäten aus XML einfügen). Der aktuelle Code importiert aus init-test-data-new.xml — der mit der Webapp verteilten, vorab generierten Testdatendatei. Eine ältere, auskommentierte Zeile zeigt denselben Test, der aus target/pf-dump.xml (der Ausgabe von ToXmlTest) importiert.

//  @Test
public void testImp() {
  System.getProperties().setProperty("projectForgeDs", "postgres2");
  //SchemaExpMain.main(new String[] { "-imp", "-cleardb", "-insertall", "target/pf-dump.xml" });
  SchemaExpMain.main(new String[] { "-imp", "-cleardb", "-insertall",
      "../../projectforge-webapp/src/main/resources/data/init-test-data-new.xml" });
}

Zeile 8: postgres2 — bewusst eine ANDERE Datenbank als das postgres des Export-Tests. Dies verhindert die versehentliche Zerstörung Ihrer primären Entwicklungsdatenbank.

Zeile 10: Der auskommentierte alternative Pfad dokumentiert den Export→Import-Workflow: Zuerst ToXmlTest ausführen, um pf-dump.xml zu generieren, dann diesen Test ausführen, um es zu importieren.

Zeilen 10-11: Importiert aus init-test-data-new.xml — der kanonischen Test-Startdatei. Wenn ein Benutzer während der ProjectForge-Einrichtung "Testsystem" auswählt, importiert der Assistent genau diese Datei, um die Datenbank mit Beispieldaten zu befüllen. Dieser Test validiert, dass die Import-Pipeline reale Seed-Daten korrekt verarbeitet.

Pfadnavigation: ../../projectforge-webapp/src/main/resources/data/ — navigiert von tools/org.projectforge.tools.schemaexp/ zwei Verzeichnisse hoch, dann in das Webapp-Modul. Anfälliger relativer Pfad — hängt vom Arbeitsverzeichnis ab, das das Wurzelverzeichnis des Werkzeugs sein muss.
