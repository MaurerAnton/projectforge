DESTRUCTEUR : Utilise -cleardb — supprime TOUTES les tables avant l'import. Exécuter uniquement sur postgres2, jamais sur postgres.

Ce qu'il fait

L'équivalent import de ToXmlTest. Force la source de données postgres2 (une instance PostgreSQL séparée et jetable), puis invoque SchemaExpMain avec trois indicateurs : -imp (import), -cleardb (supprimer toutes les tables d'abord), et -insertall (insérer toutes les entités depuis le XML). Le code actuel importe depuis init-test-data-new.xml — le fichier de données de test pré-généré distribué avec l'application web. Une ancienne ligne commentée montre le même test important depuis target/pf-dump.xml (la sortie de ToXmlTest).

//  @Test
public void testImp() {
  System.getProperties().setProperty("projectForgeDs", "postgres2");
  //SchemaExpMain.main(new String[] { "-imp", "-cleardb", "-insertall", "target/pf-dump.xml" });
  SchemaExpMain.main(new String[] { "-imp", "-cleardb", "-insertall",
      "../../projectforge-webapp/src/main/resources/data/init-test-data-new.xml" });
}

Ligne 8 : postgres2 — délibérément une base DIFFÉRENTE du postgres du test d'export. Cela évite de détruire accidentellement votre base de développement principale.

Ligne 10 : Le chemin alternatif commenté documente le flux de travail export→import : d'abord exécuter ToXmlTest pour générer pf-dump.xml, puis exécuter ce test pour l'importer.

Lignes 10-11 : Importe depuis init-test-data-new.xml — le fichier de seed de test canonique. Lorsqu'un utilisateur sélectionne « Système de test » lors de l'installation de ProjectForge, l'assistant importe ce fichier exact pour peupler la base avec des données d'exemple. Ce test valide que le pipeline d'import traite correctement les données de seed réelles.

Parcours de chemin : ../../projectforge-webapp/src/main/resources/data/ — navigue depuis tools/org.projectforge.tools.schemaexp/ vers le haut de deux répertoires, puis dans le module webapp. Chemin relatif fragile — dépend du répertoire de travail étant la racine de l'outil.
