Назначение: Утилита разработчика для импорта XML-дампа в чистую базу данных PostgreSQL. Использует postgres2 (вторичный экземпляр), чтобы избежать уничтожения основной базы данных разработки.

ДЕСТРУКТИВНО: Использует -cleardb — удаляет ВСЕ таблицы перед импортом. Запускать только против postgres2, никогда не против postgres.

Что это делает

Аналог импорта для ToXmlTest. Принудительно устанавливает источник данных postgres2 (отдельный, одноразовый экземпляр PostgreSQL), затем вызывает SchemaExpMain с тремя флагами: -imp (импорт), -cleardb (удалить все таблицы перед импортом) и -insertall (вставить все сущности из XML). Текущий код импортирует из init-test-data-new.xml — предварительно сгенерированного файла тестовых данных, распространяемого с веб-приложением. Старая закомментированная строка показывает тот же тест, импортирующий из target/pf-dump.xml (вывод ToXmlTest).

//  @Test
public void testImp() {
  System.getProperties().setProperty("projectForgeDs", "postgres2");
  //SchemaExpMain.main(new String[] { "-imp", "-cleardb", "-insertall", "target/pf-dump.xml" });
  SchemaExpMain.main(new String[] { "-imp", "-cleardb", "-insertall",
      "../../projectforge-webapp/src/main/resources/data/init-test-data-new.xml" });
}

Строка 8: postgres2 — намеренно ДРУГАЯ база данных, отличная от postgres из теста экспорта. Это предотвращает случайное уничтожение вашей основной базы данных разработки.

Строка 10: Закомментированный альтернативный путь документирует рабочий процесс экспорт→импорт: сначала запустите ToXmlTest для генерации pf-dump.xml, затем запустите этот тест для его импорта.

Строки 10-11: Импорт из init-test-data-new.xml — канонического файла начальных тестовых данных. Когда пользователь выбирает "Тестовая система" при настройке ProjectForge, мастер импортирует именно этот файл для заполнения базы данных примерами данных. Этот тест проверяет, что конвейер импорта корректно обрабатывает реальные начальные данные.

Обход пути: ../../projectforge-webapp/src/main/resources/data/ — переход из tools/org.projectforge.tools.schemaexp/ на два уровня вверх, затем в модуль веб-приложения. Хрупкий относительный путь — зависит от рабочей директории, которой является корень инструмента.
