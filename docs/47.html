Access flow

Is user in FINANCE_GROUP?
├─ NO  → denied
└─ YES → Is user an admin?
    ├─ YES → granted (admin override)
    └─ NO  → Is object null (new record or general query)?
        ├─ YES → granted (read access for all finance members)
        └─ NO  → Check object-level rights via BaseUserGroupRightUtils
            ├─ has rights → granted
            └─ no rights → denied

Key takeaways

  • 77 lines, redundant checks: Lines 50 and 57 duplicate the same FINANCE_GROUP gate — likely from evolving the method over time.
  • Admin bypass: Unlike BankAccountBalanceDao, this DAO explicitly grants admins unconditional access (line 53-54).
  • Object-level rights: BaseUserGroupRightUtils.hasAccess() checks per-object permission assignments — beyond simple group membership.
  • Null object = read access: Finance staff can list all bank accounts even without explicit object rights.
