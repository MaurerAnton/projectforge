Funktionsweise

Die JPA-Entität für Kontostände von Bankkonten – eine Aufzeichnung des Kontostands zu einem bestimmten Datum. Erweitert DefaultBaseDO (ProjectForge-Basisentitätsklasse, die id, created, lastUpdate, deleted bereitstellt). Verwendet 4 Annotationsebenen: JPA (Persistenz), Hibernate Search (Volltext-Indexierung), Jackson (JSON-Serialisierung) und ProjectForge-eigene Annotationen (@PropertyInfo für UI-Metadaten).

Hibernate Search Integration

@Indexed + @FullTextField auf comment ermöglicht die Volltextsuche über alle Kontostandsdatensätze. @IndexedEmbedded(includeDepth = 1) auf bankAccount indexiert die Felder des Bankkontos eine Ebene tief – die Suche nach "IBAN" im Volltextindex würde das übergeordnete BankAccountDO finden. ReindexOnUpdate.SHALLOW bedeutet, dass eine Änderung eines BankAccountDO automatisch eine Neuindexierung seiner Kontostandsdatensätze auslöst.

Wichtige Erkenntnisse

  • 79 Zeilen, 4 Annotations-Frameworks: JPA + Hibernate Search + Jackson + ProjectForge-eigene Annotationen – dichte Metadaten pro Feld.
  • IdOnlySerializer: Die JSON-Serialisierung sendet nur die ID des Bankkontos, nicht das gesamte Objekt – verhindert Endlosschleifen in API-Antworten.
  • Benannte Abfrage, die vom DAO verwendet wird: FIND_BY_BANK_ACCOUNT wird von BankAccountBalanceDao.kt (#45) Zeile 79 über die Konstante des Begleitobjekts referenziert.
  • CURRENCY-Typ: Das Feld amount hat scale=2, precision=12 – bis zu 9.999.999.999,99 in jeder Währung, geeignet für Firmenkonten.
