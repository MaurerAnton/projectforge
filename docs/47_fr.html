Ce qu'il fait

L'entité JPA pour les soldes de comptes bancaires — un enregistrement du solde d'un compte à une date spécifique. Étend DefaultBaseDO (la classe de base des entités de ProjectForge fournissant id, created, lastUpdate, deleted). Utilise 4 couches d'annotations : JPA (persistance), Hibernate Search (indexation plein texte), Jackson (sérialisation JSON) et les annotations personnalisées ProjectForge (@PropertyInfo pour les métadonnées d'interface utilisateur).

Intégration Hibernate Search

@Indexed + @FullTextField sur comment permet la recherche plein texte dans tous les enregistrements de soldes. @IndexedEmbedded(includeDepth = 1) sur bankAccount indexe les champs du compte bancaire sur un niveau de profondeur — rechercher "IBAN" dans l'index plein texte trouverait le BankAccountDO parent. ReindexOnUpdate.SHALLOW signifie que la modification d'un BankAccountDO réindexe automatiquement ses enregistrements de soldes.

Points clés à retenir

  • 79 lignes, 4 frameworks d'annotations : JPA + Hibernate Search + Jackson + annotations personnalisées ProjectForge — métadonnées denses par champ.
  • IdOnlySerializer : La sérialisation JSON envoie uniquement l'ID du compte bancaire, pas l'objet complet — évite les récursions infinies dans les réponses API.
  • Requête nommée consommée par le DAO : FIND_BY_BANK_ACCOUNT est référencée par BankAccountBalanceDao.kt (#45) ligne 79 via la constante de l'objet compagnon.
  • Type CURRENCY : Le champ amount a scale=2, precision=12 — jusqu'à 9 999 999 999,99 dans n'importe quelle devise, adapté aux comptes bancaires d'entreprise.
