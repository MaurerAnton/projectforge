Ce qu'il fait

Le Data Access Object pour les soldes de comptes bancaires — le premier fichier source Kotlin réel de la documentation. Suit le modèle standard DAO de ProjectForge : en-tête GPLv3 (lignes 1-22), étend BaseDao<T> (ligne 38), implémente hasAccess() pour l'autorisation (lignes 42-69), fournit une méthode de requête nommée getByTimePeriod() (lignes 75-83). Annoté @Service pour l'injection de dépendances Spring.

Architecture

38 class BankAccountBalanceDao : BaseDao<BankAccountBalanceDO>(BankAccountBalanceDO::class.java)

BaseDao est le framework de persistance central de ProjectForge — fournit les opérations CRUD, l'infrastructure de vérification d'accès et l'exécution de requêtes nommées. Chaque entité du système possède un DAO correspondant qui étend cette classe de base, en redéfinissant hasAccess() et newInstance().

Points clés à retenir

  • 84 lignes, modèle DAO standard : Étend BaseDao, redéfinit hasAccess et newInstance, ajoute des méthodes de requête spécifiques au métier.
  • Vérification d'accès à trois niveaux : Intégrité de l'objet → appartenance au groupe → permission de l'objet parent — un modèle d'autorisation imbriqué commun à tous les DAO.
  • FINANCE_GROUP : Seuls les membres de l'équipe financière peuvent accéder aux soldes des comptes bancaires — autorisation basée sur les rôles codée en dur dans le DAO, et non dans les annotations Spring Security.
  • KotlinLogging : Utilise mu.KotlinLogging de #33 (kotlin-logging 3.0.5) — le framework de journalisation standard pour tous les fichiers source Kotlin.
