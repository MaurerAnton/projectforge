Was es tut

DAO für Bankkonten — die übergeordnete Entität von BankAccountBalanceDO (#46). Gleiches Muster wie BankAccountBalanceDao (#45): erweitert BaseDao, überschreibt hasAccess() und newInstance(). Wird von BankAccountBalanceDao.hasAccess() in Zeile 68 als Autorisierungsdelegat aufgerufen.

Autorisierungslogik (Zeilen 43-72)

50 if (!accessChecker.isUserMemberOfGroup(user, FINANCE_GROUP))
51   return false                              ← Sperre: Finanzgruppe erforderlich
53 if (accessChecker.isUserMemberOfAdminGroup(user))
54   return true                               ← Umgehung: Admins haben immer Zugriff
57 if (!accessChecker.isUserMemberOfGroup(user, FINANCE_GROUP))
58   return false                              ← Redundant: gleiche Prüfung wie Zeile 50
61 if (obj == null && oldObj == null)
62   return true                               ← Null-Objekte = allgemeiner Lesezugriff
65 return BaseUserGroupRightUtils.hasAccess(...)  ← Objektrechte prüfen
Zeilen 50 und 57 sind redundant: Beide prüfen die Mitgliedschaft in der FINANCE_GROUP. Zeile 57 ist unerreichbar, wenn Zeile 50 bestanden wird (Zeile 51 gibt bereits false für Nicht-Mitglieder zurück). Dies scheint ein defensives Copy-Paste zu sein, bei dem accessChecker.isUserMemberOfGroup(user, ...) (Zeile 50) vs. accessChecker.isLoggedInUserMemberOfGroup(...) (wie in #45 Zeile 58 verwendet) aufgerufen wird.

Zugriffsablauf

Ist der Benutzer in der FINANCE_GROUP?
├─ NEIN → verweigert
└─ JA → Ist der Benutzer ein Admin?
    ├─ JA → gewährt (Admin-Überschreibung)
    └─ NEIN → Ist das Objekt null (neuer Datensatz oder allgemeine Abfrage)?
        ├─ JA → gewährt (Lesezugriff für alle Finanzmitglieder)
        └─ NEIN → Objektrechte über BaseUserGroupRightUtils prüfen
            ├─ hat Rechte → gewährt
            └─ keine Rechte → verweigert

Wichtige Erkenntnisse

  • 77 Zeilen, redundante Prüfungen: Zeilen 50 und 57 duplizieren dieselbe FINANCE_GROUP-Sperre — wahrscheinlich durch Weiterentwicklung der Methode im Laufe der Zeit entstanden.
  • Admin-Umgehung: Im Gegensatz zu BankAccountBalanceDao gewährt dieses DAO Admins explizit uneingeschränkten Zugriff (Zeile 53-54).
  • Objektrechte: BaseUserGroupRightUtils.hasAccess() prüft berechtigungszuweisungen pro Objekt — über die reine Gruppenmitgliedschaft hinaus.
  • Null-Objekt = Lesezugriff: Finanzmitarbeiter können alle Bankkonten auflisten, auch ohne explizite Objektrechte.
