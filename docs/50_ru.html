Что делает

DAO для банковских счетов — родительская сущность для BankAccountBalanceDO (#46). Тот же шаблон, что и BankAccountBalanceDao (#45): расширяет BaseDao, переопределяет hasAccess() и newInstance(). Вызывается из BankAccountBalanceDao.hasAccess() строка 68 как делегат авторизации.

Логика авторизации (строки 43-72)

50 if (!accessChecker.isUserMemberOfGroup(user, FINANCE_GROUP))
51   return false                              ← шлюз: требуется группа finance
53 if (accessChecker.isUserMemberOfAdminGroup(user))
54   return true                               ← обход: у администраторов всегда есть доступ
57 if (!accessChecker.isUserMemberOfGroup(user, FINANCE_GROUP))
58   return false                              ← избыточно: та же проверка, что и в строке 50
61 if (obj == null && oldObj == null)
62   return true                               ← null-объекты = общий доступ на чтение
65 return BaseUserGroupRightUtils.hasAccess(...)  ← проверка прав на уровне объекта
Строки 50 и 57 избыточны: Обе проверяют членство в FINANCE_GROUP. Строка 57 недостижима, если строка 50 пройдена (строка 51 уже вернула false для не-членов). Похоже на защитное копирование при вызове accessChecker.isUserMemberOfGroup(user, ...) (строка 50) против accessChecker.isLoggedInUserMemberOfGroup(...) (как используется в #45 строка 58).

Схема доступа

Пользователь в FINANCE_GROUP?
├─ НЕТ  → отказано
└─ ДА → Пользователь администратор?
    ├─ ДА → предоставлено (переопределение администратором)
    └─ НЕТ → Объект null (новая запись или общий запрос)?
        ├─ ДА → предоставлено (доступ на чтение для всех членов finance)
        └─ НЕТ → Проверка прав на уровне объекта через BaseUserGroupRightUtils
            ├─ есть права → предоставлено
            └─ нет прав → отказано

Ключевые выводы

  • 77 строк, избыточные проверки: Строки 50 и 57 дублируют один и тот же шлюз FINANCE_GROUP — вероятно, из-за эволюции метода с течением времени.
  • Обход администратором: В отличие от BankAccountBalanceDao, этот DAO явно предоставляет администраторам безусловный доступ (строки 53-54).
  • Права на уровне объекта: BaseUserGroupRightUtils.hasAccess() проверяет назначения разрешений для каждого объекта — выходит за рамки простого членства в группе.
  • Null-объект = доступ на чтение: Сотрудники finance могут просматривать все банковские счета даже без явных прав на объект.
