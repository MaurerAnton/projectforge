Ce qu'il fait

Entité JPA pour les transactions bancaires individuelles (enregistrements). 15 champs couvrant les données standard d'un relevé bancaire : montant, date, date de valeur, type, objet, devise, champs SEPA (identifiant du créancier, référence de mandat, référence client, référence de recouvrement), bénéficiaire/émetteur, IBAN, BIC. Plus un champ de somme de contrôle pour détecter les manipulations après importation.

Intégrité de la somme de contrôle

fun buildCheckSum(): String {
  sb.append(amount?.setScale(2)).append('|')
  sb.append(StringHelper.removeNonDigitsAndNonASCIILetters(subject)).append('|')
  ... // 8 champs concaténés avec le séparateur |
  return DigestUtils.sha256Hex(sb.toString())
}

buildCheckSum() calcule un hachage SHA-256 sur 8 champs normalisés. ensureChecksum (propriété calculée) génère automatiquement la somme de contrôle si elle est nulle. Utilisé par BankAccountRecordPagesRest (#55) pour la détection de doublons : deux enregistrements avec des sommes de contrôle identiques mais des ID différents sont signalés comme doublons potentiels. Également utilisé pour détecter les manipulations manuelles des enregistrements importés.
