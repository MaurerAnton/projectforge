Ce qu'il fait

CLAUDE.md est un fichier d'instructions pour agent — il est automatiquement lu par Claude Code lorsque l'IA interagit avec ce dépôt. Considérez-le comme le document d'intégration pour les agents IA.

Sans ce fichier, Claude devrait découvrir les commandes de construction, le style de code et les conventions en lisant build.gradle.kts, buildSrc/ et les fichiers source existants. Avec lui, l'agent sait immédiatement :

  • Comment construire (./gradlew build) et exécuter (./gradlew bootRun)
  • Comment exécuter un seul test (./gradlew test --tests "...")
  • La pile technique (Kotlin JVM 17, Spring Boot, JUnit 5)
  • Les conventions de code (camelCase, PascalCase, types nullables, indentation de 4 espaces)

Section par section

Commandes de construction/test (lignes 5–11)

Construire tout :           ./gradlew build
Construire sans tests :     ./gradlew build -x test
Exécuter l'application :    ./gradlew bootRun
Test unique :               ./gradlew test --tests "org.projectforge.package.ClassName.methodName"
Tests d'un package :        ./gradlew test --tests "org.projectforge.package.*"
Tests d'un module :         ./gradlew :projectforge-business:test

Six commandes couvrant les opérations les plus courantes. Le filtre --tests est particulièrement utile — il exécute une seule méthode de test sans lancer toute la suite (ce qui prend des minutes).

Remarque : Ces commandes fonctionnent car le build.gradle.kts racine s'applique à tous les sous-projets via allprojects { }.

Comment cela se rapporte au reste du projet

Ce fichier est la couche de traduction entre les conventions lisibles par l'humain et ce que le système de construction applique réellement :

CLAUDE.md ditAppliqué par
"Cible Kotlin JVM 17"Plugin de convention ligne 28 : options.release.set(17)
"JUnit 5 pour les tests"Plugin de convention ligne 38 : useJUnitPlatform()
"kotlin-logging"Plugin de convention ligne 60 : api("kotlin-logging")
"Construire tout"build.gradle.kts racine : s'applique à tous les sous-projets

CLAUDE.md indique à l'IA quoi faire ; les fichiers de construction l'appliquent.

Pourquoi il existe

Ce fichier a été ajouté spécifiquement pour Claude Code — l'assistant de codage IA d'Anthropic. Il suit la convention CLAUDE.md où l'agent lit automatiquement ce fichier au début de chaque session. Il a probablement été ajouté par le même développeur qui a introduit le développement assisté par IA dans le projet.

L'équivalent pour GitHub Copilot serait .github/copilot-instructions.md ou des commentaires en ligne. Pour Cursor, ce serait .cursor/rules.md.

Notablement, le fichier mentionne les Coroutines Kotlin (ligne 22) — mais la base de code actuelle utilise encore Thread à plusieurs endroits (par exemple IdpLoginHandler.kt). Cela signifie que CLAUDE.md décrit davantage le style souhaité que la réalité actuelle.
