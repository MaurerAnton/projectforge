Что делает

CLAUDE.md — это файл с инструкциями для агента — он автоматически считывается Claude Code, когда AI взаимодействует с этим репозиторием. Воспринимайте его как вводный документ для AI-агентов.

Без этого файла Claude пришлось бы самостоятельно находить команды сборки, стиль кода и соглашения, читая build.gradle.kts, buildSrc/ и существующие исходные файлы. С ним агент сразу знает:

  • Как собрать проект (./gradlew build) и запустить (./gradlew bootRun)
  • Как запустить один тест (./gradlew test --tests "...")
  • Технологический стек (Kotlin JVM 17, Spring Boot, JUnit 5)
  • Соглашения по коду (camelCase, PascalCase, nullable-типы, отступ 4 пробела)

По разделам

Команды сборки/тестирования (строки 5–11)

Собрать всё:           ./gradlew build
Собрать без тестов:    ./gradlew build -x test
Запустить приложение:  ./gradlew bootRun
Один тест:            ./gradlew test --tests "org.projectforge.package.ClassName.methodName"
Тесты пакета:         ./gradlew test --tests "org.projectforge.package.*"
Модульные тесты:      ./gradlew :projectforge-business:test

Шесть команд, покрывающих наиболее частые операции. Фильтр --tests особенно полезен — он запускает один тестовый метод без выполнения всего набора (что занимает минуты).

Примечание: Они работают, потому что корневой build.gradle.kts применяется ко всем подпроектам через allprojects { }.

Как это связано с остальной частью проекта

Этот файл — промежуточный слой между человекочитаемыми соглашениями и тем, что фактически обеспечивает система сборки:

CLAUDE.md говоритОбеспечивается
«Целевая версия Kotlin JVM 17»Convention plugin, строка 28: options.release.set(17)
«JUnit 5 для тестов»Convention plugin, строка 38: useJUnitPlatform()
«kotlin-logging»Convention plugin, строка 60: api("kotlin-logging")
«Собрать всё»Корневой build.gradle.kts: применяется ко всем подпроектам

CLAUDE.md сообщает AI что делать; файлы сборки это обеспечивают.

Зачем это существует

Этот файл был добавлен специально для Claude Code — AI-помощника по коду от Anthropic. Он следует соглашению CLAUDE.md, согласно которому агент автоматически читает этот файл в начале каждого сеанса. Вероятно, он был добавлен тем же разработчиком, который ввёл AI-ассистированную разработку в проект.

Эквивалентом для GitHub Copilot был бы .github/copilot-instructions.md или встроенные комментарии. Для Cursor — .cursor/rules.md.

Примечательно, что файл упоминает Kotlin Coroutines (строка 22) — но текущая кодовая база всё ещё использует Thread в нескольких местах (например, IdpLoginHandler.kt). Это означает, что CLAUDE.md описывает скорее желаемый стиль, чем текущую реальность.
