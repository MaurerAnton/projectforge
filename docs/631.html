#631: DatabaseExecutor.java

Lines: 48 · Author: Kai Reinhard · Type: Java interface — org.projectforge.database package

Interface for direct JDBC operations outside Hibernate. 48 lines, 5 methods. Described as "For manipulating the database (patching data etc.)" — used when Hibernate ORM is not suitable (e.g. Flyway migrations, bulk data fixes, schema introspection). The key design principle: this gives raw SQL access bypassing Hibernate's session/transaction management, with a simpler API than JdbcTemplate.

Methods:

  • setDataSource(DataSource) / getDataSource() — injects/accesses the JDBC javax.sql.DataSource. The DataSource comes from Spring's connection pool (HikariCP in production).
  • execute(String sql, boolean ignoreErrors) — runs DDL/DML statements. If ignoreErrors=true, SQL exceptions are caught and logged rather than propagated — used for idempotent Flyway operations (e.g. "DROP TABLE IF EXISTS").
  • queryForInt(String sql, Object... args) — returns a single integer from a SELECT (e.g. SELECT COUNT(*) FROM ...). Uses PreparedStatement with positional ? parameters. Throws RuntimeException if the result set is empty.
  • query(String sql, Object... args) — returns List<DatabaseResultRow> — a generic row/column map of the result set. Columns are indexed by both position (0-based) and name.
  • update(String sql, Object... args) — executes UPDATE/INSERT/DELETE, returns affected row count.

Implemented by: DatabaseExecutorImpl (JDBC-based — for Flyway/dev use), and a JdbcTemplate-based version (for production with connection pooling).
