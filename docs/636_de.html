#636: DatabaseSupport.java

projectforge-business/src/main/java/org/projectforge/database/DatabaseSupport.java Zeilen: 101 · Autor: Kai Reinhard · Typ: Java-Singleton — Paket org.projectforge.database 101 Zeilen · 47 Code · 42 Kommentare · 12 leer

Abstraktionsschicht für Datenbank-Dialekte. Singleton (statisches getInstance() + setInstance() — wird beim Anwendungsstart gesetzt). Enthält den erkannten DatabaseDialect (PostgreSQL oder HSQL) und bietet dialektspezifische Optimierungen. 101 Zeilen.

Konstruktor: DatabaseSupport(DatabaseDialect dialect) — protokolliert den erkannten Dialekt auf INFO-Ebene: "Setze Datenbank-Dialekt auf: PostgreSQL". Der Dialekt wird von ConfigurationService anhand der JDBC-URL beim Start ermittelt.

Schlüsselmethode — getIntervalInSeconds(fromProperty, toProperty): Dies ist die leistungskritische Methode. Zur Berechnung der Dauer (z. B. Zeiterfassung stopTime - startTime) wird, anstatt alle Zeilen nach Java zu laden und Differenzen im Speicher zu berechnen (O(n) Speicher + CPU), eine datenbankseitige SUM in SQL erzeugt:

PostgreSQL: "SUM(EXTRACT(EPOCH FROM toProperty) - EXTRACT(EPOCH FROM fromProperty))"

Dies gibt die Gesamtsekunden als einzelnes Datenbank-Aggregat zurück — O(1) Ergebnisgröße unabhängig von der Zeilenanzahl. Kritisch für Installationen mit vielen Zeiterfassungseinträgen. Die auskommentierte Alternative EXTRACT(EPOCH FROM SUM(to - from)) wurde erwogen, aber die Berechnung pro Zeile wurde aus Genauigkeitsgründen gewählt.

Fallback: Wenn die Datenbank nicht PostgreSQL ist (also HSQL für Tests), wird null zurückgegeben. Der Aufrufer muss dann alle Zeilen abrufen und die Summe in Java berechnen. Eine einmalige Warnung wird protokolliert (gesichert durch static boolean errorMessageShown), die den Entwickler kontaktiert, falls die Installation >10.000 Zeiterfassungseinträge hat — die Java-seitige Aggregation wird bei großen Datenmengen langsam.

getShutdownDatabaseStatement(): Wird von WicketApplication beim Herunterfahren aufgerufen. Für HSQL (eingebettete Testdatenbank) wird "SHUTDOWN COMPACT" zurückgegeben — schließt die eingebettete Datenbank sicher und kompaktiert die Datendatei. Für PostgreSQL wird null zurückgegeben — der Verbindungspool kümmert sich um das Herunterfahren.

Entwurfshinweis: Dies ist die einzige Stelle im Codebestand, an der datenbankspezifisches SQL erzeugt wird. Alle anderen SQL-Abfragen werden von Hibernate/HQL generiert, das datenbankunabhängig ist. Diese Klasse existiert speziell für die Intervalloptimierung, die HQL nicht portabel ausdrücken kann.
