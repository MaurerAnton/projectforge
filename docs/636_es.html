#636: DatabaseSupport.java

projectforge-business/src/main/java/org/projectforge/database/DatabaseSupport.java Líneas: 101 · Autor: Kai Reinhard · Tipo: Singleton Java — paquete org.projectforge.database 101 líneas · 47 código · 42 comentarios · 12 en blanco

Capa de abstracción de dialecto de base de datos. Singleton (static getInstance() + setInstance() — se establece durante el inicio de la aplicación). Contiene el DatabaseDialect detectado (PostgreSQL o HSQL) y proporciona optimizaciones específicas del dialecto. 101 líneas.

Constructor: DatabaseSupport(DatabaseDialect dialect) — registra el dialecto detectado a nivel INFO: "Estableciendo dialecto de base de datos a: PostgreSQL". El dialecto es determinado por ConfigurationService a partir de la URL JDBC al iniciar.

Método clave — getIntervalInSeconds(fromProperty, toProperty): Este es el método crítico de rendimiento. Para calcular la duración (ej. stopTime - startTime de una hoja de tiempos), en lugar de obtener todas las filas en Java y calcular diferencias en memoria (O(n) memoria + CPU), genera un SUM del lado de la base de datos en SQL:

PostgreSQL: "SUM(EXTRACT(EPOCH FROM toProperty) - EXTRACT(EPOCH FROM fromProperty))"

Esto devuelve los segundos totales como un único agregado de base de datos — tamaño de resultado O(1) independientemente del número de filas. Crítico para instalaciones con muchas entradas de hoja de tiempos. La alternativa comentada EXTRACT(EPOCH FROM SUM(to - from)) fue considerada pero se eligió el cálculo por fila para mayor precisión.

Alternativa: Si la base de datos no es PostgreSQL (es decir, HSQL para pruebas), devuelve null. Quien lo invoque debe entonces obtener todas las filas y calcular la suma en Java. Se registra una advertencia única (protegida por static boolean errorMessageShown) pidiendo contactar al desarrollador si la instalación tiene más de 10,000 entradas de hoja de tiempos — la agregación del lado de Java se vuelve lenta a gran escala.

getShutdownDatabaseStatement(): Llamado por WicketApplication al apagar. Para HSQL (base de datos de prueba embebida), devuelve "SHUTDOWN COMPACT" — cierra de forma segura la base de datos embebida y compacta el archivo de datos. Para PostgreSQL, devuelve null — el pool de conexiones maneja el apagado.

Nota de diseño: Este es el único lugar en el código base donde se genera SQL específico de la base de datos. Todo el demás SQL es generado por Hibernate/HQL, que es independiente de la base de datos. Esta clase existe específicamente para la optimización de intervalos que HQL no puede expresar de manera portátil.
