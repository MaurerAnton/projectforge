Couche d'abstraction du dialecte de base de données. Singleton (static getInstance() + setInstance() — défini lors du démarrage de l'application). Contient le DatabaseDialect détecté (PostgreSQL ou HSQL) et fournit des optimisations spécifiques au dialecte. 101 lignes.

Constructeur : DatabaseSupport(DatabaseDialect dialect) — enregistre le dialecte détecté au niveau INFO : "Réglage du dialecte de base de données sur : PostgreSQL". Le dialecte est déterminé par ConfigurationService à partir de l'URL JDBC au démarrage.

Méthode clé — getIntervalInSeconds(fromProperty, toProperty) : C'est la méthode critique pour les performances. Pour calculer la durée (par exemple, stopTime - startTime d'une feuille de temps), au lieu de récupérer toutes les lignes en Java et de calculer les différences en mémoire (O(n) mémoire + CPU), elle génère une somme côté base de données en SQL :

PostgreSQL : "SUM(EXTRACT(EPOCH FROM toProperty) - EXTRACT(EPOCH FROM fromProperty))"

Cela renvoie le total des secondes sous forme d'agrégat unique de la base de données — taille de résultat O(1) quel que soit le nombre de lignes. Critique pour les installations avec de nombreuses entrées de feuilles de temps. L'alternative commentée EXTRACT(EPOCH FROM SUM(to - from)) a été envisagée mais le calcul par ligne a été choisi pour la précision.

Solution de repli : Si la base de données n'est pas PostgreSQL (c'est-à-dire HSQL pour les tests), renvoie null. L'appelant doit alors récupérer toutes les lignes et calculer la somme en Java. Un avertissement unique est enregistré (protégé par static boolean errorMessageShown) demandant de contacter le développeur si l'installation contient plus de 10 000 entrées de feuilles de temps — l'agrégation côté Java devient lente à grande échelle.

getShutdownDatabaseStatement() : Appelé par WicketApplication lors de l'arrêt. Pour HSQL (base de données de test embarquée), renvoie "SHUTDOWN COMPACT" — ferme en toute sécurité la base de données embarquée et compacte le fichier de données. Pour PostgreSQL, renvoie null — le pool de connexions gère l'arrêt.

Note de conception : C'est le seul endroit dans la base de code où du SQL spécifique à la base de données est généré. Tout autre SQL est généré par Hibernate/HQL, qui est indépendant de la base de données. Cette classe existe spécifiquement pour l'optimisation des intervalles que HQL ne peut pas exprimer de manière portable.
