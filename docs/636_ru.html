projectforge-business/src/main/java/org/projectforge/database/DatabaseSupport.java Строк: 101 · Автор: Kai Reinhard · Тип: Java-синглтон — пакет org.projectforge.database 101 строка · 47 кода · 42 комментария · 12 пустых

Уровень абстракции диалекта базы данных. Синглтон (статический getInstance() + setInstance() — устанавливается во время запуска приложения). Содержит обнаруженный DatabaseDialect (PostgreSQL или HSQL) и предоставляет оптимизации, специфичные для диалекта. 101 строка.

Конструктор: DatabaseSupport(DatabaseDialect dialect) — логирует обнаруженный диалект на уровне INFO: "Установлен диалект базы данных: PostgreSQL". Диалект определяется ConfigurationService из JDBC URL при запуске.

Ключевой метод — getIntervalInSeconds(fromProperty, toProperty): Это критический по производительности метод. Для вычисления длительности (например, stopTime - startTime в табеле учёта времени), вместо загрузки всех строк в Java и вычисления разницы в памяти (O(n) память + процессор), он генерирует вычисление SUM на стороне базы данных в SQL:

PostgreSQL: "SUM(EXTRACT(EPOCH FROM toProperty) - EXTRACT(EPOCH FROM fromProperty))"

Это возвращает общее количество секунд как единый агрегат базы данных — размер результата O(1) независимо от количества строк. Критически важно для установок с большим количеством записей в табеле. Альтернативный вариант EXTRACT(EPOCH FROM SUM(to - from)) был закомментирован, но для точности был выбран расчёт по каждой строке.

Запасной вариант: Если база данных не PostgreSQL (т.е. HSQL для тестирования), возвращает null. Вызывающий код должен тогда загрузить все строки и вычислить сумму в Java. Одноразовое предупреждение логируется (защищено static boolean errorMessageShown) с просьбой связаться с разработчиком, если в установке более 10 000 записей табеля — агрегация на стороне Java становится медленной при больших объёмах.

getShutdownDatabaseStatement(): Вызывается WicketApplication при завершении работы. Для HSQL (встроенная тестовая база данных) возвращает "SHUTDOWN COMPACT" — безопасно закрывает встроенную базу данных и уплотняет файл данных. Для PostgreSQL возвращает null — пул соединений обрабатывает завершение работы.

Примечание по дизайну: Это единственное место в кодовой базе, где генерируется SQL, специфичный для базы данных. Весь остальной SQL генерируется Hibernate/HQL, который не зависит от базы данных. Этот класс существует специально для оптимизации интервалов, которую HQL не может выразить переносимым способом.
