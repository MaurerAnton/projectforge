#637: DatabaseResultRowImpl.java

Lines: 73 · Author: Kai Reinhard · Type: Java POJO — implements DatabaseResultRow

Mutable row container backed by a LinkedList. 73 lines. Holds an ordered list of DatabaseResultRowEntry objects — one per column in the SQL result.

Key design detail — getEntry(String name): The name lookup is case-insensitive. The implementation converts both the query name and each entry's name to lowercase before comparing. This is important because different databases return column names with different casing: PostgreSQL returns lowercase by default, HSQL returns uppercase for unquoted identifiers, MySQL returns whatever casing the table was created with. The case-insensitive comparison insulates callers from database-specific casing differences. If no match is found, returns null rather than throwing — callers must null-check.

Performance note: getEntry(String name) uses linear scan (O(n)) through the entries list. For typical result sets (10-20 columns), this is negligible. If rows had hundreds of columns, a HashMap<String, DatabaseResultRowEntry> would be needed, but this is intentionally simple since these are only used by Flyway migrations and data patching, not high-frequency queries.

Data structure: LinkedList<DatabaseResultRowEntry> — chosen for O(1) add() at the end (which is all that happens during population). The getEntry(int index) access is O(n) on LinkedList but again negligible for small lists. A ArrayList would be faster for index access but slightly slower for add-heavy workloads — either would be fine for the use case.
