projectforge-business/src/main/java/org/projectforge/database/jdbc/DatabaseExecutorImpl.java Líneas: 161 · Autor: Kai Reinhard · Tipo: Java — implementa DatabaseExecutor · Paquete: org.projectforge.database.jdbc 161 líneas · 120 código · 29 comentarios · 12 en blanco

Implementación JDBC simple de la interfaz DatabaseExecutor. 161 líneas. Advertencia importante de Javadoc: "¡¡¡NO USES ESTA CLASE EN PRODUCCIÓN! Esto es solo para fines de demostración, porque no hay pool de conexiones y las conexiones pueden perderse!!!!!" — esta clase es para migraciones de Flyway (que se ejecutan antes de que se inicialice Hibernate), scripts de parcheo de datos y desarrollo/pruebas. El código de producción utiliza una implementación basada en JdbcTemplate con pool de conexiones HikariCP.

Arquitectura: Cada método crea una subclase anónima de JdbcExecutor (#638) que sobrescribe el método plantilla execute(PreparedStatement). Este es el patrón Template Method — JdbcExecutor maneja el ciclo de vida de la conexión (abrir, establecer parámetros, cerrar), mientras que cada subclase anónima proporciona la operación JDBC específica.

Detalles de los métodos:

  • execute(sql, ignoreErrors) — ejecuta DDL/DML mediante stmt.execute(). No devuelve nada. Cuando ignoreErrors=true, JdbcExecutor captura SQLException y lo registra a nivel WARN en lugar de relanzarlo. Se usa para operaciones idempotentes como DROP TABLE IF EXISTS.
  • query(sql, args...) — el método de consulta principal. Crea un JdbcExecutor cuya sobrescritura de execute():
    1. Llama a stmt.executeQuery() para obtener el ResultSet
    2. Itera while(rs.next()), creando un DatabaseResultRowImpl por fila
    3. Para cada fila, itera las columnas de ResultSetMetaData (conversión de índice basado en 1 a basado en 0)
    4. Crea DatabaseResultRowEntryImpl(type, name, value) para cada columna
    5. Devuelve List<DatabaseResultRow> — correctamente poblada con metadatos de columna
    Seguridad de recursos: ResultSet se cierra en un bloque finally — crítico ya que esto evita la gestión de recursos de Hibernate.
  • queryForInt(sql, args...) — devuelve un único entero. Lanza RuntimeException si el conjunto de resultados está vacío (sin rs.next()). Se usa para SELECT COUNT(*) y consultas agregadas similares. Cierra ResultSet en finally.
  • update(sql, args...) — ejecuta stmt.executeUpdate(), devuelve el número de filas afectadas como Integer. Conversión desde Object — la plantilla genérica de JdbcExecutor devuelve Object para adaptarse a diferentes tipos de retorno.

Dos constructores: DatabaseExecutorImpl() (sin argumentos — el DataSource debe establecerse después mediante setDataSource()) y DatabaseExecutorImpl(DataSource) (listo para usar). El constructor sin argumentos existe para escenarios de configuración XML de Spring donde el DataSource se inyecta mediante un setter de propiedad.

Flujo del DataSource: El DataSource proviene del @Bean DataSource de Spring (configurado en las propiedades de la aplicación: spring.datasource.url, spring.datasource.username, spring.datasource.password). En producción, este es un DataSource agrupado de HikariCP — pero esta clase no utiliza las características de agrupación. Su advertencia sobre "sin pool de conexiones" se refiere a su propio manejo de conexiones: cada llamada a JdbcExecutor abre una nueva conexión JDBC sin procesar a través de DataSource.getConnection() en lugar de tomarla del pool, lo que debería funcionar con HikariCP pero no es el uso previsto.

Dependencias: JdbcExecutor (#638), DatabaseResultRowImpl (#637), DatabaseResultRowEntryImpl (#636). Todos en el mismo subpaquete jdbc.
