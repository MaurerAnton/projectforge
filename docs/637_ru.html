projectforge-business/src/main/java/org/projectforge/database/jdbc/DatabaseExecutorImpl.java Строк: 161 · Автор: Kai Reinhard · Тип: Java — реализует DatabaseExecutor · Пакет: org.projectforge.database.jdbc 161 строка · 120 кода · 29 комментариев · 12 пустых

Простая JDBC-реализация интерфейса DatabaseExecutor. 161 строка. Важное предупреждение Javadoc: "НЕ ИСПОЛЬЗУЙТЕ ЭТОТ КЛАСС В ПРОДАКШЕНЕ! Он предназначен только для демонстрации, так как здесь нет пула соединений и соединения могут теряться!!!!!" — этот класс предназначен для миграций Flyway (которые выполняются до инициализации Hibernate), скриптов исправления данных и разработки/тестирования. Продакшен-код использует реализацию на основе JdbcTemplate с пулом соединений HikariCP.

Архитектура: Каждый метод создаёт анонимный подкласс JdbcExecutor (#638), который переопределяет шаблонный метод execute(PreparedStatement). Это шаблонный метод — JdbcExecutor управляет жизненным циклом соединения (открытие, установка параметров, закрытие), а каждый анонимный подкласс предоставляет конкретную JDBC-операцию.

Детали методов:

  • execute(sql, ignoreErrors) — выполняет DDL/DML через stmt.execute(). Ничего не возвращает. Когда ignoreErrors=true, JdbcExecutor перехватывает SQLException и логирует его на уровне WARN, не пробрасывая дальше. Используется для идемпотентных операций, таких как DROP TABLE IF EXISTS.
  • query(sql, args...) — основной метод запроса. Создаёт JdbcExecutor, чей переопределённый execute():
    1. Вызывает stmt.executeQuery() для получения ResultSet
    2. Проходит в цикле while(rs.next()), создавая один DatabaseResultRowImpl на строку
    3. Для каждой строки проходит по колонкам ResultSetMetaData (преобразование индексации с 1 на 0)
    4. Создаёт DatabaseResultRowEntryImpl(type, name, value) для каждой колонки
    5. Возвращает List<DatabaseResultRow> — корректно заполненный метаданными колонок
    Безопасность ресурсов: ResultSet закрывается в блоке finally — это критично, так как обходится управление ресурсами Hibernate.
  • queryForInt(sql, args...) — возвращает одно целое число. Выбрасывает RuntimeException, если результирующий набор пуст (нет rs.next()). Используется для SELECT COUNT(*) и подобных агрегатных запросов. Закрывает ResultSet в finally.
  • update(sql, args...) — выполняет stmt.executeUpdate(), возвращает количество затронутых строк как Integer. Приводится из Object — обобщённый шаблон JdbcExecutor возвращает Object для поддержки разных типов возвращаемых значений.

Два конструктора: DatabaseExecutorImpl() (без аргументов — DataSource должен быть установлен позже через setDataSource()) и DatabaseExecutorImpl(DataSource) (готов к использованию). Конструктор без аргументов существует для сценариев конфигурации Spring XML, где DataSource внедряется через сеттер свойства.

Поток DataSource: DataSource поступает из Spring-бина @Bean DataSource (настраивается в application properties: spring.datasource.url, spring.datasource.username, spring.datasource.password). В продакшене это пулированный DataSource HikariCP — но этот класс не использует функции пула. Его предупреждение об "отсутствии пула соединений" относится к его собственной обработке соединений: каждый вызов JdbcExecutor открывает новое "сырое" JDBC-соединение через DataSource.getConnection() вместо заимствования из пула, что должно работать с HikariCP, но не является предполагаемым использованием.

Зависимости: JdbcExecutor (#638), DatabaseResultRowImpl (#637), DatabaseResultRowEntryImpl (#636). Все в одном подпакете jdbc.
