#647: MyXlsExportContext.java

Lines: 94 · Type: Java — implements ExportContext

Export context providing locale, i18n, and date formatting for Excel generation. 94 lines. Implements ExportContext (#390) — the interface that the Excel engine calls for locale settings, i18n string resolution, and date format preferences.

Singleton initialization (constructor): Uses a static-once pattern — the first time this class is constructed, it registers itself as the default export context via ExportConfig.setInstance(). Inside that call, it sets up the ContentProvider factory to create MyXlsContentProvider instances. This means every export in the application automatically uses this context unless explicitly overridden. The static boolean initialized flag prevents re-registration on subsequent constructor calls. This is a lazy singleton — not an enum singleton — created when the first export is triggered.

getLocale(): If a locale was explicitly set via setLocale(), uses that. Otherwise, falls back to ThreadLocalUserContext.getLocale() — the locale of the currently logged-in user. Note the bug: There's a potential issue — the getter overwrites the stored locale field with ThreadLocalUserContext.getLocale() on every call when this.locale != null, rather than only when this.locale == null. The condition appears inverted. In practice, this means if a locale was explicitly set, every subsequent getLocale() call overwrites it with the thread-local locale, making setLocale() ineffective after the first get.

getLocalizedString(i18nKey): Delegates to ThreadLocalUserContext.getLocalizedString(i18nKey). Actually performs i18n translation (unlike the Javadoc which erroneously says "Does not translation: returns the i18nKey itself" — the implementation clearly calls the translation method).

getExcelDateFormat(): Returns the current user's preferred Excel date format from PFUserDO.getExcelDateFormat(). If no user is logged in (e.g. during system export jobs), falls back to ExcelDateFormats.EXCEL_DEFAULT_DATE. This allows each user to have their own date format preference for exported Excel files (e.g. DD.MM.YYYY for German users, MM/DD/YYYY for US users).
