#652: AccessCheckerImpl.java

Lines: 853 · Author: Roger Rene Kommer · Type: Java @Service — implements AccessChecker

THE central access control implementation — 853 lines, one of the largest and most critical files in the framework. Implements all 30+ methods of AccessChecker. Autowires UserRightService, TaskTree, and UserGroupCache. Every access check in the application ultimately flows through this class.

Dependencies: UserRightService (#691) — evaluates UserRight registrations. TaskTree — the singleton WBS task tree for task-based access checks. UserGroupCache — for admin/demo/group membership queries. Registry — for looking up registered UserRight instances.

Key implementation patterns:

  • Admin check: isUserMemberOfAdminGroup() delegates to UserGroupCache.isUserMemberOfAdminGroup() which checks if the user is in the ADMIN_GROUP constant defined by ProjectForgeGroup. Admin users bypass all further access checks.
  • Demo/restricted user check: isDemoUser() — a static method that checks user.getUsername().equals("demo"). The username is hardcoded — the demo user concept is a simple heuristic, not a database flag. Restricted/demo users are blocked from write operations.
  • Group membership: isUserMemberOfGroup() checks UserGroupCache.isUserMemberOfGroup() for the given ProjectForgeGroup constants. If throwException=true, throws AccessException on failure.
  • Right evaluation: hasRight() looks up the UserRight by IUserRightId, checks availability via right.isAvailable(userGroupCache, user), then checks the value against the demanded UserRightValue. If throwException=true, throws on denial.
  • Row-level access: hasAccess(user, rightId, obj, oldObj, operationType, throwException) — the core row-level check. Looks up the right, calls right.hasAccess(user, obj, oldObj, operationType). If access is denied and throwException=true, throws AccessException with user/operation/object context.
  • Task permission: hasPermission(user, taskId, accessType, operationType, throwException) — checks if the user has access to a WBS task node via group permissions on the task tree. Iterates user's groups, checks each against the task's assigned groups.

Singleton pattern: AccessChecker is accessed statically via WicketSupport.getAccessChecker() or AccessChecker.getInstance() — a deliberate anti-pattern that circumvents Spring DI for access from Wicket components and static utility methods. The Spring @Service + static singleton dual-initialization ensures the same instance is used everywhere.

I18n key: I18N_KEY_VIOLATION_USER_NOT_MEMBER_OF = "access.violation.userNotMemberOf" — the error message shown when a user is denied group-based access.
