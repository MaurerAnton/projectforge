#654: AccessChecker.java

projectforge-business/src/main/java/org/projectforge/framework/access/AccessChecker.java Zeilen: 275 · Autor: Kai Reinhard · Typ: Java-Interface — am häufigsten wiederverwendetes Interface 275 Zeilen · 76 Code · 149 Kommentare · 50 leer

Zentraler Zugriffskontrollvertrag — 275 Zeilen, 30+ Methoden. Beschrieben als "Hilfsmethoden zur Bewertung von Benutzer- und Gruppenberechtigungen." Jede Seite, jeder REST-Controller, jedes DAO ruft dieses Interface auf (über das statische Singleton), bevor geschützte Operationen ausgeführt werden. Implementiert von AccessCheckerImpl (853 Zeilen).

Methodenkategorien:

  • Admin-Prüfungen: isUserMemberOfAdminGroup(), checkIsLoggedInUserMemberOfAdminGroup(), isLoggedInUserMemberOfAdminGroup() — Varianten mit/ohne Ausnahmewurf, sowohl für explizite Benutzer als auch für Kontextbenutzer
  • Eingeschränkter/Demo-Benutzer: isRestrictedUser(), isDemoUser(), checkRestrictedOrDemoUser() — Demo-Benutzer wird durch den Benutzernamen "demo" erkannt (statische Hilfsmethode in Zeile 76 vergleicht Benutzernamen), eingeschränkter Benutzer ist ein Datenbank-Flag. Diese Prüfungen verhindern, dass Demo-/eingeschränkte Benutzer Schreiboperationen durchführen
  • Gruppenmitgliedschaft: isUserMemberOfGroup(user, throwException, groups...) — prüft gegen ProjectForgeGroup-Konstanten (ADMIN, FINANCE, HR, etc.). Der Varargs-Parameter groups bedeutet "mindestens eine davon" — der Benutzer muss in einer der angegebenen Gruppen sein
  • Rechteprüfungen: hasRight(), hasLoggedInUserRight(), checkUserRight() — bewertet registrierte UserRight-Instanzen anhand von IUserRightId mit angefordertem UserRightValue (TRUE/FALSE/INHERIT). Mehrere Werte über Varargs — "mindestens einer muss übereinstimmen"
  • Zugriff auf Zeilenebene: hasAccess(user, rightId, obj, oldObj, operationType, throwException), hasInsertAccess(), hasReadAccess(), hasWriteAccess() — die Kernberechtigungen auf Entitätsebene. Wenn throwException=true, wird die Prüfung obligatorisch — eine Verweigerung löst AccessException aus
  • Task-Berechtigungen: hasPermission(user, taskId, accessType, operationType, throwException) — prüft Task-Ebene-Berechtigungen über die Gruppenberechtigungen des WBS-Task-Baums
  • Benutzervergleich: userEquals(), userEqualsToContextUser(), areUsersInSameGroup() — Hilfsmethoden für allgemeine Benutzeridentitäts-/Ähnlichkeitsprüfungen
  • Verlaufszugriff: hasHistoryAccess(), hasLoggedInUserHistoryAccess() — ob der Benutzer den Änderungsverlauf einer Entität einsehen kann

Entwurfsmuster — throwException-Parameter: Viele Methoden haben eine boolean throwException-Variante. Wenn true, löst eine Verweigerung AccessException aus; wenn false, wird boolean zurückgegeben. Dies ermöglicht Aufrufern, Berechtigungen ohne Ausnahmebehandlungs-Overhead zu prüfen, wenn sie nur eine Ja/Nein-Antwort benötigen, und eine automatische Ausnahme mit i18n-Nachricht zu erhalten, wenn ein Fehler den Vorgang abbrechen muss.

Ausnahmehierarchie in Methodenpräfixen: check*-Methoden (z.B. checkIsLoggedInUserMemberOfAdminGroup()) sind void und werfen bei Fehlschlag immer eine Ausnahme. has*-Methoden geben boolean zurück und werfen nur eine Ausnahme, wenn throwException=true ist.
