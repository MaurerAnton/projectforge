#654: AccessChecker.java

projectforge-business/src/main/java/org/projectforge/framework/access/AccessChecker.java Líneas: 275 · Autor: Kai Reinhard · Tipo: Interfaz Java — interfaz más reutilizada 275 líneas · 76 código · 149 comentarios · 50 en blanco

Contrato central de control de acceso — 275 líneas, más de 30 métodos. Descrito como "métodos auxiliares para la evaluación del acceso de usuarios y grupos." Cada página, cada controlador REST, cada DAO llama a esta interfaz (a través del singleton estático) antes de realizar operaciones protegidas. Implementada por AccessCheckerImpl (853 líneas).

Categorías de métodos:

  • Verificaciones de administrador: isUserMemberOfAdminGroup(), checkIsLoggedInUserMemberOfAdminGroup(), isLoggedInUserMemberOfAdminGroup() — variantes con/sin lanzamiento de excepción, tanto para usuario explícito como para usuario de contexto
  • Usuario restringido/demo: isRestrictedUser(), isDemoUser(), checkRestrictedOrDemoUser() — el usuario demo se detecta por el nombre de usuario "demo" (helper estático en la línea 76 compara el nombre de usuario), el usuario restringido es una bandera de base de datos. Estas verificaciones evitan que los usuarios restringidos/demo realicen operaciones de escritura
  • Pertenencia a grupos: isUserMemberOfGroup(user, throwException, groups...) — verifica contra constantes de ProjectForgeGroup (ADMIN, FINANCE, HR, etc.). El parámetro varargs groups significa "al menos uno de" — el usuario debe estar en cualquiera de los grupos especificados
  • Verificaciones de derechos: hasRight(), hasLoggedInUserRight(), checkUserRight() — evalúa instancias registradas de UserRight mediante IUserRightId con el UserRightValue solicitado (TRUE/FALSE/INHERIT). Múltiples valores mediante varargs — "al menos uno debe coincidir"
  • Acceso a nivel de fila: hasAccess(user, rightId, obj, oldObj, operationType, throwException), hasInsertAccess(), hasReadAccess(), hasWriteAccess() — los permisos centrales a nivel de entidad. Cuando throwException=true, la verificación se vuelve obligatoria — la denegación lanza AccessException
  • Permisos de tarea: hasPermission(user, taskId, accessType, operationType, throwException) — verifica el acceso a nivel de tarea a través de los permisos de grupo del árbol de tareas WBS
  • Comparación de usuarios: userEquals(), userEqualsToContextUser(), areUsersInSameGroup() — métodos de utilidad para verificaciones comunes de identidad/similitud de usuarios
  • Acceso al historial: hasHistoryAccess(), hasLoggedInUserHistoryAccess() — indica si el usuario puede ver el historial de cambios de una entidad

Patrón de diseño — parámetro throwException: Muchos métodos tienen una variante boolean throwException. Cuando es true, la denegación lanza AccessException; cuando es false, devuelve boolean. Esto permite a los llamantes verificar el acceso sin la sobrecarga del manejo de excepciones cuando solo necesitan una respuesta sí/no, y obtener una excepción automática con mensaje i18n cuando el fallo debe abortar la operación.

Jerarquía de excepciones en prefijos de métodos: Los métodos check* (ej. checkIsLoggedInUserMemberOfAdminGroup()) son void y siempre lanzan excepción al fallar. Los métodos has* devuelven boolean y solo lanzan excepción si throwException=true.
