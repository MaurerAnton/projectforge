#654 : AccessChecker.java

projectforge-business/src/main/java/org/projectforge/framework/access/AccessChecker.java Lignes : 275 · Auteur : Kai Reinhard · Type : Interface Java — interface la plus réutilisée 275 lignes · 76 code · 149 commentaires · 50 vides

Contrat central de contrôle d'accès — 275 lignes, 30+ méthodes. Décrit comme « méthodes d'aide pour l'évaluation de l'accès utilisateur et groupe ». Chaque page, chaque contrôleur REST, chaque DAO appelle cette interface (via le singleton statique) avant d'effectuer des opérations protégées. Implémentée par AccessCheckerImpl (853 lignes).

Catégories de méthodes :

  • Vérifications admin : isUserMemberOfAdminGroup(), checkIsLoggedInUserMemberOfAdminGroup(), isLoggedInUserMemberOfAdminGroup() — variantes avec/sans levée d'exception, pour utilisateur explicite et utilisateur contextuel
  • Utilisateur restreint/démo : isRestrictedUser(), isDemoUser(), checkRestrictedOrDemoUser() — l'utilisateur démo est détecté par le nom d'utilisateur "demo" (assistant statique à la ligne 76 compare le nom d'utilisateur), l'utilisateur restreint est un indicateur en base de données. Ces vérifications empêchent les utilisateurs restreints/démo d'effectuer des opérations d'écriture
  • Appartenance à un groupe : isUserMemberOfGroup(user, throwException, groups...) — vérifie par rapport aux constantes ProjectForgeGroup (ADMIN, FINANCE, RH, etc.). Le paramètre varargs groups signifie « au moins un de » — l'utilisateur doit être dans l'un des groupes spécifiés
  • Vérifications de droits : hasRight(), hasLoggedInUserRight(), checkUserRight() — évalue les instances UserRight enregistrées par IUserRightId avec la UserRightValue demandée (TRUE/FALSE/INHERIT). Valeurs multiples via varargs — « au moins une doit correspondre »
  • Accès au niveau ligne : hasAccess(user, rightId, obj, oldObj, operationType, throwException), hasInsertAccess(), hasReadAccess(), hasWriteAccess() — les permissions centrales au niveau entité. Quand throwException=true, la vérification devient obligatoire — le refus lève une AccessException
  • Permissions de tâche : hasPermission(user, taskId, accessType, operationType, throwException) — vérifie l'accès au niveau tâche via les permissions de groupe de l'arbre WBS de la tâche
  • Comparaison d'utilisateurs : userEquals(), userEqualsToContextUser(), areUsersInSameGroup() — méthodes utilitaires pour les vérifications courantes d'identité/similarité d'utilisateurs
  • Accès à l'historique : hasHistoryAccess(), hasLoggedInUserHistoryAccess() — indique si l'utilisateur peut consulter l'historique des modifications d'une entité

Patron de conception — paramètre throwException : De nombreuses méthodes ont une variante boolean throwException. Quand true, le refus lève une AccessException ; quand false, retourne un boolean. Cela permet aux appelants de vérifier l'accès sans la surcharge de gestion des exceptions lorsqu'ils ont seulement besoin d'une réponse oui/non, et d'obtenir une exception automatique avec un message i18n lorsque l'échec doit interrompre l'opération.

Hiérarchie des exceptions dans les préfixes de méthodes : Les méthodes check* (par ex. checkIsLoggedInUserMemberOfAdminGroup()) sont void et lèvent toujours une exception en cas d'échec. Les méthodes has* retournent un booléen et ne lèvent une exception que si throwException=true.
