#654: AccessChecker.java

projectforge-business/src/main/java/org/projectforge/framework/access/AccessChecker.java Строк: 275 · Автор: Kai Reinhard · Тип: Интерфейс Java — наиболее часто используемый интерфейс 275 строк · 76 кода · 149 комментариев · 50 пустых

Центральный контракт управления доступом — 275 строк, 30+ методов. Описан как «вспомогательные методы для оценки доступа пользователя и группы». Каждая страница, каждый REST-контроллер, каждый DAO вызывает этот интерфейс (через статический синглтон) перед выполнением защищённых операций. Реализован в AccessCheckerImpl (853 строки).

Категории методов:

  • Проверки администратора: isUserMemberOfAdminGroup(), checkIsLoggedInUserMemberOfAdminGroup(), isLoggedInUserMemberOfAdminGroup() — варианты с/без выбрасывания исключения, как для явного пользователя, так и для контекстного
  • Ограниченный/демо-пользователь: isRestrictedUser(), isDemoUser(), checkRestrictedOrDemoUser() — демо-пользователь определяется по имени "demo" (статический помощник в строке 76 сравнивает имя пользователя), ограниченный пользователь — это флаг в базе данных. Эти проверки предотвращают выполнение операций записи демо/ограниченными пользователями
  • Членство в группе: isUserMemberOfGroup(user, throwException, groups...) — проверяет константы ProjectForgeGroup (ADMIN, FINANCE, HR и т.д.). Параметр groups с переменным числом аргументов означает «хотя бы одна из» — пользователь должен состоять в любой из указанных групп
  • Проверки прав: hasRight(), hasLoggedInUserRight(), checkUserRight() — оценивает зарегистрированные экземпляры UserRight по IUserRightId с требуемым UserRightValue (TRUE/FALSE/INHERIT). Несколько значений через переменное число аргументов — «хотя бы одно должно совпадать»
  • Доступ на уровне строк: hasAccess(user, rightId, obj, oldObj, operationType, throwException), hasInsertAccess(), hasReadAccess(), hasWriteAccess() — основные разрешения на уровне сущностей. Когда throwException=true, проверка становится обязательной — отказ вызывает AccessException
  • Разрешения задач: hasPermission(user, taskId, accessType, operationType, throwException) — проверяет доступ на уровне задачи через групповые разрешения дерева задач WBS
  • Сравнение пользователей: userEquals(), userEqualsToContextUser(), areUsersInSameGroup() — служебные методы для стандартных проверок идентичности/сходства пользователей
  • Доступ к истории: hasHistoryAccess(), hasLoggedInUserHistoryAccess() — может ли пользователь просматривать историю изменений сущности

Шаблон проектирования — параметр throwException: Многие методы имеют вариант с boolean throwException. Когда true, отказ вызывает AccessException; когда false, возвращается boolean. Это позволяет вызывающим сторонам проверять доступ без обработки исключений, когда нужен только ответ да/нет, и получать автоматическое исключение с i18n-сообщением, когда сбой должен прервать операцию.

Иерархия исключений в префиксах методов: Методы check* (например, checkIsLoggedInUserMemberOfAdminGroup()) ничего не возвращают и всегда выбрасывают исключение при неудаче. Методы has* возвращают boolean и выбрасывают исключение только если throwException=true.
