projectforge-business/src/main/java/org/projectforge/framework/access/AccessControlInterface.java Lignes : 87 · Auteur : Kai Reinhard · Type : Interface Java — contrat de contrôle d'accès au niveau DO 87 lignes · 12 code · 65 commentaires · 10 vides

Interface pour le contrôle d'accès par DO en mode applicatif « restreint ». 87 lignes. Le Javadoc indique : « Toutes les méthodes de cette interface doivent être implémentées par chaque classe DOAccessControl nécessaire à chaque classe DO en mode applicatif access-type='restricted' (mode productif). » — ceci concerne les déploiements de production où le contrôle d'accès doit être appliqué au niveau DO.

Cinq méthodes de vérification CRUD :

  • checkFind(List list, PFUserDO user) — filtrage post-requête. La liste est déjà chargée depuis la base de données. L'implémentation peut supprimer les entrées que l'utilisateur ne doit pas voir (retourne la liste filtrée). C'est la seule méthode qui modifie la liste — toutes les autres lèvent des exceptions en cas de refus
  • checkLoad(Object obj, PFUserDO user) — appelée lors du chargement d'un objet unique par son ID. Si l'utilisateur ne doit pas le voir, lève une AccessException
  • checkSave(Object obj, PFUserDO user) — appelée avant INSERT. Peut modifier les propriétés de l'objet (ex. définir owner sur l'utilisateur courant) pour satisfaire les règles d'accès
  • checkUpdate(Object obj, PFUserDO user) — appelée avant UPDATE. Même capacité de modification que save
  • checkDestroy(Object obj, PFUserDO user) — appelée avant DELETE. Aucune modification — seulement autoriser ou refuser

Philosophie de conception : CheckSave/CheckUpdate peuvent modifier l'objet pour appliquer les règles d'accès (ex. forcer la propriété de l'objet à l'utilisateur courant), tandis que CheckLoad/CheckDestroy ne le peuvent pas — elles autorisent ou lèvent une exception. Il s'agit de l'approche de contrôle d'accès de l'ère pré-AOP, avant que les annotations @PreAuthorize et la sécurité méthodique Spring Security ne deviennent la norme. L'interface utilise des types Object bruts — pas de génériques — car elle opère au niveau du framework où les types DO ne sont pas connus à la compilation.
