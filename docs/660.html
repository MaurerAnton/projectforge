#660: DayMonthYearHolder.java

Lines: 110 · Author: Kai Reinhard · Type: Java Serializable — XStream-annotated

Timezone-free date representation — three integer values without time-of-day. 110 lines. Described as "no time zone information" — deliberately avoids java.time.LocalDate or java.util.Date because those carry timezone context. Used in XML configuration serialization and calendar date comparisons where timezone ambiguity would cause bugs.

Fields: dayOfMonth (short, default 1), month (short, default 1 = January — note: 1-based, unlike the old ConfigureHoliday which was 0-based before v7), year (int, default 1970 — Unix epoch). All annotated @XStreamAsAttribute — when serialized to XML, they appear as attributes of the <day> element: <day dayOfMonth="25" month="12" year="2025"/>.

Design — no timezone vs LocalDate: This was created before Java 8's LocalDate became standard in ProjectForge. A LocalDate would serve the same purpose (date without time/timezone) but wasn't available in the older Java versions ProjectForge targeted. This class and DayHolder (#721) are the pre-Java-8 era date types that persist in the codebase. The "Holder" suffix is a common pattern in ProjectForge — a thin wrapper around primitive values with getters/setters and serialization annotations.

Chaining setters: All three setters return this for fluent API: new DayMonthYearHolder().setDayOfMonth(25).setMonth(12).setYear(2025).

Type choices: Day and month are short (smallest integer type sufficient for 1-31 and 1-12), year is int (to support years beyond 32767). No validation — Javadoc explicitly says "No sanity check will be done" for setters, meaning setMonth(99) compiles and runs without error. Callers are responsible for providing valid values.
