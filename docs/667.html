#667: ApplicationContextProvider.java

Lines: 52 · Author: Roger Rene Kommer · Type: Java @Component — ApplicationContextAware

Static access bridge to Spring ApplicationContext for non-Spring-managed code. 52 lines. Implements ApplicationContextAware — Spring calls setApplicationContext() after the context is initialized, storing it in a static field. This allows code that is NOT managed by Spring (e.g. Wicket components, static utility methods, Groovy scripts, JPA entity listeners) to access Spring beans via ApplicationContextProvider.getApplicationContext().getBean(MyService.class).

Key problem solved: ProjectForge has a hybrid architecture — Spring Boot for the application layer, Wicket for legacy web pages, and Groovy for scripting. Wicket components and Groovy scripts are not Spring-managed, so they can't use @Autowired. This class is the standard escape hatch — a few dozen places in the codebase call ApplicationContextProvider.getApplicationContext() to get Spring beans. This is a deliberate anti-pattern acknowledged by the Javadoc: "for implementation, which has no possibilities to be registered itself as spring bean."
