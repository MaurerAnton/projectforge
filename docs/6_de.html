#6: Dockerfile

Dockerfile

Pfad: ./Dockerfile · Typ: Docker-Build-Anweisungen · Zeilen: 43 · Quelle: GitHub

43 Zeilen · 16 Code · 13 Kommentare · 14 Leerzeichen

Was es tut

Erstellt das ProjectForge-Docker-Image – ein 43-zeiliges Dockerfile, das einen minimalen, rootlosen Java-17-Container mit einem Volume für persistente Daten erzeugt. Das Image enthält 4 Komponenten, die durch entrypoint.sh verbunden sind:

Dockerfile-Komponenten: ┌─────────────────────────────────────────────┐ │ /app/application.jar ← Zeile 12 │ │ /app/entrypoint.sh ← Zeile 13 │ │ /ProjectForge/ ← Zeile 31 (VOLUME) │ │ ├─ environment.sh ← Zeile 34 │ │ └─ projectforge.properties (Laufzeit) │ └─────────────────────────────────────────────┘

Abschnitt für Abschnitt

Zeilen 1–7: Basis-Image und Einrichtung

1  FROM openjdk:17-slim
4  ARG JAR_FILE
7  WORKDIR /app

openjdk:17-slim: Die schlanke Variante schließt unnötige Pakete aus (Compiler, Dokumentation) – kleinere Angriffsfläche und schnellere Downloads. ARG JAR_FILE ist ein Build-Zeit-Argument, das über --build-arg JAR_FILE=... in docker build übergeben wird, typischerweise von build.gradle.kts gesetzt, um auf das erstellte Fat-JAR zu verweisen.

Zeilen 9–16: Dateien kopieren

9  RUN mkdir -p /app
12 COPY ${JAR_FILE} /app/application.jar        ← Fat-JAR aus dem Build
13 COPY docker/entrypoint.sh /app/entrypoint.sh  ← Startskript
16 RUN chmod +x /app/entrypoint.sh               ← ausführbar machen

Zwei Dateien werden kopiert: das Spring-Boot-Fat-JAR (umbenannt in application.jar) und das entrypoint.sh-Skript (ausführbar gemacht). Das ARG JAR_FILE aus Zeile 4 wird hier zur Build-Zeit ersetzt.

Zeile 19: Port-Freigabe

19 EXPOSE 8080

8080 ist der Standard-Spring-Boot-Port. Beachten Sie, dass EXPOSE nur dokumentierend ist – es veröffentlicht den Port nicht tatsächlich. Das eigentliche Port-Mapping erfolgt in docker-compose.yml Zeile 12 (ports: - "8080:8080").

Zeilen 22–27: Nicht-Root-Benutzer + procps

22 RUN addgroup --system projectforge && \
      adduser --system --ingroup projectforge projectforge
27 RUN apt-get update && apt-get install -y procps && \
      rm -rf /var/lib/apt/lists/*

Sicherheit: Läuft als Nicht-Root-Benutzer (projectforge:projectforge). Das Flag --system erstellt ein Systemkonto (kein Home-Verzeichnis, keine Login-Shell, UID < 1000). Das Paket procps stellt pgrep bereit, das von entrypoint.sh Zeile 14 für die Funktion checkStopped() benötigt wird. Die Bereinigung rm -rf /var/lib/apt/lists/* ist gängige Docker-Praxis – entfernt den Paket-Cache, um das Image klein zu halten.

Zeilen 30–32: Volume

31 RUN mkdir -p /ProjectForge && chown -R projectforge:projectforge /ProjectForge
32 VOLUME /ProjectForge

Die VOLUME-Deklaration teilt Docker mit, dass dieses Verzeichnis persistente Daten enthält – die Konfigurationsdatei projectforge.properties, die eingebettete HSQLDB-Datenbank und Logs. Ohne ein Volume gingen alle Daten beim Neustart des Containers verloren. Das Verzeichnis gehört dem Nicht-Root-Benutzer, damit der Java-Prozess darauf schreiben kann.

Zeile 34: Umgebungsvorlage

34 COPY docker/environment.sh /ProjectForge

Kopiert die Vorlage aus docker/environment.sh in das Volume. Da /ProjectForge ein VOLUME ist, sind hier zur Build-Zeit kopierte Dateien nur beim ersten Start sichtbar – wenn ein externes Volume eingehängt wird, überschattet es diese Kopie. Dies ist beabsichtigt: Die Vorlage dient der Ersteinrichtung, danach übernimmt die angepasste Version des Administrators.

Zeilen 37–43: Einstiegspunkt

37 USER projectforge:projectforge                  ← Wechsel zu Nicht-Root
40 ENTRYPOINT ["/app/entrypoint.sh"]               ← JSON-Exec-Form
41 # ENTRYPOINT ["java", "-jar", "/app/application.jar"]  ← Umgehung (auskommentiert)
43 LABEL maintainer="Micromata"

Zeile 40: Verwendet die JSON-Exec-Form von ENTRYPOINT (Array-Syntax) – diese ruft keine Shell auf, sodass Signale direkt an entrypoint.sh weitergeleitet werden. Zeile 41 ist auskommentiert: Auskommentieren, um die Herunterfahrlogik in entrypoint.sh zu umgehen und Java direkt auszuführen (nützlich zum Debuggen).

Wichtige Erkenntnisse

  • 43 Zeilen, minimal: Nur procps (für pgrep) wurde über das Basis-Java-Image hinaus hinzugefügt.
  • Rootlos: Läuft als projectforge:projectforge – gute Docker-Sicherheitspraxis.
  • Drei Kopien, ein Volume: JAR + Einstiegspunkt → /app (unveränderlich), environment.sh → /ProjectForge (persistent).
  • Schlankes JRE: openjdk:17-slim – das vollständige JDK wird zur Laufzeit nicht benötigt.
  • Umgehungsschalter: Zeile 41 auskommentieren, um entrypoint.sh für die direkte Java-Ausführung zu überspringen.
