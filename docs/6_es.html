#6: Dockerfile

Dockerfile

Ruta: ./Dockerfile · Tipo: Instrucciones de compilación Docker · Líneas: 43 · Fuente: GitHub

43 líneas · 16 código · 13 comentarios · 14 en blanco

Qué hace

Construye la imagen Docker de ProjectForge — un Dockerfile de 43 líneas que crea un contenedor mínimo, sin root y con Java 17, que incluye un volumen para datos persistentes. La imagen contiene 4 componentes conectados por entrypoint.sh:

Componentes del Dockerfile: ┌─────────────────────────────────────────────┐ │ /app/application.jar ← línea 12 │ │ /app/entrypoint.sh ← línea 13 │ │ /ProjectForge/ ← línea 31 (VOLUMEN) │ │ ├─ environment.sh ← línea 34 │ │ └─ projectforge.properties (en tiempo de ejecución) │ └─────────────────────────────────────────────┘

Sección por sección

Líneas 1–7: Imagen base y configuración

1  FROM openjdk:17-slim
4  ARG JAR_FILE
7  WORKDIR /app

openjdk:17-slim: La variante slim excluye paquetes innecesarios (compiladores, documentación) — menor superficie de ataque y descarga más rápida. ARG JAR_FILE es un argumento en tiempo de compilación que se pasa mediante --build-arg JAR_FILE=... en docker build, normalmente definido por build.gradle.kts para apuntar al fat JAR compilado.

Líneas 9–16: Copia de archivos

9  RUN mkdir -p /app
12 COPY ${JAR_FILE} /app/application.jar        ← fat JAR de la compilación
13 COPY docker/entrypoint.sh /app/entrypoint.sh  ← script de inicio
16 RUN chmod +x /app/entrypoint.sh               ← hacerlo ejecutable

Se copian dos archivos: el fat JAR de Spring Boot (renombrado a application.jar) y el script entrypoint.sh (se le otorgan permisos de ejecución). El ARG JAR_FILE de la línea 4 se sustituye aquí durante la compilación.

Línea 19: Exposición de puerto

19 EXPOSE 8080

8080 es el puerto predeterminado de Spring Boot. Nótese que EXPOSE es solo documentación — no publica el puerto realmente. El mapeo real del puerto se realiza en docker-compose.yml, línea 12 (ports: - "8080:8080").

Líneas 22–27: Usuario no root + procps

22 RUN addgroup --system projectforge && \
      adduser --system --ingroup projectforge projectforge
27 RUN apt-get update && apt-get install -y procps && \
      rm -rf /var/lib/apt/lists/*

Seguridad: se ejecuta como un usuario no root (projectforge:projectforge). La bandera --system crea una cuenta de sistema (sin directorio home, sin shell de inicio de sesión, UID < 1000). El paquete procps proporciona pgrep, necesario para la función checkStopped() en la línea 14 de entrypoint.sh. La limpieza rm -rf /var/lib/apt/lists/* es una práctica estándar en Docker — elimina la caché de paquetes para mantener la imagen pequeña.

Líneas 30–32: Volumen

31 RUN mkdir -p /ProjectForge && chown -R projectforge:projectforge /ProjectForge
32 VOLUME /ProjectForge

La declaración VOLUME le indica a Docker que este directorio contiene datos persistentes — el archivo de configuración projectforge.properties, la base de datos HSQLDB embebida y los registros. Sin un volumen, todos los datos se perderían al reiniciar el contenedor. El directorio es propiedad del usuario no root para que el proceso de Java pueda escribir en él.

Línea 34: Plantilla de entorno

34 COPY docker/environment.sh /ProjectForge

Copia la plantilla desde docker/environment.sh al interior del volumen. Dado que /ProjectForge es un VOLUMEN, los archivos copiados aquí durante la compilación serán visibles solo en la primera ejecución — si se monta un volumen externo, este sobrescribe la copia. Esto es intencional: la plantilla está ahí para la configuración inicial, pero después la versión personalizada del administrador toma el control.

Líneas 37–43: Punto de entrada

37 USER projectforge:projectforge                  ← cambiar a no root
40 ENTRYPOINT ["/app/entrypoint.sh"]               ← formato exec JSON
41 # ENTRYPOINT ["java", "-jar", "/app/application.jar"]  ← bypass (comentado)
43 LABEL maintainer="Micromata"

Línea 40: Utiliza el formato exec JSON de ENTRYPOINT (sintaxis de arreglo) — esto no invoca un shell, por lo que las señales se pasan directamente a entrypoint.sh. La línea 41 está comentada: descomentarla para omitir la lógica de apagado en entrypoint.sh y ejecutar Java directamente (útil para depuración).

Conclusiones clave

  • 43 líneas, mínimo: Solo se añade procps (para pgrep) además de la imagen base de Java.
  • Sin root: Se ejecuta como projectforge:projectforge — buena práctica de seguridad en Docker.
  • Tres copias, un volumen: JAR + entrypoint → /app (inmutable), environment.sh → /ProjectForge (persistente).
  • JRE ligero: openjdk:17-slim — el JDK completo no es necesario en tiempo de ejecución.
  • Interruptor de bypass: Descomentar la línea 41 para saltar entrypoint.sh y ejecutar Java directamente.
