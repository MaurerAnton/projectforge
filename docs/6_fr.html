#6 : Dockerfile

Dockerfile

Chemin : ./Dockerfile · Type : Instructions de construction Docker · Lignes : 43 · Source : GitHub

43 lignes · 16 de code · 13 commentaires · 14 lignes vides

Ce qu'il fait

Construit l'image Docker de ProjectForge — un Dockerfile de 43 lignes qui crée un conteneur Java 17 minimal et sans privilèges avec un volume pour les données persistantes. L'image contient 4 composants reliés par entrypoint.sh :

Composants du Dockerfile : ┌─────────────────────────────────────────────┐ │ /app/application.jar ← ligne 12 │ │ /app/entrypoint.sh ← ligne 13 │ │ /ProjectForge/ ← ligne 31 (VOLUME) │ │ ├─ environment.sh ← ligne 34 │ │ └─ projectforge.properties (exécution) │ └─────────────────────────────────────────────┘

Section par section

Lignes 1–7 : Image de base et configuration

1  FROM openjdk:17-slim
4  ARG JAR_FILE
7  WORKDIR /app

openjdk:17-slim : La variante slim exclut les paquets inutiles (compilateurs, documentation) — surface d'attaque réduite et téléchargement plus rapide. ARG JAR_FILE est un argument de construction passé via --build-arg JAR_FILE=... dans docker build, généralement défini par build.gradle.kts pour pointer vers le fat JAR construit.

Lignes 9–16 : Copie des fichiers

9  RUN mkdir -p /app
12 COPY ${JAR_FILE} /app/application.jar        ← fat JAR de la construction
13 COPY docker/entrypoint.sh /app/entrypoint.sh  ← script de démarrage
16 RUN chmod +x /app/entrypoint.sh               ← rendre exécutable

Deux fichiers copiés : le fat JAR Spring Boot (renommé en application.jar) et le script entrypoint.sh (rendu exécutable). Le ARG JAR_FILE de la ligne 4 est substitué ici au moment de la construction.

Ligne 19 : Exposition du port

19 EXPOSE 8080

8080 est le port Spring Boot par défaut. Notez que EXPOSE est uniquement documentaire — il ne publie pas réellement le port. Le mappage réel du port est effectué dans docker-compose.yml ligne 12 (ports: - "8080:8080").

Lignes 22–27 : Utilisateur non-root + procps

22 RUN addgroup --system projectforge && \
      adduser --system --ingroup projectforge projectforge
27 RUN apt-get update && apt-get install -y procps && \
      rm -rf /var/lib/apt/lists/*

Sécurité : s'exécute en tant qu'utilisateur non-root (projectforge:projectforge). Le drapeau --system crée un compte système (pas de répertoire personnel, pas de shell de connexion, UID < 1000). Le paquet procps fournit pgrep, nécessaire à entrypoint.sh ligne 14 pour la fonction checkStopped(). Le nettoyage rm -rf /var/lib/apt/lists/* est une pratique Docker standard — supprime le cache des paquets pour garder l'image légère.

Lignes 30–32 : Volume

31 RUN mkdir -p /ProjectForge && chown -R projectforge:projectforge /ProjectForge
32 VOLUME /ProjectForge

La déclaration VOLUME indique à Docker que ce répertoire contient des données persistantes — le fichier de configuration projectforge.properties, la base de données HSQLDB embarquée et les journaux. Sans volume, toutes les données seraient perdues lors du redémarrage du conteneur. Le répertoire appartient à l'utilisateur non-root afin que le processus Java puisse y écrire.

Ligne 34 : Modèle d'environnement

34 COPY docker/environment.sh /ProjectForge

Copie le modèle depuis docker/environment.sh dans le volume. Puisque /ProjectForge est un VOLUME, les fichiers copiés ici lors de la construction ne seront visibles qu'au premier démarrage — si un volume externe est monté, il masque cette copie. C'est intentionnel : le modèle est là pour la configuration initiale, mais ensuite la version personnalisée par l'administrateur prend le relais.

Lignes 37–43 : Point d'entrée

37 USER projectforge:projectforge                  ← passage à non-root
40 ENTRYPOINT ["/app/entrypoint.sh"]               ← forme exec JSON
41 # ENTRYPOINT ["java", "-jar", "/app/application.jar"]  ← contournement (commenté)
43 LABEL maintainer="Micromata"

Ligne 40 : Utilise la forme exec JSON d'ENTRYPOINT (syntaxe tableau) — cela n'invoque pas de shell, donc les signaux sont transmis directement à entrypoint.sh. La ligne 41 est commentée : décommentez-la pour contourner la logique d'arrêt dans entrypoint.sh et exécuter Java directement (utile pour le débogage).

Points clés à retenir

  • 43 lignes, minimal : Seulement procps (pour pgrep) ajouté en plus de l'image Java de base.
  • Sans privilèges : S'exécute en tant que projectforge:projectforge — bonne pratique de sécurité Docker.
  • Trois copies, un volume : JAR + point d'entrée → /app (immuable), environment.sh → /ProjectForge (persistant).
  • JRE léger : openjdk:17-slim — le JDK complet n'est pas nécessaire à l'exécution.
  • Interrupteur de contournement : Décommentez la ligne 41 pour sauter entrypoint.sh et exécuter Java directement.
