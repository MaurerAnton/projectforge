#703: ReflectionToString.java

projectforge-business/src/main/java/org/projectforge/framework/persistence/utils/ReflectionToString.java Java-Utility — Hibernate-bewusster, reflexionsbasierter toString()-Builder, projectforge-business/src/main/java/org/projectforge/framework/persistence/utils/ReflectionToString.java 118 Zeilen · 82 Code · 28 Kommentare · 8 leer
Erweitert Apache Commons Lang3 ReflectionToStringBuilder, um eine sichere, menschenlesbare toString()-Ausgabe für JPA-Entitäten zu erzeugen. Behandelt Hibernate-Lazy-Proxys, nicht initialisierte Collections, BaseDO-IDs, DisplayNameCapable-Bezeichnungen und TimeZone-Objekte, ohne eine LazyInitializationException auszulösen. Der einzige statische Einstiegspunkt ReflectionToString.asString(obj) wird in der gesamten Codebasis verwendet, wann immer eine Debug-/Log-Ausgabe von Domänenobjekten benötigt wird.

Architektur

Klassenhierarchie

ReflectionToString erweitert org.apache.commons.lang3.builder.ReflectionToStringBuilder (Apache Commons Lang3). Intern durchläuft ReflectionToStringBuilder mittels Java-Reflection alle deklarierten Felder eines Objekts (und seiner Oberklassen) und hängt jedes Feldname/Wert-Paar an einen ToStringBuilder an. Diese Klasse überschreibt drei Schlüsselmethoden, um Hibernate-Bewusstsein zu integrieren.

MethodeZweck der Überschreibung
ReflectionToString(Object) (Konstruktor)Prüft, ob das Wurzelobjekt mittels Hibernate.isInitialized() initialisiert ist. Falls nicht, wird ein synthetischer String wie "Lazy" + className + "@" + identityHash anstelle des tatsächlichen Proxys übergeben, wodurch eine LazyInitializationException von Anfang an verhindert wird.
append(String, Object)Der Kern der Hibernate-sicheren Logik. Bevor jeder Feldwert angehängt wird, wird Hibernate.isInitialized() geprüft und basierend auf dem Typ des Werts eine spezialisierte Formatierung angewendet.
accept(Field)Filtert Felder heraus, deren Werte nicht initialisierte Hibernate-Proxys sind. Anstatt sie stillschweigend zu überspringen, wird direkt append() aufgerufen (was die Proxy-Informationen darstellt) und false zurückgegeben, damit die Oberklasse das Feld nicht doppelt verarbeitet.

Entscheidungsbaum zur Wertbehandlung in append()

Wenn append(fieldName, object) aufgerufen wird, kommt die folgende Logik in der angegebenen Reihenfolge zur Anwendung:

  1. Null: wird an die Oberklasse durchgereicht (stellt <null> dar).
  2. Nicht Hibernate-initialisiert:
    • Wenn BaseDO — wird der Identifikator mittels HibernateUtils.getIdentifier() extrahiert; stellt die numerische oder String-ID dar (oder "<id>", falls null).
    • Andernfalls — wird das String-Literal "LazyCollection" dargestellt.
  3. Initialisiert und DisplayNameCapable: delegiert an die private myToString()-Methode, die für BaseDO-Objekte "id:displayName" oder für Nicht-DO-Objekte nur den Anzeigenamen darstellt.
  4. Initialisiert und BaseDO: stellt die Entitäts-ID allein dar.
  5. Collection: iteriert über die Elemente, ruft für jedes myToString() auf, formatiert als [el1, el2, ...]. Vermeidet das standardmäßige toString() der Collection, das rekursiv ReflectionToString auf jedes Element aufrufen und die Ausgabe potenziell aufblähen würde.
  6. TimeZone: stellt die Zeitzonen-ID als String dar (z.B. "Europe/Berlin") anstelle des vollständigen TimeZone.toString().
  7. Andernfalls: wird an die Oberklasse durchgereicht.

Logik der privaten Methode myToString(Object)

Behandelt Sonderfälle: null → "<null>", dann DisplayNameCapable-Objekte (mit BaseDO-Präfix der ID), BaseDO-Objekte (nur ID) und fällt schließlich für alle anderen Typen auf obj.toString() zurück.

Javassist-Workaround

Wenn append() auf ein nicht initialisiertes BaseDO-Objekt trifft, wird HibernateUtils.getIdentifier() aufgerufen, anstatt das eigene getId() des Proxys zu verwenden. Der Kommentar im Quelltext weist darauf hin, dass dies ein „Workaround für einen Javassist-Fehler“ ist – Javassist-Proxys (von Hibernate verwendet) können bei Methodenaufrufen auf nicht initialisierten Proxys ein falsches Verhalten zeigen, daher wird die Framework-Utility bevorzugt, um die ID direkt aus den Proxy-Metadaten zu extrahieren.

Integrationspunkte

  • Wird als Standard-toString()-Implementierung in BaseDO und seinen Unterklassen verwendet (jedes Domänenobjekt in ProjectForge).
  • Wird von Logging-Anweisungen in der gesamten Geschäftslogikschicht konsumiert – jeder Aufruf von log.debug("entity: {}", entity) löst diesen Formatierer über das toString() der Entität aus.
  • Abhängig von HibernateUtils.getIdentifier() für die sichere ID-Extraktion aus Proxys.
  • Verlässt sich auf Apache Commons Lang3 ReflectionToStringBuilder für das Reflexionsschleifen-Grundgerüst.

Designentscheidungen & Fallstricke

  • Leistung: Reflexionsbasiertes toString ist von Natur aus langsam. Dies ist akzeptabel, da es nur für Debug-/Log-Ausgaben verwendet wird, niemals in heißen Codepfaden. Der accept()-Filter verhindert, dass es in nicht initialisierte Lazy-Assoziationen absteigt, die Datenbankabfragen auslösen würden.
  • Nicht initialisierte Collections: Die accept()-Methode ruft getValue(field) auf, was den Feldzugriff erzwingt. Wenn das Feld eine nicht initialisierte PersistentCollection enthält, gibt Hibernate.isInitialized() false zurück und das Feld wird inline behandelt – es erfolgt kein Datenbankzugriff.
  • Zirkuläre Referenzen: Die Collection-Behandlung in append() verwendet myToString() (das IDs/Anzeigenamen darstellt) anstelle von toString() auf Collection-Elementen. Dies verhindert eine Endlosrekursion, wenn Entitäten bidirektionale @OneToMany/@ManyToOne-Beziehungen haben.
  • TimeZone-Sonderfall: Javas standardmäßiges TimeZone.toString() erzeugt eine lange Ausgabe mit Offset-Details. Diese Überschreibung extrahiert nur die ID und hält die Ausgabe prägnant.
