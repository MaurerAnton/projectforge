Extiende ReflectionToStringBuilder de Apache Commons Lang3 para producir una salida toString() segura y legible para entidades JPA. Maneja proxies perezosos de Hibernate, colecciones no inicializadas, IDs de BaseDO, etiquetas DisplayNameCapable y objetos TimeZone sin provocar LazyInitializationException. El único punto de entrada estático ReflectionToString.asString(obj) se utiliza en toda la base de código cuando se necesita salida de depuración/registro de objetos de dominio.

Arquitectura

Jerarquía de clases

ReflectionToString extiende org.apache.commons.lang3.builder.ReflectionToStringBuilder (Apache Commons Lang3). Internamente, ReflectionToStringBuilder usa reflexión de Java para recorrer todos los campos declarados de un objeto (y sus superclases), añadiendo cada par nombre/valor de campo a un ToStringBuilder. Esta clase sobrescribe tres métodos clave para inyectar la compatibilidad con Hibernate.

MétodoPropósito de la sobrescritura
ReflectionToString(Object) (constructor) Verifica si el objeto raíz está inicializado mediante Hibernate.isInitialized(). Si no lo está, pasa una cadena sintética como "Lazy" + className + "@" + identityHash en lugar del proxy real, evitando LazyInitializationException desde el inicio.
append(String, Object) El núcleo de la lógica segura para Hibernate. Antes de añadir cada valor de campo, verifica Hibernate.isInitialized() y aplica un formato especializado según el tipo del valor.
accept(Field) Filtra los campos cuyos valores son proxies de Hibernate no inicializados. En lugar de omitirlos silenciosamente, llama directamente a append() (que mostrará la información del proxy) y devuelve false para que la superclase no procese el campo dos veces.

Árbol de decisión del manejo de valores en append()

Cuando se llama a append(fieldName, object), se aplica la siguiente lógica en orden:

  1. Null: se pasa a la superclase (muestra <null>).
  2. No inicializado por Hibernate:
    • Si es BaseDO — extrae el identificador mediante HibernateUtils.getIdentifier(); muestra el ID numérico o de cadena (o "<id>" si es nulo).
    • De lo contrario — muestra el literal de cadena "LazyCollection".
  3. Inicializado y DisplayNameCapable: delega en el método privado myToString() que muestra "id:displayName" para objetos BaseDO o solo el nombre mostrado para objetos que no son DO.
  4. Inicializado y BaseDO: muestra solo el ID de la entidad.
  5. Collection: itera sobre los elementos, llama a myToString() en cada uno, formatea como [el1, el2, ...]. Evita el toString() predeterminado de la colección, que llamaría recursivamente a ReflectionToString en cada elemento y podría explotar la salida.
  6. TimeZone: muestra la cadena de ID de la zona horaria (ej. "Europe/Berlin") en lugar del TimeZone.toString() completo.
  7. De lo contrario: se pasa a la superclase.

Lógica de myToString(Object) privado

Casos especiales: null → "<null>", luego objetos DisplayNameCapable (con BaseDO anteponiendo el ID), objetos BaseDO (solo ID), y finalmente recurre a obj.toString() para todos los demás tipos.

Solución para Javassist

Cuando append() encuentra un objeto BaseDO no inicializado, llama a HibernateUtils.getIdentifier() en lugar de usar el getId() del propio proxy. El comentario en la fuente indica que esto es una "solución para un error de Javassist" — los proxies de Javassist (usados por Hibernate) pueden producir un comportamiento incorrecto al llamar a métodos en proxies no inicializados, por lo que se prefiere la utilidad del framework para extraer el ID directamente de los metadatos del proxy.

Puntos de integración

  • Se utiliza como la implementación predeterminada de toString() en BaseDO y sus subclases (cada objeto de dominio en ProjectForge).
  • Consumido por sentencias de registro en toda la capa de negocio — cualquier log.debug("entity: {}", entity) activará este formateador a través del toString() de la entidad.
  • Depende de HibernateUtils.getIdentifier() para la extracción segura de ID desde proxies.
  • Se basa en ReflectionToStringBuilder de Apache Commons Lang3 para el esqueleto del bucle de reflexión.

Decisiones de diseño y problemas conocidos

  • Rendimiento: El toString basado en reflexión es inherentemente lento. Esto es aceptable porque solo se usa para salida de depuración/registro, nunca en rutas de código críticas. El filtro accept() evita que descienda a asociaciones perezosas no inicializadas que dispararían consultas a la base de datos.
  • Colecciones no inicializadas: El método accept() llama a getValue(field) lo que fuerza el acceso al campo. Si el campo contiene un PersistentCollection no inicializado, Hibernate.isInitialized() devuelve falso y el campo se maneja en línea — no se produce carga de la base de datos.
  • Referencias circulares: El manejo de colecciones en append() usa myToString() (que muestra IDs/nombres mostrados) en lugar de toString() en los elementos de la colección. Esto evita la recursión infinita cuando las entidades tienen relaciones bidireccionales @OneToMany/@ManyToOne.
  • Caso especial de TimeZone: El TimeZone.toString() predeterminado de Java produce una salida larga con detalles de desplazamiento. Esta sobrescritura extrae solo el ID, manteniendo la salida concisa.
