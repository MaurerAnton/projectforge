projectforge-business/src/main/java/org/projectforge/framework/persistence/utils/ReflectionToString.java Utilitaire Java — Constructeur toString() basé sur la réflexion et compatible Hibernate, projectforge-business/src/main/java/org/projectforge/framework/persistence/utils/ReflectionToString.java 118 lignes · 82 lignes de code · 28 commentaires · 8 lignes vides
Étend ReflectionToStringBuilder d'Apache Commons Lang3 pour produire une sortie toString() sûre et lisible pour les entités JPA. Gère les proxies paresseux Hibernate, les collections non initialisées, les IDs BaseDO, les étiquettes DisplayNameCapable et les objets TimeZone sans déclencher de LazyInitializationException. Le point d'entrée statique unique ReflectionToString.asString(obj) est utilisé dans toute la base de code chaque fois qu'une sortie de débogage/journalisation d'objets métier est nécessaire.

Architecture

Hiérarchie des classes

ReflectionToString étend org.apache.commons.lang3.builder.ReflectionToStringBuilder (Apache Commons Lang3). En interne, ReflectionToStringBuilder utilise la réflexion Java pour parcourir tous les champs déclarés d'un objet (et de ses superclasses), en ajoutant chaque paire nom/valeur de champ dans un ToStringBuilder. Cette classe redéfinit trois méthodes clés pour injecter la compatibilité Hibernate.

MéthodeObjectif de la redéfinition
ReflectionToString(Object) (constructeur)Vérifie si l'objet racine est initialisé via Hibernate.isInitialized(). Si ce n'est pas le cas, transmet une chaîne synthétique comme "Lazy" + className + "@" + identityHash au lieu du proxy réel, empêchant ainsi LazyInitializationException dès le départ.
append(String, Object)Le cœur de la logique compatible Hibernate. Avant d'ajouter chaque valeur de champ, vérifie Hibernate.isInitialized() et applique un formatage spécialisé en fonction du type de la valeur.
accept(Field)Filtre les champs dont les valeurs sont des proxies Hibernate non initialisés. Plutôt que de les ignorer silencieusement, appelle directement append() (qui affichera les informations du proxy) et renvoie false pour que la superclasse ne traite pas deux fois le champ.

Arbre de décision du traitement des valeurs dans append()

Lorsque append(fieldName, object) est appelé, la logique suivante s'applique dans l'ordre :

  1. Null : transmet à la superclasse (affiche <null>).
  2. Non initialisé par Hibernate :
    • Si BaseDO — extrait l'identifiant via HibernateUtils.getIdentifier() ; affiche l'ID numérique ou textuel (ou "<id>" si null).
    • Sinon — affiche la chaîne littérale "LazyCollection".
  3. Initialisé et DisplayNameCapable : délègue à la méthode privée myToString() qui affiche "id:displayName" pour les objets BaseDO ou simplement le nom d'affichage pour les objets non-DO.
  4. Initialisé et BaseDO : affiche uniquement l'ID de l'entité.
  5. Collection : itère sur les éléments, appelle myToString() sur chacun, formate comme [el1, el2, ...]. Évite le toString() par défaut des collections qui appellerait récursivement ReflectionToString sur chaque élément et pourrait exploser la sortie.
  6. TimeZone : affiche la chaîne d'ID du fuseau horaire (ex. "Europe/Berlin") au lieu du TimeZone.toString() complet.
  7. Sinon : transmet à la superclasse.

Logique de myToString(Object) privée

Traitement spécial pour null → "<null>", puis objets DisplayNameCapable (avec préfixe d'ID pour BaseDO), objets BaseDO (ID uniquement), et enfin recours à obj.toString() pour tous les autres types.

Contournement Javassist

Lorsque append() rencontre un objet BaseDO non initialisé, il appelle HibernateUtils.getIdentifier() plutôt que d'utiliser le propre getId() du proxy. Le commentaire dans la source note qu'il s'agit d'un "contournement pour un bug Jassist" — les proxies Javassist (utilisés par Hibernate) peuvent produire un comportement incorrect lors de l'appel de méthodes sur des proxies non initialisés, donc l'utilitaire du framework est préféré pour extraire l'ID directement des métadonnées du proxy.

Points d'intégration

  • Utilisé comme implémentation par défaut de toString() dans BaseDO et ses sous-classes (chaque objet métier dans ProjectForge).
  • Consommé par les instructions de journalisation dans toute la couche métier — tout log.debug("entité : {}", entité) déclenchera ce formateur via le toString() de l'entité.
  • Dépend de HibernateUtils.getIdentifier() pour une extraction sûre de l'ID depuis les proxies.
  • Repose sur ReflectionToStringBuilder d'Apache Commons Lang3 pour le squelette de la boucle de réflexion.

Décisions de conception & Pièges

  • Performance : Le toString basé sur la réflexion est intrinsèquement lent. Cela est acceptable car il n'est utilisé que pour la sortie de débogage/journalisation, jamais dans des chemins de code critiques. Le filtre accept() l'empêche de descendre dans les associations paresseuses non initialisées qui déclencheraient des requêtes en base de données.
  • Collections non initialisées : La méthode accept() appelle getValue(field) ce qui force l'accès au champ. Si le champ contient une PersistentCollection non initialisée, Hibernate.isInitialized() renvoie false et le champ est traité en ligne — aucun chargement en base de données n'a lieu.
  • Références circulaires : Le traitement des collections dans append() utilise myToString() (qui affiche les IDs/noms d'affichage) plutôt que toString() sur les éléments de la collection. Cela empêche la récursion infinie lorsque les entités ont des relations bidirectionnelles @OneToMany/@ManyToOne.
  • Cas spécial TimeZone : Le TimeZone.toString() par défaut de Java produit une sortie longue avec des détails de décalage. Cette redéfinition extrait uniquement l'ID, gardant la sortie concise.
