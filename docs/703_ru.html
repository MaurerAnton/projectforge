#703: ReflectionToString.java

projectforge-business/src/main/java/org/projectforge/framework/persistence/utils/ReflectionToString.java Утилита Java — Hibernate-совместимый построитель toString() на основе рефлексии, projectforge-business/src/main/java/org/projectforge/framework/persistence/utils/ReflectionToString.java 118 строк · 82 кода · 28 комментариев · 8 пустых
Расширяет Apache Commons Lang3 ReflectionToStringBuilder для создания безопасного, читаемого вывода toString() для JPA-сущностей. Обрабатывает ленивые прокси Hibernate, неинициализированные коллекции, ID BaseDO, метки DisplayNameCapable и объекты TimeZone без вызова LazyInitializationException. Единая статическая точка входа ReflectionToString.asString(obj) используется во всей кодовой базе везде, где требуется отладочный/логовый вывод доменных объектов.

Архитектура

Иерархия классов

ReflectionToString расширяет org.apache.commons.lang3.builder.ReflectionToStringBuilder (Apache Commons Lang3). Внутренне ReflectionToStringBuilder использует Java-рефлексию для обхода всех объявленных полей объекта (и его суперклассов), добавляя каждую пару имя/значение поля в ToStringBuilder. Этот класс переопределяет три ключевых метода для внедрения Hibernate-совместимости.

МетодЦель переопределения
ReflectionToString(Object) (конструктор)Проверяет, инициализирован ли корневой объект через Hibernate.isInitialized(). Если нет, передает синтетическую строку вида "Lazy" + className + "@" + identityHash вместо реального прокси, предотвращая LazyInitializationException с самого начала.
append(String, Object)Ядро Hibernate-безопасной логики. Перед добавлением каждого значения поля проверяет Hibernate.isInitialized() и применяет специализированное форматирование в зависимости от типа значения.
accept(Field)Отфильтровывает поля, значения которых являются неинициализированными прокси Hibernate. Вместо того чтобы молча пропускать, вызывает append() напрямую (который отобразит информацию о прокси) и возвращает false, чтобы суперкласс не обрабатывал поле дважды.

Дерево решений по обработке значений в append()

Когда вызывается append(fieldName, object), применяется следующая логика по порядку:

  1. Null: передается суперклассу (отображает <null>).
  2. Не инициализировано Hibernate:
    • Если BaseDO — извлекает идентификатор через HibernateUtils.getIdentifier(); отображает числовой или строковый ID (или "<id>", если null).
    • Иначе — отображает строковый литерал "LazyCollection".
  3. Инициализировано и DisplayNameCapable: делегирует приватному myToString(), который отображает "id:displayName" для объектов BaseDO или только отображаемое имя для объектов не-DO.
  4. Инициализировано и BaseDO: отображает только ID сущности.
  5. Collection: перебирает элементы, вызывает myToString() для каждого, форматирует как [el1, el2, ...]. Избегает стандартного toString() коллекции, который рекурсивно вызывал бы ReflectionToString для каждого элемента и потенциально раздувал вывод.
  6. TimeZone: отображает строку ID часового пояса (например, "Europe/Berlin") вместо полного TimeZone.toString().
  7. Иначе: передается суперклассу.

Логика приватного myToString(Object)

Особые случаи: null → "<null>", затем объекты DisplayNameCapable (с префиксом ID для BaseDO), объекты BaseDO (только ID), и в конце — возврат к obj.toString() для всех остальных типов.

Обходной путь для Javassist

Когда append() встречает неинициализированный объект BaseDO, он вызывает HibernateUtils.getIdentifier() вместо использования собственного getId() прокси. Комментарий в исходном коде отмечает, что это "обходной путь для ошибки Javassist" — прокси Javassist (используемые Hibernate) могут давать некорректное поведение при вызове методов на неинициализированных прокси, поэтому предпочтительнее использовать утилиту фреймворка для извлечения ID напрямую из метаданных прокси.

Точки интеграции

  • Используется как реализация toString() по умолчанию в BaseDO и его подклассах (каждый доменный объект в ProjectForge).
  • Потребляется операторами логирования во всем бизнес-слое — любой log.debug("entity: {}", entity) вызовет этот форматтер через toString() сущности.
  • Зависит от HibernateUtils.getIdentifier() для безопасного извлечения ID из прокси.
  • Полагается на Apache Commons Lang3 ReflectionToStringBuilder для каркаса цикла рефлексии.

Проектные решения и подводные камни

  • Производительность: toString на основе рефлексии по своей сути медленный. Это приемлемо, поскольку используется только для отладочного/логового вывода, никогда в горячих путях кода. Фильтр accept() предотвращает погружение в неинициализированные ленивые ассоциации, которые могли бы вызвать запросы к базе данных.
  • Неинициализированные коллекции: Метод accept() вызывает getValue(field), что принудительно обращается к полю. Если поле содержит неинициализированную PersistentCollection, Hibernate.isInitialized() возвращает false, и поле обрабатывается встроенно — загрузки базы данных не происходит.
  • Циклические ссылки: Обработка коллекций в append() использует myToString() (который отображает ID/отображаемые имена) вместо toString() на элементах коллекции. Это предотвращает бесконечную рекурсию, когда сущности имеют двунаправленные отношения @OneToMany/@ManyToOne.
  • Особый случай TimeZone: Стандартный TimeZone.toString() в Java выдает длинный вывод с деталями смещения. Это переопределение извлекает только ID, сохраняя вывод кратким.
