Implementa com.thoughtworks.xstream.converters.Converter para interceptar cada instancia de PersistentCollection antes de que XStream la serialice. Fuerza la inicialización de colecciones de carga diferida, extrae la colección java.util subyacente (manejando la peculiar representación interna de Hibernate de conjuntos como mapas) y delega la escritura real del XML al convertidor XStream estándar apropiado. Este es el convertidor a nivel de valor — el HibernateCollectionsMapper maneja el mapeo a nivel de nombre, y este convertidor maneja los datos reales de la colección.

Arquitectura

Registro del Convertidor

Los convertidores XStream forman una cadena. Cuando XStream encuentra un objeto para serializar, itera sobre los convertidores registrados llamando a canConvert(Class). HibernateCollectionConverter reclama cualquier clase asignable a org.hibernate.collection.spi.PersistentCollection — esto cubre PersistentBag, PersistentList, PersistentSet, PersistentSortedSet, PersistentMap y PersistentSortedMap. Debido a que XStream verifica los convertidores en el orden de registro, este convertidor debe registrarse antes que los convertidores predeterminados. Esto lo hace HibernateMapper al configurar las instancias de XStream.

Constructor: Almacenamiento en Caché de Convertidores

El constructor acepta un ConverterLookup y resuelve inmediatamente y almacena en caché cinco referencias de convertidores:

CampoTipo ConvertidoPropósito
listSetConverterArrayList.classManeja la salida de List y Set
mapConverterHashMap.classManeja la salida de Map
treeMapConverterTreeMap.classManeja la salida de mapas ordenados
treeSetConverterTreeSet.classManeja la salida de conjuntos ordenados
defaultConverterObject.classRespaldo para tipos no reconocidos

Algoritmo marshal()

  1. Convertir a PersistentCollection: Verifica si source instanceof PersistentCollection. Si es así, llama a forceInitialization() para activar la carga diferida, luego recupera getStoredSnapshot() — la colección JDK subyacente que Hibernate usa internamente. (Nota: un comentario TODO hace referencia a getCollectionSnapshot() como una alternativa potencial.)
  2. Solución para PersistentSortedSet: Hibernate almacena conjuntos ordenados internamente como un HashMap donde las claves son los elementos del conjunto. El convertidor extrae .values() y los envuelve en un nuevo TreeSet para restaurar la semántica adecuada de conjunto.
  3. Solución para PersistentSet: Mismo problema — almacenado como HashMap internamente. Extrae .values() y los envuelve en un nuevo HashSet.
  4. Despacho del convertidor: Prueba la clase de colección final contra los convertidores en caché en orden: listSetConverter (para ArrayList/HashSet/TreeSet), mapConverter, treeMapConverter, treeSetConverter. Recurre a defaultConverter.

unmarshal() — No Implementado

unmarshal() devuelve null. Este convertidor es unidireccional — solo maneja serialización (Java→XML). La deserialización (XML→Java) produce colecciones JDK estándar, que luego se asignan a los campos de la entidad. Hibernate las reemplaza con envoltorios persistentes cuando la entidad se adjunta posteriormente a una sesión.

Puntos de Integración

  • Registrado con instancias de XStream a través de HibernateMapper o llamadas directas a xstream.registerConverter().
  • Trabaja en conjunto con HibernateCollectionsMapper: el mapper traduce los nombres de tipo de colección en el XML, mientras que este convertidor traduce los contenidos de la colección en tiempo de serialización.
  • Utilizado por el subsistema de exportación XML (XStreamMarshallingStrategy) que serializa grafos de entidades para archivos XML de respaldo/configuración.

Decisiones de Diseño y Problemas Conocidos

  • forceInitialization(): Esto desencadena una consulta a la base de datos si la colección se cargó de forma diferida pero aún no se había accedido a ella. Para la exportación XML de grafos de entidades grandes, esto puede causar una cascada de consultas. Quien lo llame (típicamente un método de exportación de la capa de servicio) debe asegurarse de que la sesión de Hibernate permanezca abierta y, idealmente, precargar las asociaciones con consultas JOIN FETCH.
  • Particularidad de Hibernate Set-como-Map: Hibernate 3.x/4.x representa internamente tanto PersistentSet como PersistentSortedSet usando estructuras HashMap. El convertidor debe desenvolverlas explícitamente. Si se eliminara esta lógica, XStream serializaría los conjuntos como mapas XML (con elementos clave), produciendo una salida no analizable.
  • Snapshot vs. Colección: El comentario TODO en la línea ~66 sugiere usar getCollectionSnapshot().getSnapshot() en lugar de getStoredSnapshot(). El enfoque actual funciona porque forceInitialization() garantiza que la instantánea almacenada exista, pero esto es frágil entre versiones de Hibernate.
  • Seguridad en hilos: Las referencias de convertidores en caché son inmutables después de la construcción. La instancia es efectivamente segura para hilos para operaciones de solo lectura del convertidor.
