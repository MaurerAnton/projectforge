projectforge-business/src/main/java/org/projectforge/framework/persistence/xstream/HibernateCollectionConverter.java Конвертер XStream — преобразует постоянные коллекции Hibernate в коллекции JDK во время маршалинга, projectforge-business/src/main/java/org/projectforge/framework/persistence/xstream/HibernateCollectionConverter.java 130 строк · 69 кода · 45 комментариев · 16 пустых
Реализует com.thoughtworks.xstream.converters.Converter для перехвата каждого экземпляра PersistentCollection до того, как XStream его сериализует. Принудительно инициализирует лениво загружаемые коллекции, извлекает базовую коллекцию java.util (обрабатывая особенность внутреннего представления Hibernate множеств в виде карт) и делегирует фактическую запись XML соответствующему стандартному конвертеру XStream. Это конвертер уровня значений — HibernateCollectionsMapper обрабатывает сопоставление на уровне имён, а этот конвертер обрабатывает фактические данные коллекции.

Архитектура

Регистрация конвертера

Конвертеры XStream образуют цепочку. Когда XStream встречает объект для сериализации, он перебирает зарегистрированные конвертеры, вызывая canConvert(Class). HibernateCollectionConverter обрабатывает любой класс, приводимый к org.hibernate.collection.spi.PersistentCollection — это охватывает PersistentBag, PersistentList, PersistentSet, PersistentSortedSet, PersistentMap и PersistentSortedMap. Поскольку XStream проверяет конвертеры в порядке регистрации, этот конвертер должен быть зарегистрирован до конвертеров по умолчанию. Это делается с помощью HibernateMapper при настройке экземпляров XStream.

Конструктор: кэширование конвертеров

Конструктор принимает ConverterLookup и немедленно разрешает и кэширует пять ссылок на конвертеры:

treeMapConverterTreeMap.classОбрабатывает вывод отсортированной карты

Алгоритм marshal()

  1. Приведение к PersistentCollection: Проверяет, является ли source экземпляром PersistentCollection. Если да, вызывает forceInitialization() для запуска ленивой загрузки, затем извлекает getStoredSnapshot() — базовую коллекцию JDK, которую Hibernate использует внутри. (Примечание: комментарий TODO ссылается на getCollectionSnapshot() как на потенциальную альтернативу.)
  2. Обходной путь для PersistentSortedSet: Hibernate хранит отсортированные множества внутри как HashMap, где ключи являются элементами множества. Конвертер извлекает .values() и оборачивает их в новый TreeSet для восстановления правильной семантики множества.
  3. Обходной путь для PersistentSet: Та же проблема — хранится внутри как HashMap. Извлекает .values() и оборачивает в новый HashSet.
  4. Диспетчеризация конвертера: Проверяет конечный класс коллекции по кэшированным конвертерам в порядке: listSetConverter (для ArrayList/HashSet/TreeSet), mapConverter, treeMapConverter, treeSetConverter. В случае неудачи использует defaultConverter.

unmarshal() — не реализован

unmarshal() возвращает null. Этот конвертер однонаправленный — он обрабатывает только сериализацию (Java→XML). Десериализация (XML→Java) создаёт стандартные коллекции JDK, которые затем присваиваются полям сущности. Hibernate заменяет их постоянными обёртками, когда сущность позже присоединяется к сессии.

Точки интеграции

  • Регистрируется в экземплярах XStream через HibernateMapper или прямые вызовы xstream.registerConverter().
  • Работает совместно с HibernateCollectionsMapper: маппер переводит имена типов коллекций в XML, в то время как этот конвертер переводит содержимое коллекций во время маршалинга.
  • Используется подсистемой экспорта XML (XStreamMarshallingStrategy), которая сериализует графы сущностей для файлов резервного копирования/конфигурации XML.

Проектные решения и подводные камни

  • forceInitialization(): Это вызывает запрос к базе данных, если коллекция была лениво загружена, но ещё не запрошена. Для экспорта XML больших графов сущностей это может вызвать каскад запросов. Вызывающий код (обычно метод экспорта сервисного слоя) должен гарантировать, что сессия Hibernate остаётся открытой, и в идеале предварительно загружать ассоциации с помощью запросов JOIN FETCH.
  • Особенность Hibernate «Set-как-Map»: Hibernate 3.x/4.x внутренне представляет как PersistentSet, так и PersistentSortedSet с использованием структур HashMap. Конвертер должен явно разворачивать их. Если эту логику удалить, XStream будет сериализовать множества как XML-карты (с элементами-ключами), создавая неразбираемый вывод.
  • Снимок vs. Коллекция: Комментарий TODO в строке ~66 предлагает использовать getCollectionSnapshot().getSnapshot() вместо getStoredSnapshot(). Текущий подход работает, потому что forceInitialization() гарантирует существование сохранённого снимка, но это хрупко для разных версий Hibernate.
  • Потокобезопасность: Кэшированные ссылки на конвертеры неизменяемы после создания. Экземпляр эффективно потокобезопасен для операций конвертера только для чтения.
  • Авторство: Первоначально написан Костином Леу (Costin Leau), известным участником экосистемы интеграции Spring/Hibernate.
