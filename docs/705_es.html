#705: HibernateCollectionsMapper.java

projectforge-business/src/main/java/org/projectforge/framework/persistence/xstream/HibernateCollectionsMapper.java Mapper XStream — reemplaza los nombres de tipo de colección de Hibernate con equivalentes de JDK en la salida XML, projectforge-business/src/main/java/org/projectforge/framework/persistence/xstream/HibernateCollectionsMapper.java 114 líneas · 49 código · 51 comentarios · 14 en blanco
Extiende el XmlFriendlyMapper de XStream para interceptar las búsquedas de tipo-a-nombre y clase-a-nombre durante la serialización. Cuando XStream necesita escribir un nombre de clase como elemento o atributo XML, este mapper sustituye las clases de colección específicas de Hibernate (PersistentList, PersistentSet, etc.) con sus contrapartes estándar de JDK (ArrayList, HashSet, etc.). Esto asegura que el XML generado contenga nombres de tipo legibles y agnósticos al framework. Opera en la capa de mapeo de nombres — el HibernateCollectionConverter maneja la conversión de datos de la colección real.

Arquitectura

Jerarquía de clases

HibernateCollectionsMapper extiende com.thoughtworks.xstream.mapper.XmlFriendlyMapper, que a su vez extiende MapperWrapper. La cadena de mappers de XStream sigue el patrón Decorador — cada mapper envuelve a otro mapper, y las llamadas se reenvían a través de la cadena. Este mapper intercepta tres métodos específicos para aplicar las sustituciones de clases de colección Hibernate→JDK.

Direccionalidad

Este mapper es de solo escritura (dirección de serialización/desinflado). No implementa el mapeo inverso para realClass() ni deserialización. La fuente señala explícitamente: "Este mapper solo se encarga de la escritura al XML (desinflado), no al revés (inflado) porque no es necesario." Cuando el XML se deserializa, XStream crea colecciones JDK estándar, y la capa ORM de Hibernate las envuelve en subclases de PersistentCollection cuando la entidad se adjunta posteriormente a una sesión.

Puntos de integración

  • Envuelve la cadena de mappers de XStream — se instancia con un delegado Mapper (el mapper subyacente que decora).
  • Trabaja junto con HibernateCollectionConverter: el mapper maneja qué nombre de tipo aparece en XML, el converter maneja cómo se escriben los datos.
  • Se utiliza en la configuración de XStream junto con HibernateMapper (que tiene lógica de mapeo superpuesta pero más completa).

Decisiones de diseño y aspectos a considerar

  • Superclase XmlFriendlyMapper: Extender XmlFriendlyMapper (en lugar de MapperWrapper simple) asegura que después del reemplazo del nombre de clase, el resultado siga siendo seguro para XML (ej., los caracteres $ de nombres de clases internas se codifican).
  • Patrón de arreglos paralelos: El mapeo utiliza tres arreglos paralelos codificados en el momento de inicialización de la clase. Esto es eficiente (escaneo lineal O(n) de 5 elementos) pero frágil — si Hibernate agrega nuevos subtipos de PersistentCollection, este mapper los ignora silenciosamente. Compárese con HibernateMapper que utiliza un Map para un registro más legible y extensible.
  • Redundancia con HibernateMapper: Tanto HibernateCollectionsMapper como HibernateMapper realizan sustitución de nombres de clases de colección. HibernateMapper (que usa defaultImplementationOf() y serializedClass()) es el enfoque más moderno e incluye PersistentBag (que este mapper omite). En la práctica, solo uno debería estar activo para evitar doble mapeo.
  • Sin soporte para PersistentBag: Nótese que PersistentBag (la colección predeterminada de Hibernate para campos List sin tipo) falta en los arreglos de este mapper. Está presente en HibernateMapper.
