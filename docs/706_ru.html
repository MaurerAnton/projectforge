#706: HibernateMapper.java

projectforge-business/src/main/java/org/projectforge/framework/persistence/xstream/HibernateMapper.java Маппер XStream — комплексный маппер типов коллекций Hibernate и резолвер прокси-классов, projectforge-business/src/main/java/org/projectforge/framework/persistence/xstream/HibernateMapper.java 95 строк · 46 кода · 35 комментариев · 14 пустых
Расширяет MapperWrapper от XStream (паттерн «Декоратор»), выступая в роли центрального маппера для всей Hibernate-совместимой сериализации XStream. Выполняет две критически важные функции: (1) заменяет внутренние реализации коллекций Hibernate на их стандартные JDK-аналоги при определении реализаций по умолчанию во время маршаллинга/демаршаллинга, и (2) обнаруживает экземпляры HibernateProxy путём проверки реализованных интерфейсов и определяет имена их реальных суперклассов для именования XML-элементов. Это наиболее полный из компонентов XStream для Hibernate — он обрабатывает PersistentBag (который более старый HibernateCollectionsMapper пропускает) и также обнаруживает обёртки HibernateProxy, которые HibernateCollectionsMapper игнорирует.

Архитектура

Иерархия классов

HibernateMapper расширяет com.thoughtworks.xstream.mapper.MapperWrapper — базовый класс для декораторов маппера XStream. Два конструктора принимают делегаты MapperWrapper или обычный Mapper и вызывают init() для заполнения карты подстановки коллекций.

Таблица маппинга коллекций

Метод init() заполняет Map<Class<?>, Class<?>> шестью маппингами Hibernate→JDK:

Постоянная коллекция HibernateЗамена JDK
PersistentBagArrayList
PersistentListArrayList
PersistentMapHashMap
PersistentSetHashSet
PersistentSortedMapTreeMap
PersistentSortedSetTreeSet
В отличие от HibernateCollectionsMapper, этот маппер включает PersistentBag — коллекцию Hibernate по умолчанию для неиндексированных полей List, объявленных без @OrderColumn. Это наиболее распространённый тип коллекций в сущностях ProjectForge, и его отсутствие в старом маппере является заметным пробелом.

Переопределённые методы

defaultImplementationOf(Class clazz)

Вызывается XStream, когда необходимо создать конкретный класс для интерфейса или абстрактного типа (например, при десериализации поля List XStream запрашивает, какую реализацию создать). Если запрошенный класс находится в collectionMap, возвращается замена JDK. Это гарантирует, что десериализованный XML создаёт обычные объекты ArrayList/HashSet, а не специфические для Hibernate реализации, которые были бы неработоспособны без сессии Hibernate.

serializedClass(Class clazz)

Вызывается XStream для определения имени класса, которое будет записано в XML. Этот метод выполняет двухэтапную проверку:

  1. Обнаружение HibernateProxy: Перебирает clazz.getInterfaces() в поисках HibernateProxy.class. Если найден, возвращает clazz.getSuperclass().getName() — реальное имя класса сущности. Это гарантирует, что в XML появится <org.projectforge.business.user.UserDO>, а не <org.projectforge.business.user.UserDO_$$_jvstXXX> (сгенерированное Javassist имя прокси).
  2. Подстановка коллекции: Если класс находится в collectionMap, возвращает полное квалифицированное имя замены JDK.
  3. Запасной вариант: Делегирует обёрнутому мапперу через super.serializedClass(clazz).

Точки интеграции

  • Оборачивает базовый маппер XStream при создании экземпляров XStream для XML-экспорта. Применяется однократно во время инициализации XStream.
  • Работает совместно с HibernateProxyConverter для обработки прокси: маппер исправляет имя класса, записываемое в XML, а конвертер исправляет данные экземпляра при маршаллинге.
  • Дополняет HibernateCollectionConverter: маппер отвечает за разрешение типов, конвертер — за маршаллинг значений.
  • Оба маппера — HibernateMapper и HibernateCollectionsMapper (#703) — не должны быть активны одновременно, так как это приведёт к двойной подстановке и проблемам. HibernateMapper является предпочтительной, более полной реализацией.
  • Используется инфраструктурой импорта/экспорта XML, включая XStreamMarshallingStrategy.

Проектные решения и «подводные камни»

  • Обнаружение прокси через проверку интерфейсов: Перебор getInterfaces() для поиска HibernateProxy несколько хрупок — он предполагает, что прокси Javassist/CGLIB реализует HibernateProxy как один из своих интерфейсов. В современном Hibernate 5.x это надёжно, но альтернативные прокси-фреймворки (например, прокси Spring @Transactional) могут не реализовывать этот интерфейс. В коде есть закомментированные строки отладки System.err.println, что указывает на итеративную отладку.
  • Имя суперкласса для прокси: Вызов clazz.getSuperclass().getName() работает, поскольку прокси Hibernate генерируются как подклассы класса сущности (например, UserDO_$$_jvstXXX extends UserDO). Это корректно для имени класса, но не обрабатывает случай более глубокой цепочки прокси (вложенные прокси CGLIB).
  • Подстановка на основе карты: Использование HashMap для collectionMap чище и более поддерживаемо, чем параллельные массивы в HibernateCollectionsMapper. Добавление новых маппингов — это изменение одной строки в init().
  • Перегрузка конструкторов: Два конструктора, принимающие как MapperWrapper, так и обычный Mapper, предполагают, что этот класс развивался с течением времени и должен интегрироваться в разных точках цепочки декораторов маппера.
  • Авторство: Изначально написан Костином Леу (Costin Leau), как и большая часть слоя моста XStream+Hibernate в этом пакете.
