#707: HibernateProxyConverter.java

projectforge-business/src/main/java/org/projectforge/framework/persistence/xstream/HibernateProxyConverter.java Convertidor XStream — extrae los proxies de carga perezosa de Hibernate a sus instancias de entidad real durante la serialización, projectforge-business/src/main/java/org/projectforge/framework/persistence/xstream/HibernateProxyConverter.java 63 líneas · 31 código · 25 comentarios · 7 en blanco
Extiende el ReflectionConverter de XStream para interceptar cualquier objeto que implemente org.hibernate.proxy.HibernateProxy antes de que la serialización basada en reflexión de XStream se active. Cuando se encuentra un proxy de Hibernate, llama a getHibernateLazyInitializer().getImplementation() para extraer la instancia de entidad subyacente, luego delega la serialización al convertidor apropiado para la clase real. Sin este convertidor, XStream serializaría el objeto proxy generado por Javassist/CGLIB (una cáscara sin significado que contiene solo un inicializador perezoso), resultando en una salida XML vacía o rota para cualquier asociación de entidad cargada de forma perezosa.

Arquitectura

Jerarquía de clases

HibernateProxyConverter extiende com.thoughtworks.xstream.converters.reflection.ReflectionConverter, que es el convertidor predeterminado de XStream para objetos que no tienen un convertidor más específico. Utiliza la reflexión para recorrer los campos y serializarlos. Al extender esta clase base, el convertidor hereda automáticamente todo el comportamiento estándar de serialización basada en reflexión — solo sobrescribe los puntos de intercepción relacionados con proxies.

Campos

CampoTipoPropósito
converterLookup ConverterLookup Referencia al registro de convertidores de XStream. Se utiliza en el momento de la serialización para delegar al convertidor correcto para la clase real de la entidad extraída. Se establece mediante inyección por constructor.

canConvert(Class clazz)

Devuelve true para cualquier clase que cumpla HibernateProxy.class.isAssignableFrom(clazz). Esto coincide con todas las clases proxy de Hibernate generadas por Javassist/CGLIB (que implementan la interfaz HibernateProxy). Cuando esto devuelve true, XStream enruta la serialización a través de este convertidor en lugar del ReflectionConverter predeterminado.

Importante: Este convertidor debe registrarse antes del ReflectionConverter predeterminado en la cadena de convertidores de XStream, de lo contrario el convertidor predeterminado reclamaría el proxy primero (ya que los proxies son clases regulares) y serializaría los internos del proxy en lugar de la entidad real.

marshal(Object, HierarchicalStreamWriter, MarshallingContext)

La lógica central de extracción:

  1. Verificación de tipo: Comprueba item instanceof HibernateProxy.
  2. Extraer: Llama a ((HibernateProxy) arg0).getHibernateLazyInitializer().getImplementation() para obtener la entidad real. La llamada a LazyInitializer.getImplementation() fuerza la inicialización del proxy — esto desencadena una consulta a la base de datos si la entidad aún no se ha cargado.
  3. Delegar: Utiliza converterLookup.lookupConverterForType(item.getClass()) para encontrar el convertidor apropiado para la clase de entidad real, luego llama a converter.marshal(item, writer, context). Esto asegura que la entidad real se serialice usando el convertidor correcto (potencialmente este mismo HibernateProxyConverter si la entidad real también es un proxy, o el convertidor de reflexión estándar en caso contrario).

Sin sobrescritura de unmarshal()

Este convertidor no sobrescribe unmarshal(). Durante la deserialización, XStream crea objetos Java estándar — no hay necesidad de crear proxies de Hibernate a partir de XML. Los campos deserializados se establecen en la entidad mediante reflexión, y Hibernate los envuelve cuando la entidad se persiste o fusiona posteriormente.

Puntos de integración

  • Registrado con instancias de XStream junto con HibernateMapper y HibernateCollectionConverter.
  • Utilizado por el subsistema de exportación XML (XStreamMarshallingStrategy) cada vez que se serializan grafos de entidades.
  • Depende de la interfaz LazyInitializer de Hibernate — si una versión futura de Hibernate cambia la forma en que los proxies exponen su entidad subyacente, este convertidor necesitaría actualizarse.

Decisiones de diseño & Problemas conocidos

  • Inicialización forzada: Llamar a getImplementation() fuerza la carga del proxy perezoso. Esto significa que la exportación XML de un grafo de entidades puede desencadenar consultas en cascada a la base de datos para cada asociación cargada de forma perezosa. Quien llama debe asegurarse de que la sesión de Hibernate permanezca abierta y debería considerar usar patrones JOIN FETCH o OpenSessionInView para precargar las asociaciones antes de la serialización.
  • Seguridad contra doble extracción: Si la entidad extraída es en sí misma un proxy de Hibernate (por ejemplo, un proxy envuelve a otro proxy), la búsqueda del convertidor delegado puede encontrar nuevamente este mismo HibernateProxyConverter, y la extracción se repite. Esto eventualmente termina porque la cadena llega a la clase de entidad real.
  • converterLookup.lookupConverterForType(item.getClass()): Después de la extracción, la búsqueda utiliza item.getClass() (la clase de la entidad real) en lugar de la clase proxy. Esto significa que cualquier convertidor personalizado registrado para tipos de entidad específicos será seleccionado correctamente, sin ser omitido por el envoltorio del proxy.
  • Visibilidad a nivel de paquete: La clase tiene visibilidad a nivel de paquete (class HibernateProxyConverter sin public), lo que indica que es un detalle de implementación interno del paquete persistence.xstream, no destinado para uso directo fuera del framework.
  • Nombres de argumentos del constructor: Utiliza nombres de parámetros arg0, arg1 — un estilo Java heredado que sugiere que este código se originó en una versión anterior del código base.
