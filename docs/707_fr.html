#707 : HibernateProxyConverter.java

projectforge-business/src/main/java/org/projectforge/framework/persistence/xstream/HibernateProxyConverter.java Convertisseur XStream — dépaquette les proxies de chargement différé Hibernate vers leurs instances d'entité réelles lors du marshalling, projectforge-business/src/main/java/org/projectforge/framework/persistence/xstream/HibernateProxyConverter.java 63 lignes · 31 code · 25 commentaires · 7 vides
Étend le ReflectionConverter de XStream pour intercepter tout objet qui implémente org.hibernate.proxy.HibernateProxy avant que la sérialisation par réflexion de XStream ne s'enclenche. Lorsqu'un proxy Hibernate est rencontré, il appelle getHibernateLazyInitializer().getImplementation() pour extraire l'instance d'entité sous-jacente, puis délègue le marshalling au convertisseur approprié pour la classe réelle. Sans ce convertisseur, XStream sérialiserait l'objet proxy généré par Javassist/CGLIB (une coquille vide contenant uniquement un initialiseur différé), ce qui produirait une sortie XML vide ou cassée pour toute association d'entité chargée paresseusement.

Architecture

Hiérarchie des classes

HibernateProxyConverter étend com.thoughtworks.xstream.converters.reflection.ReflectionConverter, qui est le convertisseur par défaut de XStream pour les objets n'ayant pas de convertisseur plus spécifique. Il utilise la réflexion pour parcourir les champs et les sérialiser. En étendant cette classe de base, le convertisseur hérite automatiquement de tout le comportement standard de sérialisation par réflexion — il ne surcharge que les points d'interception liés aux proxies.

Champs

ChampTypeObjectif
converterLookupConverterLookupRéférence au registre des convertisseurs de XStream. Utilisé au moment du marshalling pour déléguer au convertisseur correct pour la classe réelle de l'entité dépaquetée. Défini via l'injection dans le constructeur.

canConvert(Class clazz)

Retourne true pour toute classe pour laquelle HibernateProxy.class.isAssignableFrom(clazz). Cela correspond à toutes les classes proxy Hibernate générées par Javassist/CGLIB (qui implémentent l'interface HibernateProxy). Lorsque cela retourne true, XStream achemine le marshalling via ce convertisseur au lieu du ReflectionConverter par défaut.

Important : Ce convertisseur doit être enregistré avant le ReflectionConverter par défaut dans la chaîne de convertisseurs de XStream, sinon le convertisseur par défaut s'emparerait du proxy en premier (car les proxies sont des classes normales) et sérialiserait les internes du proxy au lieu de l'entité réelle.

marshal(Object, HierarchicalStreamWriter, MarshallingContext)

La logique centrale de dépaquetage :

  1. Vérification de type : Teste item instanceof HibernateProxy.
  2. Dépaquetage : Appelle ((HibernateProxy) arg0).getHibernateLazyInitializer().getImplementation() pour obtenir l'entité réelle. L'appel à LazyInitializer.getImplementation() force l'initialisation du proxy — cela déclenche une requête en base de données si l'entité n'a pas encore été chargée.
  3. Délégation : Utilise converterLookup.lookupConverterForType(item.getClass()) pour trouver le convertisseur approprié pour la classe d'entité réelle, puis appelle converter.marshal(item, writer, context). Cela garantit que l'entité réelle est sérialisée en utilisant le convertisseur correct (potentiellement ce même HibernateProxyConverter si l'entité réelle est aussi un proxy, ou le convertisseur par réflexion standard sinon).

Pas de surcharge de unmarshal()

Ce convertisseur ne surcharge pas unmarshal(). Pendant la désérialisation, XStream crée des objets Java standards — il n'est pas nécessaire de créer des proxies Hibernate à partir du XML. Les champs désérialisés sont définis sur l'entité via la réflexion, et Hibernate les encapsule lorsque l'entité est ensuite persistée ou fusionnée.

Points d'intégration

  • Enregistré avec les instances XStream aux côtés de HibernateMapper et HibernateCollectionConverter.
  • Utilisé par le sous-système d'export XML (XStreamMarshallingStrategy) chaque fois que des graphes d'entités sont sérialisés.
  • Dépend de l'interface LazyInitializer de Hibernate — si une future version de Hibernate modifie la façon dont les proxies exposent leur entité sous-jacente, ce convertisseur devrait être mis à jour.

Décisions de conception & pièges

  • Initialisation forcée : L'appel à getImplementation() force le chargement du proxy différé. Cela signifie que l'export XML d'un graphe d'entités peut déclencher des requêtes en cascade pour chaque association chargée paresseusement. L'appelant doit s'assurer que la session Hibernate reste ouverte et devrait envisager d'utiliser des motifs JOIN FETCH ou OpenSessionInView pour précharger les associations avant la sérialisation.
  • Sécurité de double-dépaquetage : Si l'entité dépaquetée est elle-même un proxy Hibernate (par exemple, un proxy en encapsule un autre), la recherche du convertisseur délégué peut retrouver ce même HibernateProxyConverter, et le dépaquetage se répète. Cela se termine finalement car la chaîne aboutit à la classe d'entité réelle.
  • converterLookup.lookupConverterForType(item.getClass()) : Après le dépaquetage, la recherche utilise item.getClass() (la classe de l'entité réelle) plutôt que la classe du proxy. Cela signifie que tous les convertisseurs personnalisés enregistrés pour des types d'entités spécifiques seront correctement sélectionnés, sans être contournés par l'encapsulation du proxy.
  • Visibilité package-privé : La classe a une visibilité au niveau du package (class HibernateProxyConverter sans public), ce qui indique qu'il s'agit d'un détail d'implémentation interne du package persistence.xstream, non destiné à une utilisation directe en dehors du framework.
  • Nommage des arguments du constructeur : Utilise les noms de paramètres arg0, arg1 — un style Java hérité suggérant que ce code provient d'une version plus ancienne de la base de code.
