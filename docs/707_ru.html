#707: HibernateProxyConverter.java

projectforge-business/src/main/java/org/projectforge/framework/persistence/xstream/HibernateProxyConverter.java Конвертер XStream — распаковывает Hibernate-прокси ленивой загрузки в реальные экземпляры сущностей во время маршаллинга, projectforge-business/src/main/java/org/projectforge/framework/persistence/xstream/HibernateProxyConverter.java 63 строки · 31 код · 25 комментариев · 7 пустых
Расширяет ReflectionConverter от XStream, чтобы перехватывать любой объект, реализующий org.hibernate.proxy.HibernateProxy, до того как XStream запустит рефлексивную сериализацию. При обнаружении Hibernate-прокси вызывает getHibernateLazyInitializer().getImplementation() для извлечения базового экземпляра сущности, затем делегирует маршаллинг подходящему конвертеру для реального класса. Без этого конвертера XStream сериализовал бы прокси-объект, сгенерированный Javassist/CGLIB (бессмысленную оболочку, содержащую только ленивый инициализатор), что привело бы к пустому или сломанному XML-выводу для любой лениво загружаемой ассоциации сущностей.

Архитектура

Иерархия классов

HibernateProxyConverter расширяет com.thoughtworks.xstream.converters.reflection.ReflectionConverter — стандартный конвертер XStream для объектов, для которых нет более специфичного конвертера. Он использует рефлексию для обхода полей и их сериализации. Расширяя этот базовый класс, конвертер автоматически наследует всё стандартное поведение рефлексивной сериализации — он переопределяет только точки перехвата, связанные с прокси.

Поля

ПолеТипНазначение
converterLookupConverterLookupСсылка на реестр конвертеров XStream. Используется во время маршаллинга для делегирования правильному конвертеру для реального класса распакованной сущности. Устанавливается через внедрение в конструктор.

canConvert(Class clazz)

Возвращает true для любого класса, для которого HibernateProxy.class.isAssignableFrom(clazz). Это соответствует всем классам Hibernate-прокси, сгенерированным Javassist/CGLIB (которые реализуют интерфейс HibernateProxy). Когда этот метод возвращает true, XStream направляет маршаллинг через этот конвертер вместо стандартного ReflectionConverter.

Важно: Этот конвертер должен быть зарегистрирован до стандартного ReflectionConverter в цепочке конвертеров XStream, иначе стандартный конвертер перехватит прокси первым (поскольку прокси — обычные классы) и сериализует внутренности прокси вместо реальной сущности.

marshal(Object, HierarchicalStreamWriter, MarshallingContext)

Основная логика распаковки:

  1. Проверка типа: Проверяет item instanceof HibernateProxy.
  2. Распаковка: Вызывает ((HibernateProxy) arg0).getHibernateLazyInitializer().getImplementation() для получения реальной сущности. Вызов LazyInitializer.getImplementation() принудительно инициализирует прокси — это запускает запрос к базе данных, если сущность ещё не загружена.
  3. Делегирование: Использует converterLookup.lookupConverterForType(item.getClass()) для поиска подходящего конвертера для класса реальной сущности, затем вызывает converter.marshal(item, writer, context). Это гарантирует, что реальная сущность сериализуется с использованием правильного конвертера (возможно, того же HibernateProxyConverter, если реальная сущность также является прокси, или стандартного рефлексивного конвертера в противном случае).

Отсутствие переопределения unmarshal()

Этот конвертер не переопределяет unmarshal(). Во время десериализации XStream создаёт стандартные Java-объекты — нет необходимости создавать Hibernate-прокси из XML. Десериализованные поля устанавливаются в сущность через рефлексию, и Hibernate оборачивает их, когда сущность позже сохраняется или сливается.

Точки интеграции

  • Регистрируется в экземплярах XStream вместе с HibernateMapper и HibernateCollectionConverter.
  • Используется подсистемой экспорта XML (XStreamMarshallingStrategy) при сериализации графов сущностей.
  • Зависит от интерфейса Hibernate LazyInitializer — если будущая версия Hibernate изменит способ, которым прокси предоставляют базовую сущность, этот конвертер потребует обновления.

Проектные решения и подводные камни

  • Принудительная инициализация: Вызов getImplementation() принудительно загружает ленивый прокси. Это означает, что XML-экспорт графа сущностей может вызвать каскадные запросы к базе данных для каждой лениво загружаемой ассоциации. Вызывающий код должен убедиться, что сессия Hibernate остаётся открытой, и рассмотреть использование JOIN FETCH или шаблона OpenSessionInView для предварительной загрузки ассоциаций перед сериализацией.
  • Безопасность двойной распаковки: Если распакованная сущность сама является Hibernate-прокси (например, прокси оборачивает другой прокси), поиск конвертера-делегата может снова найти этот же HibernateProxyConverter, и распаковка повторяется. В конечном итоге это завершается, поскольку цепочка доходит до реального класса сущности.
  • converterLookup.lookupConverterForType(item.getClass()): После распаковки поиск использует item.getClass() (класс реальной сущности), а не класс прокси. Это означает, что любые пользовательские конвертеры, зарегистрированные для конкретных типов сущностей, будут корректно выбраны, а не обойдены обёрткой прокси.
  • Видимость на уровне пакета: Класс имеет видимость на уровне пакета (class HibernateProxyConverter без public), что указывает на то, что это внутренняя деталь реализации пакета persistence.xstream, не предназначенная для прямого использования вне фреймворка.
  • Именование аргументов конструктора: Использует имена параметров arg0, arg1 — стиль старой Java, предполагающий, что этот код появился в более старой версии кодовой базы.
