Une petite classe utilitaire statique fournissant une seule méthode générique get(T object) qui détecte si un objet est un HibernateProxy et, le cas échéant, le désemballe vers l'entité réelle via getHibernateLazyInitializer().getImplementation(). Si l'objet n'est pas un proxy, il retourne l'objet inchangé. C'est l'utilitaire de désemballage de proxy le plus simple et le plus réutilisable dans la couche de pont XStream+Hibernate — utilisé par ProxyIdRefMarshaller pour le suivi des références basé sur l'ID et disponible pour tout code qui a besoin d'inspecter l'objet réel derrière un wrapper proxy.

Architecture

Conception de la classe

HibernateProxyHelper est une classe utilitaire pure avec une seule méthode statique publique générique. Elle n'a pas d'état, pas de dépendances (au-delà de org.hibernate.proxy.HibernateProxy), et pas de méthodes d'instance. Le paramètre de type générique <T> préserve le type à la compilation à travers l'opération de désemballage, de sorte que les appelants n'ont pas besoin de caster.

Méthode get(T object)

public static <T> T get(T object) {
    if (object instanceof HibernateProxy) {
        HibernateProxy proxy = (HibernateProxy) object;
        return (T) proxy.getHibernateLazyInitializer().getImplementation();
    }
    return object;
}

La logique est simple :

  1. Vérification de proxy : Utilise instanceof HibernateProxy — la manière standard de détecter les proxies Hibernate, car tous les proxies générés par Hibernate implémentent cette interface.
  2. Désemballage : Appelle getHibernateLazyInitializer().getImplementation() qui force l'initialisation du proxy (déclenche le chargement paresseux) et retourne l'entité réelle.
  3. Retour d'identité : Si ce n'est pas un proxy, retourne la même référence d'objet — un passage direct sans opération.
L'appel à getImplementation() force l'initialisation du proxy. Si l'entité n'a pas été chargée depuis la base de données, cela déclenche une requête SQL. Les appelants doivent s'assurer qu'une session Hibernate active est disponible, ou gérer la potentielle LazyInitializationException.

Points d'intégration

  • Consommateur principal : ProxyIdRefMarshaller — utilise HibernateProxyHelper.get(item) pour désemballer les proxies avant de vérifier le dictionnaire de références d'ID et le marshalling.
  • Peut être utilisé par tout code dans le package persistence.xstream ou ailleurs qui a besoin d'un désemballage sécurisé de proxy.
  • Écrit par Wolfgang Jung (w.jung@micromata.de), contrairement à la plupart des classes du pont XStream qui sont attribuées à Costin Leau.

Décisions de conception et pièges

  • Cast non vérifié : Le cast (T) n'est pas vérifié car getImplementation() retourne Object. C'est sûr en pratique car les proxies Hibernate sont toujours des sous-classes du type d'entité, donc l'objet retourné est toujours assignable à T.
  • Pas de vérification null : La méthode ne se protège pas contre une entrée null — null instanceof HibernateProxy évalue à false, donc null est retourné inchangé. C'est un comportement correct.
  • Simplicité vs Hibernate.isInitialized() : Contrairement à ReflectionToString, cet helper ne vérifie pas d'abord Hibernate.isInitialized(). Il essaie toujours d'obtenir l'implémentation, ce qui force l'initialisation. C'est intentionnel — l'helper est utilisé dans des contextes où l'objet réel est nécessaire (export XML), pas à des fins d'affichage.
