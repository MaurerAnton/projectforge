projectforge-business/src/main/java/org/projectforge/framework/persistence/xstream/HibernateProxyHelper.java Утилита Java — статический помощник, который разворачивает прокси-объекты Hibernate до их базовых экземпляров сущностей, projectforge-business/src/main/java/org/projectforge/framework/persistence/xstream/HibernateProxyHelper.java 49 строк · 13 кода · 33 комментария · 3 пустых
Небольшой статический утилитный класс, предоставляющий единственный обобщённый метод get(T object), который определяет, является ли объект HibernateProxy, и если да, разворачивает его до реальной сущности через getHibernateLazyInitializer().getImplementation(). Если объект не является прокси, метод возвращает его без изменений. Это самая простая и наиболее переиспользуемая утилита разворачивания прокси в слое моста XStream+Hibernate — используется ProxyIdRefMarshaller для отслеживания ссылок на основе ID и доступна для любого кода, которому нужно получить реальный объект за прокси-обёрткой.

Архитектура

Дизайн класса

HibernateProxyHelper — это чистый утилитный класс с единственным публичным статическим обобщённым методом. Он не имеет состояния, зависимостей (кроме org.hibernate.proxy.HibernateProxy) и методов экземпляра. Параметр обобщённого типа <T> сохраняет тип времени компиляции при операции разворачивания, поэтому вызывающим сторонам не нужно выполнять приведение.

Метод get(T object)

public static <T> T get(T object) {
    if (object instanceof HibernateProxy) {
        HibernateProxy proxy = (HibernateProxy) object;
        return (T) proxy.getHibernateLazyInitializer().getImplementation();
    }
    return object;
}

Логика проста:

  1. Проверка на прокси: Используется instanceof HibernateProxy — стандартный способ обнаружения прокси Hibernate, поскольку все сгенерированные Hibernate прокси реализуют этот интерфейс.
  2. Разворачивание: Вызов getHibernateLazyInitializer().getImplementation() принудительно инициализирует прокси (запускает ленивую загрузку) и возвращает реальную сущность.
  3. Возврат без изменений: Если объект не является прокси, возвращается та же ссылка на объект — сквозной проход без операций.
Вызов getImplementation() принудительно инициализирует прокси. Если сущность ещё не загружена из базы данных, это вызовет SQL-запрос. Вызывающие стороны должны гарантировать наличие активной сессии Hibernate или обрабатывать возможное LazyInitializationException.

Точки интеграции

  • Основной потребитель: ProxyIdRefMarshaller — использует HibernateProxyHelper.get(item) для разворачивания прокси перед проверкой словаря ID-ссылок и маршаллингом.
  • Может использоваться любым кодом в пакете persistence.xstream или в других местах, где требуется безопасное разворачивание прокси.
  • Автор: Wolfgang Jung (w.jung@micromata.de), в отличие от большинства классов моста XStream, которые приписываются Costin Leau.

Проектные решения и подводные камни

  • Непроверяемое приведение: Приведение (T) является непроверяемым, поскольку getImplementation() возвращает Object. На практике это безопасно, так как прокси Hibernate всегда являются подклассами типа сущности, поэтому возвращаемый объект всегда может быть присвоен T.
  • Отсутствие проверки на null: Метод не защищается от входного null — null instanceof HibernateProxy возвращает false, поэтому null возвращается без изменений. Это корректное поведение.
  • Простота vs. Hibernate.isInitialized(): В отличие от ReflectionToString, этот помощник не проверяет Hibernate.isInitialized() в первую очередь. Он всегда пытается получить реализацию, что принудительно инициализирует прокси. Это сделано намеренно — помощник используется в контекстах, где требуется реальный объект (экспорт XML), а не для отображения.
