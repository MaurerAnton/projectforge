Konvertiert SVG-DOM-Dokumente in Rasterbilder (PNG, JPEG), PDF oder rohe SVG-Byte-Arrays unter Verwendung von Apache Batik und Apache FOP-Transcodern. Fungiert als zustandsloses Dienstprogramm für die Multi-Format-SVG-Rendering.

Architektur & Design

BatikImageRenderer ist eine zustandslose Dienstprogrammklasse, die einen einzigen öffentlichen Einstiegspunkt getByteArray(Document, int, ImageFormat) bereitstellt. Intern delegiert sie je nach angefordertem ImageFormat an eine von drei privaten Methoden. Die Klasse verwendet die Transcoder-API von Apache Batik (PNGTranscoder, JPEGTranscoder) für die Rasterausgabe und den PDFTranscoder von Apache FOP für die Vektor-PDF-Ausgabe. SVG-Bytes werden durch Serialisierung des DOM über XmlHelper.toString() ohne Transcodierungsschritt gewonnen.

Öffentliche API

MethodeBeschreibung
getByteArray(Document, int width, ImageFormat)Haupt-Einstiegspunkt. Leitet basierend auf ImageFormat an formatspezifische Renderer weiter. Wirft UnsupportedOperationException für unbekannte Formate.

Private Rendering-Methoden

MethodeFormatDetails
getRasterImageByteArray(Document, int, ImageFormat)PNG / JPEGErstellt eine ImageTranscoder-Instanz (PNG oder JPEG). JPEG verwendet den Hinweis JPEGTranscoder.KEY_QUALITY mit Wert 0,8. Beide wenden KEY_WIDTH für die Ausgabebreite an. TIFF-Unterstützung ist auskommentiert.
getPDFByteArray(Document, int)PDFVerwendet PDFTranscoder mit deaktiviertem KEY_AUTO_FONTS und gesetztem KEY_WIDTH. Ausgabe in ByteArrayOutputStream über TranscoderOutput.
getSVGByteArray(Document, int)SVGSerialisiert das DOM mit XmlHelper.toString(document, true) in einen XML-String und gibt dann UTF-8-Bytes zurück. Der Parameter width wird ignoriert.

Fehlerbehandlung

Alle Transcoder-Aufrufe sind in Try-Catch-Blöcke eingeschlossen, die TranscoderException abfangen. Fehler werden über SLF4J auf Fehlerebene protokolliert, die Ausnahme wird jedoch nicht erneut geworfen – der partielle Inhalt des ByteArrayOutputStream wird zurückgegeben. Das bedeutet, dass Aufrufer bei einem Fehler potenziell unvollständige oder leere Daten ohne jeglichen Hinweis erhalten.

Absicherung gegen nicht unterstützte Formate

Die Dispatch-Logik verwendet ImageFormat.isIn(ImageFormat.PNG, ImageFormat.JPEG) für den Raster-Zweig, dann Gleichheitsprüfungen gegen ImageFormat.PDF und ImageFormat.SVG. Jedes nicht erkannte Format löst eine UnsupportedOperationException aus. Beachten Sie das redundante Identitätsprüfungsmuster: imageFormat == ImageFormat.PDF == true, was semantisch identisch mit imageFormat == ImageFormat.PDF ist.

Abhängigkeiten

  • Apache Batik: TranscoderInput, TranscoderOutput, PNGTranscoder, JPEGTranscoder, ImageTranscoder, TranscoderException
  • Apache FOP: PDFTranscoder (aus org.apache.fop.svg)
  • Intern: XmlHelper für DOM-Serialisierung, ImageFormat-Enum für Format-Routing
  • W3C DOM: org.w3c.dom.Document als Eingabe
