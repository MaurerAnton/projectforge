Convierte documentos DOM SVG a imágenes ráster (PNG, JPEG), PDF o arreglos de bytes SVG sin procesar utilizando los transcodificadores Apache Batik y Apache FOP. Actúa como una utilidad sin estado para la representación SVG en múltiples formatos.

Arquitectura y Diseño

BatikImageRenderer es una clase de utilidad sin estado que expone un único punto de entrada público getByteArray(Document, int, ImageFormat). Internamente, delega en uno de tres métodos privados dependiendo del ImageFormat solicitado. La clase utiliza la API de transcodificación de Apache Batik (PNGTranscoder, JPEGTranscoder) para la salida ráster y el PDFTranscoder de Apache FOP para la salida PDF vectorial. Los bytes SVG se obtienen serializando el DOM a través de XmlHelper.toString() sin ningún paso de transcodificación.

API Pública

MétodoDescripción
getByteArray(Document, int width, ImageFormat)Punto de entrada principal. Enruta a los renderizadores específicos de formato según ImageFormat. Lanza UnsupportedOperationException para formatos desconocidos.

Métodos de Renderizado Privados

MétodoFormatoDetalles
getRasterImageByteArray(Document, int, ImageFormat)PNG / JPEGCrea una instancia de ImageTranscoder (PNG o JPEG). JPEG utiliza la sugerencia JPEGTranscoder.KEY_QUALITY establecida en 0.8. Ambos aplican KEY_WIDTH para el ancho de salida. El soporte para TIFF está comentado.
getPDFByteArray(Document, int)PDFUtiliza PDFTranscoder con KEY_AUTO_FONTS deshabilitado y KEY_WIDTH establecido. La salida se dirige a ByteArrayOutputStream a través de TranscoderOutput.
getSVGByteArray(Document, int)SVGSerializa el DOM a una cadena XML usando XmlHelper.toString(document, true), luego devuelve los bytes UTF-8. El parámetro width se ignora.

Manejo de Errores

Todas las invocaciones al transcodificador están envueltas en bloques try-catch que capturan TranscoderException. Los errores se registran mediante SLF4J a nivel de error, pero la excepción no se relanza — se devuelve el contenido parcial del ByteArrayOutputStream. Esto significa que los llamantes reciben datos potencialmente incompletos o vacíos en caso de fallo sin ninguna indicación.

Protección de Formato No Soportado

La lógica de despacho utiliza ImageFormat.isIn(ImageFormat.PNG, ImageFormat.JPEG) para la rama ráster, luego comprobaciones de igualdad contra ImageFormat.PDF y ImageFormat.SVG. Cualquier formato no reconocido desencadena una UnsupportedOperationException. Nótese el patrón de comprobación de identidad redundante: imageFormat == ImageFormat.PDF == true, que es semánticamente idéntico a imageFormat == ImageFormat.PDF.

Dependencias

  • Apache Batik: TranscoderInput, TranscoderOutput, PNGTranscoder, JPEGTranscoder, ImageTranscoder, TranscoderException
  • Apache FOP: PDFTranscoder (de org.apache.fop.svg)
  • Interno: XmlHelper para serialización DOM, enumeración ImageFormat para enrutamiento de formatos
  • W3C DOM: org.w3c.dom.Document como entrada
