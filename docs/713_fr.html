Convertit des documents DOM SVG en images raster (PNG, JPEG), en PDF ou en tableaux d'octets SVG bruts à l'aide des transcodeurs Apache Batik et Apache FOP. Agit comme un utilitaire sans état pour le rendu SVG multi-format.

Architecture & Conception

BatikImageRenderer est une classe utilitaire sans état exposant un seul point d'entrée public getByteArray(Document, int, ImageFormat). En interne, elle délègue à l'une des trois méthodes privées selon le ImageFormat demandé. La classe utilise l'API de transcodage d'Apache Batik (PNGTranscoder, JPEGTranscoder) pour la sortie raster et le PDFTranscoder d'Apache FOP pour la sortie PDF vectorielle. Les octets SVG sont obtenus en sérialisant le DOM via XmlHelper.toString() sans étape de transcodage.

API publique

MéthodeDescription
getByteArray(Document, int width, ImageFormat)Point d'entrée principal. Achemine vers les rendus spécifiques au format en fonction de ImageFormat. Lève une UnsupportedOperationException pour les formats inconnus.

Méthodes de rendu privées

MéthodeFormatDétails
getRasterImageByteArray(Document, int, ImageFormat)PNG / JPEGCrée une instance ImageTranscoder (PNG ou JPEG). JPEG utilise l'indicateur JPEGTranscoder.KEY_QUALITY défini à 0,8. Les deux appliquent KEY_WIDTH pour la largeur de sortie. Le support TIFF est commenté.
getPDFByteArray(Document, int)PDFUtilise PDFTranscoder avec KEY_AUTO_FONTS désactivé et KEY_WIDTH défini. Sortie vers ByteArrayOutputStream via TranscoderOutput.
getSVGByteArray(Document, int)SVGSérialise le DOM en une chaîne XML en utilisant XmlHelper.toString(document, true), puis retourne les octets UTF-8. Le paramètre width est ignoré.

Gestion des erreurs

Toutes les invocations de transcodeur sont encapsulées dans des blocs try-catch attrapant TranscoderException. Les erreurs sont journalisées via SLF4J au niveau erreur, mais l'exception n'est pas relancée — le contenu partiel du ByteArrayOutputStream est retourné. Cela signifie que les appelants reçoivent potentiellement des données incomplètes ou vides en cas d'échec, sans aucune indication.

Protection contre les formats non supportés

La logique de répartition utilise ImageFormat.isIn(ImageFormat.PNG, ImageFormat.JPEG) pour la branche raster, puis des vérifications d'égalité contre ImageFormat.PDF et ImageFormat.SVG. Tout format non reconnu déclenche une UnsupportedOperationException. Notez le motif de vérification d'identité redondant : imageFormat == ImageFormat.PDF == true, qui est sémantiquement identique à imageFormat == ImageFormat.PDF.

Dépendances

  • Apache Batik : TranscoderInput, TranscoderOutput, PNGTranscoder, JPEGTranscoder, ImageTranscoder, TranscoderException
  • Apache FOP : PDFTranscoder (depuis org.apache.fop.svg)
  • Interne : XmlHelper pour la sérialisation DOM, énumération ImageFormat pour le routage des formats
  • DOM W3C : org.w3c.dom.Document comme entrée
