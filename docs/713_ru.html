Преобразует SVG DOM-документы в растровые изображения (PNG, JPEG), PDF или необработанные байтовые массивы SVG с помощью транскодеров Apache Batik и Apache FOP. Действует как утилита без сохранения состояния для многформатного рендеринга SVG.

Архитектура и дизайн

BatikImageRenderer — это утилитный класс без состояния, предоставляющий единственную публичную точку входа getByteArray(Document, int, ImageFormat). Внутренне он делегирует выполнение одному из трёх приватных методов в зависимости от запрошенного ImageFormat. Класс использует транскодерный API Apache Batik (PNGTranscoder, JPEGTranscoder) для растрового вывода и PDFTranscoder от Apache FOP для векторного вывода PDF. Байты SVG получаются путём сериализации DOM через XmlHelper.toString() без какого-либо этапа транскодирования.

Публичный API

МетодОписание
getByteArray(Document, int width, ImageFormat)Основная точка входа. Направляет к рендерерам, специфичным для формата, на основе ImageFormat. Выбрасывает UnsupportedOperationException для неизвестных форматов.

Приватные методы рендеринга

МетодФорматДетали
getRasterImageByteArray(Document, int, ImageFormat)PNG / JPEGСоздаёт экземпляр ImageTranscoder (PNG или JPEG). JPEG использует подсказку JPEGTranscoder.KEY_QUALITY, установленную на 0.8. Оба применяют KEY_WIDTH для выходной ширины. Поддержка TIFF закомментирована.
getPDFByteArray(Document, int)PDFИспользует PDFTranscoder с отключённым KEY_AUTO_FONTS и установленным KEY_WIDTH. Выводит в ByteArrayOutputStream через TranscoderOutput.
getSVGByteArray(Document, int)SVGСериализует DOM в XML-строку с помощью XmlHelper.toString(document, true), затем возвращает байты в кодировке UTF-8. Параметр width игнорируется.

Обработка ошибок

Все вызовы транскодеров обёрнуты в блоки try-catch, перехватывающие TranscoderException. Ошибки логируются через SLF4J на уровне ошибки, но исключение не выбрасывается повторно — возвращается частичное содержимое ByteArrayOutputStream. Это означает, что вызывающие стороны могут получить потенциально неполные или пустые данные при сбое без каких-либо указаний на это.

Защита от неподдерживаемых форматов

Логика диспетчеризации использует ImageFormat.isIn(ImageFormat.PNG, ImageFormat.JPEG) для растровой ветки, затем проверки на равенство с ImageFormat.PDF и ImageFormat.SVG. Любой нераспознанный формат вызывает UnsupportedOperationException. Обратите внимание на избыточный шаблон проверки идентичности: imageFormat == ImageFormat.PDF == true, что семантически идентично imageFormat == ImageFormat.PDF.

Зависимости

  • Apache Batik: TranscoderInput, TranscoderOutput, PNGTranscoder, JPEGTranscoder, ImageTranscoder, TranscoderException
  • Apache FOP: PDFTranscoder (из org.apache.fop.svg)
  • Внутренние: XmlHelper для сериализации DOM, перечисление ImageFormat для маршрутизации по форматам
  • W3C DOM: org.w3c.dom.Document как входные данные
