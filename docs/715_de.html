#715: FontMap.java

Lädt AFM-Dateien (Adobe Font Metrics) aus einem Verzeichnis in eine Map, die nach PostScript-Schriftartnamen indiziert ist. Wird von der FOP/XSL-FO-PDF-Rendering-Pipeline verwendet, um einbettbare Schriftarten bereitzustellen.

Architektur

FontMap verwaltet eine interne Map<String, BaseFont> (HashMap), die PostScript-Schriftartnamen auf iText-BaseFont-Objekte abbildet. Die einzige öffentliche Methode loadFonts(File fontDir) durchsucht das angegebene Verzeichnis rekursiv nach .afm-Dateien und lädt jede einzelne.

Ladevorgang

  1. Verwendet FileUtils.listFiles(fontDir, ["afm"], true), um rekursiv alle AFM-Dateien zu sammeln.
  2. Ruft für jede Datei BaseFont.createFont(pfad, BaseFont.CP1252, BaseFont.EMBEDDED) auf, um eine iText-Schriftart mit CP1252-Kodierung und aktivierter Einbettung zu erstellen.
  3. Extrahiert den PostScript-Schriftartnamen über font.getPostscriptFontName() und speichert ihn in der Map.
  4. Fehler beim Laden von Schriftarten (z. B. beschädigte Datei) werden über SLF4J protokolliert und die problematische Schriftart wird übersprungen (via continue).

Wichtige Details

  • Kodierung: CP1252 (Windows-1252). Alle Schriftarten werden unabhängig von ihrer tatsächlichen Kodierung mit dieser Kodierung geladen.
  • Einbettung: BaseFont.EMBEDDED — Schriftarten werden in das Ausgabe-PDF eingebettet, was eine konsistente Darstellung auf jedem System gewährleistet.
  • Duplikatsbehandlung: Wenn zwei AFM-Dateien denselben PostScript-Namen ergeben, gewinnt die zuletzt geladene (Standardverhalten von HashMap.put).
  • Kein öffentlicher Getter: Das Feld fontMap ist paketprivat (in dieser Quelle wird kein Zugriff gezeigt). Andere Klassen im Renderer-Paket können direkt darauf zugreifen.

Abhängigkeiten

  • iText 2: com.itextpdf.text.pdf.BaseFont für Schrifterstellung und -einbettung.
  • Apache Commons IO: FileUtils.listFiles() für rekursive Verzeichnissuche.
  • Apache Commons Collections 4: CollectionUtils.isNotEmpty() für nullsichere Leerprüfung.
