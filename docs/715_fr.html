Charge les fichiers de polices AFM (Adobe Font Metrics) depuis un répertoire dans une table indexée par le nom de police PostScript. Utilisé par le pipeline de rendu PDF FOP/XSL-FO pour fournir des polices intégrables.

Architecture

FontMap maintient une Map<String, BaseFont> interne (HashMap) qui associe les noms de polices PostScript aux objets BaseFont d'iText. La seule méthode publique loadFonts(File fontDir) analyse récursivement le répertoire donné à la recherche de fichiers .afm et charge chacun d'eux.

Processus de chargement

  1. Utilise FileUtils.listFiles(fontDir, ["afm"], true) pour collecter récursivement tous les fichiers AFM.
  2. Pour chaque fichier, appelle BaseFont.createFont(path, BaseFont.CP1252, BaseFont.EMBEDDED) pour créer une police iText avec l'encodage CP1252 et l'intégration activée.
  3. Extrait le nom de police PostScript via font.getPostscriptFontName() et le stocke dans la table.
  4. Les erreurs lors du chargement des polices (par exemple, fichier corrompu) sont journalisées via SLF4J et la police problématique est ignorée (via continue).

Détails clés

  • Encodage : CP1252 (Windows-1252). Toutes les polices sont chargées avec cet encodage, quel que soit leur encodage réel.
  • Intégration : BaseFont.EMBEDDED — les polices sont intégrées dans le PDF de sortie, garantissant un rendu cohérent sur n'importe quel système.
  • Gestion des doublons : Si deux fichiers AFM produisent le même nom PostScript, le dernier chargé l'emporte (comportement standard de HashMap.put).
  • Pas d'accesseur public : Le champ fontMap est privé au package (aucun accesseur n'est montré dans cette source). D'autres classes du package renderer peuvent y accéder directement.

Dépendances

  • iText 2 : com.itextpdf.text.pdf.BaseFont pour la création et l'intégration des polices.
  • Apache Commons IO : FileUtils.listFiles() pour l'analyse récursive des répertoires.
  • Apache Commons Collections 4 : CollectionUtils.isNotEmpty() pour une vérification de vide sécurisée contre les valeurs nulles.
