Загружает файлы шрифтов AFM (Adobe Font Metrics) из каталога в карту, ключами которой являются имена шрифтов PostScript. Используется в конвейере рендеринга PDF на основе FOP/XSL-FO для обеспечения встраиваемых шрифтов.

Архитектура

FontMap поддерживает внутреннюю Map<String, BaseFont> (HashMap), которая сопоставляет имена шрифтов PostScript с объектами iText BaseFont. Единственный публичный метод loadFonts(File fontDir) рекурсивно сканирует указанный каталог на наличие файлов .afm и загружает каждый из них.

Процесс загрузки

  1. Использует FileUtils.listFiles(fontDir, ["afm"], true) для рекурсивного сбора всех AFM-файлов.
  2. Для каждого файла вызывает BaseFont.createFont(path, BaseFont.CP1252, BaseFont.EMBEDDED) для создания шрифта iText с кодировкой CP1252 и включённым встраиванием.
  3. Извлекает имя шрифта PostScript через font.getPostscriptFontName() и сохраняет его в карту.
  4. Ошибки во время загрузки шрифта (например, повреждённый файл) логируются через SLF4J, а проблемный шрифт пропускается (через continue).

Ключевые детали

  • Кодировка: CP1252 (Windows-1252). Все шрифты загружаются с этой кодировкой независимо от их фактической кодировки.
  • Встраивание: BaseFont.EMBEDDED — шрифты встраиваются в выходной PDF, что обеспечивает единообразное отображение на любой системе.
  • Обработка дубликатов: Если два AFM-файла дают одно и то же имя PostScript, побеждает последний загруженный (стандартное поведение HashMap.put).
  • Отсутствие публичного геттера: Поле fontMap имеет доступ на уровне пакета (в этом исходнике аксессор не показан). Другие классы в пакете рендеринга могут обращаться к нему напрямую.

Зависимости

  • iText 2: com.itextpdf.text.pdf.BaseFont для создания и встраивания шрифтов.
  • Apache Commons IO: FileUtils.listFiles() для рекурсивного сканирования каталогов.
  • Apache Commons Collections 4: CollectionUtils.isNotEmpty() для безопасной проверки на пустоту с учётом null.
