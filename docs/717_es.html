Servicio central de renderizado PDF. Acepta una hoja de estilo XSL-FO, una plantilla Groovy/XML y un mapa de datos, luego produce un arreglo de bytes PDF utilizando Apache FOP con transformación XSLT y preprocesamiento Groovy.

Arquitectura y canal de procesamiento

PdfRenderer es un @Service de Spring con un único método público render(String stylesheet, String groovyXml, Map<String, Object> data). El canal de renderizado procede en cuatro etapas:

1. Enriquecimiento de datos

Antes de cualquier transformación, el mapa de datos se enriquece con variables de plantilla estándar:

  • createdLabel — cadena "creado" localizada
  • loggedInUser — el PFUserDO actual
  • baseDir — ruta del directorio de recursos desde ConfigurationService
  • logoFile — ruta completa a la imagen de logotipo configurada
  • appId / appVersion — desde las constantes de ProjectForgeVersion
  • organization — desde Configuration (con respaldo a appId)

2. Configuración de FOP

Apache FOP se configura con:

  • Una FopFactory instanciada con la URI del directorio de recursos de fuentes
  • Un FOUserAgent para configuraciones a nivel de agente de usuario
  • Un objeto Fop dirigido a la salida MIME_PDF hacia un ByteArrayOutputStream
  • Nota: El código comentado muestra un intento anterior de setFontBaseURL() que fue eliminado

3. Preprocesamiento de plantilla Groovy

La plantilla XML (groovyXml) pasa por dos pasos del motor Groovy:

  1. preprocessGroovyXml() — preprocesa la plantilla
  2. executeTemplate() — ejecuta la plantilla Groovy con el mapa de datos para producir el XML final

4. Transformación XSLT + Renderizado FOP

  • La hoja de estilo XSLT se carga desde los recursos a través de ConfigurationService.getResourceAsInputStream()
  • Se crea un Transformer con parámetros del mapa de datos
  • El XML generado por Groovy se alimenta como entrada StreamSource
  • El resultado se canaliza como SAXResult a través del manejador predeterminado de FOP, produciendo bytes PDF

Manejo de errores

Las excepciones se capturan y envuelven:

ExcepciónManejo
FOPExceptionRegistrada y envuelta en RuntimeException
TransformerExceptionRegistrada y envuelta en RuntimeException
IOException (cerrando BAOS)Registrada y envuelta en RuntimeException

El bloque finally cierra el ByteArrayOutputStream y utiliza IOUtils.closeQuietly() para el flujo de entrada XSLT. Después de cerrar, se llama a baos.toByteArray() — note que esto funciona porque ByteArrayOutputStream.close() es una operación nula.

Integración con Spring

  • @Service — bean de Spring detectado automáticamente
  • @Autowired — ConfigurationService inyectado
  • @Value("${projectforge.export.logoFile}") — nombre del archivo de logotipo desde propiedades de la aplicación
  • Inicialización perezosa de fontResourcePath a través de getFontResourcePath()

Dependencias

  • Apache FOP: FopFactory, Fop, FOUserAgent, FOPException
  • JAXP XSLT: TransformerFactory, Transformer, StreamSource, SAXResult
  • Internas: ConfigurationService, GroovyEngine, Configuration, ProjectForgeVersion, ThreadLocalUserContext
  • Commons IO: IOUtils.closeQuietly()
  • Commons Lang3: StringUtils.defaultString()
