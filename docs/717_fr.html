Service central de rendu PDF. Accepte une feuille de style XSL-FO, un modèle Groovy/XML et une carte de données, puis produit un tableau d'octets PDF en utilisant Apache FOP avec transformation XSLT et prétraitement Groovy.

Architecture et pipeline de traitement

PdfRenderer est un @Service Spring avec une seule méthode publique render(String stylesheet, String groovyXml, Map<String, Object> data). Le pipeline de rendu se déroule en quatre étapes :

1. Enrichissement des données

Avant toute transformation, la carte de données est enrichie avec des variables de modèle standard :

  • createdLabel — chaîne localisée "créé"
  • loggedInUser — l'utilisateur PFUserDO actuel
  • baseDir — chemin du répertoire des ressources depuis ConfigurationService
  • logoFile — chemin complet vers l'image du logo configurée
  • appId / appVersion — depuis les constantes ProjectForgeVersion
  • organization — depuis Configuration (en repli sur appId)

2. Configuration FOP

Apache FOP est configuré avec :

  • Une FopFactory instanciée avec l'URI du répertoire des ressources de polices
  • Un FOUserAgent pour les paramètres au niveau de l'agent utilisateur
  • Un objet Fop ciblant la sortie MIME_PDF vers un ByteArrayOutputStream
  • Remarque : le code commenté montre une tentative précédente de setFontBaseURL() qui a été supprimée

3. Prétraitement du modèle Groovy

Le modèle XML (groovyXml) passe par deux passes du moteur Groovy :

  1. preprocessGroovyXml() — prétraite le modèle
  2. executeTemplate() — exécute le modèle Groovy avec la carte de données pour produire le XML final

4. Transformation XSLT + rendu FOP

  • La feuille de style XSLT est chargée depuis les ressources via ConfigurationService.getResourceAsInputStream()
  • Un Transformer est créé avec des paramètres provenant de la carte de données
  • Le XML généré par Groovy est fourni en entrée StreamSource
  • Le résultat est acheminé en tant que SAXResult via le gestionnaire par défaut de FOP, produisant des octets PDF

Gestion des erreurs

Les exceptions sont capturées et encapsulées :

ExceptionTraitement
FOPExceptionJournalisée et encapsulée dans RuntimeException
TransformerExceptionJournalisée et encapsulée dans RuntimeException
IOException (fermeture BAOS)Journalisée et encapsulée dans RuntimeException

Le bloc finally ferme le ByteArrayOutputStream et utilise IOUtils.closeQuietly() pour le flux d'entrée XSLT. Après la fermeture, baos.toByteArray() est appelé — notez que cela fonctionne car ByteArrayOutputStream.close() est une opération sans effet.

Intégration Spring

  • @Service — bean Spring détecté automatiquement
  • @Autowired — ConfigurationService injecté
  • @Value("${projectforge.export.logoFile}") — nom du fichier logo depuis les propriétés de l'application
  • Initialisation paresseuse de fontResourcePath via getFontResourcePath()

Dépendances

  • Apache FOP : FopFactory, Fop, FOUserAgent, FOPException
  • JAXP XSLT : TransformerFactory, Transformer, StreamSource, SAXResult
  • Internes : ConfigurationService, GroovyEngine, Configuration, ProjectForgeVersion, ThreadLocalUserContext
  • Commons IO : IOUtils.closeQuietly()
  • Commons Lang3 : StringUtils.defaultString()
