Центральный сервис рендеринга PDF. Принимает XSL-FO таблицу стилей, Groovy/XML шаблон и карту данных, затем создаёт массив байтов PDF с использованием Apache FOP с XSLT-трансформацией и Groovy-предобработкой.

Архитектура и конвейер обработки

PdfRenderer — это Spring @Service с единственным публичным методом render(String stylesheet, String groovyXml, Map<String, Object> data). Конвейер рендеринга состоит из четырёх этапов:

1. Обогащение данных

Перед любой трансформацией карта данных обогащается стандартными переменными шаблона:

  • createdLabel — локализованная строка "создано"
  • loggedInUser — текущий PFUserDO
  • baseDir — путь к каталогу ресурсов из ConfigurationService
  • logoFile — полный путь к настроенному изображению логотипа
  • appId / appVersion — из констант ProjectForgeVersion
  • organization — из Configuration (с запасным вариантом appId)

2. Конфигурация FOP

Apache FOP настраивается с:

  • Экземпляром FopFactory, созданным с URI каталога шрифтов
  • FOUserAgent для настроек на уровне пользовательского агента
  • Объектом Fop, нацеленным на вывод MIME_PDF в ByteArrayOutputStream
  • Примечание: закомментированный код показывает предыдущую попытку использования setFontBaseURL(), которая была удалена

3. Предобработка Groovy-шаблона

XML-шаблон (groovyXml) проходит два прохода движка Groovy:

  1. preprocessGroovyXml() — предобрабатывает шаблон
  2. executeTemplate() — выполняет Groovy-шаблон с картой данных для получения финального XML

4. XSLT-трансформация + рендеринг FOP

  • XSLT-таблица стилей загружается из ресурсов через ConfigurationService.getResourceAsInputStream()
  • Создаётся Transformer с параметрами из карты данных
  • Сгенерированный Groovy XML подаётся как входной StreamSource
  • Результат передаётся как SAXResult через стандартный обработчик FOP, создавая байты PDF

Обработка ошибок

Исключения перехватываются и оборачиваются:

ИсключениеОбработка
FOPExceptionЛогируется и оборачивается в RuntimeException
TransformerExceptionЛогируется и оборачивается в RuntimeException
IOException (закрытие BAOS)Логируется и оборачивается в RuntimeException

Блок finally закрывает ByteArrayOutputStream и использует IOUtils.closeQuietly() для входного потока XSLT. После закрытия вызывается baos.toByteArray() — обратите внимание, это работает, потому что ByteArrayOutputStream.close() является пустой операцией.

Интеграция со Spring

  • @Service — автоматически обнаруживаемый Spring-бин
  • @Autowired — внедрённый ConfigurationService
  • @Value("${projectforge.export.logoFile}") — имя файла логотипа из application properties
  • Ленивая инициализация fontResourcePath через getFontResourcePath()

Зависимости

  • Apache FOP: FopFactory, Fop, FOUserAgent, FOPException
  • JAXP XSLT: TransformerFactory, Transformer, StreamSource, SAXResult
  • Внутренние: ConfigurationService, GroovyEngine, Configuration, ProjectForgeVersion, ThreadLocalUserContext
  • Commons IO: IOUtils.closeQuietly()
  • Commons Lang3: StringUtils.defaultString()
