Propósito

Representa una unión de intervalos enteros — analiza cadenas como "1,3-5,10-15,20" en un conjunto estructurado de rangos y valores individuales, luego proporciona doesMatch(valor) para probar pertenencia. Esta es la especialización entera de la clase base abstracta genérica Ranges<T> (#742).

El caso de uso concreto es el filtrado de números de semana en hojas de tiempo. Cuando un administrador configura "mostrar hojas de tiempo para las semanas 1-5, 10 y 20-25", esa cadena de configuración se pasa a new IntRanges("1-5,10,20-25"), y el número de semana de cada entrada de hoja de tiempo se prueba con rangos.doesMatch(numeroSemana). Esto es más simple y legible que construir cláusulas SQL complejas WHERE semana IN (...), especialmente cuando la lista de rangos es configurable por usuario.

Ranges maneja toda la lógica de análisis — dividir por comas/puntos y coma (separatorChars = ";,"), detectar guiones como delimitadores de rango (rangesSeparatorChar = '-'), y construir una lista de objetos Range<T> más valores aislados. IntRanges solo proporciona el método concreto parseValue(String) que convierte una cadena a un Integer — esto es el patrón Template Method: la base abstracta define el algoritmo, la subclase define la conversión de tipo.

El algoritmo de análisis (en la clase base Ranges)

Dada la entrada "1-5,10,20-25":

  1. Dividir por , o ; → ["1-5", "10", "20-25"]
  2. Para cada parte, verificar si contiene -:
    • Si sí: dividir por -, analizar ambos lados → Range(1, 5) o Range(20, 25)
    • Si no: analizar como valor único → agregar 10 a la lista de valores

El método doesMatch(valor) prueba contra todos los rangos (usando Range.doesMatch() que verifica min <= valor <= max) y todos los valores individuales (usando Comparable.compareTo() para coincidencia exacta). Una bandera nullRangeMatchesAlways controla el comportamiento cuando no se especifican rangos/valores (por defecto es false — nada coincide).

Detalles clave de diseño

  • Caracteres separadores: Se aceptan tanto la coma (,) como el punto y coma (;) — manejo elegante de entrada copiada y pegada de diferentes fuentes
  • Números negativos: El análisis soporta enteros negativos (ej. "-5--1" significa "de -5 a -1") porque Integer.valueOf() maneja el signo menos. El guion como separador de rango entra en conflicto con el signo negativo, pero el analizador verifica dos guiones consecutivos (--) como un rango con límites negativos
  • Tolerancia a espacios en blanco: El analizador recorta espacios alrededor de los valores, por lo que "1 - 5, 10" funciona igual que "1-5,10"
  • Manejo de duplicados: Agregar el mismo valor o rango superpuesto varias veces está permitido — doesMatch() devuelve true en la primera coincidencia, por lo que los duplicados no causan resultados incorrectos pero desperdician una pequeña cantidad de memoria
  • Simplicidad de 54 líneas: Todo el archivo es solo un constructor que llama a super(cadenaRangos) y una sobreescritura de parseValue() de 3 líneas. Toda la complejidad reside en la base abstracta Ranges — este es el uso ideal de la herencia: la subclase proporciona solo la conversión específica del tipo, nada más

Uso en la base de código

Se utiliza principalmente en el módulo de hojas de tiempo para el filtrado por número de semana. El filtro de hojas de tiempo (#598) permite filtrar por números de semana — el administrador o usuario ingresa una expresión de rango como "1-10, 15, 20-25", que se analiza en una instancia de IntRanges. Al mostrar las hojas de tiempo, el número de semana de cada entrada se prueba contra los rangos para determinar la visibilidad. La interfaz Serializable (heredada de Ranges) permite guardar los rangos en XML de preferencias de usuario.
