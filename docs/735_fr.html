Objectif

Représente une union d'intervalles entiers — analyse des chaînes comme "1,3-5,10-15,20" en un ensemble structuré de plages et de valeurs individuelles, puis fournit doesMatch(valeur) pour tester l'appartenance. Il s'agit de la spécialisation entière de la classe de base abstraite générique Ranges<T> (#742).

Le cas d'utilisation concret est le filtrage des numéros de semaine dans les feuilles de temps. Lorsqu'un administrateur configure « afficher les feuilles de temps pour les semaines 1-5, 10 et 20-25 », cette chaîne de configuration est passée à new IntRanges("1-5,10,20-25"), et le numéro de semaine de chaque entrée de feuille de temps est testé avec plages.doesMatch(numeroSemaine). C'est plus simple et plus lisible que de construire des clauses SQL complexes WHERE semaine IN (...), surtout lorsque la liste de plages est configurable par utilisateur.

Hiérarchie de classes

Ranges gère toute la logique d'analyse — découpage sur virgules/points-virgules (separatorChars = ";,"), détection des traits d'union comme délimiteurs de plage (rangesSeparatorChar = '-'), et construction d'une liste d'objets Range<T> plus des valeurs isolées. IntRanges fournit uniquement la méthode concrète parseValue(String) qui convertit une chaîne en Integer — c'est le modèle Template Method : la classe de base abstraite définit l'algorithme, la sous-classe définit la conversion de type.

L'algorithme d'analyse (dans la classe de base Ranges)

Étant donné l'entrée "1-5,10,20-25" :

  1. Découpage sur , ou ; → ["1-5", "10", "20-25"]
  2. Pour chaque partie, vérifier si elle contient - :
    • Si oui : découper sur -, analyser les deux côtés → Range(1, 5) ou Range(20, 25)
    • Si non : analyser comme valeur unique → ajouter 10 à la liste values

La méthode doesMatch(valeur) teste toutes les plages (en utilisant Range.doesMatch() qui vérifie min <= valeur <= max) et toutes les valeurs individuelles (en utilisant Comparable.compareTo() pour une correspondance exacte). Un indicateur nullRangeMatchesAlways contrôle le comportement lorsqu'aucune plage/valeur n'est spécifiée (par défaut false — rien ne correspond).

Détails clés de conception

  • Caractères séparateurs : La virgule (,) et le point-virgule (;) sont tous deux acceptés — gestion élégante des entrées copiées-collées de différentes sources
  • Nombres négatifs : L'analyse prend en charge les entiers négatifs (par exemple "-5--1" signifie « de -5 à -1 ») car Integer.valueOf() gère le signe moins. Le trait d'union comme séparateur de plage entre en conflit avec le signe négatif, mais l'analyseur vérifie la présence de deux traits d'union consécutifs (--) comme une plage avec des bornes négatives
  • Tolérance aux espaces : L'analyseur supprime les espaces autour des valeurs, donc "1 - 5, 10" fonctionne comme "1-5,10"
  • Gestion des doublons : L'ajout de la même valeur ou d'une plage qui se chevauche plusieurs fois est autorisé — doesMatch() retourne true dès la première correspondance, donc les doublons ne provoquent pas de résultats incorrects mais gaspillent un peu de mémoire
  • Simplicité en 54 lignes : Le fichier entier n'est qu'un constructeur qui appelle super(chaînePlages) et une redéfinition de parseValue() de 3 lignes. Toute la complexité réside dans la classe de base abstraite Ranges — c'est l'utilisation idéale de l'héritage : la sous-classe fournit uniquement la conversion spécifique au type, rien d'autre

Utilisation dans la base de code

Principalement utilisé dans le module des feuilles de temps pour le filtrage des numéros de semaine. Le filtre des feuilles de temps (#598) permet de filtrer par numéros de semaine — l'administrateur ou l'utilisateur saisit une expression de plage comme "1-10, 15, 20-25", qui est analysée en une instance IntRanges. Lors de l'affichage des feuilles de temps, le numéro de semaine de chaque entrée est testé par rapport aux plages pour déterminer la visibilité. L'interface Serializable (héritée de Ranges) permet d'enregistrer les plages dans le XML des préférences utilisateur.
