#736: KeyValueBean.java

projectforge-business/src/main/java/org/projectforge/framework/utils/KeyValueBean.java Líneas: 82 · Autor: Kai Reinhard · Tipo: POJO genérico Java 82 líneas · 40 código · 29 comentarios · 13 en blanco

Propósito

Un par clave-valor genérico, similar a java.util.Map.Entry pero independiente y comparable. Se usa en todas partes de ProjectForge donde dos datos necesitan viajar juntos: opciones de desplegable, parámetros de configuración, atributos de etiquetas HTML, criterios de ordenación, etiquetas de gráficos, etc. 82 líneas.

La clase tiene dos parámetros de tipo: KeyType (sin restricciones) y ValueType extends Comparable<ValueType> (debe ser comparable — porque el bean mismo implementa Comparable basado en el valor). Esto es diferente de ILabelValueBean — esa interfaz no requiere comparabilidad; esta clase sí, porque se usa en colecciones ordenadas.

Comportamiento Comparable

El método compareTo() compara solo por valor, ignorando la clave por completo. El valor debe implementar Comparable — esto se aplica a nivel de tipo. Esto significa que dos KeyValueBeans con claves diferentes pero valores iguales se consideran iguales a efectos de ordenación. Esto es correcto para listas desplegables ordenadas (donde ordenas por el texto mostrado, no por el ID), pero sorprendente si usas KeyValueBean como clave de HashMap (donde equals/hashCode importan más — y estos se heredan de Object, no se sobrescriben). Esta es una decisión de diseño deliberada: KeyValueBean es principalmente para visualización ordenada, no para almacenamiento en mapas.

Constructores

  • KeyValueBean() — constructor vacío para frameworks que lo necesitan (serialización Wicket, XStream)
  • KeyValueBean(clave) — solo clave (el valor por defecto es null). Se usa cuando la clave misma es la información a mostrar
  • KeyValueBean(clave, valor) — constructor completo. El más usado

Relación con ILabelValueBean

Clave-valor vs etiqueta-valor — mismo patrón, semántica diferente:

  • ILabelValueBean<L,V> — la etiqueta es lo que el usuario ve, el valor es el ID del sistema. Se usa para desplegables de UI. Ambos tipos no tienen restricciones
  • KeyValueBean<K, V> — la clave es un identificador del sistema, el valor son datos comparables. Se usa para estructuras de datos. El valor debe ser Comparable

Conceptualmente son el mismo patrón pero se usan en contextos diferentes. La distinción en el nombre (Etiqueta vs Clave) fue intencional — ayuda a los lectores a entender el dominio: etiqueta/valor para UI, clave/valor para estructuras de datos internas.
