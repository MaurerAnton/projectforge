Назначение

Универсальная пара «ключ-значение», похожая на java.util.Map.Entry, но автономная и сопоставимая. Используется повсеместно в ProjectForge, где два фрагмента данных должны передаваться вместе — параметры выпадающих списков, конфигурационные параметры, атрибуты HTML-тегов, критерии сортировки, метки диаграмм и т. д. 82 строки.

Класс имеет два параметра типа: KeyType (без ограничений) и ValueType extends Comparable<ValueType> (должен быть сопоставимым — потому что сам бин реализует Comparable на основе значения). Это отличие от ILabelValueBean — тот интерфейс не требует сопоставимости; этот класс требует, потому что используется в отсортированных коллекциях.

Поведение Comparable

Метод compareTo() сравнивает только по значению, полностью игнорируя ключ. Значение должно реализовывать Comparable — это обеспечивается на уровне типа. Это означает, что два KeyValueBean с разными ключами, но равными значениями считаются равными для целей упорядочивания. Это корректно для отсортированных выпадающих списков (где сортировка идёт по отображаемому тексту, а не по ID), но может быть неожиданным, если использовать KeyValueBean в качестве ключа HashMap (где equals/hashCode важнее — а они унаследованы от Object и не переопределены). Это осознанный компромисс в дизайне: KeyValueBean предназначен в первую очередь для упорядоченного отображения, а не для хранения в картах.

Конструкторы

  • KeyValueBean() — пустой конструктор для фреймворков, которым он нужен (сериализация Wicket, XStream)
  • KeyValueBean(key) — только ключ (значение по умолчанию null). Используется, когда сам ключ является отображаемой информацией
  • KeyValueBean(key, value) — полный конструктор. Используется наиболее часто

Связь с ILabelValueBean

Ключ-значение против метка-значение — одинаковый паттерн, разная семантика:

  • ILabelValueBean<L,V> — метка — это то, что видит пользователь, значение — системный ID. Используется для выпадающих списков UI. Оба типа не имеют ограничений
  • KeyValueBean<K, V> — ключ — системный идентификатор, значение — любые сопоставимые данные. Используется для структур данных. Значение должно быть Comparable

Концептуально это один и тот же паттерн, но используется в разных контекстах. Различие в названиях (Label vs Key) было намеренным — оно помогает читателям понять область применения: метка/значение для UI, ключ/значение для внутренних структур данных.
