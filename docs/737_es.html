#737: KeyValuePairParser.java

projectforge-business/src/main/java/org/projectforge/framework/utils/KeyValuePairParser.java Líneas: 301 · Autor: Kai Reinhard · Tipo: Analizador léxico/parser escrito a mano en Java — cero dependencias 301 líneas · 229 código · 34 comentarios · 38 en blanco

Propósito

Un analizador de flujo escrito a mano que lee pares clave=valor desde un java.io.Reader, un carácter a la vez. Sin expresiones regulares, sin bibliotecas de análisis de terceros — solo análisis puro carácter por carácter con estado, utilizando un búfer de retroceso de 5 elementos. Este es el tipo de código que existía antes de que bibliotecas como Apache Commons CSV se volvieran estándar — o escrito porque el autor quería control exacto sobre los mensajes de error y casos límite sin sobrecarga de dependencias.

El analizador soporta: valores entre comillas (con "), comillas escapadas dentro de cadenas entrecomilladas ("" → una " literal), carácter separador configurable (por defecto el de KeyValuePairWriter.DEFAULT_SEPARATOR_CHAR), seguimiento de línea/columna para mensajes de error, y omisión de espacios en blanco. Formato de entrada: clave1=valor1,clave2="valor entre comillas, con coma",clave3=123.

Arquitectura: un mini analizador léxico

301 líneas. El analizador está estructurado como un analizador léxico clásico de dos fases:

  1. Lector de caracteres (read() / nextToken() / unread()): lee un carácter del Reader, rastrea números de línea/columna, maneja saltos de línea \r\n (Windows) y \n (Unix), y clasifica el token como EOF, EOL o CHAR. El método nextToken() es el tokenizador
  2. Analizador sintáctico (parseKey() / parseValue()): consume tokens para construir las cadenas de clave y valor. parse() es el punto de entrada que llama a parseKey+parseValue en un bucle hasta EOF/EOL

Esta es la misma arquitectura que un front-end de compilador — tokenizador + analizador sintáctico — solo que para datos clave=valor en lugar de lenguajes de programación.

Búfer de retroceso

Un int[] pushbackBuffer de 5 elementos con índice pushbackIndex. Cuando el analizador lee un carácter de más (por ejemplo, en skipWhitespaces()), devuelve el carácter mediante unread(int b). El búfer actualiza los contadores de línea/columna al retroceder saltos de línea — crítico para mensajes de error precisos. 5 elementos son suficientes para cualquier anticipación necesaria en este analizador (la anticipación máxima es de 1-2 caracteres). Esta es la implementación estándar de anticipación de 1 carácter — la forma más simple de retroceso.

Manejo de valores entre comillas — la lógica más compleja

parseValue() (líneas 141-189) implementa un analizador de campos entrecomillados estilo CSV completo:

  1. Omite espacios en blanco, lee el primer carácter
  2. Si el primer carácter es ", entra en modo entrecomillado (quoted=true)
  3. En modo entrecomillado:
    • "" → comilla escapada (agrega una " al valor)
    • " seguido de separador o espacio+separador → fin del valor
    • " seguido de cualquier otra cosa → error (UNEXPECTED_CHARACTER_AFTER_QUOTATION_MARK)
    • Cualquier otro carácter → se agrega al búfer del valor
  4. En modo no entrecomillado:
    • Carácter separador → fin del valor
    • " → error (UNEXPECTED_QUOTATIONMARK — las comillas solo se permiten en modo entrecomillado)
    • Cualquier otro carácter → se agrega
  5. Si se alcanza EOF/EOL mientras está entrecomillado → error (QUOTATIONMARK_MISSED_AT_END_OF_CELL)

Esto sigue la especificación CSV RFC 4180 para campos entrecomillados, pero simplificada — sin campos entrecomillados multilínea, sin detección de encabezados, sin inferencia de tipos.

Manejo de errores — información de ubicación precisa

Cada mensaje de error incluye número de línea y número de columna — por ejemplo, "Unexpected quotation mark... Error in line: 3 (14)". Esto es crítico para depurar archivos de configuración. El método estático createMessage() formatea los errores con el patrón: msg + " Error in line: " + line + " (" + col + ")" + (s != null ? ": " + s : ""). Los contadores lineno y colno son mantenidos por read() (incrementa línea en \n) y nextToken() (incrementa columna en cada carácter).

Contexto de uso

Este analizador se utiliza para leer archivos de configuración y entradas de parámetros de scripts — lugares donde los usuarios o administradores escriben datos clave=valor en archivos de texto simples. Ejemplo de archivo analizado por esto:

nombre=ProjectForge
versión="8.0.0"
descripción="Sistema ERP con hoja de tiempos, calendario y contabilidad"
maxUsuarios=100

El analizador lee línea por línea (EOL detiene cada llamada a parse()), produciendo un Map<String, String>. La clase complementaria KeyValuePairWriter hace lo inverso — escribe mapas en formato de texto clave=valor.
