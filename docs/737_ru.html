Назначение

Ручной потоковый парсер, который читает пары ключ=значение из java.io.Reader, по одному символу за раз. Никаких регулярных выражений, никаких сторонних библиотек для парсинга — только чистый посимвольный парсинг с сохранением состояния и 5-элементным буфером возврата. Это тот код, который существовал до того, как библиотеки вроде Apache Commons CSV стали стандартом — или написан, потому что автор хотел полного контроля над сообщениями об ошибках и граничными случаями без накладных расходов на зависимости.

Парсер поддерживает: значения в кавычках (с "), экранированные кавычки внутри строк в кавычках ("" → литерал "), настраиваемый символ-разделитель (по умолчанию из KeyValuePairWriter.DEFAULT_SEPARATOR_CHAR), отслеживание строки/столбца для сообщений об ошибках и пропуск пробелов. Формат ввода: ключ1=значение1,ключ2="значение в кавычках, с запятой",ключ3=123.

Архитектура: миниатюрный лексер

301 строка. Парсер построен как классический двухфазный лексер:

  1. Читатель символов (read() / nextToken() / unread()): читает один символ из Reader, отслеживает номера строк/столбцов, обрабатывает \r\n (Windows) и \n (Unix) как конец строки и классифицирует токен как EOF, EOL или CHAR. Метод nextToken() является токенизатором
  2. Парсер (parseKey() / parseValue()): потребляет токены для построения строк ключа и значения. parse() — точка входа, которая вызывает parseKey+parseValue в цикле до достижения EOF/EOL

Это та же архитектура, что и у фронтенда компилятора — токенизатор + парсер — только для данных вида ключ=значение вместо языков программирования.

Буфер возврата

5-элементный int[] pushbackBuffer с индексом pushbackIndex. Когда парсер читает на один символ слишком много (например, в skipWhitespaces()), он возвращает символ обратно через unread(int b). Буфер обновляет счётчики строк/столбцов при возврате символов новой строки — критически важно для точных сообщений об ошибках. 5 элементов достаточно для любого опережающего просмотра, необходимого этому парсеру (максимальный опережающий просмотр — 1-2 символа). Это стандартная реализация опережающего просмотра на 1 символ — простейшая форма возврата.

Обработка значений в кавычках — самая сложная логика

parseValue() (строки 141-189) реализует полноценный парсер полей в кавычках в стиле CSV:

  1. Пропускает пробелы, читает первый символ
  2. Если первый символ — ", переходит в режим кавычек (quoted=true)
  3. В режиме кавычек:
    • "" → экранированная кавычка (добавляет один " к значению)
    • " после которой идёт разделитель или пробел+разделитель → конец значения
    • " после которой идёт что-то ещё → ошибка (UNEXPECTED_CHARACTER_AFTER_QUOTATION_MARK)
    • Любой другой символ → добавляется в буфер значения
  4. В режиме без кавычек:
    • Символ-разделитель → конец значения
    • " → ошибка (UNEXPECTED_QUOTATIONMARK — кавычки разрешены только в режиме кавычек)
    • Любой другой символ → добавляется
  5. Если достигнут EOF/EOL, когда значение в кавычках → ошибка (QUOTATIONMARK_MISSED_AT_END_OF_CELL)

Это соответствует спецификации CSV RFC 4180 для полей в кавычках, но в упрощённом виде — без многострочных полей в кавычках, без определения заголовков, без определения типов.

Обработка ошибок — точная информация о местоположении

Каждое сообщение об ошибке включает номер строки и номер столбца — например, "Неожиданный знак кавычки... Ошибка в строке: 3 (14)". Это критически важно для отладки конфигурационных файлов. Статический метод createMessage() форматирует ошибки по шаблону: msg + " Ошибка в строке: " + line + " (" + col + ")" + (s != null ? ": " + s : ""). Счётчики lineno и colno поддерживаются методами read() (увеличивает строку при \n) и nextToken() (увеличивает столбец для каждого символа).

Контекст использования

Этот парсер используется для чтения конфигурационных файлов и входных параметров скриптов — мест, где пользователи или администраторы записывают данные в формате ключ=значение в простых текстовых файлах. Пример файла, разбираемого этим парсером:

name=ProjectForge
version="8.0.0"
description="ERP-система с табелем учёта времени, календарём и бухгалтерией"
maxUsers=100

Парсер читает построчно (EOL останавливает каждый вызов parse()), создавая Map<String, String>. Сопутствующий класс KeyValuePairWriter делает обратное — записывает карты в текстовый формат ключ=значение.
