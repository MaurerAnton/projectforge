Zweck

Serialisiert Schlüssel-Wert-Paare in ein kommagetrenntes Textformat — die Umkehrung von KeyValuePairParser. Wandelt eine Folge von write(key, value)-Aufrufen in eine einzelne Zeile wie name="ProjectForge",version=8.0,maxUsers=100 um. 157 Zeilen.

Der Writer behandelt korrekte Anführungszeichen: Zeichenkettenwerte werden immer in doppelte Anführungszeichen gesetzt, und jedes " innerhalb des Werts wird durch Verdopplung maskiert (" → "") — dieselbe CSV-Konvention, die der Parser erwartet. Zahlen und Daten werden ohne Anführungszeichen geschrieben. Das Trennzeichen ist standardmäßig ein Komma, kann aber über setCsvSeparator() konfiguriert werden.

Überladene write()-Methoden — 4 Varianten

  • write(key, long value) — schreibt als reine Zahl: maxUsers=100. Keine Anführungszeichen — sicher, da Zahlen keine Sonderzeichen enthalten
  • write(key, Date value) — schreibt als Zeichenkette in Anführungszeichen im Format "yyyy-MM-dd HH:mm:ss.SSS". Das Datumsformat ist über setDateFormat() konfigurierbar. Beispiel: lastUpdate="2025-01-24 14:30:00.000"
  • write(key, String s) — schreibt als Zeichenkette in Anführungszeichen mit Maskierungsbehandlung. Durchläuft jedes Zeichen: Wenn das Zeichen " ist, wird es zweimal geschrieben ("" → maskiertes Anführungszeichen). Beispiel: description="Hallo, das ist ein ""Test""." → dies kodiert als Hallo, das ist ein "Test". beim Parsen
  • write(key, Object value) — Fallback für jeden Typ. Verwendet String.valueOf(value) — keine Anführungszeichen. Geeignet für Typen, bei denen toString() eine sichere, nicht in Anführungszeichen gesetzte Darstellung erzeugt. Nicht empfohlen für Zeichenketten (verwenden Sie stattdessen die String-Überladung — diese Methode maskiert keine Anführungszeichen)

Trennzeichen-Logik

Die Methode writeSeparator() implementiert das klassische Erster-Eintrag-Muster: Wenn dies der erste Eintrag ist, wird kein Trennzeichen geschrieben; andernfalls wird vor dem aktuellen Eintrag ein Komma eingefügt. Dadurch wird ein abschließendes Komma am Ende der Zeile vermieden. Der boolesche Wert firstEntry wird mit jeder neuen Zeile zurückgesetzt (das EOL des Parsers löst eine neue Writer-Instanz oder einen Reset aus).

Standard-Trennzeichen-Konstante

DEFAULT_SEPARATOR_CHAR = ',' ist öffentlich — wird von KeyValuePairParser verwendet, um dessen pairsSeparatorChar vorzubelegen. Sowohl Parser als auch Writer verwenden standardmäßig das Komma, und beide erlauben eine Änderung. Die Konstante stellt sicher, dass sie mit demselben Standardwert beginnen.
