Objectif

Sérialise les paires clé-valeur dans un format texte séparé par des virgules — l'inverse de KeyValuePairParser. Convertit une séquence d'appels write(clé, valeur) en une seule ligne comme nom="ProjectForge",version=8.0,utilisateursMax=100. 157 lignes.

Le writer gère un guillemetage approprié : les valeurs chaîne sont toujours entourées de guillemets doubles, et tout " à l'intérieur de la valeur est échappé en le doublant (" → "") — la même convention CSV attendue par l'analyseur. Les nombres et les dates sont écrits sans guillemets. Le caractère séparateur par défaut est la virgule mais est configurable via setCsvSeparator().

Méthodes write() surchargées — 4 variantes

  • write(clé, valeur long) — écrit comme un nombre brut : utilisateursMax=100. Pas de guillemets — sûr car les nombres ne contiennent pas de caractères spéciaux
  • write(clé, valeur Date) — écrit comme une chaîne entre guillemets au format "yyyy-MM-dd HH:mm:ss.SSS". Le format de date est configurable via setDateFormat(). Exemple : dernièreMiseÀJour="2025-01-24 14:30:00.000"
  • write(clé, chaîne s) — écrit comme une chaîne entre guillemets avec gestion d'échappement. Parcourt chaque caractère : si le caractère est ", l'écrit deux fois ("" → guillemet échappé). Exemple : description="Bonjour, ceci est un ""Test""." → cela encode comme Bonjour, ceci est un "Test". lors de l'analyse
  • write(clé, valeur Objet) — solution de repli pour tout type. Utilise String.valueOf(valeur) — pas de guillemets. Adapté pour les types où toString() produit une représentation sûre et non guillemetée. Non recommandé pour les chaînes (utilisez plutôt la surcharge String — cette méthode n'échappe pas les guillemets)

Logique du séparateur

La méthode writeSeparator() implémente le modèle de première entrée classique : s'il s'agit de la première entrée, aucun séparateur n'est écrit ; sinon, une virgule est insérée avant l'entrée courante. Cela évite une virgule finale à la fin de la ligne. Le booléen firstEntry est réinitialisé à chaque nouvelle ligne (le EOL de l'analyseur déclenche une nouvelle instance du writer ou une réinitialisation).

Constante de séparateur par défaut

DEFAULT_SEPARATOR_CHAR = ',' est publique — utilisée par KeyValuePairParser pour définir par défaut son pairsSeparatorChar. L'analyseur et le writer utilisent tous deux la virgule par défaut, et tous deux permettent de la modifier. La constante garantit qu'ils commencent avec la même valeur par défaut.
