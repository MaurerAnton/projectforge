Propósito

Implementación concreta del patrón Etiqueta/Valor. 89 líneas. Este es el DTO más utilizado en la capa de UI de ProjectForge — cada desplegable, cada autocompletado, cada lista de selección se construye a partir de un List<LabelValueBean>. La "Etiqueta" es lo que el usuario ve (típicamente texto localizado); el "Valor" es lo que el sistema almacena (típicamente un ID Long o una constante enum).

Jerarquía de clases: ILabelValueBean<L, V> (interfaz) → LabelValueBean<L extends Comparable<L>, V> (esta clase). Nótese la restricción adicional respecto a la interfaz — L debe ser Comparable porque el bean compara por etiqueta.

Estrategia de comparación: ordenado por ETIQUETA

Punto clave: LabelValueBean compara por etiqueta (this.label.compareTo(o.label)), mientras que KeyValueBean compara por valor. Esta es la diferencia semántica fundamental:

  • LabelValueBean: la etiqueta es la clave de ordenación principal — "ordena este desplegable alfabéticamente por nombre mostrado." El valor (ID) es secundario — es solo la carga útil
  • KeyValueBean: el valor es la clave de ordenación principal — "ordena estos parámetros de configuración por su valor numérico." La clave (nombre) es el identificador

Esto significa que la restricción de tipo también está en la etiqueta: L extends Comparable<L>. El tipo de valor V no tiene restricciones — no necesita ser comparable porque el bean nunca compara valores.

Mutabilidad del bean

A diferencia de KeyValueBean (que es efectivamente inmutable — sin setters), LabelValueBean tiene un setter setValue(V). La etiqueta no tiene setter pero el campo es protected — las subclases pueden modificarlo. Esta mutabilidad importa porque el framework de enlace de formularios de Wicket (PropertyModel) a menudo necesita escribir de vuelta los valores seleccionados en el bean — la selección del desplegable establece el valor mediante setValue(). KeyValueBean no necesita esto porque se usa en contextos de solo lectura (visualización de configuración, etiquetas de gráficos).

toString()

Usa ToStringBuilder pero con nombres de campo intercambiados (un error menor): imprime key={valor} y value={etiqueta} — los nombres "key" y "value" provienen de un copiar-pegar del toString de KeyValueBean. Los datos reales son correctos (etiqueta y valor están en las posiciones correctas), pero las etiquetas son engañosas. Esto no tiene impacto funcional — toString() solo se usa para depuración.

Constructores

  • LabelValueBean() — vacío para deserialización Wicket/XStream
  • LabelValueBean(V value) — solo valor (la etiqueta por defecto es null). Se usa cuando la etiqueta se calculará más tarde o cuando el valor es también la etiqueta
  • LabelValueBean(L label, V value) — constructor completo. El más usado: new LabelValueBean<>("Juan Pérez", 42L)
