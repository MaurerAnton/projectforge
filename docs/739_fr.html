Objectif

Implémentation concrète du pattern Label/Valeur. 89 lignes. C'est le DTO le plus couramment utilisé dans la couche UI de ProjectForge — chaque liste déroulante, chaque autocomplétion, chaque liste de sélection est construite à partir d'une List<LabelValueBean>. Le « Label » est ce que l'utilisateur voit (généralement du texte localisé) ; la « Valeur » est ce que le système stocke (généralement un ID Long ou une constante d'énumération).

Hiérarchie de classes : ILabelValueBean<L, V> (interface) → LabelValueBean<L extends Comparable<L>, V> (cette classe). Notez la contrainte supplémentaire par rapport à l'interface — L doit être Comparable car le bean compare par label.

Stratégie de comparaison : trié par LABEL

Point clé : LabelValueBean compare par label (this.label.compareTo(o.label)), tandis que KeyValueBean compare par valeur. C'est la différence sémantique fondamentale :

  • LabelValueBean : le label est la clé de tri principale — « trier cette liste déroulante par ordre alphabétique du nom affiché ». La valeur (ID) est secondaire — c'est juste la charge utile
  • KeyValueBean : la valeur est la clé de tri principale — « trier ces paramètres de configuration par leur valeur numérique ». La clé (nom) est l'identifiant

Cela signifie que la contrainte de type porte également sur le label : L extends Comparable<L>. Le type de valeur V est sans contrainte — il n'a pas besoin d'être comparable car le bean ne compare jamais les valeurs.

Mutabilité du bean

Contrairement à KeyValueBean (qui est effectivement immuable — pas de setters), LabelValueBean possède un setter setValue(V). Le label n'a pas de setter mais le champ est protected — les sous-classes peuvent le modifier. Cette mutabilité est importante car le framework de liaison de formulaires de Wicket (PropertyModel) a souvent besoin de réécrire les valeurs sélectionnées dans le bean — la sélection dans la liste déroulante définit la valeur via setValue(). KeyValueBean n'en a pas besoin car il est utilisé dans des contextes en lecture seule (affichage de configuration, étiquettes de graphiques).

toString()

Utilise ToStringBuilder mais avec des noms de champs inversés (un bug mineur) : il affiche key={valeur} et value={label} — les noms « key » et « value » proviennent d'un copier-coller du toString de KeyValueBean. Les données réelles sont correctes (label et valeur sont aux bonnes positions), mais les libellés sont trompeurs. Cela n'a aucun impact fonctionnel — toString() n'est utilisé que pour le débogage.

Constructeurs

  • LabelValueBean() — vide pour la désérialisation Wicket/XStream
  • LabelValueBean(V value) — valeur uniquement (label par défaut à null). Utilisé lorsque le label sera calculé plus tard ou lorsque la valeur est aussi le label
  • LabelValueBean(L label, V value) — constructeur complet. Le plus couramment utilisé : new LabelValueBean<>("John Doe", 42L)
