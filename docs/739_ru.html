Назначение

Конкретная реализация паттерна «Метка/Значение». 89 строк. Это наиболее часто используемый DTO в UI-слое ProjectForge — каждый выпадающий список, каждое автодополнение, каждый список выбора строится из List<LabelValueBean>. «Метка» — это то, что видит пользователь (обычно локализованный текст); «Значение» — то, что хранит система (обычно Long ID или константа перечисления).

Иерархия классов: ILabelValueBean<L, V> (интерфейс) → LabelValueBean<L extends Comparable<L>, V> (данный класс). Обратите внимание на дополнительное ограничение по сравнению с интерфейсом — L должен быть Comparable, так как бин сравнивается по метке.

Стратегия сравнения: сортировка по МЕТКЕ

Ключевое понимание: LabelValueBean сравнивает по метке (this.label.compareTo(o.label)), в то время как KeyValueBean сравнивает по значению. В этом заключается фундаментальное семантическое различие:

  • LabelValueBean: метка является первичным ключом сортировки — «отсортировать этот выпадающий список по алфавиту по отображаемому имени». Значение (ID) является вторичным — это просто нагрузка
  • KeyValueBean: значение является первичным ключом сортировки — «отсортировать эти параметры конфигурации по их числовому значению». Ключ (имя) является идентификатором

Это означает, что ограничение типа также накладывается на метку: L extends Comparable<L>. Тип значения V не ограничен — ему не нужно быть сравнимым, так как бин никогда не сравнивает значения.

Изменяемость бина

В отличие от KeyValueBean (который фактически неизменяем — нет сеттеров), LabelValueBean имеет сеттер setValue(V). Метка не имеет сеттера, но поле объявлено как protected — подклассы могут его изменять. Эта изменяемость важна, потому что фреймворк привязки форм Wicket (PropertyModel) часто должен записывать обратно выбранные значения в бин — выбор в выпадающем списке устанавливает значение через setValue(). KeyValueBean не нуждается в этом, так как используется в контекстах «только для чтения» (отображение конфигурации, метки диаграмм).

toString()

Использует ToStringBuilder, но с перепутанными именами полей (небольшая ошибка): выводит key={значение} и value={метка} — имена «key» и «value» взяты из копипаста toString от KeyValueBean. Фактические данные корректны (метка и значение находятся на правильных позициях), но названия вводят в заблуждение. Это не имеет функционального влияния — toString() используется только для отладки.

Конструкторы

  • LabelValueBean() — пустой для десериализации Wicket/XStream
  • LabelValueBean(V value) — только значение (метка по умолчанию null). Используется, когда метка будет вычислена позже или когда значение также является меткой
  • LabelValueBean(L label, V value) — полный конструктор. Наиболее часто используемый: new LabelValueBean<>("Иван Иванов", 42L)
