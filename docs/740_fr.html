#740 : ListHelper.java

projectforge-business/src/main/java/org/projectforge/framework/utils/ListHelper.java Lignes : 39 · Auteur : Kai Reinhard · Type : Utilitaire Java — 1 méthode 39 lignes · 10 code · 26 commentaires · 3 vides

Objectif

Une classe utilitaire à 1 méthode — littéralement 39 lignes (dont 17 pour l'en-tête de licence GPLv3). Fournit addAll(List<T> list, T... elements) — une commodité varargs pour ajouter plusieurs éléments à une liste en un seul appel. Sans cela : list.addAll(Arrays.asList(a, b, c)). Avec cela : ListHelper.addAll(list, a, b, c).

Pourquoi cela existe-t-il ? La méthode List.addAll() de Java prend une Collection, pas des varargs. Pour ajouter des éléments individuels, vous devez d'abord les encapsuler dans Arrays.asList() — ce qui est verbeux lorsque vous avez 3-4 éléments en ligne. Cette méthode est purement du sucre syntaxique — elle fait exactement la même chose que list.addAll(Arrays.asList(elements)) sans aucune logique supplémentaire.

En Java 9+, la bibliothèque standard a ajouté List.of(a, b, c) (qui retourne une liste immuable), mais comme ProjectForge cible Java 17 et que ce code date de l'ère Java 8, le modèle varargs était un ajout personnalisé courant. Le code moderne utiliserait plutôt l'API Stream ou List.copyOf().

Critique de conception

Une classe avec une seule méthode d'une ligne est généralement un code smell — elle devrait soit être supprimée (les appelants peuvent utiliser Arrays.asList directement), soit être enrichie avec davantage d'utilitaires de liste. Cependant, ce modèle (classes d'assistance à méthode unique) est courant dans l'ancien code de ProjectForge, reflétant une culture de développement où la création d'une nouvelle classe utilitaire était préférée au code passe-partout en ligne. Dans le code Kotlin moderne de ProjectForge, cela serait une simple fonction d'extension : fun <T> MutableList<T>.addAll(vararg elements: T) — mais l'API Java ne prend pas en charge les fonctions d'extension, donc la classe demeure.
