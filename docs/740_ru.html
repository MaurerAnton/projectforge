#740: ListHelper.java

projectforge-business/src/main/java/org/projectforge/framework/utils/ListHelper.java Строк: 39 · Автор: Kai Reinhard · Тип: Утилита Java — 1 метод 39 строк · 10 кода · 26 комментариев · 3 пустых

Назначение

Утилитарный класс с одним методом — буквально 39 строк (17 из которых — заголовок лицензии GPLv3). Предоставляет addAll(List<T> list, T... elements) — удобную обёртку с переменным числом аргументов для добавления нескольких элементов в список одним вызовом. Без него: list.addAll(Arrays.asList(a, b, c)). С ним: ListHelper.addAll(list, a, b, c).

Зачем это существует? Метод Java List.addAll() принимает Collection, а не varargs. Чтобы добавить отдельные элементы, их нужно сначала обернуть в Arrays.asList() — что становится громоздким при 3-4 элементах в строке. Этот метод — чистый синтаксический сахар: он делает то же самое, что и list.addAll(Arrays.asList(elements)), без какой-либо дополнительной логики.

В Java 9+ стандартная библиотека добавила List.of(a, b, c) (возвращает неизменяемый список), но поскольку ProjectForge ориентируется на Java 17, а этот код относится к эпохе Java 8, шаблон с varargs был распространённым кастомным дополнением. В современном коде вместо этого использовали бы Stream API или List.copyOf().

Критика дизайна

Класс с одним однострочным методом обычно является признаком плохого кода — его следует либо удалить (вызывающие могут использовать Arrays.asList напрямую), либо расширить дополнительными утилитами для списков. Однако этот шаблон (классы-помощники с одним методом) распространён в старом коде ProjectForge, отражая культуру разработки, где создание нового утилитарного класса предпочитали встраиваемому шаблонному коду. В современном Kotlin-коде ProjectForge это была бы простая функция-расширение: fun <T> MutableList<T>.addAll(vararg elements: T) — но Java API не поддерживает функции-расширения, поэтому класс остаётся.
