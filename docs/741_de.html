Zweck

Generischer, reflexionsbasierter Bean-Vergleicher mit Unterstützung für natürliche und alphanumerische Sortierung. 139 Zeilen. Sortiert jede Liste von Java-Beans nach einer oder zwei Eigenschaften mittels Laufzeit-Reflexion — ohne Typsicherheit zur Kompilierzeit für den Eigenschaftsnamen. Dies ist der Vergleicher, der von Wickets SortableDataProvider auf jeder Listenseite verwendet wird — wenn ein Benutzer auf eine Spaltenüberschrift klickt, um zu sortieren, wird dieser Vergleicher mit dem Eigenschaftsnamen der Spalte und der Sortierrichtung instanziiert.

Sortierfähigkeiten

  • Primäre + sekundäre Sortierung: Der Konstruktor akzeptiert eine Eigenschaft (Einzelschlüsselsortierung) oder eine primäre + sekundäre Eigenschaft (die sekundäre wird als Tiebreaker verwendet, wenn primäre Werte gleich sind)
  • Verschachtelter Eigenschaftszugriff: Verwendet BeanHelper.getNestedProperty(obj, "address.city") — Punktnotation durchläuft Objektgraphen: user.getAddress().getCity()
  • Null-Behandlung: Null-Werte werden im aufsteigenden Modus vor Nicht-Null sortiert (umgekehrt im absteigenden). Zwei Nulls sind gleich
  • Alphanumerische Sortierung: Wenn das Eigenschaftsfeld mit @StringAlphanumericSort annotiert ist, wird se.sawano.java.text.AlphanumericComparator verwendet, der "file2.txt" korrekt vor "file10.txt" sortiert (natürliche Sortierreihenfolge)
  • Fallback auf String: Wenn die beiden Werte inkompatible Typen haben (z.B. ein Integer, ein String), wird auf String.valueOf()-Vergleich zurückgegriffen — dies behandelt Listen mit gemischten Typen problemlos

Annotationsbasierte Sortiererkennung

Die Methode checkAnnotation() prüft, ob der Getter/das Feld der Eigenschaft die Annotation @StringAlphanumericSort besitzt. Diese Annotation auf einem DO-Feld bedeutet: "Sortiere diese Spalte alphanumerisch, nicht lexikografisch." Beispiel: Ein Feld, das Dokumentnamen wie "Report1", "Report2", "Report10" anzeigt — lexikografische Sortierung ergibt "Report1", "Report10", "Report2"; alphanumerisch ergibt "Report1", "Report2", "Report10". Beide Objekte müssen die Annotation für die alphanumerische Sortierung besitzen — andernfalls wird auf Standard-String.compareTo() zurückgegriffen.

Fehlertoleranz

Wenn der Eigenschaftszugriff eine Ausnahme auslöst (z.B. NoSuchMethodException für einen falsch geschriebenen Eigenschaftsnamen), wird der Fehler protokolliert und 0 zurückgegeben — die beiden Objekte werden für Sortierzwecke als gleich betrachtet. Dies verhindert, dass ein einzelner falscher Eigenschaftsname eine gesamte Listenseite zum Absturz bringt. Dies ist ein ausfallsicheres Design — der Benutzer sieht unsortierte Daten anstelle einer Fehlerseite.
