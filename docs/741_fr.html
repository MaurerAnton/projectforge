Objectif

Comparateur générique de beans basé sur la réflexion avec prise en charge du tri naturel et alphanumérique. 139 lignes. Trie n'importe quelle liste de beans Java par une ou deux propriétés en utilisant la réflexion à l'exécution — aucune sécurité de type à la compilation sur le nom de la propriété. C'est le comparateur utilisé par le SortableDataProvider de Wicket dans chaque page de liste — lorsqu'un utilisateur clique sur un en-tête de colonne pour trier, ce comparateur est instancié avec le nom de la propriété de la colonne et la direction du tri.

Capacités de tri

  • Tri primaire + secondaire : le constructeur accepte une propriété (tri à clé unique) ou une propriété primaire + secondaire (la secondaire est utilisée comme départage lorsque les valeurs primaires sont égales)
  • Accès aux propriétés imbriquées : utilise BeanHelper.getNestedProperty(obj, "address.city") — la notation par points parcourt les graphes d'objets : user.getAddress().getCity()
  • Gestion des valeurs nulles : les valeurs nulles sont triées avant les non-nulles en mode ascendant (l'inverse en mode descendant). Deux valeurs nulles sont considérées comme égales
  • Tri alphanumérique : si le champ de la propriété est annoté @StringAlphanumericSort, utilise se.sawano.java.text.AlphanumericComparator qui trie correctement "fichier2.txt" avant "fichier10.txt" (ordre de tri naturel)
  • Recours au texte : si les deux valeurs ont des types incompatibles (par ex. un Integer, un String), utilise la comparaison String.valueOf() — cela gère élégamment les listes de types mixtes

Détection du type de tri basée sur les annotations

La méthode checkAnnotation() vérifie si le getter/champ de la propriété possède l'annotation @StringAlphanumericSort. Cette annotation sur un champ DO signifie « trier cette colonne de manière alphanumérique, pas lexicographique ». Exemple : un champ affichant des noms de documents comme « Rapport1 », « Rapport2 », « Rapport10 » — le tri lexicographique donne « Rapport1 », « Rapport10 », « Rapport2 » ; le tri alphanumérique donne « Rapport1 », « Rapport2 », « Rapport10 ». Les deux objets doivent avoir l'annotation pour que le tri alphanumérique soit utilisé — sinon, on revient à String.compareTo() standard.

Résilience aux erreurs

Si l'accès à la propriété lève une exception (par ex. NoSuchMethodException pour un nom de propriété mal orthographié), l'erreur est journalisée et 0 est retourné — les deux objets sont considérés comme égaux à des fins de tri. Cela empêche qu'un seul mauvais nom de propriété ne casse une page de liste entière. Il s'agit d'une conception sécurisée — l'utilisateur voit des données non triées plutôt qu'une page d'erreur.
