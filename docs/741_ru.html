Назначение

Универсальный компаратор бинов на основе рефлексии с поддержкой естественной и буквенно-цифровой сортировки. 139 строк. Сортирует любой список Java-бинов по одному или двум свойствам, используя рефлексию времени выполнения — без типобезопасности на уровне компиляции для имени свойства. Это компаратор, используемый SortableDataProvider из Wicket на каждой странице со списком — когда пользователь щёлкает по заголовку столбца для сортировки, этот компаратор создаётся с именем свойства столбца и направлением сортировки.

Возможности сортировки

  • Первичная + вторичная сортировка: конструктор принимает одно свойство (одноключевая сортировка) или первичное + вторичное свойство (вторичное используется как дополнительный критерий, когда первичные значения равны)
  • Доступ к вложенным свойствам: использует BeanHelper.getNestedProperty(obj, "address.city") — точечная нотация обходит графы объектов: user.getAddress().getCity()
  • Обработка null: нулевые значения сортируются перед не-нулевыми в режиме по возрастанию (противоположно при сортировке по убыванию). Два null считаются равными
  • Буквенно-цифровая сортировка: если поле свойства аннотировано @StringAlphanumericSort, используется se.sawano.java.text.AlphanumericComparator, который корректно сортирует "file2.txt" перед "file10.txt" (естественный порядок сортировки)
  • Запасной вариант — строка: если два значения имеют несовместимые типы (например, один Integer, другой String), выполняется сравнение через String.valueOf() — это корректно обрабатывает списки со смешанными типами

Определение типа сортировки на основе аннотаций

Метод checkAnnotation() проверяет, имеет ли геттер/поле свойства аннотацию @StringAlphanumericSort. Эта аннотация на поле DO означает "сортировать этот столбец буквенно-цифровым способом, а не лексикографически". Пример: поле, отображающее имена документов, такие как "Report1", "Report2", "Report10" — лексикографическая сортировка даёт "Report1", "Report10", "Report2"; буквенно-цифровая даёт "Report1", "Report2", "Report10". Оба объекта должны иметь аннотацию для использования буквенно-цифровой сортировки — в противном случае используется стандартный String.compareTo().

Устойчивость к ошибкам

Если доступ к свойству вызывает любое исключение (например, NoSuchMethodException для неправильно написанного имени свойства), ошибка логируется и возвращается 0 — два объекта считаются равными для целей сортировки. Это предотвращает поломку всей страницы со списком из-за одного неправильного имени свойства. Это отказоустойчивая конструкция — пользователь видит несортированные данные вместо страницы с ошибкой.
