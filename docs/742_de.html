Zweck

Polymorphe "isEmpty"-Prüfung, die sowohl Zeichenketten als auch Zahlen behandelt. 52 Zeilen mit einer Methode — isEmpty(Object... values). Nimmt Varargs beliebigen Typs entgegen, gibt true zurück, wenn ALLE Werte effektiv leer sind. Die Logik pro Wert:

  • null → gilt als leer (prüft den nächsten Wert weiter)
  • String → leer, wenn trim().length() == 0. Eine Zeichenkette, die nur Leerzeichen enthält, wie " ", ist leer
  • BigDecimal → leer, wenn compareTo(ZERO) == 0. BigDecimal.ZERO und new BigDecimal("0.00") gelten beide als leer (sie sind im Vergleich gleich)
  • Jedes andere nicht-null Objekt → gilt als NICHT leer — gibt sofort false zurück. Dies unterbricht die Schleife vorzeitig

Wird in der Formularvalidierung und Datenverarbeitung verwendet, um zu prüfen, ob ein Formularfeld einen sinnvollen Inhalt hat. Beispiel: ObjectHelper.isEmpty(user.getFirstName(), user.getLastName()) — gibt false zurück, wenn einer der Namen einen Inhalt hat.

Design-Kritik

Die Methode gibt true (leer) zurück, wenn ein Nicht-String-, Nicht-BigDecimal-Objekt vorhanden ist – dies ist kontraintuitiv für Booleans, Daten oder jeden Typ mit einer sinnvollen "leeren" Darstellung. Ein Boolean.FALSE-Wert würde dazu führen, dass isEmpty(falseObj) false zurückgibt (der nicht-null-Zweig), was semantisch "nicht leer" bedeutet, obwohl false oft als "leerer" Boolean betrachtet wird. Die Methode ist auf String und BigDecimal spezialisiert, da dies die beiden wichtigsten Formularfeldtypen in ProjectForge sind – Textfelder und Währungsfelder. Ein allgemeinerer Ansatz hätte eine Map<Class, Predicate> für erweiterbare typspezifische Leerprüfungen verwendet.
