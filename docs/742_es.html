Propósito

Verificación polimórfica "isEmpty" que maneja tanto cadenas como números. 52 líneas con un método — isEmpty(Object... values). Toma varargs de cualquier tipo, devuelve true si TODOS los valores están efectivamente vacíos. La lógica por valor:

  • null → se considera vacío (continúa verificando el siguiente valor)
  • String → vacío si trim().length() == 0. Una cadena de solo espacios como " " está vacía
  • BigDecimal → vacío si compareTo(ZERO) == 0. BigDecimal.ZERO y new BigDecimal("0.00") se consideran vacíos (se comparan iguales)
  • Cualquier otro objeto no nulo → se considera NO vacío — devuelve false inmediatamente. Esto cortocircuita el bucle

Se utiliza en validación de formularios y procesamiento de datos para verificar si un campo de formulario tiene contenido significativo. Ejemplo: ObjectHelper.isEmpty(user.getFirstName(), user.getLastName()) — devuelve false si alguno de los nombres tiene contenido.

Crítica de diseño

El método devuelve true (vacío) cuando hay un objeto que no es String ni BigDecimal — esto es contraintuitivo para booleanos, fechas o cualquier tipo con una representación "vacía" significativa. Un valor Boolean.FALSE haría que isEmpty(falseObj) devuelva false (la rama no nula), lo que semánticamente significa "no vacío" aunque false a menudo se considera un booleano "vacío". El método está especializado para String y BigDecimal porque esos son los dos tipos principales de campos de formulario en ProjectForge — campos de texto y campos de moneda. Un enfoque más general habría utilizado un Map<Class, Predicate> para verificaciones extensibles de vacío según el tipo.
