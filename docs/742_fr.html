Objectif

Vérification polymorphe "isEmpty" qui gère à la fois les chaînes et les nombres. 52 lignes avec une seule méthode — isEmpty(Object... values). Prend des varargs de n'importe quel type, retourne true si TOUTES les valeurs sont effectivement vides. La logique par valeur :

  • null → considéré comme vide (continue la vérification de la valeur suivante)
  • String → vide si trim().length() == 0. Une chaîne ne contenant que des espaces comme " " est vide
  • BigDecimal → vide si compareTo(ZERO) == 0. BigDecimal.ZERO et new BigDecimal("0.00") sont tous deux considérés comme vides (ils sont égaux par comparaison)
  • Tout autre objet non nul → considéré comme NON vide — retourne false immédiatement. Cela court-circuite la boucle

Utilisé dans la validation de formulaires et le traitement des données pour vérifier si un champ de formulaire a un contenu significatif. Exemple : ObjectHelper.isEmpty(user.getFirstName(), user.getLastName()) — retourne false si l'un des noms a un contenu.

Critique de conception

La méthode retourne true (vide) lorsqu'un objet non String, non BigDecimal est présent — cela est contre-intuitif pour les booléens, les dates ou tout type ayant une représentation "vide" significative. Une valeur Boolean.FALSE ferait que isEmpty(falseObj) retourne false (la branche non nulle), ce qui signifie sémantiquement "non vide" même si false est souvent considéré comme un booléen "vide". La méthode est spécialisée pour String et BigDecimal car ce sont les deux principaux types de champs de formulaire dans ProjectForge — les champs de texte et les champs monétaires. Une approche plus générale aurait utilisé une Map<Class, Predicate> pour des vérifications de vide extensibles par type.
