projectforge-business/src/main/java/org/projectforge/framework/utils/ObjectHelper.java Строк: 52 · Автор: Kai Reinhard · Тип: Утилита Java 52 строки · 27 кода · 22 комментария · 3 пустых

Назначение

Полиморфная проверка "isEmpty", обрабатывающая как строки, так и числа. 52 строки с одним методом — isEmpty(Object... values). Принимает varargs любого типа, возвращает true, если ВСЕ значения фактически пусты. Логика для каждого значения:

  • null → считается пустым (продолжает проверку следующего значения)
  • String → пусто, если trim().length() == 0. Строка, содержащая только пробелы, например " ", считается пустой
  • BigDecimal → пусто, если compareTo(ZERO) == 0. BigDecimal.ZERO и new BigDecimal("0.00") оба считаются пустыми (они равны при сравнении)
  • Любой другой не-null объект → считается НЕ пустым — немедленно возвращает false. Это прерывает цикл

Используется при валидации форм и обработке данных для проверки, содержит ли поле формы значимое содержимое. Пример: ObjectHelper.isEmpty(user.getFirstName(), user.getLastName()) — возвращает false, если хотя бы одно из имён имеет содержимое.

Критика дизайна

Метод возвращает true (пусто), когда присутствует объект, не являющийся ни String, ни BigDecimal — это неинтуитивно для булевых значений, дат или любого типа, имеющего осмысленное "пустое" представление. Значение Boolean.FALSE приведёт к тому, что isEmpty(falseObj) вернёт false (ветка не-null), что семантически означает "не пусто", хотя false часто считается "пустым" булевым значением. Метод специализирован для String и BigDecimal, поскольку это два основных типа полей форм в ProjectForge — текстовые поля и поля валют. Более общий подход мог бы использовать Map<Class, Predicate> для расширяемых проверок пустоты в зависимости от типа.
