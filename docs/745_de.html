Zweck

Begrenzte "zuletzt verwendet"-Warteschlange – die Datenstruktur hinter jedem "Zuletzt verwendet"-Dropdown in ProjectForge. 137 Zeilen. Speichert bis zu maxSize (Standard 25) Einträge, wobei der neueste an Position 0 steht. Wenn ein Eintrag erneut hinzugefügt wird, wird er an die Spitze verschoben, anstatt dupliziert zu werden. Die ältesten Einträge werden verdrängt. Thread-sicher durch synchronized(this) bei Änderungen. Wird über XStream zur Persistenz in Benutzereinstellungen in XML serialisiert.

Wichtige Methoden

  • append(T entry) — die Haupt-Änderungsmethode. Wenn der Eintrag bereits existiert (ermittelt durch indexOf() → verwendet equals()), wird er zuerst entfernt (Deduplizierung). Wenn die Kapazität erreicht ist, wird der älteste Eintrag (am Ende der Liste) entfernt. Fügt an Position 0 ein. Gibt this für Methodenverkettung zurück
  • getRecent() — gibt get(0) (den aktuellsten) oder null zurück, wenn die Liste leer ist
  • get(Integer pos) — null-sicher — gibt null für ungültige Positionen zurück, anstatt eine IndexOutOfBoundsException zu werfen. Behandelt auch pos == null, indem get(0) zurückgegeben wird. Dieses defensive Design dient Wicket-Serialisierungs-Grenzfällen
  • addOnly(T entry) — fügt ohne Verdrängung hinzu (ignoriert maxSize). Wird beim Initialisieren aus gespeichertem XML verwendet – die Warteschlange wurde zum Speicherzeitpunkt bereits abgeschnitten, daher sollte ein erneutes Hinzufügen nicht verdrängen

XStream-Kompatibilität

Das Feld recentList ist mit @XStreamAlias("recents") annotiert (beachten Sie den Tippfehler "recents" nicht "recents" – dies ist beabsichtigt). Der Kommentar sagt: "War in der früheren Version (vor 2020-04-05) als recents benannt" – dies ist ein Abwärtskompatibilitäts-Alias. Alte Präferenz-XML verwendete <recents> als Elementnamen; als das Feld in recentList umbenannt wurde, bewahrte der Alias das alte XML-Format, sodass bestehende Benutzereinstellungen nicht brachen.
