Objectif

File d'attente bornée « récemment utilisé » — la structure de données derrière chaque menu déroulant « Éléments récents » dans ProjectForge. 137 lignes. Stocke jusqu'à maxSize (25 par défaut) entrées, la plus récente étant en position 0. Lorsqu'une entrée est ré-ajoutée, elle se déplace en tête plutôt que de se dupliquer. Les entrées les plus anciennes sont supprimées. Thread-safe via synchronized(this) sur les mutations. Sérialisée en XML via XStream pour la persistance dans les préférences utilisateur.

Méthodes clés

  • append(T entry) — le mutateur principal. Si l'entrée existe déjà (trouvée par indexOf() → utilise equals()), la supprime d'abord (déduplication). Si la capacité est atteinte, supprime l'entrée la plus ancienne (à la fin de la liste). Insère en position 0. Retourne this pour le chaînage
  • getRecent() — retourne get(0) (le plus récent) ou null si vide
  • get(Integer pos) — sécurisé contre les null — retourne null pour les positions invalides au lieu de lever une IndexOutOfBoundsException. Gère également pos == null en retournant get(0). Cette conception défensive est destinée aux cas particuliers de sérialisation Wicket
  • addOnly(T entry) — ajoute sans éviction (ignore maxSize). Utilisé lors de l'initialisation à partir du XML sauvegardé — la file était déjà tronquée au moment de la sauvegarde, donc un ré-ajout ne doit pas provoquer d'éviction

Compatibilité XStream

Annotation @XStreamAlias("recents") sur le champ recentList (notez la faute de frappe « recents » et non « recents » — c'est intentionnel). Le commentaire dit : « Était nommé recents dans la version précédente (avant 2020-04-05) » — il s'agit d'un alias de rétrocompatibilité. L'ancien XML de préférences utilisait <recents> comme nom d'élément ; lorsque le champ a été renommé en recentList, l'alias a préservé l'ancien format XML afin que les préférences utilisateur existantes ne soient pas cassées.
