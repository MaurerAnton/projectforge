Zweck

Generischer Ergebnis-Wrapper, der als Rückgabewert von Servicemethoden verwendet wird. 106 Zeilen. Kombiniert einen Status (ResultHolderStatus: OK/WARNUNG/FEHLER/GESCHEITERT) mit einer Liste von Nachrichten. Dies ist ProjectForges Version des Ergebnis-Musters — anstatt dass Methoden einen Wert zurückgeben oder Ausnahmen werfen, geben sie einen ResultHolder mit gesammelten Nachrichten zurück.

Innere Klassen — das Nachrichtenmodell

  • IMessage — Schnittstelle mit getMessage()
  • Message — speichert eine rohe Zeichenfolgennachricht (statischer Text)
  • I18nMessage — speichert einen i18n-Schlüssel + optionale Parameter. getMessage() löst den Schlüssel über ThreadLocalUserContext.getLocalizedString() mit MessageFormat-Parameterersetzung auf. Dies ist die häufiger verwendete Variante — die meisten Operationsergebnisse benötigen internationalisierte Nachrichten

Verwendungsmuster

ResultHolder ergebnis = meinDienst.machEtwas();
if (ergebnis.getStatus() == ResultHolderStatus.FEHLER) {
    zeigeFehler(ergebnis.getMessages());
}

Der Holder sammelt Nachrichten über addMessage() — mehrere Validierungsfehler können gesammelt werden, bevor zurückgegeben wird. Verwendet von Formularvalidierern, Importvorgängen und Setup-Assistentenschritten, bei denen mehrere Probleme auf einmal gemeldet werden sollen, anstatt beim ersten Fehler abzubrechen.
