Propósito

Estado de resultado de cuatro niveles para ResultHolder. Valores: OK (éxito), WARNING (éxito con problemas — la operación se completó pero algo es digno de mención), ERROR (fallo — la operación no pudo completarse), FAILED (fallo fatal — error crítico, probablemente un bug o problema del sistema). Claves I18n: common.resultholder.ok, etc. Tiene el helper de argumentos variables isIn(ResultHolderStatus...) para comprobaciones de múltiples valores.

La distinción entre ERROR y FAILED es sutil: ERROR significa "la solicitud del usuario no pudo cumplirse" (fallo de validación, permiso denegado), mientras que FAILED significa "algo salió mal que no debería haber ocurrido" (NullPointerException, fallo de conexión a la base de datos). En la interfaz de usuario, los mensajes de ERROR se muestran como banners de error rojos; FAILED puede mostrar una página genérica de "error interno".
