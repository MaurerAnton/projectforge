Objectif

Statut de résultat à quatre niveaux pour ResultHolder. Valeurs : OK (succès), WARNING (succès avec problèmes — l'opération s'est terminée mais quelque chose mérite attention), ERROR (échec — l'opération n'a pas pu aboutir), FAILED (échec fatal — erreur critique, probablement un bug ou un problème système). Clés I18n : common.resultholder.ok, etc. Dispose de l'aide varargs isIn(ResultHolderStatus...) pour les vérifications multi-valeurs.

La distinction entre ERROR et FAILED est subtile : ERROR signifie « la demande de l'utilisateur n'a pas pu être satisfaite » (échec de validation, permission refusée), tandis que FAILED signifie « quelque chose s'est mal passé qui n'aurait pas dû » (NullPointerException, échec de connexion à la base de données). Dans l'interface utilisateur, les messages ERROR sont affichés sous forme de bannières d'erreur rouges ; FAILED peut afficher une page générique « erreur interne ».
