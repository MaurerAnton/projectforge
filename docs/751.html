#751: ProjectForgeRootElement.java

Lines: 98 · Author: Kai Reinhard · Type: Java abstract class · Package: org.projectforge.framework.xmlstream

Что это и зачем

Абстрактный базовый класс для корневых элементов XML в собственной системе сериализации ProjectForge — XmlStream. Это не JAXB и не XStream, а свой легковесный XML-фреймворк, написанный с нуля для конкретных нужд проекта: экспорт/импорт данных между инстансами ProjectForge, сохранение пользовательских настроек, и сериализация конфигурации.

Javadoc объясняет назначение: "For export and import it's useful to use an instance of this object to define for example the time zone, version etc." — то есть каждый экспортированный XML-файл должен нести метаданные: какой часовой пояс использовался при экспорте, какая версия ProjectForge создала файл, и когда он был создан. Без этой информации импорт на другом сервере может неправильно интерпретировать даты или не суметь применить миграции формата.

Три поля — три аспекта совместимости

  1. created (Date): когда XML был создан. Сеттер setCreated() без аргументов автоматически устанавливает текущее время с точностью до секунд (миллисекунды обнулены — withPrecision(DatePrecision.SECOND)). Это важно: если в двух XML-файлах одинаковый created, они экспортированы из одного пакета. Импортёр использует эту метку чтобы понять, какие данные новее при конфликтах
  2. timeZone (java.util.TimeZone): часовой пояс, использованный при экспорте. Критично для дат: если сервер в Берлине экспортирует "2025-05-15 09:00 Europe/Berlin", а импорт происходит в Нью-Йорке, без таймзоны дата будет интерпретирована как 09:00 EST вместо 03:00 EST. Наличие явного timeZone предотвращает сдвиги дат при кроссплатформенном импорте
  3. version (String, аннотирован @XmlField(asAttribute=true)): версия ProjectForge, создавшая файл. Используется для миграции формата — если импортёр видит version="7.4", он знает что нужно применить конвертеры для формата 7.4 → 8.0. Аннотация @XmlField(asAttribute=true) (из пакета org.projectforge.framework.xmlstream, не из XStream!) означает что в XML версия будет записана как атрибут корневого элемента: <projectforge version="8.0">, а не как вложенный тег

Fluent API — все сеттеры возвращают this

Каждый сеттер возвращает ProjectForgeRootElement, позволяя цепочечную инициализацию:

export.setTimeZone(userTZ).setCreated().setVersion("8.0.0");

Это удобно при создании экспорта — одной строкой настраиваются все метаданные, и объект готов к сериализации.

Место в иерархии XmlStream

ProjectForgeRootElement — это абстрактный базовый класс. Конкретные корневые элементы (например, корневой элемент экспорта данных: <projectforgeData>) наследуют его и добавляют свои дочерние поля. Вся система XmlStream состоит из:

  • @XmlField / @XmlOmitField — аннотации для пометки полей (аналог XStream's @XStreamAlias/@XStreamOmitField)
  • XmlObject (#772) — базовый класс для сериализуемых объектов (с версионированием)
  • XmlObjectReader / XmlObjectWriter (#773, #774) — движок чтения/записи
  • Converter иерархия (#749+) — конвертеры типов (Date→ISO, BigDecimal→String и т.д.)
  • AliasMap (#750) — маппинг Class↔XML-tag
  • XmlRegistry (#776) — реестр зарегистрированных XML-объектов

Этот фреймворк существует параллельно с XStream в ProjectForge. XStream используется для пользовательских настроек (сериализация RecentQueue, UserPref), а XmlStream — для экспорта/импорта данных между инстансами (где нужен контроль формата, валидация и версионирование).

Почему не XStream?

XStream — отличная библиотека, но у неё есть ограничения для use case'а экспорта данных:

  • Версионирование: XStream не поддерживает миграцию формата. Если формат XML изменился между версиями ProjectForge, XStream просто упадёт с ошибкой при десериализации. XmlStream явно хранит версию и позволяет применять конвертеры при чтении
  • Контроль схемы: XStream генерирует XML "как получится" — имена полей Java класса становятся именами тегов. XmlStream позволяет явно задавать алиасы и структуру через аннотации, что важно для обратной совместимости
  • Безопасность: XStream может десериализовать произвольные Java-объекты (известная уязвимость). XmlStream работает только с зарегистрированными в XmlRegistry типами
