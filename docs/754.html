#754: XmlField.java

Lines: 92 · Author: Kai Reinhard · Type: Java annotation · Retention: RUNTIME · Target: FIELD

Что это

Центральная аннотация фреймворка XmlStream — аналог @XStreamAlias, @XStreamAsAttribute, @XStreamOmitField, и части @XmlElement из JAXB, но в одной аннотации. 92 строки, из которых 40 — детальные Javadoc-комментарии к каждому параметру. Помечает поле Java-класса как сериализуемое в XML и управляет тем, как именно оно будет записано. Применяется на уровне полей (@Target(FIELD)) и доступна во время выполнения через reflection (@Retention(RUNTIME)) — именно так XmlObjectWriter и XmlObjectReader находят сериализуемые поля.

Параметры аннотации — 8 атрибутов

alias() — имя в XML

Переопределяет имя поля при сериализации. Без alias: поле private String firstName → тег <firstName>. С alias: @XmlField(alias = "first-name") → тег <first-name>. Полезно когда XML-формат должен соответствовать внешней схеме (например, для импорта из другой системы), или когда имя поля Java конфликтует с зарезервированным словом XML.

asAttribute() и asElement() — атрибут или элемент?

В XML данные могут быть представлены двумя способами:

<!-- Как атрибут: -->
<user id="42" name="John"/>

<!-- Как элемент: -->
<user><id>42</id><name>John</name></user>

asAttribute=true — записать как атрибут (компактно, но только для простых типов).

asElement=true — явно записать как элемент (даже если тип поля по умолчанию пишется как атрибут — см. XmlObjectWriter.asAttributeAsDefault()).

Важный нюанс из Javadoc: "asAttribute=false has no effect (please use asElement=true instead)" и наоборот. Это значит что false — это не "отрицание", а "значение по умолчанию, которое может быть переопределено глобальной настройкой". Чтобы гарантированно записать как элемент, нужно asElement=true; чтобы гарантированно как атрибут — asAttribute=true.

defaultDoubleValue / defaultIntValue / defaultStringValue / defaultBooleanValue — сжатие XML

Если значение поля равно значению по умолчанию, оно НЕ записывается в XML. Это механизм сжатия: типичные значения по умолчанию не занимают места в выходном файле. При чтении: если тег отсутствует, полю присваивается значение по умолчанию.

Магические числа для defaultIntValue и defaultStringValue берутся из XmlConstants и никогда не совпадут с реальными данными. Для boolean — по умолчанию false (самое частое значение). Для double — NaN (который обычно означает "не задано").

asCDATA() — защита от спецсимволов

Если true, строковое значение оборачивается в XML-блок <![CDATA[...]]>. Нужно для полей, которые могут содержать символы <, >, & — например, HTML-код в поле описания, или SQL-запросы в логах. Без CDATA эти символы пришлось бы экранировать как &lt;, &gt;, &amp;, что делает XML нечитаемым.

Как XmlField читается в рантайме

  1. XmlObjectWriter при сериализации объекта обходит все его поля через reflection
  2. Для каждого поля проверяет наличие @XmlField (и отсутствие @XmlOmitField)
  3. Если аннотация есть — читает её параметры: alias (имя тега), asAttribute (атрибут или элемент), default* (пропускать ли), asCDATA (формат)
  4. Вызывает соответствующий Converter (AbstractValueConverter и подклассы) для преобразования значения поля в строку
  5. XmlObjectReader делает обратное: читает тег/атрибут из XML, ищет поле с соответствующим именем (или alias), вызывает Converter для обратного преобразования

XmlField + XmlStream дают больше контроля над форматом XML чем XStream, но требуют ручного написания аннотаций. XStream "просто работает" без аннотаций, но генерирует менее контролируемый XML. Выбор в пользу XmlStream для экспорта данных был обусловлен именно необходимостью контроля формата и версионирования.
