#755: XmlHelper.java

Lines: 135 · Author: Kai Reinhard · Type: Java utility · Package: org.projectforge.framework.xmlstream

Что это

Утилитный класс для работы с XML — преобразование строк в XML-элементы, XML-элементов в строки, форматирование. 135 строк. Использует библиотеку dom4j для парсинга и сериализации обычного XML (не XStream, не W3C DOM). Это третья XML-библиотека в проекте наряду с XStream (пользовательские настройки) и W3C DOM API (SVG через Batik).

Константа XML_HEADER = "<?xml version=\"1.0\" encoding=\"UTF-8\"?>" — стандартный XML-заголовок, используемый при генерации XML-файлов для экспорта. Кодировка жёстко зафиксирована как UTF-8 — это решение на уровне кода, не конфигурации.

Методы

replaceQuotes(String xml) — нормализация кавычек

Заменяет одинарные кавычки (') на двойные (") в XML-строке. Javadoc: "This is useful for writing xml string constants e.g. in test cases." В Java строковых литералах проще использовать одинарные кавычки для атрибутов (не надо экранировать), но валидный XML требует двойные. Этот метод позволяет писать в тестах: XmlHelper.replaceQuotes("<node name='test'/>") → "<node name=\"test\"/>".

fromString(String str) — строка → dom4j Element

Парсит XML-строку в dom4j Element. Использует DocumentHelper.parseText() — dom4j'евский аналог DocumentBuilder.parse() из W3C. Возвращает корневой элемент (document.getRootElement()). При ошибке парсинга логирует и возвращает null (не бросает исключение — вызывающий код должен проверять null). Для пустой строки возвращает null.

toString(Element el, boolean prettyFormat) — dom4j Element → отформатированная XML-строка

Сериализует dom4j Element обратно в строку. Использует dom4j'евский XMLWriter с OutputFormat. При prettyFormat=true: включает переносы строк и отступ в 2 пробела. Важно: writer.close() вызывается в finally-неявном стиле (в try-блоке после записи) — writer должен быть закрыт чтобы flush'нуть буфер.

toString(org.w3c.dom.Document, boolean prettyFormat) — W3C DOM Document → строка

Этот метод работает с другим типом XML — org.w3c.dom.Document (используется в SVG/Batik). Использует javax.xml.transform.Transformer (XSLT-процессор) для сериализации. При prettyFormat=true: добавляет INDENT=yes и специфичный для Xalan отступ ({http://xml.apache.org/xslt}indent-amount=2). Все ошибки оборачиваются в InternalErrorException (в отличие от dom4j-метода который логирует и возвращает null) — это потому что ошибки транcформации W3C DOM считаются критическими внутренними ошибками, а не ошибками пользовательских данных.

Две XML-библиотеки в одном классе — архитектурный долг

Наличие методов для двух разных XML-представлений (dom4j и W3C DOM) в одном классе — это исторический артефакт. dom4j используется для XmlStream (сериализация данных), W3C DOM — для SVG-рендеринга (Batik). Они оказались в одном утилитном классе потому что "работа с XML" была воспринята как одна ответственность, хотя на самом деле это две разные подсистемы. Правильный рефакторинг: выделить W3C-метод в SvgXmlHelper или встроить его в BatikImageRenderer (#711).
