Zweck: Der Deserialisierungskern des XmlStream-Frameworks – konvertiert XML (als dom4j Element-Bäume) zurück in Java-Objekte mit befüllten Feldern. 514 Zeilen. Dies ist die größte Datei im XmlStream-Framework. Javadoc: "Analysiert Objekte, die vom XmlObjectWriter serialisiert wurden. Verwendet dom4j." Arbeitet paarweise mit XmlObjectWriter – Writer serialisiert Objekte in XML, Reader deserialisiert XML zurück in Objekte.

Architektur – Zustandsautomat mit Rückverfolgung

Reader ist ein zustandsbehaftetes Objekt (im Gegensatz zum zustandslosen Writer). Es hält während einer einzelnen Lese-Sitzung den Zustand:

  • processedElements (Set<Element>) – welche XML-Elemente erfolgreich gelesen wurden. Nach Abschluss gelten Elemente, die NICHT in diesem Set sind, als "ignoriert" und erscheinen in Warnungen
  • processedAttributes (Map<Element, Set<String>>) – welche Attribute pro Element gelesen wurden. Gleicher Zweck für Warnungen
  • referenceObjects (Map<String, Object>) – Cache deserialisierter Objekte, keyed by o-id. Wird für Deduplizierung verwendet: Wenn zwei XML-Elemente auf dasselbe Objekt verweisen, wird es einmal deserialisiert und beim zweiten Mal aus dem Cache zurückgegeben
  • warnings (String) – gesammelte Warnungen über ignorierte Elemente/Attribute

Einstiegspunkte – Zwei read()-Methoden

read(String xml) – öffentliche API

Nimmt einen rohen XML-String entgegen. Analysiert ihn über XmlHelper.fromString() → dom4j Element. Setzt den Zustand zurück (processedElements, processedAttributes, warnings). Ruft internes read(Element) auf. Nach dem Lesen wird checkForIgnoredElements() ausgeführt – wenn XML-Tags/Attribute nicht verarbeitet wurden, erscheinen sie in Warnungen. Gibt das root-deserialisierte Objekt zurück.

read(Element el) – interne API

Nimmt ein dom4j-Element entgegen, findet die Klasse anhand des Tag-Namens (über getClass()) und ruft rekursives read(Class, Element, ...) auf. Wenn Klasse nicht gefunden – gibt null zurück.

Dreistufige Klassenauflösung – getClass(String elementName)

Beim Auftreten eines XML-Tags sucht der Reader an drei Stellen nach der entsprechenden Java-Klasse (in Prioritätsreihenfolge):

  1. Eigene AliasMap: this.aliasMap.getClassForAlias(name) – wenn explizit über setAliasMap() gesetzt
  2. Globales XmlRegistry: xmlRegistry.getClassForAlias(name) – beim Start registrierte Klassen
  3. Class.forName() (Fallback): Versuch, per FQCN zu laden. Wenn Klasse ein Interface ist, wird implementationMapping geprüft. Wenn nicht gefunden, wird Fehler protokolliert und null zurückgegeben (Element wird ignoriert)

Dieses dreistufige System ermöglicht flexibles Mapping-Management: AliasMap für lokale Überschreibungen, XmlRegistry für globale Regeln, Class.forName für Abwärtskompatibilität mit alten XML-Dateien, in denen Tags FQCNs waren.

Kern-Rekursionsmethode – read(Class, Element, attrName, attrValue)

Das Herz des Readers. Nimmt einen Feldtyp, ein XML-Element und optionalen Attributnamen/-wert entgegen. Die Logik ist eine Kette von Typprüfungen:

  1. Referenzprüfung: wenn Element Attribut o-ref-id hat – ist es eine Referenz auf ein bereits deserialisiertes Objekt. Sucht in referenceObjects und gibt gecachtes Objekt zurück (Deduplizierung). Wenn ref-id nicht gefunden – Fehlerprotokollierung
  2. Converter-Prüfung: wenn Typ einen registrierten IConverter hat (über xmlRegistry.getConverter(clazz)) – ruft converter.fromString() auf. Für einfache Typen: String, Integer, Date, BigDecimal, Boolean
  3. Enum-Prüfung: wenn Klasse ein Enum ist, ruft enumFromString() auf. Versucht Enum.valueOf(clazz, val). Bei IllegalArgumentException wird ein zweiter Versuch mit toUpperCase() unternommen – Abwärtskompatibilität mit altem XML, in dem Enums kleingeschrieben waren. Wert "null" wird als null behandelt
  4. Collection-Prüfung: wenn Klasse eine Collection ist (List/Set/SortedSet), wird die entsprechende Implementierung erstellt (ArrayList/HashSet/TreeSet) und rekursiv alle untergeordneten XML-Elemente als Collection-Elemente gelesen. Wenn ignoreEmptyCollections=true und Collection leer – bleibt Feld null
  5. Komplexes Objekt: für alle anderen Typen (Klassen mit @XmlObject) – Instanzerzeugung über BeanHelper.newInstance(), Prüfung auf o-id-Attribut (Speicherung in referenceObjects für zukünftige ref-id-Suchen) und Aufruf von read(obj, el) für rekursive Feldbefüllung

Feldbefüllung – read(Object obj, Element el)

Iteriert über alle Felder des Objekts (über BeanHelper.getAllDeclaredFields() – einschließlich geerbter), macht sie zugänglich (Reflection) und findet für jedes XML-Attribut und untergeordnete Element das entsprechende Feld:

  • Zuerst Prüfung auf @XmlOmitField – wenn vorhanden, wird Feld übersprungen
  • Suche nach @XmlField-Annotation. Vergleich von Tag/Attribut-Name mit Feldname (Groß-/Kleinschreibung) und mit Alias aus Annotation
  • Wenn Feld gefunden – Aufruf von read(field.getType(), element, key, attrValue) zur Deserialisierung, dann field.set(obj, value) zur Zuweisung
  • Wenn Feld NICHT gefunden – Warnung "Feld '...' nicht gefunden." Element bleibt unmarkiert in processedElements und erscheint in Warnungen

Wichtig: Die Felder o-id und ref-id (XML-Attribute des Writers) werden explizit übersprungen – sie werden nicht unter den Objektfeldern gesucht.

Warnungen – checkForIgnoredElements()

Nach dem Lesen des gesamten XML prüft der Reader: Wurden alle Elemente aus dem Quell-XML-Baum als processed markiert? Wenn nicht – enthält das XML Tags, für die keine Felder in der Java-Klasse gefunden wurden. Dies kann auf Folgendes hinweisen:

  • XML wurde von einer neueren ProjectForge-Version erstellt (neue Felder in XML, aber nicht im Code)
  • Tippfehler im Feldnamen oder Alias
  • Klasse wurde geändert (Feld entfernt oder umbenannt)

Alle nicht markierten Elemente und Attribute werden in einem warnings-String gesammelt. Wenn der String 500 Zeichen überschreitet – wird er gekürzt (ABBREVIATE_WARNING=500), um Log-Spam zu vermeiden.

Template-Method-Hooks für Unterklassen

Drei geschützte Methoden können in Unterklassen überschrieben werden:

  • newInstance(Class, Element, String, String) – greift in die Objekterzeugung ein. Wenn Status.IGNORE zurückgegeben wird, wird das Objekt übersprungen. Standardmäßig wird null zurückgegeben (Standarderzeugung)
  • addCollectionEntry(Collection, Object, Element) – greift in das Hinzufügen zur Collection ein. Wenn true zurückgegeben wird, wird das Objekt NICHT automatisch hinzugefügt. Standard ist false
  • setField(Field, Object, Object, Element, String, String) – greift in die Feldzuweisung ein. Standardmäßig wird field.set(obj, value) aufgerufen

Diese Hooks ermöglichen es Unterklassen, das Verhalten zu ändern, ohne die gesamte Logik neu schreiben zu müssen – z. B. bestimmte Felder überspringen, Collections filtern oder Objekte nachbearbeiten.

initialize(Class) – Vorab-Scan

Kann vor dem Lesen aufgerufen werden, um vorab alle @XmlObject-Klassen in der AliasMap zu registrieren. Durchläuft rekursiv den Typbaum: Für eine Klasse mit @XmlObject wird der Alias registriert, dann für jedes nicht-primitive Feld rekursiv initialize() aufgerufen. Verwendet ein processed-Set, um Endlosschleifen bei zirkulären Referenzen zu verhindern. Dies ermöglicht es, nur die root-Klasse zu übergeben – der Reader findet selbst alle verschachtelten Typen.
