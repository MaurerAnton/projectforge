Propósito: El núcleo de deserialización del framework XmlStream — convierte XML (como árboles de Element de dom4j) de vuelta a objetos Java con campos poblados. 514 líneas. Este es el archivo más grande del framework XmlStream. Javadoc: "Analiza objetos serializados por XmlObjectWriter. Utiliza dom4j." Funciona en conjunto con XmlObjectWriter — el Writer serializa objetos a XML, el Reader deserializa XML de vuelta a objetos.

Arquitectura — Máquina de Estados con Retroceso

El Reader es un objeto con estado (a diferencia del Writer sin estado). Mantiene el estado durante una única sesión de lectura:

  • processedElements (Set<Element>) — qué elementos XML fueron leídos exitosamente. Al finalizar, los elementos NO en este conjunto se consideran "ignorados" y aparecen en advertencias
  • processedAttributes (Map<Element, Set<String>>) — qué atributos por elemento fueron leídos. Mismo propósito para advertencias
  • referenceObjects (Map<String, Object>) — caché de objetos deserializados indexados por o-id. Se usa para deduplicación: si dos elementos XML referencian el mismo objeto, se deserializa una vez y se devuelve desde la caché la segunda vez
  • warnings (String) — advertencias acumuladas sobre elementos/atributos ignorados

Puntos de Entrada — Dos Métodos read()

read(String xml) — API pública

Toma una cadena XML cruda. La analiza mediante XmlHelper.fromString() → Element de dom4j. Limpia el estado (processedElements, processedAttributes, warnings). Llama al read(Element) interno. Después de la lectura, ejecuta checkForIgnoredElements() — si alguna etiqueta/atributo XML no fue procesado, aparece en advertencias. Devuelve el objeto deserializado raíz.

read(Element el) — API interna

Toma un Element de dom4j, encuentra la clase por nombre de etiqueta (mediante getClass()), y llama al read(Class, Element, ...) recursivo. Si no se encuentra la clase — devuelve null.

Resolución de Clase en Tres Niveles — getClass(String elementName)

Al encontrar una etiqueta XML, el Reader busca la clase Java correspondiente en tres lugares (en orden de prioridad):

  1. AliasMap propio: this.aliasMap.getClassForAlias(name) — si se estableció explícitamente mediante setAliasMap()
  2. XmlRegistry global: xmlRegistry.getClassForAlias(name) — clases registradas al inicio
  3. Class.forName() (respaldo): intenta cargar por FQCN. Si la clase es una interfaz, verifica implementationMapping. Si no se encuentra, registra error y devuelve null (el elemento será ignorado)

Este sistema de tres niveles permite una gestión flexible de mapeos: AliasMap para sobrescrituras locales, XmlRegistry para reglas globales, Class.forName para compatibilidad hacia atrás con archivos XML antiguos donde las etiquetas eran FQCN.

Método Recursivo Central — read(Class, Element, attrName, attrValue)

El corazón del Reader. Toma un tipo de campo, elemento XML, y nombre/valor de atributo opcional. La lógica es una cadena de verificaciones de tipo:

  1. Verificación de referencia: si el elemento tiene el atributo o-ref-id — es una referencia a un objeto ya deserializado. Busca en referenceObjects y devuelve el objeto en caché (deduplicación). Si no se encuentra ref-id — registra error
  2. Verificación de convertidor: si el tipo tiene un IConverter registrado (mediante xmlRegistry.getConverter(clazz)) — llama a converter.fromString(). Para tipos simples: String, Integer, Date, BigDecimal, Boolean
  3. Verificación de enum: si la clase es enum, llama a enumFromString(). Intenta Enum.valueOf(clazz, val). En caso de IllegalArgumentException, hace un segundo intento con toUpperCase() — compatibilidad hacia atrás con XML antiguo donde los enums estaban en minúsculas. El valor "null" se trata como null
  4. Verificación de colección: si la clase es Collection (List/Set/SortedSet), crea la implementación apropiada (ArrayList/HashSet/TreeSet), y lee recursivamente todos los elementos XML hijos como elementos de la colección. Si ignoreEmptyCollections=true y la colección está vacía — deja el campo null
  5. Objeto complejo: para todos los demás tipos (clases con @XmlObject) — crea una instancia mediante BeanHelper.newInstance(), verifica el atributo o-id (lo guarda en referenceObjects para futuras búsquedas ref-id), y llama a read(obj, el) para la población recursiva de campos

Población de Campos — read(Object obj, Element el)

Itera todos los campos del objeto (mediante BeanHelper.getAllDeclaredFields() — incluyendo heredados), los hace accesibles (reflexión), y para cada atributo XML y elemento hijo encuentra el campo correspondiente:

  • Primero verifica @XmlOmitField — si está presente, el campo se omite
  • Busca la anotación @XmlField. Compara el nombre de la etiqueta/atributo con el nombre del campo (sensible a mayúsculas) y con el alias de la anotación
  • Si se encuentra el campo — llama a read(field.getType(), element, key, attrValue) para deserialización, luego field.set(obj, value) para asignación
  • Si NO se encuentra el campo — registra advertencia "Campo '...' no encontrado." El elemento permanece sin marcar en processedElements y aparecerá en advertencias

Importante: los campos o-id y ref-id (atributos XML del Writer) se omiten explícitamente — no se buscan entre los campos del objeto.

Advertencias — checkForIgnoredElements()

Después de leer todo el XML, el Reader verifica: ¿todos los elementos del árbol XML fuente fueron marcados como processed? Si no — el XML contiene etiquetas para las cuales no se encontraron campos en la clase Java. Esto puede indicar:

  • El XML fue creado por una versión más reciente de ProjectForge (nuevos campos en XML pero no en código)
  • Error tipográfico en el nombre del campo o alias
  • La clase fue modificada (campo eliminado o renombrado)

Todos los elementos y atributos no marcados se recogen en una cadena de warnings. Si la cadena supera los 500 caracteres — se trunca (ABBREVIATE_WARNING=500) para evitar saturar los registros.

Métodos Hook de Plantilla para Subclases

Tres métodos protegidos pueden ser sobrescritos en subclases:

  • newInstance(Class, Element, String, String) — intercepta la creación de objetos. Si devuelve Status.IGNORE, el objeto se omite. Por defecto devuelve null (creación estándar)
  • addCollectionEntry(Collection, Object, Element) — intercepta la adición a la colección. Si devuelve true, el objeto NO se agrega automáticamente. Por defecto es false
  • setField(Field, Object, Object, Element, String, String) — intercepta la asignación de campo. Por defecto llama a field.set(obj, value)

Estos hooks permiten a las subclases modificar el comportamiento sin reescribir toda la lógica — por ejemplo, omitir ciertos campos, filtrar colecciones o posprocesar objetos.

initialize(Class) — Pre-escaneo

Puede llamarse antes de la lectura para pre-registrar todas las clases @XmlObject en AliasMap. Recorre recursivamente el árbol de tipos: para una clase con @XmlObject, registra el alias, luego para cada campo no primitivo llama recursivamente a initialize(). Utiliza un conjunto processed para evitar recursión infinita en referencias circulares. Esto permite pasar solo la clase raíz — el Reader mismo encuentra todos los tipos anidados.
