Objectif : Le noyau de désérialisation du framework XmlStream — convertit le XML (sous forme d'arbres d'éléments dom4j) en objets Java avec des champs remplis. 514 lignes. C'est le fichier le plus volumineux du framework XmlStream. Javadoc : "Analyse les objets sérialisés par XmlObjectWriter. Utilise dom4j." Fonctionne en tandem avec XmlObjectWriter — l'écrivain sérialise les objets en XML, le lecteur désérialise le XML en objets.

Architecture — Machine à états avec retour en arrière

Le lecteur est un objet avec état (contrairement à l'écrivain sans état). Il conserve l'état pendant une session de lecture unique :

  • processedElements (Set<Element>) — quels éléments XML ont été lus avec succès. Après la fin, les éléments qui ne sont PAS dans cet ensemble sont considérés comme "ignorés" et apparaissent dans les avertissements
  • processedAttributes (Map<Element, Set<String>>) — quels attributs par élément ont été lus. Même objectif pour les avertissements
  • referenceObjects (Map<String, Object>) — cache des objets désérialisés, indexé par o-id. Utilisé pour la déduplication : si deux éléments XML référencent le même objet, il est désérialisé une fois et renvoyé depuis le cache la deuxième fois
  • warnings (String) — avertissements accumulés concernant les éléments/attributs ignorés

Points d'entrée — Deux méthodes read()

read(String xml) — API publique

Prend une chaîne XML brute. L'analyse via XmlHelper.fromString() → Element dom4j. Efface l'état (processedElements, processedAttributes, warnings). Appelle la méthode interne read(Element). Après la lecture, exécute checkForIgnoredElements() — si des balises/attributs XML n'ont pas été traités, ils apparaissent dans les avertissements. Renvoie l'objet désérialisé racine.

read(Element el) — API interne

Prend un Element dom4j, trouve la classe par le nom de la balise (via getClass()), et appelle la méthode récursive read(Class, Element, ...). Si la classe n'est pas trouvée — renvoie null.

Résolution de classe à trois niveaux — getClass(String elementName)

Lors de la rencontre d'une balise XML, le lecteur recherche la classe Java correspondante à trois endroits (par ordre de priorité) :

  1. AliasMap propre : this.aliasMap.getClassForAlias(name) — si défini explicitement via setAliasMap()
  2. XmlRegistry global : xmlRegistry.getClassForAlias(name) — classes enregistrées au démarrage
  3. Class.forName() (solution de repli) : tentative de chargement par FQCN. Si la classe est une interface, vérifie implementationMapping. Si introuvable, enregistre une erreur et renvoie null (l'élément sera ignoré)

Ce système à trois niveaux permet une gestion flexible du mappage : AliasMap pour les surcharges locales, XmlRegistry pour les règles globales, Class.forName pour la rétrocompatibilité avec les anciens fichiers XML où les balises étaient des FQCN.

Méthode récursive centrale — read(Class, Element, attrName, attrValue)

Le cœur du lecteur. Prend un type de champ, un élément XML, et un nom/valeur d'attribut optionnel. La logique est une chaîne de vérifications de type :

  1. Vérification de référence : si l'élément a l'attribut o-ref-id — c'est une référence à un objet déjà désérialisé. Recherche dans referenceObjects et renvoie l'objet mis en cache (déduplication). Si l'ID de référence n'est pas trouvé — enregistre une erreur
  2. Vérification du convertisseur : si le type a un IConverter enregistré (via xmlRegistry.getConverter(clazz)) — appelle converter.fromString(). Pour les types simples : String, Integer, Date, BigDecimal, Boolean
  3. Vérification d'énumération : si la classe est une énumération, appelle enumFromString(). Essaie Enum.valueOf(clazz, val). En cas de IllegalArgumentException, effectue une deuxième tentative avec toUpperCase() — rétrocompatibilité avec les anciens XML où les énumérations étaient en minuscules. La valeur "null" est traitée comme null
  4. Vérification de collection : si la classe est une Collection (List/Set/SortedSet), crée l'implémentation appropriée (ArrayList/HashSet/TreeSet), et lit récursivement tous les éléments XML enfants comme éléments de la collection. Si ignoreEmptyCollections=true et que la collection est vide — laisse le champ à null
  5. Objet complexe : pour tous les autres types (classes avec @XmlObject) — crée une instance via BeanHelper.newInstance(), vérifie l'attribut o-id (le sauvegarde dans referenceObjects pour les futures recherches de ref-id), et appelle read(obj, el) pour le remplissage récursif des champs

Remplissage des champs — read(Object obj, Element el)

Parcourt tous les champs de l'objet (via BeanHelper.getAllDeclaredFields() — y compris les champs hérités), les rend accessibles (réflexion), et pour chaque attribut XML et élément enfant trouve le champ correspondant :

  • Vérifie d'abord @XmlOmitField — si présent, le champ est ignoré
  • Recherche l'annotation @XmlField. Compare le nom de la balise/attribut avec le nom du champ (sensible à la casse) et avec l'alias de l'annotation
  • Si le champ est trouvé — appelle read(field.getType(), element, key, attrValue) pour la désérialisation, puis field.set(obj, value) pour l'affectation
  • Si le champ n'est PAS trouvé — enregistre un avertissement "Champ '...' introuvable." L'élément reste non marqué dans processedElements et apparaîtra dans les avertissements

Important : les champs o-id et ref-id (attributs XML de l'écrivain) sont explicitement ignorés — ils ne sont pas recherchés parmi les champs de l'objet.

Avertissements — checkForIgnoredElements()

Après avoir lu tout le XML, le lecteur vérifie : tous les éléments de l'arbre XML source ont-ils été marqués comme processed ? Sinon, le XML contient des balises pour lesquelles aucun champ n'a été trouvé dans la classe Java. Cela peut indiquer :

  • Le XML a été créé par une version plus récente de ProjectForge (nouveaux champs dans le XML mais pas dans le code)
  • Faute de frappe dans le nom du champ ou l'alias
  • La classe a été modifiée (champ supprimé ou renommé)

Tous les éléments et attributs non marqués sont collectés dans une chaîne warnings. Si la chaîne dépasse 500 caractères — elle est tronquée (ABBREVIATE_WARNING=500) pour éviter de surcharger les logs.

Points d'extension de méthode modèle pour les sous-classes

Trois méthodes protégées peuvent être redéfinies dans les sous-classes :

  • newInstance(Class, Element, String, String) — intercepte la création d'objet. Si elle renvoie Status.IGNORE, l'objet est ignoré. Par défaut, renvoie null (création standard)
  • addCollectionEntry(Collection, Object, Element) — intercepte l'ajout à la collection. Si elle renvoie true, l'objet n'est PAS ajouté automatiquement. Par défaut, renvoie false
  • setField(Field, Object, Object, Element, String, String) — intercepte l'affectation du champ. Par défaut, appelle field.set(obj, value)

Ces points d'extension permettent aux sous-classes de modifier le comportement sans réécrire toute la logique — par exemple, ignorer certains champs, filtrer les collections ou post-traiter les objets.

initialize(Class) — Pré-analyse

Peut être appelé avant la lecture pour pré-enregistrer toutes les classes @XmlObject dans AliasMap. Parcourt récursivement l'arbre des types : pour une classe avec @XmlObject, enregistre l'alias, puis pour chaque champ non primitif appelle récursivement initialize(). Utilise un ensemble processed pour éviter les récursions infinies sur les références circulaires. Cela permet de passer uniquement la classe racine — le lecteur trouve lui-même tous les types imbriqués.
