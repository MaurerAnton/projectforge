#758: AliasMap.java

Java utility class — bidirectional Class↔XML-alias mapping. 40 lines. Source: projectforge-business/src/main/java/org/projectforge/framework/xmlstream/AliasMap.java
Purpose: A bidirectional map that bridges Java classes and XML element/attribute names. It maintains two internal HashMaps — one mapping Class → alias and another mapping alias → Class — providing O(1) lookup in both directions. This is the central registry of "how Java classes map to XML tags" in the XmlStream framework, used by both XmlObjectWriter (to write the correct tag name) and XmlObjectReader (to find the correct class for a tag encountered in XML).

Design — Bidirectional HashMap

The class uses two HashMap fields:

  • aliasMap1: Map<Class<?>, String> — Class → alias for converting Java types to XML tag names during serialization
  • aliasMap2: Map<String, Class<?>> — alias → Class for converting XML tag names back to Java types during deserialization

Both maps are populated simultaneously via put(Class, String). This is a simple but effective pattern: no need for Guava's BiMap or any external dependency — just two plain HashMaps maintained in sync. The trade-off is double the memory for fast bidirectional lookups, but since alias maps typically contain tens to hundreds of entries, the overhead is negligible.

Usage in the XmlStream Pipeline

  1. Registration phase: XmlRegistry (#759) and XmlObjectReader.initialize() populate AliasMap entries for all @XmlObject-annotated classes
  2. Serialization (Writer): XmlObjectWriter.write() calls aliasMap.getAliasForClass(type) to determine the XML tag name. Falls back to @XmlObject.alias(), then XmlRegistry, then FQCN
  3. Deserialization (Reader): XmlObjectReader.getClass() calls aliasMap.getClassForAlias(elementName) to find the Java class for an XML tag. Falls back to XmlRegistry, then Class.forName()

This allows both local (per-reader/writer) and global (XmlRegistry-level) alias customization.

Why Not Guava BiMap?

Guava's BiMap provides a bidirectional map with value uniqueness guarantees and inverse() view. However, AliasMap predates widespread Guava adoption in ProjectForge, or the author chose to minimize dependencies. The two-HashMap approach is simpler, avoids an external dependency boundary, and the value uniqueness (no two classes should have the same alias) is enforced by the caller (XmlRegistry), not the data structure.
