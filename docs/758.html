#758: XmlObjectWriter.java

Lines: 387 · Author: Kai Reinhard · Type: Java — движок сериализации XmlStream · Library: dom4j

Что это

Движок сериализации фреймворка XmlStream — превращает Java-объекты в XML (dom4j Document). 387 строк. Javadoc объясняет мотивацию создания: "A simple solution for streaming xml objects and to prevent default values from the xml output (because this feature isn't yet available in XStream). It's only fit the ProjectForge requirements and is not very useful as generic xml streaming package." — то есть XStream на момент написания не умел пропускать поля со значениями по умолчанию, а для экспорта данных это критично (чтобы XML не раздувался от тысяч <deleted>false</deleted>).

Пара с XmlObjectReader: Writer сериализует Java → XML, Reader десериализует XML → Java. Оба используют dom4j как XML-библиотеку и @XmlObject/@XmlField аннотации для управления форматом.

Две константы — deduplication через XML-атрибуты

  • ATTR_ID = "o-id" — уникальный идентификатор объекта в XML. Writer присваивает каждому новому объекту возрастающий refIdCounter и записывает как атрибут o-id="0", o-id="1" и т.д.
  • ATTR_REF_ID = "ref-id" — ссылка на уже записанный объект. Если объект уже был сериализован ранее (найден в writtenObjects кэше), Writer НЕ записывает его содержимое повторно, а только ставит ref-id="0" — ссылку на элемент с o-id="0"

Этот механизм решает проблему циклических ссылок и дублирования. Пример: объект A содержит ссылку на объект B, а B содержит обратную ссылку на A. Без deduplication Writer ушёл бы в бесконечную рекурсию. С deduplication: A записывается с o-id=0, B с o-id=1, обратная ссылка на A — как ref-id=0.

Кэш записанных объектов — writtenObjects

Map<String, Element> где ключ — className:hashCode объекта (например "org.projectforge.business.user.PFUserDO:987345678854"). Это identity-based кэш (по хэш-коду), а не equals-based — два разных объекта с одинаковыми полями будут записаны оба, а один объект встреченный дважды — только один раз. Использование hashCode() для identity ненадёжно (коллизии возможны), но на практике для типичных размеров XML (сотни-тысячи объектов) вероятность коллизии пренебрежимо мала.

Основной метод — write(Branch parent, Object obj, String name, boolean asAttribute, boolean asCDATA)

Рекурсивный метод сериализации. Логика — та же цепочка проверок типа что и в Reader, но в обратном направлении:

  1. Определение имени тега: сначала AliasMap, потом @XmlObject.alias, потом XmlRegistry, потом fallback на полное имя класса
  2. Проверка deduplication: если объект уже в writtenObjects — пишет ref-id вместо полного содержимого
  3. Converter: если тип имеет зарегистрированный IConverter — вызывает converter.toString() и записывает результат как текст элемента или атрибут
  4. Enum: записывает enum.name() (например "ACTIVE", "PAID")
  5. Collection: создаёт элемент-обёртку и рекурсивно пишет каждый элемент коллекции
  6. Complex object: создаёт элемент, регистрирует объект в writtenObjects, обходит все поля через reflection, для каждого НЕ-default поля вызывает writeField()

Default-value skipping — ключевая фича

Метод isDefaultType(ann, value) проверяет: равно ли значение поля значению по умолчанию из аннотации @XmlField.default*? Если да — поле не записывается. Это то, ради чего создавался XmlStream:

  • Boolean: если аннотация не указана, по умолчанию false — все false-поля пропускаются. Если аннотация указана — сравнивается с defaultBooleanValue()
  • Double: сравнивается с defaultDoubleValue() через compareTo(). Если аннотация не указана — проверка: !Double.isNaN(ann.defaultDoubleValue()) (NaN = "не задано")
  • Integer: сравнивается с defaultIntValue(). Магическое число MAGIC_INT_NUMBER из XmlConstants используется как sentinel "не задано"
  • String / Enum: сравнивается с defaultStringValue(). Магическая строка MAGIC_STRING — sentinel

hasDefaultType() проверяет, задан ли default в аннотации вообще (отличает "default не указан" от "default == false/0/null"). Для Boolean — всегда true (false — валидный default). Для остальных типов — сравнивает с MAGIC-значениями.

Определение атрибут vs элемент — asAttributeAsDefault()

Некоторые типы по умолчанию сериализуются как атрибуты (компактно), а не как элементы. Логика:

  • xmlRegistry.asAttributeAsDefault(type) — глобальная настройка (например, все примитивные типы → атрибуты)
  • Enum.class.isAssignableFrom(type) — все enum'ы всегда как атрибуты (короткое имя типа "ACTIVE" хорошо смотрится в атрибуте)
  • Аннотация @XmlField.asAttribute=true — переопределение для конкретного поля
  • Аннотация @XmlField.asElement=true — принудительно как элемент (даже если тип по умолчанию атрибут)

Игнорирование полей — ignoreField(Field)

Статический метод, используется и Writer'ом и Reader'ом (#757). Пропускает поля с модификаторами: static (константы класса), final (нельзя изменить после создания), transient (явно помечены как несериализуемые). Также есть protected-метод ignoreField(Object, Field) который подклассы могут переопределить для дополнительной фильтрации. Плюс аннотация @XmlOmitField — явный маркер пропуска независимо от модификаторов.
