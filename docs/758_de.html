Zweck: Die Serialisierungs-Engine des XmlStream-Frameworks — konvertiert Java-Objekte in XML (dom4j Document). 387 Zeilen. Javadoc erklärt die Motivation: „Eine einfache Lösung zum Streamen von XML-Objekten und zum Unterdrücken von Standardwerten in der XML-Ausgabe (da diese Funktion in XStream noch nicht verfügbar ist).“ — zum Zeitpunkt der Erstellung konnte XStream keine Felder mit Standardwerten überspringen, was für den Datenexport kritisch ist (um XML-Aufblähung durch tausende <deleted>false</deleted>-Tags zu vermeiden). Ergänzt sich mit XmlObjectReader: Writer serialisiert Java → XML, Reader deserialisiert XML → Java. Beide verwenden dom4j als XML-Bibliothek und @XmlObject/@XmlField-Annotationen zur Formatsteuerung.

Deduplizierung mittels XML-Attributen — ATTR_ID und ATTR_REF_ID

  • ATTR_ID = "o-id" — eindeutige Objektkennung in XML. Der Writer weist jedem neuen Objekt einen hochzählenden refIdCounter zu und schreibt ihn als Attribut o-id="0", o-id="1" usw.
  • ATTR_REF_ID = "ref-id" — Verweis auf ein bereits geschriebenes Objekt. Wenn ein Objekt bereits serialisiert wurde (im writtenObjects-Cache gefunden), schreibt der Writer seinen Inhalt NICHT erneut, sondern setzt nur ref-id="0" — ein Verweis auf das Element mit o-id="0"

Dieser Mechanismus löst zirkuläre Referenzen und Deduplizierung. Beispiel: Objekt A enthält einen Verweis auf Objekt B, und B enthält einen Rückverweis auf A. Ohne Deduplizierung würde der Writer in eine Endlosrekursion geraten. Mit Deduplizierung: A wird mit o-id=0 geschrieben, B mit o-id=1, der Rückverweis auf A wird als ref-id=0 geschrieben.

Cache für geschriebene Objekte — writtenObjects

Map<String, Element> wobei der Schlüssel className:hashCode ist (z. B. "org.projectforge.business.user.PFUserDO:987345678854"). Dies ist ein identitätsbasierter Cache (nach hashCode), nicht equals-basiert — zwei verschiedene Objekte mit identischen Feldern werden beide geschrieben, aber ein zweimal angetroffenes Objekt wird nur einmal geschrieben. Die Verwendung von hashCode() zur Identitätsbestimmung ist theoretisch unzuverlässig (Kollisionen möglich), aber in der Praxis ist die Kollisionswahrscheinlichkeit bei typischen XML-Größen (hunderte bis tausende Objekte) verschwindend gering.

Kernmethode — write(Branch parent, Object obj, String name, boolean asAttribute, boolean asCDATA)

Rekursive Serialisierungsmethode. Die Logik spiegelt die Typprüfungskette des Readers wider, jedoch umgekehrt:

  1. Tag-Namen bestimmen: zuerst AliasMap, dann @XmlObject.alias, dann XmlRegistry, dann Fallback auf FQCN
  2. Deduplizierungsprüfung: wenn das Objekt bereits in writtenObjects ist — schreibt ref-id anstelle des vollständigen Inhalts
  3. Konverter: wenn der Typ einen registrierten IConverter hat — ruft converter.toString() auf und schreibt das Ergebnis als Elementtext oder Attribut
  4. Enum: schreibt enum.name() (z. B. "ACTIVE", "PAID")
  5. Collection: erstellt ein Wrapper-Element und schreibt rekursiv jedes Collection-Element
  6. Komplexes Objekt: erstellt Element, registriert Objekt in writtenObjects, iteriert über alle Felder via Reflection, ruft writeField() für jedes nicht-standardmäßige Feld auf

Überspringen von Standardwerten — Die Killerfunktion

Die Methode isDefaultType(ann, value) prüft, ob der Feldwert dem Standardwert aus @XmlField.default* entspricht. Wenn ja, wird das Feld NICHT geschrieben. Dies ist der Grund, warum XmlStream erstellt wurde:

  • Boolean: wenn die Annotation nicht spezifiziert ist, ist der Standardwert false — alle false-Felder werden übersprungen
  • Double: Vergleich mit defaultDoubleValue() via compareTo()
  • Integer: Vergleich mit defaultIntValue(). Die magische Zahl MAGIC_INT_NUMBER aus XmlConstants dient als Sentinel für „nicht gesetzt“
  • String/Enum: Vergleich mit defaultStringValue(). Der magische String MAGIC_STRING ist der Sentinel

hasDefaultType() prüft, ob überhaupt ein Standardwert deklariert wurde (unterscheidet „Standard nicht gesetzt“ von „Standard == false/0/null“). Für Boolean — immer wahr (false ist ein gültiger Standard). Für andere Typen — Vergleich mit MAGIC-Sentinels.

Attribut vs. Element Standard — asAttributeAsDefault()

Einige Typen werden standardmäßig als Attribute serialisiert (kompakt):

  • xmlRegistry.asAttributeAsDefault(type) — globale Einstellung (z. B. alle primitiven Typen → Attribute)
  • Enum.class.isAssignableFrom(type) — alle Enums immer als Attribute (kurze Namen wie "ACTIVE" passen gut in Attribute)
  • @XmlField.asAttribute=true — feldbezogene Überschreibung
  • @XmlField.asElement=true — als Element erzwingen (auch wenn der Typ standardmäßig Attribut verwendet)

Feld ignorieren — ignoreField(Field)

Statische Methode, die sowohl vom Writer als auch vom Reader verwendet wird. Überspringt Felder mit Modifikatoren: static (Klassenkonstanten), final (unveränderlich nach Erstellung), transient (explizit nicht serialisierbar). Außerdem kann die geschützte Methode ignoreField(Object, Field) von Unterklassen für zusätzliche Filterung überschrieben werden. Plus die @XmlOmitField-Annotation — eine explizite Markierung zum Überspringen, unabhängig von Modifikatoren.
