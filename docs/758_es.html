Fuente: projectforge-business/src/main/java/org/projectforge/framework/xmlstream/XmlObjectWriter.java 387 líneas · 271 código · 80 comentarios · 36 en blanco
Propósito: El motor de serialización del framework XmlStream — convierte objetos Java a XML (dom4j Document). 387 líneas. El Javadoc explica la motivación: "Una solución simple para transmitir objetos xml y evitar valores predeterminados en la salida xml (porque esta característica aún no está disponible en XStream)." — en el momento de escribir esto, XStream no podía omitir campos con valores predeterminados, y para la exportación de datos esto es crítico (para evitar la hinchazón del XML con miles de etiquetas <deleted>false</deleted>). Se combina con XmlObjectReader: Writer serializa Java → XML, Reader deserializa XML → Java. Ambos utilizan dom4j como biblioteca XML y las anotaciones @XmlObject/@XmlField para el control de formato.

Desduplicación mediante atributos XML — ATTR_ID y ATTR_REF_ID

  • ATTR_ID = "o-id" — identificador único de objeto en XML. Writer asigna a cada objeto nuevo un refIdCounter incremental y lo escribe como atributo o-id="0", o-id="1", etc.
  • ATTR_REF_ID = "ref-id" — referencia a un objeto ya escrito. Si un objeto ya fue serializado (encontrado en la caché writtenObjects), Writer NO vuelve a escribir su contenido, sino que solo establece ref-id="0" — una referencia al elemento con o-id="0"

Este mecanismo resuelve referencias circulares y desduplicación. Ejemplo: el objeto A contiene una referencia al objeto B, y B contiene una referencia inversa a A. Sin desduplicación, Writer entraría en recursión infinita. Con desduplicación: A se escribe con o-id=0, B con o-id=1, la referencia inversa a A se escribe como ref-id=0.

Caché de objetos escritos — writtenObjects

Map<String, Element> donde la clave es className:hashCode (ej., "org.projectforge.business.user.PFUserDO:987345678854"). Esta es una caché basada en identidad (por hashCode), no basada en equals — dos objetos diferentes con campos idénticos se escribirán ambos, pero un objeto encontrado dos veces se escribirá solo una vez. Usar hashCode() para la identidad es teóricamente poco fiable (posibles colisiones), pero en la práctica para tamaños XML típicos (cientos a miles de objetos), la probabilidad de colisión es extremadamente baja.

Método principal — write(Branch parent, Object obj, String name, boolean asAttribute, boolean asCDATA)

Método de serialización recursivo. La lógica refleja la cadena de verificación de tipos del Reader pero en orden inverso:

  1. Determinar nombre de etiqueta: primero AliasMap, luego @XmlObject.alias, luego XmlRegistry, luego nombre completamente calificado (FQCN) como respaldo
  2. Verificación de desduplicación: si el objeto ya está en writtenObjects — escribe ref-id en lugar del contenido completo
  3. Convertidor: si el tipo tiene un IConverter registrado — llama a converter.toString() y escribe el resultado como texto del elemento o atributo
  4. Enum: escribe enum.name() (ej., "ACTIVE", "PAID")
  5. Colección: crea un elemento contenedor y escribe recursivamente cada elemento de la colección
  6. Objeto complejo: crea elemento, registra el objeto en writtenObjects, itera todos los campos mediante reflexión, llama a writeField() para cada campo no predeterminado

Omisión de valores predeterminados — La característica estrella

El método isDefaultType(ann, value) verifica si el valor del campo es igual al valor predeterminado de @XmlField.default*. Si es así, el campo NO se escribe. Esta es la razón por la que se creó XmlStream:

  • Booleano: si la anotación no está especificada, el valor predeterminado es false — todos los campos false se omiten
  • Double: se compara con defaultDoubleValue() mediante compareTo()
  • Integer: se compara con defaultIntValue(). El número mágico MAGIC_INT_NUMBER de XmlConstants sirve como centinela de "no establecido"
  • String/Enum: se compara con defaultStringValue(). La cadena mágica MAGIC_STRING es el centinela

hasDefaultType() verifica si se declaró un valor predeterminado (distingue entre "predeterminado no establecido" y "predeterminado == false/0/null"). Para Boolean — siempre es verdadero (false es un valor predeterminado válido). Para otros tipos — compara con los centinelas MAGIC.

Atributo vs. Elemento predeterminado — asAttributeAsDefault()

Algunos tipos se serializan como atributos de forma predeterminada (compacto):

  • xmlRegistry.asAttributeAsDefault(type) — configuración global (ej., todos los tipos primitivos → atributos)
  • Enum.class.isAssignableFrom(type) — todos los enums siempre como atributos (nombres cortos como "ACTIVE" encajan bien en atributos)
  • @XmlField.asAttribute=true — anulación por campo
  • @XmlField.asElement=true — forzar como elemento (incluso si el tipo predetermina atributo)

Ignorar campos — ignoreField(Field)

Método estático utilizado tanto por Writer como por Reader. Omite campos con modificadores: static (constantes de clase), final (inmutables después de la creación), transient (explícitamente no serializables). Además, el método protegido ignoreField(Object, Field) puede ser anulado por subclases para filtrado adicional. Más la anotación @XmlOmitField — un marcador de omisión explícito independientemente de los modificadores.
