Source : projectforge-business/src/main/java/org/projectforge/framework/xmlstream/XmlObjectWriter.java 387 lignes · 271 code · 80 commentaires · 36 vides
Objectif : Le moteur de sérialisation du framework XmlStream — convertit des objets Java en XML (dom4j Document). 387 lignes. Le Javadoc explique la motivation : "Une solution simple pour diffuser des objets xml et empêcher les valeurs par défaut de la sortie xml (car cette fonctionnalité n'est pas encore disponible dans XStream)." — à l'époque de l'écriture, XStream ne pouvait pas ignorer les champs avec des valeurs par défaut, et pour l'export de données, c'est critique (pour éviter le gonflement XML dû à des milliers de balises <deleted>false</deleted>). Fonctionne avec XmlObjectReader : Writer sérialise Java → XML, Reader désérialise XML → Java. Les deux utilisent dom4j comme bibliothèque XML et les annotations @XmlObject/@XmlField pour le contrôle du format.

Déduplication via les attributs XML — ATTR_ID et ATTR_REF_ID

  • ATTR_ID = "o-id" — identifiant unique d'objet en XML. Writer attribue à chaque nouvel objet un refIdCounter incrémenté et écrit comme attribut o-id="0", o-id="1", etc.
  • ATTR_REF_ID = "ref-id" — référence à un objet déjà écrit. Si un objet a déjà été sérialisé (trouvé dans le cache writtenObjects), Writer n'écrit PAS son contenu à nouveau, mais définit seulement ref-id="0" — une référence à l'élément avec o-id="0"

Ce mécanisme résout les références circulaires et la déduplication. Exemple : l'objet A contient une référence à l'objet B, et B contient une référence retour à A. Sans déduplication, Writer entrerait dans une récursion infinie. Avec la déduplication : A est écrit avec o-id=0, B avec o-id=1, la référence retour à A est écrite comme ref-id=0.

Cache des objets écrits — writtenObjects

Map<String, Element> où la clé est className:hashCode (ex. "org.projectforge.business.user.PFUserDO:987345678854"). Il s'agit d'un cache basé sur l'identité (par hashCode), pas basé sur equals — deux objets différents avec des champs identiques seront tous deux écrits, mais un objet rencontré deux fois ne sera écrit qu'une seule fois. L'utilisation de hashCode() pour l'identité est théoriquement peu fiable (collisions possibles), mais en pratique pour des tailles XML typiques (centaines à milliers d'objets), la probabilité de collision est extrêmement faible.

Méthode principale — write(Branch parent, Object obj, String name, boolean asAttribute, boolean asCDATA)

Méthode de sérialisation récursive. La logique reflète la chaîne de vérification de type du Reader mais en sens inverse :

  1. Déterminer le nom de la balise : d'abord AliasMap, puis @XmlObject.alias, puis XmlRegistry, puis repli sur le FQCN
  2. Vérification de déduplication : si l'objet est déjà dans writtenObjects — écrit ref-id au lieu du contenu complet
  3. Convertisseur : si le type a un IConverter enregistré — appelle converter.toString() et écrit le résultat comme texte d'élément ou attribut
  4. Enum : écrit enum.name() (ex. "ACTIVE", "PAID")
  5. Collection : crée un élément wrapper et écrit récursivement chaque élément de la collection
  6. Objet complexe : crée un élément, enregistre l'objet dans writtenObjects, itère tous les champs via la réflexion, appelle writeField() pour chaque champ non par défaut

Ignorance des valeurs par défaut — La fonctionnalité phare

La méthode isDefaultType(ann, value) vérifie si la valeur du champ est égale à la valeur par défaut de @XmlField.default*. Si c'est le cas, le champ n'est PAS écrit. C'est pourquoi XmlStream a été créé :

  • Booléen : si l'annotation n'est pas spécifiée, la valeur par défaut est false — tous les champs false sont ignorés
  • Double : comparé à defaultDoubleValue() via compareTo()
  • Entier : comparé à defaultIntValue(). Le nombre magique MAGIC_INT_NUMBER de XmlConstants sert de sentinelle "non défini"
  • Chaîne/Enum : comparé à defaultStringValue(). La chaîne magique MAGIC_STRING est la sentinelle

hasDefaultType() vérifie si une valeur par défaut a été déclarée (distingue "valeur par défaut non définie" de "valeur par défaut == false/0/null"). Pour Boolean — toujours vrai (false est une valeur par défaut valide). Pour les autres types — compare avec les sentinelles MAGIC.

Attribut vs. Élément par défaut — asAttributeAsDefault()

Certains types sont sérialisés comme attributs par défaut (compacts) :

  • xmlRegistry.asAttributeAsDefault(type) — paramètre global (ex. tous les types primitifs → attributs)
  • Enum.class.isAssignableFrom(type) — toutes les énumérations toujours comme attributs (les noms courts comme "ACTIVE" s'intègrent bien dans les attributs)
  • @XmlField.asAttribute=true — remplacement par champ
  • @XmlField.asElement=true — force comme élément (même si le type par défaut est attribut)

Ignorance de champ — ignoreField(Field)

Méthode statique utilisée à la fois par Writer et Reader. Ignore les champs avec les modificateurs : static (constantes de classe), final (immuable après création), transient (explicitement non sérialisable). De plus, la méthode protégée ignoreField(Object, Field) peut être surchargée par les sous-classes pour un filtrage supplémentaire. Plus l'annotation @XmlOmitField — un marqueur d'ignorance explicite indépendamment des modificateurs.
