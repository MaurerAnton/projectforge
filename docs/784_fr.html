Entrée du registre qui lie un DAO, son DAO de script, et les métadonnées (filtre de recherche, préfixe i18n, DO imbriqués, support de la recherche en texte intégral) pour l'enregistrement des modules et plugins dans le registre global de l'application ProjectForge.

Architecture

RegistryEntry est une pièce centrale du système de plugins ProjectForge. Chaque module métier (feuilles de temps, adresses, todo, etc.) et chaque plugin enregistre une RegistryEntry par type d'entité. L'entrée contient :

  • id — Un identifiant unique sous forme de chaîne pour l'entrée du registre (ex. "timesheet", "address").
  • daoClassType — La classe concrète BaseDao, nécessaire car Spring encapsule les DAO dans des proxies.
  • i18nPrefix — Préfixe de clé i18n pour les étiquettes de l'interface utilisateur (par défaut, prend la valeur de id si non fourni).
  • Support de script — Chaque entrée peut enregistrer un ScriptingDao personnalisé pour l'exposition au moteur Groovy/scripting, ou supprimer complètement le scripting.
  • Recherche en texte intégral — Contrôle si l'entité participe à l'indexation Hibernate Search via isFullTextSearchSupport().
  • Classe de filtre de recherche — Enregistre une sous-classe de BaseSearchFilter pour les formulaires de recherche avancée.
  • Classes DO imbriquées — Entités dépendantes (ex. images d'adresse) qui doivent être réindexées en même temps que le parent.

La classe Registry (dans le même package) collecte toutes les instances de RegistryEntry et fournit une recherche par ID ou par classe DO. Le module Wicket étend cela avec WebRegistryEntry (dans org.projectforge.web.registry) qui ajoute des métadonnées de couche web telles que les entrées de menu.
