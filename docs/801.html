#801: SecurityHeaderFilter.java

Servlet Filter, projectforge-business/src/main/java/org/projectforge/security/SecurityHeaderFilter.java

HTTP Security Headers Filter

A servlet filter that adds HTTP security headers to every response. At 76 lines, it implements jakarta.servlet.Filter (migrated from javax.servlet.Filter in commit 77bade6df for Jakarta EE 9). The Javadoc references the AppCanary article on HTTP security headers. Protects against XSS, clickjacking, MIME-sniffing, and DNS-prefetch attacks.

Four headers are hardcoded; the fifth (CSP) is configurable via servlet init-param. The filter is registered in the web application deployment descriptor (web.xml or WebXMLInitializer).

Hardcoded Security Headers

HeaderValuePurpose
X-XSS-Protection1; mode=blockEnables browser's built-in XSS auditor. mode=block makes the browser block the page entirely rather than attempting to sanitize, which is safer since sanitization can be bypassed.
X-DNS-Prefetch-ControloffDisables DNS prefetching. Prevents information leakage about internal hosts via DNS lookups that could reveal intranet topology.
X-Frame-OptionsSAMEORIGINPrevents the page from being embedded in an iframe on a different origin. Mitigates clickjacking attacks.
X-Content-Type-OptionsnosniffPrevents browsers from MIME-sniffing. Without this, a browser might interpret a harmless text file as an executable script, enabling MIME-sniffing attacks.

Configurable CSP Header

The Content-Security-Policy (CSP) header is not hardcoded. It is loaded from the servlet configuration via filterConfig.getInitParameter("csp"). If the parameter is not set, the CSP header (and its fallbacks) are not added. This allows administrators to tune CSP to a specific deployment.

Two fallback headers are added for backward compatibility with older browsers:

  • X-Content-Security-Policy — for older Firefox versions
  • X-WebKit-CSP — for older Chrome/Safari versions

CSP is defined in the content filter mapping in web.xml:

<filter-mapping>
  <filter-name>SecurityHeaderFilter</filter-name>
  <url-pattern>/content/*</url-pattern>
</filter-mapping>

Jakarta EE 9 Migration

Originally used javax.servlet.Filter from the Java EE namespace. In commit 77bade6df, all javax.* imports were migrated to jakarta.* as part of the Jakarta EE 9 transition. The API is otherwise identical — only the package name changed.

Stability

This file has remained essentially unchanged since its creation — aside from copyright year bumps and the Jakarta namespace migration. Security headers are standardized by the OWASP community and rarely need changes. This is one of the most stable files in the entire ProjectForge codebase.
