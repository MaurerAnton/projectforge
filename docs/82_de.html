Zweck: Kernservice des DataTransfer-Plugins – ein in ProjectForge eingebettetes Dateifreigabesystem. Erstellt persönliche Dateiboxen pro Benutzer, legt Dateien über JCR (Jackrabbit Content Repository) darin ab und generiert teilbare Links. Implementiert DataTransferInterface – den Vertrag, den andere ProjectForge-Komponenten nutzen, um programmatisch Dateien in Benutzerboxen abzulegen (z. B. Berichtsgeneratoren, Rechnungsexporteure).

Die Plugin-Brücke – Selbstregistrierung beim Start

@Service
class DataTransferService : DataTransferInterface {
    @PostConstruct
    private fun postConstruct() {
        dataTransferBridge.register(this)   // "Ich bin ein DataTransfer-Anbieter!"
    }
}

Dies ist das Plugin-Selbstregistrierungsmuster. Wenn Spring diese Bean erstellt, wird @PostConstruct ausgelöst und der Service registriert sich bei DataTransferBridge. Die Bridge verwaltet eine Sammlung aller DataTransferInterface-Implementierungen. Andere Teile von ProjectForge (Berichtsgeneratoren, Skriptausführer, Rechnungsexporteure) fragen die Bridge ab, um verfügbare Datenübertragungsanbieter zu finden – sie müssen nichts über dieses spezifische Plugin wissen. Dies ist das Observer-Muster, angewendet auf die Plugin-Erkennung: Plugins registrieren sich selbst; Konsumenten entdecken sie über die Bridge.

Warum nicht einfach @Autowired? Weil es MEHRERE Datenübertragungsanbieter geben könnte (verschiedene Plugins). Das Bridge-Muster erlaubt es Konsumenten, über alle Anbieter zu iterieren oder einen nach Kriterien auszuwählen, während @Autowired mit einer Liste den Konsumenten an Springs Injektionsmechanismus koppeln würde.

Persönliche Box – jeder Benutzer erhält privaten Dateispeicher

override fun getPersonalBoxOfUserLink(userId: Long): String {
    val personalBox = dataTransferAreaDao.ensurePersonalBox(userId)
        ?: throw IllegalStateException("Persönliche Box für Benutzer mit ID $userId nicht gefunden.")
    return getDataTransferAreaLink(personalBox.id)
}

ensurePersonalBox() – das Präfix "ensure" ist eine ProjectForge-Konvention: Erstellen, falls nicht vorhanden; zurückgeben, falls vorhanden. Dies ist idempotent – ein zweimaliger Aufruf für denselben Benutzer gibt dieselbe Box zurück. Das DAO überprüft vermutlich die Datenbank auf eine vorhandene persönliche Box und erstellt eine, falls keine existiert.

Der Elvis-Operator ?:: Kotlins Nullsicherheitsoperator. Wenn ensurePersonalBox null zurückgibt (unerwartet – sollte immer erfolgreich sein), wird die IllegalStateException ausgelöst. Die Fehlermeldung enthält die Benutzer-ID zur Fehlersuche – ein Log-Grepper kann finden, welcher Benutzer den Fehler verursacht hat.

Der zurückgegebene Link verweist auf DataTransferPageRest – einen REST-Endpunkt. Der Link wird in E-Mail-Benachrichtigungen verwendet: "Ihre Rechnung wurde erstellt. Laden Sie sie hier herunter: https://projectforge.acme.com/rs/datatransfer/..."

Die Kernoperation – Ablegen einer Datei in der Benutzerbox (Zeilen 82-114)

override fun putFileInUsersInBox(
    receiver: PFUserDO,           // Wer bekommt die Datei
    filename: String,             // Anzeigename
    content: ByteArray,           // Rohe Dateibytes
    description: String?          // Optionale Beschreibung
): Boolean {                       // Gibt true bei Erfolg zurück, false bei Fehler (kein Throw!)
    
    val personalBox = dataTransferAreaDao.ensurePersonalBox(receiver.id)
    
    attachmentsService.addAttachment(
        dataTransferAreaPagesRest.jcrPath!!,  // JCR-Knotenpfad für die Speicherung
        fileInfo = FileInfo(filename, content.size.toLong(), description),
        content = content,
        baseDao = dataTransferAreaDao,        // DAO für Zugriffskontrolle
        obj = personalBox,                    // Die Entität, an die angehängt wird
        accessChecker = dataTransferAreaPagesRest.attachmentsAccessChecker
    )
    return true
  } catch (ex: Exception) {
    log.error("Dokument '${filename}' der Größe ... kann nicht abgelegt werden", ex)
    return false                              // Sanfter Fehler – Aufrufer behandelt ihn
  }
}

attachmentsService.addAttachment() – die Brücke zu JCR (Java Content Repository). Dateien werden nicht als Datenbank-BLOBs gespeichert. Sie gehen in Apache Jackrabbit – ein hierarchisches Content-Repository, das Versionierung, Zugriffskontrolle und Binärspeicherung handhabt. Der JCR-Pfad stammt von dataTransferAreaPagesRest.jcrPath – jeder Datenübertragungsbereich hat seinen eigenen Knoten im JCR-Baum.

Die 6 Parameter von addAttachment() zeigen den Vertrag des Anhangssystems:

ParameterZweck
jcrPathJCR-Knotenpfad – wo im Content-Baum gespeichert werden soll
fileInfoMetadaten: Dateiname, Größe, Beschreibung. Gekapselt in einer FileInfo-Datenklasse.
contentRohe Bytes – die eigentliche Datei. ByteArray bedeutet, dass die gesamte Datei im Speicher ist. Große Dateien (>100 MB) würden zu OOM führen.
baseDaoDas für die Entität zuständige DAO – wird für die Historie und Zugriffskontrolle verwendet
objDie besitzende Entität – die persönliche Box, die diese Datei "besitzt"
accessCheckerBestimmt, wer diesen Anhang lesen/schreiben/löschen darf

Fehlerbehandlung – false zurückgeben, niemals werfen

Rückgabetyp Boolean statt Unit: Dies ist eine bewusste Designentscheidung. Die Methode gibt bei Erfolg true zurück, bei Fehler false. Sie WIRFT NIE (der catch-Block fängt Exception – die breitestmögliche). Der Aufrufer kann entscheiden, wie er mit dem Fehler umgeht: Fehlermeldung anzeigen, wiederholen oder stillschweigend fortfahren.

Protokollierung mit formatBytes(): content.size.formatBytes() ist eine Kotlin-Erweiterungsfunktion (importiert aus org.projectforge.common.extensions). Sie wandelt rohe Byte-Zahlen in ein menschenlesbares Format um ("1,5 MB", "340 KB"). Wird in der Logmeldung verwendet: "Dokument 'invoice.pdf' der Größe 1,5 MB kann nicht in die persönliche Box von Benutzer 'Kai Reinhard' abgelegt werden" – dies ist für den Support bei der Fehlersuche hilfreich.

Das große !! in Zeile 94: dataTransferAreaPagesRest.jcrPath!! – dies wird eine NullPointerException werfen, wenn jcrPath null ist. Der !!-Operator bedeutet "Ich bin sicher, dass dies niemals null ist." Falls es DOCH null ist, wird die NPE vom catch (Exception)-Block abgefangen und protokolliert. Aber idealerweise sollte dies eine ordentliche Nullprüfung mit einer beschreibenden Fehlermeldung haben.

Wie dies mit dem Rest des Systems verbunden ist

Dieser Service ist die Brücke zwischen drei Subsystemen:

  1. Plugin-Konsumenten – Skriptausführer, Berichtsgeneratoren, Rechnungsexporteure. Sie rufen dataTransferBridge.getProviders() auf → finden DataTransferInterface → rufen putFileInUsersInBox() auf. Sie wissen nichts über JCR, persönliche Boxen oder Zugriffskontrolle.
  2. JCR-Speicher – attachmentsService.addAttachment() speichert Dateien in Apache Jackrabbit. Das JCR übernimmt Versionierung, Zugriffskontrolle und Binärspeicherung. Dateien befinden sich nicht in der Datenbank.
  3. REST-API – DataTransferPageRest und DataTransferAreaPagesRest stellen Download-/Upload-Endpunkte bereit. Die Methode getDataTransferAreaLink() generiert URLs für diese Endpunkte.

Das Entwurfsmuster ist eine Fassade: Komplexe JCR-Operationen werden hinter einer einfachen putFileInUsersInBox()-Schnittstelle verborgen.
