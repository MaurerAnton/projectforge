Objectif : Service central du plugin DataTransfer — un système de partage de fichiers intégré à ProjectForge. Crée des boîtes personnelles par utilisateur, y dépose des fichiers via JCR (Jackrabbit Content Repository) et génère des liens partageables. Implémente DataTransferInterface — le contrat que les autres composants de ProjectForge utilisent pour déposer programmatiquement des fichiers dans les boîtes des utilisateurs (ex. générateurs de rapports, exportateurs de factures).

Le pont du plugin — auto-enregistrement au démarrage

@Service
class DataTransferService : DataTransferInterface {
    @PostConstruct
    private fun postConstruct() {
        dataTransferBridge.register(this)   // "Je suis un fournisseur DataTransfer !"
    }
}

Voici le modèle d'auto-enregistrement du plugin. Lorsque Spring crée ce bean, @PostConstruct se déclenche et le service s'enregistre auprès de DataTransferBridge. Le pont maintient une collection de toutes les implémentations de DataTransferInterface. D'autres parties de ProjectForge (générateurs de rapports, exécuteurs de scripts, exportateurs de factures) interrogent le pont pour trouver les fournisseurs de transfert de données disponibles — elles n'ont pas besoin de connaître ce plugin spécifique. Il s'agit du modèle Observateur appliqué à la découverte de plugins : les plugins s'enregistrent eux-mêmes ; les consommateurs les découvrent via le pont.

Pourquoi ne pas simplement utiliser @Autowired ? Parce qu'il pourrait y avoir PLUSIEURS fournisseurs de transfert de données (différents plugins). Le modèle du pont permet aux consommateurs de parcourir tous les fournisseurs ou d'en sélectionner un selon des critères, alors que @Autowired avec une liste lierait le consommateur au mécanisme d'injection de Spring.

Boîte personnelle — chaque utilisateur dispose d'un stockage de fichiers privé

override fun getPersonalBoxOfUserLink(userId: Long): String {
    val personalBox = dataTransferAreaDao.ensurePersonalBox(userId)
        ?: throw IllegalStateException("Boîte personnelle introuvable pour l'utilisateur avec l'ID $userId.")
    return getDataTransferAreaLink(personalBox.id)
}

ensurePersonalBox() — le préfixe "ensure" est une convention de ProjectForge : créer si absent, retourner l'existant si trouvé. C'est idempotent — l'appeler deux fois pour le même utilisateur retourne la même boîte. Le DAO vérifie probablement la base de données pour une boîte personnelle existante et en crée une si aucune n'existe.

L'opérateur Elvis ?: : L'opérateur de sécurité null de Kotlin. Si ensurePersonalBox retourne null (inattendu — cela devrait toujours réussir), l'exception IllegalStateException est déclenchée. Le message d'exception inclut l'ID utilisateur pour le débogage — un outil de recherche dans les logs peut trouver quel utilisateur a causé l'échec.

Le lien retourné pointe vers DataTransferPageRest — un point de terminaison REST. Le lien est utilisé dans les notifications par e-mail : "Votre facture a été générée. Téléchargez-la ici : https://projectforge.acme.com/rs/datatransfer/..."

L'opération principale — déposer un fichier dans la boîte d'un utilisateur (lignes 82-114)

override fun putFileInUsersInBox(
    receiver: PFUserDO,           // Qui reçoit le fichier
    filename: String,             // Nom d'affichage
    content: ByteArray,           // Octets bruts du fichier
    description: String?          // Description optionnelle
): Boolean {                       // Retourne true en cas de succès, false en cas d'échec (pas de throw !)
    
    val personalBox = dataTransferAreaDao.ensurePersonalBox(receiver.id)
    
    attachmentsService.addAttachment(
        dataTransferAreaPagesRest.jcrPath!!,  // Chemin du nœud JCR pour le stockage
        fileInfo = FileInfo(filename, content.size.toLong(), description),
        content = content,
        baseDao = dataTransferAreaDao,        // DAO pour le contrôle d'accès
        obj = personalBox,                    // L'entité à laquelle est attaché le fichier
        accessChecker = dataTransferAreaPagesRest.attachmentsAccessChecker
    )
    return true
  } catch (ex: Exception) {
    log.error("Impossible de déposer le document '${filename}' de taille ...", ex)
    return false                              // Échec gracieux — l'appelant le gère
  }
}

attachmentsService.addAttachment() — le pont vers JCR (Java Content Repository). Les fichiers ne sont pas stockés comme des BLOBs de base de données. Ils vont dans Apache Jackrabbit — un référentiel de contenu hiérarchique qui gère le versioning, le contrôle d'accès et le stockage binaire. Le chemin JCR provient de dataTransferAreaPagesRest.jcrPath — chaque zone de transfert de données a son propre nœud dans l'arbre JCR.

Les 6 paramètres de addAttachment() révèlent le contrat du système de pièces jointes :

ParamètreObjectif
jcrPathChemin du nœud JCR — où stocker dans l'arbre de contenu
fileInfoMétadonnées : nom du fichier, taille, description. Encapsulé dans une classe de données FileInfo.
contentOctets bruts — le fichier réel. ByteArray signifie que le fichier entier est en mémoire. Les gros fichiers (>100 Mo) provoqueraient une OOM.

Gestion des erreurs — retourner false, ne jamais lever d'exception

Type de retour Boolean au lieu de Unit : C'est un choix de conception délibéré. La méthode retourne true en cas de succès, false en cas d'échec. Elle NE lève JAMAIS d'exception (le bloc catch attrape Exception — le plus large possible). L'appelant peut décider comment gérer l'échec : afficher un message d'erreur, réessayer ou continuer silencieusement.

Journalisation avec formatBytes() : content.size.formatBytes() est une fonction d'extension Kotlin (importée de org.projectforge.common.extensions). Elle convertit les nombres d'octets bruts en format lisible par l'humain ("1,5 Mo", "340 Ko"). Utilisée dans le message de log : "Impossible de déposer le document 'facture.pdf' de taille 1,5 Mo dans la boîte personnelle de l'utilisateur 'Kai Reinhard'" — c'est exploitable pour le débogage du support.

Le grand !! à la ligne 94 : dataTransferAreaPagesRest.jcrPath!! — cela lèvera une NullPointerException si jcrPath est null. L'opérateur !! signifie "Je suis certain que ce n'est jamais null." Si c'est null, la NPE est attrapée par le bloc catch (Exception) et journalisée. Mais idéalement, cela devrait avoir une vérification null appropriée avec un message d'erreur descriptif.

Comment cela se connecte au reste du système

Ce service est le pont entre trois sous-systèmes :

  1. Consommateurs du plugin — exécuteurs de scripts, générateurs de rapports, exportateurs de factures. Ils appellent dataTransferBridge.getProviders() → trouvent DataTransferInterface → appellent putFileInUsersInBox(). Ils ne connaissent pas JCR, les boîtes personnelles ou le contrôle d'accès.
  2. Stockage JCR — attachmentsService.addAttachment() stocke les fichiers dans Apache Jackrabbit. Le JCR gère le versioning, le contrôle d'accès et le stockage binaire. Les fichiers ne sont pas dans la base de données.
  3. API REST — DataTransferPageRest et DataTransferAreaPagesRest exposent les points de terminaison de téléchargement/téléversement. La méthode getDataTransferAreaLink() génère des URLs pour ces points de terminaison.

Le modèle de conception est une façade : les opérations JCR complexes sont cachées derrière une interface simple putFileInUsersInBox().
