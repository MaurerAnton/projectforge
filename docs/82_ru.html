Назначение: Основной сервис плагина DataTransfer — система обмена файлами, встроенная в ProjectForge. Создаёт личные файловые ящики для каждого пользователя, помещает в них файлы через JCR (репозиторий контента Jackrabbit) и генерирует ссылки для общего доступа. Реализует DataTransferInterface — контракт, который другие компоненты ProjectForge используют для программного размещения файлов в ящиках пользователей (например, генераторы отчётов, экспортёры счетов).

Мост плагина — саморегистрация при запуске

@Service
class DataTransferService : DataTransferInterface {
    @PostConstruct
    private fun postConstruct() {
        dataTransferBridge.register(this)   // "Я — провайдер DataTransfer!"
    }
}

Это паттерн саморегистрации плагина. Когда Spring создаёт этот бин, срабатывает @PostConstruct, и сервис регистрируется в DataTransferBridge. Мост хранит коллекцию всех реализаций DataTransferInterface. Другие части ProjectForge (генераторы отчётов, исполнители скриптов, экспортёры счетов) запрашивают мост для поиска доступных провайдеров передачи данных — им не нужно знать об этом конкретном плагине. Это паттерн Наблюдатель, применённый к обнаружению плагинов: плагины регистрируются сами; потребители находят их через мост.

Почему не просто @Autowired? Потому что может быть НЕСКОЛЬКО провайдеров передачи данных (разные плагины). Паттерн "Мост" позволяет потребителям перебирать всех провайдеров или выбирать по критериям, тогда как @Autowired со списком привязал бы потребителя к механизму внедрения Spring.

Личный ящик — у каждого пользователя своё приватное хранилище файлов

override fun getPersonalBoxOfUserLink(userId: Long): String {
    val personalBox = dataTransferAreaDao.ensurePersonalBox(userId)
        ?: throw IllegalStateException("Личный ящик не найден для пользователя с ID $userId.")
    return getDataTransferAreaLink(personalBox.id)
}

ensurePersonalBox() — префикс "ensure" является соглашением ProjectForge: создать, если отсутствует, вернуть существующий, если найден. Это идемпотентно — повторный вызов для того же пользователя возвращает тот же ящик. DAO, вероятно, проверяет базу данных на наличие существующего личного ящика и создаёт новый, если его нет.

Оператор Элвиса ?:: оператор нулевой безопасности Kotlin. Если ensurePersonalBox возвращает null (неожиданно — он всегда должен успешно выполняться), срабатывает IllegalStateException. Сообщение исключения включает ID пользователя для отладки — инструменты поиска по логам смогут определить, какой пользователь вызвал сбой.

Возвращаемая ссылка указывает на DataTransferPageRest — REST-эндпоинт. Ссылка используется в уведомлениях по электронной почте: "Ваш счёт сгенерирован. Скачайте его здесь: https://projectforge.acme.com/rs/datatransfer/..."

Основная операция — помещение файла в ящик пользователя (строки 82-114)

override fun putFileInUsersInBox(
    receiver: PFUserDO,           // Кто получает файл
    filename: String,             // Отображаемое имя
    content: ByteArray,           // Сырые байты файла
    description: String?          // Необязательное описание
): Boolean {                       // Возвращает true при успехе, false при неудаче (без исключений!)
    
    val personalBox = dataTransferAreaDao.ensurePersonalBox(receiver.id)
    
    attachmentsService.addAttachment(
        dataTransferAreaPagesRest.jcrPath!!,  // Путь к узлу JCR для хранения
        fileInfo = FileInfo(filename, content.size.toLong(), description),
        content = content,
        baseDao = dataTransferAreaDao,        // DAO для контроля доступа
        obj = personalBox,                    // Сущность, к которой прикрепляется файл
        accessChecker = dataTransferAreaPagesRest.attachmentsAccessChecker
    )
    return true
  } catch (ex: Exception) {
    log.error("Не удалось поместить документ '${filename}' размером ...", ex)
    return false                              // Корректный сбой — вызывающий код обрабатывает это
  }
}

attachmentsService.addAttachment() — мост к JCR (Java Content Repository). Файлы не хранятся как BLOB-объекты базы данных. Они попадают в Apache Jackrabbit — иерархический репозиторий контента, который обрабатывает версионирование, контроль доступа и двоичное хранение. Путь JCR берётся из dataTransferAreaPagesRest.jcrPath — каждая область передачи данных имеет свой узел в дереве JCR.

6 параметров addAttachment() раскрывают контракт системы вложений:

ПараметрНазначение
jcrPathПуть к узлу JCR — где в дереве контента хранить
fileInfoМетаданные: имя файла, размер, описание. Обёрнуты в класс данных FileInfo.
contentСырые байты — сам файл. ByteArray означает, что весь файл находится в памяти. Большие файлы (>100 МБ) могут вызвать OOM.

accessCheckerОпределяет, кто может читать/записывать/удалять это вложение

Обработка ошибок — возврат false, без исключений

Тип возврата Boolean вместо Unit: Это осознанный выбор дизайна. Метод возвращает true при успехе, false при неудаче. Он НИКОГДА не выбрасывает исключения (блок catch перехватывает Exception — максимально широкий). Вызывающий код может сам решить, как обрабатывать сбой: показать сообщение об ошибке, повторить попытку или молча продолжить.

Логирование с formatBytes(): content.size.formatBytes() — это функция-расширение Kotlin (импортирована из org.projectforge.common.extensions). Она преобразует сырые количества байтов в человекочитаемый формат ("1.5 МБ", "340 КБ"). Используется в сообщении лога: "Не удалось поместить документ 'invoice.pdf' размером 1.5 МБ в личный ящик пользователя 'Kai Reinhard'" — это полезно для отладки поддержки.

Огромный !! в строке 94: dataTransferAreaPagesRest.jcrPath!! — это вызовет NullPointerException, если jcrPath равен null. Оператор !! означает "Я уверен, что это никогда не null." Если это всё же null, NPE перехватывается блоком catch (Exception) и логируется. Но в идеале здесь должна быть надлежащая проверка на null с описательным сообщением об ошибке.

Как это связано с остальной системой

Этот сервис является мостом между тремя подсистемами:

  1. Потребители плагина — исполнители скриптов, генераторы отчётов, экспортёры счетов. Они вызывают dataTransferBridge.getProviders() → находят DataTransferInterface → вызывают putFileInUsersInBox(). Они не знают о JCR, личных ящиках или контроле доступа.
  2. Хранилище JCR — attachmentsService.addAttachment() сохраняет файлы в Apache Jackrabbit. JCR обрабатывает версионирование, контроль доступа и двоичное хранение. Файлы не находятся в базе данных.
  3. REST API — DataTransferPageRest и DataTransferAreaPagesRest предоставляют эндпоинты для загрузки/скачивания. Метод getDataTransferAreaLink() генерирует URL для этих эндпоинтов.

Шаблон проектирования — фасад: сложные операции JCR скрыты за простым интерфейсом putFileInUsersInBox().
