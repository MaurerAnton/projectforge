Resumen: AddressbookDO representa una colección nombrada de direcciones — una libreta de direcciones propiedad de un usuario o grupo. Extiende BaseUserGroupRightsDO para heredar un modelo de propiedad y permisos de grupo, implementa DisplayNameCapable para etiquetas de interfaz de usuario consistentes, y lleva anotaciones de Hibernate Search (@Indexed, @FullTextField) para que las libretas de direcciones puedan localizarse mediante el motor de búsqueda de texto completo de la aplicación. Los campos están anotados con @PropertyInfo para impulsar la generación automática de formularios de interfaz de usuario.

Arquitectura y posición en el sistema

Jerarquía de clases

BaseDO
 └─ DefaultBaseDO
     └─ BaseUserGroupRightsDO        ← proporciona campos de propietario, derechos de usuario, derechos de grupo

BaseUserGroupRightsDO es el padre crítico: añade columnas para owner (una referencia a PFUserDO), junto con los campos de asignación de derechos que permiten compartir una libreta de direcciones con usuarios individuales o grupos enteros. Este diseño de clase padre significa que cada libreta de direcciones participa automáticamente en el modelo de visibilidad multiinquilino de ProjectForge.

Integración con Hibernate Search

El marcador @Indexed, combinado con @FullTextField en title y description, hace que esta entidad sea descubrible a través de Hibernate Search. El HibernateSearchUsersGroupsTypeBinder (referenciado en la fuente pero no mostrado en el contenido resumido) puentea los derechos de usuario/grupo en el índice Lucene para que los resultados de búsqueda respeten las mismas restricciones de visibilidad que las consultas de base de datos — un usuario que busca libretas de direcciones solo verá resultados a los que tenga permiso de acceso.

DisplayNameCapable e integración con la interfaz de usuario

La propiedad displayName devuelve "$title", proporcionando una etiqueta consistente para menús desplegables, migas de pan y entradas de historial. Las anotaciones @PropertyInfo alimentan el sistema de representación automática de formularios de ProjectForge, que genera campos de entrada, mensajes de validación (ej. "El título es obligatorio") y encabezados de columna a partir de las búsquedas de i18nKey.

Semántica de igualdad

La clase define métodos personalizados hashCode() y equals(). Cuando la entidad ha sido persistida (el ID no es nulo), la igualdad se basa en el ID de base de datos — dos instancias de AddressbookDO con el mismo ID se consideran iguales. Cuando el ID es nulo (un objeto transitorio, aún no guardado), la igualdad recurre a la identidad del objeto (===). Este es el patrón estándar recomendado por Hibernate que evita problemas con objetos proxy y colecciones.

Justificación del diseño

¿Por qué extender BaseUserGroupRightsDO?

Las libretas de direcciones son recursos compartidos — un usuario crea una y puede conceder acceso de lectura o escritura a otros usuarios o grupos. La superclase BaseUserGroupRightsDO proporciona un modelo de derechos uniforme (propietario + concesiones por usuario + concesiones por grupo) que se reutiliza en muchos tipos de entidades de ProjectForge (libretas de direcciones, calendarios, listas de tareas, etc.). Esto evita duplicar el mismo esquema de control de acceso en cada entidad y garantiza un comportamiento consistente en las capas DAO y de interfaz de usuario.

¿Por qué cargar ansiosamente owner?

Las libretas de direcciones casi siempre se muestran con el nombre de su propietario. Si owner se cargara perezosamente, cada página de lista provocaría N+1 consultas adicionales. La carga ansiosa es una compensación de rendimiento deliberada: añade un JOIN a cada consulta de libreta de direcciones pero elimina el problema N+1 en el caso común. La anotación @JsonSerialize(using = IdOnlySerializer::class) asegura que cuando la entidad se serializa a JSON (ej. para APIs REST), solo se emite el ID numérico del propietario, evitando la serialización profunda del grafo de objetos y referencias circulares.

¿Por qué la indexación de Hibernate Search?

ProjectForge proporciona una función de búsqueda global que abarca múltiples tipos de entidades. Al anotar AddressbookDO con @Indexed y @FullTextField, el índice Lucene se mantiene sincronizado con la base de datos mediante la indexación automática de Hibernate Search al guardar/actualizar/eliminar. El HibernateSearchUsersGroupsTypeBinder asegura además que los metadatos de control de acceso se incrusten en el índice de búsqueda, de modo que el mismo usuario que no puede ver una libreta de direcciones en una vista de lista tampoco pueda encontrarla mediante búsqueda de texto completo — una propiedad de seguridad crítica.

¿Por qué implementar DisplayNameCapable?

Esta interfaz (que proporciona displayName: String) es una convención de ProjectForge utilizada por el registro de auditoría/historial, las migas de pan de la interfaz de usuario y los menús desplegables de selección. Al implementarla, AddressbookDO se conecta a estos subsistemas sin que cada consumidor necesite saber que el nombre para mostrar es simplemente el campo title.

¿Por qué Constants.LENGTH_TITLE en lugar de longitudes codificadas?

ProjectForge utiliza una clase Constants compartida para definir longitudes de columna estándar. Esto asegura que todas las entidades que utilizan campos "title" o "description" tengan tamaños de columna de base de datos consistentes, simplificando la gestión del esquema y evitando errores sutiles donde el título de una entidad tiene 255 caracteres pero el de otra tiene 1000.
