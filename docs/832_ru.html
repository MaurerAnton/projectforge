Краткое описание: AddressbookDO представляет именованную коллекцию адресов — адресную книгу, принадлежащую пользователю или группе. Расширяет BaseUserGroupRightsDO для наследования модели владения и прав доступа групп, реализует DisplayNameCapable для единообразных меток в интерфейсе и содержит аннотации Hibernate Search (@Indexed, @FullTextField), чтобы адресные книги можно было найти через полнотекстовый поиск приложения. Поля аннотированы @PropertyInfo для автоматической генерации форм в пользовательском интерфейсе.

Архитектура и место в системе

Иерархия классов

BaseDO
 └─ DefaultBaseDO
     └─ BaseUserGroupRightsDO        ← предоставляет поля владельца, прав пользователей и прав групп
         └─ AddressbookDO             ← этот класс
             также реализует DisplayNameCapable

BaseUserGroupRightsDO — критически важный родительский класс: он добавляет столбцы для owner (ссылка на PFUserDO), а также поля назначения прав, позволяющие делиться адресной книгой с отдельными пользователями или целыми группами. Такая конструкция родительского класса означает, что каждая адресная книга автоматически участвует в многопользовательской модели видимости ProjectForge.

Унаследованные поля (из BaseUserGroupRightsDO)

Эти поля определены в родительском классе и наследуются автоматически; они не объявляются повторно в AddressbookDO, но присутствуют в таблице базы данных:

  • owner — фактически переопределено здесь (см. выше)
  • Коллекция прав пользователей: какие отдельные пользователи имеют доступ на чтение/запись
  • Коллекция прав групп: какие группы имеют доступ на чтение/запись
  • Стандартные поля BaseDO: id, created, lastUpdate, deleted

Интеграция с Hibernate Search

Маркер @Indexed в сочетании с @FullTextField на title и description делает эту сущность доступной для поиска через Hibernate Search. HibernateSearchUsersGroupsTypeBinder (упоминается в исходном коде, но не показан в сокращённом содержании) связывает права пользователей/групп с индексом Lucene, чтобы результаты поиска соблюдали те же ограничения видимости, что и запросы к базе данных — пользователь, ищущий адресные книги, увидит только те, к которым у него есть доступ.

DisplayNameCapable и интеграция с интерфейсом

Свойство displayName возвращает "$title", обеспечивая единообразную метку для выпадающих списков, навигационных цепочек и записей истории. Аннотации @PropertyInfo используются системой автоматического рендеринга форм ProjectForge, которая генерирует поля ввода, сообщения валидации (например, "Название обязательно") и заголовки столбцов на основе поиска по i18nKey.

Семантика равенства

Класс определяет пользовательские методы hashCode() и equals(). Когда сущность была сохранена (ID не равен null), равенство основывается на ID в базе данных — два экземпляра AddressbookDO с одинаковым ID считаются равными. Когда ID равен null (транзиентный, ещё не сохранённый объект), равенство сводится к идентичности объекта (===). Это стандартный рекомендуемый Hibernate шаблон, который позволяет избежать проблем с прокси-объектами и коллекциями.

Обоснование дизайна

Почему расширение BaseUserGroupRightsDO?

Адресные книги — это общие ресурсы: пользователь создаёт книгу и может предоставить доступ на чтение или запись другим пользователям или группам. Суперкласс BaseUserGroupRightsDO предоставляет единообразную модель прав (владелец + права для отдельных пользователей + права для групп), которая используется во многих типах сущностей ProjectForge (адресные книги, календари, списки задач и т.д.). Это позволяет избежать дублирования одной и той же схемы контроля доступа в каждой сущности и обеспечивает согласованное поведение в слоях DAO и пользовательского интерфейса.

Почему немедленная загрузка owner?

Адресные книги почти всегда отображаются с именем их владельца. Если бы owner загружался лениво, каждая страница со списком вызывала бы N+1 дополнительных запросов. Немедленная загрузка — это осознанный компромисс производительности: она добавляет JOIN к каждому запросу адресной книги, но устраняет проблему N+1 в типичном случае. Аннотация @JsonSerialize(using = IdOnlySerializer::class) гарантирует, что при сериализации сущности в JSON (например, для REST API) будет передан только числовой ID владельца, предотвращая глубокую сериализацию графа объектов и циклические ссылки.

Почему индексация Hibernate Search?

ProjectForge предоставляет глобальный поиск, охватывающий несколько типов сущностей. Аннотируя AddressbookDO с помощью @Indexed и @FullTextField, индекс Lucene синхронизируется с базой данных через автоматическую индексацию Hibernate Search при сохранении/обновлении/удалении. HibernateSearchUsersGroupsTypeBinder дополнительно гарантирует, что метаданные контроля доступа встраиваются в поисковый индекс, поэтому пользователь, который не видит адресную книгу в списке, не сможет найти её и через полнотекстовый поиск — это критически важное свойство безопасности.

Почему реализация DisplayNameCapable?

Этот интерфейс (предоставляющий displayName: String) является соглашением ProjectForge, используемым для журналирования истории/аудита, навигационных цепочек в интерфейсе и выпадающих списков выбора. Реализуя его, AddressbookDO подключается к этим подсистемам без необходимости каждому потребителю знать, что отображаемое имя — это просто поле title.

Почему Constants.LENGTH_TITLE вместо жёстко заданных длин?

ProjectForge использует общий класс Constants для определения стандартных длин столбцов. Это гарантирует, что все сущности, использующие поля "title" или "description", имеют согласованные размеры столбцов базы данных, упрощая управление схемой и предотвращая тонкие ошибки, когда заголовок одной сущности составляет 255 символов, а другой — 1000.
