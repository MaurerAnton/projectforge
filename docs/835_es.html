#835: BirthdayCache.kt

projectforge-business/src/main/kotlin/org/projectforge/business/address/BirthdayCache.kt Clase de caché Kotlin — índice en caché de todos los cumpleaños de la libreta de direcciones para consultas rápidas por rango de fechas. Extiende AbstractCache para actualización automática basada en TTL. Ubicación: projectforge-business/src/main/kotlin/org/projectforge/business/address/BirthdayCache.kt 124 líneas · 81 código · 33 comentarios · 10 en blanco
Propósito: El panel de control del calendario y el sistema de notificación de cumpleaños necesitan responder eficientemente a "¿de quién es el cumpleaños esta semana/este mes?". Sin una caché, cada consulta escanearía toda la tabla de direcciones. BirthdayCache carga en memoria todas las direcciones no eliminadas con fecha de cumpleaños una vez y realiza el filtrado por rango de fechas en memoria, logrando un costo de consulta O(1) después de la carga inicial.

Arquitectura

Cadena de herencia

BirthdayCache extiende AbstractCache (de org.projectforge.framework.cache), la clase base de ProjectForge para cachés basadas en TTL. Esto le proporciona:
• checkRefresh() — llama automáticamente a refresh() si el TTL ha expirado
• setExpireInMinutes() — TTL configurable
• Registro seguro para subprocesos en PfCaches (#820)
• Participación en SystemService.refreshCaches() actualización masiva

Protector de singleton

La caché utiliza un objeto companion con una lateinit var instance y un protector instanceCounter. Si Spring (o el código de prueba) crea una segunda instancia, se registra una advertencia. Esto evita que la clase base AbstractCache registre dos veces la caché en PfCaches, lo que provocaría llamadas de actualización duplicadas.

Modelo de datos

La caché almacena un MutableList<BirthdayAddress> donde cada BirthdayAddress envuelve un AddressDO e implementa Comparable. La comparación ordena primero por mes/día de cumpleaños, luego por nombre, lo que permite que el TreeSet utilizado en getBirthdays() produzca resultados ordenados naturalmente sin llamadas de ordenación explícitas.

Algoritmo de consulta

getBirthdays(fromDate, toDate, all, favorites) filtra la lista en caché con cuatro condiciones de guarda aplicadas en este orden de prioridad para mayor eficiencia:

1. Control de acceso (addressDao.hasLoggedInUserSelectAccess): Omite las direcciones que el usuario actual no puede ver. Esto es esencial porque la caché carga TODAS las direcciones (usando checkAccess = false en la consulta DAO).
2. Filtro de favoritos (!all && !favorites.contains(address.id)): Si no está en modo "todos", solo se incluyen las direcciones en la lista de favoritos del usuario.
3. Disponibilidad de cumpleaños: Omite direcciones donde PFDateTime.fromOrNull(address.birthday) devuelve null.
4. Verificación de rango de fechas (DateHelper.dateOfYearBetween): Compara mes/día (ignorando el año) con el rango. Esto maneja rangos que abarcan años (ej., 15 dic — 15 ene).

Los resultados se recopilan en un TreeSet<BirthdayAddress> para ordenación automática.

Lógica de actualización

refresh() se ejecuta dentro de persistenceService.runIsolatedReadOnly { } — un contexto de transacción dedicado separado de cualquier transacción de solicitud HTTP activa. Este aislamiento evita:
• Contención con sesiones de Hibernate de ámbito de solicitud
• Problemas de carga diferida (todos los datos se obtienen de manera ansiosa)
• Fenómenos de lectura de escrituras no confirmadas en la transacción de solicitud

La consulta utiliza QueryFilter.isNotNull("birthday") para excluir direcciones sin fecha de cumpleaños (que son la mayoría). El filtro deleted = false asegura que las direcciones eliminadas de forma suave sean excluidas.

Una verificación defensiva adicional (if (it.deleted != true)) protege contra entidades donde el filtro JPA podría no haberse aplicado (ej., durante la migración o si la configuración del filtro cambia).

Explicación de confirmaciones clave

615c248f4 (más antigua) — Corrección de rendimiento: La caché se creó para resolver un problema crítico de rendimiento. PersonalAddressDao.getList tardaba segundos en ejecutarse, y mostrar cumpleaños en la vista del calendario causaba latencia notable. La caché eliminó el escaneo de la tabla de direcciones por solicitud.

0ceceb28f — Transacciones aisladas: Las operaciones de actualización se movieron de la transacción de solicitud a runIsolatedReadOnly. Esto solucionó una clase de errores donde una actualización de larga duración dentro de una transacción de solicitud podía causar tiempos de espera de la sesión de Hibernate o problemas de visibilidad de datos obsoletos.

4c04cfd65 — Migración int→Long: Todos los tipos de ID cambiaron de Integer a Long, afectando al parámetro favorites: List<Long> y a las comparaciones de address.id en toda la lógica de filtrado.

cf80afb28 — Eliminación de tenencia: La función multiinquilino se eliminó, simplificando la caché (no se necesita aislamiento de inquilino).

bfa336a64 — Corrección de usuario eliminado: Se agregó la verificación explícita para el cumpleaños de usuarios eliminados, asegurando que no aparezcan en los widgets del panel de control.

El escaneo lineal es aceptable porque la caché solo contiene direcciones con cumpleaños (no la libreta de direcciones completa), y el filtrado de acceso/favoritos evita costosas búsquedas en BD por entrada al trabajar completamente en memoria con datos de seguridad precargados.
Advertencia — Omisión de control de acceso en actualización: La consulta de actualización utiliza checkAccess = false para cargar TODAS las direcciones. El control de acceso se aplica más tarde en getBirthdays() por consulta. Esto significa que la caché en sí contiene datos que el usuario actual podría no tener permiso para ver. Cada llamada a getBirthdays() reevalúa el acceso basado en el usuario actual que ha iniciado sesión, haciendo que la caché sea independiente del usuario en el momento del almacenamiento, pero consciente del usuario en el momento de la consulta. Si se revoca el acceso de un usuario, la próxima consulta de cumpleaños (no la próxima actualización de la caché) excluirá sus entradas.
