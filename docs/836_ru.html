Этот фильтр позволяет интерфейсу списка адресов отображать представление «Только дублеты», помогая администраторам находить и объединять дубликаты.

Архитектура

Реализует CustomResultFilter<AddressDO> — интерфейс фреймворка ProjectForge для пост-запросной фильтрации результатов. В отличие от фильтрации на стороне базы данных (условия WHERE), фильтры результатов работают в памяти над набором результатов, возвращенных DAO. Это необходимо для дедупликации, потому что:

• Дубликаты могут находиться в разных строках базы данных с разными ID
• Логика нормализации (getNormalizedFullname) включает манипуляции со строками, которые сложно выразить в SQL/HQL
• Фильтру требуется накапливать состояние между несколькими элементами — метод match() вызывается для каждого элемента по порядку, но изменяет внутренние множества

Конечный автомат

Фильтр работает как конечный автомат с двумя множествами и двумя проходами:

Проход 1 (накопление): Когда каждый элемент адреса передается в match():
• Если нормализованное полное имя уже есть в fullnames, это дублет — добавляется в doubletFullnames
• Если его нет в fullnames, это первое вхождение — добавляется в all и fullnames

Проход 2 (сброс): Когда обнаружен дублет, все ранее просмотренные адреса, чьи имена совпадают с любым именем дублета, добавляются в результирующий список. Множество addedDoublets предотвращает добавление одного и того же адреса дважды.

Обоснование дизайна

Почему пост-фильтр, а не GROUP BY + HAVING в базе данных? SQL GROUP BY normalized_name HAVING COUNT(*) > 1 потребовал бы, чтобы функция нормализации была выразима в SQL (возможно, но хрупко из-за различий в диалектах SQL) и не предоставил бы точные объекты сущностей, необходимые для диалога слияния в интерфейсе. Подход с пост-фильтром сохраняет логику нормализации в Java/Kotlin, где она типизирована, тестируема и согласована с остальной частью приложения.

Почему шаблон ретроактивного сброса? Интерфейс match() возвращает true/false для каждого элемента (включить/исключить из результатов). Элементы, обработанные до обнаружения дублета, уже были исключены (возвращали false). Ретроактивный сброс вставляет эти более ранние экземпляры, напрямую изменяя результирующий список. Это преднамеренный побочный эффект — фильтр имеет доступ на запись к списку и использует его для компенсации потоковой природы API match().
