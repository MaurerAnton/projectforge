Zusammenfassung: BookType ist eine einfache Aufzählung der Medientypen, die von der Buchverwaltungsfunktion von ProjectForge unterstützt werden. Es implementiert I18nEnum, sodass die Bezeichnung jedes Werts (z. B. „Hörbuch“, „E-Book“, „Zeitschrift“) lokalisiert werden kann. Das Enum deckt sowohl traditionelle bibliografische Kategorien (Buch, These) als auch moderne digitale Medien (E-Book, Software, Film) ab.

Architektur

Das Enum wird als Eigenschaftstyp für die Entität BookDO (das Domänenobjekt für bibliografische Einträge) verwendet. Da es I18nEnum implementiert, kann die UI-Ebene BookType.BOOK.i18nKey aufrufen, um den Eigenschaftsschlüssel "book.type.book" zu erhalten und die lokalisierte Zeichenfolge nachzuschlagen (z. B. „Buch“ auf Deutsch, „Book“ auf Englisch). Dadurch bleibt die Anzeigelogik außerhalb des Enums selbst.

Der Konstruktorparameter key dient zwei Zwecken: Er bildet das rechteste Segment des i18n-Schlüssels und kann als datenbanksicherer gespeicherter Wert verwendet werden (z. B. "ebook" anstelle von "EBOOK"). Die Konvention, einen Kleinbuchstaben-Schlüssel an den i18n-Eigenschaftspfad zu übergeben, vermeidet Groß-/Kleinschreibungsprobleme in verschiedenen Front-End-Frameworks.

Beziehung zu I18nEnum

I18nEnum ist ein ProjectForge-Interface, das eine einzelne Eigenschaft erfordert: val i18nKey: String. Jedes Enum, das es implementiert, kann in der UI dargestellt werden, indem der zurückgegebene Schlüssel in den Ressourcenbündeln der Anwendung nachgeschlagen wird. Dieses Muster vermeidet das Hartcodieren von Anzeigezeichenfolgen in Enum-Konstanten und ermöglicht mehrsprachige Unterstützung, ohne den Kotlin-Quellcode zu ändern.

Design-Grund

Warum ein Enum anstelle einer Datenbank-Nachschlagetabelle?

Buchtypen sind eine kleine, stabile, geschlossene Menge. Ein Enum bietet Typsicherheit zur Kompilierzeit, vermeidet einen Join bei der Abfrage und eliminiert die Notwendigkeit einer separaten Verwaltungsoberfläche zur Kategorienverwaltung. Der Nachteil ist, dass das Hinzufügen eines neuen Typs eine Codeänderung und eine erneute Bereitstellung erfordert – akzeptabel für eine Domäne, in der neue Medienkategorien selten sind.

Warum Nicht-Buch-Artikel wie FILM und SOFTWARE einschließen?

Das Buchmodul von ProjectForge ist eigentlich ein allgemeiner bibliografischer/Medienkatalog. Der Name „Buch“ ist eine Vereinfachung für das benutzerseitige Modul-Label; intern verfolgt das System eine breitere Palette von Medien. Die erweiterten Enum-Werte spiegeln die tatsächlichen Anwendungsfälle der Benutzerbasis wider (wahrscheinlich eine Organisation, die verschiedene Referenzmaterialien verwaltet).

Warum I18nEnum anstelle der direkten Speicherung von Anzeigenamen?

Das Hartcodieren von Anzeigezeichenfolgen in Kotlin-Enums würde mehrsprachige Unterstützung unmöglich machen, ohne das Enum für jedes Gebietsschema zu duplizieren. Das I18nEnum-Muster entkoppelt die symbolische Konstante (EBOOK) von ihrer menschenlesbaren Bezeichnung und ermöglicht es Übersetzern, lokalisierte Werte in Ressourcenbündel-Eigenschaftendateien bereitzustellen.
