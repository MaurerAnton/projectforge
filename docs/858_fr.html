Résumé : BookType est une énumération simple des types de supports pris en charge par la fonctionnalité de gestion des livres de ProjectForge. Elle implémente I18nEnum afin que l'étiquette de chaque valeur (p. ex. « Livre audio », « Livre numérique », « Magazine ») puisse être localisée. L'énumération couvre à la fois les catégories bibliographiques traditionnelles (livre, thèse) et les supports numériques modernes (livre numérique, logiciel, film).

Architecture

L'énumération est utilisée comme type de propriété sur l'entité BookDO (l'objet domaine pour les entrées bibliographiques). Comme elle implémente I18nEnum, la couche d'interface utilisateur peut appeler BookType.BOOK.i18nKey pour obtenir la clé de propriété "book.type.book" et rechercher la chaîne localisée (par exemple « Buch » en allemand, « Book » en anglais). Cela évite d'intégrer la logique d'affichage dans l'énumération elle-même.

Le paramètre constructeur key a un double objectif : il constitue le segment le plus à droite de la clé i18n et peut être utilisé comme valeur stockée compatible avec la base de données (par exemple "ebook" plutôt que "EBOOK"). La convention consistant à passer une clé en minuscules au chemin de propriété i18n évite les problèmes de casse dans différents frameworks front-end.

Relation avec I18nEnum

I18nEnum est une interface de ProjectForge qui nécessite une seule propriété : val i18nKey: String. Toute énumération l'implémentant peut être rendue dans l'interface utilisateur en recherchant la clé retournée dans les bundles de ressources de l'application. Ce modèle évite de coder en dur les chaînes d'affichage dans les constantes d'énumération et permet la prise en charge multilingue sans modifier le code source Kotlin.

Justification de la conception

Pourquoi une énumération plutôt qu'une table de recherche en base de données ?

Les types de livres constituent un ensemble petit, stable et fermé. Une énumération offre une sécurité de type à la compilation, évite une jointure lors des requêtes et élimine le besoin d'une interface d'administration séparée pour gérer les catégories. La contrepartie est que l'ajout d'un nouveau type nécessite une modification du code et un redéploiement — acceptable pour un domaine où les nouvelles catégories de supports sont rares.

Pourquoi inclure des éléments non livresques comme FILM et SOFTWARE ?

Le module livre de ProjectForge est en réalité un catalogue bibliographique/média général. Le nom « livre » est une simplification pour l'étiquette du module côté utilisateur ; en interne, le système suit une gamme plus large de supports. Les valeurs étendues de l'énumération reflètent les cas d'utilisation réels de la base d'utilisateurs (probablement une organisation qui gère divers matériels de référence).

Pourquoi I18nEnum plutôt que de stocker directement les noms d'affichage ?

Coder en dur les chaînes d'affichage dans les énumérations Kotlin rendrait la prise en charge multilingue impossible sans dupliquer l'énumération pour chaque locale. Le modèle I18nEnum dissocie la constante symbolique (EBOOK) de son étiquette lisible par l'humain, permettant aux traducteurs de fournir des valeurs localisées dans des fichiers de propriétés de bundles de ressources.
