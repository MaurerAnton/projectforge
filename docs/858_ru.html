Расположение: projectforge-business/src/main/kotlin/org/projectforge/business/book/BookType.kt 51 строка · 18 кода · 29 комментариев · 4 пустых
Краткое описание: BookType — это простая перечислимая константа типов медиа, поддерживаемых функцией управления книгами ProjectForge. Она реализует I18nEnum, чтобы метка каждого значения (например, «Аудиокнига», «Электронная книга», «Журнал») могла быть локализована. Перечисление охватывает как традиционные библиографические категории (книга, диссертация), так и современные цифровые носители (электронная книга, программное обеспечение, фильм).

Архитектура

Перечисление используется как тип свойства в сущности BookDO (объект домена для библиографических записей). Поскольку оно реализует I18nEnum, уровень пользовательского интерфейса может вызвать BookType.BOOK.i18nKey для получения ключа свойства "book.type.book" и поиска локализованной строки (например, «Книга» на русском, «Book» на английском). Это позволяет вынести логику отображения из самого перечисления.

Параметр конструктора key выполняет двойную функцию: он образует крайний правый сегмент ключа i18n и может использоваться как безопасное для базы данных хранимое значение (например, "ebook", а не "EBOOK"). Соглашение о передаче ключа в нижнем регистре в путь свойства i18n позволяет избежать проблем с регистром в различных интерфейсных фреймворках.

Связь с I18nEnum

I18nEnum — это интерфейс ProjectForge, который требует одно свойство: val i18nKey: String. Любое перечисление, реализующее его, может быть отображено в пользовательском интерфейсе путем поиска возвращенного ключа в ресурсных пакетах приложения. Этот шаблон позволяет избежать жесткого кодирования строк отображения в константах перечисления и обеспечивает поддержку нескольких языков без изменения исходного кода Kotlin.

Обоснование дизайна

Почему перечисление, а не таблица поиска в базе данных?

Типы книг — это небольшой, стабильный, закрытый набор. Перечисление обеспечивает типобезопасность на этапе компиляции, избегает объединения таблиц во время запроса и устраняет необходимость в отдельном интерфейсе администрирования для управления категориями. Компромисс заключается в том, что добавление нового типа требует изменения кода и повторного развертывания — что приемлемо для области, где новые медиа-категории появляются редко.

Почему включены не книжные элементы, такие как FILM и SOFTWARE?

Модуль книг ProjectForge на самом деле является общим библиографическим/медиа-каталогом. Название «книга» — это упрощение для метки модуля, видимой пользователю; внутренне система отслеживает более широкий спектр носителей. Расширенные значения перечисления отражают реальные случаи использования пользовательской базы (вероятно, организации, которая управляет разнообразными справочными материалами).

Почему I18nEnum вместо прямого хранения отображаемых имен?

Жесткое кодирование строк отображения в перечислениях Kotlin сделало бы поддержку нескольких языков невозможной без дублирования перечисления для каждой локали. Шаблон I18nEnum отделяет символьную константу (EBOOK) от ее читаемой метки, позволяя переводчикам предоставлять локализованные значения в файлах свойств ресурсных пакетов.
