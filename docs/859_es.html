Resumen: CalendarEventColorScheme es un enum mínimo de dos valores que controla cómo se colorean los eventos del calendario en la interfaz de usuario del calendario. STANDARD representa los eventos con la paleta y opacidad predeterminadas de ProjectForge, mientras que CLASSIC elimina los efectos de opacidad para usuarios que necesitan mayor contraste, particularmente aquellos con discapacidades visuales o cuando se utilizan proyectores en salas de reuniones.

Arquitectura

Este enum se referencia desde la configuración de calendario específica del usuario (probablemente las preferencias de PFUserDO o una entidad dedicada de configuración de calendario). El valor seleccionado se persiste como una cadena ("standard" o "classic") y es utilizado por la capa de representación del front-end (componentes Wicket o JavaScript) para determinar la clase CSS o el estilo en línea aplicado a las celdas de eventos del calendario. La implementación de I18nEnum proporciona etiquetas localizadas para la interfaz de configuración donde los usuarios eligen su esquema preferido.

Debido a que solo tiene dos valores, el enum es intencionalmente simple. Extenderlo con más esquemas (p. ej., un modo de alto contraste, una paleta amigable para daltonismo) solo requeriría agregar nuevas constantes; el patrón ya admite expansión.

Justificación del Diseño

¿Por qué solo dos valores?

El esquema CLASSIC se agregó específicamente para abordar un problema de accesibilidad: los rectángulos de eventos parcialmente transparentes pueden ser difíciles de distinguir para usuarios con baja visión o en proyectores con poco contraste. En lugar de construir un motor de temas completo, el equipo optó por un interruptor binario simple. Esto mantiene la interfaz de configuración simple y el código de representación directo: una única rama condicional en el front-end en lugar de un complejo pipeline de mapeo de colores.

¿Por qué un enum en lugar de un booleano isHighContrast: Boolean?

Un enum es compatible con el futuro. Si los requisitos futuros exigen un tercer esquema (por ejemplo, una paleta de modo oscuro o un conjunto de colores amigable para deuteranopía), agregar una nueva constante es un cambio no disruptivo. Un booleano requeriría una migración a un enum más adelante, afectando el esquema de la base de datos, la interfaz de configuración y todos los consumidores. Comenzar con un enum, incluso uno de dos valores, evita este costo de refactorización futuro sin una sobrecarga significativa.

¿Por qué implementar I18nEnum para un conjunto tan pequeño?

Consistencia. Cada enumeración visible para el usuario en ProjectForge implementa I18nEnum para que la interfaz de configuración pueda representar listas desplegables de manera genérica: dado cualquier subclase de I18nEnum, el framework puede iterar sus valores y buscar etiquetas localizadas. Esta uniformidad significa que la página de configuración del calendario no necesita código especial para manejar el selector de esquema de color: utiliza el mismo componente que cualquier otra configuración basada en enum.
