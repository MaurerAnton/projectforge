Кратко: CalendarEventColorScheme — минимальный двухзначный перечень, управляющий окраской событий в интерфейсе календаря. STANDARD отображает события с палитрой и прозрачностью по умолчанию ProjectForge, тогда как CLASSIC убирает эффекты прозрачности для пользователей, которым требуется более высокая контрастность — особенно для людей с нарушениями зрения или при использовании проекторов в переговорных комнатах.

Константа перечисленияКлючСвойство i18nПоведение
STANDARD standard calendar.settings.colors.scheme.standard Стандартная цветопередача с эффектами прозрачности/непрозрачности, заданными темой.

Архитектура

Это перечисление используется в пользовательских настройках календаря (вероятно, в предпочтениях PFUserDO или в отдельной сущности настроек календаря). Выбранное значение сохраняется в виде строки ("standard" или "classic") и используется уровнем отрисовки фронтенда (компоненты Wicket или JavaScript) для определения CSS-класса или встроенного стиля, применяемого к ячейкам событий календаря. Реализация I18nEnum предоставляет локализованные метки для интерфейса настроек, где пользователи выбирают предпочтительную схему.

Поскольку перечисление содержит только два значения, оно намеренно простое. Расширение его дополнительными схемами (например, режимом высокой контрастности, палитрой, удобной для дальтоников) потребует лишь добавления новых констант — шаблон уже поддерживает расширение.

Обоснование дизайна

Почему только два значения?

Схема CLASSIC была добавлена специально для решения проблемы доступности — частично прозрачные прямоугольники событий могут быть трудно различимы для пользователей с ослабленным зрением или на проекторах с низкой контрастностью. Вместо создания полноценного движка тем команда выбрала простой бинарный переключатель. Это сохраняет простоту интерфейса настроек и кода отрисовки: одна условная ветвь во фронтенде вместо сложного конвейера сопоставления цветов.

Почему перечисление, а не булево isHighContrast: Boolean?

Перечисление является перспективно-совместимым. Если в будущем потребуется третья схема (например, палитра тёмной темы или набор цветов, удобный для дейтеранопии), добавление новой константы будет неразрушающим изменением. Булево значение потребовало бы последующей миграции на перечисление, затрагивающей схему базы данных, интерфейс настроек и все потребители. Начало с перечисления — даже двухзначного — позволяет избежать этих будущих затрат на рефакторинг без значительных накладных расходов.

Зачем реализовывать I18nEnum для такого маленького набора?

Согласованность. Каждое видимое пользователю перечисление в ProjectForge реализует I18nEnum, чтобы интерфейс настроек мог универсально отображать выпадающие списки: для любого подкласса I18nEnum фреймворк может перебрать его значения и найти локализованные метки. Эта единообразность означает, что страница настроек календаря не нуждается в специальном коде для обработки выбора цветовой схемы — она использует тот же компонент, что и любая другая настройка на основе перечисления.
