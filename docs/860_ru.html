#860: CalendarFilter.kt

projectforge-business/src/main/kotlin/org/projectforge/business/calendar/CalendarFilter.kt Тип: Класс Kotlin (модель данных)
Назначение: Сохраняемый пользовательский фильтр календаря с настройками видимости, табеля учета времени и отпусков
Путь к исходнику: projectforge-business/src/main/kotlin/org/projectforge/business/calendar/CalendarFilter.kt
Расширяет: AbstractFavorite (предоставляет name: String? и id: Long?) 252 строки · 135 кода · 92 комментария · 25 пустых

CalendarFilter — это основной пользовательский объект конфигурации для календаря ProjectForge. Он расширяет систему избранного, позволяя пользователям создавать именованные профили фильтров, переключаться между ними и сохранять свои настройки. Каждый фильтр управляет тем, какие календари отображаются, какие скрыты, какой календарь используется по умолчанию для новых записей, видимостью табелей учета времени (для конкретного пользователя), записями об отпусках (по группе или пользователю), выделением перерывов и параметрами отображения, такими как размер сетки и первый видимый час дня. Класс также включает глубокое копирование, очистку при сериализации и поддержку миграции из старого календаря на базе Wicket (ProjectForge v6).

Ключевые свойства

calendarIds: MutableSet<Long?>

Все идентификаторы календарей, управляемые этим фильтром (как видимые, так и скрытые). Это основной набор календарей, о которых знает фильтр.

invisibleCalendars: MutableSet<Long?>

Подмножество calendarIds, которые в данный момент скрыты. Календари из calendarIds, отсутствующие в этом наборе, являются видимыми.

Публичные методы

copyFrom(src: CalendarFilter): CalendarFilter

Выполняет глубокое копирование всех полей из src в this, включая копирование всего содержимого коллекций. Возвращает this для плавного цепочечного вызова. Наборы calendarIds и invisibleCalendars перераспределяются и заполняются значениями источника.

addCalendarId(calendarId: Long)

Добавляет календарь в фильтр и делает его видимым (удаляет его из invisibleCalendars, если он там присутствует).

removeCalendarId(calendarId: Long)

Удаляет календарь как из calendarIds, так и из invisibleCalendars.

setVisibility(calendarId: Long?, visible: Boolean)

Переключает видимость для указанного календаря. Если calendarId равен null (возможно при десериализации), вызов игнорируется. Вызывает tidyUp() после изменения.

isInvisible(calendarId: Long?): Boolean

Возвращает true, если календарь равен null или присутствует в invisibleCalendars.

tidyUp()

Удаляет записи из invisibleCalendars, которых нет в основном наборе calendarIds. Поддерживает синхронизацию двух наборов.

afterDeserialization()

Очистка после десериализации. Обрабатывает случай, когда calendarIds или invisibleCalendars могут быть null после десериализации, и удаляет любые ложные значения null из наборов. В конце вызывает tidyUp().

isModified(other: CalendarFilter): Boolean

Сравнивает все поля (name, id, defaultCalendarId, timesheetUserId, gridSize, firstHour, showBreaks, showPlanning, а также все содержимое коллекций) с другим фильтром, чтобы определить, отличается ли какое-либо значение. Использует вспомогательный метод isModified(col1, col2) для сравнения коллекций (проверка взаимного включения ненулевых значений).

Приватные вспомогательные методы

copySet(srcSet: Set<Long?>?): Set<Long>?

Копирует nullable набор, отфильтровывая нулевые записи. Возвращает null, если исходный набор равен null.

isModified(col1, col2)

Сравнивает две nullable коллекции, проверяя, что каждый ненулевой элемент col1 существует в col2 и наоборот.

Объект-компаньон — поддержка устаревшего кода

copyFrom(templateEntry: TemplateEntry?): CalendarFilter

Фабричный метод, который преобразует устаревший TemplateEntry (из старой системы календаря Wicket, ProjectForge ≤v6) в новый CalendarFilter. Сопоставляет свойства, включая идентификаторы календарей, настройки видимости, настройки табеля учета времени и флаги перерывов/планирования. Если в старом шаблоне было включено showTimesheets, пользователь табеля устанавливается на текущего вошедшего в систему пользователя.

Обоснование дизайна

CalendarFilter — это насыщенная данными модель класса, а не традиционный DTO. Он несет бизнес-логику для поддержания согласованности между двумя связанными наборами (calendarIds и invisibleCalendars) через такие методы, как tidyUp() и afterDeserialization(). Аннотации @Suppress("SENSELESS_COMPARISON") признают, что nullable значения Long? в наборах технически возможны после десериализации XML/JSON, и класс защитно очищает их. Расширяя AbstractFavorite, он наследует инфраструктуру именованных избранных (имя + id), позволяя пользователям создавать, именовать и переключаться между несколькими конфигурациями фильтров — ключевая функция UX календаря. Глубокое копирование через copyFrom() (вместо переопределения clone() или класса данных) дает вызывающим сторонам явный контроль над тем, когда происходят копии, избегая непреднамеренного общего изменяемого состояния. Устаревший copyFrom(TemplateEntry) в объекте-компаньоне инкапсулирует всю логику миграции из старого календаря Wicket, сохраняя основной класс чистым и обеспечивая обратную совместимость для существующих пользовательских настроек.
