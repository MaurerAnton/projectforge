Zweck: Migriert Kalenderpräferenzen von ProjectForge v6 (Wicket) zum v7+ Kalendersystem
Quellpfad: projectforge-business/src/main/kotlin/org/projectforge/business/calendar/CalendarLegacyFilter.kt
Dateianmerkung: @file:Suppress("DEPRECATION") 97 Zeilen · 47 Code · 43 Kommentare · 7 leer

CalendarLegacyFilter ist eine einmalige Migrationsklasse, die die alten Wicket-basierten Kalenderfilter-Präferenzen (gespeichert als TeamCalCalendarFilter in t_user_xml_prefs unter dem Schlüssel "TeamCalendarPage.userPrefs") ausliest und in die modernen Kalenderdatenstrukturen umwandelt: CalendarFilterState, Favorites<CalendarFilter>, CalendarStyleMap und einen Standard-CalendarFilter. Dies ermöglicht nahtlose Upgrades von ProjectForge v6 auf v7+, ohne dass Benutzer ihre Kalendereinstellungen verlieren.

Konstruktor

Die Klasse hält alle migrierten Daten als Konstruktor-Eigenschaften:

EigenschaftTypBeschreibung

Begleitobjekt — Migrationseinstiegspunkt

migrate(userXmlPreferenceService: UserXmlPreferencesService): CalendarLegacyFilter?

Der primäre Einstiegspunkt. Schritte:

  1. Ruft den alten TeamCalCalendarFilter aus dem userXmlPreferenceService mit dem Schlüssel "TeamCalendarPage.userPrefs" ab.
  2. Wenn kein alter Filter existiert, wird null zurückgegeben (keine Migration erforderlich).
  3. Erstellt einen neuen CalendarFilterState und setzt startDate (konvertiert vom alten Date über PFDateCompatibilityUtils) und view (konvertiert vom alten ViewType).
  4. Erstellt eine CalendarStyleMap und befüllt sie mit Hintergrundfarben aus den alten CalendarProperty-Einträgen jeder Vorlage.
  5. Erstellt den aktiven Filter durch Kopieren des alten activeTemplateEntry über CalendarFilter.copyFrom().
  6. Iteriert über alle alten templateEntries, konvertiert jeden in einen CalendarFilter und fügt sie zur Favoritenliste hinzu.
  7. Ermittelt die ID des aktiven Filters aus der Favoritenliste durch Namensabgleich.
  8. Gibt einen CalendarLegacyFilter zurück, der alle vier migrierten Komponenten enthält.

Design-Grundlage

Die Migrationslogik ist bewusst in einer separaten Klasse isoliert und nicht in CalendarFilter oder der Kalenderdienstschicht eingebettet. Dies hält das Kern-Datenmodell frei von Legacy-Abhängigkeiten und ermöglicht es, die Migrationsklasse selbst in einer zukünftigen Version zu löschen, sobald alle Benutzer aktualisiert wurden. Die Unterdrückung @file:Suppress("DEPRECATION") ist notwendig, da der Code absichtlich auf veraltete Typen verweist (TeamCalCalendarFilter, ViewType, TemplateEntry) — dies sind genau die Typen, von denen migriert wird. Die Klasse referenziert sowohl den alten XStream-Persistenzschlüssel (OLD_USERPREF_KEY) als auch die Legacy-Datumsdienstprogramme (PFDateCompatibilityUtils) und kapselt so das gesamte Legacy-Wissen an einem Ort.
