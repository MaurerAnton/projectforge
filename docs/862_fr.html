#862: CalendarLegacyFilter.kt

projectforge-business/src/main/kotlin/org/projectforge/business/calendar/CalendarLegacyFilter.kt Type : Classe Kotlin (utilitaire de migration)
Objectif : Migre les préférences de calendrier de ProjectForge v6 (Wicket) vers le système de calendrier v7+
Chemin source : projectforge-business/src/main/kotlin/org/projectforge/business/calendar/CalendarLegacyFilter.kt
Annotation du fichier : @file:Suppress("DEPRECATION") 97 lignes · 47 code · 43 commentaires · 7 vides

CalendarLegacyFilter est une classe de migration unique qui lit les anciennes préférences de filtre de calendrier basées sur Wicket (stockées sous forme de TeamCalCalendarFilter dans t_user_xml_prefs avec la clé "TeamCalendarPage.userPrefs") et les convertit dans les structures de données modernes du calendrier : CalendarFilterState, Favorites<CalendarFilter>, CalendarStyleMap et un CalendarFilter par défaut. Cela permet des mises à niveau transparentes de ProjectForge v6 vers v7+ sans que les utilisateurs perdent leurs paramètres de calendrier.

Constructeur

La classe contient toutes les données migrées en tant que propriétés du constructeur :

PropriétéTypeDescription
stateCalendarFilterStateLe dernier état d'affichage de l'utilisateur (plage de dates et type d'affichage).
listFavorites<CalendarFilter>La liste migrée des filtres de calendrier nommés (favoris).
currentCalendarFilterLe filtre actuellement actif après la migration (dérivé de l'ancien modèle actif).
styleMapCalendarStyleMapStyles de couleur/affichage pour chaque calendrier, déduits des anciennes entrées de modèle.

Objet compagnon — Point d'entrée de la migration

migrate(userXmlPreferenceService: UserXmlPreferencesService): CalendarLegacyFilter?

Le point d'entrée principal. Étapes :

  1. Récupère l'ancien TeamCalCalendarFilter depuis userXmlPreferenceService en utilisant la clé "TeamCalendarPage.userPrefs".
  2. Si aucun ancien filtre n'existe, retourne null (aucune migration nécessaire).
  3. Crée un nouveau CalendarFilterState et définit startDate (converti depuis l'ancien Date via PFDateCompatibilityUtils) et view (converti depuis l'ancien ViewType).
  4. Crée un CalendarStyleMap, en l'initialisant avec les couleurs d'arrière-plan des anciennes entrées CalendarProperty de chaque modèle.
  5. Crée le filtre actif en copiant l'ancien activeTemplateEntry via CalendarFilter.copyFrom().
  6. Parcourt toutes les anciennes templateEntries, convertit chacune en CalendarFilter et les ajoute à la liste des favoris.
  7. Résout l'ID du filtre actif à partir de la liste des favoris en faisant correspondre le nom.
  8. Retourne un CalendarLegacyFilter contenant les quatre composants migrés.

convert(oldViewType: ViewType?): CalendarView?

Correspondance privée entre l'ancienne énumération ViewType et la nouvelle énumération CalendarView :

Ancien ViewTypeNouveau CalendarView
AGENDA_WEEKCalendarView.WEEK
BASIC_WEEKCalendarView.WEEK
AGENDA_DAYCalendarView.DAY
BASIC_DAYCalendarView.DAY
tout autreCalendarView.MONTH

Justification de la conception

La logique de migration est intentionnellement isolée dans une classe séparée plutôt que d'être intégrée dans CalendarFilter ou la couche de service du calendrier. Cela permet de garder le modèle de données principal propre de toute dépendance héritée et permet de supprimer la classe de migration elle-même dans une future version une fois que tous les utilisateurs auront été mis à niveau. La suppression @file:Suppress("DEPRECATION") est nécessaire car le code fait intentionnellement référence à des types dépréciés (TeamCalCalendarFilter, ViewType, TemplateEntry) — ce sont exactement les types à partir desquels la migration est effectuée. La classe fait référence à la fois à l'ancienne clé de persistance XStream (OLD_USERPREF_KEY) et aux utilitaires de date hérités (PFDateCompatibilityUtils), encapsulant ainsi toutes les connaissances héritées en un seul endroit.
