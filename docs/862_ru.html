projectforge-business/src/main/kotlin/org/projectforge/business/calendar/CalendarLegacyFilter.kt Тип: Класс Kotlin (утилита миграции)
Назначение: Переносит настройки календаря из ProjectForge v6 (Wicket) в систему календаря v7+
Путь к исходнику: projectforge-business/src/main/kotlin/org/projectforge/business/calendar/CalendarLegacyFilter.kt
Аннотация файла: @file:Suppress("DEPRECATION") 97 строк · 47 кода · 43 комментария · 7 пустых

CalendarLegacyFilter — это одноразовый класс миграции, который читает старые настройки фильтра календаря на основе Wicket (сохранённые как TeamCalCalendarFilter в t_user_xml_prefs по ключу "TeamCalendarPage.userPrefs") и преобразует их в современные структуры данных календаря: CalendarFilterState, Favorites<CalendarFilter>, CalendarStyleMap и стандартный CalendarFilter. Это обеспечивает плавное обновление с ProjectForge v6 до v7+ без потери пользователями своих настроек календаря.

Конструктор

Класс хранит все перенесённые данные как свойства конструктора:

СвойствоТипОписание
stateCalendarFilterStateПоследнее состояние просмотра пользователя (диапазон дат и тип просмотра).
listFavorites<CalendarFilter>Перенесённый список именованных фильтров календаря (избранное).
currentCalendarFilterТекущий активный фильтр после миграции (получен из старого активного шаблона).

Объект-компаньон — Точка входа миграции

migrate(userXmlPreferenceService: UserXmlPreferencesService): CalendarLegacyFilter?

Основная точка входа. Шаги:

  1. Извлекает старый TeamCalCalendarFilter из userXmlPreferenceService, используя ключ "TeamCalendarPage.userPrefs".
  2. Если старый фильтр не найден, возвращает null (миграция не требуется).
  3. Создаёт новый CalendarFilterState и устанавливает startDate (преобразованный из старого Date через PFDateCompatibilityUtils) и view (преобразованный из старого ViewType).
  4. Создаёт CalendarStyleMap, заполняя его цветами фона из старых записей CalendarProperty каждого шаблона.
  5. Создаёт активный фильтр, копируя старый activeTemplateEntry через CalendarFilter.copyFrom().
  6. Перебирает все старые templateEntries, преобразуя каждый в CalendarFilter и добавляя их в список избранного.
  7. Определяет ID активного фильтра из списка избранного, сопоставляя по имени.
  8. Возвращает CalendarLegacyFilter, содержащий все четыре перенесённых компонента.

convert(oldViewType: ViewType?): CalendarView?

Обоснование дизайна

Логика миграции намеренно вынесена в отдельный класс, а не встроена в CalendarFilter или слой сервисов календаря. Это сохраняет чистоту основной модели данных от устаревших зависимостей и позволяет удалить сам класс миграции в одном из будущих релизов, как только все пользователи будут обновлены. Подавление @file:Suppress("DEPRECATION") необходимо, поскольку код намеренно ссылается на устаревшие типы (TeamCalCalendarFilter, ViewType, TemplateEntry) — это именно те типы, из которых производится миграция. Класс ссылается как на старый ключ персистентности XStream (OLD_USERPREF_KEY), так и на устаревшие утилиты для работы с датами (PFDateCompatibilityUtils), инкапсулируя все устаревшие знания в одном месте.
