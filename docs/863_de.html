#863: CalendarStyle.kt

projectforge-business/src/main/kotlin/org/projectforge/business/calendar/CalendarStyle.kt Typ: Kotlin-Klasse (Hilfsprogramm für Styling)
Zweck: Berechnet Hintergrund- und Textfarben für Kalenderereignisse basierend auf einer konfigurierbaren Grundfarbe
Quellpfad: projectforge-business/src/main/kotlin/org/projectforge/business/calendar/CalendarStyle.kt 161 Zeilen · 103 Code · 38 Kommentare · 20 leer

CalendarStyle nimmt eine Grund-Hintergrundfarbe (Hex-String) entgegen, berechnet eine passende Textfarbe und leitet eine halbtransparente Hintergrundvariante für die Darstellung von Kalenderereignissen ab. Die Textfarbe wird serverseitig mittels HSB-Farbraum-Manipulation berechnet, um einen ausreichenden Kontrast sicherzustellen. Ergebnisse werden in einem ColorCache (erweitert AbstractCache mit 1-Stunde-Ablauf) zwischengespeichert, um wiederholte Berechnungen derselben Konvertierungen zu vermeiden. Zwei Farbschemata werden unterstützt: der Standardmodus (modern) mit HSB-abgeleiteten Farben und ein CLASSIC-Modus, der das ursprüngliche v6-Verhalten (schwarz auf weiß oder weiß auf dunkel) beibehält.

Konstruktor

ParameterTypStandardBeschreibung

Eigenschaften

bgColor: String

Die Grund-Hintergrundfarbe. Wird aus dem Konstruktorparameter initialisiert, mit Rückfall auf "#777" (ein neutrales Grau). Dies wird als kanonischer Hex-Wert gespeichert und sollte nicht direkt für die Darstellung verwendet werden — verwenden Sie stattdessen getBackgroundColor().

Öffentliche Methoden

getTextColor(colorScheme: CalendarEventColorScheme?): String

Gibt die berechnete Textfarbe für das angegebene Farbschema zurück. Delegiert an colorCache.getTextColor(bgColor, colorScheme).

getBackgroundColor(calendarEventColorScheme: CalendarEventColorScheme?): String

Gibt die für das Farbschema angepasste Hintergrundfarbe zurück:

  • CLASSIC-Modus: Gibt bgColor unverändert zurück (undurchsichtig).
  • Moderner Modus (Standard): Fügt Alpha-Transparenz hinzu — "3" für kurzes Hex ("#7773" → ~20% Deckkraft) oder "33" für volles Hex ("#77777733" → ~20% Deckkraft). Dies erzeugt durchscheinende Kalenderereignisse, die mit dem Hintergrund verschmelzen.

Begleitobjekt — Farbberechnungs-Engine

Interne Klasse RGB(r: Int, g: Int, b: Int)

Einfache Datenklasse, die RGB-Kanalwerte (0–255) hält.

Interne Klasse ColorCache : AbstractCache()

Cache mit 1-Stunde-TTL, der berechnete Textfarben, gespeichert nach Hex-String, zwischenspeichert und redundante HSB-Konvertierungen vermeidet. Unterhält separate Maps für das Standard- und das klassische Farbschema. Thread-sicher durch synchronized-Blöcke auf der pro-Schema-Map.

Details zum Farbalgorithmus

Für das moderne Schema wird die Textfarbe wie folgt berechnet:

  1. Konvertieren des Hintergrund-Hex in java.awt.Color.
  2. Extrahieren der HSB-Werte (Farbton, Sättigung, Helligkeit) mittels Color.RGBtoHSB().
  3. Subtraktion von 0,6 von der Helligkeit, wobei die untere Grenze auf 0,3 begrenzt wird. Dies erzeugt einen merklich dunkleren Farbton des gleichen Farbtons.
  4. Rückkonvertierung nach RGB mittels Color.HSBtoRGB() und Formatierung als "#rrggbb".
  5. Auskommentierter Code hatte eine zusätzliche Sättigungsverstärkung für nahezu graue Farben, die deaktiviert wurde.

Das CLASSIC-Schema ist einfacher: Dunkle Hintergründe erhalten weißen Text ("#fff"), helle Hintergründe erhalten dunkelgrauen Text ("#444"), mit einem Schwellenwert bei Helligkeit 180.

Design-Grundlage

Die serverseitige Farbberechnung ist eine bewusste architektonische Entscheidung. Durch die Berechnung von Text- und Hintergrundfarben auf dem Server (anstatt im React-Frontend) stehen dieselben Farbwerte sowohl für die FullCalendar-Ereignisdarstellung als auch für Formular-Auswahllisten zur Verfügung, wodurch Inkonsistenzen vermieden werden. Der HSB-basierte Algorithmus erzeugt Farben, die wahrnehmbar mit dem Hintergrund verwandt sind (gleicher Farbton, angepasste Helligkeit), anstatt einfach zu invertieren – dies schafft ein kohärenteres visuelles Design. Der ColorCache vermeidet die wiederholte Berechnung derselben Farbkombinationen (jeder Kalenderstil wird für viele Ereignisse verwendet), und der 1-Stunden-Ablauf über AbstractCache ermöglicht die Weitergabe von Themenänderungen ohne Neustart. Der CLASSIC-Modus wurde nachträglich hinzugefügt (Commit 5a2c98523) als Benutzeroption für diejenigen, die den einfacheren kontrastreichen Ansatz aus früheren Versionen bevorzugen.
