#863 : CalendarStyle.kt

projectforge-business/src/main/kotlin/org/projectforge/business/calendar/CalendarStyle.kt Type : Classe Kotlin (utilitaire de style)
Objectif : Calcule les couleurs d'arrière-plan et de texte pour les événements du calendrier en fonction d'une couleur de base configurable
Chemin source : projectforge-business/src/main/kotlin/org/projectforge/business/calendar/CalendarStyle.kt 161 lignes · 103 code · 38 commentaires · 20 lignes vides

CalendarStyle prend une couleur d'arrière-plan de base (chaîne hexadécimale), calcule une couleur de texte correspondante et dérive une variation d'arrière-plan semi-transparente pour le rendu des événements du calendrier. La couleur du texte est calculée côté serveur en utilisant la manipulation de l'espace colorimétrique HSB pour garantir un contraste adéquat. Les résultats sont mis en cache dans un ColorCache (étendant AbstractCache avec une expiration d'une heure) pour éviter de recalculer les mêmes conversions de manière répétée. Deux schémas de couleurs sont pris en charge : le mode par défaut (moderne) avec des couleurs dérivées de HSB et un mode CLASSIC qui préserve le comportement original v6 de noir sur blanc ou blanc sur foncé.

Constructeur

ParamètreTypeDéfautDescription
baseBackgroundColor String? null Une chaîne de couleur hexadécimale (ex. "#06790e"). Par défaut "#777" si null.

Propriétés

bgColor: String

La couleur d'arrière-plan de base. Initialisée à partir du paramètre du constructeur, avec repli sur "#777" (un gris neutre). Elle est stockée comme valeur hexadécimale canonique et ne doit pas être utilisée directement pour le rendu — utilisez getBackgroundColor() à la place.

Méthodes publiques

getTextColor(colorScheme: CalendarEventColorScheme?): String

Retourne la couleur de texte calculée pour le schéma de couleurs donné. Délègue à colorCache.getTextColor(bgColor, colorScheme).

getBackgroundColor(calendarEventColorScheme: CalendarEventColorScheme?): String

Retourne la couleur d'arrière-plan ajustée pour le schéma de couleurs :

  • Mode CLASSIC : Retourne bgColor non modifié (opaque).
  • Mode moderne (par défaut) : Ajoute une transparence alpha — "3" pour hex court ("#7773" → ~20% d'opacité) ou "33" pour hex complet ("#77777733" → ~20% d'opacité). Cela crée des événements de calendrier translucides qui se fondent avec l'arrière-plan.

Objet compagnon — Moteur de calcul des couleurs

Classe interne RGB(r: Int, g: Int, b: Int)

Classe de données simple contenant les valeurs des canaux RVB (0–255).

Classe interne ColorCache : AbstractCache()

Cache avec une TTL d'une heure qui stocke les couleurs de texte calculées, indexées par chaîne hexadécimale, évitant ainsi les conversions HSB redondantes. Maintient des cartes séparées pour les schémas de couleurs standard et classique. Thread-safe via des blocs synchronized sur la carte par schéma.

Détails de l'algorithme de couleur

Pour le schéma moderne, la couleur du texte est calculée par :

  1. Conversion de l'hexadécimal d'arrière-plan en java.awt.Color.
  2. Extraction des valeurs HSB (Teinte, Saturation, Luminosité) via Color.RGBtoHSB().
  3. Soustraction de 0,6 à la luminosité, avec limitation de la borne inférieure à 0,3. Cela produit une nuance nettement plus foncée de la même teinte.
  4. Conversion retour en RVB via Color.HSBtoRGB() et formatage en "#rrggbb".
  5. Le code commenté avait un renforcement supplémentaire de la saturation pour les couleurs quasi grises qui a été désactivé.

Le schéma CLASSIC est plus simple : les arrière-plans sombres reçoivent du texte blanc ("#fff"), les arrière-plans clairs reçoivent du texte gris foncé ("#444"), avec le seuil à une luminosité de 180.

Justification de la conception

Le calcul des couleurs côté serveur est une décision architecturale délibérée. En calculant les couleurs du texte et de l'arrière-plan sur le serveur (plutôt que sur le frontend React), les mêmes valeurs de couleur sont disponibles à la fois pour le rendu des événements FullCalendar et pour les listes déroulantes de sélection de formulaire, évitant ainsi les incohérences. L'algorithme basé sur HSB produit des couleurs qui sont perceptuellement liées à l'arrière-plan (même teinte, luminosité ajustée) plutôt que simplement inversées — cela crée une conception visuelle plus cohérente. Le ColorCache évite de recalculer les mêmes combinaisons de couleurs de manière répétée (le style de chaque calendrier est utilisé pour de nombreux événements), et l'expiration d'une heure via AbstractCache permet aux changements de thème de se propager sans redémarrage. Le mode CLASSIC a été ajouté rétroactivement (commit 5a2c98523) comme option utilisateur pour ceux qui préfèrent l'approche simple à contraste élevé des versions antérieures.
