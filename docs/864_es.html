Propósito: Asigna identificadores de calendario a sus estilos de visualización (colores), con valores predeterminados integrados para calendarios de cumpleaños
Ruta de origen: projectforge-business/src/main/kotlin/org/projectforge/business/calendar/CalendarStyleMap.kt 69 líneas · 30 código · 31 comentarios · 8 en blanco

CalendarStyleMap es un registro con ámbito de usuario que asocia cada calendario (por su ID de base de datos) con un objeto CalendarStyle que define sus colores. Proporciona accesores de conveniencia para los dos calendarios de cumpleaños integrados e inicializa automáticamente sus estilos con valores predeterminados fijos (verde #06790e para cumpleaños favoritos, blanco #ffffff para todos los cumpleaños) cuando se accede por primera vez si aún no están configurados.

Campos

styles: MutableMap<Long, CalendarStyle> (privado)

Mapa interno que almacena el CalendarStyle por ID de calendario. No se expone directamente; se accede a través de get(), add() y contains().

Accesores de conveniencia

birthdaysFavoritesStyle: CalendarStyle

Devuelve el estilo para el calendario de "cumpleaños favoritos" (BIRTHDAYS_FAVS_CAL_ID). Utiliza !! porque el método get() garantiza que no sea nulo para este ID (lo crea automáticamente si está ausente).

birthdaysAllStyle: CalendarStyle

Devuelve el estilo para el calendario de "todos los cumpleaños" (BIRTHDAYS_ALL_CAL_ID). De igual manera, se garantiza que no sea nulo.

Métodos

contains(calendarId: Long): Boolean

Verifica si existe un estilo para el ID de calendario dado.

add(calendarId: Long, style: CalendarStyle)

Añade o reemplaza un estilo para un ID de calendario dado.

get(calendarId: Long?): CalendarStyle?

Recupera el estilo para un ID de calendario. Devuelve null si el ID en sí es nulo. Trata de forma especial los dos ID de calendario de cumpleaños integrados (BIRTHDAYS_FAVS_CAL_ID y BIRTHDAYS_ALL_CAL_ID): si no se ha añadido ningún estilo explícitamente para ellos, crea y almacena en caché de forma diferida un estilo predeterminado ("#06790e" para favoritos, "#ffffff" para todos). Esta inicialización diferida garantiza que los calendarios de cumpleaños siempre tengan un estilo visible sin requerir configuración explícita.

Justificación del diseño

El patrón de inicialización diferida para los calendarios de cumpleaños evita la necesidad de un paso de configuración explícito. En lugar de necesitar un instalador o un script de migración para pre-sembrar los estilos de cumpleaños, la primera llamada a get() con cualquiera de los ID de cumpleaños crea el estilo predeterminado de forma transparente. Esto también significa que si las preferencias almacenadas de un usuario carecen de estas entradas (por ejemplo, después de una actualización), se regeneran sobre la marcha. El MutableMap se mantiene privado para evitar la mutación directa desde fuera de la clase, asegurando que los valores predeterminados diferidos siempre se activen a través de get() en lugar de mediante el acceso al mapa.
