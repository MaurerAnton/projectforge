CalendarStyleMap est un registre propre à chaque utilisateur qui associe chaque calendrier (par son identifiant en base de données) à un objet CalendarStyle définissant ses couleurs. Il fournit des accesseurs pratiques pour les deux calendriers d'anniversaires intégrés et initialise automatiquement leurs styles avec des valeurs par défaut codées en dur (#06790e vert pour les anniversaires favoris, #ffffff blanc pour tous les anniversaires) lors du premier accès s'ils ne sont pas déjà configurés.

Champs

styles: MutableMap<Long, CalendarStyle> (privé)

Map interne stockant le CalendarStyle pour chaque identifiant de calendrier. Non exposée directement ; accessible via get(), add() et contains().

Accesseurs pratiques

birthdaysFavoritesStyle: CalendarStyle

Renvoie le style pour le calendrier des « anniversaires favoris » (BIRTHDAYS_FAVS_CAL_ID). Utilise !! car la méthode get() garantit une valeur non nulle pour cet identifiant (création automatique si absent).

birthdaysAllStyle: CalendarStyle

Renvoie le style pour le calendrier de « tous les anniversaires » (BIRTHDAYS_ALL_CAL_ID). Garantie de non-nullité similaire.

Méthodes

contains(calendarId: Long): Boolean

Vérifie si un style existe pour l'identifiant de calendrier donné.

add(calendarId: Long, style: CalendarStyle)

Ajoute ou remplace un style pour un identifiant de calendrier donné.

get(calendarId: Long?): CalendarStyle?

Récupère le style pour un identifiant de calendrier. Renvoie null si l'identifiant lui-même est nul. Traite de manière spéciale les deux identifiants de calendrier d'anniversaires intégrés (BIRTHDAYS_FAVS_CAL_ID et BIRTHDAYS_ALL_CAL_ID) : si aucun style n'a été explicitement ajouté pour eux, crée et met en cache paresseusement un style par défaut ("#06790e" pour les favoris, "#ffffff" pour tous). Cette initialisation paresseuse garantit que les calendriers d'anniversaires ont toujours un style visible sans nécessiter de configuration explicite.

Justification de la conception

Le modèle d'initialisation paresseuse pour les calendriers d'anniversaires évite de nécessiter une étape de configuration explicite. Au lieu d'avoir besoin d'un installateur ou d'un script de migration pour pré-initialiser les styles d'anniversaires, le premier appel à get() avec l'un des identifiants d'anniversaire crée de manière transparente le style par défaut. Cela signifie également que si les préférences stockées d'un utilisateur ne contiennent pas ces entrées (par exemple après une mise à niveau), elles sont régénérées à la volée. La MutableMap est conservée privée pour empêcher toute mutation directe depuis l'extérieur de la classe, garantissant que les valeurs par défaut paresseuses sont toujours déclenchées via get() plutôt que par un accès direct à la map.
