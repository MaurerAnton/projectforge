#864: CalendarStyleMap.kt

Назначение: Сопоставляет идентификаторы календарей с их стилями отображения (цветами) со встроенными значениями по умолчанию для календарей дней рождения

CalendarStyleMap — это реестр в области видимости пользователя, который связывает каждый календарь (по его идентификатору в базе данных) с объектом CalendarStyle, определяющим его цвета. Он предоставляет удобные методы доступа для двух встроенных календарей дней рождения и автоматически инициализирует их стили с жестко заданными значениями по умолчанию (зеленый #06790e для избранных дней рождения, белый #ffffff для всех дней рождения) при первом обращении, если они еще не настроены.

Поля

styles: MutableMap<Long, CalendarStyle> (закрытое)

Внутренняя карта, хранящая CalendarStyle для каждого идентификатора календаря. Не раскрывается напрямую; доступ осуществляется через get(), add() и contains().

Удобные методы доступа

birthdaysFavoritesStyle: CalendarStyle

Возвращает стиль для календаря «избранные дни рождения» (BIRTHDAYS_FAVS_CAL_ID). Использует !!, так как метод get() гарантирует ненулевое значение для этого идентификатора (автоматически создает, если отсутствует).

birthdaysAllStyle: CalendarStyle

Возвращает стиль для календаря «все дни рождения» (BIRTHDAYS_ALL_CAL_ID). Аналогично гарантированно не равен null.

Методы

contains(calendarId: Long): Boolean

Проверяет, существует ли стиль для указанного идентификатора календаря.

add(calendarId: Long, style: CalendarStyle)

Добавляет или заменяет стиль для указанного идентификатора календаря.

get(calendarId: Long?): CalendarStyle?

Извлекает стиль для идентификатора календаря. Возвращает null, если сам идентификатор равен null. Особый случай для двух встроенных идентификаторов календарей дней рождения (BIRTHDAYS_FAVS_CAL_ID и BIRTHDAYS_ALL_CAL_ID): если для них не был явно добавлен стиль, лениво создает и кэширует стиль по умолчанию ("#06790e" для избранных, "#ffffff" для всех). Такая ленивая инициализация гарантирует, что календари дней рождения всегда имеют видимый стиль без необходимости явной настройки.

Обоснование дизайна

Шаблон ленивой инициализации для календарей дней рождения позволяет избежать необходимости в явном шаге настройки. Вместо того чтобы требовать установщик или скрипт миграции для предварительного заполнения стилей дней рождения, первый вызов get() с любым идентификатором дня рождения прозрачно создает стиль по умолчанию. Это также означает, что если в сохраненных настройках пользователя отсутствуют эти записи (например, после обновления), они регенерируются на лету. MutableMap остается закрытым, чтобы предотвратить прямое изменение извне класса, гарантируя, что ленивые значения по умолчанию всегда запускаются через get(), а не через доступ к карте.
