#866: StyledTeamCalendar.kt

projectforge-business/src/main/kotlin/org/projectforge/business/calendar/StyledTeamCalendar.kt Typ: Datenklasse · Zweck: Kalender mit Styling · Quelle: projectforge-business/src/main/kotlin/org/projectforge/business/calendar/StyledTeamCalendar.kt 45 Zeilen · 14 Code · 28 Kommentare · 3 leer
Erweitert TeamCalendar um CalendarStyle (Farbe, Erscheinungsbild) und ein visible-Flag. Wird verwendet, um Teamkalender-Objekte mit Rendering-Metadaten für die Kalender-UI zu dekorieren, ohne das Kernmodell des Teamkalenders zu verändern.

Klassenhierarchie

StyledTeamCalendar erbt von TeamCalendar (siehe #862), indem die id, der title und der access des Elternteils über den Konstruktor übergeben werden. Dies ist ein Kotlin-datenklassenähnliches Muster – die Klasse ist open, aber effektiv ein Wert-Wrapper.

EigenschaftTypBeschreibung
idLong?Von TeamCalendar geerbt
titleString?Von TeamCalendar geerbt
accessACCESS?Von TeamCalendar geerbt
styleCalendarStyle?Visueller Stil (Farbe usw.) für die Kalenderdarstellung
visibleBooleanOb der Kalender sichtbar ist (Standard true)

Begleitobjekt

map()

fun map(calendars: List<TeamCalendar>, styleMap: CalendarStyleMap): List<StyledTeamCalendar>

Nimmt eine Liste von TeamCalendar-Objekten und eine CalendarStyleMap, die nach Kalender-ID indiziert ist. Erzeugt eine entsprechende Liste von StyledTeamCalendar-Instanzen, die jeweils mit ihrem Stil aus der Map dekoriert sind. Verwendet calendars.find { it.id == cal.id }, um den passenden Quellkalender für jeden Eintrag zu finden.

Entwurfsbegründung

Die Trennung in TeamCalendar (reine Daten) und StyledTeamCalendar (mit UI-Metadaten dekoriert) folgt einem sauberen Dekorator-Muster. Die Basisklasse TeamCalendar bleibt von Darstellungsbelangen unberührt. Die CalendarStyleMap-Suche wird über die begleitende map-Funktion stapelweise angewendet, wodurch die Transformationslogik zentralisiert bleibt.
