projectforge-business/src/main/kotlin/org/projectforge/business/calendar/TeamCalendar.kt Tipo: Clase de datos abierta · Propósito: Modelo de acceso a calendario · Fuente: projectforge-business/src/main/kotlin/org/projectforge/business/calendar/TeamCalendar.kt 73 líneas · 37 código · 28 comentarios · 8 en blanco
Objeto de dominio central que representa un calendario de equipo con derechos de acceso de usuario. Se construye ya sea a partir de propiedades sin procesar o de una entidad JPA (TeamCalDO) con resolución de acceso mediante TeamCalCache. Sirve como clase base para StyledTeamCalendar (ver #861).

Propiedades

PropiedadTipoValor por defectoDescripción
idLong?—Identificador único del calendario
titleString?—Nombre visible del calendario
accessACCESS?nullNivel de acceso del usuario a este calendario
externalSubscriptionBooleanfalseIndica si es un calendario suscrito externamente

Enumeración ACCESS

Refleja DataobjectAccessType pero adaptado a la semántica de nivel de calendario.
ValorSignificado
OWNEREl usuario es el propietario del calendario
FULLAcceso completo de lectura/escritura
READAcceso de solo lectura
MINIMALAcceso mínimo (ej. solo horarios, sin detalles)
NONESin acceso (solo los administradores reciben esto)

Constructores

Constructor principal

TeamCalendar(id: Long?, title: String?, access: ACCESS? = null, externalSubscription: Boolean = false)

Construcción directa con valores de propiedad explícitos.

Constructor secundario (desde TeamCalDO)

constructor(teamCalDO: TeamCalDO, userId: Long, teamCalCache: TeamCalCache)

Construye un TeamCalendar a partir de una entidad JPA. Resuelve el nivel de acceso del usuario llamando a teamCalCache.teamCalRight.getAccessType(teamCalDO, userId) y mapeando el resultado de DataobjectAccessType a la enumeración ACCESS. También lee externalSubscription de la entidad.

Devuelve un TeamCalendar con ID -3, título localizado "calendar.birthdays.all" y ACCESS.READ.

Relación con StyledTeamCalendar

TeamCalendar es la clase base para StyledTeamCalendar (#861), que añade CalendarStyle y una bandera visible. Esta separación sigue el patrón decorador: TeamCalendar contiene los datos centrales y la lógica de acceso, mientras que StyledTeamCalendar añade metadatos de representación de interfaz de usuario.
