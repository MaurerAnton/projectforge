#868: ICalendarEvent.kt

projectforge-business/src/main/kotlin/org/projectforge/business/calendar/event/model/ICalendarEvent.kt Тип: Интерфейс Kotlin
Назначение: Общий контракт для всех реализаций событий календаря независимо от типа календаря
Путь к исходнику: projectforge-business/src/main/kotlin/org/projectforge/business/calendar/event/model/ICalendarEvent.kt 45 строк · 11 кода · 25 комментариев · 9 пустых

ICalendarEvent определяет минимальный набор свойств, которые должно предоставлять любое событие календаря в системе ProjectForge. Этот интерфейс позволяет единообразно обрабатывать различные типы событий (события командного календаря, записи табеля, записи отпусков, дни рождения) в коде отрисовки и фильтрации календаря. Изначально это был Java-класс (TeamEvent.java), который был преобразован в интерфейс Kotlin в ходе модернизации.

Свойства интерфейса

СвойствоТипОписание
uid String? Уникальный идентификатор события. Может быть nullable для поддержки типов событий без собственных UID.
subject String? Название или тема события. Отображается как основной текст в календаре.
location String? Физическое или виртуальное местоположение события. Nullable для событий без местоположения.
allDay Boolean Указывает, занимает ли событие целый день (или несколько полных дней). Влияет на отображение (без временных слотов).
startDate Date? Дата и время начала события (устаревший java.util.Date). Nullable для поддержки граничных случаев.
endDate Date? Дата и время окончания события. Nullable — некоторые реализации могут определять длительность из startDate.
note String? Необязательное описание или текст заметки. Отображается в подсказках и детальных представлениях.

Архитектура

Этот интерфейс служит общим знаменателем для различных источников событий:

  • События командного календаря реализуют полный интерфейс с сохранёнными данными.
  • Записи табеля адаптированы к этому интерфейсу, чтобы отображаться вместе с событиями календаря.
  • Записи отпусков реализуют интерфейс для отображения наложения отпусков.
  • События дней рождения являются синтетическими событиями, созданными из данных профиля пользователя.

Кодируя отрисовку и фильтрацию календаря на основе ICalendarEvent, а не конкретного класса, система достигает полиморфизма для этих разнородных источников событий без необходимости общего базового класса или таблицы базы данных.

Обоснование дизайна

Преобразование исходного Java-класса TeamEvent в интерфейс Kotlin (ICalendarEvent) было ключевым архитектурным улучшением (коммит aab28d48a). Конкретный класс подразумевал единственную реализацию с общим состоянием; интерфейс позволяет каждому типу событий независимо владеть своей структурой данных, оставаясь при этом полиморфно обрабатываемым кодом календаря. Тип java.util.Date (а не java.time) сохраняется, поскольку многие реализации являются сущностями JPA, основанными на столбцах базы данных типа Date. Широкое использование nullable-типов отражает реальность частичных данных событий (например, событие на целый день может не иметь значимого времени начала/окончания, день рождения не имеет местоположения).
