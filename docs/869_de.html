#869: SeriesModificationMode.kt

projectforge-business/src/main/kotlin/org/projectforge/business/calendar/event/model/SeriesModificationMode.kt Typ: Kotlin-Enum-Klasse
Zweck: Gibt an, welche Ereignisse einer wiederkehrenden Serie von einer Änderung betroffen sind
Quellpfad: projectforge-business/src/main/kotlin/org/projectforge/business/calendar/event/model/SeriesModificationMode.kt 30 Zeilen · 2 Code · 26 Kommentare · 2 Leerzeilen

SeriesModificationMode ist ein einfaches dreiwertiges Enum, das den Umfang von Änderungen steuert, wenn ein Benutzer ein Ereignis bearbeitet, das zu einer wiederkehrenden Serie gehört. Dieses Muster ist in Kalender-UI (Google Kalender, Outlook usw.) üblich und bestimmt, ob die Bearbeitung für ein einzelnes Vorkommen, alle Vorkommen oder dieses und alle zukünftigen Vorkommen gilt.

Enum-Werte

WertBeschreibung
ALL Die Änderung gilt für jedes Ereignis der Serie – Vergangenheit, Gegenwart und Zukunft. Dies ist der weitreichendste Änderungsumfang.
FUTURE Die Änderung gilt für das ausgewählte Ereignis und alle nachfolgenden Vorkommen. Vergangene Vorkommen der Serie bleiben unverändert. Dies erzeugt typischerweise einen Teilungspunkt in der Serie.
SINGLE Die Änderung gilt nur für das spezifische bearbeitete Vorkommen. Andere Vorkommen der Serie bleiben unberührt. Dies erzeugt einen Ausnahmedatensatz im Serien-Datenmodell.

Verwendungskontext

Dieses Enum ist Teil des Pakets event.model zusammen mit ICalendarEvent und wird bei der Verarbeitung von Bearbeitungs-/Speichervorgängen für wiederkehrende Kalenderereignisse verwendet. Das Frontend zeigt vermutlich einen Dialog mit der Frage „Dieses Ereignis bearbeiten? / Alle Ereignisse der Serie bearbeiten? / Dieses und alle folgenden Ereignisse bearbeiten?“ an, wobei der entsprechende Enum-Wert an das Backend gesendet wird.

Design-Entscheidung

Ein dediziertes Enum für den Änderungsumfang von Serien (anstelle eines booleschen Flags oder eines Integer-Codes) bietet Typsicherheit und Selbstdokumentation. Die drei Werte spiegeln das Standard-Kalender-UI-Muster (einzeln / alle zukünftigen / alle) wider, das Benutzer bereits aus anderen Kalenderanwendungen kennen. Durch die Platzierung im Paket event.model zusammen mit ICalendarEvent ist das Enum zusammen mit dem Ereignisvertrag lokalisiert, sodass für Entwickler offensichtlich ist, dass dies das Ereignisbearbeitungsverhalten für die Ereignismodellschicht steuert.
