#871: ConfigurationService.kt

Type: Spring @Service — Application-wide configuration facade

Purpose: Central configuration service that reads and manages all ProjectForge runtime settings from XML config files, database-stored configuration entries, and Spring property values.

Source path: projectforge-business/src/main/kotlin/org/projectforge/business/configuration/ConfigurationService.kt

The single most important service in the ProjectForge business layer. It serves as the unified entry point for all configuration concerns — file system paths, security settings, email, locale, currency, SSL keystores, Datev limits, and dozens of database-backed parameters. It is initialized via @PostConstruct and registers itself globally via ConfigurationServiceAccessor, making it available even during early Spring startup (e.g., for Flyway migrations).

2. Initialization (@PostConstruct init())

  • Registers this in ConfigurationServiceAccessor (static accessor pattern)
  • Sets staticApplicationHomeDir for early Flyway access
  • Loads ConfigXml from the application home directory
  • Creates the resources, fonts, and plugins directories if missing
  • In Docker mode, creates an environment.sh file with initial content for Java options
  • Sets up SSL keystores via setupKeyStores()
  • Creates the framework-level Configuration object

3. Resource Resolution

Two methods handle file resolution with a fallback strategy:

  • getResourceAsInputStream(filename) — Tries filesystem path under resources dir first, then falls back to classpath resource loading
  • getResourceContentAsString(filename) — Same resolution but returns the content as a UTF-8 string

Both return Array<Any?> of size 2: [InputStream?, URI?]. Logging helpers track which resources exist on disk vs. classpath to avoid spamming logs with repeated "file not found" messages.

4. Database-Backed Configuration

Numerous properties are read from the ConfigurationDao (persisted ConfigurationDO entities):

  • timezone — Default timezone from DB (falls back to system default)
  • getEndOfCarryVacationOfPreviousYear(year) — Parses day/month string (defaults to 31.03.)
  • hREmailadress — HR contact email
  • minPasswordLength — Enforced minimum; falls back to ConfigurationParam.MIN_PASSWORD_LENGTH default
  • flagCheckPasswordChange — Whether password change is required
  • timesheetNoteSavingsByAI — AI-generated timesheet note savings flag

All DB-backed getters defensively catch RuntimeException for the case where the database hasn't been initialized yet (initial setup phase).

5. SSL / Keystore Management

The private setupKeyStores() method loads a custom jssecacerts file (if configured) and creates an SSLSocketFactory via createSSLSocketFactory(). This factory is exposed as usersSSLSocketFactory for custom certificate validation (e.g., for CardDAV/CalDAV connections).

6. Template Resolution

getTemplateFile(dir, filename, resourceFilename) and getOfficeTemplateFile() resolve Office template files from the filesystem first (resources/officeTemplates/), then from the classpath (classpath:officeTemplates/), returning Spring Resource objects.

7. Logo Management

Properties logoFileName, logoFileObject, isLogoFileValid, and syntheticLogoName manage the application logo. The logo file is resolved relative to resources/images/ and the synthetic name returns logo.png, logo.jpg, or logo.gif based on the extension.

9. Companion Object

Contains constants and static utilities:

  • staticApplicationHomeDir — Available before Spring context is fully loaded (used by Flyway)
  • nonExistingResources / existingResources — Sets to avoid repeated log messages about resource availability
  • showNonExistingMessage() / showExistingMessage() — Logging helpers that suppress duplicates
  • ENVIRONMENT_FILE / ENVIRONMENT_FILE_INITIAL_CONTENT — Shell script template for Docker setups
