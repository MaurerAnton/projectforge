#872: BaseUserGroupRightService.kt

projectforge-business/src/main/kotlin/org/projectforge/business/common/BaseUserGroupRightService.kt Typ: Spring @Service · Zweck: CRUD-Hilfsklasse für Benutzer-/Gruppenrechte · Quelle: projectforge-business/src/main/kotlin/org/projectforge/business/common/BaseUserGroupRightService.kt 230 Zeilen · 91 Code · 112 Kommentare · 27 leer
Spring-Service, der Getter/Setter-Methoden für die CSV-Felder der Zugriffsrechte auf BaseUserGroupRightsDO-Objekten bereitstellt. Löst rohe ID-Strings in sortierte GroupDO- und PFUserDO-Sammlungen über GroupService und UserService auf. Verwaltet eine Singleton-instance über @PostConstruct für den statischen Zugriff.

Abhängigkeiten

AbhängigkeitTypZweck
GroupService@AutowiredLöst Gruppen-IDs in GroupDO-Entitäten auf
UserService@AutowiredLöst Benutzer-IDs in PFUserDO-Entitäten auf

Getter-Methoden (insgesamt 6)

Jede Zugriffsebene (voll, schreibgeschützt, minimal) x Entitätstyp (Gruppen, Benutzer) hat einen entsprechenden Getter:

MethodeRückgabe
getSortedFullAccessGroups(rights)Collection<GroupDO>
getSortedFullAccessUsers(rights)Collection<PFUserDO>
getSortedReadonlyAccessGroups(rights)Collection<GroupDO>
getSortedReadonlyAccessUsers(rights)Collection<PFUserDO>
getSortedMinimalAccessGroups(rights)Collection<GroupDO>
getSortedMinimalAccessUsers(rights)Collection<PFUserDO>

Setter-Methoden (insgesamt 12)

Jede Zugriffsebene x Entitätstyp hat zwei Überladungen – eine akzeptiert eine Collection<IdObject<Long>?>? und eine akzeptiert einen rohen String? mit kommagetrennten IDs:

MethodeEingabe
setFullAccessGroupsCollection<IdObject<Long>?>? oder String?
setFullAccessUsersCollection<IdObject<Long>?>? oder String?
setReadonlyAccessGroupsCollection<IdObject<Long>?>? oder String?
setReadonlyAccessUsersCollection<IdObject<Long>?>? oder String?
setMinimalAccessGroupsCollection<IdObject<Long>?>? oder String?
setMinimalAccessUsersCollection<IdObject<Long>?>? oder String?
Alle Setter-Methoden ändern nur das Feld des DO im Speicher. Keine löst eine Datenbankspeicherung aus – der Aufrufer ist für das Persistieren der Entität verantwortlich.

Begleitobjekt

asSortedIdStrings(collection)

@JvmStatic. Wandelt eine Sammlung von IdObject<Long> in einen sortierten, kommagetrennten String von IDs um. Filtert Nullen, sortiert numerisch, verbindet mit ",". Gibt null zurück, wenn die Sammlung null oder leer ist.

// Beispiel: [Group(3), Group(1), Group(2)] → "1,2,3"

asSortedIdStrings(idString)

@JvmStatic. Analysiert einen CSV-String, extrahiert gültige Long-Werte, sortiert sie und gibt den normalisierten CSV-String zurück. Filtert leere/ungültige Einträge. Gibt null für null-Eingabe zurück.

instance

@JvmStatic lateinit var mit privatem Setter. Initialisiert in @PostConstruct. Bietet globalen statischen Zugriff auf das von Spring verwaltete Singleton für Dienstprogrammkontexte, in denen Dependency Injection nicht verfügbar ist.

Design-Entscheidungen

Das Getter/Setter-Muster stellt sicher, dass die rohen CSV-Strings immer sortiert und normalisiert bleiben. Die zwei Überladungen pro Setter (Sammlung vs. String) unterstützen sowohl UI-gesteuerte Bearbeitung (wo eine Mehrfachauswahl eine Sammlung von Entitäten erzeugt) als auch programmatische/API-gesteuerte Bearbeitung (wo rohe ID-Strings bereitgestellt werden).

Das Singleton-instance-Muster ist eine pragmatische Brücke zwischen Spring DI und älterem statischen Dienstprogrammcode. Neuere Code sollte die Konstruktorinjektion von BaseUserGroupRightService bevorzugen.
