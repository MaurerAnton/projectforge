Eigenständiges Dienstprogrammobjekt, das die Kernlogik zur Auflösung von Zugriffsrechten enthält. Bestimmt, ob ein Benutzer OWNER-, FULL-, READONLY-, MINIMAL- oder NONE-Zugriff auf ein BaseUserGroupRightsDO-Objekt hat, indem die CSV-ID-Felder gegen die Gruppenmitgliedschaft und den direkten Benutzer-ID-Abgleich geprüft werden. Wird sowohl von BaseUserGroupRight (#864) als auch von TeamCalCache verwendet.

API

isOwner(user, obj) / isOwner(userId, obj)

Gibt true zurück, wenn userId == obj.ownerId (beide nicht null). Einfache Identitätsprüfung.

getAccessType(obj, userId): DataobjectAccessType

Die Kernmethode zur Auflösung. Wertet den Zugriff in der folgenden Prioritätsreihenfolge aus:

  1. Null-Prüfung: Gibt NONE zurück, wenn obj oder userId null ist
  2. Besitzer-Prüfung: Gibt OWNER zurück, wenn userId == obj.ownerId
  3. Vollzugriff: Prüft fullAccessGroupIds und fullAccessUserIds
  4. Nur-Lese-Zugriff: Prüft readonlyAccessGroupIds und readonlyAccessUserIds
  5. Minimaler Zugriff: Prüft minimalAccessGroupIds und minimalAccessUserIds
  6. Fallback: Gibt NONE zurück

hasReadAccess(obj, userId, throwException?): Boolean

Gibt true zurück, wenn der Zugriffstyp READONLY, FULL oder OWNER ist. Andernfalls wird false zurückgegeben oder eine AccessException("access.exception.noReadAccess") ausgelöst, wenn throwException true ist.

hasWriteAccess(obj, userId, throwException?): Boolean

Gibt true zurück, wenn der Zugriffstyp FULL oder OWNER ist. Andernfalls wird false zurückgegeben oder eine AccessException("access.exception.noWriteAccess") ausgelöst.

hasAccess(obj, userId, operationType, throwException?)

Leitet an hasReadAccess oder hasWriteAccess weiter, basierend auf operationType.isWriteType.

hasAccess(obj, oldObj, userId, operationType, throwException?)

Prüft bei Schreiboperationen zuerst das alte Objekt (erlaubt Änderungen, wenn der Benutzer bereits Schreibzugriff hatte). Fällt auf die Prüfung des neuen Objekts zurück. Bei Leseoperationen wird oldObj ?: obj geprüft.

Interne Logik

isMemberOfAny(groupIds, userIds, userId): Boolean

Private Hilfsmethode, die die eigentliche Gruppen-/Benutzermitgliedschaftsprüfung durchführt:

  • Wenn groupIds nicht leer ist, wird UserGroupCache.getInstance().isUserMemberOfAtLeastOneGroup(userId, *groupIds) geprüft
  • Wenn userIds die angegebene userId enthält, wird true zurückgegeben
  • Verwendet StringHelper.splitToLongObjects(), um die CSV-Spalten in Array<Long> zu parsen

Datenfluss

BaseUserGroupRightsDO (CSV-Spalten)
  │
  ├─ StringHelper.splitToLongObjects()
  │
  ├─ UserGroupCache.isUserMemberOfAtLeastOneGroup()  ← Gruppen
  └─ Direkter Benutzer-ID-Vergleich                   ← Benutzer
  │
  ▼

  │
  ▼
hasReadAccess / hasWriteAccess → Boolean

Design-Entscheidungen

Das object-Muster (Kotlin-Singleton) wurde gewählt, weil die Zugriffslogik rein funktional ist – kein Zustand oder Abhängigkeiten, nur Berechnung. Dies ermöglicht den Aufruf von überall (Services, Caches, Entitätskonstruktoren) ohne Injektions-Overhead.

Die abgestufte Auswertung (Besitzer → Vollzugriff → Nur-Lesen → Minimal → Kein) bedeutet, dass der erste Treffer gewinnt. Wenn ein Benutzer sowohl in der Vollzugriffsgruppe als auch in der Nur-Lese-Gruppe ist, erhält er FULL-Zugriff. Der Parameter oldObj in hasAccess unterstützt das Muster, bei dem die Berechtigung zum Ändern eines Objekts gegen den Zustand vor der Änderung geprüft wird – entscheidend für Aktualisierungsoperationen, bei denen sich die Zugriffslisten des Objekts als Teil der Bearbeitung ändern können.

Externe Abhängigkeiten

  • UserGroupCache — Singleton-Cache für Gruppenmitgliedschaftsabfragen
  • StringHelper.splitToLongObjects() — Parst CSV-ID-Strings in Array<Long>
  • AccessException — Wird ausgelöst, wenn throwException = true und der Zugriff verweigert wird
