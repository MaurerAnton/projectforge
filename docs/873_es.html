Objeto de utilidad independiente que contiene la lógica central de resolución de derechos de acceso. Determina si un usuario tiene acceso OWNER, FULL, READONLY, MINIMAL o NONE a un objeto BaseUserGroupRightsDO verificando los campos CSV de ID contra la pertenencia a grupos y la coincidencia directa de ID de usuario. Utilizado tanto por BaseUserGroupRight (#864) como por TeamCalCache.

API

isOwner(usuario, obj) / isOwner(userId, obj)

Devuelve true si userId == obj.ownerId (ambos no nulos). Verificación de identidad simple.

getAccessType(obj, userId): DataobjectAccessType

El método de resolución principal. Evalúa el acceso en orden de prioridad:

  1. Protección nula: Devuelve NONE si obj o userId es nulo
  2. Verificación de propietario: Devuelve OWNER si userId == obj.ownerId
  3. Acceso completo: Verifica fullAccessGroupIds y fullAccessUserIds
  4. Acceso de solo lectura: Verifica readonlyAccessGroupIds y readonlyAccessUserIds
  5. Acceso mínimo: Verifica minimalAccessGroupIds y minimalAccessUserIds
  6. Respaldo: Devuelve NONE

hasReadAccess(obj, userId, throwException?): Boolean

Devuelve true si el tipo de acceso es READONLY, FULL o OWNER. De lo contrario, devuelve false, o lanza AccessException("access.exception.noReadAccess") si throwException es verdadero.

hasWriteAccess(obj, userId, throwException?): Boolean

Devuelve true si el tipo de acceso es FULL o OWNER. De lo contrario, devuelve false, o lanza AccessException("access.exception.noWriteAccess").

hasAccess(obj, userId, operationType, throwException?)

Redirige a hasReadAccess o hasWriteAccess según operationType.isWriteType.

hasAccess(obj, oldObj, userId, operationType, throwException?)

Para operaciones de escritura, verifica primero el objeto antiguo (permitiendo la modificación si el usuario ya tenía acceso de escritura). Si no, verifica el objeto nuevo. Para operaciones de lectura, verifica oldObj ?: obj.

Lógica interna

isMemberOfAny(groupIds, userIds, userId): Boolean

Ayudante privado que realiza la verificación real de pertenencia a grupo/usuario:

  • Si groupIds no está vacío, verifica UserGroupCache.getInstance().isUserMemberOfAtLeastOneGroup(userId, *groupIds)
  • Si userIds contiene el userId dado, devuelve verdadero
  • Utiliza StringHelper.splitToLongObjects() para analizar las columnas CSV en Array<Long>

Flujo de datos

BaseUserGroupRightsDO (columnas CSV)
  │
  ├─ StringHelper.splitToLongObjects()
  │
  ├─ UserGroupCache.isUserMemberOfAtLeastOneGroup()  ← grupos
  └─ Comparación directa de userId                    ← usuarios
  │
  ▼
DataobjectAccessType (OWNER / FULL / READONLY / MINIMAL / NONE)
  │
  ▼
hasReadAccess / hasWriteAccess → Boolean

Justificación del diseño

Se eligió el patrón object (singleton de Kotlin) porque la lógica de acceso es puramente funcional: sin estado ni dependencias, solo computación. Esto permite que sea llamado desde cualquier lugar (servicios, cachés, constructores de entidades) sin sobrecarga de inyección.

La evaluación escalonada (propietario → completo → solo lectura → mínimo → ninguno) significa que la primera coincidencia gana. Si un usuario está tanto en el grupo de acceso completo como en el grupo de solo lectura, obtiene acceso FULL. El parámetro oldObj en hasAccess respalda el patrón donde el permiso para modificar un objeto se verifica contra el estado anterior a la modificación, algo crítico para operaciones de actualización donde las listas de acceso del objeto pueden cambiar como parte de la edición.

Dependencias externas

  • UserGroupCache — caché singleton para consultas de pertenencia a grupos
  • StringHelper.splitToLongObjects() — analiza cadenas CSV de ID a Array<Long>
  • AccessException — se lanza cuando throwException = true y se deniega el acceso
