Objet utilitaire autonome contenant la logique centrale de résolution des droits d'accès. Détermine si un utilisateur a un accès PROPRIÉTAIRE, COMPLET, LECTURE SEULE, MINIMAL ou AUCUN à un objet BaseUserGroupRightsDO en vérifiant les champs d'identifiants CSV par rapport à l'appartenance à un groupe et à la correspondance directe d'identifiant utilisateur. Utilisé à la fois par BaseUserGroupRight (#864) et TeamCalCache.

API

isOwner(utilisateur, obj) / isOwner(idUtilisateur, obj)

Renvoie true si idUtilisateur == obj.proprietaireId (les deux non nuls). Vérification d'identité simple.

getAccessType(obj, idUtilisateur) : DataobjectAccessType

La méthode de résolution centrale. Évalue l'accès par ordre de priorité :

  1. Protection nulle : Renvoie AUCUN si obj ou idUtilisateur est nul
  2. Vérification propriétaire : Renvoie PROPRIÉTAIRE si idUtilisateur == obj.proprietaireId
  3. Accès complet : Vérifie fullAccessGroupIds et fullAccessUserIds
  4. Accès lecture seule : Vérifie readonlyAccessGroupIds et readonlyAccessUserIds
  5. Accès minimal : Vérifie minimalAccessGroupIds et minimalAccessUserIds
  6. Repli : Renvoie AUCUN

hasReadAccess(obj, idUtilisateur, leverException?) : Boolean

Renvoie true si le type d'accès est LECTURE SEULE, COMPLET ou PROPRIÉTAIRE. Sinon, renvoie false, ou lève AccessException("access.exception.noReadAccess") si leverException est vrai.

hasWriteAccess(obj, idUtilisateur, leverException?) : Boolean

Renvoie true si le type d'accès est COMPLET ou PROPRIÉTAIRE. Sinon, renvoie false, ou lève AccessException("access.exception.noWriteAccess").

hasAccess(obj, idUtilisateur, typeOperation, leverException?)

Aiguille vers hasReadAccess ou hasWriteAccess selon typeOperation.estTypeEcriture.

hasAccess(obj, ancienObj, idUtilisateur, typeOperation, leverException?)

Pour les opérations d'écriture, vérifie d'abord l'objet ancien (permettant la modification si l'utilisateur avait déjà un accès en écriture). Se replie sur la vérification du nouvel objet. Pour les opérations de lecture, vérifie ancienObj ?: obj.

Logique interne

estMembreDUnAuMoins(groupIds, userIds, idUtilisateur) : Boolean

Méthode privée qui effectue la vérification réelle d'appartenance au groupe/utilisateur :

  • Si groupIds n'est pas vide, vérifie UserGroupCache.getInstance().isUserMemberOfAtLeastOneGroup(idUtilisateur, *groupIds)
  • Si userIds contient l'idUtilisateur donné, renvoie vrai
  • Utilise StringHelper.splitToLongObjects() pour analyser les colonnes CSV en Array<Long>

Flux de données

BaseUserGroupRightsDO (colonnes CSV)
  │
  ├─ StringHelper.splitToLongObjects()
  │
  ├─ UserGroupCache.isUserMemberOfAtLeastOneGroup()  ← groupes
  └─ Comparaison directe d'identifiant utilisateur    ← utilisateurs
  │
  ▼

  │
  ▼
hasReadAccess / hasWriteAccess → Booléen

Justification de la conception

Le modèle object (singleton Kotlin) a été choisi car la logique d'accès est purement fonctionnelle — pas d'état ni de dépendances, seulement du calcul. Cela permet de l'appeler depuis n'importe où (services, caches, constructeurs d'entités) sans surcharge d'injection.

L'évaluation par niveaux (propriétaire → complet → lecture seule → minimal → aucun) signifie que la première correspondance l'emporte. Si un utilisateur est à la fois dans le groupe d'accès complet et dans le groupe de lecture seule, il obtient l'accès COMPLET. Le paramètre ancienObj dans hasAccess prend en charge le modèle où l'autorisation de modifier un objet est vérifiée par rapport à l'état avant modification — critique pour les opérations de mise à jour où les listes d'accès de l'objet peuvent changer dans le cadre de l'édition.

Dépendances externes

  • UserGroupCache — cache singleton pour les recherches d'appartenance à un groupe
  • StringHelper.splitToLongObjects() — analyse les chaînes d'identifiants CSV en Array<Long>
  • AccessException — levée lorsque leverException = true et que l'accès est refusé
