projectforge-business/src/main/kotlin/org/projectforge/business/common/BaseUserGroupRightUtils.kt Тип: Объект Kotlin (статическая утилита) · Назначение: Основная логика прав доступа · Исходник: projectforge-business/src/main/kotlin/org/projectforge/business/common/BaseUserGroupRightUtils.kt 136 строк · 93 кода · 33 комментария · 10 пустых
Автономный объект утилиты, содержащий основную логику разрешения прав доступа. Определяет, имеет ли пользователь доступ OWNER, FULL, READONLY, MINIMAL или NONE к объекту BaseUserGroupRightsDO, проверяя поля CSV ID на соответствие членству в группах и прямое совпадение ID пользователя. Используется как BaseUserGroupRight (#864), так и TeamCalCache.

API

isOwner(user, obj) / isOwner(userId, obj)

Возвращает true, если userId == obj.ownerId (оба не null). Простая проверка идентичности.

getAccessType(obj, userId): DataobjectAccessType

Основной метод разрешения. Оценивает доступ в порядке приоритета:

  1. Защита от null: Возвращает NONE, если obj или userId равны null
  2. Проверка владельца: Возвращает OWNER, если userId == obj.ownerId
  3. Полный доступ: Проверяет fullAccessGroupIds и fullAccessUserIds
  4. Доступ только для чтения: Проверяет readonlyAccessGroupIds и readonlyAccessUserIds
  5. Минимальный доступ: Проверяет minimalAccessGroupIds и minimalAccessUserIds
  6. Запасной вариант: Возвращает NONE

hasReadAccess(obj, userId, throwException?): Boolean

Возвращает true, если тип доступа — READONLY, FULL или OWNER. В противном случае возвращает false или выбрасывает AccessException("access.exception.noReadAccess"), если throwException равен true.

hasWriteAccess(obj, userId, throwException?): Boolean

Возвращает true, если тип доступа — FULL или OWNER. В противном случае возвращает false или выбрасывает AccessException("access.exception.noWriteAccess").

hasAccess(obj, userId, operationType, throwException?)

Направляет к hasReadAccess или hasWriteAccess на основе operationType.isWriteType.

hasAccess(obj, oldObj, userId, operationType, throwException?)

Для операций записи сначала проверяет старый объект (разрешая модификацию, если у пользователя уже был доступ на запись). В противном случае проверяет новый объект. Для операций чтения проверяет oldObj ?: obj.

Внутренняя логика

isMemberOfAny(groupIds, userIds, userId): Boolean

Приватный помощник, выполняющий фактическую проверку членства в группе/пользователе:

  • Если groupIds не пуст, проверяет UserGroupCache.getInstance().isUserMemberOfAtLeastOneGroup(userId, *groupIds)
  • Если userIds содержит указанный userId, возвращает true
  • Использует StringHelper.splitToLongObjects() для разбора CSV-столбцов в Array<Long>

Поток данных

BaseUserGroupRightsDO (CSV-столбцы)
  │
  ├─ StringHelper.splitToLongObjects()
  │
  ├─ UserGroupCache.isUserMemberOfAtLeastOneGroup()  ← группы
  └─ Прямое сравнение userId                          ← пользователи
  │
  ▼

  │
  ▼
hasReadAccess / hasWriteAccess → Boolean

Обоснование дизайна

Паттерн object (синглтон Kotlin) был выбран, потому что логика доступа является чисто функциональной — без состояния или зависимостей, только вычисления. Это позволяет вызывать её откуда угодно (сервисы, кэши, конструкторы сущностей) без накладных расходов на внедрение.

Многоуровневая оценка (владелец → полный → только чтение → минимальный → нет) означает, что первое совпадение выигрывает. Если пользователь состоит как в группе полного доступа, так и в группе только для чтения, он получает доступ FULL. Параметр oldObj в hasAccess поддерживает паттерн, при котором разрешение на изменение объекта проверяется относительно состояния до модификации — критически важно для операций обновления, где списки доступа объекта могут измениться в процессе редактирования.

Внешние зависимости

  • UserGroupCache — синглтон-кэш для поиска членства в группах
  • StringHelper.splitToLongObjects() — разбирает строки CSV ID в Array<Long>
  • AccessException — выбрасывается, когда throwException = true и доступ запрещён
