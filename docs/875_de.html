Eine Hibernate Search ValueBridge<String?, String>, die ein Telefonnummernfeld in eine durchsuchbare Zeichenkette umwandelt, indem sie den Originalwert, eine auf Ziffern reduzierte Normalform und eine formatierte Extraktion kombiniert. Ermöglicht Suchanfragen wie „+49 30 123456“, „4930123456“ und „030/123456“, die alle denselben Datensatz finden.

Bridge-Signatur

class HibernateSearchPhoneNumberBridge : ValueBridge<String?, String>
  • Eingabetyp: nullable String (die rohe Telefonnummer aus der Entität)
  • Indizierter Typ: String (die zusammengesetzte Zeichenkette im Suchindex)

toIndexedValue()

override fun toIndexedValue(number: String?, context: ValueBridgeToIndexedValueContext): String

Erzeugt eine leerzeichengetrennte Zeichenkette mit drei Darstellungen:

  1. Originalnummer: Die rohe Eingabe (z. B. "+49 30 123456-78")
  2. Normalisierte Nummer: Nur Ziffern via StringHelper.removeNonDigits(number) (z. B. "493012345678")
  3. Formatierte Nummer: Extrahierte Telefonnummer via NumberHelper.extractPhonenumber(number)

Beispielergebnis: "+49 30 123456-78 493012345678 030/12345678"

Der Standard-Analyzer von Hibernate Search zerlegt an Leerzeichen, sodass alle drei Formen unabhängig voneinander durchsuchbar sind.

Bei Null-Eingabe wird eine leere Zeichenkette ("") zurückgegeben, nicht null. Dies verhindert NullPointerExceptions im Suchindex-Schreiber.

Entwurfsbegründung

Telefonnummern sind bekanntermaßen schwer zu durchsuchen, da Benutzer sie in verschiedenen Formaten eingeben: international (+49 30 123456), lokal (030/123456), kompakt (4930123456) oder mit Satzzeichen. Durch die Indexierung mehrerer normalisierter Formen nebeneinander in einem einzigen Feld kann jedes vom Benutzer eingegebene Suchformat übereinstimmen.

Der onlyDigits-Ansatz behandelt den allgemeinsten Fall (jedes Format reduziert sich auf dieselbe Ziffernfolge), während der extractPhonenumber-Ansatz lokale Formatierungskonventionen für exakte Übereinstimmungen bewahrt.
