projectforge-business/src/main/kotlin/org/projectforge/business/common/YearValueBridge.kt Type : Hibernate Search ValueBridge · Objectif : Pont Date → année entière · Source : projectforge-business/src/main/kotlin/org/projectforge/business/common/YearValueBridge.kt 34 lignes · 9 code · 22 commentaires · 3 vides
Un pont minimal Hibernate Search ValueBridge<LocalDate, Int> qui extrait uniquement le composant année d'un LocalDate pour l'indexation. Permet des recherches basées sur l'année (ex. "2024") dans les champs de date sans indexer la chaîne de date complète.

Signature du pont

class YearValueBridge : ValueBridge<LocalDate, Int>
  • Type d'entrée : LocalDate (le champ date de l'entité, nullable)
  • Type indexé : Int (l'année sous forme d'entier, nullable)
  • Unidirectionnel : Implémente uniquement toIndexedValue (indexation uniquement, pas de lecture retour)

toIndexedValue()

override fun toIndexedValue(value: LocalDate?, context: ValueBridgeToIndexedValueContext): Int?

Retourne simplement value?.year — l'année sous forme d'Int. Retourne null si la date d'entrée est nulle.

Cas d'utilisation

Appliqué aux champs de date d'entité où le filtrage ou la recherche par année est le cas d'utilisation principal (ex. dates de facture, saisies de temps, limites d'année fiscale). En indexant uniquement l'année sous forme d'entier, Hibernate Search peut gérer efficacement des requêtes comme :

  • Correspondance exacte d'année : year = 2024
  • Plage d'années : year BETWEEN 2020 AND 2024
  • Comparaison d'années : year >= 2024

C'est plus efficace que d'indexer la chaîne ISO complète de la date et de la parser dans les requêtes, et évite le besoin de fonctions de date au niveau base de données dans les prédicats de recherche.

Justification de conception

Le pont est intentionnellement unidirectionnel (pas d'implémentation de fromIndexedValue) car l'index n'a pas besoin de reconstruire un LocalDate complet à partir de l'année stockée. Les requêtes de projection qui ont besoin du champ date original peuvent le lire directement depuis l'entité plutôt que depuis l'index.

Utiliser Int comme type indexé (plutôt que String) permet les requêtes de plage numérique et les comparaisons nativement dans Hibernate Search, ce qui est plus performant que les requêtes de plage basées sur des chaînes.
