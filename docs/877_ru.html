#877: YearValueBridge.kt

projectforge-business/src/main/kotlin/org/projectforge/business/common/YearValueBridge.kt Тип: Hibernate Search ValueBridge · Назначение: Мост Date → целое число года · Исходник: projectforge-business/src/main/kotlin/org/projectforge/business/common/YearValueBridge.kt 34 строки · 9 кода · 22 комментария · 3 пустых
Минимальный мост Hibernate Search ValueBridge<LocalDate, Int>, который извлекает только компонент года из LocalDate для индексации. Позволяет выполнять поисковые запросы на основе года (например, «2024») по полям даты без индексации полной строки даты.

Сигнатура моста

class YearValueBridge : ValueBridge<LocalDate, Int>
  • Входной тип: LocalDate (поле даты сущности, допускает null)
  • Индексируемый тип: Int (год в виде целого числа, допускает null)
  • Однонаправленный: Реализует только toIndexedValue (только индексация, без обратного чтения)

toIndexedValue()

override fun toIndexedValue(value: LocalDate?, context: ValueBridgeToIndexedValueContext): Int?

Просто возвращает value?.year — год в виде Int. Возвращает null, если входная дата равна null.

Сценарий использования

Применяется к полям дат сущностей, где фильтрация или поиск по году является основным сценарием (например, даты счетов, записи табеля учёта времени, границы финансового года). Индексируя только год в виде целого числа, Hibernate Search может эффективно обрабатывать запросы, такие как:

  • Точное совпадение года: year = 2024
  • Диапазон годов: year BETWEEN 2020 AND 2024
  • Сравнение годов: year >= 2024

Это более эффективно, чем индексация полной строки даты в формате ISO и её разбор в запросах, а также позволяет избежать необходимости использования функций работы с датами на уровне базы данных в предикатах поиска.

Обоснование дизайна

Мост намеренно сделан однонаправленным (без реализации fromIndexedValue), потому что индексу не нужно восстанавливать полный LocalDate из сохранённого года. Запросы проекций, которым требуется исходное поле даты, могут читать его напрямую из сущности, а не из индекса.

Использование Int в качестве индексируемого типа (вместо String) позволяет выполнять числовые запросы диапазона и сравнения нативно в Hibernate Search, что более производительно, чем строковые запросы диапазона.
