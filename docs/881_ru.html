#881: DvelopConfiguration.kt

projectforge-business/src/main/kotlin/org/projectforge/business/dvelop/DvelopConfiguration.kt

Тип: Spring @Configuration класс — держатель свойств

Назначение: Содержит конфигурацию подключения и аутентификации для интеграции ProjectForge с D-velop (базовый URI, ключ API и название организации).

Путь к исходнику: projectforge-business/src/main/kotlin/org/projectforge/business/dvelop/DvelopConfiguration.kt

56 строк · 19 кода · 31 комментарий · 6 пустых

Класс конфигурации Spring, который считывает настройки подключения к D-velop из файла свойств приложения. Интеграция с D-velop обеспечивает двунаправленную синхронизацию TradingPartners (клиентов, поставщиков, партнёров) между ProjectForge и платформой D-velop. Этот класс служит простым держателем свойств с удобным методом isConfigured(), используемым для включения функций D-velop.

Свойства

СвойствоИсточникТипОписание
baseUriprojectforge.dvelop.baseUriStringБазовый URL конечной точки REST API D-velop
apiKeyprojectforge.dvelop.apiKeyStringКлюч API, используемый для аутентификации при обращении к API D-velop
organizationNameprojectforge.dvelop.organizationStringЕсли указано, все сущности TradingPartner будут привязаны к этой организации D-velop по ID

Ключевой метод

fun isConfigured(): Boolean

Возвращает true только если оба поля baseUri и apiKey непустые. Это условие определяет, активны ли функции синхронизации с D-velop. Все сервисы D-velop должны проверять это перед выполнением вызовов API.

Архитектурные заметки

  • Аннотирован как @Configuration (не @ConfigurationProperties), что делает его управляемым Spring бином с прямой инъекцией через @Value
  • Все свойства объявлены как lateinit var — они должны быть указаны в файле свойств приложения для его запуска
  • В комментарии к свойству organizationName сказано "указывается по ID", но поле называется "Name" — это известное небольшое несоответствие в именовании
  • Изначально этот класс находился в projectforge-rest, а позже был перемещён в projectforge-business
