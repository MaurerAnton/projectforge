#882: ExtractPFTradingPartners.kt

projectforge-business/src/main/kotlin/org/projectforge/business/dvelop/ExtractPFTradingPartners.kt

Tipo: Spring @Service — Motor de extracción de datos

Propósito: Extrae socios comerciales (proveedores, clientes) de las tablas de la base de datos financiera de ProjectForge y los convierte en objetos TradingPartner adecuados para la importación inicial en D-velop.

Ruta de origen: projectforge-business/src/main/kotlin/org/projectforge/business/dvelop/ExtractPFTradingPartners.kt

385 líneas · 319 código · 38 comentarios · 28 en blanco

Actúa como el puente entre los datos financieros heredados de ProjectForge (facturas de entrada, facturas de salida y datos maestros de clientes) y el modelo de socios comerciales de D-velop. Escanea 5 años de datos de facturas, desduplica entidades entre cuentas, maneja el patrón de cuentas "diversas" (varios), analiza direcciones de facturación en texto libre en campos estructurados y clasifica las entidades como PROVEEDOR, CLIENTE o SOCIO. También proporciona funcionalidad de exportación a Excel para conciliación.

Arquitectura

Un acumulador mutable que recopila los socios comerciales extraídos durante el proceso de extracción en múltiples fases:

Fases de extracción

Fase 1: extractTradingVendors(invoices)

Procesa EingangsrechnungDO (facturas de entrada/acreedores):

  • Omite facturas sin un nombre de kreditor o asignación de konto
  • Cuentas "Diversas": Si la descripción de la cuenta contiene "divers", cada nombre de proveedor único recibe un nuevo número de socio sintético (de nextVal) porque múltiples acreedores comparten la misma cuenta
  • Cuentas normales: Un socio por número de cuenta; el importCode se establece en el número de cuenta para referencia cruzada durante fases posteriores
  • Todos los proveedores obtienen datevKonto configurado con el número de cuenta y se anteponen observaciones con información de la cuenta

Fase 2: extractTradingCustomersInvoices(invoices, context)

Procesa RechnungDO (facturas de salida/clientes):

  • Si la factura tiene un kunde (cliente) vinculado, delega en handleKunde()
  • Si no hay cliente pero existe una cuenta, intenta coincidir con proveedores existentes (actualizándolos a SOCIO) o crea nuevas entradas de cliente
  • Omite cuentas "diversas" (no se necesita socio comercial)

Fase 3: extractTradingCustomers(customers, context)

Procesa KundeDO (datos maestros de clientes) para cualquier cliente no capturado ya a través de facturas. Llama a context.cleanUp() al final.

Lógica central de desduplicación: handleKunde()

El método más complejo de este servicio. Para cada KundeDO:

  1. Verifica si ya existe un cliente con el mismo número → omite la creación, opcionalmente completa datevKonto
  2. Verifica si la cuenta coincide con un proveedor existente → actualiza el proveedor a SOCIO, reasigna el número de cliente como número principal
  3. De lo contrario, crea un nuevo cliente; los clientes activos son aquellos con estado ACQUISITION o ACTIVE (o nulo)

Análisis de direcciones: checkBillAddress()

Analiza direcciones de facturación en texto libre de las cadenas customerAddress de las facturas utilizando una heurística ascendente:

  1. Divide la dirección en líneas no vacías
  2. Filtra las líneas iniciales que coinciden con palabras de relleno conocidas ("Herr", "Frau", "Firma", "An", "Portal", "Klinikdienst")
  3. Última línea: país o código postal+ciudad (intenta extractZipCodeCity())
  4. Penúltima: línea de calle
  5. Cualquier línea restante se antepone a billToAddressAdditional

extractZipCodeCity(line)

Utiliza un patrón regex ^[0-9 ]{5,10} para extraer un código postal alemán de 5+ dígitos. Elimina los prefijos de país "D-" y "D ". Devuelve Pair<String, String> de (código postal, ciudad) o nulo si no hay coincidencia.

Exportación a Excel: extractTradingPartnersAsExcel()

Crea un libro de Excel de dos hojas usando ExcelWorkbook:

  • Hoja 1: "D.velop TradingPartners" — la lista pasada como parámetro
  • Hoja 2: "ProjectForge TradingPartners" — lista recién extraída de la base de datos

Las columnas incluyen número, datevKonto, importCode, tipo, empresa, nombre corto, observaciones, activo y todos los campos de dirección de facturación. Los valores de enumeración (contactType, type, active) se resuelven a su representación de cadena value.
