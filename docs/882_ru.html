#882: ExtractPFTradingPartners.kt

projectforge-business/src/main/kotlin/org/projectforge/business/dvelop/ExtractPFTradingPartners.kt

Тип: Spring @Service — механизм извлечения данных

Назначение: Извлекает торговых партнёров (поставщиков, клиентов) из финансовых таблиц базы данных ProjectForge и преобразует их в объекты TradingPartner, пригодные для первоначального импорта в D-velop.

Путь к исходнику: projectforge-business/src/main/kotlin/org/projectforge/business/dvelop/ExtractPFTradingPartners.kt

385 строк · 319 кода · 38 комментариев · 28 пустых

Выступает в качестве моста между устаревшими финансовыми данными ProjectForge (входящие счета, исходящие счета и основные данные клиентов) и моделью торговых партнёров D-velop. Он сканирует 5 лет данных счетов, дедублицирует сущности по счетам, обрабатывает шаблон счёта "разное", разбирает текстовые платёжные адреса в структурированные поля и классифицирует сущности как ПОСТАВЩИК, КЛИЕНТ или ПАРТНЁР. Также предоставляет функциональность экспорта в Excel для сверки.

Архитектура

Внутренний класс: Context

Изменяемый аккумулятор, который собирает извлечённых торговых партнёров в процессе многофазного извлечения:

Фазы извлечения

Фаза 1: extractTradingVendors(invoices)

Обрабатывает EingangsrechnungDO (входящие/кредиторские счета):

  • Пропускает счета без имени kreditor или назначения konto
  • Счета "Разное": Если описание счёта содержит "разное", каждое уникальное имя кредитора получает новый синтетический номер партнёра (из nextVal), поскольку несколько кредиторов используют один и тот же счёт
  • Обычные счета: Один партнёр на номер счёта; importCode устанавливается равным номеру счёта для перекрёстных ссылок на последующих фазах
  • Все поставщики получают datevKonto, установленный на номер счёта, а к примечаниям добавляется информация о счёте

Фаза 2: extractTradingCustomersInvoices(invoices, context)

Обрабатывает RechnungDO (исходящие/клиентские счета):

  • Если счёт имеет связанного kunde (клиента), делегирует обработку handleKunde()
  • Если клиента нет, но есть счёт (konto), пытается сопоставить существующих поставщиков (повышая их до ПАРТНЁРА) или создаёт новые записи клиентов
  • Пропускает счета "разное" (торговый партнёр не требуется)

Фаза 3: extractTradingCustomers(customers, context)

Обрабатывает KundeDO (основные данные клиентов) для клиентов, ещё не захваченных через счета. В конце вызывает context.cleanUp().

Основная логика дедубликации: handleKunde()

Самый сложный метод в этом сервисе. Для каждого KundeDO:

  1. Проверяет, существует ли уже клиент с таким же номером → пропускает создание, опционально заполняя datevKonto
  2. Проверяет, соответствует ли счёт существующему поставщику → повышает поставщика до ПАРТНЁРА, переназначает номер клиента как основной номер
  3. В противном случае создаёт нового клиента; активными клиентами считаются те, у кого статус ACQUISITION или ACTIVE (или null)

Разбор адреса: checkBillAddress()

Разбирает текстовые платёжные адреса из строк customerAddress счетов, используя эвристику снизу вверх:

  1. Разделяет адрес на непустые строки
  2. Отфильтровывает начальные строки, соответствующие известным словам-заполнителям ("Господин", "Госпожа", "Компания", "Кому", "Портал", "Клиникдинст")
  3. Последняя строка: страна или индекс+город (пытается использовать extractZipCodeCity())
  4. Предпоследняя: строка с улицей
  5. Любые оставшиеся строки добавляются в начало billToAddressAdditional

extractZipCodeCity(line)

Использует регулярное выражение ^[0-9 ]{5,10} для извлечения немецкого почтового индекса из 5+ цифр. Удаляет префиксы страны "D-" и "D ". Возвращает Pair<String, String> (индекс, город) или null, если совпадения нет.

Экспорт в Excel: extractTradingPartnersAsExcel()

Создаёт книгу Excel с двумя листами, используя ExcelWorkbook:

  • Лист 1: "D.velop TradingPartners" — список, переданный как параметр
  • Лист 2: "ProjectForge TradingPartners" — свежеизвлечённый список из базы данных

Колонки включают номер, datevKonto, importCode, тип, компанию, краткое имя, примечания, активность и все поля платёжного адреса. Значения перечислений (contactType, type, active) преобразуются в их строковое представление value.
