Zweck: Stellt einen Geschäftspartner (Lieferant, Kunde oder beides) in der D-velop-Plattform dar. Dies ist die primäre Entität, die während der Synchronisation zwischen ProjectForge und D-velop übertragen wird.

201 Zeilen · 103 Code · 72 Kommentare · 26 leer

Das zentrale Domänenmodell für die D-velop-Integration. Ein Geschäftspartner repräsentiert eine Geschäftseinheit (Unternehmen oder Person), mit der ProjectForge Rechnungen austauscht – Lieferanten (Vendoren), Kunden oder Entitäten, die beides sind. Diese Klasse bildet direkt die JSON-Struktur der D-velop-REST-API für Geschäftspartner ab und enthält alle Felder, die für die Adressverwaltung (Rechnungs-, Liefer- und physische Adressen), Kontaktdaten, organisatorische Zuordnung und einen benutzerdefinierten Feldmechanismus benötigt werden, der die DATEV-Kontonummer von ProjectForge mit der benutzerdefinierten Feld-API von D-velop verbindet.

Enum-Wert-Wrapper

D-velop verwendet enum-ähnliche Wertobjekte anstelle von einfachen Zeichenketten. ProjectForge kapselt diese als innere Klassen:

Innere KlasseEnum-WerteJSON-Struktur
TypeVENDOR, CUSTOMER, PARTNER{ "value": "VENDOR" }
ContactTypeCOMPANY, PRIVATE{ "value": "COMPANY" }
ActiveTRUE, FALSE{ "value": "TRUE" }
Organizationid, number?, name?{ "id": "...", "number": null, "name": null }

Organization implementiert equals() und hashCode() ausschließlich basierend auf id für die mengenbasierte Deduplizierung.

Begleitobjekt

companion object {
    var datevKontoFieldId: String? = null
}

Die datevKontoFieldId ist eine global gecachte ID der benutzerdefinierten Felddefinition von D-velop für "datevKonto". Sie wird einmal während des D-velop-Bootstrappings gesetzt (durch Ermitteln der benutzerdefinierten Felddefinitionen) und dann von der Eigenschaft customFields verwendet, um die DATEV-Kontonummer über den benutzerdefinierten Feldmechanismus von D-velop zu serialisieren/deserialisieren.

Mechanismus für benutzerdefinierte Felder

Die Eigenschaft customFields mit benutzerdefiniertem Getter/Setter ist die Brücke zwischen dem datevKonto-Feld von ProjectForge und der generischen API für benutzerdefinierte Felder von D-velop:

Getter

get() {
    if (datevKonto == null || datevKontoFieldId == null) return null
    return mapOf(datevKontoFieldId!! to CustomField(
        configID = datevKontoFieldId!!,
        name = "datevKonto",
        value = datevKonto
    ))
}

Wenn eine DATEV-Kontonummer gesetzt ist und die datevKontoFieldId bekannt ist, wird eine Map mit einem einzelnen Eintrag erstellt, der den Wrapper für das benutzerdefinierte Feld enthält.

Setter

set(value) {
    value?.values?.find { it.name == "datevKonto" }?.value?.let {
        datevKonto = it as Int?
    }
    if (value == null) { datevKonto = null }
}

Beim Deserialisieren von D-velop-JSON-Antworten wird das benutzerdefinierte Feld "datevKonto" gefunden und sein ganzzahliger Wert extrahiert.

Architekturnotizen

  • @JsonIgnore auf datevKonto verhindert die direkte Serialisierung – es muss über den customFields-Mechanismus erfolgen
  • Alle Enum-Werte sind in Containerobjekte (Type(value)) eingekapselt, um der JSON-Struktur von D-velop {"value": "..."} zu entsprechen
  • isBillToAddressEmpty ist mit @JsonIgnore annotiert, um die Serialisierung zu verhindern
  • Die Klasse verwendet reguläre var-Eigenschaften (keine Datenklasse), da sie benutzerdefinierte Getter/Setter und eine Begleitobjektlogik hat
  • Die Adresse ist auf drei separate Gruppen aufgeteilt: physisch (street/zip/city), Rechnung (billTo*) und Lieferung (shipTo*)
