El modelo de dominio central para la integración con D-velop. Un socio comercial representa una entidad empresarial (empresa o persona) con la que ProjectForge intercambia facturas: proveedores, clientes o entidades que son ambas cosas. Esta clase se asigna directamente a la estructura JSON de la API REST de D-velop para socios comerciales e incluye todos los campos necesarios para la gestión de direcciones (dirección de facturación, dirección de envío y direcciones físicas), información de contacto, asignación organizativa y un mecanismo de campos personalizados que conecta el número de cuenta DATEV de ProjectForge con la API de campos personalizados de D-velop.

Contenedores de valores Enum

D-velop utiliza objetos de valor similares a enumeraciones en lugar de cadenas simples. ProjectForge los envuelve como clases internas:

Organization implementa equals() y hashCode() basándose únicamente en id para la deduplicación basada en conjuntos.

Objeto complementario

companion object {
    var datevKontoFieldId: String? = null
}

El datevKontoFieldId es un ID almacenado en caché global de la definición de campo personalizado de D-velop para "datevKonto". Se establece una vez durante el arranque de D-velop (descubriendo las definiciones de campos personalizados) y luego lo utiliza la propiedad customFields para serializar/deserializar el número de cuenta DATEV a través del mecanismo de campos personalizados de D-velop.

Mecanismo de campos personalizados

La propiedad customFields con getter/setter personalizado es el puente entre el campo datevKonto de ProjectForge y la API genérica de campos personalizados de D-velop:

Getter

get() {
    if (datevKonto == null || datevKontoFieldId == null) return null
    return mapOf(datevKontoFieldId!! to CustomField(
        configID = datevKontoFieldId!!,
        name = "datevKonto",
        value = datevKonto
    ))
}

Si se ha establecido un número de cuenta DATEV y se conoce el datevKontoFieldId, crea un mapa de una sola entrada con el contenedor del campo personalizado.

Setter

set(value) {
    value?.values?.find { it.name == "datevKonto" }?.value?.let {
        datevKonto = it as Int?
    }
    if (value == null) { datevKonto = null }
}

Al deserializar las respuestas JSON de D-velop, busca el campo personalizado "datevKonto" y extrae su valor entero.

Notas de arquitectura

  • @JsonIgnore en datevKonto evita que se serialice directamente; debe pasar a través del mecanismo customFields
  • Todos los valores enum están envueltos en objetos contenedores (Type(value)) para que coincidan con la estructura JSON de D-velop {"value": "..."}
  • isBillToAddressEmpty está anotado con @JsonIgnore para evitar la serialización
  • La clase utiliza propiedades var regulares (no una clase de datos) porque tiene getters/setters personalizados y lógica de objeto complementario
  • La dirección se divide en tres grupos separados: física (street/zip/city), facturación (billTo*) y envío (shipTo*)
