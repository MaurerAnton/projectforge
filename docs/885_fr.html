Le modèle de domaine central pour l'intégration D-velop. Un partenaire commercial représente une entité commerciale (entreprise ou personne) avec laquelle ProjectForge échange des factures — fournisseurs, clients, ou entités qui sont les deux. Cette classe correspond directement à la structure JSON de l'API REST de D-velop pour les partenaires commerciaux et inclut tous les champs nécessaires à la gestion des adresses (adresse de facturation, adresse de livraison et adresse physique), aux coordonnées, à l'affectation organisationnelle et à un mécanisme de champ personnalisé qui fait le pont entre le numéro de compte DATEV de ProjectForge et l'API de champs personnalisés de D-velop.

Wrappers de valeurs d'énumération

D-velop utilise des objets de valeur de type énumération plutôt que des chaînes simples. ProjectForge les encapsule sous forme de classes internes :

Classe interneValeurs d'énumérationStructure JSON
TypeVENDOR, CUSTOMER, PARTNER{ "value": "VENDOR" }
ContactTypeCOMPANY, PRIVATE{ "value": "COMPANY" }
ActiveTRUE, FALSE{ "value": "TRUE" }
Organizationid, number?, name?{ "id": "...", "number": null, "name": null }

Organization implémente equals() et hashCode() uniquement sur la base de id pour la déduplication basée sur les ensembles.

Objet compagnon

companion object {
    var datevKontoFieldId: String? = null
}

Le datevKontoFieldId est un ID mis en cache globalement de la définition de champ personnalisé D-velop pour "datevKonto". Il est défini une fois lors du démarrage de D-velop (en découvrant les définitions de champs personnalisés), puis utilisé par la propriété customFields pour sérialiser/désérialiser le numéro de compte DATEV via le mécanisme de champ personnalisé de D-velop.

Mécanisme de champs personnalisés

La propriété customFields avec un getter/setter personnalisé est le pont entre le champ datevKonto de ProjectForge et l'API générique de champs personnalisés de D-velop :

Getter

get() {
    if (datevKonto == null || datevKontoFieldId == null) return null
    return mapOf(datevKontoFieldId!! to CustomField(
        configID = datevKontoFieldId!!,
        name = "datevKonto",
        value = datevKonto
    ))
}

Si un numéro de compte DATEV est défini et que le datevKontoFieldId est connu, il crée une carte à une seule entrée avec le wrapper de champ personnalisé.

Setter

set(value) {
    value?.values?.find { it.name == "datevKonto" }?.value?.let {
        datevKonto = it as Int?
    }
    if (value == null) { datevKonto = null }
}

Lors de la désérialisation des réponses JSON de D-velop, trouve le champ personnalisé "datevKonto" et extrait sa valeur entière.

Notes d'architecture

  • @JsonIgnore sur datevKonto l'empêche d'être sérialisé directement — il doit passer par le mécanisme customFields
  • Toutes les valeurs d'énumération sont encapsulées dans des objets conteneurs (Type(value)) pour correspondre à la structure JSON de D-velop {"value": "..."}
  • isBillToAddressEmpty est annoté avec @JsonIgnore pour empêcher la sérialisation
  • La classe utilise des propriétés var classiques (pas une classe de données) car elle a des getters/setters personnalisés et une logique d'objet compagnon
  • L'adresse est répartie en trois groupes distincts : physique (street/zip/city), facturation (billTo*) et livraison (shipTo*)
