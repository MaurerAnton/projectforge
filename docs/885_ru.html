Центральная доменная модель для интеграции с D-velop. Торговый партнер представляет собой бизнес-сущность (компанию или физическое лицо), с которой ProjectForge обменивается счетами: поставщики (вендоры), клиенты или сущности, являющиеся и тем, и другим. Этот класс напрямую отображается на структуру JSON REST API D-velop для торговых партнеров и включает все поля, необходимые для управления адресами (платежный, отгрузочный и физический адреса), контактной информацией, организационной принадлежностью, а также механизм пользовательских полей, который связывает номер счета DATEV из ProjectForge с API пользовательских полей D-velop.

Обертки значений перечислений

D-velop использует объекты значений, подобные перечислениям, а не простые строки. ProjectForge оборачивает их как внутренние классы:

Внутренний классЗначения перечисленияСтруктура JSON
TypeVENDOR, CUSTOMER, PARTNER{ "value": "VENDOR" }
ContactTypeCOMPANY, PRIVATE{ "value": "COMPANY" }
ActiveTRUE, FALSE{ "value": "TRUE" }
Organizationid, number?, name?{ "id": "...", "number": null, "name": null }

Organization реализует equals() и hashCode() исключительно на основе id для дедупликации на основе множеств.

Объект-компаньон

companion object {
    var datevKontoFieldId: String? = null
}

datevKontoFieldId — это глобально кэшированный идентификатор определения пользовательского поля D-velop для "datevKonto". Он устанавливается один раз во время начальной загрузки D-velop (путем обнаружения определений пользовательских полей), а затем используется свойством customFields для сериализации/десериализации номера счета DATEV через механизм пользовательских полей D-velop.

Механизм пользовательских полей

Свойство customFields с пользовательским геттером/сеттером является мостом между полем datevKonto ProjectForge и общим API пользовательских полей D-velop:

Геттер

get() {
    if (datevKonto == null || datevKontoFieldId == null) return null
    return mapOf(datevKontoFieldId!! to CustomField(
        configID = datevKontoFieldId!!,
        name = "datevKonto",
        value = datevKonto
    ))
}

Если номер счета DATEV установлен и datevKontoFieldId известен, создается карта с одной записью, содержащей обертку пользовательского поля.

Сеттер

set(value) {
    value?.values?.find { it.name == "datevKonto" }?.value?.let {
        datevKonto = it as Int?
    }
    if (value == null) { datevKonto = null }
}

При десериализации ответов JSON от D-velop находит пользовательское поле "datevKonto" и извлекает его целочисленное значение.

Архитектурные заметки

  • @JsonIgnore на datevKonto предотвращает его прямую сериализацию — он должен проходить через механизм customFields
  • Все значения перечислений обернуты в объекты-контейнеры (Type(value)) для соответствия структуре JSON D-velop {"value": "..."}
  • isBillToAddressEmpty аннотирован @JsonIgnore для предотвращения сериализации
  • Класс использует обычные свойства var (а не data class), поскольку имеет пользовательские геттеры/сеттеры и логику объекта-компаньона
  • Адрес разделен на три отдельные группы: физический (street/zip/city), платежный (billTo*) и отгрузочный (shipTo*)
