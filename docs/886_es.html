projectforge-business/src/main/kotlin/org/projectforge/business/fibu/AbstractRechnungCache.kt

Tipo: Clase abstracta de Kotlin que extiende AbstractCache — Capa de caché para cálculos de facturas

Propósito: Almacena en caché los totales de facturas precalculados (RechnungInfo) y los cálculos de posiciones (RechnungPosInfo) para evitar recálculos redundantes. Soporta tanto facturas de salida (RechnungDO) como facturas de entrada (EingangsrechnungDO) a través de su parámetro de tipo genérico.

Ruta de origen: projectforge-business/src/main/kotlin/org/projectforge/business/fibu/AbstractRechnungCache.kt

136 líneas · 79 código · 44 comentarios · 13 en blanco

Una caché de rendimiento en memoria sobre el marco AbstractCache. Los cálculos de facturas (totales netos/brutos, desglose de IVA, asignaciones de costos) son costosos porque requieren recorrer todo el árbol de posiciones con búsquedas de asignación de costos. Esta caché almacena objetos RechnungInfo y RechnungPosInfo precalculados, indexados por ID de entidad, con actualización automática mediante el mecanismo de programación de CacheHelper. La caché fue refactorizada de bloques synchronized a ConcurrentHashMap para eliminar un punto muerto.

Parámetros de tipo y constructor

abstract class AbstractRechnungCache(

    protected val rechnungJdbcService: RechnungJdbcService,
) : AbstractCache()
ParámetroDescripción
entityClassLa referencia de clase de Kotlin para el tipo de entidad de factura (RechnungDO::class o EingangsrechnungDO::class) — utilizada para consultas JDBC y registro
rechnungJdbcServiceServicio JDBC para carga masiva eficiente de información de facturas desde la base de datos (evita Hibernate por rendimiento)

Estado interno

CampoTipoDescripción
invoiceInfoMapConcurrentHashMap<Long, RechnungInfo>Caché principal: ID de factura → cálculos agregados de factura
invoicePosInfoMapConcurrentHashMap<Long, RechnungPosInfo>Caché secundaria: ID de posición → cálculos a nivel de posición

Ambos mapas usan ConcurrentHashMap (no bloques sincronizados) — este cambio se realizó en el commit 85d8930b3 para corregir un punto muerto que ocurría cuando las operaciones de caché interactuaban entre sí bajo sincronización.

API pública

update(invoice: AbstractRechnungDO)

Fuerza el recálculo de una sola factura y almacena el resultado en la caché. Se llama cuando se modifica una factura (insertada, actualizada o eliminada a través de la capa DAO). Utiliza RechnungCalculator.calculate(invoice) para calcular valores actualizados.

ensureRechnungInfo(rechnung: AbstractRechnungDO): RechnungInfo

Garantiza que exista un RechnungInfo para la factura dada. Si ya está en caché, devuelve la versión almacenada (y establece rechnung.info). De lo contrario, lo calcula mediante RechnungCalculator, lo almacena en la caché y lo devuelve. Este es el método de acceso preferido: funciona incluso si el árbol de posiciones aún no se ha cargado de forma diferida.

getRechnungInfo(rechnungId: Long?): RechnungInfo?

Devuelve la información de factura almacenada en caché por ID (seguro para nulos en el parámetro ID). Llama a checkRefresh() que asegura que la caché no esté obsoleta.

getRechnungInfo(rechnung: AbstractRechnungDO?): RechnungInfo?

Sobrecarga que extrae el ID de la entidad. Seguro para nulos.

ensureRechnungPosInfo(pos: AbstractRechnungsPositionDO): RechnungPosInfo

Análogo a ensureRechnungInfo pero para posiciones individuales. Asegura que primero exista el RechnungInfo de la factura principal (necesario como contexto), luego calcula la información específica de la posición mediante RechnungCalculator.calculate(posInfo, pos).

getRechnungPosInfo(rechnungPosId: Long?): RechnungPosInfo?

Devuelve la información de posición almacenada en caché por ID. Seguro para nulos.

Actualización de caché (override fun refresh())

Llamada automáticamente por el marco CacheHelper en un temporizador y durante la guardia checkRefresh(). La estrategia de actualización utiliza copia e intercambio para la seguridad en hilos:

  1. Crea nuevas instancias de ConcurrentHashMap (nInvoiceInfoMap, nInvoicePosInfoMap)
  2. Carga masiva de toda la información de facturas mediante rechnungJdbcService.selectRechnungInfos(entityClass) — esto usa JDBC directamente por rendimiento, evitando Hibernate
  3. Puebla ambos mapas desde el conjunto de resultados de JDBC
  4. Intercambia atómicamente los nuevos mapas en lugar de los antiguos

Este enfoque significa que la caché nunca está obsoleta por más de un ciclo de actualización, y las lecturas nunca se bloquean en la operación de actualización.

Notas de arquitectura

  • Subclases concretas: RechnungCache (para RechnungDO) y EingangsrechnungCache (para EingangsrechnungDO), cada una proporcionando solo el parámetro entityClass
  • Utiliza kotlin.reflect.KClass de Kotlin en lugar de Class de Java para seguridad de tipos
  • El campo @Transient lateinit var info en AbstractRechnungDO es el campo complementario que esta caché puebla
  • Durante la actualización, las posiciones sin ID se registran como errores — esto puede ocurrir con facturas clonadas donde los ID de posición aún no se han asignado
  • La utilidad LogDuration rastrea el rendimiento de la actualización en los registros
