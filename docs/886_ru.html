#886: AbstractRechnungCache.kt

projectforge-business/src/main/kotlin/org/projectforge/business/fibu/AbstractRechnungCache.kt

Тип: Абстрактный класс Kotlin, расширяющий AbstractCache — кэш-слой для расчётов счетов

Назначение: Кэширует предварительно рассчитанные итоги по счетам (RechnungInfo) и расчёты по позициям (RechnungPosInfo), чтобы избежать избыточных пересчётов. Поддерживает как исходящие счета (RechnungDO), так и входящие счета (EingangsrechnungDO) через параметр обобщённого типа.

Путь к исходнику: projectforge-business/src/main/kotlin/org/projectforge/business/fibu/AbstractRechnungCache.kt

136 строк · 79 кода · 44 комментария · 13 пустых

Кэш производительности в памяти поверх фреймворка AbstractCache. Расчёты по счетам (итоги нетто/брутто, разбивка НДС, распределение затрат) являются дорогостоящими, поскольку требуют обхода всего дерева позиций с поиском распределения затрат. Этот кэш хранит предварительно вычисленные объекты RechnungInfo и RechnungPosInfo, ключом к которым является ID сущности, с автоматическим обновлением через механизм планирования CacheHelper. Кэш был рефакторизован с блоков synchronized на ConcurrentHashMap для устранения взаимоблокировки.

Параметры типа и конструктор

abstract class AbstractRechnungCache(

    protected val rechnungJdbcService: RechnungJdbcService,
) : AbstractCache()

Обе карты используют ConcurrentHashMap (не синхронизированные блоки) — это изменение было сделано в коммите 85d8930b3 для исправления взаимоблокировки, которая возникала при взаимодействии операций кэша друг с другом в условиях синхронизации.

Публичный API

update(invoice: AbstractRechnungDO)

Принудительно пересчитывает один счёт и сохраняет результат в кэше. Вызывается при изменении счёта (вставка, обновление или удаление через уровень DAO). Использует RechnungCalculator.calculate(invoice) для вычисления актуальных значений.

ensureRechnungInfo(rechnung: AbstractRechnungDO): RechnungInfo

Гарантирует существование RechnungInfo для указанного счёта. Если уже кэширован, возвращает кэшированную версию (и устанавливает rechnung.info). В противном случае вычисляет его через RechnungCalculator, сохраняет в кэше и возвращает. Это предпочтительный метод доступа — он работает даже если дерево позиций ещё не было лениво загружено.

getRechnungInfo(rechnungId: Long?): RechnungInfo?

Возвращает кэшированную информацию о счете по ID (безопасен для null-параметра ID). Вызывает checkRefresh(), который гарантирует, что кэш не устарел.

getRechnungInfo(rechnung: AbstractRechnungDO?): RechnungInfo?

Перегрузка, извлекающая ID из сущности. Безопасна для null.

ensureRechnungPosInfo(pos: AbstractRechnungsPositionDO): RechnungPosInfo

Аналог ensureRechnungInfo, но для отдельных позиций. Сначала гарантирует существование RechnungInfo родительского счёта (необходимо как контекст), затем вычисляет информацию, специфичную для позиции, через RechnungCalculator.calculate(posInfo, pos).

getRechnungPosInfo(rechnungPosId: Long?): RechnungPosInfo?

Возвращает кэшированную информацию о позиции по ID. Безопасен для null.

Обновление кэша (override fun refresh())

Автоматически вызывается фреймворком CacheHelper по таймеру и во время проверки checkRefresh(). Стратегия обновления использует копирование-и-замену для потокобезопасности:

  1. Создаёт новые экземпляры ConcurrentHashMap (nInvoiceInfoMap, nInvoicePosInfoMap)
  2. Массово загружает всю информацию о счетах через rechnungJdbcService.selectRechnungInfos(entityClass) — использует JDBC напрямую для производительности, обходя Hibernate
  3. Заполняет обе карты из набора результатов JDBC
  4. Атомарно заменяет старые карты новыми

Этот подход означает, что кэш никогда не устаревает более чем на один цикл обновления, и операции чтения никогда не блокируются операцией обновления.

Архитектурные заметки

  • Конкретные подклассы: RechnungCache (для RechnungDO) и EingangsrechnungCache (для EingangsrechnungDO), каждый предоставляет только параметр entityClass
  • Использует kotlin.reflect.KClass из Kotlin вместо Java Class для типобезопасности
  • Поле @Transient lateinit var info в AbstractRechnungDO — это сопутствующее поле, которое заполняет данный кэш
  • Во время обновления позиции без ID логируются как ошибки — это может происходить с клонированными счетами, где ID позиций ещё не назначены
  • Утилита LogDuration отслеживает производительность обновления в логах
