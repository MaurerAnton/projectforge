Typ: Kotlin @MappedSuperclass abstrakte JPA-Entität — Basisklasse für alle Rechnungs-Domänenobjekte

Zweck: Definiert das gemeinsame Datenbankschema und die Geschäftslogik sowohl für ausgehende Kundenrechnungen (RechnungDO) als auch für eingehende Kreditorenrechnungen (EingangsrechnungDO) und bietet gemeinsame Felder, Hibernate Search-Indizierung, berechnete Eigenschaften und Positionsverwaltung.

227 Zeilen · 138 Code · 59 Kommentare · 30 leer

Die gemeinsame Datenmodell-Grundlage für alle Rechnungstypen in ProjectForge. Sie erweitert DefaultBaseDO (die Framework-Basisentität mit Prüffeldern wie created, lastUpdate, deleted) und implementiert IRechnung (gemeinsames Rechnungs-Interface) und DisplayNameCapable (für die UI-Darstellung). Sie verwendet JPA @MappedSuperclass, sodass ihre Felder von konkreten Entitätstabellen geerbt werden, ohne eine separate Tabelle zu erstellen. Alle Eigenschaften sind als open deklariert, um den Lazy-Loading-Proxy-Mechanismus von Hibernate zu unterstützen.

uiStatus / uiStatusAsXml

Der Benutzeroberflächenstatus wird als XML in uiStatusAsXml (@Column(length = 10000)) gespeichert und über XmlObjectReader lazy in eine RechnungUIStatus-Instanz deserialisiert. Der Getter cached das deserialisierte Objekt. Mit @NoHistory annotiert, um von der Nachverfolgung ausgeschlossen zu werden.

info (RechnungInfo)

@Transient @CandHIgnore lateinit var info: RechnungInfo

Die berechnete Rechnungszusammenfassung (Netto-/Bruttobeträge, Umsatzsteueraufschlüsselung, Kostenverteilung). Initialisiert von RechnungCalculator und gecached von AbstractRechnungCache. Mit @CandHIgnore markiert, um die Verarbeitung durch Verlauf/Prüfung zu verhindern. Die Prüfung isInfoInitialized verhindert eine erneute Initialisierung.

ensuredInfo

val ensuredInfo: RechnungInfo
    get() {
        if (!isInfoInitialized) { RechnungCalculator.calculate(this) }
        return info
    }

Garantierter Zugriff — falls info noch nicht berechnet wurde (z. B. nach Deserialisierung oder wenn der Cache es nicht vorab befüllt hat), wird die Berechnung bei Bedarf erzwungen.

Hibernate Search / Indizierungsstrategie

AnnotationVerwendung
@GenericFieldDatums- und Zahlenfelder — exakte Filterung, nicht analysierte Volltextsuche
@FullTextFieldTextfelder (betreff, bemerkung, besonderheiten, currency) — analysierte Volltextsuche
@IndexedEmbedded(includeDepth = 1)konto — Indizierung verschachtelter Entitäten mit begrenzter Tiefe
@IndexingDependency(reindexOnUpdate = SHALLOW)konto — nur Neuindizierung, wenn sich das Konto selbst ändert (nicht seine verschachtelten Kinder)
@IndexingDependency(derivedFrom = ...)year — transparent abgeleitet vom Feld datum

Wichtige Geschäftsmethoden

recalculate()

Berechnet zahlungsZielInTagen und discountZahlungsZielInTagen aus datum, faelligkeit und discountMaturity. Wenn datum null ist, werden beide auf null gesetzt.

addPosition(position: AbstractRechnungsPositionDO)

Fügt der Rechnung einen neuen Zeilenartikel mit automatischer Nummernvergabe hinzu:

  1. Stellt sicher, dass die Positionsliste existiert
  2. Ermittelt die maximale vorhandene Positionsnummer und erhöht sie um 1 (oder verwendet 1 für die erste Position)
  3. Setzt die Rückreferenz über setAbstractRechnung()
  4. Fügt zur internen Sammlung über addPositionWithoutCheck() hinzu

hasKostZuweisungen(): Boolean

Gibt true zurück, wenn eine Position dieser Rechnung Kostenverteilungen (kostZuweisungen) hat.

getAbstractPosition(idx: Int): AbstractRechnungsPositionDO?

Gibt die Position am angegebenen 0-basierten Index zurück oder null, wenn außerhalb des gültigen Bereichs.

Architekturnotizen

  • Alle Eigenschaften und Methoden sind open — dies ist entscheidend für den CGLIB-Proxy-Mechanismus von Hibernate und die Kotlin-JPA-Interoperabilität. Commit 8675a1dbe identifizierte dies als ein großes Leistungsproblem, bei dem nicht-offene Kotlin-Eigenschaften Lazy Loading verhinderten und Tausende unnötiger SQL-Abfragen verursachten
  • ID-only-JSON-Serialisierung: Die konto-Beziehung verwendet @JsonSerialize(using = IdOnlySerializer::class), um eine tiefe Serialisierung verschachtelter Entitäten in REST-Antworten zu vermeiden
  • Verlaufsausschluss: uiStatusAsXml ist mit @NoHistory annotiert, da Änderungen am UI-Status nicht im Prüfprotokoll verfolgt werden sollen
  • CanH-Ausschluss: info ist @CandHIgnore, da es sich um einen berechneten Cache-Wert handelt, der möglicherweise noch nicht initialisiert ist
  • Die @PropertyInfo-Annotationen bieten i18n-Schlüssel und Typmetadaten für automatisch generierte UI-Formulare
  • Migration von Java zu Kotlin in Phasen — siehe Verlauf unten
