Tipo: Entidad JPA abstracta @MappedSuperclass de Kotlin — Clase base para todos los objetos de dominio de facturas

Propósito: Define el esquema de base de datos compartido y la lógica de negocio tanto para facturas de clientes salientes (RechnungDO) como para facturas de acreedores entrantes (EingangsrechnungDO), proporcionando campos comunes, indexación de Hibernate Search, propiedades calculadas y gestión de posiciones.

El fundamento del modelo de datos compartido para todos los tipos de facturas en ProjectForge. Extiende DefaultBaseDO (la entidad base del framework con campos de auditoría como created, lastUpdate, deleted) e implementa IRechnung (interfaz de factura compartida) y DisplayNameCapable (para renderizado de UI). Utiliza JPA @MappedSuperclass para que sus campos sean heredados por las tablas de entidades concretas sin crear una tabla separada. Todas las propiedades se declaran open para soportar el mecanismo de proxy de carga diferida de Hibernate.

Calcula zahlungsZielInTagen y discountZahlungsZielInTagen a partir de datum, faelligkeit y discountMaturity. Si datum es nulo, establece ambos en nulo.

addPosition(position: AbstractRechnungsPositionDO)

Añade una nueva partida a la factura con asignación automática de número:

  1. Se asegura de que la lista de posiciones exista
  2. Encuentra el número máximo de posición existente y lo incrementa en 1 (o usa 1 para la primera posición)
  3. Establece la referencia inversa mediante setAbstractRechnung()
  4. Añade a la colección interna mediante addPositionWithoutCheck()

Devuelve true si alguna posición en esta factura tiene asignaciones de costos (kostZuweisungen).

Notas de Arquitectura

  • Todas las propiedades y métodos son open — esto es crítico para el mecanismo de proxy CGLIB de Hibernate y la interoperabilidad Kotlin-JPA. El commit 8675a1dbe identificó esto como un problema importante de rendimiento donde las propiedades de Kotlin no abiertas impedían la carga diferida, causando miles de consultas SQL innecesarias
  • Serialización JSON solo con ID: La relación konto usa @JsonSerialize(using = IdOnlySerializer::class) para evitar la serialización profunda de entidades anidadas en respuestas REST
  • Exclusión de historial: uiStatusAsXml está anotado con @NoHistory porque los cambios de estado de la UI no deben rastrearse en el registro de auditoría
  • Exclusión de CanH: info es @CandHIgnore porque es un valor de caché calculado que puede no estar inicializado aún
  • Las anotaciones @PropertyInfo proporcionan claves de i18n y metadatos de tipo para formularios de UI generados automáticamente
  • Migrado de Java a Kotlin en etapas — ver historial abajo
