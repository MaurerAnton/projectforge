Type : Kotlin @MappedSuperclass entité JPA abstraite — Classe de base pour tous les objets métier de facture

Objectif : Définit le schéma de base de données partagé et la logique métier pour les factures clients sortantes (RechnungDO) et les factures fournisseurs entrantes (EingangsrechnungDO), en fournissant des champs communs, l'indexation Hibernate Search, des propriétés calculées et la gestion des positions.

Le fondement du modèle de données partagé pour tous les types de factures dans ProjectForge. Il étend DefaultBaseDO (l'entité de base du framework avec des champs d'audit comme created, lastUpdate, deleted) et implémente IRechnung (interface de facture partagée) et DisplayNameCapable (pour le rendu UI). Il utilise JPA @MappedSuperclass afin que ses champs soient hérités par les tables d'entités concrètes sans créer de table séparée. Toutes les propriétés sont déclarées open pour prendre en charge le mécanisme de proxy de chargement différé d'Hibernate.

uiStatus / uiStatusAsXml

L'état de l'interface utilisateur est persisté sous forme de XML dans uiStatusAsXml (@Column(length = 10000)) et désérialisé paresseusement en une instance RechnungUIStatus via XmlObjectReader. Le getter met en cache l'objet désérialisé. Annoté avec @NoHistory pour exclure du suivi d'historique.

info (RechnungInfo)

@Transient @CandHIgnore lateinit var info: RechnungInfo

Le résumé calculé de la facture (totaux net/brut, ventilation TVA, affectations des coûts). Initialisé par RechnungCalculator et mis en cache par AbstractRechnungCache. Marqué @CandHIgnore pour empêcher le traitement d'historique/audit. La vérification isInfoInitialized empêche la réinitialisation.

ensuredInfo

val ensuredInfo: RechnungInfo
    get() {
        if (!isInfoInitialized) { RechnungCalculator.calculate(this) }
        return info
    }

Accesseur garanti — si info n'a pas encore été calculé (par exemple, après désérialisation ou lorsque le cache ne l'a pas pré-rempli), il force le calcul à la demande.

Calcule zahlungsZielInTagen et discountZahlungsZielInTagen à partir de datum, faelligkeit et discountMaturity. Si datum est nul, définit les deux à null.

addPosition(position: AbstractRechnungsPositionDO)

Ajoute un nouvel article à la facture avec attribution automatique du numéro :

  1. Vérifie que la liste des positions existe
  2. Trouve le numéro de position maximum existant et l'incrémente de 1 (ou utilise 1 pour la première position)
  3. Définit la référence arrière via setAbstractRechnung()
  4. Ajoute à la collection interne via addPositionWithoutCheck()

Notes d'architecture

  • Toutes les propriétés et méthodes sont open — ceci est critique pour le mécanisme de proxy CGLIB d'Hibernate et l'interopérabilité Kotlin-JPA. Le commit 8675a1dbe a identifié cela comme un problème de performance majeur où les propriétés Kotlin non-open empêchaient le chargement différé, provoquant des milliers de requêtes SQL inutiles
  • Sérialisation JSON par ID uniquement : La relation konto utilise @JsonSerialize(using = IdOnlySerializer::class) pour éviter la sérialisation profonde des entités imbriquées dans les réponses REST
  • Exclusion d'historique : uiStatusAsXml est annoté avec @NoHistory car les changements d'état de l'interface utilisateur ne doivent pas être suivis dans le journal d'audit
  • Exclusion CanH : info est @CandHIgnore car c'est une valeur de cache calculée qui peut ne pas encore être initialisée
  • Les annotations @PropertyInfo fournissent des clés i18n et des métadonnées de type pour les formulaires d'interface utilisateur générés automatiquement
  • Migré de Java vers Kotlin par étapes — voir l'historique ci-dessous
