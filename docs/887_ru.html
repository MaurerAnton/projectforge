Фундамент общей модели данных для всех типов счетов в ProjectForge. Расширяет DefaultBaseDO (базовую сущность фреймворка с полями аудита, такими как created, lastUpdate, deleted) и реализует IRechnung (общий интерфейс счёта) и DisplayNameCapable (для отображения в UI). Использует JPA @MappedSuperclass, поэтому его поля наследуются конкретными таблицами сущностей без создания отдельной таблицы. Все свойства объявлены как open для поддержки механизма прокси-объектов Hibernate с ленивой загрузкой.

info (RechnungInfo)

@Transient @CandHIgnore lateinit var info: RechnungInfo

Вычисляемая сводка по счёту (итоги нетто/брутто, разбивка НДС, распределение затрат). Инициализируется RechnungCalculator и кэшируется AbstractRechnungCache. Помечен @CandHIgnore для предотвращения обработки историей/аудитом. Проверка isInfoInitialized предотвращает повторную инициализацию.

Гарантированный доступ — если info ещё не был вычислен (например, после десериализации или когда кэш не заполнил его), принудительно вычисляет по требованию.

Ключевые бизнес-методы

recalculate()

Вычисляет zahlungsZielInTagen и discountZahlungsZielInTagen из datum, faelligkeit и discountMaturity. Если datum равен null, устанавливает оба значения в null.

addPosition(position: AbstractRechnungsPositionDO)

Добавляет новую позицию в счёт с автоматическим назначением номера:

  1. Проверяет, что список позиций существует
  2. Находит максимальный существующий номер позиции и увеличивает его на 1 (или использует 1 для первой позиции)
  3. Устанавливает обратную ссылку через setAbstractRechnung()
  4. Добавляет во внутреннюю коллекцию через addPositionWithoutCheck()

hasKostZuweisungen(): Boolean

Возвращает true, если любая позиция в этом счёте имеет назначения затрат (kostZuweisungen).

getAbstractPosition(idx: Int): AbstractRechnungsPositionDO?

Возвращает позицию по указанному 0-индексированному индексу или null, если индекс выходит за пределы.

Архитектурные заметки

  • Все свойства и методы объявлены как open — это критически важно для механизма прокси CGLIB Hibernate и взаимодействия Kotlin-JPA. Коммит 8675a1dbe определил это как серьёзную проблему производительности, где не-open свойства Kotlin препятствовали ленивой загрузке, вызывая тысячи ненужных SQL-запросов
  • Сериализация JSON только по ID: Связь konto использует @JsonSerialize(using = IdOnlySerializer::class) для избежания глубокой сериализации вложенных сущностей в REST-ответах
  • Исключение из истории: uiStatusAsXml аннотирован @NoHistory, так как изменения состояния UI не должны отслеживаться в журнале аудита
  • Исключение CanH: info помечен @CandHIgnore, так как это вычисляемое кэшированное значение, которое может быть ещё не инициализировано
  • Аннотации @PropertyInfo предоставляют ключи i18n и метаданные типов для автоматически генерируемых форм UI
  • Мигрирован с Java на Kotlin поэтапно — см. историю ниже
