Gemeinsam genutztes Hilfsobjekt, das Datenbank-Filterkriterien-Builder und Validierungslogik bereitstellt, die sowohl von AuftragDao (Aufträge) als auch von RechnungDao (Rechnungen) verwendet werden. Zentralisiert gemeinsame Muster wie die Filterung nach Leistungszeitraum, die Erstellung von Datumsbereichsabfragen und die Validierung beim Speichern von Rechnungen (Fälligkeitsberechnung, Konsistenz von Zahlungsdatum/-betrag).

Öffentliche Methoden

createCriterionForPeriodOfPerformance(myFilter)

Rückgabe: Optional<DBPredicate>

Erstellt ein Prädikat zum Filtern nach Überschneidung des Leistungszeitraums. Verwendet die Filterfelder periodOfPerformanceStartDate und periodOfPerformanceEndDate. Die Logik prüft auf überlappende Datumsbereiche:

  • Beide Daten angegeben → popEnd >= startDate AND popBegin <= endDate
  • Nur Startdatum → popEnd >= startDate
  • Nur Enddatum → popBegin <= endDate
  • Keines → leer

createQueryFilterWithDateRestriction(myFilter)

Rückgabe: QueryFilter

Erstellt einen QueryFilter aus einem RechnungFilter und fügt Datumsbereichsbeschränkungen für das Feld "datum" (Rechnungsdatum) hinzu. Unterstützt Von-Datum, Bis-Datum oder beide Bereiche mittels der Operatoren between, ge und le.

onSaveOrModify(rechnung)

Parameter: AbstractRechnungDO

Hauptvalidierungsmethode, die vor dem Speichern einer Rechnung aufgerufen wird. Delegiert an drei private Helfer:

  • checkAndCalculateFaelligkeit() — Berechnet automatisch faelligkeit (Fälligkeitsdatum) aus rechnungsDatum + zahlungsZielInTagen, jedoch nur, wenn das Fälligkeitsdatum null und die Zahlungsfrist gesetzt ist
  • checkAndCalculateDiscountMaturity() — Berechnet automatisch discountMaturity (Skontofälligkeit) aus rechnungsDatum + discountZahlungsZielInTagen, nur wenn der Skontosatz nicht null/nicht null ist und die Skontofälligkeit null ist
  • validateBezahlDatumAndZahlBetrag() — Erzwingt gegenseitige Konsistenz: Wenn bezahlDatum gesetzt ist, muss zahlBetrag gesetzt (und ungleich null) sein, und umgekehrt. Wirft bei Verstößen eine UserException mit spezifischen i18n-Schlüsseln

Entwurfsnotizen

  • Alle Methoden sind @JvmStatic für nahtlose Java-Interoperabilität
  • Verwendet das Interface SearchFilterWithPeriodOfPerformance für polymorphe Filterbehandlung
  • Fälligkeitsdaten werden mit PFDateTime (für Fälligkeitsdatum) und PFDay (für Skontofälligkeit) berechnet
  • Die Skontofälligkeit wird nur berechnet, wenn discountPercent ungleich null ist; bei null wird keine Skontofälligkeit gesetzt
