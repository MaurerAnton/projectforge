Objeto de utilidad compartido que proporciona constructores de criterios de filtro de base de datos y lógica de validación utilizados tanto por AuftragDao (pedidos) como por RechnungDao (facturas). Centraliza patrones comunes como el filtrado por período de ejecución, la construcción de consultas con rangos de fechas y la validación al guardar facturas (cálculo de vencimiento, consistencia entre fecha de pago y monto).

Métodos públicos

createCriterionForPeriodOfPerformance(myFilter)

Retorna: Optional<DBPredicate>

Construye un predicado para filtrar por superposición de períodos de ejecución. Utiliza los campos periodOfPerformanceStartDate y periodOfPerformanceEndDate del filtro. La lógica verifica rangos de fechas superpuestos:

  • Ambas fechas presentes → popEnd >= startDate AND popBegin <= endDate
  • Solo fecha de inicio → popEnd >= startDate
  • Solo fecha de fin → popBegin <= endDate
  • Ninguna → vacío

createQueryFilterWithDateRestriction(myFilter)

Retorna: QueryFilter

Crea un QueryFilter a partir de un RechnungFilter, añadiendo restricciones de rango de fechas sobre el campo "datum" (fecha de factura). Soporta fecha desde, fecha hasta, o ambos rangos usando los operadores between, ge y le.

onSaveOrModify(rechnung)

Parámetro: AbstractRechnungDO

Método de validación principal llamado antes de persistir cualquier factura. Delega en tres ayudantes privados:

  • checkAndCalculateFaelligkeit() — Calcula automáticamente faelligkeit (fecha de vencimiento) a partir de rechnungsDatum + zahlungsZielInTagen, pero solo si la fecha de vencimiento es nula y el plazo de pago está definido
  • checkAndCalculateDiscountMaturity() — Calcula automáticamente discountMaturity a partir de rechnungsDatum + discountZahlungsZielInTagen, solo cuando el porcentaje de descuento no es nulo/cero y el vencimiento del descuento es nulo
  • validateBezahlDatumAndZahlBetrag() — Asegura consistencia mutua: si bezahlDatum está definido, zahlBetrag debe estar definido (y no ser cero), y viceversa. Lanza UserException con claves i18n específicas en caso de violaciones

Notas de diseño

  • Todos los métodos son @JvmStatic para interoperabilidad fluida con Java
  • Utiliza la interfaz SearchFilterWithPeriodOfPerformance para manejo polimórfico de filtros
  • Las fechas de vencimiento se calculan usando PFDateTime (para fecha de vencimiento) y PFDay (para vencimiento de descuento)
  • El vencimiento del descuento solo se calcula cuando discountPercent no es cero; si es cero, no se establece ningún vencimiento de descuento
