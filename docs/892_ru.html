Основной объект доступа к данным для AuftragDO (заказы/предложения). Расширяет BaseDao<AuftragDO> и предоставляет полные CRUD-операции, расширенную фильтрацию (по статусу, типу позиции, типу оплаты, назначению пользователя, проекту, диапазонам дат), валидацию при вставке/изменении, уведомления по электронной почте, загрузку истории и интеграцию с AuftragsCache. Отвечает за логику «к выставлению счета» и многоуровневую фильтрацию позиций заказа.

Определение класса

@Service
open class AuftragDao : BaseDao<AuftragDO>(AuftragDO::class.java)

Ключевые операции

Запрос и выборка

select(filter, checkAccess) — основной метод запроса, переопределённый из BaseDao. Строит сложный QueryFilter, поддерживающий:

  • Фильтр «Fakturiert»: При ZU_FAKTURIEREN запрашивает заказы/позиции со статусом ABGESCHLOSSEN или достигнутые графики платежей через LEFT JOIN
  • Фильтр по пользователю: Находит заказы, где пользователь является контактным лицом, руководителем проекта, руководителем отдела или менеджером по продажам
  • Фильтр по проекту: isIn по списку проектов
  • Фильтр по дате: between/ge/le по erfassungsDatum (дата создания)
  • Период выполнения: Делегируется AuftragAndRechnungDaoHelper
  • Фильтр по типу позиции: filterPositionsArten с использованием AuftragsPositionsArtFilter
  • Фильтр по статусу позиции: filterPositionsStatus — находит заказы, где хотя бы одна неудалённая позиция имеет заданный статус
  • Фильтр по типу оплаты: filterPositionsPaymentTypes с использованием AuftragsPositionsPaymentTypeFilter
  • Результаты упорядочены по nummer по убыванию

Валидация: onInsertOrModify(obj, operationType)

Применяет бизнес-правила перед сохранением:

  1. nummer не должен быть null
  2. status не должен быть null или OPTIONAL
  3. При вставке: nummer должен быть следующим последовательным номером (без пропусков)
  4. При обновлении: nummer не должен конфликтовать с другим существующим заказом
  5. Должна существовать хотя бы одна позиция
  6. Завершающие пустые позиции (id=null, isEmpty=true) удаляются с конца (но первая позиция никогда не удаляется)
  7. Флаг vollstaendigFakturiert каждой позиции проверяется через checkVollstaendigFakturiert()
  8. Статус UI сериализуется в XML и сохраняется в uiStatusAsXml
  9. Завершающие пустые графики платежей обрезаются
  10. validateDatesInPaymentScheduleWithinPeriodOfPerformanceOfPosition() — проверяет, что все даты графиков платежей находятся в пределах периода выполнения позиции (плюс 3 месяца допуска для конечной даты)
  11. validateAmountsInPaymentScheduleNotGreaterThanNetSumOfPosition() — сумма всех сумм графика платежей для позиции не должна превышать чистую сумму позиции

Управление номерами

  • nextNumber — Возвращает следующий доступный номер заказа (максимальный существующий + 1)
  • getNextNumber(auftrag) — Если заказ уже имеет ID, извлекает его исходный номер для сохранения; в противном случае назначает следующий последовательный номер
  • Начальный номер определён как START_NUMBER = 1

Уведомление: sendNotificationIfRequired(auftrag, operationType, requestUrl)

Отправляет HTML-уведомление по электронной почте контактному лицу при создании/изменении/удалении заказа. Использует шаблон Groovy mail/orderChangeNotification.html. Включает до 10 последних записей истории. Возвращает false, если почта не настроена, не назначено контактное лицо или у контактного лица нет доступа SELECT.

Интеграция с историей

  • addOwnHistoryEntries(obj, context) — Загружает и объединяет историю для всех позиций (включая удалённые) и графиков платежей
  • getHistoryPropertyPrefix(context) — Возвращает "pos#N" для записей истории позиций и "payment#N" для записей истории графиков платежей
  • additionalHistorySearchDOs — Включает AuftragsPositionDO для полнотекстового поиска по истории

Методы поиска

  • getAuftragsPosition(posString) — Разбирает формат "###.##" (номер заказа.номер позиции) и возвращает соответствующую позицию
  • getAuftragsPosition(id) — Находит позицию по её ID в базе данных
  • years — Возвращает массив всех лет с активностью заказов (мин/макс angebotsDatum)
  • buildStatistik(list) — Агрегирует статистику для списка заказов

Вспомогательные методы установки

Методы setContactPerson(), setTask(), setKunde() и setProjekt() разрешают связанные сущности по ID с помощью findOrLoad и устанавливают их в заказе или позиции.

Дополнительные поля поиска

Массив ADDITIONAL_SEARCH_FIELDS расширяет Hibernate Search для индексации полей из связанных сущностей:

contactPerson.username, contactPerson.firstname, contactPerson.lastname,
kunde.name, projekt.name, projekt.kunde.name,
positionen.position, positionen.art, positionen.status,
positionen.titel, positionen.bemerkung, positionen.nettoSumme
