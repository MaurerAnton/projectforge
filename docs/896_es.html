Define las reglas de control de acceso para el libro de pedidos (Auftragsbuch). Extiende UserRightAccessCheck<AuftragDO?> y proporciona un control de acceso detallado y multinivel basado en la pertenencia a grupos de usuarios y la asignación de roles de usuario. Gestiona la visibilidad para personas de contacto, gestores de proyectos, asistentes de proyectos, personal de control y miembros del grupo financiero, con reglas especiales para pedidos completamente facturados y la protección del indicador vollstaendigFakturiert.

Definición de la clase

class AuftragRight : UserRightAccessCheck<AuftragDO?>(
    UserRightId.PM_ORDER_BOOK, UserRightCategory.PM,
    *UserRightServiceImpl.FALSE_READONLY_PARTLYREADWRITE_READWRITE
)

Valores de derecho

Valores disponibles: FALSE, READONLY, PARTLYREADWRITE, READWRITE.

Comportamiento especial de PARTLYREADWRITE: Los usuarios que son miembros de FIBU_ORGA_GROUPS y PROJECT_MANAGER/PROJECT_ASSISTANT solo tienen acceso a sus propios proyectos (asignados por grupos de gestores de proyectos). Elegir READWRITE concede acceso completo a todos los pedidos.

hasSelectAccess(user): Boolean

Devuelve true si el usuario tiene derecho READONLY, PARTLYREADWRITE o READWRITE sobre el ID de derecho PM_ORDER_BOOK. Esto determina si el libro de pedidos es visible como módulo.

hasAccess(user, obj, oldObj, operationType): Boolean

El método central de decisión de acceso con comprobaciones en capas:

Capa 1: Grupo de control

Los miembros de CONTROLLING_GROUP tienen acceso SELECT incondicional. Otros tipos de operación pasan a la siguiente capa.

Capa 2: Comprobación básica de derecho

  • SELECT: requiere READONLY, PARTLYREADWRITE o READWRITE
  • INSERT/UPDATE/DELETE: requiere PARTLYREADWRITE o READWRITE

Capa 3: Protección del indicador vollstaendigFakturiert

Solo los miembros de FINANCE_GROUP pueden cambiar el indicador vollstaendigFakturiert en las posiciones del pedido:

  • En INSERT: cualquier posición con vollstaendigFakturiert == true desencadena AccessException
  • En UPDATE: comparando cada posición con su versión en base de datos (oldObj), cualquier cambio en vollstaendigFakturiert desencadena AccessException
  • Las posiciones eliminadas se omiten
  • Las posiciones recién añadidas (sin dbPosition) se comprueban como en INSERT

Capa 4: Acceso basado en proyecto

Para usuarios que NO están en FIBU_ORGA_GROUPS con derecho READONLY/READWRITE (es decir, gestores de proyectos, asistentes de proyectos o usuarios PARTLYREADWRITE):

  • Asignación directa: El usuario es el contactPerson del pedido → acceso concedido
  • Pertenencia al proyecto: El usuario pertenece al projektManagerGroup del proyecto, es el headOfBusinessManager del proyecto, o es el salesManager del proyecto → acceso concedido
  • Restricción de facturación completa: Si el pedido está completamente facturado (isVollstaendigFakturiert), el acceso se limita a pedidos cuya fecha de fin del período de ejecución (o fecha de cotización como alternativa) esté dentro de MAX_DAYS_OF_VISIBILITY_4_PROJECT_MANGER (1800 días ≈ 5 años)
  • No completamente facturado: Se concede acceso completo
  • Si ninguna de las condiciones anteriores coincide, se deniega el acceso
