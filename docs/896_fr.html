Définit les règles de contrôle d'accès pour le livre des commandes (Auftragsbuch). Étend UserRightAccessCheck<AuftragDO?> et fournit un contrôle d'accès fin et multi-niveaux basé sur l'appartenance à un groupe d'utilisateurs et l'attribution de rôles utilisateur. Gère la visibilité pour les personnes de contact, les chefs de projet, les assistants de projet, le personnel de contrôle et les membres du groupe financier, avec des règles spéciales pour les commandes entièrement facturées et la protection du drapeau vollstaendigFakturiert.

Définition de la classe

class AuftragRight : UserRightAccessCheck<AuftragDO?>(
    UserRightId.PM_ORDER_BOOK, UserRightCategory.PM,
    *UserRightServiceImpl.FALSE_READONLY_PARTLYREADWRITE_READWRITE
)

Valeurs des droits

Valeurs disponibles : FALSE, READONLY, PARTLYREADWRITE, READWRITE.

Comportement spécial de PARTLYREADWRITE : Les utilisateurs membres de FIBU_ORGA_GROUPS et de PROJECT_MANAGER/PROJECT_ASSISTANT n'ont accès qu'à leurs propres projets (assignés par les groupes de chefs de projet). Choisir READWRITE accorde un accès complet à toutes les commandes.

hasSelectAccess(user): Boolean

Retourne true si l'utilisateur dispose du droit READONLY, PARTLYREADWRITE ou READWRITE sur l'ID de droit PM_ORDER_BOOK. Cela détermine si le livre des commandes est visible en tant que module.

hasAccess(user, obj, oldObj, operationType): Boolean

La méthode centrale de décision d'accès avec des vérifications en couches :

Couche 1 : Groupe de contrôle

Les membres de CONTROLLING_GROUP ont un accès SELECT inconditionnel. Les autres types d'opérations passent à la couche suivante.

Couche 2 : Vérification de droit de base

  • SELECT : nécessite READONLY, PARTLYREADWRITE ou READWRITE
  • INSERT/UPDATE/DELETE : nécessite PARTLYREADWRITE ou READWRITE

Couche 3 : Protection du drapeau vollstaendigFakturiert

Seuls les membres de FINANCE_GROUP peuvent modifier le drapeau vollstaendigFakturiert sur les positions de commande :

  • Sur INSERT : toute position avec vollstaendigFakturiert == true déclenche une AccessException
  • Sur UPDATE : en comparant chaque position avec sa version en base de données (oldObj), toute modification de vollstaendigFakturiert déclenche une AccessException
  • Les positions supprimées sont ignorées
  • Les positions nouvellement ajoutées (sans dbPosition) sont vérifiées comme dans INSERT

Couche 4 : Accès basé sur le projet

Pour les utilisateurs qui NE sont PAS dans FIBU_ORGA_GROUPS avec le droit READONLY/READWRITE (c'est-à-dire les chefs de projet, les assistants de projet ou les utilisateurs PARTLYREADWRITE) :

  • Attribution directe : L'utilisateur est le contactPerson de la commande → accès accordé
  • Appartenance au projet : L'utilisateur appartient au projektManagerGroup du projet, est le headOfBusinessManager du projet, ou est le salesManager du projet → accès accordé
  • Restriction de facturation complète : Si la commande est entièrement facturée (isVollstaendigFakturiert), l'accès est limité aux commandes dont la date de fin de période de performance (ou la date de devis comme solution de repli) est dans MAX_DAYS_OF_VISIBILITY_4_PROJECT_MANGER (1800 jours ≈ 5 ans)
  • Non entièrement facturée : L'accès complet est accordé
  • Si aucune des conditions ci-dessus n'est remplie, l'accès est refusé
