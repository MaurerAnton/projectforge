Определяет правила контроля доступа для книги заказов (Auftragsbuch). Расширяет UserRightAccessCheck<AuftragDO?> и обеспечивает детальный многоуровневый контроль доступа на основе членства в группах пользователей и назначения ролей. Управляет видимостью для контактных лиц, руководителей проектов, ассистентов проектов, сотрудников контроллинга и членов финансовой группы, с особыми правилами для полностью выставленных счетов и защиты флага vollstaendigFakturiert.

Определение класса

class AuftragRight : UserRightAccessCheck<AuftragDO?>(
    UserRightId.PM_ORDER_BOOK, UserRightCategory.PM,
    *UserRightServiceImpl.FALSE_READONLY_PARTLYREADWRITE_READWRITE
)

Значения прав

Доступные значения: FALSE, READONLY, PARTLYREADWRITE, READWRITE.

Особое поведение PARTLYREADWRITE: Пользователи, являющиеся членами FIBU_ORGA_GROUPS и PROJECT_MANAGER/PROJECT_ASSISTANT, имеют доступ только к своим собственным проектам (назначенным через группы руководителей проектов). Выбор READWRITE предоставляет полный доступ ко всем заказам.

hasSelectAccess(user): Boolean

Возвращает true, если пользователь имеет право READONLY, PARTLYREADWRITE или READWRITE на идентификатор права PM_ORDER_BOOK. Это определяет, видна ли книга заказов как модуль вообще.

hasAccess(user, obj, oldObj, operationType): Boolean

Основной метод принятия решения о доступе с многоуровневыми проверками:

Уровень 1: Группа контроллинга

Члены CONTROLLING_GROUP имеют безусловный доступ SELECT. Для других типов операций переход к следующему уровню.

Уровень 2: Базовая проверка прав

  • SELECT: требуется READONLY, PARTLYREADWRITE или READWRITE
  • INSERT/UPDATE/DELETE: требуется PARTLYREADWRITE или READWRITE

Уровень 3: Защита флага vollstaendigFakturiert

Только члены FINANCE_GROUP могут изменять флаг vollstaendigFakturiert в позициях заказа:

  • При INSERT: любая позиция с vollstaendigFakturiert == true вызывает AccessException
  • При UPDATE: сравнение каждой позиции с её версией в базе данных (oldObj), любое изменение vollstaendigFakturiert вызывает AccessException
  • Удалённые позиции пропускаются
  • Новые добавленные позиции (без dbPosition) проверяются как при INSERT

Уровень 4: Доступ на основе проекта

Для пользователей, которые НЕ входят в FIBU_ORGA_GROUPS с правом READONLY/READWRITE (т.е. руководители проектов, ассистенты проектов или пользователи PARTLYREADWRITE):

  • Прямое назначение: Пользователь является contactPerson заказа → доступ предоставлен
  • Членство в проекте: Пользователь принадлежит к projektManagerGroup проекта, является headOfBusinessManager проекта или salesManager проекта → доступ предоставлен
  • Ограничение по полностью выставленным счетам: Если заказ полностью выставлен (isVollstaendigFakturiert), доступ ограничен заказами, дата окончания периода выполнения (или дата предложения как запасной вариант) которых находится в пределах MAX_DAYS_OF_VISIBILITY_4_PROJECT_MANGER (1800 дней ≈ 5 лет)
  • Не полностью выставлен: Предоставляется полный доступ
  • Если ни одно из вышеперечисленных условий не выполнено, доступ запрещён
