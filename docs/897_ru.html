Производительный кэш с таймером, который предварительно загружает и поддерживает всю информацию о заказах (Auftrag) для книги заказов. Расширяет AbstractCache с циклом обновления 8 часов. Загружает все неудалённые заказы, их позиции и графики платежей в карты памяти, чтобы избежать повторных запросов к базе данных. Вычисляет суммы по счетам, статус полной выписки счетов, флаги «подлежит выставлению счёта» и отслеживает количество заказов, требующих выставления счёта. Слушает изменения через хуки BaseDOModifiedListener как для AuftragDO, так и для RechnungDO, чтобы аннулировать кэшированные данные. Обрабатывает циклическую зависимость с AuftragDao через пост-конструкционное связывание.

Определение класса

@Service
class AuftragsCache : AbstractCache(8 * TICKS_PER_HOUR)

Инициализация (@PostConstruct init())

Устанавливает синглтон instance, связывает this с auftragDao.auftragsCache и регистрирует два слушателя изменений:

  • Слушатель счетов: Любая вставка/изменение в RechnungDO вызывает setExpired() для аннулирования всего кэша (поскольку счета влияют на суммы по позициям заказов)
  • Слушатель заказов: Любая вставка/изменение в AuftragDO вызывает setExpired()

Аннулирование кэша

  • setExpired() — Переопределяет AbstractCache.setExpired(), чтобы также сбросить toBeInvoicedCounter в null, принуждая к пересчёту при следующем доступе
  • setExpired(order) — То же, что и выше (ранее обновлял отдельные записи; теперь аннулирует весь кэш)
  • Обе реализации слушателей (auftragListener, rechnungListener) вызывают setExpired() при любом изменении

Логика обновления (refresh())

Вызывается, когда истекает TTL кэша (каждые 8 часов) или при ручном аннулировании:

  1. Логирует начало обновления с таймером LogDuration
  2. Загружает все неудалённые позиции заказов через auftragsCacheService.selectNonDeletedAuftragsPositions(), группирует по auftrag.id
  3. Загружает все заказы через auftragsCacheService.selectAuftragsList()
  4. Загружает все неудалённые графики платежей через auftragsCacheService.selectNonDeletedPaymentSchedules(), группирует по auftrag.id
  5. Инициализирует объекты OrderInfo для каждого заказа (вызывая updateFields(order) для копирования базовых данных)
  6. Создаёт объекты OrderPositionInfo для каждой позиции (примечание: конструктор использует AuftragsRechnungCache, который в свою очередь использует AuftragsCache — циклическая зависимость решается запуском кэшей дважды при инициализации)
  7. Назначает позиции и графики платежей каждому заказу, вызывая order.info.calculateAll(order, positions, paymentSchedules)
  8. Атомарно заменяет неизменяемые карты
  9. Сбрасывает toBeInvoicedCounter в null
  10. Логирует время завершения

Потокобезопасность

Карты (orderInfoMap, orderPositionMapByPosId) атомарно заменяются новыми неизменяемыми картами во время обновления. Комментарий «Нет синхронизации, неизменяемая карта» во всех операциях чтения указывает на шаблон снимка только для чтения: при каждом вызове checkRefresh() кэш может перестроить новую карту и заменить ссылку.

Замечания по дизайну

  • Параметр checkRefresh в getOrderInfo(order, checkRefresh) существует для предотвращения взаимоблокировок во время инициализации кэша — когда кэш уже обновляется, рекурсивные вызовы пропускают обновление
  • Циклическая зависимость между AuftragsCache, AuftragsRechnungCache и OrderPositionInfo задокументирована в коммите 51d352133 — решена запуском кэшей дважды при инициализации
  • toBeInvoicedCounter использует шаблон ленивого вычисления с отладочным логированием того, какие номера заказов учитываются
  • Все удобные методы-геттеры вызывают checkRefresh() перед доступом для обеспечения свежести данных
