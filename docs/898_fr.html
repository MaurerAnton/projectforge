Objectif : Fournit un accès base de données en lecture seules hautes performances pour les commandes (AuftragDO), les positions de commande (AuftragsPositionDO) et les échéanciers de paiement (PaymentScheduleDO) en utilisant des requêtes JPQL natives par tuples. Évite l'hydratation complète des entités et la surcharge du chargement paresseux en sélectionnant uniquement les colonnes nécessaires au rendu des listes et au remplissage du cache.

Architecture & Conception

Déclaration du Service

La classe est annotée avec @Service et dépend de PfPersistenceService via @Autowired. Toutes les méthodes utilisent runIsolatedReadOnly pour exécuter les requêtes dans un contexte de persistance frais, empêchant ainsi la pollution du cache de session de l'appelant.

DépendanceTypeRôle
PfPersistenceServiceFrameworkFournit des contextes JPA isolés en lecture seule pour des requêtes par tuples rapides

Méthodes

selectAuftragsList() : List<AuftragDO>

Retourne toutes les commandes (y compris supprimées) avec un ensemble de colonnes sélectionnées. Mappe chaque Tuple vers un AuftragDO partiellement rempli en utilisant les accesseurs TupleUtils. Les clés étrangères (kundeId, projektId, contactPersonId) sont résolues via em.getReference() pour éviter des requêtes supplémentaires — Hibernate retourne un proxy paresseux sans accéder à la base de données.

selectNonDeletedAuftragsPositions() : List<AuftragsPositionDO>

Retourne les positions de commande non supprimées. Suit le même modèle de mappage par tuples avec une optimisation de performance supplémentaire : bemerkung (commentaire) est abrégé à 30 caractères via abbreviate(30), réduisant ainsi l'empreinte mémoire pour les vues de liste. La référence de tâche (taskId) crée un objet TaskDO factice avec uniquement l'ID défini.

selectNonDeletedPaymentSchedules() : List<PaymentScheduleDO>

Retourne les échéanciers de paiement non supprimés, en créant des objets AuftragDO factices (ID uniquement) pour la référence de clé étrangère auftragId.

Définitions des Requêtes (Objet Compagnon)

Trois requêtes JPQL sont définies comme constantes private val dans l'objet compagnon, en utilisant l'interpolation ${AuftragDO::class.simpleName} pour des références d'entité typées :

ConstanteEntité cibleFiltre
SELECT_ORDERSAuftragDOAucun (tous les enregistrements, y compris supprimés)
SELECT_POSITIONSAuftragsPositionDOWHERE deleted = false
SELECT_PAYMENTS_SCHEDULESPaymentScheduleDOWHERE deleted = false

Stratégie de Performance

  • Les requêtes par tuples sélectionnent uniquement les colonnes nécessaires ; aucun graphe d'entité complet n'est chargé.
  • em.getReference() crée des proxies paresseux pour les associations FK, évitant les JOINs.
  • runIsolatedReadOnly garantit que chaque appel dispose d'un contexte de persistance propre, empêchant toute interférence avec la transaction active de l'appelant.
  • L'appel abbreviate(30) sur bemerkung minimise la pression sur le tas pour les grands champs de commentaires lors du rendu des listes.
