Entidad de dominio central que representa una línea de detalle dentro de un AuftragDO (pedido/propuesta). Cada pedido puede tener múltiples posiciones, identificadas de forma única por (auftrag_fk, number). Realiza seguimiento de datos financieros (suma neta, días-persona), estado, tipo de pago, clasificación (art) e indicadores de facturación. Implementa DisplayNameCapable y está completamente indexada por Hibernate Search para capacidades de búsqueda de texto completo.

Propiedades Calculadas

  • displayName — formato "{order.nummer}.{number}", ej. "12345.2"
  • formattedNumber — igual que displayName: "{auftrag?.nummer}.{number}"
  • isEmpty — devuelve true si el título está en blanco Y la suma neta es cero/nula Y el comentario está en blanco
  • hasOwnPeriodOfPerformance() — devuelve true si periodOfPerformanceType == PeriodOfPerformanceType.OWN

Validación

checkVollstaendigFakturiert() — lanza UserException si vollstaendigFakturiert está establecido en true pero el estado no es ABGESCHLOSSEN (solo las posiciones completadas pueden marcarse como totalmente facturadas).

Igualdad y Hashing

La igualdad (y el hash) se basa en number y auftrag.id — dos posiciones se consideran iguales si comparten el mismo número de posición dentro del mismo pedido padre.

Configuración de Hibernate Search

La entidad utiliza @TypeBinding con HibernateSearchAuftragsPositionTypeBinder y un @ClassBridge(name = "position") personalizado. Varios campos llevan @FullTextField (art, forecastType, status, titel, bemerkung) y @GenericField (nettoSumme) para la indexación de Hibernate Search. El puente de clase permite la búsqueda compuesta en campos relacionados con la posición.
