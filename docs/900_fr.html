Entité de domaine centrale représentant une ligne d'article dans un AuftragDO (commande/devis). Chaque commande peut avoir plusieurs positions, identifiées de manière unique par (auftrag_fk, number). Suit les données financières (montant net, jours-personnes), le statut, le type de paiement, la classification (art) et les indicateurs de facturation. Implémente DisplayNameCapable et est entièrement indexée par Hibernate Search pour des capacités de recherche en texte intégral.

Propriétés calculées

  • displayName — format "{order.nummer}.{number}", ex. "12345.2"
  • formattedNumber — identique à displayName : "{auftrag?.nummer}.{number}"
  • isEmpty — retourne true si le titre est vide ET le montant net est nul/zéro ET le commentaire est vide
  • hasOwnPeriodOfPerformance() — retourne true si periodOfPerformanceType == PeriodOfPerformanceType.OWN

Validation

checkVollstaendigFakturiert() — lève une UserException si vollstaendigFakturiert est défini sur true mais que le statut n'est pas ABGESCHLOSSEN (seules les positions terminées peuvent être marquées comme entièrement facturées).

Égalité & Hachage

L'égalité (et le hachage) est basée sur number et auftrag.id — deux positions sont considérées égales si elles partagent le même numéro de position dans la même commande parente.

Configuration Hibernate Search

L'entité utilise @TypeBinding avec HibernateSearchAuftragsPositionTypeBinder et un @ClassBridge(name = "position") personnalisé. Plusieurs champs portent @FullTextField (art, forecastType, status, titel, bemerkung) et @GenericField (nettoSumme) pour l'indexation Hibernate Search. Le pont de classe permet une recherche composite sur les champs liés à la position.

Classes associées

  • Recherche : HibernateSearchAuftragsPositionTypeBinder — liaison de recherche personnalisée
  • JSON : IdOnlySerializer — sérialise les références FK uniquement par ID
