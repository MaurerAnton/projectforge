Основная доменная сущность, представляющая строку в AuftragDO (заказ/предложение). Каждый заказ может содержать несколько позиций, однозначно идентифицируемых по (auftrag_fk, number). Отслеживает финансовые данные (нетто-сумма, человеко-дни), статус, тип оплаты, классификацию (art) и флаги выставления счетов. Реализует DisplayNameCapable и полностью индексируется Hibernate Search для полнотекстового поиска.

Вычисляемые свойства

  • displayName — формат "{order.nummer}.{number}", например "12345.2"
  • formattedNumber — то же, что displayName: "{auftrag?.nummer}.{number}"
  • isEmpty — возвращает true, если название пустое И нетто-сумма равна нулю/null И комментарий пустой
  • hasOwnPeriodOfPerformance() — возвращает true, если periodOfPerformanceType == PeriodOfPerformanceType.OWN

Валидация

checkVollstaendigFakturiert() — выбрасывает UserException, если vollstaendigFakturiert установлено в true, но статус не ABGESCHLOSSEN (только завершённые позиции могут быть помечены как полностью выставленные).

Равенство и хеширование

Равенство (и хеш) основано на number и auftrag.id — две позиции считаются равными, если у них одинаковый номер позиции в одном родительском заказе.

Конфигурация Hibernate Search

Сущность использует @TypeBinding с HibernateSearchAuftragsPositionTypeBinder и пользовательский @ClassBridge(name = "position"). Несколько полей имеют @FullTextField (art, forecastType, status, titel, bemerkung) и @GenericField (nettoSumme) для индексации Hibernate Search. Мост класса обеспечивает составной поиск по полям, связанным с позицией.

Связанные классы

  • Родитель: AuftragDO — заказ, содержащий эту позицию
  • Перечисления: AuftragsPositionsArt, AuftragsPositionsPaymentType, AuftragsStatus, AuftragForecastType, PeriodOfPerformanceType, ModeOfPaymentType
  • Кэш: AuftragsCacheService — загружает позиции через кортежные запросы для производительности
  • Поиск: HibernateSearchAuftragsPositionTypeBinder — пользовательская привязка поиска
  • JSON: IdOnlySerializer — сериализует FK-ссылки только как ID
