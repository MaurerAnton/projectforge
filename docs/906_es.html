Una caché en memoria que asigna posiciones de factura (RechnungPosInfo) a sus posiciones de pedido y pedidos asociados. Esto permite búsquedas rápidas para que el libro de pedidos muestre qué facturas están vinculadas a cada pedido, y para que la vista de factura muestre qué pedidos están cubiertos. Maneja una dependencia cíclica con AuftragsCache ejecutando ambas cachés dos veces durante la inicialización (un mecanismo de bandera "ready").

Arquitectura y Diseño

Jerarquía de Clases

Extiende AbstractCache, que proporciona el ciclo de vida refresh()/setExpired()/forceReload(). Registrado como un @Component de Spring.

Ciclo de Vida e Inicialización

@PostConstruct init() registra dos oyentes:

  • rechnungListener — un BaseDOModifiedListener<RechnungDO> que llama a setExpired() cada vez que se inserta o modifica una factura. Esto asegura que la caché se mantenga actualizada cuando se crean, editan o eliminan facturas.
  • auftragsCacheListener — un CacheListener registrado en AuftragsCache. Implementa el patrón de actualización mutua: cuando AuftragsCache termina su actualización, este oyente lo detecta y desencadena un segundo ciclo de actualización para ambas cachés para resolver referencias cruzadas.

Patrón de Actualización Mutua (Resolución de Dependencia Cíclica)

AuftragsCache y AuftragsRechnungCache dependen de los datos del otro. La solución utiliza una bandera ready:

  1. Primero se ejecuta AuftragsCache.refresh() — los datos de esta caché aún están vacíos
  2. onAfterCacheRefresh se dispara, establece ready = true, desregistra el oyente
  3. AuftragsRechnungCache.forceReload() se ejecuta — ahora tiene datos de AuftragsCache disponibles
  4. AuftragsCache.forceReload() se ejecuta de nuevo — ahora tiene datos de esta caché disponibles
  5. Ambas cachés están completamente pobladas

Métodos Públicos

getRechnungsPosInfoByAuftragId(auftragId: Long?): List<RechnungPosInfo>?

Devuelve las posiciones de factura asignadas a un pedido dado. Los resultados se ordenan por número de factura, luego por número de posición. Devuelve null si auftragId es nulo. Llama a checkRefresh() para activar el poblamiento diferido de la caché si es necesario.

getRechnungsPosInfosByAuftragsPositionId(auftragsPositionId: Long?): Set<RechnungPosInfo>?

Devuelve las posiciones de factura asignadas a una posición de pedido específica. Devuelve null para entrada nula.

Lógica de Actualización

refresh() consulta rechnungJdbcService.selectRechnungsPositionenWithAuftragPosition() para obtener el conjunto de resultados JDBC sin procesar (más rápido que JPA para esta operación masiva), luego:

    <> Itera todos los enlaces de posición de factura a posición de pedido
  • Omite registros eliminados y referencias nulas, registrando errores para posiciones de pedido faltantes
  • Puebla tres mapas respaldados por TreeSet (ordenados automáticamente) para cada dimensión
  • Asigna los nuevos mapas atómicamente a los campos de la instancia
  • Registra la duración de la inicialización en segundos

Invalidación

Cuando se inserta o modifica cualquier RechnungDO, rechnungListener llama a setExpired(). La siguiente llamada a un método getter público activará checkRefresh() → refresh(), reconstruyendo perezosamente el mapeo de la caché.
