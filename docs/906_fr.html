Un cache en mémoire qui fait correspondre les positions de facture (RechnungPosInfo) à leurs positions de commande et commandes associées. Cela permet des recherches rapides pour le carnet de commandes afin d'afficher quelles factures sont liées à chaque commande, et pour la vue facture d'afficher quelles commandes sont couvertes. Gère une dépendance cyclique avec AuftragsCache en exécutant les deux caches deux fois lors de l'initialisation (mécanisme de drapeau « ready »).

Architecture & Conception

Hiérarchie des classes

Cycle de vie & Initialisation

@PostConstruct init() enregistre deux écouteurs :

  • rechnungListener — un BaseDOModifiedListener<RechnungDO> qui appelle setExpired() chaque fois qu'une facture est insérée ou modifiée. Cela garantit que le cache reste à jour lorsque des factures sont créées, éditées ou supprimées.
  • auftragsCacheListener — un CacheListener enregistré sur AuftragsCache. Implémente le modèle de rafraîchissement mutuel : lorsque AuftragsCache termine son rafraîchissement, cet écouteur le détecte et déclenche un second cycle de rafraîchissement pour les deux caches afin de résoudre les références croisées.

Modèle de rafraîchissement mutuel (résolution de dépendance cyclique)

AuftragsCache et AuftragsRechnungCache dépendent des données l'un de l'autre. La solution utilise un drapeau ready :

  1. Premier AuftragsCache.refresh() s'exécute — les données de ce cache sont encore vides
  2. onAfterCacheRefresh se déclenche, définit ready = true, désenregistre l'écouteur
  3. AuftragsRechnungCache.forceReload() s'exécute — dispose maintenant des données de AuftragsCache
  4. AuftragsCache.forceReload() s'exécute à nouveau — dispose maintenant des données de ce cache
  5. Les deux caches sont entièrement peuplés

Méthodes publiques

getRechnungsPosInfoByAuftragId(auftragId: Long?): List<RechnungPosInfo>?

Retourne les positions de facture affectées à une commande donnée. Les résultats sont triés par numéro de facture, puis par numéro de position. Retourne null si auftragId est nul. Appelle checkRefresh() pour déclencher le peuplement paresseux du cache si nécessaire.

getRechnungsPosInfosByAuftragsPositionId(auftragsPositionId: Long?): Set<RechnungPosInfo>?

Retourne les positions de facture affectées à une position de commande spécifique. Retourne null pour une entrée nulle.

Logique de rafraîchissement

refresh() interroge rechnungJdbcService.selectRechnungsPositionenWithAuftragPosition() pour obtenir le jeu de résultats JDBC brut (plus rapide que JPA pour cette opération en masse), puis :

  • Parcourt tous les liens position-facture vers position-commande
  • Ignore les enregistrements supprimés et les références nulles, en journalisant les erreurs pour les positions de commande manquantes
  • Peuple trois maps basées sur TreeSet (tri automatique) pour chaque dimension
  • Assigne les nouvelles maps de manière atomique aux champs de l'instance
  • Journalise la durée d'initialisation en secondes

Invalidation

Lorsqu'un RechnungDO est inséré ou modifié, rechnungListener appelle setExpired(). Le prochain appel à une méthode getter publique déclenchera checkRefresh() → refresh(), reconstruisant paresseusement la correspondance du cache.
