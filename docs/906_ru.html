Кэш в памяти, который сопоставляет позиции счетов (RechnungPosInfo) с соответствующими позициями заказов и самими заказами. Это обеспечивает быстрый поиск для книги заказов, чтобы отобразить, какие счета привязаны к каждому заказу, а также для просмотра счёта, чтобы показать, какие заказы покрыты. Обрабатывает циклическую зависимость с AuftragsCache путём двукратного запуска обоих кэшей при инициализации (механизм флага "ready").

Архитектура и дизайн

Иерархия классов

Расширяет AbstractCache, который предоставляет жизненный цикл refresh()/setExpired()/forceReload(). Зарегистрирован как Spring @Component.

Жизненный цикл и инициализация

@PostConstruct init() регистрирует два слушателя:

  • rechnungListener — BaseDOModifiedListener<RechnungDO>, который вызывает setExpired() при вставке или изменении счёта. Это гарантирует актуальность кэша при создании, редактировании или удалении счетов.
  • auftragsCacheListener — CacheListener, зарегистрированный на AuftragsCache. Реализует шаблон взаимного обновления: когда AuftragsCache завершает своё обновление, этот слушатель обнаруживает это и запускает второй цикл обновления для обоих кэшей для разрешения перекрёстных ссылок.

Шаблон взаимного обновления (разрешение циклической зависимости)

AuftragsCache и AuftragsRechnungCache зависят от данных друг друга. Решение использует флаг ready:

  1. Сначала выполняется AuftragsCache.refresh() — данные этого кэша всё ещё пусты
  2. Срабатывает onAfterCacheRefresh, устанавливает ready = true, отменяет регистрацию слушателя
  3. Выполняется AuftragsRechnungCache.forceReload() — теперь доступны данные AuftragsCache
  4. Снова выполняется AuftragsCache.forceReload() — теперь доступны данные этого кэша
  5. Оба кэша полностью заполнены

Публичные методы

getRechnungsPosInfoByAuftragId(auftragId: Long?): List<RechnungPosInfo>?

Возвращает позиции счетов, привязанные к заданному заказу. Результаты сортируются по номеру счёта, затем по номеру позиции. Возвращает null, если auftragId равен null. Вызывает checkRefresh() для запуска ленивого заполнения кэша при необходимости.

getRechnungsPosInfosByAuftragsPositionId(auftragsPositionId: Long?): Set<RechnungPosInfo>?

Возвращает позиции счетов, привязанные к конкретной позиции заказа. Возвращает null для нулевого ввода.

Логика обновления

refresh() запрашивает rechnungJdbcService.selectRechnungsPositionenWithAuftragPosition() для получения необработанного набора результатов JDBC (быстрее, чем JPA для этой массовой операции), затем:

  • Перебирает все связи позиция счёта — позиция заказа
  • Пропускает удалённые записи и нулевые ссылки, логируя ошибки для отсутствующих позиций заказов
  • Заполняет три карты на основе TreeSet (автосортировка) для каждого измерения
  • Атомарно присваивает новые карты полям экземпляра
  • Логирует продолжительность инициализации в секундах

Инвалидация

Когда любой RechnungDO вставляется или изменяется, rechnungListener вызывает setExpired(). Следующий вызов публичного геттера запустит checkRefresh() → refresh(), лениво перестраивая сопоставление кэша.

Связанные классы

  • Пир: AuftragsCache — партнёр по взаимному обновлению; предоставляет getOrderInfoByPositionId()
  • Пир: RechnungCache — предоставляет getRechnungInfo() и ensureRechnungPosInfo()
  • Сервис: RechnungJdbcService — сырой JDBC-запрос для производительности
  • Данные: RechnungPosInfo — объект значения, представляющий позицию счёта в кэше
  • Фреймворк: AbstractCache — базовый класс, предоставляющий checkRefresh()/setExpired()/forceReload()
