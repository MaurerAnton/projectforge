Una clase acumuladora Serializable que resume valores monetarios y recuentos en múltiples instancias de AuftragDO. Se utiliza en el libro de pedidos y las vistas de pronóstico para mostrar cifras agregadas del pipeline. Delega el cálculo por pedido a AuftragsCache.getOrderInfo() que devuelve un objeto OrderInfo con sumas precalculadas. Proporciona desgloses separados para adquisición (potencial), comisionado, facturado, no facturado aún y por facturar, junto con los contadores correspondientes.

Inicialización

Todas las sumas se inicializan a BigDecimal.ZERO y todos los contadores a 0 en el bloque init.

Método principal: add(auftrag: AuftragDO)

Para cada pedido, recupera el OrderInfo a través de WicketSupport.get(AuftragsCache::class.java).getOrderInfo(auftrag). El OrderInfo contiene desgloses precalculados (akquiseSum, commissionedNetSum, notYetInvoicedSum, toBeInvoicedSum, invoicedSum, netSum). Para cada suma > BigDecimal.ZERO, el acumulador de estadísticas incrementa el contador correspondiente y agrega el monto usando NumberHelper.add() (suma segura de BigDecimal que maneja valores nulos).

Semántica calculada

  • notYetInvoicedSum — representa montos abiertos: suma neta total menos lo que ya se ha facturado. Este es el monto aún por facturar.
  • toBeInvoiced — subconjunto más reducido: solo de pedidos que están ABGESCHLOSSEN (completados) pero aún no vollstaendigFakturiert (totalmente facturados) o tienen calendarios de pago no alcanzados. Representa candidatos inmediatos para facturación.
  • akquiseSum — de pedidos en estados del pipeline (POTENZIAL, IN_ERSTELLUNG, GELEGT)
  • beauftragtSum — de pedidos que están realmente comisionados (LOI, BEAUFTRAGT, ESKALATION)

Serialización

Implementa Serializable con serialVersionUID = -5486964211679100585L para la serialización de páginas Wicket. El set privado en todos los campos permite acceso de lectura desde el exterior mientras se evita la mutación directa (solo add() modifica el estado).
