Une classe d'accumulateur Sérialisable qui résume les valeurs monétaires et les comptages sur plusieurs instances AuftragDO. Utilisée dans le carnet de commandes et les vues de prévisions pour afficher des chiffres agrégés du pipeline. Délègue le calcul par commande à AuftragsCache.getOrderInfo() qui retourne un objet OrderInfo avec des sommes pré-calculées. Fournit des cumuls séparés pour les catégories acquisition (potentiel), commissionné, facturé, non encore facturé et à facturer, ainsi que les compteurs correspondants.

Initialisation

Toutes les sommes sont initialisées à BigDecimal.ZERO et tous les compteurs à 0 dans le bloc init.

Méthode principale : add(auftrag: AuftragDO)

Pour chaque commande, récupère le OrderInfo via WicketSupport.get(AuftragsCache::class.java).getOrderInfo(auftrag). Le OrderInfo contient des décompositions pré-calculées (akquiseSum, commissionedNetSum, notYetInvoicedSum, toBeInvoicedSum, invoicedSum, netSum). Pour chaque somme > BigDecimal.ZERO, l'accumulateur de statistiques incrémente le compteur correspondant et ajoute le montant en utilisant NumberHelper.add() (addition BigDecimal sécurisée qui gère les valeurs nulles).

Sémantique calculée

  • notYetInvoicedSum — représente les montants ouverts : somme nette totale moins ce qui a déjà été facturé. C'est le montant encore à facturer.
  • toBeInvoiced — sous-ensemble plus restreint : uniquement les commandes qui sont ABGESCHLOSSEN (terminées) mais pas encore vollstaendigFakturiert (entièrement facturées) ou qui ont des échéances de paiement non atteintes. Représente les candidats immédiats à la facturation.
  • akquiseSum — provenant des commandes dans les états du pipeline (POTENZIAL, IN_ERSTELLUNG, GELEGT)
  • beauftragtSum — provenant des commandes effectivement commissionnées (LOI, BEAUFTRAGT, ESKALATION)

Sérialisation

Implémente Sérialisable avec serialVersionUID = -5486964211679100585L pour la sérialisation des pages Wicket. Le set privé sur tous les champs permet un accès en lecture depuis l'extérieur tout en empêchant la mutation directe (seule add() modifie l'état).
