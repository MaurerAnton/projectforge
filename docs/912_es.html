Clase de soporte interna para operaciones de conversión de moneda. Gestiona persistencia en base de datos, validación y control de acceso. Marcada como internal — no forma parte de la API pública. CurrencyConversionService es la fachada pública; esta clase realiza las operaciones reales de datos y la invalidación de caché.

Validación

validate(rate) verifica unicidad mediante consultas nombradas:

  • Nuevas entradas: FIND_BY_PAIR_AND_DATE — verifica si ya existe alguna tasa para este par+fecha
  • Entradas existentes: FIND_OTHER_BY_PAIR_AND_DATE — excluye la tasa actual

Si se encuentra una tasa eliminada coincidente, se devuelve al llamante para su reutilización (patrón recuperar + copiar desde). Esto permite a los usuarios recrear tasas en fechas que estaban previamente activas pero fueron eliminadas lógicamente.

CRUD con Reutilización de Entradas Eliminadas

Tanto insert() como updateRate() implementan un algoritmo especial para manejar entradas eliminadas lógicamente:

  1. validate(rate) devuelve una entrada eliminada existente si coincide
  2. Si existe una coincidencia eliminada: los campos de la entrada eliminada se copian desde la nueva tasa, luego se recupera y la nueva entrada se descarta
  3. Para actualizaciones: el registro existente se marca como eliminado, y el registro coincidente previamente eliminado se recupera y actualiza
  4. La caché se invalida en un bloque finally

Control de Acceso

Todos los métodos mutantes (insertar, actualizar, eliminar) verifican que el usuario conectado tenga el derecho de acceso apropiado mediante currencyPairDao.checkLoggedInUser*Access(). El parámetro checkAccess (con valor predeterminado true) permite omitir estas verificaciones para operaciones de importación/lote.
