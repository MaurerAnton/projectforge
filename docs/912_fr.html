Classe de support interne pour les opérations de conversion de devises. Gère la persistance en base de données, la validation et le contrôle d'accès. Marqué internal — ne fait pas partie de l'API publique. CurrencyConversionService est la façade publique ; cette classe effectue les opérations réelles sur les données et l'invalidation du cache.

Validation

validate(rate) vérifie l'unicité via des requêtes nommées :

  • Nouvelles entrées : FIND_BY_PAIR_AND_DATE — vérifie si un taux existe déjà pour cette paire et cette date
  • Entrées existantes : FIND_OTHER_BY_PAIR_AND_DATE — exclut le taux actuel

Si un taux supprimé correspondant est trouvé, il est retourné à l'appelant pour réutilisation (modèle annulation de suppression + copie). Cela permet aux utilisateurs de recréer des taux à des dates qui étaient auparavant actives mais qui ont été supprimées de manière logicielle.

CRUD avec réutilisation d'entrée supprimée

Les deux méthodes insert() et updateRate() implémentent un algorithme spécial pour gérer les entrées supprimées de manière logicielle :

  1. validate(rate) retourne une entrée supprimée existante si elle correspond
  2. Si une correspondance supprimée existe : les champs de l'entrée supprimée sont copiés à partir du nouveau taux, puis elle est annulée de suppression, et la nouvelle entrée est ignorée
  3. Pour les mises à jour : l'enregistrement existant est marqué comme supprimé, et l'enregistrement correspondant précédemment supprimé est annulé de suppression et mis à jour
  4. Le cache est invalidé dans un bloc finally

Contrôle d'accès

Toutes les méthodes de mutation (insertion, mise à jour, suppression) vérifient que l'utilisateur connecté dispose du droit d'accès approprié via currencyPairDao.checkLoggedInUser*Access(). Le paramètre checkAccess (par défaut true) permet de contourner ces vérifications pour les opérations d'importation/par lots.
