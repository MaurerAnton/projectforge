Валидация

validate(rate) проверяет уникальность через именованные запросы:

  • Новые записи: FIND_BY_PAIR_AND_DATE — проверяет, существует ли уже курс для этой пары+даты
  • Существующие записи: FIND_OTHER_BY_PAIR_AND_DATE — исключает текущий курс

Если найден соответствующий удалённый курс, он возвращается вызывающему коду для повторного использования (паттерн undelete + copy-from). Это позволяет пользователям воссоздавать курсы на даты, которые ранее были активны, но мягко удалены.

CRUD с повторным использованием удалённых записей

Оба метода insert() и updateRate() реализуют специальный алгоритм обработки мягко удалённых записей:

  1. validate(rate) возвращает существующую удалённую запись, если она соответствует
  2. Если найдена удалённая запись: поля удалённой записи копируются из нового курса, затем она восстанавливается, а новая запись отбрасывается
  3. Для обновлений: существующая запись помечается как удалённая, а ранее удалённая соответствующая запись восстанавливается и обновляется
  4. Кэш инвалидируется в блоке finally

Контроль доступа

Все изменяющие методы (insert, update, delete) проверяют, что у вошедшего пользователя есть соответствующее право доступа через currencyPairDao.checkLoggedInUser*Access(). Параметр checkAccess (по умолчанию true) позволяет обходить эти проверки для операций импорта/пакетной обработки.
