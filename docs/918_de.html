Zentrale Domänenentität, die eine einzelne Position in einer Eingangsrechnung repräsentiert. Erweitert AbstractRechnungsPositionDO und stellt die Verbindung zur übergeordneten EingangsrechnungDO sowie den Kostenverteilungen (KostZuweisungDO) her. Hibernate-Search-indiziert für Volltextsuche.

Architektur / Design

Vererbung & JPA-Mapping

Erweitert AbstractRechnungsPositionDO (die gemeinsame Basisklasse für sowohl Eingangs- als auch Ausgangsrechnungspositionen). Deklariert als open (erforderlich für Kotlin + Hibernate für Lazy-Loading-Proxies). Die @Table-Annotation bildet auf t_fibu_eingangsrechnung_position ab, mit einer zusammengesetzten Unique-Constraint auf (eingangsrechnung_fk, number) – stellt sicher, dass Positionsnummern innerhalb einer einzelnen Rechnung eindeutig sind.

FeldTypJPA / Anmerkungen
eingangsrechnungEingangsrechnungDO?@ManyToOne(LAZY) — Referenz auf die übergeordnete Rechnung. Verwendet @JsonBackReference, um Serialisierungszyklen zu vermeiden. Wird nur als ID serialisiert über @JsonSerialize(IdOnlySerializer).
rechnungIdLong?@Transient — praktischer Getter, der an eingangsrechnung?.id delegiert. Überschreibt die abstrakte Eigenschaft aus AbstractRechnungsPositionDO.
kostZuweisungenMutableList<KostZuweisungDO>?@OneToMany(mappedBy="eingangsrechnungsPosition") mit @OrderColumn(name="index"). @JsonManagedReference (die "besitzende" Seite des JSON-Paares). Annotiert mit @PersistenceBehavior(autoUpdateCollectionEntries=true).

Wichtige Methoden

  • checkKostZuweisungId() — Validiert, dass eine Kostenverteilung zu dieser Position gehört, indem die FK-Referenz der Position verglichen wird.
  • newClone() — Erstellt eine tiefe Kopie (ohne IDs) einschließlich aller Kostenverteilungen. Verwendet copyValuesFrom() unter Ausschluss von "id" und "kostZuweisungen", klont dann jede KostZuweisungDO einzeln.
  • newInstance() — Factory-Methode, die eine neue leere EingangsrechnungsPositionDO zurückgibt.

JSON-Serialisierungsstrategie

Verwendet @JsonBackReference auf eingangsrechnung und @JsonManagedReference auf kostZuweisungen, um bidirektionale Beziehungen ohne Endlosschleifen zu handhaben. Die übergeordnete Rechnung wird nur als ID serialisiert, um JSON-Antworten kompakt zu halten.
