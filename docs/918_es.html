Entidad de dominio central que representa una sola posición/línea en una factura entrante. Extiende AbstractRechnungsPositionDO y establece el enlace con la EingangsrechnungDO padre más las asignaciones de costos (KostZuweisungDO). Indexado con Hibernate-search para búsqueda de texto completo.

Arquitectura / Diseño

Herencia y mapeo JPA

Extiende AbstractRechnungsPositionDO (la clase base común para posiciones de facturas entrantes y salientes). Declarado open (requerido por Kotlin + Hibernate para proxies de carga diferida). La anotación @Table mapea a t_fibu_eingangsrechnung_position con una restricción única compuesta en (eingangsrechnung_fk, number) — asegurando que los números de posición sean únicos dentro de una misma factura.

CampoTipoJPA / Notas
eingangsrechnungEingangsrechnungDO?@ManyToOne(LAZY) — referencia a la factura padre. Usa @JsonBackReference para romper el ciclo de serialización. Serializado solo como ID mediante @JsonSerialize(IdOnlySerializer).
rechnungIdLong?@Transient — getter de conveniencia que delega a eingangsrechnung?.id. Sobrescribe la propiedad abstracta de AbstractRechnungsPositionDO.
kostZuweisungenMutableList<KostZuweisungDO>?@OneToMany(mappedBy="eingangsrechnungsPosition") con @OrderColumn(name="index"). @JsonManagedReference (el lado "propietario" del par JSON). Anotado con @PersistenceBehavior(autoUpdateCollectionEntries=true).

Métodos clave

  • checkKostZuweisungId() — Valida que una asignación de costo pertenezca a esta posición comparando la referencia FK de la posición.
  • newClone() — Crea una copia profunda (sin IDs) incluyendo todas las asignaciones de costo. Usa copyValuesFrom() excluyendo "id" y "kostZuweisungen", luego clona cada KostZuweisungDO individualmente.
  • newInstance() — Método de fábrica que devuelve un nuevo EingangsrechnungsPositionDO vacío.

Estrategia de serialización JSON

Usa @JsonBackReference en eingangsrechnung y @JsonManagedReference en kostZuweisungen para manejar relaciones bidireccionales sin recursión infinita. La factura padre se serializa solo como ID, manteniendo las respuestas JSON compactas.
