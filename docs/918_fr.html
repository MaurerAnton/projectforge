Architecture / Conception

Héritage et mapping JPA

Étend AbstractRechnungsPositionDO (la classe de base commune pour les positions de factures entrantes et sortantes). Déclaré open (requis par Kotlin + Hibernate pour les proxies de chargement différé). L'annotation @Table mappe vers t_fibu_eingangsrechnung_position avec une contrainte unique composite sur (eingangsrechnung_fk, number) — garantissant que les numéros de position sont uniques au sein d'une même facture.

Méthodes clés

  • checkKostZuweisungId() — Valide qu'une affectation de coût appartient à cette position en comparant la référence FK de la position.
  • newClone() — Crée une copie profonde (sans ID) incluant toutes les affectations de coûts. Utilise copyValuesFrom() en excluant "id" et "kostZuweisungen", puis clone chaque KostZuweisungDO individuellement.

Stratégie de sérialisation JSON

Utilise @JsonBackReference sur eingangsrechnung et @JsonManagedReference sur kostZuweisungen pour gérer les relations bidirectionnelles sans récursion infinie. La facture parente est sérialisée sous forme d'ID uniquement, ce qui permet de garder les réponses JSON compactes.
