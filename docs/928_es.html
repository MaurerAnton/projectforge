Proxy de scripting que envuelve EmployeeService proporcionando acceso de solo lectura a la lógica de negocio de empleados para scripts Groovy/Kotlin. Disponible en scripts como: employeeService. Expone búsquedas de atributos dependientes del tiempo, verificaciones de estado activo, búsqueda de empleados y generación de informes mensuales. Esta es la interfaz de scripting más nueva y preferida en comparación con EmployeeScriptingDao.

Arquitectura y Diseño

Patrón de Delegación

Cada método delega directamente a la instancia subyacente de EmployeeService (inyectada por constructor como __employeeService). El proxy sigue el mismo patrón que ScriptingDao pero envuelve un servicio en lugar de un DAO — proporcionando lógica de negocio en lugar de solo acceso a entidades.

Justificación del Diseño

Los scripts necesitan acceso a lógica de negocio como "obtener horas semanales para empleado en fecha X" o "¿está este empleado activo?" — no solo CRUD. Este proxy expone únicamente métodos de solo lectura. Los scripts nunca deben mutar datos a través de esta interfaz; las mutaciones se realizan a través de DAOs de scripting dedicados.
