Proxy de script qui encapsule EmployeeService en fournissant un accès lecture seule à la logique métier des employés pour les scripts Groovy/Kotlin. Disponible dans les scripts sous le nom : employeeService. Expose les recherches d'attributs dépendants du temps, les vérifications de statut actif, la recherche d'employés et la génération de rapports mensuels. Il s'agit de l'interface de script préférée et plus récente par rapport à EmployeeScriptingDao.

Architecture & Conception

Patron de Délégation

Chaque méthode délègue directement à l'instance sous-jacente EmployeeService (injectée par constructeur sous le nom __employeeService). Le proxy suit le même modèle que ScriptingDao mais encapsule un service plutôt qu'un DAO — fournissant ainsi une logique métier plutôt qu'un simple accès aux entités.

Justification de la Conception

Les scripts ont besoin d'accéder à la logique métier comme « obtenir les heures hebdomadaires pour un employé à une date X » ou « cet employé est-il actif ? » — pas seulement du CRUD. Ce proxy expose uniquement des méthodes en lecture seule. Les scripts ne doivent jamais modifier les données via cette interface ; les mutations passent par des DAO de script dédiés.
