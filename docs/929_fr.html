L'API publique principale pour la logique métier des employés. Sert de façade sur EmployeeServiceSupport (implémentation interne), EmployeeDao, EmployeeCache et TimesheetDao. Exposé en tant que singleton via EmployeeService.instance. Enregistre un adaptateur d'historique pour EmployeeValidSinceAttrDO lors de l'initialisation.

Architecture & Conception

Dépendances & Initialisation

Logique de statut actif

isEmployeeActive(employé, afficherRécemmentPartis) : Renvoie vrai si :

  • Pas de date de départ : L'employé est actif si l'utilisateur n'est ni supprimé ni désactivé (utilisateur nul = actif, pour les tests).
  • A une date de départ : L'employé est actif si la date de départ est le jour même ou après la date de référence (maintenant, ou maintenant moins 3 mois si afficherRécemmentPartis=true).

Méthodes d'attributs dépendant du temps

Toutes les méthodes dépendant du temps parcourent les entrées ValidSinceAttrDO triées par validSince DESC et sélectionnent l'entrée dont validSince est le jour même ou avant la date de référence. Les méthodes sont organisées par type d'attribut :

  • Congés annuels : getAnnualLeaveDays() (avec/sans date), selectAnnualLeaveDayEntries() (par employé ou ID), insertAnnualLeaveDays()
  • Heures hebdomadaires : getWeeklyWorkingHours() (avec/sans date), selectWeeklyWorkingHoursEntries() (par employé ou ID), insertWeeklyHours()
  • Statut : getEmployeeStatus(), selectStatusEntries(), insertStatus()

Opérations CRUD ValidSinceAttr

Le service fournit une surface CRUD complète pour EmployeeValidSinceAttrDO :

  • insert() — Insertion avec ID employé ou entité, délègue à EmployeeServiceSupport
  • updateValidSinceAttr() — Mise à jour avec sémantique de copie (gère la réutilisation d'entrée supprimée)
  • markValidSinceAttrAsDeleted() — Suppression logicielle
  • undeleteValidSinceAttr() — Annulation de suppression / restauration
  • validate() — Renvoie un message d'erreur ou null si valide

Rapport mensuel des employés

getReportOfMonth(année, mois, utilisateur) crée un MonthlyEmployeeReport, initialise les limites de date, interroge les feuilles de temps via TimesheetFilter pour l'utilisateur et la plage mensuelle donnés, ajoute chaque feuille de temps (avec info de vérification d'accès) et calcule les durées agrégées par Kost2.
