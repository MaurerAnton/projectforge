El motor de implementación detrás de EmployeeService. Marcado como internal — no accesible fuera del paquete fibu. Contiene toda la lógica real para consultar, validar, insertar, actualizar, eliminar suave y recuperar entradas EmployeeValidSinceAttrDO. También resuelve los valores de atributos actuales (vacaciones anuales, horas semanales, estado) a partir de las entradas del período de validez.

Métodos de Consulta

  • findValidSinceAttr(id, expectedType, checkAccess) — Búsqueda simple de entidad por ID con validación opcional de tipo (lanza IllegalArgumentException si hay discrepancia de tipo).
  • selectAllValidSinceAttrs(employee, type, deleted, checkAccess) — Consulta principal: obtiene todos los ValidSinceAttr para un empleado, opcionalmente filtrados por tipo y estado de eliminación. Ordenados por validSince DESC.
  • selectAnnualLeaveDayEntries() / selectWeeklyWorkingHoursEntries() — Envoltorios de conveniencia que filtran por tipo ANNUAL_LEAVE o WEEKLY_HOURS. Disponibles con parámetros employeeId o EmployeeDO.

Resolución de Entrada Activa (getActiveEntry)

El método getActiveEntry(entries, validAtDate) resuelve un problema comercial clave: dada una lista de entradas ValidSinceAttr con fechas validSince, encontrar la que es actualmente aplicable en un punto dado en el tiempo. Algoritmo:

  1. Iterar todas las entradas no eliminadas.
  2. Para cada entrada donde validAtDate >= entry.validSince, comparar con la mejor encontrada hasta ahora.
  3. Seleccionar la entrada con el último validSince que aún sea anterior/en la fecha de referencia.

Esto soporta búsquedas históricas — preguntar "cuál eran las vacaciones anuales para el empleado X en la fecha Y" — lo cual es crítico para informes precisos.

Lógica de Validación (validate)

Antes de insertar o actualizar, el sistema verifica si existe otro ValidSinceAttr con la misma combinación (employee, type, validSince):

  • Nueva entrada (id==null): Usa la consulta nombrada FIND_BY_TYPE_AND_DATE.
  • Entrada existente: Usa FIND_OTHER_BY_TYPE_AND_DATE (excluye el ID actual).
  • Reutilización de entrada eliminada: Si existe una entrada eliminada con el mismo validSince, se devuelve para reutilización en lugar de lanzar excepción. Esto maneja el escenario de UX donde los usuarios no pueden ver entradas eliminadas pero intentan agregar una nueva que colisionaría — el sistema silenciosamente recupera y actualiza el registro existente.
  • Si existe un duplicado no eliminado, lanza IllegalArgumentException.

Operaciones CRUD

  • insert() — Valida, luego inserta uno nuevo o recupera uno existente (lógica de reutilización). Siempre expira la caché del empleado.
  • insertValidSinceAttr() — Fábrica de conveniencia: crea EmployeeValidSinceAttrDO, establece todos los campos e inserta.
  • updateValidSinceAttr() — Actualización compleja con semántica de copia: valida, potencialmente marca la entrada existente como eliminada y recupera/modifica una previamente eliminada con la fecha objetivo.
  • markValidSinceAttrAsDeleted() — Valida, luego elimina suavemente con verificación de acceso.
  • undeleteValidSinceAttr() — Valida, luego recupera con verificación de acceso.

Obtenedores de Valores Concretos

  • getEmployeeStatus() — Selecciona entradas STATUS, obtiene la entrada activa, convierte el valor al enum EmployeeStatus mediante safeValueOf(). Registra error si se encuentra un valor de estado desconocido.
  • getAnnualLeaveDays() — Selecciona entradas ANNUAL_LEAVE, obtiene la entrada activa, convierte a BigDecimal.
  • getWeeklyWorkingHours() — Selecciona entradas WEEKLY_HOURS, obtiene la entrada activa, convierte a BigDecimal.

Todos devuelven null si el empleado o validAtDate es null (para compatibilidad de pruebas con CallAllPagesTest/Wicket).
