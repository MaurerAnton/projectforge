Le moteur d'implémentation derrière EmployeeService. Marqué internal — non accessible en dehors du package fibu. Contient toute la logique réelle pour interroger, valider, insérer, mettre à jour, supprimer logiquement et restaurer les entrées EmployeeValidSinceAttrDO. Résout également les valeurs d'attribut actuelles (congés annuels, heures hebdomadaires, statut) à partir des entrées de période de validité.

Architecture & Conception

Méthodes de requête

  • findValidSinceAttr(id, expectedType, checkAccess) — Recherche simple d'entité par ID avec validation de type optionnelle (lève IllegalArgumentException en cas de non-concordance de type).
  • selectAllValidSinceAttrs(employee, type, deleted, checkAccess) — Requête principale : récupère tous les ValidSinceAttr pour un employé, éventuellement filtrés par type et statut de suppression. Triés par validSince DESC.
  • selectAnnualLeaveDayEntries() / selectWeeklyWorkingHoursEntries() — Raccourcis pratiques filtrant par type ANNUAL_LEAVE ou WEEKLY_HOURS. Disponibles avec les paramètres employeeId ou EmployeeDO.

Résolution d'entrée active (getActiveEntry)

La méthode getActiveEntry(entries, validAtDate) résout un problème métier clé : étant donné une liste d'entrées ValidSinceAttr avec des dates validSince, trouver celle qui est actuellement applicable à un moment donné. Algorithme :

  1. Parcourir toutes les entrées non supprimées.
  2. Pour chaque entrée où validAtDate >= entry.validSince, comparer avec la meilleure trouvée jusqu'à présent.
  3. Sélectionner l'entrée avec le plus récent validSince qui est encore avant/à la date de référence.

Cela permet les recherches historiques — demander « quel était le congé annuel pour l'employé X à la date Y » — ce qui est essentiel pour des rapports précis.

Logique de validation (validate)

Avant l'insertion ou la mise à jour, le système vérifie si une autre entrée ValidSinceAttr existe avec la même combinaison (employee, type, validSince) :

  • Nouvelle entrée (id==null) : Utilise la requête nommée FIND_BY_TYPE_AND_DATE.
  • Entrée existante : Utilise FIND_OTHER_BY_TYPE_AND_DATE (exclut l'ID actuel).
  • Réutilisation d'entrée supprimée : Si une entrée supprimée avec le même validSince existe, elle est retournée pour réutilisation plutôt que de lever une exception. Cela gère le scénario UX où les utilisateurs ne peuvent pas voir les entrées supprimées mais tentent d'en ajouter une nouvelle qui entrerait en conflit — le système restaure silencieusement et met à jour l'enregistrement existant à la place.
  • Si un doublon non supprimé existe, lève une IllegalArgumentException.

Opérations CRUD

  • insert() — Valide, puis soit insère une nouvelle entrée, soit restaure une entrée existante (logique de réutilisation). Expire toujours le cache de l'employé.
  • insertValidSinceAttr() — Fabrique pratique : crée EmployeeValidSinceAttrDO, définit tous les champs et insère.
  • updateValidSinceAttr() — Mise à jour complexe avec sémantique de copie : valide, marque potentiellement l'entrée existante comme supprimée et restaure/modifie une entrée précédemment supprimée avec la date cible.
  • markValidSinceAttrAsDeleted() — Valide, puis supprime logiquement avec vérification d'accès.
  • undeleteValidSinceAttr() — Valide, puis restaure avec vérification d'accès.

Accesseurs de valeurs concrètes

  • getEmployeeStatus() — Sélectionne les entrées STATUS, obtient l'entrée active, convertit la valeur en énumération EmployeeStatus via safeValueOf(). Enregistre une erreur si une valeur de statut inconnue est rencontrée.
  • getAnnualLeaveDays() — Sélectionne les entrées ANNUAL_LEAVE, obtient l'entrée active, convertit en BigDecimal.
  • getWeeklyWorkingHours() — Sélectionne les entrées WEEKLY_HOURS, obtient l'entrée active, convertit en BigDecimal.

Tous retournent null si l'employé ou validAtDate est null (pour la compatibilité des tests avec CallAllPagesTest/Wicket).
