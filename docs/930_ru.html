projectforge-business/src/main/kotlin/org/projectforge/business/fibu/EmployeeServiceSupport.kt Тип: Spring-сервис (внутренний) · Назначение: Внутренняя реализация EmployeeService — валидация, сохранение и логика поиска для атрибутов, зависящих от времени · Путь: projectforge-business/src/main/kotlin/org/projectforge/business/fibu/EmployeeServiceSupport.kt 418 строк · 304 кода · 88 комментариев · 26 пустых
Движок реализации, лежащий в основе EmployeeService. Помечен как internal — недоступен за пределами пакета fibu. Содержит всю фактическую логику для запросов, валидации, вставки, обновления, мягкого удаления и восстановления записей EmployeeValidSinceAttrDO. Также разрешает текущие значения атрибутов (ежегодный отпуск, еженедельные часы, статус) на основе записей периода действия.

Методы запросов

  • findValidSinceAttr(id, expectedType, checkAccess) — Простой поиск сущности по ID с опциональной проверкой типа (выбрасывает IllegalArgumentException при несоответствии типа).
  • selectAllValidSinceAttrs(employee, type, deleted, checkAccess) — Основной запрос: извлекает все ValidSinceAttr для сотрудника, опционально отфильтрованные по типу и статусу удаления. Упорядочены по validSince DESC.
  • selectAnnualLeaveDayEntries() / selectWeeklyWorkingHoursEntries() — Удобные обёртки, фильтрующие по типу ANNUAL_LEAVE или WEEKLY_HOURS. Доступны с параметрами employeeId или EmployeeDO.

Разрешение активной записи (getActiveEntry)

Метод getActiveEntry(entries, validAtDate) решает ключевую бизнес-задачу: имея список записей ValidSinceAttr с датами validSince, найти ту, которая актуальна на заданный момент времени. Алгоритм:

  1. Перебрать все неудалённые записи.
  2. Для каждой записи, где validAtDate >= entry.validSince, сравнить с лучшей найденной на данный момент.
  3. Выбрать запись с самой поздней датой validSince, которая всё ещё находится до/на контрольной дате.

Это поддерживает исторические запросы — например, «каким был ежегодный отпуск для сотрудника X на дату Y» — что критически важно для точной отчётности.

Логика валидации (validate)

Перед вставкой или обновлением система проверяет, существует ли другая запись ValidSinceAttr с той же комбинацией (employee, type, validSince):

  • Новая запись (id==null): Использует именованный запрос FIND_BY_TYPE_AND_DATE.
  • Существующая запись: Использует FIND_OTHER_BY_TYPE_AND_DATE (исключает текущий ID).
  • Повторное использование удалённой записи: Если существует удалённая запись с тем же validSince, она возвращается для повторного использования вместо выбрасывания исключения. Это обрабатывает сценарий UX, когда пользователи не видят удалённые записи, но пытаются добавить новую, которая может конфликтовать — система молча восстанавливает и обновляет существующую запись.
  • Если существует неудалённый дубликат, выбрасывается IllegalArgumentException.

CRUD-операции

  • insert() — Выполняет валидацию, затем либо вставляет новую запись, либо восстанавливает существующую (логика повторного использования). Всегда сбрасывает кэш сотрудника.
  • insertValidSinceAttr() — Удобная фабрика: создаёт EmployeeValidSinceAttrDO, устанавливает все поля и вставляет.
  • updateValidSinceAttr() — Сложное обновление с семантикой копирования: выполняет валидацию, потенциально помечает существующую запись как удалённую и восстанавливает/изменяет ранее удалённую запись с целевой датой.
  • markValidSinceAttrAsDeleted() — Выполняет валидацию, затем мягко удаляет с проверкой доступа.
  • undeleteValidSinceAttr() — Выполняет валидацию, затем восстанавливает с проверкой доступа.

Конкретные геттеры значений

  • getEmployeeStatus() — Выбирает записи STATUS, получает активную запись, преобразует значение в перечисление EmployeeStatus через safeValueOf(). Логирует ошибку при обнаружении неизвестного значения статуса.
  • getAnnualLeaveDays() — Выбирает записи ANNUAL_LEAVE, получает активную запись, преобразует в BigDecimal.
  • getWeeklyWorkingHours() — Выбирает записи WEEKLY_HOURS, получает активную запись, преобразует в BigDecimal.

Все возвращают null, если сотрудник или validAtDate равны null (для совместимости с тестами CallAllPagesTest/Wicket).
