Representa un único valor de atributo dependiente del tiempo para un empleado que se vuelve válido a partir de una fecha específica. Soporta tres tipos: STATUS, ANNUAL_LEAVE y WEEKLY_HOURS. Se asigna a t_fibu_employee_valid_since_attr con una restricción única compuesta en (employee_fk, type, valid_since). Implementa CandHHistoryEntryICustomizer para renderizado de historial tipado y WithHistory para seguimiento automático de historial.

Arquitectura y Diseño

Polimorfismo de Tipo mediante Valor String

En lugar de usar tablas o columnas separadas para cada tipo de atributo, esta entidad utiliza una única columna value (String) con un discriminador type. Las propiedades transitorias proporcionan acceso seguro por tipo:

  • annualLeave — Getter/setter que valida type == ANNUAL_LEAVE y convierte a/desde BigDecimal.
  • weeklyWorkingHours — Getter/setter que valida type == WEEKLY_HOURS y convierte a/desde BigDecimal.
  • status — Getter/setter que valida type == STATUS y convierte mediante EmployeeStatus.safeValueOf().

Todos los accesores transitorios están anotados con @CandHIgnore y @JsonIgnore — no forman parte del modelo persistente ni serializado.

  • EmployeeValidSinceAttr_FindByTypeAndDate — from EmployeeValidSinceAttrDO where employee.id=:employeeId and type=:type and validSince=:validSince

Semántica de Copia

copyFrom(other) copia solo validSince, value y comment. Notablemente, type, id y employee NO se copian — esto se debe a que la copia se usa para el patrón de reutilización de entradas eliminadas donde una entrada existente del mismo tipo se actualiza con nuevos valores.

Integración con Historial

Implementa CandHHistoryEntryICustomizer:

  • El método customize(historyEntry) encuentra el atributo "value" en el historial y establece su propertyTypeClass basado en el discriminador type:
    • ANNUAL_LEAVE → BigDecimal::class
    • WEEKLY_HOURS → BigDecimal::class
    • STATUS → EmployeeStatus::class

Esto asegura que las entradas del historial muestren el campo value con el formato de tipo correcto (ej., "5.00" para BigDecimal, etiqueta i18n para enum) en lugar de como strings sin formato.

Fundamento del Diseño

El patrón de "período de validez" (también llamado "atributos temporales") permite que los atributos del empleado cambien con el tiempo mientras se mantiene un historial completo. Por ejemplo:

  • Las vacaciones anuales de un empleado podrían cambiar de 24 a 30 días a partir del 2025-01-01.
  • Sus horas semanales podrían cambiar de 40 a 32 a partir del 2023-06-01.
  • Su estado podría cambiar de Aushilfe a Festangestellter a partir del 2024-03-01.

Todos los cambios se registran como entradas separadas con fechas validSince. EmployeeCache y EmployeeServiceSupport resuelven el valor actual encontrando la entrada más reciente cuyo validSince sea igual o anterior a la fecha de hoy.
