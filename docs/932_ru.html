projectforge-business/src/main/kotlin/org/projectforge/business/fibu/EmployeeValidSinceAttrDO.kt Тип: JPA-сущность (объект данных) · Назначение: Зависящие от времени (период действия) атрибуты для сотрудников — статус, ежегодный отпуск, недельные часы · Путь: projectforge-business/src/main/kotlin/org/projectforge/business/fibu/EmployeeValidSinceAttrDO.kt 186 строк · 133 кода · 33 комментария · 20 пустых
Представляет одно значение атрибута сотрудника, зависящее от времени, которое становится действительным с определённой даты. Поддерживает три типа: STATUS, ANNUAL_LEAVE и WEEKLY_HOURS. Соответствует таблице t_fibu_employee_valid_since_attr с составным уникальным ограничением на (employee_fk, type, valid_since). Реализует CandHHistoryEntryICustomizer для типизированного отображения истории и WithHistory для автоматического отслеживания истории.

Архитектура и дизайн

Полиморфизм типов через строковое значение

Вместо использования отдельных таблиц или столбцов для каждого типа атрибута, эта сущность использует один столбец value (строка) с дискриминатором type. Временные свойства обеспечивают типобезопасный доступ:

  • annualLeave — Геттер/сеттер, проверяющий type == ANNUAL_LEAVE и преобразующий в/из BigDecimal.
  • weeklyWorkingHours — Геттер/сеттер, проверяющий type == WEEKLY_HOURS и преобразующий в/из BigDecimal.
  • status — Геттер/сеттер, проверяющий type == STATUS и преобразующий через EmployeeStatus.safeValueOf().

Все временные аксессоры аннотированы @CandHIgnore и @JsonIgnore — они не являются частью постоянной или сериализованной модели.

Именованные запросы

  • EmployeeValidSinceAttr_FindByTypeAndDate — from EmployeeValidSinceAttrDO where employee.id=:employeeId and type=:type and validSince=:validSince
  • EmployeeValidSinceAttr_FindOtherByTypeAndDate — То же, но с and id!=:id (для проверки обновления, исключая текущую запись).

Семантика копирования

copyFrom(other) копирует только validSince, value и comment. Примечательно, что тип, id и сотрудник НЕ копируются — это связано с тем, что копирование используется для шаблона повторного использования удалённой записи, когда существующая запись того же типа обновляется новыми значениями.

Интеграция с историей

Реализует CandHHistoryEntryICustomizer:

  • Метод customize(historyEntry) находит атрибут "value" в истории и устанавливает его propertyTypeClass на основе дискриминатора type:
    • ANNUAL_LEAVE → BigDecimal::class
    • WEEKLY_HOURS → BigDecimal::class
    • STATUS → EmployeeStatus::class

Это гарантирует, что записи истории отображают поле value с правильным форматированием типа (например, "5.00" для BigDecimal, i18n-метка для перечисления), а не в виде сырых строк.

Обоснование дизайна

Шаблон "периода действия" (также называемый "атрибуты со временем") позволяет атрибутам сотрудника изменяться со временем, сохраняя полную историю. Например:

  • Ежегодный отпуск сотрудника может измениться с 24 до 30 дней, начиная с 2025-01-01.
  • Его недельные часы могут измениться с 40 до 32, начиная с 2023-06-01.
  • Его статус может измениться с Aushilfe на Festangestellter, начиная с 2024-03-01.

Все изменения отслеживаются как отдельные записи с датами validSince. EmployeeCache и EmployeeServiceSupport определяют текущее значение, находя последнюю запись, чья дата validSince не превышает сегодняшнюю.
