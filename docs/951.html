#951: RechnungDao.kt

Type: DAO / Service · Purpose: Data access and business logic for outgoing invoices (Rechnungen) · Source: projectforge-business/src/main/kotlin/org/projectforge/business/fibu/RechnungDao.kt
Core Spring @Service for outgoing invoice management. Extends BaseDao<RechnungDO> to provide CRUD operations, payment status filtering, invoice numbering, maturity calculation, cost assignment loading, and history integration for child positions and cost assignments.

Selection & Filtering Architecture

The select(filter) method implements a sophisticated two-phase filtering:

  1. Database phase: Converts search filter to RechnungListFilter, builds a QueryFilter with date restrictions and period-of-performance criteria, ordered by datum/number descending
  2. In-memory phase: Uses RechnungCache to determine per-invoice payment status (RechnungInfo.isBezahlt, isUeberfaellig), filtering by listType: ALL, UNPAID, PAID, or OVERDUE

Validation (onInsertOrModify)

Extensive business rule enforcement:

  • Credit notes (GUTSCHRIFTSANZEIGE_DURCH_KUNDEN) must not have an invoice number
  • Regular invoices without GEPLANT status must have a sequential invoice number; new invoices get the next number assigned
  • Duplicate invoice numbers are rejected (uses FIND_OTHER_BY_NUMMER named query)
  • Payment amount is rounded to 2 decimal places (HALF_UP)
  • Empty trailing positions (new, empty) are automatically removed
  • At least one position required
  • PAID status requires a non-zero zahlBetrag
  • A customer, project, or customer text reference is required
  • AuftragAndRechnungDaoHelper.onSaveOrModify() is called for shared order/invoice logic

Invoice Lifecycle: Planned → Active

When an invoice transitions from GEPLANT (planned) to any other status: - A sequential number is assigned - The current date is set as datum - The payment target is computed from zahlungsZielInTagen

History Integration

addOwnHistoryEntries() loads history for child RechnungsPositionDO and grandchild KostZuweisungDO records. getHistoryPropertyPrefix() provides contextual labels: position numbers for positions, and "kost #index" for cost assignments.

@Service
open class RechnungDao : BaseDao<RechnungDO>(RechnungDO::class.java) {
    @Autowired private lateinit var rechnungCache: RechnungCache

    override fun select(filter: BaseSearchFilter): List<RechnungDO> {
        val myFilter = if (filter is RechnungListFilter) filter
                       else RechnungListFilter(filter)
        val queryFilter = createQueryFilterWithDateRestriction(myFilter)
        queryFilter.addOrder(desc("datum")).addOrder(desc("nummer"))
        createCriterionForPeriodOfPerformance(myFilter)
            .ifPresent { queryFilter.add(it) }
        val list = select(queryFilter)
        if (myFilter.isShowAll || myFilter.deleted) return list
        val result = mutableListOf<RechnungDO>()
        for (rechnung in list) {
            val info = rechnungCache.getRechnungInfo(rechnung.id)
                      ?: RechnungInfo(rechnung)
            when {
                myFilter.isShowUnbezahlt && !info.isBezahlt -> result.add(rechnung)
                myFilter.isShowBezahlt && info.isBezahlt -> result.add(rechnung)
                myFilter.isShowUeberFaellig && info.isUeberfaellig -> result.add(rechnung)
            }
        }
        return result
    }

    override fun onInsertOrModify(obj: RechnungDO, op: OperationType) {

        // Validation: credit notes, payment amount, customer reference
        // Position cleanup, recalculation, UI status XML
    }
}
