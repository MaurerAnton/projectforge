#973: ContractPagesRest

Type: REST Controller (Spring)  |  Purpose: Contract management with dual-party data, cloning, Jira integration
Source: projectforge-rest/src/main/kotlin/org/projectforge/rest/orga/ContractPagesRest.kt
Extends: AbstractDTOPagesRest<ContractDO, Contract, ContractDao>
Endpoint: /rs/contract

REST controller for the contract management module. Supports full CRUD with clone functionality, dual co-contractor fields, date validation (no future dates), year-based magic filtering, JCR attachments, and integration with Jira issue tracking for contract text references.

Architecture & Design

Clone Support

Uses CloneSupport.CLONE. The prepareClone() method sets number to null on cloned contracts so the copy gets a fresh number.

Validation

Ensures date is not in the future using PFDay comparison. New contracts default to today's date.

Magic Filter

Adds a year filter element. The preProcessMagicFilter() intercepts it as synthetic and sets yearAndMonth on the QueryFilter (month = -1 for full year).

Edit Layout

Complex four-fieldset layout:

  1. Left-top: Number (read-only), Title (auto-complete), Type (dropdown from configurationService.contractTypes), Status, Reference
  2. Right-top: Date, Resubmission date, Due date, Signing date, Valid from/to
  3. Co-contractor A: Contractor name, Contact person, Signer (all auto-completable)
  4. Co-contractor B: Same structure as contractor A
  5. Bottom: Contract text (with optional Jira element), Filing location, Attachment list

Jira Integration

Uses JiraSupport.createJiraElement(dto.text, ...) to add a Jira issue reference component to the contract text fieldset when Jira references are detected in the text.

Auto-Completion

Title, both co-contractor names, contact persons, and signers all have auto-completion enabled, reusing the address/contract search index.
