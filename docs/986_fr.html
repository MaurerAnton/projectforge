Le service d'orchestration pour les imports Excel de type DATEV. Coordonne le pipeline d'import pour le Kontenplan (plan comptable) et les Buchungssätze (écritures comptables). Gère le cycle de vie de l'import : analyse (import), validation (réconciliation) et persistance (validation). Toutes les opérations nécessitent le droit utilisateur FIBU_DATEV_IMPORT.

Architecture

Cycle de vie de l'import

Phase 1 : Import (Analyse Excel)

MéthodeEntréeSortie
importKontenplan(inputStream, filename)InputStream ExcelImportStorage<KontoDO>
importBuchungsdaten(inputStream, filename)InputStream ExcelImportStorage<BuchungssatzDO>

Les deux méthodes ouvrent un ExcelWorkbook à partir du flux d'entrée, créent un ImportStorage avec la configuration de journalisation, délèguent à la classe d'import respective (KontenplanExcelImporter / BuchungssatzExcelImporter) et retournent le stockage rempli.

Phase 2 : Réconciliation (Validation & Diff)

MéthodeDescription
reconcile(storage, sheetName)Distribue vers reconcileKontenplan() ou reconcileBuchungsdaten() selon le type de stockage. Définit numberOfCommittedElements à -1.

La réconciliation fait correspondre les éléments importés avec les entrées existantes de la base de données :

  • Kontenplan : recherche chaque KontoDO importé par numéro de compte. Les entrées trouvées sont stockées comme oldValue sur l'élément importé et leur horodatage created est copié dans l'import (nécessaire à BaseDao pour déterminer l'insertion ou la mise à jour).
  • Buchungssätze : recherche par (year, month, satznr) en utilisant buchungssatzDao.getBuchungssatz().

Phase 3 : Validation (Persistance)

MéthodeDescription
commit(storage, sheetName)Nécessite le statut RECONCILED. Distribue vers commitKontenplan() ou commitBuchungsdaten(). Définit le statut à IMPORTED.

La validation collecte les éléments sélectionnés, définit l'identifiant de base de données à partir de oldValue si l'entrée existe déjà, et effectue une insertion en masse via le DAO par blocs de 50.

Énumération des types d'import

DatevImportService.Type : KONTENPLAN, BUCHUNGSSAETZE. Utilisé comme discriminateur dans ImportStorage.

Contrôle d'accès

Toutes les méthodes publiques appellent checkLoggedinUserRight() qui vérifie UserRightId.FIBU_DATEV_IMPORT avec la valeur TRUE. L'objet compagnon fournit des méthodes statiques d'aide pour une utilisation dans les pages Wicket (découplage pré-service).
