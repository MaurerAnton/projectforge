Orchestrierungsservice für die Mitarbeitergehaltsimport-Pipeline. Folgt dem gleichen Drei-Phasen-Importlebenszyklus (Import → Abgleich → Commit), der von DatevImportService etabliert wurde. Koordiniert zwischen EmployeeSalaryExcelImporter (Parsing), EmployeeSalaryDao (Persistenz) und EmployeeSalaryService (Nachschlagefunktion).

Architektur

Abhängigkeiten

AbhängigkeitRolle
EmployeeSalaryExcelImporterParst die Excel-Arbeitsmappe in ImportStorage<EmployeeSalaryDO>
EmployeeSalaryServiceNachschlagen vorhandener Gehälter nach Monat für den Abgleich
EmployeeSalaryDaoMassen-Commit und Zugriffskontrolle

Import-Lebenszyklus

Phase 1: Import

importData(inputStream, filename, year, month) — öffnet eine ExcelWorkbook, erstellt einen ImportStorage, delegiert an EmployeeSalaryExcelImporter.doImport(). Gibt den befüllten Speicher zurück.

Phase 2: Abgleich

reconcile(storage, sheetName, year, month) — sucht vorhandene Gehälter für das angegebene Jahr/den Monat über employeeSalaryService.selectByMonth(), gleicht dann jedes importierte Element mit einem vorhandenen DB-Datensatz anhand der Mitarbeiter-ID ab. Setzt oldValue, id und created-Zeitstempel auf das Element für die Commit-Phase. Setzt den Status auf RECONCILED.

Phase 3: Commit

commit(storage, sheetName) — erfordert den Status RECONCILED. Sammelt ausgewählte Elemente, kopiert die vorhandene id aus oldValue für Aktualisierungen und führt einen Massen-Commit über employeeSalaryDao.insertOrUpdate() in Blöcken von 50 durch. Setzt den Status auf IMPORTED.

Zugriffskontrolle

checkLoggedinUserRight() delegiert an employeeSalaryDao.checkLoggedInUserInsertAccess(), das überprüft, ob der Benutzer das Einfüge-Recht für Mitarbeitergehälter besitzt.

Einfüge-Blockgröße

SALARY_INSERT_BLOCK_SIZE = 50 — steuert die Batch-Größe für Persistenzoperationen.
