Сервис оркестрации для конвейера импорта зарплат сотрудников. Следует тому же трёхфазному жизненному циклу импорта (импорт → сверка → фиксация), который установлен в DatevImportService. Координирует работу EmployeeSalaryExcelImporter (парсинг), EmployeeSalaryDao (персистентность) и EmployeeSalaryService (поиск).

Архитектура

Зависимости

ЗависимостьРоль
EmployeeSalaryExcelImporterРазбирает книгу Excel в ImportStorage<EmployeeSalaryDO>
EmployeeSalaryServiceПоиск существующих зарплат по месяцу для сверки
EmployeeSalaryDaoПакетная фиксация и контроль доступа

Жизненный цикл импорта

Фаза 1: Импорт

importData(inputStream, filename, year, month) — открывает ExcelWorkbook, создаёт ImportStorage, делегирует выполнение EmployeeSalaryExcelImporter.doImport(). Возвращает заполненное хранилище.

Фаза 2: Сверка

reconcile(storage, sheetName, year, month) — ищет существующие зарплаты за указанные год/месяц через employeeSalaryService.selectByMonth(), затем сопоставляет каждый импортированный элемент с существующей записью в БД по идентификатору сотрудника. Устанавливает oldValue, id и временную метку created для элемента на этапе фиксации. Устанавливает статус RECONCILED.

Фаза 3: Фиксация

commit(storage, sheetName) — требует статуса RECONCILED. Собирает выбранные элементы, копирует существующий id из oldValue для обновлений и выполняет пакетную фиксацию через employeeSalaryDao.insertOrUpdate() блоками по 50. Устанавливает статус IMPORTED.

Контроль доступа

checkLoggedinUserRight() делегирует выполнение employeeSalaryDao.checkLoggedInUserInsertAccess(), который проверяет, имеет ли пользователь право на вставку для зарплат сотрудников.

Размер блока вставки

SALARY_INSERT_BLOCK_SIZE = 50 — управляет размером пакета для операций персистентности.
