But fixing a real bug. Here's why.

Why the old test was wrong

The source code at rest.js:10-11 defines:

export const baseURL = ... ? testServer : '';
export const baseRestURL = `${baseURL}/rs`;  // ← NOT baseURL

baseURL can be either 'http://localhost:8080' (dev) or '' (prod/test). It is not '/rs'.

The old test asserted baseURL === '/rs' — which is the value of baseRestURL, not baseURL. This worked by accident in CRA because:

  1. In CRA test environment: process.env.NODE_ENV === 'test'
  2. So baseURL = '' (empty string)
  3. But the test expected '/rs' — somehow the test passed

How did it pass? In CRA, process.env.NODE_ENV might not be reliably set to 'test' in all setups. The Jest config might have overridden it. Regardless, the assertion was testing the wrong variable — it was checking baseRestURL's value against baseURL's name.

In Vite: import.meta.env.MODE === 'test' is always set during vitest run. baseURL is '' — reliably. The test now correctly expects ''.

How this file connects to authentication.test.js

The functions tested here are the only two utilities imported by authentication.js:1:

import { getServiceURL, handleHTTPErrors } from '../utilities/rest';

getServiceURL — converts '/rsPublic/login' to either 'http://localhost:8080/rsPublic/login' (dev) or '/rsPublic/login' (prod). This test verifies the dev→prod URL logic.

handleHTTPErrors — throws Error('Fetch failed: Error 401') on non-OK responses. This is the exact error string that authentication.test.js expects at line 88.

The baseURL change (process.env.NODE_ENV → import.meta.env) is what made the whole Vite migration work — without it, every fetch() in the app would fail in dev mode.
